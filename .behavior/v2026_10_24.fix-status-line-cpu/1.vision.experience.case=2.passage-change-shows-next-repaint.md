# case=2 — a passage change shows on the next repaint (happy · critipath, the densest walk)

## .narrative

the driver runs `rhx route.stone.set --stone 3.blueprint --as passed`. the guard clears and an
entry lands in `.route/passage.jsonl`. the cache still holds `🗿 3.blueprint, review.peer …`. on
the next repaint the passage file's mtime and size differ from the fingerprint, so the cache is a
miss; the render runs (no repo-wide glob — the cached route's bind flag still stands), the line
becomes `🗿 4.execution, yield 🌾`, and the cache is rewritten. the glance that follows the
command already shows the new stone.

## .bdd sketch

```
given('[case2] a bound route at 3.blueprint, cache warm with its line')
  when('[t0] a passed entry for 3.blueprint is appended to passage.jsonl')
    then('the next repaint prints 🗿 4.execution, yield 🌾')
    then('the render runs exactly once for that repaint')
    then('the cache now holds the new line and fingerprint')
  when('[t1] the line repaints again with no further write')
    then('it prints the same new line, and the render does not run')
```
