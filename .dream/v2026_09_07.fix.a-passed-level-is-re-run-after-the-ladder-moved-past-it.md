## .the cue that fired

the wisher asked it outright:

> *"should we just never reopen lower levels once we cross to higher levels of reviewers? e.g., once
> l1 passes, never run them again?"*

## .the gap, precisely

the ladder advances when a level goes terminal, and **it does not remember that it advanced.** every
subsequent round re-runs every level from l1 up. so a rubric that read the diff and approved it is
asked again, and again, at a fresh brain call each time.

the extant cache is keyed per **round**, not per **ladder**:
`howdoes.the-guard-caches-a-clean-lane-by-artifact-hash` reuses a lane that returned 0 blockers at an
unchanged hash — which is the right mechanism at the wrong scope. the moment the hash moves for a
reason l1's rubric does not govern (a `.taken` written to answer l3, say), l1 re-runs in full.

| the cost | how it lands |
|---|---|
| **brain calls** | `levels × lanes` per round, where `latest × lanes` would do |
| **context** | every re-run lane carries the whole `--conversation` payload |
| 🔴 **it is the engine of the loop** | more lanes per round ⇒ more overflow ⇒ more minted debt ⇒ more `.taken` ⇒ a larger payload |

## 🔴 .the shape of the fix — and the one word that carries it

> once every lane at level N returns **0 blockers**, level N is **settled** for that artifact hash.
> later rounds at levels > N do not re-run it. any change to the artifact set un-settles it.

⚠️ **the trigger must be `approved`, never `terminal`.** `rule.always.converge-to-terminal` groups
four states as terminal, and they answer a different question:

| state | terminal? | did the rubric read the code? |
|---|---|---|
| **approved** | ✅ | ✅ **yes** — safe to settle |
| exhausted | ✅ | ⛔ a spent budget is not a verdict |
| malfunction | ✅ | ⛔ the lane faulted |
| constraint | ✅ | 🔴 **the lane rendered no verdict at all** |

`terminal` answers *"may the ladder advance?"*. this proposal asks *"has this rubric read the code?"* —
and only `approved` answers it yes.

**measured on this very drive, i029: all five l1 lanes returned `constraint ✋`.** every one overflowed
its window. under a `terminal`-keyed skip, five rubrics would retire permanently though not one had
read the diff, each would still hold the blocker its unreadable verdict minted, and the tell — a lane
that never speaks again — would be indistinguishable from a lane that approved.

⇒ **the wrong trigger word converts a transient overflow into a permanent blind spot.**

### the second bound — the hash

an approval is an approval **of an artifact set**, so the settle must be keyed to it. otherwise a
driver edits code after l1 approves and l1 never sees the edit. the un-settle on any artifact change
is what keeps this a cache rather than a bypass.

### the interaction that must ship with it

a blanket `route.guard.budget --add N` re-arms **every** reviewer on the stone, which re-opens the very
levels this would settle. ⇒ **the budget scope fix and this one constrain each other**, and to ship
either alone leaves a contradiction on disk. the wisher stated both in one breath for that reason.

## .why it is not done in this round

**in scope? no.** this behavior fixes the contemplation gate — P1 gates who may *enter* a round; this
governs which lanes *run* once entry is granted. the guard's level-ladder logic
(`getAllReviewPeerMeterStatuses`, `runStoneGuardReviews`) is untouched by the diff, and a change there
is a wholly separate concern (`rule.require.review-test-changes`).

**safe? no.** a settle that fires on the wrong state permanently blinds a rubric, and the failure is
**silent** — a lane that stops to run looks exactly like a lane with no findings. that is the same
class as the fabricated snapshot baselines this round repaired: a green that proves naught.
