# case 6: the human learns the guard is off, and turns it back on

rows 31, 32 (row 33 itemized).

## .narrative

a human watches a crew's session in a tree that lacks the learner link. the crew never stalls, but under each tool call the transcript shows a notice: `memory.guard hook error`, and its line says the guard could not run, the call was allowed, and the fix is `npx rhachet roles link --repo bhrain --role learner`. the human runs it. from the next call on, the notices stop and the guard judges again. had the human left it be, the crew would keep its flow and the notice would keep its watch, one line per call.

the notice is the whole safety story of fail-open, which is why it rides on exit 1: claude code shows a hook's stderr to the human only for a non-0, non-2 exit, and never for exit 0.

## .bdd sketch

```
given a tree with the learner hook in settings and no learner link
  when [t0] a crew's Bash `ls` fires the hook
    then the call proceeds
    then the human sees a `memory.guard hook error` notice
    then the notice holds the fault and `npx rhachet roles link --repo bhrain --role learner`
  when [t1] the human runs the fix
    then .agent/repo=bhrain/role=learner/skills/memory.guard.sh exists
  when [t2] the crew's next Bash `ls` fires the hook
    then exit 0, silent: the guard ran
```
