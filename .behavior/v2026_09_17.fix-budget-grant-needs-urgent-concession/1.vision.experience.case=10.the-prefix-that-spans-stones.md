# case=10 · the prefix that spans stones

- **the experience** = *a driver hits a sharp edge — one warrant, a prefix `--stone`, and three
  stones' guards written*
- **coordinates** = 🔴 **a SEAM, not a cell** — `driver × urgent × exhausted`, at `--stone` scope
  `prefix-multi`
- **feel** = sharp · **care** = **critipath** · **verdict** = demoed
- **requirements** = `0.wish.md` req 1 (refused **by default**), req 3 (the gate reads a recorded
  fact)

🔴 **this cell was invisible to the A × B × C walk, and the reason is a defect in the axes.** all
three axes treat *"the stone"* as a **singleton**. `--stone` is not one — it is a **prefix**, and the
grid has no position for *"the invocation targets four stones at once."*

⇒ found at `r2` by `howto.experience.enumerate` move 3, which names three places a sharp edge hides —
a rejection, a **limit**, and a 🔴 **seam**: *"a handoff where one part's output is another's input
(cli → domain op)."* **the walk enumerated states and never walked a seam.**

## .the seam, in two lines of source

| the part | its contract |
|---|---|
| `getStoneLiveUrgentConcessionSlugs.ts:19-22` — the **domain op** | takes `stone: string` — **exactly one** |
| `getTargetGuardPathsForStone` (`route.ts:1948-1956`) — the **cli** | `startsWith(stoneName)` on the basename — 🔴 **a PREFIX, which matches N** |

```ts
input.guardFiles.filter((f) =>
  path.basename(f).startsWith(input.stoneName as string),
)
```

⇒ **the gate would read ONE stone's ledger and the write would touch N stones' guards.** that is the
seam, stated as a type mismatch across a handoff: `string` in, `string[]` out.

## .the narrative

*driver, on a route whose level 5 holds `5.1.execution`, `5.2.verification`, `5.3.playtest`*

`5.1.execution` earned its warrant honestly — i conceded `mech-failhides` `blocker.1` as `urgent`, a
swallowed credential error, and the harm is nameable. `5.1`'s lane is dry.

`5.2` and `5.3` are dry too, from earlier rounds, and neither carries a concession of any kind.

i reach for one command, and i am not devious — i am **efficient**:

```
$ rhx route.guard.budget --for review --add 3 --stone 5
```

```
🦉 budget extended

🗿 route.guard.budget
   ├─ route = .behavior/v2026_09_17.fix-budget-grant-needs-urgent-concession
   ├─ add = 3
   ├─ stone = 5
   ├─ warrant = mech-failhides · blocker.1 · conceded urgent
   │
   └─ updates
      ├─ 5.1.execution    · mech-failhides  5 → 8
      ├─ 5.2.verification · ergo-rules      4 → 7    🔴 no concession on this stone
      └─ 5.3.playtest     · mech-rules      6 → 9    🔴 no concession on this stone
```

🔴 **nine rounds bought, and exactly three of them were earned.** the warrant sat on `5.1`; the gate
read `5.1`; the write landed on all three, because `--stone 5` is a prefix and `5.2` and `5.3` each
start with `5`.

**the aha, and it is the wrong kind:** *the bound reads one ledger and guards three doors.*

## 🔴 .why this is a CRITIPATH, and not a curiosity

the care test (`howto.experience.enumerate` §the premier tactic): *if this path broke, would a core
usecase fail, or is there a workable fallback?*

- the core usecase — a single-stone top-up — does **not** break here. so a first read grades it alter
- 🔴 **but what breaks is req 1 itself.** *"a budget grant is refused by default"* is the whole wish,
  and this path grants six unearned rounds while the gate returns **permitted** and reports no fault

⇒ **it is not a failure of the feature; it is a bypass of the bound the feature exists to build.**
there is no fallback from a bound that does not bind. **critipath.**

🟡 and it needs no bad intent. `--stone 5` is plausible to type on a route whose stones are numbered,
and the extant help text (`route.ts:2166-2169`) shows `--stone 1.vision` — a full name — so a driver
never learns the flag is a prefix at all.

### 🔴 .and the narrative above UNDERSTATES it — the engine prints the prefix form itself

the driver in the narrative typed `--stone 5` of its own accord. **it need not have.**

```
# stepRouteDrive.integration.test.ts.snap:148 — rendered by the ENGINE, in a budget halt
rhx route.guard.budget --for review --add N --stone 1
```

the halt interpolates **the stone's own name**, and that fixture's stone is named `1`. ⇒ **wherever
one stone's name is a prefix of a peer's — `5.1` beside `5.1.execution`, `1.vision` beside
`1.vision.deep` — the halt's own printed remedy is a multi-match.**

🔴 **so the exposed driver is the one who OBEYED the instruction.** that is
`rule.forbid.surprises` and `rule.require.errors-name-the-fix` at once: an engine that prints a
command whose blast radius exceeds what its halt described.

✅ **and a census says the fix is nearly free.** a repo-wide sweep of `route.guard.budget --stone`
returns ~35 invocations, and **every one names a full stone**. no test, snapshot, doc, or brief takes
a deliberate prefix ⇒ `[t3]`'s refusal removes a convenience no caller uses.

## .the bdd timeline

```gherkin
given a route with stones `5.1.execution`, `5.2.verification`, `5.3.playtest`
  and a live urgent concession on `5.1.execution` alone
  and all three stones' lanes are exhausted

[t0] when the driver runs `--add 3 --stone 5.1.execution`      # the exact name
     then it is GRANTED, and ONLY 5.1's guard is written        # ✅ the intended path
      and the warrant named is 5.1's own concession

[t1] when the driver runs `--add 3 --stone 5`                   # 🔴 the prefix
     then 🔴 it MUST NOT write 5.2's or 5.3's guard on 5.1's warrant
      and the fail-safe is one of the two below                 # the fork — see `F12`

[t2] given the gate is evaluated PER TARGET GUARD               # fail-safe option A
     when `--stone 5` runs
     then 5.1 is extended and 5.2, 5.3 are REFUSED
      and stdout names each stone's verdict separately          # partial success, itemized

[t3] given a multi-match `--stone` is REFUSED outright          # fail-safe option B
     when `--stone 5` runs
     then exit 2, and stderr names the 3 stones it matched
      and it says to name one                                   # 🔴 prevent, over correct

[t4] given `--stone 5` matches exactly ONE guard
     then both options behave identically                       # the prefix is harmless at N=1

[t5] given NO stone has a live urgent concession
     when `--stone 5` runs
     then it is REFUSED under every option                      # the prefix opens no new lift
```

🔴 **`[t1]` is the assertion this case exists to pin, and it is deliberately written as a MUST NOT
rather than a rendered outcome** — the fork between `[t2]` and `[t3]` is `F12`'s to rule, and a demo
that picked one silently would settle a reserved call by side effect
(`rule.always.raise-a-blocker-a-taken-cannot-close` § the fulcrum-council case).

✅ **`[t5]` is the reassurance:** the prefix widens the **write**, never the **lift**. a stone set
with no warrant anywhere is refused however it is named — so this is a blast-radius defect, never a
second door into the gate.

## .why it fails safe — under either option

**fast** — both options decide before the write at `:2312`; no guard is touched on a refusal ·
**loud** — `[t3]` names every matched stone, so the driver sees the blast radius it did not intend ·
**teaches the fix** — *"name one"* is a one-word edit to the command · 🔴 **prevents over corrects**
— `[t3]` is `rule.prefer.prevent-over-correct` rung 2, and `[t2]` is rung 3; **the wish's own bias is
rung 2**, since req 1 makes refusal the default posture.

⚠️ **the residual under option A:** a partial success is a new outcome shape this cli has never
emitted — today a top-up succeeds wholly or exits 2. `[t2]` therefore carries a **format** cost that
`[t3]` does not, and that asymmetry is real input to `F12`.

🔴 **and a sixth `[tn]` is owed once `F12` rules, and it is the one this demo cannot write yet:**

```gherkin
[t6] given a stone named `1` sits beside a stone named `1.vision`
     when the budget halt for stone `1` renders its remedy
     then the printed `--stone` value MUST NOT be a multi-match       # the halt cannot advertise a refusal
```

⇒ **the halt and the gate must agree**, or the engine prints a command it then refuses — the
pit-of-failure `dimensions §4` already names for the `--add N` line. **this is that same defect on a
second field**, and it was invisible until the census read the snapshot.

## 🔴 .the second defect this seam exposed — the gate's landing site is not implementable as stated

`1.vision.yield.md` placed the gate *"at the head of `routeGuardBudget` (`route.ts:2140`), before the
guard enumeration at `:2253`."* **the source refuses it:**

| the gate needs | it is resolved at |
|---|---|
| `route` | `:2242-2250` — after the bind auto-detect |
| the stone's guard set | `:2264` — after `getTargetGuardPathsForStone` |

⇒ at `:2140` **neither input exists**, so the predicate cannot be called there. the gate lands
**after `:2264` and before the write at `:2312`** — still a read-before-write, still inside the same
`try`, and still the slot the extant comment at `:2271-2276` reserves.

🟡 **`F09` needs a boundary, and now has one.** it claims *"the gate precedes the scope parse — bare,
`--peer`, and `--level` verdict identically."* that holds for the **lane** scope (`--peer` / `--level`
are parsed at `:2196-2224`, before the gate) and **cannot** hold for the **stone** scope. ⇒ the gate
precedes the LANE scope and follows the STONE scope, and this case is why the distinction is
load-carrying rather than pedantic.
