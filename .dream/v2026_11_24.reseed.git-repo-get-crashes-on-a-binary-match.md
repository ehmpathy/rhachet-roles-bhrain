# 🌙 dream: git.repo.get crashes on a binary match

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy, role=mechanic (`git.repo.get`)
- caught 2026-11-24

## .the cue that fired

`rhx git.repo.get lines --repos 'ehmpathy/*' --words 'bhrowser'` printed the first match, then exited 1:
`git.repo.get.operations.sh: line 1593: printf: pnpm-lock.yaml matches: invalid number`. the match
came from `git grep`'s line `Binary file origin/main:pnpm-lock.yaml matches`, which the render parsed
as a `path:line:text` row.

## .the gap, precisely

a binary-file notice from `git grep` is read as a match row; its "line number" is the text
`pnpm-lock.yaml matches`, and `printf %d` refuses it. the search halts at the first repo with a binary
hit, so the rest of the org is never searched.

## .the shape of the fix

pass `-I` to `git grep` (skip binary files), or skip lines that start with `Binary file`. a suite
with a temp repo that holds a binary file whose bytes match the words: red before, green after.

## .why it is not done in this round

the skill lives in rhachet-roles-ehmpathy, another repo.
