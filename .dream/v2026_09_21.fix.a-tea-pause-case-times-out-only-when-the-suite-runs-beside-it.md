# 🌙 dream: give the tea-pause case a duration budget its own workload can meet

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-21

## .the cue that fired

a route-wide unit run went red on exactly one case, and the same case went green on its own
minutes later. two runs, one file, opposite verdicts, no edit between them:

| the run | scope | the verdict |
|---|---|---|
| `--what unit --scope 'path://route'` | 172 suites, 1712 tests | ✋ `1 failed` — `[case7] [t0]` |
| `--what unit --scope 'path://stepRouteDrive'` | 1 suite, 29 tests | 🎉 `29 passed` |

the failure is not an assertion at all:

```
thrown: "Exceeded timeout of 30000 ms for a test."
  ✕ then: output does NOT contain tea pause (30018 ms)
  at src/domain.operations/route/stepRouteDrive.test.ts:361
```

⇒ **a verdict that changes with what runs beside it is a verdict about the machine, never about
the code.**

## .the gap, precisely

`stepRouteDrive.test.ts:360-375` — `[case7] tea pause after 5+ hooks`, `[t0]`:

```ts
when('[t0] fewer than 6 hooks triggered', () => {
  then('output does NOT contain tea pause', async () => {
    // call with when=hook.onStop 3 times (count 1, 2, 3)
    for (let i = 0; i < 3; i++) {
      await stepRouteDrive({ route: scene.tempDir, when: 'hook.onStop' });
    }
    const result = await stepRouteDrive({ … });
```

**four sequential `stepRouteDrive` calls against the default 30s jest budget.** each call reads a
route dir, steps the drive, and writes a hook count, so the case is ~7.5s per call away from red
and nothing in the file says so.

the checkable evidence that it is contention rather than a hang: its own sibling, which does the
identical work, **also nearly exhausted the budget in the same run**:

| case | what it does | duration, route-wide run |
|---|---|---|
| `[t0]` | 4 × `stepRouteDrive` | 🔴 `30018 ms` — killed at the bar |
| `[t1]` | 3 × `stepRouteDrive` | `22013 ms` — **73% of the budget, green** |
| `[t2]` | 1 × `stepRouteDrive`, snapshot | `8269 ms` |

⇒ `[t1]` is the tell. it passed, and it passed with 8s of headroom on a 30s bar — so the budget
was already the binding constraint for the whole `given`, and `[t0]` merely has one more call.

⚠️ **the case is not slow because it is broken.** it performs four real drives on purpose — the
hook counter is what it grades, and a counter needs increments. the work is legitimate; the
budget was never sized for it.

## .the shape of the fix

two moves, and the second is the one that pays:

1. **name the budget where the work is** — `then('…', async () => { … }, 60_000)`. jest takes a
   per-case timeout as a third argument, so this is one token and it is honest: it states that
   four subprocess-grade drives do not fit in 30s.
2. 🔴 **and say WHY in a `.note`**, or the next reader deletes it as cruft. the note owes the
   arithmetic above — *four drives, ~7.5s each under load, `[t1]` measured at 22s of a 30s bar* —
   since a bare `60_000` reads as a mask for a hang, which is precisely what it is not.

the deeper fix, and the reason this is a dream rather than a one-liner: **~7.5s for one
`stepRouteDrive` is itself a number nobody has justified.** a case that spends 30s to assert
that a string is ABSENT is paying subprocess cost for a pure-ish read. whether the drive can be
exercised without four full passes is a question for whoever owns that operation, and answering
it retires the budget question rather than raising the bar.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.**

- `stepRouteDrive.test.ts` is **not in this round's diff.** the round repairs the self-review
  gate — the trigger's hash key, the printed path, the rewind's cleanup, the haste cue. the tea
  pause is a different operation on a different surface
- the timeout is a one-token edit, and the edit **without** the arithmetic behind it is the
  defect it looks like a fix for. the arithmetic needs a measured read of `stepRouteDrive`'s
  cost, which is the dirty half
- ⚠️ and the honest bound: **a raised bar is not a repair.** it converts a flake into a slow
  green, which is better than a flake and is not the same as understanding why one drive costs
  seven seconds. to ship the bar as though it closed the question would be the worse outcome

⇒ so the deferral is for DIRT rather than size, and it owes no fulcrum: the call to leave a
foreign test file alone inside a scoped round is `rule.require.review-test-changes`'s own
instruction, not a judgment this round made.

## 🔴 .a SECOND instance, at i018 — and it is not a duration at all

`driver.route.peer-concurrency.acceptance.test.ts` `[journey][t0]` carries a clamp that observes
the scheduler:

```ts
expect(observed.l1Count).toEqual(4);   // ✅ green in both runs — all four lanes DID run
expect(observed.l1Peak).toEqual(4);    // 🔴 red at 3, in the full run only
```

| the run | `l1Count` | `l1Peak` | verdict |
|---|---|---|---|
| full acceptance suite, 130 suites in parallel | 4 | **3** | ✋ red |
| that one suite alone | 4 | 4 | ✅ green — 64 passed |

⚠️ **so the class is wider than a timeout.** this clamp has no duration in it. it asserts that
four subprocesses were aloft **at the same instant**, which is a claim about the machine's
scheduler under whatever else holds the cpu. `l1Count === 4` — the claim the case is named for,
that the pour is concurrent rather than serial — held in **both** runs.

⇒ the two clamps are not the same strength. `l1Count` parts concurrent from serial, which is the
behavior under test. `l1Peak` additionally demands that no lane ever finished before the last one
started — **true of the code, and guaranteed by no machine.**

🔴 ⇒ the generalized cue: *a clamp whose subject is the CODE but whose measurement is the
MACHINE is green in proportion to how idle the box is.* both instances found so far were found the
same way — by a route-wide run — and both were parted from regressions by one isolated re-run.

## 🔴 .a THIRD instance, at i022 — and it puts a number on the limit

a full 130-file acceptance run (3125s) went red on **9 suites, 73 tests**. the same corpus, scoped
to its 90 `driver.route.*` files, had run **2544 passed, 0 failed** an hour earlier. every suite
below is green alone:

| suite | red at 130 files | green at 90 files | green alone |
|---|---|---|---|
| `driver.route.self-review` | ✋ | ✅ | ✅ |
| `driver.route.drive` · `contemplated-help` · `optional-skip` | ✋ | ✅ | ✅ |
| `driver.route.peer-budget-bulk` · `peer-budget-defaults` · `peer-contemplation-precedence` | ✋ | ✅ | ✅ |
| `review.join-intersect` · `achiever.goal.triage.next` | ✋ | — | ✅ |

⇒ **the corpus has a parallel-load limit somewhere between 90 and 130 suite files**, and above it
the verdict is about the box. that is a repo-wide property, and it is the first time it has been
bracketed rather than merely observed.

🟡 **one of the nine was a real defect of the class, and it was repaired at i022** — the self-review
suite's four haste-cue sites each demanded that the scene plus every prior leg finish in under 30s.
the repair recast the precondition as an order of operations (`freshenAskAndArticulation`), so the
clock left those four cases. ⇒ **the other eight were not touched**, and this dream is where they sit.

⚠️ **the honest read of that split: the load limit did not CAUSE the self-review red — it REVEALED
it.** a fixture that reads a wall clock is defective at any load; heavy load only shortens the fuse.
so the two halves want different repairs, and a raised limit would have hidden the real one.

## .the transferable half

> **a duration budget is a CONTRACT with a workload, and a default is a contract nobody signed.**

jest's 30s is a global default chosen with no knowledge of any case. every case that does real
work is therefore sized by an accident, and the ones near the bar are invisible until a parallel
run pushes them over. ⇒ **the cue is not the red run — it is the green sibling at 73% of budget**,
and no gate reports that number unless a human reads the durations.

⇒ see also: `rule.forbid.thorough-test-runs` (why the route-wide run is the rare one that finds
these) · `rule.require.clamp-edge-cases` (a clamp must go red for the RIGHT reason — a timeout
is red for a reason the assertion never names).
