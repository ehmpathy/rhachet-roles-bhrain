# case 5 — the-hook-says-to-itself

## .the narrative

i am the driver, enrolled as `@:driver`, live, and the guard for the next stone prescribes opus. the
hook fires. it does the obvious move — the move the wish itself spells out:

```sh
rhx clone whoami
rhx clone say @:driver --what '/model claude-opus-5[1m]'
```

`whoami` returns my address. correct. `clone say` connects to my socket, writes the message to my
pty input, and gets its `delivered` ack. also correct.

then `clone say` does the check that makes it trustworthy: it refuses to call that success. a
hand-off ack proves bytes arrived, never that the brain submitted them — so it polls my transcript
until the message appears as a real user turn.

**and it will wait there until it dies.**

because *i* am the brain that must submit it. and i am not free to submit aught: i am blocked, right
now, inside the hook that holds this poll open. the submit `clone say` waits for cannot happen until
the hook returns, and the hook cannot return until the submit happens.

the deadlock does not even get to resolve itself honestly. `clone say` would give up at 15s with a
`MalfunctionError` that names the fix — but my hooks are capped at 5s, so the hook is killed first.
what a human sees is not a deadlock and not a failed switch. it is a hook that timed out.

> `timeout: 25`, so the 15s verify DOES complete and the `MalfunctionError` IS reached. the

>
> ⚠️ **the deadlock is unchanged, and so is every conclusion this case draws.** a raise moves the

```
CLONE_SUBMIT_VERIFY_TIMEOUT_MS = 15000     # constants.js:30
"timeout": 5                               # every driver hook, .claude/settings.json
```

⇒ **the "aha": the hook is not an outside caller. it runs inside the very clone it addresses.**
every mental model of `clone say` — reach *into* a clone *from* outside — is the wrong model here,
and it is wrong in a way that a design review reads straight past, because the command is verbatim
correct.

the fix is not a longer timeout. a longer timeout deadlocks longer. the fix is that **the hook must
hand the switch off, never wait on it**: dispatch, return at once, and let the queued `/model` land
on my next read of my own input. the confirmation that it landed belongs to case 3's live-brain
check, on the next turn — not to a poll the hook holds open against itself.

## .the bdd `[tn]` timeline

```
given a driver enrolled as @:driver, reach=LIVE
  and  a driver-role hook that dispatches the switch synchronously and waits on it
  and  a hook timeout of 5s (.claude/settings.json) against a submit-verify of 15s (constants.js:30)

  when [t0] the driver enters a stone that declares a brain
    then the hook fires, and the driver's brain is blocked for the whole time the hook runs

  when [t1] the hook calls `rhx clone say @:driver --what '/model claude-opus-5[1m]'`
    then sayClone connects, writes, and gets its `delivered` ack — the bytes reach the pty input
    and  clone say then polls the driver's transcript for the submit, up to 15s

  when [t2] the poll waits for a submit only this driver can perform
    then the submit cannot land, because this driver is blocked on this very hook
    and  the wait is a deadlock, not a slow path — no elapsed time resolves it

  when [t3] 5s elapse
    then the hook timeout kills the hook BEFORE the 15s verify can fail loud
    and  the MalfunctionError that would have named the fix is never raised
    and  the failure surfaces as a slow hook, never as a failed brain switch

  when [t4] the hook is rebuilt to hand the switch off rather than wait on it
    then the hook returns at once, well inside its 5s budget
    and  the queued `/model` lands when the driver next reads its own input
    and  the switch is confirmed on the NEXT turn by the live-brain check (case 3, [t2])
```

## .the fail-safe grade — graded on BOTH builds

🔴 **two of the four rows depend on `F5`, and until peer review r3 the table did not say so.** they
cite `case=3`'s live-brain check, and `case=3` is itself graded on two builds precisely because that
check cannot be built if `F5` is refused. a grade that borrows a neighbour's fail-safe inherits the
neighbour's dependency, and this table hid that.

| obligation | with `F5` — the halt exists | 🔴 without `F5` — the label exists |
|---|---|---|
| **fast** | ✅ `[t4]` — the hook returns at once. it never enters a wait it cannot exit | ✅ **identical.** the hand-off is `F5`-independent |
| **loud** | ✅ the confirmation moves to the next turn's live-brain check, which **halts** on a mismatch | 🟡 the record reads `requested — unconfirmed` (`case=3` `[t6]`). a label on every brain line, never a halt |
| **teaches the fix** | ✅ a failure surfaces through `case=3`'s message, which names both brains, rather than as an unattributed hook timeout | ✅ `case=3` `[t8]` — the `unconfirmed` label names where to look and what to ask for |
| **holds the limit** | ✅ the hand-off has no wait, so no hook-timeout budget can be exceeded — for any message length, on any host | ✅ **identical, and it is the limit this case exists for** |

⇒ 🔴 **the deadlock is avoided in both builds.** `fast` and `holds the limit` — the two obligations
this case is actually about — rest on the hand-off alone, and the hand-off asks naught of rhachet.
what a refusal of `F5` costs here is **only** the `loud` row: a failed switch surfaces as an honest
label rather than as a halt.

### 🔴 and the `loud` row survives a refusal too — found 2026-09-10

`[t4]` already places the confirmation *"on the NEXT turn"*, and **that is exactly the turn `rhx clone
get` can run in.** the queued `/model` has landed, the brain has replied, and the reply is on disk in
the brain-cli's own transcript — which `clone get` reads, with no reach probe and no cred gate
(`case=3`, *the open question*).

| the row | with `F5` | 🔴 without `F5`, via `clone get` |
|---|---|---|
| **loud** | ✅ a halt on a live-brain mismatch | ✅ **a halt on the brain's own refusal** — no ask on rhachet |

⇒ 🔴 **so the hand-off at `[t4]` is not merely `F5`-independent, it is what makes the free detection
possible.** a hook that waited would read a transcript the reply has not reached yet; a hook that
hands off returns, and the next turn reads a transcript that has it. **the fix for the deadlock and
the enabler of the free check are one design move.**

⚠️ what a refusal of `F5` still costs here is narrower than the table above states: not the `loud`
row, but the **silent-refusal** corner of it — a brain that declines without a word leaves the next
turn with no reply to read.

⚠️ so `F5` is not a dependency of **this** case's safety. it is a dependency of the **confirmation**
this case delegates, and the delegation is what carries the dependency in. that distinction is why
the row was easy to miss: the hand-off is the fix, and the hand-off is unconditional.

## ⚠️ .why this is a critipath and not a maintenance note

it fails the coverage test in the worst way: **the naive build is the one the wish describes.**

the wish's application sequence is `clone whoami`, then `clone say`. run those two commands from a
hook, in order, exactly as written, and the feature deadlocks on its own happy path. no test of
`clone say` catches it, because `clone say` is correct. no test of the guard parser catches it. it
appears only when the two are composed in the one context this feature must run in.

⇒ **freq × cost:** frequency is *every stone entry that declares a brain* — the core usecase. cost
is a 5s stall plus a switch that silently did not happen. there is no workable route around it.

## .the invariant this case establishes

> **a driver-role hook must never wait on its own brain.** any dispatch a hook makes into its own
> clone is fire-and-hand-off; the confirmation belongs to a later turn, never to the hook.

this is broader than the brain switch. it binds any future hook that reaches for `clone say`, so it
is externalized rather than left in this route's yield alone:
