# 🌙 dream: the rewind's cleanup glob never matches a self-review trigger

**kind** `fix` · **owner** `rhachet-roles-bhrain` · **caught** 2026-09-17

## .the cue that fired

a self review on `v2026_09_17.fix-self-review-min-duration` asked what invalidates a trigger report
once the round makes it hashless. the declared answer is the rewind's cleanup. a read of that
cleanup showed it cannot fire.

## .the gap, precisely

`delStoneGuardArtifacts.ts:42-45` collects the trigger markers to delete:

```ts
const triggerFiles = await enumRouteFiles({
  route: input.route,
  glob: `.route/${input.stone}.guard.selfreview.*.triggered.*.md`,
});
```

`getSelfReviewTriggeredReport.ts:19-21` names those markers:

```ts
const baseFilename = `${input.stone}.guard.selfreview.${input.slug}.${input.hash}.triggered`;
const sincePath = path.join(input.route, '.route', `${baseFilename}.since`);
const uptilPath = path.join(input.route, '.route', `${baseFilename}.uptil`);
```

**the markers end in `.since` and `.uptil`. the glob demands `.md`.** `enumRouteFiles` is a plain
`fast-glob` pass (`enumRouteFiles.ts:22`), so the pattern matches zero markers, always.

⇒ `delStoneGuardArtifacts` returns `triggers: { promises: 0 }` on every rewind, and its own docblock
— *"deletes all guard artifacts for a stone"* — is false for this class.

**measured** on `.behavior/v2026_09_17.fix-self-review-min-duration/.route/`: 13 trigger markers,
2 promise files. the promise glob (`…guard.promise.*.md`) ends in `.md` and matches; the trigger
glob matches naught.

## .the harm

a rewind clears the **promise** and keeps the **clock**. so on a rewound stone the driver is asked
for the self review again, the `.since` that survived is arbitrarily old, elapsed reads as satisfied,
and a **stale articulation from the prior round clears on the first attempt** — the exact failure
`case=6` of that wish's vision exists to forbid.

🔴 **it is worse under the hashless change that wish proposes.** today a new artifact generation
mints a new report, which masks the leak. with no hash there is one report per `(stone, slug)`, and
the broken cleanup becomes the **only** invalidation mechanism the gate has.

## .the shape of the fix

```diff
- glob: `.route/${input.stone}.guard.selfreview.*.triggered.*.md`,
+ glob: `.route/${input.stone}.guard.selfreview.*.triggered.*`,
```

⚠️ **check the two peer globs in the same operation before the change lands.** the promise glob is
correct (`.md` is the real suffix), and `.route/${stone}.blocked.triggered` carries no suffix at all
— so this operation already mixes three filename shapes, and a blanket edit would over-match.

## .the clamp

a test that rewinds a stone which has self-review trigger markers on disk, and asserts:

1. the returned `triggers.promises` count equals the marker count (today: `0` vs `N`)
2. no `…triggered.since` or `…triggered.uptil` remains under `.route/` for that stone

**dogfood it**: revert the glob to `.*.md`, watch it go red; restore, watch it go green. a clamp
that passes under the un-fixed glob does not exercise the defect.

## .why it is not done in this round

**SAFE** — yes; the change is one glob in one operation.
**CLEAN** — 🔴 **no.** the round that found it is at the `1.vision` stone of a behavior, and a vision
emits no code. the repair also touches `setStoneAsRewound`'s snapshot (the reported counts change
from `0` to `N`), which is a test-artifact change outside that stone's diff.

⇒ so it is deferred for **scope**, not for dirt. the wish it was found under records it as fulcrum
`F10`, since that wish's core change makes this cleanup load-bearing.
