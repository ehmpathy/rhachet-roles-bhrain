# 🌙 dream: a stray `.snap` in a gitignored scratch dir fails the unit gate, and reports `0 failed`

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, on `.behavior/v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

the unit gate failed with a verdict that names no failure:

```
├─ status
│  └─ ✋ failed (15s)
├─ stats
│  ├─ suites: 176 files
│  ├─ tests: 1522 passed, 0 failed, 0 skipped
```

⇒ **`0 failed`, and exit 2.** a driver who reads the summary alone has no thread to pull. the cause
sat only in the log:

```
Snapshot Summary
 › 2 snapshot files obsolete from 2 test suites.
   ↳   • .log/tmp-main-guard-peer.snap
       • .log/tmp-main-review-by-acceptance.snap
```

## .the gap, precisely

`.log/` is **gitignored scratch** — the repo's own convention for it, and `git.repo.test` writes its
own run logs there. jest's snapshot resolver does not read `.gitignore`, so any `.snap` a traveler
parks in `.log/` is collected, reported obsolete, and **fails the run** under
`ci: true` / `--ci` semantics.

the two files here were baselines saved from `main` mid-repair, to diff a restore against. that is
exactly the use `.log/` exists for.

🔴 **the sharp part is the SIGNAL, not the config.** three readings of the summary are available and
they disagree:

| what the summary says | what is true |
|---|---|
| `0 failed` | correct, and it is why the driver stalls |
| `176 suites passed` | correct |
| `✋ failed` | correct, and unattributed |

⇒ a gate that fails on a condition its own summary reports as clean will be read as a flake, and the
cheap response — re-run it — never clears it.

## .the shape of the fix

two halves, and the second is the one that matters more:

1. **exclude the scratch dir from snapshot resolution** — add `.log/` to `testPathIgnorePatterns`
   (and its peers) in `jest.unit.config.ts` and `jest.integration.config.ts`. the repo already
   carries `!**/.scratch/**` in both for exactly this class of problem, so this is one more entry in
   an extant list rather than a new mechanism
2. 🔴 **surface the cause in the summary.** `git.repo.test` already parses the jest tail for
   `tests: N passed`; an obsolete-snapshot count belongs beside it. a `snapshots: 2 obsolete` row
   would have turned a five-minute log read into a glance

⚠️ option 1 alone is insufficient. it closes `.log/` and leaves every other gitignored dir open, and
the next traveler meets the identical unattributed failure somewhere else.

## 🔴 .amended 2026-09-07 — `rmsafe` CANNOT remove a stray `.snap`. the delete relocates the failure

**measured this round, and it makes the "just remove the file" remedy above false as written.**

a guard lane wrote `.scratch_audit/main_guard_peer.snap` into the worktree mid-round. the unit gate
failed with the same unattributed `0 failed` + exit 2. the obvious repair — remove it with the
repo's own sanctioned delete tool — **moved the failure rather than closed it:**

```
$ rhx rmsafe --path '.scratch_audit/main_guard_peer.snap'          # → trash
$ rhx git.repo.test --what unit --mode apply --thorough            # → ✋ failed, again
   ↳ • .agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/.scratch_audit/main_guard_peer.snap
```

⇒ 🔴 **`rmsafe`'s trash lives INSIDE the repo, and jest collects from it.** so the one tool a driver
is permitted to delete with cannot delete a `.snap` at all — it relabels its path and the gate fails
on the new one. it took a **second** `rmsafe`, aimed at the trash copy, to clear it (that one reports
`(not trackable)` and deletes outright rather than nests, so there is no infinite regress).

| the trap | why it bites |
|---|---|
| the sanctioned tool is the one that fails | a driver reaches for `rmsafe` **because** raw `rm` is denied |
| the second failure names a **different** path | it reads as a new defect, not the same file |
| `.agent/**` **is** in `testMatch`'s ignore list (`:35`) | ⚠️ **and that governs test DISCOVERY, never obsolete-snapshot collection** — the exclusion looks like it should have covered this and does not |

⚠️ **that last row sharpens fix #1 above.** `testPathIgnorePatterns` / `testMatch` are not the knob
that stops obsolete-snapshot collection; the entry must reach the config key that governs it, and it
must cover **`.agent/.cache/`** — the trash of the repo's own delete tool — rather than only the
scratch dirs a human picks.

⚠️ **and the extant ignore was `.scratch`, while the dir here was `.scratch_audit`.** a prefix that
does not match is indistinguishable from an absent rule at the moment it fails.

## .why it is not done in this round

**in scope? no.** this behavior fixes the contemplation gate. the jest configs and the
`git.repo.test` summary parser are untouched by the diff, and a change to either is a wholly
separate concern (`rule.require.review-test-changes`).

**safe? no.** `testPathIgnorePatterns` governs which suites run at all. a mistaken pattern silently
stops collection of real tests, which is the same class of failure as the fabricated baselines this
very round restored — a green that proves naught.

⇒ the local half was done: the two stray files were removed and the gate is green at
**1522 passed / 176 suites**. what is deferred is the mechanism.
