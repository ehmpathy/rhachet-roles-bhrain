## .what it is NOT — two candidates ruled out by read

| candidate | ruled out because |
|---|---|
| the **stamp** is stale | `setStoneAsPassed.ts`'s `stampGuardReport` helper passes the emit through **verbatim** to `setStoneGuardStamp`. the stamp does not compute a verdict; the divergence is already inside the emit |
| `computeReviewPeerVerdict` is wrong | it is pure and correct — it returns `malfunction` from the `exitClass` it is **handed**. so the stale value reaches it, rather than originates in it |

⚠️ **these cited `setStoneAsPassed.ts:363-374` and `:43`.** both were accurate when read and both name
files this branch edits heavily, so **the numbers were fused and the expressions are not**.

⇒ the defect is in what the **meter** holds for that slug after a fresh round, or in which meter row
`formatGuardTree` reads. those are a write-side and a read-side hypothesis and this dream does not
choose between them — that determination is the first step of the fix.

## .the shape of the fix

1. **determine the side.** after a fresh approved round on a slug that previously malfunctioned, does
   `.route/reviewPeerMeters.jsonl` hold a new row with `exitClass: 'passed'`? yes → a **read-side**
   defect in the meter read (which row wins). no → a **write-side** gap (the fresh round wrote none)
2. **fix at that side**, then resnap the two `[t1]` entries above
3. **clamp it** — the assertion is *"the live verdict and the guard-tree verdict for one `given` path
   agree"*, and it goes red under the un-fixed engine. the two snapshots already added are the
   evidence; a structural assertion beside them is what makes it bite

## .why it is not done in this round

**not clean.** the repair touches the meter's read-or-write path, which is the exact surface **P2**
widened (latest-given-per-slug across hashes). a second change there, un-clamped, risks the
contemplation-debt semantics this whole behavior exists to establish — and P1/P2 are order-coupled,
so a regression there is not local.

⚠️ **and it is adjacent to a fence the wisher already set.** wish **scope item #1** —
*"per-reviewer cache keys … a reviewer's clean verdict dies on a hash change its own rule does not
govern"* — is the same meter surface, reached from the other end. to fix this here would move that
fence without an ask.

⇒ the itemized call is **fulcrum F10**; the vision's **Q1** already flags that P2 removed a
guarantee a prior author wrote down, and this is the second observation on that same surface.

## .what it costs to leave

a reader of the persisted guard report sees a reviewer marked `malfunction 💥` on a stone whose
passage is `allowed`. it misleads, and it is **shipped in a baseline**, so it also freezes.

⚠️ it does **not** gate passage — the judge reads the live verdict, which is correct. so the harm is
legibility, not correctness. that is what makes the deferral defensible and the fix still owed.
