## .said

> and we should only need to do that for the ones --conversation doesn't already resolve right?

## .settled

**a dispute is owed only where the conversation loop ALREADY FAILED — and the design must keep the
loop live, never presume it ran.**

the loop is the resolver, and it is already wired: `enumRouteGuardReviewPeerConversationFiles`
feeds a reviewer every prior `.given`, every detailed `.report`, and **every `.taken`**, minus the
current generation. so a reviewer that reads an answer and is persuaded **drops the point**, the
lane approves, and no stance, no fulcrum, and no council read is ever owed.

🔴 **a stance that silences a lane PERMANENTLY takes the loop out of the design.** requirement of
an *answer* is not requirement of a *tested* answer:

```
write .taken  →  --as disputed  →  the lane goes dark forever
```

⇒ the reviewer never reads it. a fulcrum is minted for a disagreement the loop was never given a
chance to resolve, and a human's attention is spent on what one free round would have closed.

## 🔴 .what closes it

**`S03` — the skip is per-hash-generation, never per-stone.** the lane returns the moment the
artifact moves, reads the `.taken` through `--conversation`, and either drops the point or
re-raises it. ⇒ **the loop re-engages by construction**, so no extra gate clause is owed and the
untested-answer hole closes itself.

⚠️ **the two utterances are one insight, in two halves:** this one names the loop as the resolver;
`S03` names the mechanism that keeps it in the loop.
