# 🌙 dream: a fulcrum's OPTION SET is an enumeration, and no rule asks it to be complete

**kind** — fix · **owner** — bhrain (this repo) · **caught** 2026-09-08

## .the cue that fired

three fulcrums in one round were settled by the wisher — and **not one of them was settled by a
choice between the options the fulcrum offered.** each was settled by a thing the option set had
left out:

| case | the fork as posed | what was absent | severity |
|---|---|---|---|
| F4 | floor, peak, or both? | 🔴 whether the peak was **buildable** — `\r` gives one mutable line | an **impossible** option, priced as expensive |
| F2 | default `1` or unbounded? | 🔴 a **third value** — `10` | a defensible option, never listed |
| F1 | a map, or on each reviewer? | 🔴 a **second fact** — membership vs bound, so both sites are right | a false binary |

⇒ **every fork was fairly stated, every pick was defensible given its set, and every set was short.**

## .the gap, precisely

`rule.always.itemize-the-fulcrums-you-best-guess` demands *"the fork stated fairly"* — and **fairly
is not completely.** a two-option fork can be stated with perfect fairness and still omit the option
that settles it.

⚠️ **and the confidence percentage actively conceals this.** F4 was recorded at **91%** while one of
its two options was unbuildable — the number priced the *judgment within the set*, and no field on
the record prices *the set itself*. a reader sees 91% and reads *"this call is nearly settled"*,
where the truth was *"this call is nearly settled **if the set is right**"*.

🔴 **`rule.require.enumerate-before-you-name` already carries the discipline that is absent here** —
*list every instance the word must cover, THEN pick the word* — and it is filed under the learner,
scoped to **terms**. its claim is about **choices**, and a fork is a choice. ⇒ the rule exists; its
scope is one axis too narrow.

## .the shape of the fix

**a fulcrum owes two checks its rule does not currently ask for**, both cheap and both at authorship:

1. 🔴 **is each option POSSIBLE?** — F4's lesson. an option priced but never verified buildable makes
   the fork look like a tradeoff when it is not, and inflates confidence, because *"pick the cheap
   one"* reads as judgment when the expensive one was never on the table.

2. 🔴 **is a THIRD option defensible?** — F2's lesson. the tell is mechanical and needs no wisher:
   **a fork with exactly two options, where no line asks whether a third exists.** all three of this
   round's collapsed fulcrums had exactly two.

⇒ the smallest useful change: `rule.always.itemize-the-fulcrums-you-best-guess` gains a required
line per entry — **`.the option set, and what it assumes`** — which states what was ruled out and
why. that line is where *"the peak may be unbuildable"* would have been written down.

⚠️ **and a second, sharper candidate**: confidence is currently one number. it could be **two** —
confidence in the *pick*, and confidence in the *set*. F4 would have read `91% / 60%`, and the 60%
is the number that would have earned a second look.

## 🔴 .why this is worth a rule rather than more care

the three fulcrums were authored across different days, on different subsystems, at 91%, 78%, and
72% confidence. **care was not the variable.** the record's shape does not ask the question, so the
question does not get asked — the same class as the `.taken`-per-nitpick dream caught this round: a
rule agreed with, and looked past, because no cue fires.

## .why it is not done in this round

**safe?** yes — an added field on a record format mutates no behavior.

**clean?** 🔴 **no.** `rule.always.itemize-the-fulcrums-you-best-guess` is a **published brief** that
governs every route in this repo and downstream. a new required field makes every extant fulcrum
entry non-conformant at once, so it wants a migration decision and a `left in place until disturbed`
clause. that ripples well past this wish's diff.

⚠️ **and one honest counter-argument, recorded so it is not lost**: the three collapses cost this
round **not one wasted pass** — every fulcrum was clean, and `rule.always.defer-fulcrums-to-last`
worked exactly as designed. ⇒ the case for the fix is that a **dirty** fulcrum with a short option
set would be far less forgiving, and no mechanism today parts the two.
