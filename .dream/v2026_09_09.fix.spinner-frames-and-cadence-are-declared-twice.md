# 🌙 dream: one spinner cadence, declared once

- **kind** = fix
- **owner** = `rhachet-roles-bhrain`
- **caught** = 2026-09-09

## .the cue that fired

a `has-consistent-mechanisms` self review on `5.1.execution.from_vision` asked the guide's own
question — *"do we duplicate extant utilities or patterns?"* — of the spinner I had just added to
`genContextCliEmit.ts`. the answer for **my** code was no: `drawStatus` reads the file's own
module constants.

⇒ but the grep that settled it turned up the same two constants in a **second** file.

## .the gap, precisely

`FRAMES` and `SPIN_MS` are declared twice, with byte-identical values:

| file | line |
|---|---|
| `src/domain.operations/route/guard/genContextCliEmit.ts` | `:14-15` |
| `src/domain.operations/review.by/genReviewByRubricStreamer.ts` | `:9-10` |

```ts
const FRAMES = ['⠋', '⠙', '⠹', '⠸', '⠼', '⠴', '⠦', '⠧', '⠇', '⠏'];
const SPIN_MS = 80;
```

🔴 **the second file's own docblock states the coupling outright**, at `:6`:

> *"spinner frames + cadence, **matched to** genContextCliEmit (the route peer-review streamer)"*

⇒ so the duplication is not an accident nobody noticed. it is **a deliberate copy, with a comment
that names the file it must stay in step with** — and no mechanism that keeps it there.

⚠️ the harm is a drift a reviewer cannot see: a cadence tuned in one file leaves the other at 80ms,
and the two surfaces animate at different rates. the comment says *"matched"* while the code has
quietly stopped to match, and no test reads either constant.

## .the shape of the fix

extract both constants to one module and import them in each streamer:

```ts
// src/domain.operations/cli/genSpinnerCadence.ts  (or a shared const module)
export const SPINNER_FRAMES = ['⠋', '⠙', '⠹', '⠸', '⠼', '⠴', '⠦', '⠧', '⠇', '⠏'];
export const SPINNER_SPIN_MS = 80;
```

then delete both local declarations and update the four `FRAMES[...]` / `SPIN_MS` reads in
`genContextCliEmit.ts` and the two in `genReviewByRubricStreamer.ts`.

⚠️ **the `.why` comment at `genReviewByRubricStreamer.ts:6` must change too** — *"matched to
genContextCliEmit"* describes a convention that the extraction replaces with a shared import, so the
comment would outlive its own subject (`rule.require.timeless-comments`).

🟡 **scope it to the constants, not the streamers.** the two files also share a
`clearActive → setInterval → overwrite` shape, and to unify *that* is a real refactor of two live
render paths. the constants are the part with a stated coupling and no mechanism behind it.

## .why it is not done in this round

the SAFE/CLEAN test, answered honestly:

| question | answer |
|---|---|
| **safe?** | ✅ yes — two constants, byte-identical, no behavior change |
| **clean?** | 🔴 **no** — it opens `src/domain.operations/review.by/`, a subsystem this wish's diff does not touch at all |

⇒ the wish is peer-review concurrency. `review.by` is a different surface with its own acceptance
suites, and a new shared module under it would enter every reviewer's `--diffs since-main` scope on
a branch where four lanes already overflowed on diff size.

⚠️ **and this predates the round.** both declarations are on `origin/main`; my diff adds neither.
so there is no urgency that would justify the ripple — the drift has been latent for as long as the
second streamer has existed, and one more round leaves it exactly where it already sat.

⇒ per `rule.always.fix-forward-under-scouts-honor`, a defer for **dirt** owes a dream. this is it.
no fulcrum is owed beside it: the dirt call is not a design judgment the council could overrule, it
is a scope fact about which directories the diff opens.
