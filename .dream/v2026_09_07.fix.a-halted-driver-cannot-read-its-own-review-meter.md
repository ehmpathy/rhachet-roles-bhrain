# 🌙 dream: a halted driver cannot read its own review meter

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-07, on the `v2026_09_03.fix-contemplation-gate-on-entrance` route @ `5.3.verification`

## .the cue that fired

the stone's yield carried this line across several rounds:

> *"five of eight peer lanes have never graded this work."*

**every number in it was wrong**, and it was written by a driver with full access to the route. the
guard carries **13** peer lanes, not 8 — *eight* is the count of **self-review** slugs. and the five
lanes it named had graded repeatedly, right up to the latest iteration.

⚠️ the tell is not that a driver miscounted. it is that **no command would have told it the answer**,
so it counted the only quantity it could see.

## .the gap, precisely

while a stone is halted, the driver's three natural reads all decline to report the meter:

| the read | what it gives while halted |
|---|---|
| `rhx route.drive` | the blocked stone plus a path to the blocker file. **no meter, no lane roster** |
| `rhx route.guard.budget --for review --stone X` | 🔴 **`error: --add is required`** — the operation is **write-only** |
| the guard tree (`formatGuardTree`) | ✅ shows `exhausted 🌙` per lane — but it is emitted **only when a round runs**, and the round is what the halt forbids |

⇒ **the one surface that carries the answer is gated behind the act the halt exists to prevent.**

so the path left is a hand-count: glob `.reviews/peer/*given*.<slug>.md` once per slug, tally each,
and compare against the `budget:` field in the `.guard` file. that is what finally produced the
correct split, and it is not a read any driver would reach for unprompted.

### 🔴 the two dark states look IDENTICAL in a directory read, and take OPPOSITE remedies

this is what makes the absent read expensive rather than merely inconvenient:

| the lane is | what the directory shows | the lever | owner |
|---|---|---|---|
| **overflowed** | givens keep arriving, each one `✋ blocked by constraints` | `rhx route.mutate.guard` — narrow its `--paths-with` | driver |
| **exhausted** | givens simply **stop** at some iteration | `rhx route.guard.budget --for review --add N` | driver |

both read as *"this lane is dark."* ⇒ **a driver who takes one for the other spends the wrong lever
and the lane stays dark**, with a plausible repair on record and no measurement to refute it. that is
exactly what happened here: the yield named the narrowed binds as the fix for all of them, and four
of the ten needed a budget top-up instead.

⚠️ **and the arithmetic that parts them is counter-intuitive.** an overflow draws **no** budget,
because a lane that renders no verdict costs no round. so the overflowed lanes hold *more* givens than
their budget allows (25 against `budget: 18`) while the exhausted ones hold *exactly* their budget and
then fall silent. **the lane with more artifacts is the one that has reviewed less.**

## .the shape of the fix

cheapest first, and the first is nearly free:

- 🔴 **make `--add` optional on `route.guard.budget`.** with `--for review --stone X` and no `--add`,
  print the per-lane meter: spent / left / last verdict / last iteration. **the data is already
  computed** by `getAllReviewPeerMeterStatuses` and already rendered by `formatReviewsMeterLines` — so
  this is a wire-up of two extant operations, not new logic. it also repairs a plain ergonomic defect:
  an operation whose bare invocation errors rather than reports
  (`rule.prefer.defaults-match-common-case`, ergonomist)
- **or fold the meter into the halt emit** — `route.drive` on a blocked stone prints the reason path
  and stops. the lanes' states are part of *why* the stone is where it is, so a reader of the halt has
  a legitimate claim on them
- ⚠️ **do NOT solve it with a brief.** *"remember to hand-count givens against the guard's budget"* is
  a procedure a tool should own (`rule.always.entool-the-skills-you-touch`) — and the driver that got
  this wrong had every relevant rule already booted

⇒ the first shape is likely right, because the second widens an emit that several snapshots pin,
while the first adds a read mode no test asserts against yet.

## .why it is not done in this round

**safe? yes — a read mode adds no write path. clean? no.**

- **out of the wish's fence.** this route fixes the contemplation gate; `0.wish.md` carries an explicit
  `.scope — do NOT let these expand it` block, and a budget-read surface is not on it
- **it is a CLI contract change**, so it owes a snapshot, an acceptance case, and a help-text update —
  a diff that shares no file with this one
- 🔴 **the route is halted at `5.3.verification` while wisher rulings are unresolved**, and its
  `since-main` already unions 437 files and overflows five review lanes. to add a new CLI surface now
  is to add files the lanes that would grade it cannot read

⇒ dirty, so it is caught rather than fixed — and the measurement it would have saved is already
recorded, so the next traveler inherits the answer even before the tool exists.
