# domain.term.choice.reason: unattributed

## .etymology
the word names the method's limit, not the content's kind. the content is often knowable — the
harness prompt, the tool schemas — but no record in the transcript carries it, so the instrument
cannot attribute it. a tier word keeps the claim honest: it says *we did not see this arrive*.

chosen over:
- `other` / `misc` — read as a classified leftover bucket, which hides that no classification ran
- `unknown` — overclaims; a reader can often name what it is, only the transcript cannot
- `overhead` — a judgment that it is waste, which the instrument cannot make

## .disputes
none raised.

## .evidence
- the row renders with its tier, `[unattributed]`, beside the measured, exact, and apportioned
  rows, so a reader sees which share the method could not trace
- its label names the likely contents — `harness (system prompt + tool schemas)`, or
  `harness + compacted context` after a compaction re-bases the context
- invariant: base context at call 1 minus the bytes-apportioned boot blocks is unattributed;
  clamped in `getOneTokenInventory.test.ts` case1
