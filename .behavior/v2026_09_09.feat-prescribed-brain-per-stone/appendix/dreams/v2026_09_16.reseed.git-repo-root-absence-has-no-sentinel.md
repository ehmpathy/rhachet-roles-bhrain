# 🌙 dream: `getGitRepoRoot` must let a caller detect "not in a git repo" without a message match

- kind  = `reseed` — the fix belongs to `ehmpathy/rhachet-artifact-git`, never to this tree
- owner = `ehmpathy/rhachet-artifact-git`
- caught 2026-09-16

## .the cue that fired

a peer reviewer (i022, `enroll-impl-arch-defects` nitpick.2) flagged
`getRepoRootWithFallback`'s not-in-git detection as a fragile string match, and noted that
this feature pushed its blast radius from two guard call sites to eight — the passage gate,
the contemplation gate, the review runner, the peer meters, the guard display path, the
drive blocker message, the route cli, and `setStoneBrain`.

⇒ the lane was right that the dependency is real. it was wrong that the fix lives here.

## .the gap, precisely

`getGitRepoRoot` raises a generic 400 with a human sentence and no machine-readable marker:

```js
// node_modules/rhachet-artifact-git/dist/domain.operations/repo/getGitRepoRoot.js:21
if (!gitPath)
  throw new helpful_errors_1.BadRequestError('Not inside a Git repository', { input });
```

so **every** caller that wants to part "this path is not in a repo" from "the lookup broke"
must match on `error.message`. that is what this repo does:

```ts
// src/domain.operations/route/guard/getRepoRootWithFallback.ts
const isNotInGitRepoError =
  error instanceof Error && error.message.includes('Not inside a Git');
if (!isNotInGitRepoError) throw error;
return process.cwd();
```

**and a class check is not the remedy it reads as.** `BadRequestError` is `helpful-errors`'
generic 400 — checked 2026-09-16, `BadRequestError.d.ts` declares only
`constructor(message, metadata?)` and carries no `code`. so `instanceof BadRequestError`
is **wider** than the message match, and would swallow every future 400 upstream adds to
this call.

⇒ **the caller has no correct check available.** the least-wrong one is the one in place.

## .what is NOT the gap — measured, so a later reader does not re-raise it

the message match's failure modes are both **loud**, dogfooded 2026-09-16:

| the drift | what happens |
|---|---|
| upstream rewords its message | the predicate goes false → the error **RETHROWS**. `getRepoRootWithFallback.integration.test.ts [case2]` runs the real lookup from a real non-git temp dir, so the drift goes red in CI. proven: a one-word edit let `BadRequestError: Not inside a Git repository` escape the clamp |
| a genuine fault swallowed as "not in git" | needs a DIFFERENT error whose message carries `Not inside a Git`, and line 21 above is its only producer |

⇒ so this is a **maintenance hazard with a build-time clamp**, never a live failhide. it is
worth a fix upstream; it is not worth a workaround downstream.

## .the shape of the fix

in `ehmpathy/rhachet-artifact-git`, give the absence a marker a caller can read. any one of:

1. **a dedicated class** — `NotInsideGitRepoError extends BadRequestError`, exported from
   the package index. callers narrow on the class, and the message stays free to change
2. **a `code` on the metadata** — `new BadRequestError('Not inside a Git repository', { code: 'NOT_INSIDE_GIT_REPO', input })`. cheapest, and it needs no new export
3. 🔴 **a non-throw read** — `getGitRepoRootOrNull({ from })`, which returns `null` rather
   than raises. the strongest of the three: **the absence of a repo is not an exceptional
   condition for a caller that has a fallback**, and every one of this repo's eight sites
   has one. it would delete the try/catch outright

⇒ prefer **3**, with **2** as the compatible half-step. `rule.require.exit-code-semantics`'s
own claim applies one level in: a caller must be able to part "your input" from "my fault"
without a string read.

then, here: replace the message match with the marker, and keep `[case2]` as its clamp.

## .why it is not done in this round

- **SAFE?** ❌ — the fix is in another repo, on another release cadence. this tree cannot
  change what `getGitRepoRoot` throws
- **CLEAN?** ❌ — a downstream workaround (a probe for `.git` before the call, a re-derived
  root lookup) would be a **second path beside a serviceable one**, which
  `rule.always.reuse-pavement-before-improvise` names as the braided trail

⇒ a tree adopts only what is scoped to itself. caught as a `reseed`, not adopted.

⚠️ **caught is not dispatched.** the radio push to `ehmpathy/rhachet-artifact-git` is a
separate act, and it has not happened.
