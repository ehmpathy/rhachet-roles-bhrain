### the cause, reproduced directly

| `--paths-with` argument | reported `paths:` | targets | result |
|---|---|---|---|
| `'**/*.{ts,sh,md,snap}'` — brace in the **ext** slot | ⛔ `(none)` | 278 | 92.4% → **overflow** |
| `'**/*.ts'` — no brace | ✅ `**/*.ts` | 88 | 43.7% → ran clean |
| `'{blackbox,src/contract}/**'` — brace in the **dir** slot | ✅ as written | 71 | ran |
| `'**'` then `'package.json'` — the flag **repeated** | ⛔ `package.json` | **1** | the first glob is discarded |

two parser defects, and both are read from source as well as measured
(`parseReviewArgs`, `src/contract/cli/review.ts:121-151`):

1. a brace in the **extension** slot is silently dropped — the bind never reaches the resolver, so
   the lane runs **unbounded** and blows the window. `.md` rode along in a glob that was discarded
   whole; a `{ts,snap}` glob fails identically
2. a **repeated** flag keeps only the LAST — only `refs` (`:130`) and `optional` (`:136`)
   accumulate; every other key falls to `:147` `options[key] = value`. the repo's own
   `accumulateNamedArg` (`src/infra/cli/getCliArgs.ts:20-33`) does accumulate, with a docblock that
   says *"enables repeated flags like --refs x --refs y"* — **two parsers, one repo, opposite
   behaviour on repeats**
