## .the fail-safe proof

a happy path owes no fail-safe, per `define.experience._.axis=feel.path=happy-vs-sharp`. this cell owes a demo, and the demo is above.

🟡 **but `[t4]` is a real hazard on a happy cell: the failure is not an edge that throws — it is two outcomes that render identically to the machine that grades them.**

| what parts a pass from a skip | reaches the guard? |
|---|---|
| the `🌙 skipped — no rules found` header | no — prose the regex ignores |
| the exit code | no — both are 0 |
| the two numeric lines | no — both are `0` / `0` |
| a `logs:` line — a skip writes no log dir | present on a pass, absent on a skip, and the guard does not read it |

⇒ two rows are human-visible and neither reaches the guard, and they mark opposite outcomes:

| the marker | present on | absent on |
|---|---|---|
| the `🌙 skipped` header | a skip | a pass |
| the `logs:` line | a pass | a skip |

🟡 the `logs:` row is the one worth a repair, and the header is not:

- a header is **prose** — to parse it re-opens the incidental-match trap `contract.reviewer-output` bans outright
  - *"no major blockers here"* must never read as a count
- a log dir exists on disk or it does not
  - ⇒ so it is a **check**, never a match

⇒ so the guard has a discriminator available and does not use it, which makes `[t4]` a repair with a known shape rather than an open problem.

### `[t4]` was EXECUTED, not read — the transcript

the two rows above were a source read until `i018`. the skip half was then run first-party against this repo:

```
$ rhx review --rules 'src/domain.roles/telepath/briefs/rule.does-not-exist-*.md' \
             --paths 'src/domain.roles/telepath/boot.yml' \

      └─ 0 nitpicks
```

| the claim | measured |
|---|---|
| a zero-match glob under the flag renders `0` / `0` | both numeric lines present, both zero |
| the exit code is 0 | — so a guard tallies it **approved** |
| a skip carries **no** `logs:` line | absent, and `review:` is present in its place |
| a skip writes **no log dir** — the discriminator this cell proposes | **on disk.** the newest `.log/bhrain/review/*` dir predates the probe by 14 minutes, so **the skip created none** |

⇒ the source agrees exactly: a pass emits both lines (`genReviewOutputStdout.ts:82-83`), a skip emits only `review:` (`getReviewSkipReport.ts:9,19`), and a unit test asserts the absence (`getReviewSkipReport.test.ts:30`).

### and the run found a trap the source read had not named

the probe's `--output` file was written — `.log/probe.optional-rules.md`, 291B, on a skip.

| candidate discriminator | present on a pass | present on a skip | usable? |
|---|---|---|---|
| the `logs:` line and its dir | yes | no | yes |
| the `review:` line and its file | yes | yes | no — identical |

⇒ **so *"a skip writes no artifacts"* is too broad, and the imprecision carries weight**: a skip writes no log dir and does write its review artifact. a repair that reached for *"the output file exists"* would tally every skip as a pass — the exact failure it was built to catch.

🟡 this is why `[t4]` was run rather than cited. the source read gave the right discriminator and the wrong reason, and only the disk parted them.

🟡 the reason this run was worth its minute is a claim-type correction, never a doubt about the code:

- the wish's own motivation is *"an unreviewed reviewer is indistinguishable from a clean one"*
- this route has twice found a claim asserted from one source and derived from another — acceptance line 1, §4 of the yield
- ⇒ a footgun named as the sharpest hazard in the inventory owes a first-party demonstration, never a citation
