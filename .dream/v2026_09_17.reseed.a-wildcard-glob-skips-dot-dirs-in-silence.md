# 🌙 dream: `globsafe` and `grepsafe` must not report a pruned dot-dir as an empty result

- kind  = `reseed` — the skills belong to `ehmpathy/rhachet-roles-ehmpathy`
- owner = `ehmpathy/rhachet-roles-ehmpathy` (`role=mechanic`)
- caught 2026-09-17

## .the cue that fired

four `.taken` artifacts landed at a repo-root `.reviews/peer/` rather than `$route/.reviews/peer/`.
five `globsafe` / `Glob` searches returned zero; `tree -a` found all four in one call. the round was
lost to a silent zero.

## .the gap, precisely

a **wildcard** segment does not descend into a dot-prefixed dir; a **literal** one does. measured
2026-09-17 on the same four files:

| the call | result |
|---|---|
| `globsafe --pattern '.behavior/**/*i033*taken*'` | 🔴 `files: 0`, exit 0 |
| `globsafe --pattern '.behavior/$route/.reviews/peer/*i033*taken*'` | ✅ 4 files |
| `grepsafe --path '.behavior/$route/.reviews/peer' --glob '*i033*'` | ✅ 4 files |

the behavior is correct — `fast-glob`'s `dot: false` keeps `**` off `.git/` and `node_modules/`.
**the defect is the report:** `files: 0` is byte-identical for a true zero and for four matches behind
a pruned dot dir (`rule.forbid.failhide`). and the two want opposite next moves: a true zero means the
artifact was never written; a pruned zero means the probe was wrong.

## .the shape of the fix

in `skills/claude.tools/globsafe.sh` + `grepsafe.sh`:

1. **name the prune on a zero result** — when a run returns zero and the pattern holds a wildcard
   segment, append `└─ note: dot dirs were not descended. spell the dot segment, or pass --dot`.
   zero case only; on every run it is noise
2. **a `--dot` flag**, as its companion
3. ~~`dot: true` by default~~ — rejected: it drags `.git/` and `node_modules/` into every sweep

## .why it is not done in this round

- **SAFE — no.** the skills live in another repo
- **CLEAN — no.** a local wrapper is a second path beside a serviceable one

⇒ see also: `hazard.a-route-artifact-at-the-repo-root-reads-as-stale` (the symptom, and the
literal-path workaround).
