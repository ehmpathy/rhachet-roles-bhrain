# 🌙 dream: iso-time's asIsoTimeStamp must stamp the utc instant, not local wall time

kind = reseed · owner = ehmpathy/iso-time · caught 2026-10-24

## .the cue that fired

the status line cache adopted `asIsoTimeStamp(new Date())` for its `at` field, per
`rule.forbid.any-time`. the acceptance clamp `routeStatusLine` [case19] runs the renderer under
`TZ=America/Chicago`: the stamp read the local wall clock with a `Z` suffix, five hours behind the true utc instant (a skew of 18,001s),
so every repaint read its own cache as 5h old and missed.

## .the gap, precisely

`iso-time@1.11.1` `dist/domain.operations/checks/isIsoTimeStamp.js`:

```js
const asIsoTimeStamp = (input) =>
  format(castInputToDate(input), "yyyy-MM-dd'T'HH:mm:ss'Z'");
```

date-fns `format` renders in the host's LOCAL zone, then a literal `'Z'` is appended. on any host
off utc the stamp claims utc and names another instant. `isIsoTimeStamp` round-trips through the
same `format`, so it accepts the wrong stamp as valid. it also drops millis.

it hides on a utc host — this repo's jest config pins `TZ = 'UTC'`, and the sandbox cannot move
node's zone, so no unit test here could see it.

## .the shape of the fix

- `asIsoTimeStamp`: `formatInTimeZone(date, 'UTC', "yyyy-MM-dd'T'HH:mm:ss'Z'")`
  (date-fns-tz), or `date.toISOString().replace(/\.\d{3}Z$/, 'Z')`
- a clamp that spawns a child node under `TZ=America/Chicago` and asserts
  `Date.parse(asIsoTimeStamp(d)) === Math.floor(d.getTime() / 1000) * 1000`
- audit every caller that stamped with it on a non-utc host: each stored stamp is skewed by the
  host offset

## .why it is not done in this round

the fix belongs to another repo (a `reseed`). here the cache stamps via its own
`asRouteStatusLineCacheStamp` (`toISOString`, narrowed by a guard, no cast), so this route ships
correct without it. once iso-time is fixed, the cache may adopt it — on the miss path only, since
the hit path loads no node_modules module.
