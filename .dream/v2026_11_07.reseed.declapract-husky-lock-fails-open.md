# 🌙 dream: the husky practice's timestamp lock fails open, and its hooks ship with no clamp

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (practice `husky`)
- caught 2026-11-07

## .the cue that fired

the peer review of `feat-toggle-term-learner-hook` stone 5.1 read the practice's `.husky` files in
the tree and raised five concerns. the lock forbids a hand edit (only a practice upgrade may
change it), so the fix belongs to the practice.

## .the gap, precisely

in `.husky/check.timestamps.lock.sh`:

1. no `set -eu`, unlike its peers `check.timestamps.sh` and `check.secrets.sh`
2. `git hash-object` is unguarded: a git fault yields an empty id, and the lock reports
   `✋ ConstraintError: … was changed` (exit 2) for what is a malfunction (exit 1)
3. an empty `git ls-files -s` passes: a staged deletion (`git rm --cached .husky/check.timestamps.sh`)
   keeps the hook on disk, drops it from the commit, and the lock lets it through
4. the hook path is built from `$0`, the hook that sources the lock, so a wrapper outside
   `.husky/` breaks it

and across `check.secrets.sh` / `check.timestamps.sh`: the refusals a human meets at commit carry
no harness test and no snapshot.

## .the shape of the fix

- `set -eu` with the peers' rationale comment
- `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK") || timestamps_lock_malfunction`
- halt when the index entry is absent: `[ -n "$TIMESTAMPS_LOCK_INDEX" ] || timestamps_lock_halt 'absent' 'in the index'`
- locate the lock by its own path (a `BASH_SOURCE` read, with a POSIX fallback)
- a small harness that stages a secret and a timestamp, and snaps each refusal's stderr

## .why it is not done in this round

the files are the practice's output; the lock itself forbids a hand edit, and the next
`declapract apply` would revert one. the toggle's nano bound excludes them too (fulcrum F7).
