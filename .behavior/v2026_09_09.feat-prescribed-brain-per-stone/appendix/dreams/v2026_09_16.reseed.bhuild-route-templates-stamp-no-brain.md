## .the gap, precisely

`rhachet-roles-bhrain` now ships the **mechanism**: a stone's `.guard` may declare `brain: <arg>`,
and the driver-role hook applies it to the live driver clone on stone entry.

checkable evidence, in this repo:

- `RouteStoneGuard.brain?: string` — the field
- `parseStoneGuard` — the inline-key branch that reads it
- `applyStoneBrainOnEntry` + `setStoneBrain` + `dispatchBrainSwitch` — the appliers
- `src/domain.operations/route/.test/assets/**/*.guard` — **zero** carry a `brain:` key

⇒ **the mechanism has no callers.** every guard that exists in the wild is stamped from a bhuild
route template, and not one of those templates emits a `brain:` line. so the feature is live,
correct, tested — and dormant, until a template stamps it.

🔴 **the economy argument is the whole point, and it is the half that is unshipped.** the vision's
claim is that mechanical stones (a rebase, a lint repair, a snapshot refresh) do not need an
expensive brain, and that a route which stamps a cheap one on those stones pays for itself. this
repo can prove the switch *happens*; only bhuild can make it happen *on the stones that matter*.

## .the shape of the fix

in `ehmpathy/rhachet-roles-bhuild`, the route-template stamper:

1. **pick the axis** — which stone kinds are mechanical enough for a cheap brain. the candidate set
   from this feature's own vision: reflect / repair / verification-rerun stones, and emphatically
   NOT vision, criteria, or blueprint stones (they are the ones that most need the expensive brain)
2. **stamp the key** — emit `brain: <arg>` into the generated `.guard`, beside the extant
   `artifacts:` / `reviews:` / `judges:` / `protect:` keys. it is a top-level INLINE key, so the
   line is `brain: claude-haiku-4-5-20251001` with no list beneath it
3. ⚠️ **the value is the brain-cli's own `/model` argument, verbatim** — NOT a rhachet brainslug.
   this is `F10`, ruled and overturned once already. `claude-sonnet-5[1m]` is right;
   `anthropic/claude/sonnet` is wrong and will be passed through to `/model` unchanged, where it
   fails
4. **leave the key absent where it should be absent** — an absent `brain:` means the driver keeps
   its inherited brain, and the hook returns before it does any I/O at all. that is the correct,
   zero-cost default for every stone the axis does not name

## .why it is not done in this round

**SAFE** — yes. **CLEAN** — 🔴 **no.** the change lands in a different repo entirely. a tree adopts
only what is scoped to itself (`rule.always.scope-onetime-lessons-to-the-behavior`), and no edit in
`rhachet-roles-bhrain` can stamp a bhuild template.

🟡 it is also **sequenced after a ruling this route has not received.** `F6` — whether a switched
brain is sticky or restored on stone exit — is an open fulcrum awaiting the wisher. the template's
axis depends on it: if a brain is **sticky**, a cheap stamp on stone 3 silently prices stones 4-9
too, and the template must then stamp a restore. so the bhuild work should not begin until `F6` is
ruled, or it will be built against the wrong model and re-done.
