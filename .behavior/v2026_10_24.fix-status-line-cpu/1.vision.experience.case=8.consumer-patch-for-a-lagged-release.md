# case=8 — a consumer patch for a release that lags (happy · critipath)

## .narrative

the fix is merged, yet the release has not reached a consumer repo whose seats still burn cpu.
a verifier runs `rhx gen.consumer-patch --from 0.42.1 --into <path>` from this repo. the skill
fetches the published 0.42.1 tarball, checks its integrity against the registry, overlays the
local build's runtime files and its `exports`, and writes one patch. it then applies that patch
to a fresh copy of the base, so a patch that would not apply never leaves the skill. its tree
names the patch and the four steps the consumer takes: copy it, name it in
`pnpm.patchedDependencies`, `pnpm install`, re-run the driver init.

## .bdd sketch

```
given('[case8] a local build ahead of the published base')
  when('[t0] gen.consumer-patch runs against the published version')
    then('it writes one patch that applies cleanly to the base')
    then('its tree names the patch and the consumer steps, in order')
  when('[t1] the base is unpublished, or the build equals the base')
    then('it refuses with exit 2 and names why')
  when('[t2] the tarball fails its integrity check, or the patch does not apply')
    then('it fails with exit 1 and writes no patch a consumer could trust')
```
