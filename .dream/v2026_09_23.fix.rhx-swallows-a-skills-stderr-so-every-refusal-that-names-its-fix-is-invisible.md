# 🌙 dream: `rhx` swallows a skill's stderr on exit 0, so a refusal that names its fix reaches nobody

- kind  = fix
- owner = unclaimed
- caught 2026-09-23

## .the cue that fired

`census.review-prefix` writes a refusal to **stderr** when it finds no log root, and that
refusal is written to the `errors-name-the-fix` shape:

```
🦉 no review logs at <path>
   fix: run a review here first, or point --at at a tree where reviews ran
```

an acceptance case was written to clamp it. it passes when the suite spawns the skill's own
`.sh`. then the same invocation was made the way a human makes it:

```
$ rhx census.review-prefix --at /tmp/does-not-exist-xyz
🪨 run solid skill repo=.this/role=any/skill=census.review-prefix

EXIT=0
```

**both stderr lines are gone.** exit 0, a banner, and silence — so a human who points `--at`
at the wrong tree is told naught at all, and reads the silence as *"there is no prefix
here"*, which is a claim no one made.

## .the gap, precisely

- the skill writes two lines to fd 2 and exits 0
- through `rhx`, neither line appears on either stream
- the same skill, spawned directly, emits both — the suite asserts it, and that assertion is
  green (`blackbox/census.review-prefix.acceptance.test.ts`, `[case1]`)

⇒ so the loss is **in the runner**, between the skill and the terminal, and it is scoped to
the exit-0 path: a **nonzero** exit does surface the child's output (the `Permission denied`
from a non-executable wrapper printed fine at exit 126).

🔴 **the shape this belongs to.** it is the twin of
`v2026_09_23.fix.rhx-prints-its-skill-banner-to-stdout-so-no-json-pipes.md` — that one puts
bytes on stdout that the caller did not ask for; this one takes bytes off stderr that the
caller did ask for. **one seam, two directions, and both are invisible to any suite that
spawns the skill rather than the runner** (`rule.require.acceptance.blackbox`, `F19`).

## .the shape of the fix

in the runner's skill-exec path, inherit or forward the child's stderr on **every** exit code,
not only nonzero. the child already owns fd 2; the runner should not filter it.

then, in this repo, the clamp that would have caught it:

- a case that spawns `node_modules/.bin/rhachet run --skill census.review-prefix --at <absent>`
  and asserts the refusal text reaches the caller
- ⚠️ it must assert on the **runner's** streams, since that is the only seam where the defect
  is visible. the extant `[case1]` cannot see it by construction

## .why it is not done in this round

**SAFE — no.** the repair is in `rhachet`, a dependency, not in this tree. every skill in
every repo rides that seam, so a change to it is a blast radius this branch cannot measure.

**CLEAN — no.** this branch's diff is the review cost meter; a runner-stream change shares no
file with it.

⇒ so it is caught rather than ridden along (`rule.always.fix-forward-under-scouts-honor`).
no fulcrum is owed: the deferral is for **scope**, never for a judgment about ripple that a
council would want to overrule.

## .the blast radius, stated

every `rhx <skill>` that refuses on the exit-0 path. this repo alone ships several that
deliberately exit 0 on a refusal so they do not gate a pipeline — `census.review-prefix` and
`review._.cost` among them. each one's carefully worded fix line is reaching no reader.
