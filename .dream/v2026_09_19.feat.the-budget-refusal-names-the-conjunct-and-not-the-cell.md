## .the gap, precisely

`BudgetGrantRefusal` carries exactly three kinds, and each names a **conjunct of the gate**:

```ts
| { kind: 'stone-matched-many'; guards: string[] }      // the SCOPE conjunct
| { kind: 'no-warrant' }                                // the WARRANT conjunct
| { kind: 'rounds-remain'; meters: BudgetGrantMeter[] } // the MOMENT conjunct
```

⇒ **the refusal is a function of WHICH CONJUNCT FAILED, and of naught else.** the cell the driver
occupies — B = `disputed` vs B = `none`, C = `malfunctioned` vs C = `live` — never reaches it:

- `computeBudgetGrantRefusal` reads `targetGuards`, `liveUrgentSlugs`, `targetMeters`. **a dispute
  mints no slug and a malfunction sets no field**, so both cells arrive as inputs already covered
  by an untouched stone
- `formatBudgetGrantRefusalLines` receives the refusal plus the meters, so it can branch on no
  dimension the compute operation did not hand it

🔴 **so this is not a copy edit.** the B-specific copy needs a **live disputed-stance query** beside
`getStoneLiveUrgentConcessionSlugs`; the C-specific copy needs the **meter's malfunction state**
threaded from `runStoneGuardReviews` into the gate's inputs.

### 🟡 the verdicts are correct today, and that is why this is a `feat`

both cells are refused, and refused for a defensible conjunct:

| cell | shipped verdict | is it right? |
|---|---|---|
| disputed, dry | `no-warrant` | ✅ a dispute concedes naught, so it carries no severity, and severity is what a round is priced in |
| malfunctioned, below budget | `rounds-remain` | ✅ **and the remedy lands** — `case=6` `[t2]` says the narrowed guard runs within its extant budget, so the round in hand is the one the repair needs |
| malfunctioned, dry | `no-warrant` | ✅ the malfunction mints no warrant, and `F030` forbids a concede against an unreadable given |

⇒ **what is absent is the DIAGNOSIS, never the decision.** a driver reads a true refusal with a
generic reason where a specific one was promised.

## .the shape of the fix

**two halves, and they are independent — do not bundle them.**

**half 1 — the dispute.** add `getStoneLiveDisputedConcernRefs({ route, stone })` beside the extant
urgent query, thread its result into `computeBudgetGrantRefusal`, and split `no-warrant` into
`no-warrant` and `no-warrant-disputed`. the second renders `case=8`'s three clauses, and the first
is unchanged. ⚠️ the order matters: a stone with a dispute AND a `better` concession is still a
`no-warrant` cell, so the disputed variant leads only where the dispute is the **whole** of the
ledger.

**half 2 — the malfunction.** the meter already knows: `runStoneGuardReviews.ts:654-656` declines to
increment on a malfunction. what it does not do is **record** that it declined. so the meter row
needs a state field, and `rounds-remain` needs a `malfunctioned` flag per meter — then the copy
leads with the wrench and closes the `⛔` door, per `case=6`'s render.

🟡 **half 2 is the more valuable of the two**, because its residual is the only one where a driver
is handed a remedy that reads as unrelated to the fault in front of it.
