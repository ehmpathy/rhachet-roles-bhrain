# 🌙 dream: a snapshot pins `jq`'s own error prefix, so it is host-version dependent

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04

## .the cue that fired

a full integration run went red on
`route.foreground.guard [case6][t1] stdin is malformed json → stderr matches snapshot`, in a
round whose diff touched **no file** under `src/domain.roles/driver/skills/`.

```
- jq: parse error: Invalid literal at line 1, column 5
+ parse error: Invalid literal at line 1, column 5
```

⇒ the committed snapshot carries a `jq: ` prefix that this host's `jq` does not emit.

## .the gap, precisely

`route.foreground.guard.sh` pipes the hook's stdin through `jq` to read `tool_name`. on malformed
json, `jq` writes its own diagnostic to stderr, and the test snapshots **the whole stream** — so
the assertion is over text a third-party tool owns, not text this repo authors.

`jq` changed that prefix between versions. so the snapshot is green or red by **which jq is
installed**, and neither outcome says anything about the hook.

🔴 **and the failure is misattributed by default.** it surfaces in a full-suite run as one more
red among many, in a file the current change never touched — so the honest reading (a host
dependency) costs a `git status` that a hurried driver will skip, and the cheap reading (resnap
it) is exactly wrong: it would bake THIS host's jq output into the corpus and turn the red into
a CI red for everyone else.

## .the shape of the fix

the snapshot should pin what the **hook** says and drop what **jq** says. two candidates:

1. **silence jq's own diagnostic and author the message** — the hook already prints
   `🗿 route.foreground guard: failed to parse tool_name from tool input json`, which is the
   whole contract. let jq's stderr go to `/dev/null` and keep the authored line. simplest, and
   it makes the stream fully owned
2. **strip the prefix before the snapshot** — an `asHookAuthoredStderr` cast in the test that
   drops a leading `jq: `. cheaper, but it leaves the dependency and the next jq reword breaks
   it again

⇒ prefer (1). a snapshot is a contract over output **we** promise; a dependency's phrasing is not
a promise we can keep.

⚠️ worth a sweep for peers: any snapshot over a stream that a non-authored binary writes to has
the same defect.

## .why it is not done in this round

**in scope? no.** this behavior fixes the contemplation gate. the hook, its shell, and its suite
are untouched by the diff, and a change there would be a wholly separate concern smuggled into an
unrelated round (`rule.require.review-test-changes`).

**safe? no.** the correct repair changes what the hook writes to stderr, which is itself a
snapshotted driver-facing surface with its own passing clamps.

⇒ recorded rather than resnapped, precisely because the resnap is the tempting wrong move.
