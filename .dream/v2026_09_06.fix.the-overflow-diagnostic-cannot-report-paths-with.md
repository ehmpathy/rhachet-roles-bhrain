# 🌙 dream: the overflow diagnostic cannot report `--paths-with`, so it prints `(none)` for a bind that applied

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain` (`src/domain.operations/review/stepReview.ts`)
- **caught** 2026-09-06, on `beav/fix-contemplation-gate-on-entrance`

## .the cue that fired

a driver rebound five overflowed lanes from `'**/*.{ts,sh,md,snap}'` to `'{src,blackbox}/**'` and
re-arrived. every lane still overflowed, and every lane's scope block still read:

```
   │  ├─ paths: (none)
   │  │  └─ files: null
   │  └─ joined via intersect
   │     ├─ files: 168
```

the driver read that as *"the rebind was discarded"*. **it was not.** `168` is exactly
`353 diff-files ∩ {src,blackbox}/**` — the bind applied, and the row that reports it is blind.

## .the gap, precisely

`stepReview.ts` resolves `pathsWith` correctly and reports it not at all:

| line | what it does |
|---|---|
| `:368-375` | folds `input.pathsWith` into `pathsWithGlobs` |
| `:389` | feeds those globs to `enumFilesForReviewSubjects` → `targetFilesFromPaths` |
| `:668` | `const pathsDisplay = input.paths ? … : '(none)'` — 🔴 reads `paths`, never `pathsWith` |
| `:695` | prints that display |
| `:697` | `${input.paths ? targetFilesFromPaths.length : 'null'}` — 🔴 same wrong key, and the count it guards **was computed from `pathsWith`** |
| `:468, :470` | the 75%-warn block repeats both defects |

⇒ `:697` is the sharpest of the four: it holds the **right number** and gates it on the **wrong
flag**, so a caller who binds `--paths-with` is told `null` about a set the same expression just
counted.

## 🔴 .why it costs more than a cosmetic row

the overflow block exists to answer one question — *"why is my scope too big?"* — and it is the only
surface that answers it. a caller who binds `--paths-with` gets a diagnostic that says, of the
narrowed set they just asked for, **that they asked for none.**

the two wrong repairs it invites, both measured on this branch:

| the driver concludes | what they do | what it costs |
|---|---|---|
| *"the bind was dropped"* | re-derives a bind that already worked, or blames the parser | a round, and a fulcrum entry built on a false premise |
| *"scope harder"* | narrows again, sees `(none)` again, narrows again | a loop with no feedback signal at all |

⚠️ **and it masks a real neighbour.** `--paths-with` *does* have a genuine bind defect — a doubled
flag last-wins (`review.ts:144-149`) — so the two are trivially confused. a diagnostic that reported
the resolved globs would have parted them on sight.

## .the shape of the fix

report the **resolved** glob set, never the raw `--paths` flag. the value is already in scope at both
sites as `pathsWithGlobs`.

```diff
-      const pathsDisplay = input.paths ? … : '(none)';
+      const pathsDisplay = positivePathGlobs.length > 0
+        ? positivePathGlobs.join(', ')
+        : '(none)';
...
-        `   │  │  └─ files: ${input.paths ? targetFilesFromPaths.length : 'null'}`,
+        `   │  │  └─ files: ${positivePathGlobs.length > 0 ? targetFilesFromPaths.length : 'null'}`,
```

four call sites, one file: `:468`, `:470`, `:695`, `:697`. `:773` already writes the resolved
`pathsWith` into `input.scope.json`, so the artifact is correct today and only the **human-read**
surface lies — which is why nobody caught it from the logs.

⚠️ **prefer the resolved globs over an echo of the flag.** an echo would fix the lie and keep the
silence about `--paths-wout`, which subtracts from the same set and is equally unreported.

## .why it is not done in this round

**it is a change to the instrument, made by the party under measurement.** the overflow block is
stderr of a reviewer lane, and this stone's convergence claims are comparisons across rounds of those
lanes. the same reason `.fulcrums/…case=F11-*` leaves the guard binds alone applies here verbatim,
and with less excuse to depart from it — F11 at least concerns a file this route owns.

⇒ the fix is four lines and mechanically trivial. **the reason to defer is not effort.**
