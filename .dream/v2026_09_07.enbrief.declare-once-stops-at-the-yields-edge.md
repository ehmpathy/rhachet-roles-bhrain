## .the shape of the fix

widen the declare-once clause from *one yield* to *the route plus what it ships*, and give it a check
that can actually run:

1. **state the scope** — a claim is declared once **across the route's artifacts and any code
   comment the route authors**, never once per file
2. **name the cue** — 🔴 *the moment you correct a claim is the moment to grep for its copies.* the
   correction is when the author holds the exact phrase; a sweep later does not
3. **fix the after-check** — it currently greps `$route/*.yield.md`. it wants the route dir **and**
   `src/**` for any term the route's code comments assert
4. **flag the asymmetry** — a route artifact and a code comment are not peers. a false code comment
   outlives the route, so it is graded blocker where a stale appendix row is a nitpick

5. 🔴 **add the cue rows 6 and 7 need — a summary row QUOTES or CITES its source.** cue #2 fires at a
   correction, so it is blind to a row that was wrong at authorship (#6) or overtaken by the world
   (#7). the cheap discipline that catches both: **when you write a row that characterizes another
   artifact, quote its words or cite its line — never paraphrase from memory.** a quoted row is
   checkable against its source by a reader; a paraphrased one is checkable only by whoever wrote it
6. 🔴 **grade a mis-described summary ABOVE a stale one.** a stale row has a correct ancestor on disk;
   an invented row has none, so no sweep finds it. and both outrank their entries in reader trust

7. 🔴 **do not type a value another artifact determines — derive it or cite it.** rows 16 and 17 are
   both bare numbers (`five`, `78%`) that a table one screen away already fixed. neither cue #2 nor
   #5 catches them: #2 fires at a correction and the author of row 16 *was* correcting, ten times
   over; #5 asks for a citation and a count reads as a fact rather than a characterization.
   ⇒ the repair is at the **shape of the claim**: write *"once per row of the table below"* rather
   than *"sixteen times"*, and *"see the F3 entry"* rather than *"78%"*. **a claim with no literal in
   it cannot go stale.**
8. 🔴 **propagate a correction READER-first, never source-first.** row 17 reached the source and the
   summary and stopped short of the halt file — so the drift sat where a wisher reads first. ⇒ when
   you correct a claim, **start the grep at the most-read surface** and work inward. the natural
   order is the opposite one, which is exactly why it needs stating.
9. 🔴 **where no artifact owns the value, write the COMMAND rather than the number.** rows 19 and 20
   have no source to cite — the value lives in the filesystem, and it moves on its own. `wc -l <path>`
   and `git status --porcelain | wc -l` are claims that re-evaluate at read time. ⇒ **a command cannot
   go stale; it can only be run.** cue 7 covers a value another artifact determines; this covers a
   value the *world* determines.
10. 🔴 **a `file.ts:NN` into a file your own branch edits is a literal, and it decays the same way.**
    it names a **position**, and every insert above it moves that position. ⇒ **cite the symbol, and
    let the line number be the convenience** — `runStoneGuardReviews.ts` *"the `blockers === 0`
    fast-path"* survives every edit; `:411` did not survive eight rounds. ⚠️ **and it fails more
    quietly than a stale count**, because a wrong line number still points at real code.

    ⚠️ **its scope is narrower than it first reads, on two axes:**

    | | cite the symbol | a bare `:NN` is fine |
    |---|---|---|
    | **the file** | one **your branch edits** — the number moves under you | one you do not touch — `jest.integration.env.ts:96` is as stable as the file |
| 🔴 **a GENERATED file** | 🔴 **the worst case of all — a `.snap` is rewritten WHOLE on every resnap**, so every number in it expires together, on a schedule, for a reason unrelated to the claim | — a generated file has no stable-number case |
    | **the artifact** | a **live surface** — a yield, a halt file, a summary | an **append-only** record — a `.taken` cites what it read at iteration N, and that is the record |

    ⇒ the second row is the append-only boundary applied to a line number. **a `.taken` whose `:NN`
    has since moved is not stale; it is dated** — and to rewrite it would falsify the record it
    exists to be. so the repair was applied to three live surfaces and to **no peer artifact at
    all**, deliberately.

    ⚠️ 🔴 **and a `:NN` fails in two different ways, which want two different checks:**

    | mode | what happened | what catches it |
    |---|---|---|
    | **displacement** | an insert **above** the line pushed it down — `:411` vs `:416` | re-read the line; it will hold plausible but wrong code |
    | **substitution** | the line **stayed** and its content was rewritten in place — F3's `where` | 🔴 **only a read of the content.** the number still matches, so no signal is raised |

    edits landed below them. so *"your branch edits the file"* is necessary and **not** sufficient;
    what matters is whether an edit landed **above the cited line.**

    ⚠️ 🔴 **substitution is the worse of the two and has no cheap check.** displacement leaves the
    reader at code that does not match the claim; substitution leaves them at code that **used to**
    match it and no longer does, with the number still correct. **the only defense is the symbol.**

    ⚠️ 🔴 **and this paragraph read *"none of the 679 peer artifacts"* for about a minute.** the
    count came from memory, the command to check it was blocked twice, and the number added no
    force to the claim — *"none"* is the whole point. ⇒ **cue 7 caught it inside its own brief.**

    this list and the one that is easiest to walk past.
