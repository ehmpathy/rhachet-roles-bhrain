# 🌙 dream: two test-rubric reviewers are scoped to `**/*.snap`, so they never read a `.test.ts` diff

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, at stone `5.3.verification` of
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

an enrolled verifier (`enroll-verif-test-intent`, i003 r012) reported it as a side
observation while it independently checked the diff:

> the `mech-test-intent` and `mech-given-when-then` reviewers in this conversation were
> scoped to `paths: **/*.snap` only (visible in their own logged `scope`), so they never saw
> the `.test.ts` diffs directly — only the snapshot deltas. that's why this direct check was
> worth doing independently rather than trusting their `0 blockers` verdict alone.

## .the gap, precisely

two reviewers whose rubrics govern **test intent** and **given/when/then structure** are
handed only `.snap` files. a snapshot records what a test *rendered*; it says naught about:

- whether an assertion was loosened
- whether a `given`/`when`/`then` is well-formed
- whether a `.skip` or a fail-hide landed
- whether a criterion was quietly changed rather than met

⇒ **both rubrics are about the `.test.ts` file, and neither reviewer can see one.**

🔴 **the sharp part is that they return `0 blockers`.** a reviewer that cannot see its
subject and says so is a `malfunction`; one that returns a clean verdict on an empty view
reads exactly like one that looked and found no defect. the guard tallies it as approval.

## .the shape of the fix

1. **read the guard config** for this stone and any other that carries these reviewers —
   confirm the `--paths-with` scope each is given
2. if the `**/*.snap` scope is unintentional, widen it to the `.test.ts` files the rubric
   actually grades. a `mech-test-intent` reviewer wants the test source; a
   `ergo-snapshot-visual-blemishes` reviewer genuinely wants only `.snap`
3. 🔴 **then ask the general question**, which is worth more than the two instances: should
   a reviewer whose scope matches **zero files of the kind its rubric names** be able to
   return `0 blockers` at all? `contract.reviewer-output` already refuses to infer zero from
   an absent count — the same argument says a rubric with no subject in view has rendered no
   verdict, and the guard should treat it as such

## .why it is not done in this round

- **not clean.** it touches the guard config of a live stone mid-convergence, which changes
  what the reviewers see between rounds — the very hazard already caught as
  `.dream/v2026_09_04.fix.a-guard-round-reads-a-tree-that-is-still-under-edit.md`
- **item 3 is a behavior change to the guard's verdict model**, well outside this wish's
  fence, and it wants its own argument

## .what makes it worth the catch

the verdict this round rests on is *"0 blockers from mech-test-intent"* — and that verdict
was rendered without a view of the test diffs. it happened to be corroborated by an
independent human-enrolled check. **the next round may not be.**
