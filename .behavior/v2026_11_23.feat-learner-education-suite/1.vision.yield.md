# vision: the learner education suite 📜

## .what this builds

role=learner ships three dispatcher skills. a director sends any role on a **pursuit**: the activity of education, one route that holds one or more **courses**. the role graduates once, with new briefs and skills; its **pedigree**, the record, gains one entry for the pursuit and its courses.

| skill | act | effect |
|---|---|---|
| `education.pursuit init --for <role> --slug <slug> [--course <slug>…]` | open a pursuit | findserts `.route/v$date.education.pursuit.$role.$slug/` with `.stone` + `.guard` files only, then binds it to the branch, as `declapract.upgrade init` does. `--course` seeds the plot, in order; with one `--course`, `--slug` defaults to it |
| `education.pursuit.course init --course <slug>` | descend into a course | the parent's `2.courses.pursue` runs it once per plotted course, in order: findserts `2.courses.pursue.yield/course=$k.$slug/` under the bound pursuit with the ten course stones, then swaps the bind to it (del, then set). fails fast (exit 2) unless the branch is bound to a pursuit route; the fix names `education.pursuit init` |
| `education.pursuit.course exit` | return to the pursuit | the only way a course ends: refuses until every course stone before `6.exit` has passed, then passes `6.exit` and swaps the bind back to the pursuit (del, then set) |
| `education.pedigree get [--for <role>]` | read the record | treestruct of every pursuit a role graduated, with its courses (all roles if `--for` absent; `rhx` eats `--role` as its own filter) |
| `education.pedigree set [--from <route>]` | record a pursuit | upserts one pedigree entry, keyed on `slug + date`; role, slug, and date read from the route dir name; courses read from the `course=$k.$slug/` dirs under `2.courses.pursue.yield/`, in `$k` order, never from `0.wish.md` (`--course` only seeds the plot, and `3.courses.review` may append courses); `--from` defaults to the bound pursuit route |

the shape mirrors `declapract.upgrade` (`.agent/repo=ehmpathy/role=mechanic/skills/declapract.upgrade.sh` + `declapract.upgrade/{init,output}.sh` + `templates/*.stone|*.guard`): a dispatcher that routes `init` (and later subcommands) to its handler; `init` checks its prereq, copies stones and guards only, binds, and prints a tree. per-skill engines follow the live learner's `learn.via.*` pattern (see `.the source it builds beside`).

the live learner role sits at `~/.rhx/refs/role=learner/`: 52 files (37 briefs incl. 11 `.min` peers and 7 `example=` ejections, 8 seeds, 7 skills). its skills are the extant pattern for this suite: `learn.via.walk` and `learn.via.reflect`, each a `.sh` (header doubles as `--help`, strips `--skill|--repo|--role`, `exec node` the engine) + a `.mjs` engine (`✋ ConstraintError` exit 2, `💥 MalfunctionError` exit 1, state under `<git root>/.agent/`) + an `.integration.test.ts` beside it, plus `init.learn.hooks.sh`. the education skills sit beside them as peers. the route holds a pointer and census: `refs/ref.source=role-learner-live.md`.

### .a pursuit is a stack of routes

a pursuit is a parent route; each course is its own child route beneath it. the parent plots the courses, then descends into each, in order, then graduates:

```
.route/v2026_11_23.education.pursuit.mechanic.reliable-writes/
├─ 0.wish.md                         # the role, the aim, any courses the director named
├─ 1.courses.plot.stone              # which subjects, in what order, what each builds on
├─ 1.courses.plot.yield.md           # the plot: courses in order, each with what it builds on
├─ 2.courses.pursue.stone            # descend into each course route, in order; pass once all pass
├─ 2.courses.pursue.yield/           # the stone's yield is a dir: one child route per course
│  ├─ course=1.idempotency/          # a route of its own: the standard course stones
│  │  ├─ 1.1.outcome.declare.stone
│  │  ├─ 1.2.outcome.baseline.stone
│  │  ├─ 2.1.greats.aim.stone
│  │  ├─ 2.2.greats.read.stone
│  │  ├─ 3.practice.vitro.stone
│  │  ├─ 4.1.entool.blueprint.stone
│  │  ├─ 4.2.entool.execute.stone
│  │  ├─ 5.1.outcome.assess.stone
│  │  ├─ 5.2.outcome.reflect.stone
│  │  └─ 6.exit.stone                # passes only via `education.pursuit.course exit`
│  └─ course=2.retries/              # builds on course 1's briefs
│     └─ …
├─ 3.courses.review.stone            # more courses needed, or graduate?
└─ 4.graduate.stone                  # stamp the pedigree
```

each child route sits inside the yield of the stone that pursues it, as `$stone.yield/` holds what `$stone` produced. a course route is the pursue stone's product, so it lives there, and the pedigree entry cites it by that path.

- **plot first.** `1.courses.plot` decomposes the aim into courses and their dependencies, and writes them in order. `--course` on init seeds the plot; it does not replace it
- **one course, one route.** each course route holds the same ten stones, unsubstituted; its name carries the course. a course's drive sees only its own subject
- **in order.** course k opens only after course k−1 has passed, so course k reads course k−1's briefs as given
- **review before graduation.** once every plotted course has passed, `3.courses.review` weighs the aim against what the courses yielded and decides one of two: **more courses** (append them to the plot, rewind `2.courses.pursue`) or **graduate** (pass to `4.graduate`, which stamps the pedigree). the loop runs plot → pursue → review until the review says graduate; its yield names each gap, or states that none remains
- **`education.pursuit` is the entrypoint.** a director runs only `education.pursuit init`. `education.pursuit.course init` runs within a pursuit, from its `2.courses.pursue` stone, and refuses to run anywhere else: a course with no pursuit has no plot to sit in and no pedigree entry to land in
- **the stack.** a branch holds one bind at a time (`setRouteBind.ts:67` refuses a second), so the bind marks the depth the driver stands at. two moves change it, and no other:

  | move | from → to | refuses when |
  |---|---|---|
  | `education.pursuit.course init --course <slug>` (push) | pursuit → course | the bind is not on a pursuit route |
  | `education.pursuit.course exit` (pop) | course → its pursuit | the bind is not on a course route, or a course stone before `6.exit` has not passed |

  each move is a swap, not a second bind: `setRouteBind` refuses a bind while another route is bound (`setRouteBind.ts:67`), so push and pop each delete the current bind flag, then set the new one. the two writes run under one lock (`withSimpleMutex`, keyed on the branch), so two swaps never interleave. `route.drive` reads the bind flag with no lock, so a drive in the milliseconds between the del and the set sees no bind; a re-run recovers

  the parent needs no stack file: a course route sits at `<pursuit>/2.courses.pursue.yield/course=$k.$slug/`, so exit computes its pursuit from its own path

- **a course ends only by exit.** each course route ends with `6.exit`, a stone that passes only via `education.pursuit.course exit`. so a course never reads as a finished route (where a driver stops or commits); it reads as a stone that sends the driver back up. exit passes `6.exit`, swaps the bind to the pursuit, and prints `rhx route.drive`, which resumes at `2.courses.pursue`. that stone then pushes the next course, or passes once every plotted course has exited

```
depth 0  pursuit   1.plot → 2.pursue ─┐                     ┌─→ 2.pursue ─┐              ┌─→ 3.review → 4.graduate
                                      │ course init         │ exit        │ course init  │ exit
depth 1  course 1                     └→ 1.1 … 5.2 → 6.exit ┘             │              │
depth 1  course 2                                                         └→ 1.1 … 6.exit┘
```

the phases of each course route; graduation once, in the parent. why this shape, with citations against the course-design canon: `briefs/define.education.pursuit.course.shape.md` (research: `appendix/research.course-structure-models.md`):

| phase | stone | yield |
|---|---|---|
| 1. outcome | `1.1.outcome.declare` · `1.2.outcome.baseline` | what the role must be able to do after the course, as assessment tasks with a pass bar; then a cold-booted role (enrolled as the target role only, no memory of the course) attempts them, and the result is recorded as the baseline |
| 2. greats | `2.1.greats.aim` · `2.2.greats.read` | the canon that closes the gap the baseline showed: who the greats are, why them, kernels with citations, each refutable kernel tagged a **claim** (`term=doc.kernel.claim`). reads by the researcher's method and fidelity rules: a kernel cites a page read via `bhrowser`, never a `websearch`/`webfetch` summary; a great known only by summary is a pointer, not evidence |
| 3. vitro | `3.practice.vitro` | whole, varied tasks of graded difficulty in an isolated sandbox (a temp repo or a scratch worktree, never the live tree); per claim: held, refuted, or untested. a refuted or untested claim sends the role back to `2.2` for a corrective read, then a retest |
| 4. entool | `4.1.entool.blueprint` · `4.2.entool.execute` | briefs + skills in the learner layout, landed where the table below says, before the next course begins; each new path named under `say` or `ref` in the `boot.yml` that table names (rhachet refuses an unnamed add in a mod) |
| 5. prove | `5.1.outcome.assess` · `5.2.outcome.reflect` | a cold-booted role, now with the new briefs, reruns the same tasks plus one real held-out task on a scratch branch; baseline → after recorded. below the bar → back to the weakest phase. then an after-action review: intended vs actual, why, keep vs change; it feeds the pursuit's `3.courses.review` |
| 6. exit | `6.exit` | passes only via `education.pursuit.course exit` |
| graduate (parent) | `4.graduate` | `education.pedigree set` writes the entry and names it in the same `boot.yml`: the role's own for own or native, the mod's for linked. for linked only, then `rhx init --hooks`, so the modded view picks it up; guard refuses passage until the entry exists, and, for linked, until the render exits clean |

where the pursuit lands, by target role kind. init resolves the role in this order; the first match wins:

| target role | how init knows | briefs + skills + pedigree land in | reaches the boot via |
|---|---|---|---|
| **own** — the repo publishes it (the expected case) | `rhachet.repo.yml` lists the slug | the role's source dir: `rhachet.repo.yml`'s `briefs.dirs` / `skills.dirs` with `dist/` read as `src/` (e.g. `src/domain.roles/mechanic/briefs/`); the role's own `boot.yml` names each add | the package's next build + release; the education ships with the role |
| **linked** — a dependency publishes it | `.agent/repo=$pkg/role=$slug` resolves into node_modules | `.agent/repo=.mods/role=$slug/` (rhachet mod, `of: $pkg/$slug`); the mod `boot.yml` names each add | `rhx init --hooks` re-renders the modded view; the pursuit can later be promoted upstream (dream) |
| **native** — `.agent/repo=.this/role=$slug` | the dir exists | in place | the next boot |
| **unknown** | none of the above | refused, valid roles listed | — |

pedigree shape (itemized by coordinate; root boots at `say`, entries at `ref` — named in the role's own `boot.yml` for an own or native role, or in the mod `boot.yml` for a linked one; a native role with no `boot.yml` boots by rhachet's default, so `set` writes none and changes no boot spec it does not own):

```
briefs/education/pedigree._.md                                     # the record: one row per graduated pursuit
briefs/education/pedigree.pursuit=v2026_11_23.reliable-writes.md   # one entry: courses, greats, kernels held + refuted, briefs, skills, route
```

each entry cites the pursuit's courses in the order they were pursued, each with its outcome, its greats, and its claims:

```
📜 education.pedigree (mechanic)
   └─ v2026_11_23 reliable-writes
      ├─ course 1: idempotency
      │  ├─ outcome: baseline 1/4 → after 4/4 · transfer task passed
      │  ├─ greats: helland · kleppmann · stripe · aws builders' library
      │  ├─ claims: 2 held, 1 refuted
      │  └─ yields: 2 briefs, 0 skills
      └─ course 2: retries (built on course 1)
         ├─ outcome: baseline 0/3 → after 3/3 · transfer task passed
         ├─ greats: aws builders' library · google sre book
         ├─ claims: 3 held
         └─ yields: 1 brief, 1 skill
```

`education.pedigree set` stamps the entry at `4.graduate` with no input: role, slug, and date from the pursuit dir name; courses from `2.courses.pursue.yield/`, in `$k` order; per course, the outcome from `1.2` and `5.1`, greats and claims from `2.2`, verdicts from `3`, yields from `4.2`. so each course yield holds a fixed shape (an outcome table, a greats table, a claims table) that `set` reads. a refuted claim stays on record: it tells the next reader what the role tried and rejected.

⇒ a role that boots holds its record. a director that reads `pedigree get` sees every role's.

## .the outcome world

### a day in the life

9am. the director reviews a mechanic pr that re-invents retry logic badly for the third time this month. the director runs:

```sh
rhx education.pursuit init --for mechanic --course idempotency
```

a clone enrolled as mechanic + learner + driver + researcher drives the route. the plot holds one course. the course declares its outcome (four replay tasks; pass bar: all four dedupe), and a cold-booted mechanic passes one of four. it names the greats (helland *idempotence is not a medical condition*, kleppmann *ddia* ch. 11, stripe idempotency-key docs, the aws builders' library), reads them, distills kernels with citations, and tags three as claims. in vitro, it builds a queue consumer in a temp repo, replays a message three times, watches a naive insert duplicate, then fixes it via natural-key upsert. one claim, that backoff alone makes a write safe, is refuted there and stays out of the role. it entools: `rule.require.idempotency-key-at-external-boundaries.md` + `.min`, `howto.replay-a-consumer-in-vitro.md`. a cold-booted mechanic, now with those briefs, passes four of four, plus one real replay task on a scratch branch. the review finds no gap; graduation stamps the pedigree.

3pm. the next mechanic session boots. its context now holds:

```
📜 education.pedigree (mechanic)
   └─ v2026_11_23 idempotency
      └─ course 1: idempotency
         ├─ outcome: baseline 1/4 → after 4/4 · transfer task passed
         ├─ greats: helland · kleppmann · stripe · aws builders' library
         ├─ claims: 2 held, 1 refuted
         └─ yields: 2 briefs, 0 skills
```

the next pr carries an idempotency key on the stripe call, and cites the rule.

## .the names — settled by domain discovery

evidence: [`1.vision.domain-discovery.md`](./1.vision.domain-discovery.md). the outcome:

| term | kind | why this word | rejected |
|---|---|---|---|
| `education` | noun, namespace | the domain: knowledge conferred from outside, on a director's charge | `learn` (held: retention of one's own lessons), `school` (a place) |
| `pursuit` | noun | the activity: one bounded act of education, open from `init` until graduation; holds 1..N courses | `degree` (the credential, not the act; a one-course degree reads heavy), `learnership` (rare outside south african english), `study` / `train` (forbidden synonyms of `learn`), `enroll` (overloads `rhx enroll`), `program` / `module` (software overloads) |
| `course` | noun | the unit inside a pursuit: one subject, its greats, its lab, its yields | `curriculum` (a plan, not a unit), `lesson` (a document kind, `kno201`), `subject` (review supplies-vs-subjects), `rotation` (ops overload) |
| `init` | subverb | the opener of a dispatcher skill, as `declapract.upgrade init`; findsert semantics | `gen` (no route-opener precedent) |
| `pedigree` | noun | the record: one entry per graduated pursuit, each with the lineage of greats it read; the wish's own word | `resume` (a self-curated pitch; overloads the verb "resume a route"), `transcript` (a term root here: `transcript.token.*`), `logbook` (overloads `.log/`), `provenance` (guard provenance), `cv`, `lineage` (names the chain, not the list of pursuits) |
| `kernel` | noun | one concept distilled from a doc; the thinker's word (`kno301.doc.kernelize`), already in use by researcher and librarian; declared `term=doc.kernel` | `nugget`, `takeaway`, `insight`, `point` |
| `claim` | noun | a kernel a test can refute; the only kind vitro gives a verdict; declared `term=doc.kernel.claim` | `hypothesis` (a guess before evidence), `assertion` (test assertions), `tenet`, `proposition` |
| `greats` | noun | the canon practitioners a course reads | `sources` (any input), `masters` |
| `vitro` | adj | practice in an isolated sandbox, before the live tree (vivo) | `sandbox` (a place, not a stage), `lab` |

## .mental model

- to a friend: *"you send a role to class. it reads the classics, does the lab, writes up what it learned, and gets a line on its record."*
- analogy: the guild journeyman. on his travels he works under one master after another; each master stamps his book. the travels are the pursuit, each master's bench a course, the stamped book the pedigree.
- their words vs ours: *class / school / resume* → `course` / `education` / `pedigree`; *"back to school"* → `pursuit`.

## .evaluation

### goals

| goal (wish) | met by |
|---|---|
| pedigree get/set records each course | `education.pedigree get|set` |
| init verb opens a standard route | `education.pursuit init` + four-phase template |
| route: greats → vitro → entool | phases 1–3 |
| lands in the learner brief layout | phase 3 obeys `.md` + `.md.min`, `rule.$directive.$topic`, `._.` roots |
| writes the pedigree | phase 4 + its guard |
| names settled by discovery | `.the names` above |

### pros

- reuses paved pavement: the research route's probe method, the rhachet mod overlay, the learner layout
- the pedigree boots with the role: no second place to look
- vitro isolates the experiment; a wrong kernel dies in the sandbox, never in a role's boot

### cons

- a course costs a full route of brain time; a cheap one-off brief does not need it
- briefs land in the role's boot (its source dir for own, `repo=.mods` for linked, in place for native), which adds boot mass under the role's budget; a big pursuit can breach it
- a brain chooses the greats; a weak canon yields a weak course (guard + self-review mitigate, not cure)

### edgecases → pit of success

| edge | contract |
|---|---|
| unknown role | refused, valid roles listed (case=4) |
| course reopened | findsert; kept files reported, none overwritten (case=3) |
| branch already drives another route, or is `main` | refused before any write; fix names a fresh branch (i10, i11) |
| same subject retaken later | new dated course; pedigree holds both |
| graduation with no entry | guard refuses passage (case=5) |
| course slug not kebab | refused with the fix |
| mod boot breaches budget | rhachet's own budget check fires at boot; course `3.1` blueprint names boot mass as a constraint |
| a linked role's mod write rhachet refuses (unnamed add, orphan `.md.min`, an add the role's own `not` drops) | a refused mod blocks every actor that carries the role, so `4.graduate` holds until `rhx init --hooks` exits clean; rhachet's refusal names the fix (d6, case=8) |

## .open questions & assumptions

assumptions:
- an own role's pursuit output belongs in its source dir (`rhachet.repo.yml` dirs, `dist/` read as `src/`); a linked role's belongs in `.agent/repo=.mods/role=$role/`, which rhachet 1.54.1 supports; a native role's lands in place
- the clone that drives a course enrolls the target role + learner + driver + researcher (the target role for its extant briefs, learner for the entool rules, driver for `route.drive`, researcher for the probe method and its fidelity rules); init's hint prints that enroll line. `bhrowser` (the `playwright` role of `rhachet-roles-bhrowser`) is the read tool the researcher rules name; where it is absent, phase 1 labels each `websearch` pointer as such, per `rule.forbid.websearch-and-webfetch`
- the pedigree records graduated courses only; an open course is visible via its route, not the resume

questions, triaged:
- [answered] should `pedigree get` list open courses? no. the wish has the pedigree record each course a role *has had*: a completed act. an open course is visible via its bound route (F4)
- [answered] should a course offer its briefs upstream, to the role's own package? not in this pr: no done-line asks for it, and the wish bounds the size to medium. caught as a dream: [`dreams/v2026_11_23.feat.course-offers-its-briefs-upstream.md`](./dreams/v2026_11_23.feat.course-offers-its-briefs-upstream.md)
- [answered] does `pedigree set` need `--for` and `--course`? no. the route dir name holds both, and the bound route is the default (`.what this builds`)
- [answered] does `route.drive` find a pursuit route under `.route/`? yes, via the shared route bind (`.groundwork`)
- [answered] which stones carry a quality guard, since `4.graduate` checks only that the entry exists and the render is clean? `1.2.greats.read` (self-review: each kernel cites a page read, per the fidelity rules) and `3.1.entool.blueprint` (self-review: each planned brief traces to a held kernel; refuted ones excluded, untested ones marked). these two are where a weak course would ship a falsehood (case=6, phase 1 fidelity). no peer-review lanes in the template: a repo that wants them adds a lane to its own course guard

- [answered] should a consumer that educates a linked role via a mod promote that education upstream? yes, later: a subcommand beside `init`, caught in the same dream (S3)
- [wisher] best-guesses, each a clean rework, ratified or redirected at the commander's pr review; not a halt:
