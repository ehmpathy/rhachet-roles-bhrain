# 🌙 dream: auto-grant one more round when the last round had an urgent concession

- **kind** = feat · **owner** = `rhachet-roles-bhrain` · **caught 2026-09-14**

## .the cue that fired

the wisher, mid-design on `v2026_09_08.feat-dispute-or-concede-review-budget`, verbatim:

> *"and catch a dream and dispatch a task back into this repo to automatically add budget on
> --concede urgent. i.e., if the last round had an urgent one, automatically allow one more."*

⇒ the wisher named both the dream and its dispatch in one breath. the this-PR half is the **warn**;
the auto-grant is the deferred half.

## .the gap, precisely

this PR delivers the WARN: a budget hit with ≥1 live urgent concession halts and tells the human to
grant more budget (`define.invariant.review.peer.budget.urgent-earns-budget`). the human still runs
`route.guard.budget --add N` by hand.

the dream removes the hand step: **if the last round carried a live urgent concession, the engine
auto-grants one more round** — no human, no halt. the warn becomes a notice, and the round is already
bought.

**checkable:** today the exhaustion halt reads the concession severities to decide whether to summon
a human (`isRouteGuardConcessionExhaustion`, refined by severity). no code path calls
`route.guard.budget` on the engine's own initiative — the budget is added only by an explicit cli
invocation. so the auto-grant does not exist.

## .why it is worth a round of its own

- a `better`-only budget hit already proceeds with no human (this PR). so the ONLY case a human is
  summoned for is an urgent concession — and the wisher's point is that an urgent concession is
  exactly the case the engine could handle itself, once, without a human at all.
- ⇒ the auto-grant collapses the last human touch the severity split leaves in place. the human is
  warned this PR; the dream lets the round happen and warns after.

## .the shape of the fix

1. **a bound on the auto-grant** — "allow one more" is one round, not a blank check. the engine
   grants exactly one round per urgent concession per generation, and a second urgent concession on
   the granted round is the human's call again (or the bound is `--auto-urgent-rounds N`, configured
   on the guard).
2. **the trigger** — at the exhaustion check, if the prior round carried ≥1 live urgent concession
   and the auto-grant bound is not spent, add one round to the latest level and re-run rather than
   halt.
3. **the record** — the auto-grant is a passage/meter event, so a council can see the engine bought
   a round and why (which urgent concession earned it).
4. **the warn survives** — the human is still told, after the fact, that an urgent concession earned
   an auto-round, so a run of urgent concessions is visible rather than silent.

## .why it is not done in this round

**safe? no. clean? no.**

- 🔴 **the engine would spend budget on its own initiative** — a new authority. today every budget
  add is an explicit human or driver command; an engine that tops up autonomously crosses that line,
  and it must be bounded and recorded before it ships.
- **it needs a per-generation counter** the ledger does not carry — how many auto-rounds this urgent
  concession has already earned — or an unbounded urgent concession loops forever.
- 🔴 **it interacts with the dispute skip and the per-severity exhaustion split this PR just landed.**
  the auto-grant must fire only for an urgent CONCEDE, never a dispute (a dispute earns no budget by
  any severity), and only at the exhaustion boundary — a mis-scope re-runs a lane the driver disputed.
- **the warn this PR ships is the honest floor** — the human is told to grant more, and grants it.
  the dream removes a hand step; it does not fix a defect. so it waits.

⇒ deferred for **dirt**, so a fulcrum is owed beside the dream: `F029` on
`v2026_09_08.feat-dispute-or-concede-review-budget`'s board.
