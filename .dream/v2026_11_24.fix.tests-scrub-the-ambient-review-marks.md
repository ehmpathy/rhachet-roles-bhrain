# 🌙 dream: tests scrub the ambient review-child marks

kind: fix · owner: rhachet-roles-bhrain · caught 2026-11-24

## .the cue that fired

5.3.verification r010 (`enroll-verif-snapshot-coverage`), rounds i008 and i009. a guard-summoned review clone ran `setStoneAsPassed.exhausted` and read its two `[t3]` hook assertions red (`Expected: 2, Received: undefined`). it also read 6 of 8 red in `peer-mixed-verdict-replay` and 36 red across the `driver.route.drive*` hook suites. in a clean env the same suites pass (55/55, 8/8).

## .the gap, precisely

a review clone inherits `RHACHET_REVIEW_SUBPROCESS=1` (`ENV_OF_REVIEW_CHILD.subprocess`, an INHERITED marker). `stepRouteDrive.ts:85` returns silent output under that mark. the jest envs (`jest.{unit,integration,acceptance}.env.ts`) do not scrub it, and the acceptance harness's `asChildEnv` spreads `process.env` into each child. so every hook-mode test is non-hermetic: it reads red inside a review clone for a reason outside its diff, and a reviewer cannot verify the hook behavior it is asked to grade.

## .the shape of the fix

- in each `jest.*.env.ts`, delete every `ENV_OF_REVIEW_CHILD` mark from `process.env` at setup (a deliberate mutation, before any test reads it). a test that means a mark sets it itself
- clamp: a test that spawns the jest run as a child with `RHACHET_REVIEW_SUBPROCESS=1` in its env and asserts a hook-mode case passes. revert the scrub → red; restore → green

## .why it is not done in this round

it touches the shared test env of every suite in the repo (not clean), and this shell cannot set the mark to prove the clamp red-then-green (the permission hook refuses an env prefix). an unproven change to shared test setup in a pr about the budget lever is the wrong trade. fulcrum F11.
