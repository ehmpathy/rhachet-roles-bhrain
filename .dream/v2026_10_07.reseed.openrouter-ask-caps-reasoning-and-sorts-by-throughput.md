# 🌙 dream: an openrouter ask caps its reasoning tokens and prefers a fast host

- kind: reseed
- owner: ehmpathy/rhachet-brains-openrouter
- caught 2026-10-07

## .the cue that fired

at 5.1 i014 (`.behavior/v2026_09_20.review-cost-meter`, hash `c3c17173ac16e63991`) eleven of 27
review lanes on `openrouter/deepseek/flash` hit the 20-minute review deadline with no reply. the
prime meet was not the cause: no lane wrote a prime fault line, and each timeout fired inside
`withDeadline` around the brain call itself.

## .the gap, precisely

the cost of a review lane on a reasoning model is mostly OUTPUT, and that output is reasoning
the reply never shows:

| run | output tokens | wall time | throughput |
|---|---|---|---|
| `2026-10-07T11-35-32-755Z…` (verdict: 0 blockers, 0 nitpicks) | 48,682 | 309s | 158 tok/s |
| `2026-10-07T11-41-53-782Z…` | 17,647 | 531s | 33 tok/s |
| `2026-10-07T09-09-00-027Z…` | 60,990 | 445s | 137 tok/s |
| `2026-10-07T12-55-07-610Z…` (i015 r008: `finish_reason=length`, empty reply) | 131,072 | — | — |
| i016 r013 `ergo-friction-hazards` (`finish_reason=length`, reply withheld) | 131,072 | — | — |

- the first row bills `$0.097` of output against `$0.044` of input, for an empty verdict
- at the 33 tok/s some hosts served today, a 40k-token think runs past 20 minutes, which is
  exactly the eleven timeouts
- the fourth row is the same unbounded think with no deadline in its way: it spent the model's
  whole output limit and wrote no review at all, so the lane paid in full for a malfunction
- `rhachet-brains-openrouter@0.1.3` sends no `reasoning` bound and no `provider.sort`, so
  neither the think length nor the host's speed is under the caller's control

## .the shape of the fix

1. accept an optional reasoning bound on `ask` (openrouter's `reasoning: { max_tokens }` or
   `effort`) and forward it in the request body
2. accept an optional `provider.sort: 'throughput'` preference, which composes with the
   admitted-set filter `asProviderPreference` already builds
3. then in this repo: `stepReview` passes a reasoning bound sized to the deadline (for example
   the deadline's seconds × a floor throughput), so a slow host shortens the think rather than
   blows the deadline, and the output share of the bill falls with it

### .what the numbers say

1. 🔴 **the reasoning cap is not honored on these hosts.** every capped arm on a real review prompt
   thought past its cap: b16 18,079 / 24,619 / 39,793 / 50,559 · c16 12,730 / 23,899 / 35,650 /
   35,110. InferenceNet
   ignored a 1,024 cap on the puzzle outright (4,127 vs 4,005 uncapped). Together cut the puzzle's
   think 6× under a 1,024 cap, but on a long review prompt a 16k cap bought 12.7k–50.6k (seven of eight over the cap). ⇒ the cap is
   at best advisory and host-dependent; **it cannot be a deadline guarantee**, which was the fix's
   premise ("a slow host shortens the think rather than blows the deadline")
2. 🟢 **the host is the lever, not the cap.** every off-floor arm (Together) returned a verdict, in
   41–166s, on all four prompts — P1 and P2 too, which logged a 131,072-token runaway and no
   verdict. the floor arms that replied with a full think took 208–559s on P4/P3 and **815s /
   1,192s** on P1/P2 (P2 a hair under the 20-minute review deadline); two of eight P4/P3 floor
   arms never replied within 590s, and one (P4 a:1) fell to Morph, which returned **zero**
   reasoning tokens and missed the logged blocker
   - 🟡 honest bound: the 131,072-token runaway did NOT reproduce in this replay on either host
     (the floor b16 arms stopped at 41k / 51k out). so the evidence is "off-floor is 5–8× faster on
     these prompts", not "off-floor cures the runaway" — one replay per arm cannot show the latter
3. 🟡 **cost: a wash, and it rides on cache, not on the cap.** Together's per-run $ swung 0.0185 ↔
   0.1256 on one prompt, by whether the prefix was cached (293,632 vs 0 cached tokens). where it hit
   cache it was as cheap as or cheaper than the floor (P4 c16 $0.0185 vs floor $0.0355–0.0577); where
   it missed, 2–4× dearer (P1 c32 $0.2225, P2 c16 $0.2332). each pair of concurrent identical asks
   split one cached / one cold — the prime-before-pour pattern would make the cold half warm
4. 🟡 **quality held off-floor.** recall of the logged concern: Together 4/4 on P4/P3 (the two
   prompts with a logged verdict), and P1/P2 each converged on the same concerns across c16/c32;
   floor 2/8 strict (b16 on P4, b16 on P3), two more that returned it graded as a nitpick rather
   than a blocker. the same concern flips blocker ↔ nitpick across floor runs, and P4 a:1 vs a:2
   disagree on the concern itself — that is baseline variance, and it is wide
5. 🔴 **`effort: 'none'` is fast and cheap and wrong**: 0 reasoning, 32s, $0.0144 on P3, but it missed
   the logged concern and the puzzle answer was wrong. not a candidate

### .the verdict — CONDITIONAL, and the condition is the host, not the cap

- **the reasoning cap alone: not worth it.** it does not bound the think on the floor's hosts, so it
  neither prevents a timeout nor reliably cuts output spend; it adds a knob whose effect a caller
  cannot predict. ship it upstream only as a pass-through option (it is harmless and Together
  partly honors it), never as the deadline mechanism
- **a throughput-sorted, off-floor host set: worth it, for long review lanes.** it returned a verdict on every
  prompt, two of which had logged runaway malfunctions, and cut wall time 3–10× (P1 815s → 105–138s;
  P2 1,192s → 142–166s; P3 477–559s → 72–88s), at equal or better recall. its cost
  is a wash only when the prefix is cached, so it should land together with the prime-before-pour
  rule this repo already holds; cold, it costs 2–4× the floor
- ⇒ the fix's shape changes: item 2 (`provider.sort`) is the decisive half, and it must be offered
  as an alternative to the floor walk (the floor admits one endpoint per hop, so a sort inside it
  does naught). item 3 should size the deadline by the HOST's measured throughput, not rely on a
  reasoning cap to shorten the think
- the patch was reverted; this branch runs the stock 0.1.3
- bounds on this evidence: one replay per arm (two for the P4/P3 baseline), four prompts, one day's
  host mix. measured spend ≈ $1.22 across 17 review replies + the probes, plus two P3 floor arms killed at 590s
  whose bill was never observed

| wall | ~219s / ~238s from generation to given (~550–600 tok/s, faster than any completed lane on that host at ~150–475 tok/s) — a hint of a degenerate repeat, not proof |
| looped? | **unknowable from here**: the package withholds the partial reply, and keeps no think text on a defect |

⇒ two more asks for this package, beside items 1–2 above:

4. on a `finish_reason=length` defect, keep the tail of the think (say its last 2k chars) in the
   error's metadata, so a caller can tell a loop from a long think
5. accept an output bound on `ask` (`max_tokens`), so a caller can make a runaway fail at, say,
   64k rather than bill the whole 131k — this repo's in-tree bound is one retry
   (`withOutputLimitBrainRetry`, fulcrum F180), which caps the asks but not the spend per ask
