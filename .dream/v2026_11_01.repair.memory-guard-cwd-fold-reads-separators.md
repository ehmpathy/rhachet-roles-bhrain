# 🌙 dream: the memory guard's cwd fold reads the separator before each command

- kind: repair
- owner: rhachet-roles-bhrain, learner role
- caught 2026-11-01

## .the cue that fired

the arch-defects lane, round i011 on `v2026_11_01.fix-memory-guard-fails-open`, nitpick 5: `cd M && cat a.md && cd /repo && echo x > out.txt` blocks as a write into memory, though the file lands in /repo.

## .the gap, precisely

`getAllBashCommandSegments` drops each separator, so `getAllBashSegmentScenes` cannot tell `&&` from `||` or `;`. to stay sound it keeps every cwd the shell may hold, and a `cd` only adds to the set.

## .the shape of the fix

- the splitter returns `{ segment, separatorBefore }`
- the fold replaces the set with the `cd`'s target when the separator after the `cd` is `&&` (the next command runs only if the `cd` succeeded); it keeps the union for `||`, `;`, `&`, and `|`
- rows: the reviewer's command allowed; `cd M || cd /repo; echo x > out.txt` still blocked; `cd M; cd /repo && echo x > out.txt` allowed

## .why it is not done in this round

the union errs only toward a block, so the wish's hard term holds; the cure reaches the splitter every grader reads. fulcrum F12.
