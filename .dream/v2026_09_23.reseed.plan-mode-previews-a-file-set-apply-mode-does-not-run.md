# 🌙 dream: `--mode plan` previews a file set `--mode apply` does not run

**kind**: reseed · **owner**: `ehmpathy/rhachet-roles-ehmpathy` (`git.repo.test`) · **caught** 2026-09-23

## .the cue that fired

a verification stone dropped `--thorough` (forbidden by `rule.forbid.thorough-test-runs`) and had to
state, in its gate table, **what breadth the sanctioned default actually covers**. the obvious way to
answer that is plan mode, whose own help line says *"preview matched files (plan mode default)"*.

it does not answer it. the same suite reports **three** different counts:

```
$ rhx git.repo.test --what integration           # plan (the default)
   ├─ scope: all
   │  └─ matched: 17 files
   🥥 did you know?
      └─ run with `--mode apply` to execute       # ← implies it will execute THESE

$ rhx git.repo.test --what integration --mode apply --env test
   └─ 70 files                                    # ← ran 4.1× the previewed set

$ rhx git.repo.test --what integration --mode apply --thorough
   └─ 125 files                                   # ← the whole suite
```

🔴 **the cue is the middle number, and it is the one no flag asks for.** `17` and `125` are both
explicable — the changed-file set and the full set. `70` is neither, and it is what the gate actually
ran.

reproduced across all three suites on 2026-09-23:

| suite | plan | apply | thorough |
|---|---|---|---|
| unit | 20 | **123** | 234 |
| integration | 17 | **70** | 125 |
| 🟡 acceptance | 5 | **132** | 131 |

🟡 **the acceptance row carries its own discovery**: apply ran `132` where the full suite is `132`,
so at that grain the default IS full breadth and plan previewed `5`. ⇒ **a 26× understatement**, and
the direction is the dangerous one — a caller who trusts the preview budgets for 5 files and waits 28
minutes for 132.

## .the gap, precisely

plan appears to list the **test files the diff touched directly**; apply appears to run those **plus
the tests related to every changed source file** (a `--findRelatedTests`-shaped expansion). both are
defensible selectors. what is not defensible is that **the mode whose job is to preview the other
mode reports the narrower one.**

⇒ the plan/apply contract is that plan is apply **minus the side effects** — same decisions, same
selection, no execution. here the two modes disagree about the selection itself, which is the one
matter plan exists to settle.

### 🟡 the harm direction, stated honestly

it fails **narrow**, which is the opposite of the `--scope` defect filed beside it — so a caller is
surprised by a run that is *bigger and slower* than previewed, never one that silently skipped work.
no test goes unrun because of this.

🔴 **the sharp half is again a PROOF CLAIM.** a buttonup gate cites a command beside its output and
asks a reviewer to believe they describe one event. a driver who reaches for plan mode to document
*"what breadth did my gate cover?"* gets `17`, writes it down, and has recorded a number that no run
produced. the honest figure is only obtainable by an apply run — i.e. **the preview cannot be used to
describe the run it previews.**

⚠️ and it is invisible from the inside: every number printed is internally honest. the only tell is a
side-by-side of the two modes, and no cue prompts it — the same blind spot the `--scope` dream names,
one flag over.

## .the shape of the fix

1. make plan mode run the **identical selector** apply runs, and print that set
2. 🟡 if the expansion is expensive, that is a reason to show it, never to skip it — print the two
   tiers explicitly: `matched: 17 changed · 70 related · 125 total`, which answers the breadth
   question outright and makes the `--thorough` delta legible without the flag
3. 🔴 **the clamp, and it must be seen red first**: a temp repo with a changed source file whose
   dependents are not themselves changed; assert `plan`'s printed set equals `apply`'s executed set.
   against today's code that clamp goes green-when-it-should-be-red, so it must be authored to fail
   first (`rule.require.clamp-edge-cases`)
4. repair the `🥥 did you know?` line, which currently promises apply will execute the previewed set

⛔ **not a fix**: to narrow apply down to plan's set. the expansion is the *correct* behavior — a
changed source file's tests must run. the defect is in what plan reports, never in what apply runs.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| leg | verdict |
|---|---|
| SAFE? | 🔴 **not ours to judge.** the skill is consumed by every repo in the org; its mode semantics are a published contract, and step 2 changes its stdout shape |
| CLEAN? | 🔴 **no.** the file is not in this tree — `.agent/repo=ehmpathy/role=mechanic/skills` is a symlink into `node_modules`, so an edit here is erased by the next install |

⇒ a tree adopts only what is scoped to itself, so this is a `reseed` owed to
`ehmpathy/rhachet-roles-ehmpathy`, never a fix deferred for size.

## .the fulcrum

> **a preview that previews a different set is worse than no preview**, because it is believed. the
> `--scope` defect beside it answers a question about the repo with a fact about the machine; this
> one answers a question about *the run you are about to take* with a fact about a run nobody takes.
> both land in the same place — a proof block, where the command and its result are supposed to be
> the same claim stated twice.
