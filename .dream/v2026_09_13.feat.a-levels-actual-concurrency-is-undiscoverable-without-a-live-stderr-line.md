# 🌙 dream: a level's actual concurrency is undiscoverable without a live stderr line

- kind = feat
- owner = the peer-review-parallelism route (or whoever next touches `runStoneGuardReviews` / the guard cli surface)
- caught = 2026-09-13

## .the cue that fired

r10 `enroll-impl-behavior-intent` at i016, §2 — the one ergonomic gap it found tracked NOWHERE
(paraphrased to drop gerunds; the sense is intact):

> a driver has no way to discover what concurrency a level actually pours at, short of a live stderr
> announce line or a source read. `RouteStoneGuard.ts` own comment concedes the level default is not
> even a `.guard` key. no `--show-concurrency`/dry-run surface exists.

## .the gap, precisely

the effective per-level bound is `min(levelConcurrency, Σ min(groupBound, membersHere) + ungrouped)`
(`getOneReviewLevelPourBound`). the level default (`DEFAULT_LEVEL_CONCURRENCY = 10`) is NOT a
`.guard` key — so an author cannot read their guard file and know what a level will pour at. the one
place the computed bound surfaces is the live pour announce on **stderr**
(`🦉 l3 pours 3 lanes · ≤1 at a time`), which:

- appears only on a real arrive (spends budget),
- is suppressed under a pipe (the spam arithmetic at `genContextCliEmit.drawStatus`),
- scrolls past and is gone.

⇒ discoverability is its own concern and no acceptance test treats it as one. a driver who wants
"what will level 3 pour at?" has no read that answers without a run or a source dive.

## .the shape of the fix

a dry-run surface that prints the computed per-level bound with no pour:

- a `--show-concurrency` (or `route.guard.show`) flag that parses the guard, runs the roster through
  `getOneReviewLevelPourBound` per level, and prints one line per level — `level 3: 3 lanes · ≤1 at
  a time (group serial=1)` — plus the group leaks `getAllConcurrencyGroupLeaks` already computes.
- it reuses the extant announce transformer (`asReviewLevelPourAnnounce`) so the dry-run string and
  the live string cannot drift.
- ⚠️ consider a surface for the level default as an explicit `.guard` key too (the `RouteStoneGuard`
  comment concedes it is absent), so the guard file is self-descriptive rather than
  default-by-omission.

## .why it is not done in this round

DIRTY, and out of the wish's scope. the wish is intra-level concurrency + the valve; a discovery
surface is a new cli command with its own contract, help text, and acceptance coverage. graded a
nitpick by r10. worth a feat when the guard cli next opens.
