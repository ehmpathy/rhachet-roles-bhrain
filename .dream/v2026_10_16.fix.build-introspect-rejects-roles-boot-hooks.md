# 🌙 dream: `npm run build` fails at `rhachet repo introspect` — ten roles carry `roles boot` onBoot hooks

kind: fix · owner: ehmpathy/rhachet-roles-bhrain · caught 2026-10-16

## .the cue that fired
`npm run build` exits 2 at `build:complete:repo`. rhachet 1.49.2 `repo introspect` refuses with
`✋ ConstraintError: hooks that boot their own role` for achiever, driver, learner, librarian,
navigator, reflector, researcher, reviewer, telepath, thinker — each declares
`onBrain.onBoot[0] = ./node_modules/.bin/rhachet roles boot --role <self>`.

## .the gap, precisely
rhachet ≥1.49 renders every enrolled role's briefs into the brain dir's `boot.md`, so a self-boot
hook double-boots. `dist` still builds and swaps before the introspect step, so shipped code is
current; the gate itself is red, and CI that runs `npm run build` will fail.

## .the shape of the fix
- delete each `roles boot --role <self>` onBoot hook from the ten role manifests
- 🟡 first settle the peer range: `package.json` declares `rhachet >=1.41.21`. a pre-1.49 rhachet
  may boot briefs only through that hook. either raise the peer floor to the release that renders
  `boot.md`, or keep the hook behind a version check — measure which release introduced `boot.md`
- re-run `npm run build` until introspect passes

## .why it is not done in this round
dirty: it ripples across ten role manifests and the package's peer contract, outside this route's
wish (a status-line init). the peer-floor call is a release decision. fulcrum F10 on the route.
