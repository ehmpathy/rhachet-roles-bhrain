# 🌙 dream: git.release --watch must judge the head it was asked about, never the prior one

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=git.release)
- caught 2026-11-24

## .the cue that fired
right after a push of `c83b8af4` to pr #838, `rhx git.release --watch` printed `👌 all checks passed` and `✨ done! 0s in action, 0s watched`. `gh run list` at the same moment showed the `test` run on `c83b8af4` still `queued`.

## .the gap, precisely
the watch reads the pr's check rollup before github registers the new head's runs, so it sees the prior head's green checks and reports done. a red run on the new commit would then go unseen by a driver who trusts the skill (rule.require.watch-release-after-push leans on it).

## .the shape of the fix
read the pr's `headRefOid`, and only judge checks whose head sha matches it; if no run for that sha exists yet, wait for one to register (with a bound) before any verdict. clamp: push a commit, call the watch at once, assert it does not report done until a run on the new sha completes.

## .why it is not done in this round
the skill lives in another repo; this route is a practice upgrade. the driver watched the run by hand (`gh run watch`) instead.
