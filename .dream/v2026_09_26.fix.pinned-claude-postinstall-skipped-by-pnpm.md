# 🌙 dream: the pinned claude cli installs with no binary on a fresh pnpm install

kind: fix · owner: rhachet-roles-bhrain · caught 2026-09-26

## .the cue that fired

a bump of `@anthropic-ai/claude-code` 2.1.87 → 2.1.280 (to clear the enroll lanes' version
floor) reported success, and `node_modules/.bin/claude --version` then answered
`Error: claude native binary not installed`.

## .the gap, precisely

- 2.1.x ships its native binary via a postinstall (`install.cjs`)
- pnpm skips a dependency's postinstall unless it is allowlisted; this repo declares no
  `pnpm.onlyBuiltDependencies` in `package.json` and has no `pnpm-workspace.yaml`
- ⇒ every fresh clone and every `pnpm install` leaves the guard's claude without a binary, and
  every l3 enroll lane malfunctions until someone runs the postinstall by hand

## .the shape of the fix

add to `package.json`:

```json
"pnpm": { "onlyBuiltDependencies": ["@anthropic-ai/claude-code"] }
```

then prove it: a clean `pnpm install` in a temp clone, and `node_modules/.bin/claude --version`
answers the pinned version.

## .why it is not done in this round

it is clean (one key in one file) but not plainly SAFE: it grants a vendor postinstall the right
to run on every install, which is a supply-chain policy call for a human. the manual step is
recorded in `hazard.pinned-claude-shadows-global.md` meanwhile.
