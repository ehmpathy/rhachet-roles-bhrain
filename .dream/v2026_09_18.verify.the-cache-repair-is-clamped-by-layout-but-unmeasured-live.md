## .the shape of the fix

run the meter where reviews actually run — a tree that has driven a guarded stone through several
rounds — and read two fields side by side, per reviewer, per round:

1. `prompt.sharedPrefix.sentAs` — must read `brief`. a `prompt` there explains a 0% rate outright,
   with no further diagnosis owed
2. the cache hit share — `cache.get` tokens over total input tokens

the prediction the repair makes, and the claim to falsify:

| transition | predicted |
|---|---|
| round1 → round2, one reviewer | a hit share that tracks the ~80% shared prefix, never ~3% |
| round2 → round3 | higher still (~93% shared) |
| across lanes within one round | a non-zero hit on the block all nine lanes share — `## output format` now sits inside it |

a run whose `sentAs` reads `brief` and whose hit share stays near zero is the **sharp** outcome: it
would mean the pin is sent and the replica still misses, which is an upstream question
(⇒ `ehmpathy/rhachet-brains-fireworksai#21`) rather than a layout one.

## .why it is not done in this round

the SAFE/CLEAN test, answered:

- **safe** — yes. a read-only meter run touches no behavior
- **clean** — 🔴 **no.** it needs a corpus this tree does not have, and to manufacture one costs a
  live brain call against a real review. that is spend, not a diff

⇒ so it defers. the repair itself is complete and clamped; what is owed is the **confirmation**,
and confirmation is cheapest gathered from runs that would have happened regardless.
