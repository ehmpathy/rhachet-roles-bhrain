# 🌙 dream: `init.research` is not idempotent across a UTC midnight

- **kind** = fix
- **owner** = this repo (`rhachet-roles-bhrain`)
- **caught** = 2026-09-19

## .the cue that fired

a full acceptance run started six minutes before UTC midnight on 2026-09-18 and returned
**1 failed / 3550 passed**. the one failure was `init.research [case2] ... (idempotent)` — a suite
this round never touched.

re-run a quarter hour past midnight, away from the boundary: **6 passed**. the failure is real and
it is a clock, not a regression.

## .the gap, precisely

a research dir is named `v$YYYY_MM_DD.$name` (`setResearchBind.ts:47-48` parses exactly that
shape back off). the bind flag records the **dir**, so the date is part of the identity.

⇒ the idempotency check compares the **computed** dir against the **bound** one:

```ts
// setResearchBind.ts:62-77
const researchDirFound = ...;
if (researchDirFound === researchRelative) return { ... };   // the idempotent path
throw new BadRequestError(
  `already bound to ${researchDirFound}. use research.bind --del first`,
  { researchBound: researchDirFound, researchRequested: input.researchDir },
);
```

so a second `init.research --name X` that lands on the other side of a UTC midnight computes
`v2026_09_19.X`, finds `v2026_09_18.X` bound, and takes the **throw** branch:

| the call | the computed dir | the outcome |
|---|---|---|
| first, 23:59Z | `v2026_09_18.consensus-algorithms` | ✅ created + bound |
| second, 00:00Z | `v2026_09_19.consensus-algorithms` | 🔴 `already bound to …` → exit 1 |

**the test asserts `exit 0`** (`blackbox/init.research.acceptance.test.ts:124`), so it goes red.

🔴 **the harm is not the red test — it is the driver.** a human who runs `init.research` twice
around midnight is told to `research.bind --del first` for a research they already own, under a
name they typed identically both times. the command that advertises idempotency refuses them.

## .the shape of the fix

**key the idempotency on the NAME, not on the dated dir** — the name is what the caller supplies
and the only part they control.

`setResearchBind.ts` already knows how to strip the date (`:48`,
`researchDirName.replace(/^v\d{4}_\d{2}_\d{2}\./, '')`). so the compare at `:67` becomes a compare
of **names**, with the dir returned as-is:

- names equal → idempotent. return the **bound** dir, never the newly-computed one
- names differ → the extant `already bound to …` throw, unchanged

⇒ and `initResearchDir` must not have minted a second dated dir before the bind is consulted, or
the repair leaves an orphan `v2026_09_19.X/` on disk. **check the order of those two operations**;
if the dir is created first, the lookup has to move ahead of it.

🟡 **the clamp is cheap and it must bite** (`rule.require.clamp-edge-cases`): create the first bind
against a back-dated dir (`v<yesterday>.X`), then call `init.research --name X` and assert exit 0
plus that the returned dir is the **back-dated** one. reverting the fix must turn it red — the
extant test cannot, because it only fails in a ~1-in-5760 window.

## .why it is not done in this round

**SAFE?** no. it changes the bind's identity rule for every `init.research` caller, and the
orphan-dir question above is unanswered — the repair may need to move an operation, not edit a
compare.

**CLEAN?** no. it lands in `src/domain.operations/research/init/`, a subsystem this round's diff
does not open. this round is the self-review guard (`route/guard/review/self/`).

⇒ so it fails both questions of `rule.always.fix-forward-under-scouts-honor`, and the deferral is
the rule's own answer rather than a dodge.

⚠️ **and it is worth catching precisely because it hides.** the window is ~4 seconds of a 1269s
run, so this will read as a flake to whoever meets it next and will be re-run away. the diagnosis
is the expensive half, and it is above.
