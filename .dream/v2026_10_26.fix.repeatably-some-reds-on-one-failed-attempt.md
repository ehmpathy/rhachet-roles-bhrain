# 🌙 dream: a `when.repeatably` suite graded SOME still reds when one late attempt misses

- kind: fix
- owner: test-fns (or this repo's test-fns patch), via a deflake route here
- caught 2026-10-26

## .the cue that fired

ci run 40286586280 on pr #692, shard integration 3/3:
`stepReview.casePromptCache` [case1] ran three attempts under `criteria: 'SOME'`. attempts 1 and 2
passed every `then`; attempt 3 failed one (`the serve covers most of round 2's prompt`, 0.017 vs
> 0.5). the suite reported 1 failed, and the shard went red.

## .the gap, precisely

`SOME` promises a pass when any attempt passes. each attempt's `then` blocks register as their own
jest tests, so a miss in a later attempt still counts as a failed test, whatever the prior attempts did.

## .the shape of the fix

- once an attempt passes every `then`, the later attempts skip (or never register), or
- a failed `then` in an attempt reads as a pass when a peer attempt passed the same `then`
- clamp: a fixture suite with attempts [pass, pass, fail] under SOME is green; [fail, fail, fail] is red

## .why it is not done in this round

the defect lives in test-fns, a dependency, and the suite is unchanged from main. the fix is its own
deflake route, not this pr's boot-budget scope.
