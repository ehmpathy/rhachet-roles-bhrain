# case=6 — a cue lost in the rewrite

**feel** sharp · **care** critipath (≈60 mins are rewritten by hand; one dropped row is silent)

## narrative

the driver of this route condenses `rule.always.spend-own-levers-before-escalation.md.min`. in the
cut, the owner-table row for *"a direct edit of `$route/<stone>.guard`"* goes too, because it sat
inside a paragraph of argument. the boot still passes, and it is now under budget. no reader would
notice until a driver files an overflowed lane as a fulcrum again.

two guards catch it. in this pr, a census diff names the line. after this pr, a snapshot test of
each role's booted cue lines turns any later cut into a snapshot diff a reviewer must read.

## [tn] sketch — the commands, the outputs, and the gap the census alone leaves

the narrative says "the census fails loud". a census is a report, and a report fails no one. the
sketch names the command whose exit code is the failure, and the durable guard that outlives the pr.

```
given the driver has run, before the rewrite,
  `rhx census.cues --glob 'src/domain.roles/driver/briefs/*.md.min' --emit | rhx teesafe $route/.census/cues.driver.before.tsv`

  when [t0] after the rewrite, the driver runs the same census into `cues.driver.after.tsv`
    then `diff $route/.census/cues.driver.before.tsv $route/.census/cues.driver.after.tsv` exits 1
    then a `<` line names `rule.always.spend-own-levers-before-escalation.md.min` and the owner row
    then no `>` line in that file carries the same row (so it is a drop, not a reflow)

  when [t1] the driver restores the row in the min
    then every `<` line left in the diff has a paired `>` reflow in the same file
    then `$route/5.3.verification` records each reflow pair, old line beside new

  when [t2] a later author cuts the same row, after this pr ships
    then `npm run test:integration -- cueLines` fails on the snapshot of the driver's booted cue lines
    then the snapshot diff names the file and the line
    then the fix is to restore the row, or to update the snapshot with a reason a reviewer reads
```
