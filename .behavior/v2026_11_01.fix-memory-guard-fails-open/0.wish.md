# wish: memory.guard never halts a tool it cannot judge

closes ehmpathy/rhachet-roles-bhrain#653. the issue holds the evidence, the three suspect lines, and the clamp cases; read it first.

## the outcome

memory.guard blocks one act only: a write into native claude memory. every other call passes, even when the guard itself cannot run.

- a guard that cannot run (absent binary, failed import, timeout, absent skill) lets the call through, exit 0, with one stderr line that names its own fault.
- the hook finds its binary from the role package, not from the cwd.
- a read of a memory path with `2>&1`, `=>` or `->` in it reads as a read, not a write.
- a true write into `~/.claude/**/memory/` or `MEMORY.md` is still blocked, exit 2.

## why

two crews stalled because the guard failed closed and blocked every Bash, Write and Edit call. a guard that cannot run must never halt the work it guards.
