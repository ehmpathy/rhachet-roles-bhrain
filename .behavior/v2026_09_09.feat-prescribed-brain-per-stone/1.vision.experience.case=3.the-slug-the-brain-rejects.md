# case 3 — the-slug-the-brain-rejects

**actor** = driver-clone · **feel** = sharp · **care** = critipath
**cell** = `driver-clone × apply × other-unknown × live`

> 🔴 **the seam this case exists for: `clone say` proves SUBMIT, never ACCEPT.** every part of the
> dispatch succeeds, and the switch still does not happen.

## .the narrative

i am the driver, enrolled, live, on sonnet. `5.3.verification` declares `brain: claude-opus-5` —
close, but the real slug carries a context suffix. a human typed it from memory.

the hook fires. every part of the dispatch works:

```
$ rhx clone say @:driver --what '/model claude-opus-5'
😶🎙️ said to @:driver
```

`delivered: true`. the socket answered. the bytes reached my input. the message left the buffer and
landed in my transcript as a real submit. by every signal the dispatch layer has, this worked.

then my brain-cli evaluates the slash command and answers:

```
Unknown model: claude-opus-5
```

i am still on sonnet.

**this is the dangerous shape**, and it is dangerous precisely because naught looks wrong. a hook
that reports success on the say's exit code reports success here. a record written from that exit
code records a switch that never happened. the verification stone then runs on sonnet, under a log
line that says opus — which is worse than no log line, because a human will believe it.

⇒ **the "aha": delivery is not application.** `clone say` guarantees a message arrives and is
submitted. it cannot guarantee the brain agreed with it, because the brain's answer comes back
in-band, in prose, in the transcript — not through the socket the hook holds.

so the hook must not trust its own success. after the say, it confirms the live brain against the
declared brain, and it is the **mismatch**, not the exit code, that decides:

```
🗿 5.3.verification
   └─ ✋ brain switch was delivered but not applied

   the stone prescribes  = claude-opus-5
   this driver runs      = claude-sonnet-5[1m]

   why: `/model claude-opus-5` was submitted and the brain refused the slug.
        a delivered say proves the message arrived — never that the brain took it.

   fix: correct the slug in 5.3.verification.guard; run `/model` with no argument
        to list the slugs this brain accepts.
```

## .the bdd `[tn]` timeline

```
given a driver enrolled as @:driver, reach=LIVE, live brain = claude-sonnet-5[1m]
  and  a stone 5.3.verification whose guard declares `brain: claude-opus-5`
  and  a brain-cli that does not know that slug

  when [t0] the hook confirms its address and dispatches `/model claude-opus-5`
    then `clone say` returns delivered=true, and prints `😶🎙️ said to @:driver`
    and  that ack proves the message was SUBMITTED — it proves naught about acceptance

  when [t1] the brain-cli evaluates the slash command
    then it answers in band that the slug is unknown
    and  the live brain is unchanged; no error reaches the hook, which has already exited 0

  when [t2] the driver reaches the point where it would begin the stone's work
    then it does NOT treat `delivered: true` as proof the switch landed
    and  it compares its live brain against the brain the guard declared
    and  🔴 that compare NORMALIZES both sides first — never a string equality

  when [t3] the comparison finds a mismatch
    then the stone halts, and names both brains — declared and live — never only the symptom
    and  the fix names how to list the slugs this brain accepts

  when [t4] a human corrects the slug to claude-opus-5[1m] and re-enters the stone
    then the comparison at [t2] finds a match, and the stone proceeds
```

```
given the same driver, the same stone, and the same unknown slug
  and  NO live-brain surface — `clone whoami` reports serial, slug, reach, hash, and no brain

  when [t5] the hook dispatches `/model claude-opus-5` and `clone say` returns delivered=true
    then the hook records `brain: claude-opus-5 — REQUESTED, unconfirmed`
    and  it does NOT record `switched`, because it holds no fact that would justify the word

  when [t6] the stone's brain line is rendered
    then it reads `claude-opus-5  ⟨requested — unconfirmed⟩`
    and  a reader learns the switch was ASKED FOR, and that nobody checked whether it landed

  when [t7] the brain-cli refuses the slug and the stone runs on sonnet
    then the record still reads `requested — unconfirmed`, which is TRUE
    and  🔴 no surface asserts a switch that did not happen — the lie is what this case exists to
         prevent, and it is prevented

  when [t8] a human audits the drive's cost and finds the numbers do not match the record
    then the `unconfirmed` label tells them exactly where to look, and why
    and  the fix is the same as [t4]: correct the slug, or ask for F5 so the check can fire
```

⇒ 🔴 **the harm this case names is the LIE, not the refusal.** a refused slug costs one stone at the
wrong brain; a record that says `switched` when it did not costs every future reader who trusts it.
**`[t5]`–`[t7]` destroy the lie with no cross-repo ask at all.**

| obligation | detect-state — needs `F5` | 🔴 **detect-reply — `clone get`, shipped** | declare — `[t5]`–`[t8]` |
|---|---|---|---|

| **holds the limit** | ✅ `[t2]` passes only on a confirmed match | 🔴 **weaker.** a **silent** refusal, or one whose text drifts, reads as a pass | ✅ 🔴 **strongest** — the record cannot assert more than the hook observed, **by construction** |

⇒ 🔴 **the trade is not two-way, it is a curve, and the middle build dominates the first on cost.**

claiming less.

⚠️ `[t2]` is the whole case in **both** detection builds. a build that omits it passes every test
written against `clone say`'s contract and still ships the defect — because `clone say` did its job
perfectly. 🔴 **and a build that omits `[t5]`'s label ships the same defect with no `F5` to blame.**

## 🔴 .the compare normalizes — a string equality inverts this case

⚠️ **amended 2026-09-10 after the council ruled `F10`.** this section was written when the guard was
to declare a rhachet **brainslug**, and it argued the compare must normalize **within** that
vocabulary. the ruling put the declared value in a **third** vocabulary — the brain-cli's own
`/model` argument — so the argument below holds and its instrument no longer suffices:

| | what the compare must bridge |
|---|---|
| as written below | `opus` ↔ `anthropic/claude/opus` — two spellings, **one** vocabulary. `getBrainSlugFull` handles it |
| 🔴 under the ruling | a `/model` argument ↔ a rhachet brainslug — **two vocabularies**. no shipped surface bridges them |

⇒ **the hazard is unchanged in kind and larger in size.** a raw equality still fires a false positive
on the happy path; what changed is that the fix is no longer a call to an extant normalizer.

🟡 **and this is now an argument against `F5` rather than a task the ruling created.** the *declare
rather than detect* build (`[t5]`–`[t8]`) compares no vocabularies at all — it records what was
requested. **the bridge is a cost only the detection build pays.**

### the original argument, which still holds within one vocabulary

`[t2]` must not be `declared === live`. two spellings of one brain both occur in the wild:

| where | the form |
|---|---|
| a guard, hand-written | `opus` — the engine's own test guards write exactly this |
| the brain list, and `ActorOndisk.brain` | `anthropic/claude/opus` |

rhachet already carries the normalizer, and its doc says why:

```
getBrainSlugFull.js:8-17  —  ".standard = brain.slug MUST always include the repo prefix"
                             ".note = defensively handles legacy brains where slug lacks
                                      the repo prefix"
findActorBrainInAllowlist —  ".note = uses getBrainSlugFull for comparison"
```

⇒ **a raw equality reports a mismatch on a switch that WORKED**, and `[t3]` then halts a correct
drive with a message that names two spellings of the same brain. that is a false positive on a
critipath — **worse than the silent defect this case exists to catch**, because it fires on the
happy path rather than the sharp one.

so `[t2]` normalizes both sides through `getBrainSlugFull` before it compares, exactly as
`findActorBrainInAllowlist` already does. the check stays **positive** — it passes only on a
confirmed match — and it is a match of brains, never of strings.

## 🟡 .the open question this case raises

**how does the driver read its own live brain?** `clone whoami` returns serial, slug, reach-state,
and actor hash — **not the live model** (`invokeCloneWhoami.js:74-80`).

so the comparison at `[t2]` needs a source. the candidates:

| candidate | cost |
|---|---|
| the driver reads its own brain and reports it | a probabilistic self-report, and the very fact under question |
| `clone whoami` grows a `brain` field | it is rhachet's own record to keep, and it serves every caller — 🔴 **but it is a cross-repo ask, and it must bridge two vocabularies** |
| 🔴 **`rhx clone get @:driver --output json`** | ✅ **shipped today.** it reads the brain-cli's own transcript — see below |

⇒ best-guess at r1: **`clone whoami` grows a `brain` field.** recorded as fulcrum `F5`. it is a
cross-repo ask on `rhachet`, and the vision should not pretend the check is free.

### 🔴 the third row was struck 2026-09-10 — it graded a scrape, and the surface is shipped

it read *"parse the brain-cli's answer out of the transcript — brittle, a prose format nobody
promised to keep."* **that is the right grade for an ad-hoc scrape of a terminal and the wrong grade
for `rhx clone get`**, which rhachet ships, versions, and contracts:

```
invokeCloneGet.js:51-61  —  "it reads the brain-cli's own transcripts, so it works on a DEAD
                             clone that has output — no reach probe, no cred gate"
                            "each turn a `← say` / `→ reply` header … so a reader tells an
                             inbound dispatch from an outbound reply"
asCloneMessage.d.ts      —  { direction: 'in' | 'out'; text: string; at: string | null }
```

⇒ 🔴 **that transcript is the one this case's `[t1]` names.** the refusal arrives *"in band, in prose,
in the transcript — not through the socket the hook holds"* — and `clone get` reads exactly that,
with `--output json` and a `direction` field a machine sorts on.

| what it changes | how |
|---|---|
| `[t2]`'s source | ✅ **exists today.** it reads the brain's **reply** rather than its live state |
| the vocabulary bridge | ✅ **none owed** — the reply is in the same `/model` vocabulary the dispatch used |
| the sequencing | ✅ none — `case=5` `[t4]` already puts the confirmation on the **next turn** |
| 🔴 a **silent** refusal | 🔴 **missed.** no reply, no evidence. only a **state** read catches it |
| 🔴 a refusal whose text changes | 🔴 **missed**, and missed quietly — which is this case's own harm |

⚠️ **so it does not retire `F5`; it demotes it.** `[t2]` becomes buildable without a cross-repo ask,
and the guarantee drops from a **fact** to a strong **inference**. the two 🔴 rows are what `F5` still
buys, and they are the whole of what it buys.

⚠️ **unverified by trial** — this rests on the shipped contract and its source. a first-party run is
owed at the execution stone before a build leans on it.

without `F5` the halt fires on the brain's **refusal**, read from the transcript. what it lacks is a
