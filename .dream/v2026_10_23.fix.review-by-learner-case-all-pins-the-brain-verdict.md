## .the gap, precisely

`[case-all]` snapshots the review.by tree (`genReviewByStdout`). there a nitpick changes three
things at once, not two:

- the vibe: `not even a vole` → `just a few hoots`
- the rubric mark: `hasIssue` counts nitpicks, so `r1 term-application ✓` → `✗`
- a subtree: the ✗ row gains count rows and a `review:` row, and a `summary` block appears

the two lifted masks fold only the first. a brain that nitpicks either rubric reds the case with
`0 blockers` and exit 0 intact.

## .the shape of the fix

a review.by-tree pass mask: fold the vibe to `[APPROVED]`, fold a rubric row whose children hold
only a nitpick count and a `review:` row back to a bare `r{n} <slug> [PASS]`, and drop a summary
block whose blocker count is 0. clamp it with the two renders `genReviewByStdout` emits for a
0-nitpick and a 1-nitpick pass, equal after the mask.

## .why it is not done in this round

safe but not clean: the fold must parse a subtree, a new mask with its own unit cases, in a pr
about boot budgets. the case was green in the run that went red; the red cases are fixed here.
