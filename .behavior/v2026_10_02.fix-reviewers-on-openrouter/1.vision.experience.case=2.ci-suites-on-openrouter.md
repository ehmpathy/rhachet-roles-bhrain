# case 2 — a maintainer ships again, on openrouter

happy × criti

## .narrative

for two days every PR in this repo has shown a red `test-integration` check, so no release ships.
the maintainer merges the cutover and opens the actions tab. the `keyrack firewall` step shows a
masked `OPENROUTER_API_KEY` in its export list, and no line asks for FIREWORKS. a few minutes later
the integration and acceptance jobs turn green, one after another. they run `rhx git.release
--into prod`, and the release goes out. they never had to learn which host answered: the check
marks look the same as they did before fireworks went dark.
