### 🔴 `case=6 [t3]` — one line, TWO claims, and only one of them is a test

`[t3]` reads: *"the same stone is re-driven after a repair → the second round's cache share
EXCEEDS the first's."* an earlier draft of this section graded that single line **OPEN** and
handed it up whole. 🔴 **that was a grain error.** the line fuses two claims of different kinds,
and one of them was clampable here all along:

| # | the claim | its kind | disposition |
|---|---|---|---|
| A | the **instrument** renders each round's share, **per round**, so two rounds are comparable | a property of OUR code | ✅ **clamped, and proven red** |
| B | a **repair RAISES** the share | a property of the PROVIDER's cache | 🔴 measured live; no fixture can make it true |

⇒ **A is what a test can hold.** B is a claim about a system we do not own — a fixture that
asserted it would assert only that we wrote the fixture that way, which is the fake-test shape
`rule.forbid.failhide` names. so the split does not soften the bar; it draws the line where the
falsifiability actually sits.

#### A — `genReviewMeterStdout.test.ts [case4]`, clamped

the only prior `by round` coverage was `expect(stdout).toContain('by round')` — **presence, never
content.** a renderer that folded every round of a stone into one row would have passed it, and
`[t3]`'s comparison would have had no two rows to compare.

`[case4]` drives two rounds of one stone (`i001` at 0% cached, `i002` at 75% against an
identical `400.0k prompt`) and asserts each round gets its **own** row that carries its **own**
share — never the corpus 37.5%.

🔴 **proven red** (`rule.require.clamp-edge-cases`): green at **15 passed** → the byRound key
reverted to fold on `stone` alone → **10 passed / 5 failed** → restored → **15 passed**.

#### B — the measurement, and what it needs

| what B needs | why this stone cannot supply it |
|---|---|
| a **live brain** | the acceptance suite runs offline against fixtures by construction |
| a **real guard**, driven twice | a guard round costs a review budget and a real stone's passage |
| a **repair between the two rounds** | the second round must read a genuinely changed corpus |

the instrument that takes it ships — `rhx review._.cost --of tree|grove` — and its first live

### 🔴 R6 — a suite that passed, then failed an hour later with no edit between

the integration suite ran **1,605 / 0 / 79** early in this stone and **1,594 / 11 / 79** later in
the same session, against an untouched subtree. all eleven died at one line:

```
spawnSync /bin/sh ENOBUFS
>37 |   execSync('git commit -m "initial"', { cwd: repoPath, env: GIT_ENV });
   at setupTestRepo (src/domain.operations/review/getAllFileDiffsFromRange.integration.test.ts:37:11)
```

🔴 **it is NOT a flake, and the proof came before the diagnosis**: reproduced in isolation at one
worker, **0 passed / 11 failed**. ⇒ a suite that degrades over a day, deterministically, measures a
quantity that grows.

#### the cause — six hops, and `.gitignore` is what hid it

`src/domain.operations/review/.test/assets/example.repo` is a **tracked fixture** (`git ls-files …
| wc -l` → **15**) and also a **write target**: `stepReview.integration.test.ts` and four
`stepReview.caseBrain.*` suites run real reviews with it as their cwd, so `writeInputArtifacts`
lands a full run dir inside it on every run. **654 run dirs were there**, newest timestamped
*during* the run that caught this — ~6,500 files against a 15-file fixture, a **433×** ratio.

🔴 **the repo-root `.gitignore` carries `*.log`, so the debris is invisible where it is WRITTEN —
and the ignore rule does not travel to a directory COPY.** so `fs.cpSync` dragged all ~6,500 into a
fresh temp repo, `git add .` staged them, and `git commit` printed one `create mode` line per file,
which overran node's 1 MB `spawnSync` pipe.

#### the repair — fix the CLASS, and bind BOTH call sites

⛔ **not a `maxBuffer` bump.** that silences the symptom while the directory keeps growing, so the
next consumer trips the same way at a higher threshold.

the fixture copy now takes **what git TRACKS**, never whatever sits on disk — so any future
untracked debris is excluded by construction rather than by a filter someone must maintain:

```ts
const assetFiles = execSync(`git ls-files -z -- ${ASSET_PATH}`, { encoding: 'utf8' })
  .split('\0')
  .filter((each) => each.length > 0);
```

🔴 **and it is one named helper (`copyAssetFixture`) read at BOTH copy sites** — `setupTestRepo` and
`[case7]`. that is this branch's own hard-won lesson applied: `isTargetDiffSent` bound two of three
call sites and the third drifted, so a shared decision left at two literals is a drift waiting to
happen.

**result: 11 failed → 11 passed, and 14s → 7s.**

#### 🟡 the WRITER half is owed, and is caught as a dream

the repair makes the **reader** hermetic and leaves the **writer** still aimed at the fixture, so the
directory grows on. SAFE/CLEAN: 🟡 **SAFE uncertain** — four of the five suites are `describe.skip`'d
cost-gated llm suites, so a cwd change to them is unexercised by any run this repo ships. 🔴 **CLEAN
no** — it opens five suites this branch's diff does not otherwise touch, and the cwd question is
already reserved by
`.dream/v2026_09_22.feat.review-cost-reads-the-bare-cwd-where-the-writer-writes-at-gitroot.md`.

⇒ caught as `.dream/v2026_09_22.fix.integration-suites-write-unbounded-artifacts-into-a-tracked-fixture.md`,

### 🔴 R7 — the integration proof's own LABEL was false, and a re-read of it found a tool defect

the integration row above was cited as *"`--scope path://review` · 125 files"*. to write it down
raised the question the number alone never does: **125 of how many?**

```
$ rhx git.repo.test --what integration
   └─ matched: 17 files          ← the DEFAULT (changed-files scoped)

$ rhx git.repo.test --what integration --scope path://review
   └─ matched: 125 files         ← the SCOPED run
```

🔴 **a filter that widens is not a filter.** proven with a token that appears in **no**
repo-relative path in this repo:

```
$ rhx git.repo.test --what integration --scope path://cost-meter
   └─ matched: 125 files
```

🟡 **that one command is the whole proof, and it needs no full-suite baseline beside it.** a
scope that names a token present in no path returns the identical 125 as one that names a real
directory — so the filter discriminates naught, whatever 125 turns out to be a count of. an
earlier draft reached for `--thorough` as the denominator, which is both forbidden
(`rule.forbid.thorough-test-runs`) and weaker: it would have shown the two numbers **agree**,
where the `cost-meter` run shows the filter is **inert**.

⇒ the token match runs against the **absolute** path, and this worktree is
`…/rhachet-roles-bhrain.beav.feat-review-cost-meter` — which contains `review` **and**
`cost-meter`. so the scope matched the machine, not the repo.

#### what it means for this stone — the proof is STRONGER, the label was WRONG

| | |
|---|---|
| what the row claimed | a review-scoped subset |
| what actually ran | **every integration suite the scope could reach — 125 files**, the filter inert |

⇒ the evidence over-delivered, which is the *lucky* direction — and that is exactly why it would
have shipped unexamined. a proof block's job is to state one claim twice, in the command and in the
output; here the two disagreed and only the output was true.

🟡 **the general lesson, and it is this stone's second of the same shape**: a figure read without
its denominator is not a measurement. R6 found a suite that degraded across a day because nobody

### 🔴 R13 — a de-duplication that silently VOIDED the four assertions it served

`rule.forbid.redundant-expensive-operations` was applied to two new integration suites: three
adjacent `then` blocks each re-ran one expensive call, so the call was hoisted into a `useThen` and
shared. the hoist is correct and the rule is right. **what it broke is subtler than what it fixed.**

`useThen` hands back a **proxy** over whatever the thunk returned, and a proxy does not forward:

| the member | why it vanishes | what the assertion then read |
|---|---|---|
| `Array.length` / `Array.map` | not forwarded through the proxy | `undefined` · `read.map is not a function` |
| `Error.message` | **non-enumerable** | `undefined` |
| `JSON.stringify(error)` | serializes enumerable keys only | `"{}"` |

⇒ so `getAllFileContentsBounded [case1]` lost its length and order checks, and
`getAllTargetsTouchedAt [case3]` lost both halves of its failloud check — **four assertions, in two
suites this branch authored, reduced to assertions about a proxy.**

🟡 **this one failed LOUD, and that is the only reason it is a row rather than a hole.** `undefined`
and `"{}"` do not satisfy `toEqual(150)` or `toContain('locked/secret.ts')`, so the suite reddened.
⇒ **had either assertion been a `toBeDefined()` or a `not.toThrow()`, the de-duplication would have
passed green with its checks hollowed out** — which is R5's defect exactly (*an assertion strictly
weaker than its own label*), and would have been invisible.

**the repair** is one `{ of }` wrapper per hoist, so the proxy sits over a plain object and every
member is reached through a normal key:

```ts
const read = useThen('the read completes', async () => ({
  of: await getAllFileContentsBounded({ cwd: scene.dir, files: scene.files }),
}));
// then: read.of.length · read.of.map(…) · read.of[0]!.content
```

both call sites carry a `🟡` note stating the proxy behavior, so the wrapper does not read as
ceremony to the next author who is tempted to unwrap it.

⇒ **the general lesson, and it generalizes past `useThen`:** a refactor that changes *how a value is
reached* can void assertions without touching one of them. the diff shows a hoist; the damage is in
the reads. **only a run tells them apart** — the same sentence the gate table below has to write
twice more.
