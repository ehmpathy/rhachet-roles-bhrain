## .the shape of the fix

🔴 **the hard part is not the extraction — it is that the five ask THREE different questions**, and
that is why the argument belongs in this file rather than in a one-line commit message:

| the question | asked by | the extra conjunct |
|---|---|---|
| **capacity** — has it a round left to spend? | `computeBudgetGrantRefusal` · `…AbsorptionAck` | none |
| **skip-this-pass** — will it be skipped now? | `isReviewPeerSkippedForBudget` | `!hasArtifactThisPass` |
| **exhausted-this-generation** — was it skipped for budget? | `getAllReviewPeerMeterStatuses` · `runStoneGuardReviews` | `!hasReviewForCurrentHash` |

⇒ a naive shared predicate would need **two extra boolean inputs**, and the two sites that carry them
have docblocks that warn hardest against exactly that conflation —
`getAllReviewPeerMeterStatuses.ts:170-179`, verbatim:

> *"do NOT relax this to a bare `rounds >= budget`. that reads a reviewer that ran and spent its last
> round as `exhausted` on the very pass it ran, which inverts the invariant above and unlocks the
> level above it a full pass early."*

**so the shape that fits is the SMALL one:** extract the bare arithmetic alone —

```ts
/** .what = whether a lane has run DRY — no round in hand without a grant */
export const hasMeterRunDry = (input: { rounds: number; budget: number }): boolean =>
  !Number.isFinite(input.budget) ? false : input.rounds >= input.budget;
```

— and let each of the five keep its own conjunct at its own site:

```ts
// getAllReviewPeerMeterStatuses.ts
: !hasReviewForCurrentHash && hasMeterRunDry({ rounds, budget: reviewer.budget });
```

⇒ **one home for the arithmetic, five homes for the questions.** the docblock above stays where it
is, because it is about the CONJUNCT rather than about the compare.

🟡 **and the `!Number.isFinite` branch is what makes the extraction worth more than a rename.** it
changes no outcome — `rounds >= NaN` and `rounds >= Infinity` are each already `false` — but the two
DISPLAY-paired sites must agree in shape with their renderers, and a shared operation carries that
note once rather than twice. the three raw sites gain it for free.

**where it goes:** `src/domain.operations/route/guard/review/peer/meter/hasMeterRunDry.ts`, beside
the four meter operations that call it (`rule.prefer.most-common-denominator` — the meter directory
is their common ancestor, and `runStoneGuardReviews` sits one level up).

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe?** ✅ **yes.** the arithmetic is identical at every site, and two of the five already carry
  the guarded form. no behavior moves
- **clean?** 🔴 **no.** it opens three files this change never touched — `runStoneGuardReviews.ts`,
  `isReviewPeerSkippedForBudget.ts`, `getAllReviewPeerMeterStatuses.ts` — plus their tests. the
  budget-gate behavior's diff has no reason to reach the review runner

⇒ **defer, and the deferral is a judgment about ripple cost**, so it owes a fulcrum as well as this
dream. a reviewer may fairly overrule it: the counter-case is that five homes for one arithmetic is
precisely what the rule names, and the extraction is mechanical.

⚠️ **the cost of the deferral, stated:** the fifth site ships, so the next author who needs a sixth
has five precedents that all say *write it inline*.
