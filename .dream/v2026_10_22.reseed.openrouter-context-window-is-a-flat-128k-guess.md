# 🌙 dream: openrouter brain specs claim a flat 128k context window

kind = reseed · owner = ehmpathy/rhachet-brains-openrouter · caught 2026-10-22

## .the cue that fired

nine review lanes on `openrouter/deepseek/flash` halted with `prompt exceeds 75% of context
window` at ~161k tokens. the window the review gate measured against was never the model's own.

## .the gap, precisely

`rhachet-brains-openrouter@0.1.1`, `dist/domain.operations/atom/BrainAtom.config.js`:
`SPEC_ESTIMATE_BY_TIER.pro` and `.flash` both set `gain.size.context.tokens = 128000`, and
`AtomSlug.unlisted.js:53` sets the same for every unlisted model. it is an estimate stamped
`cutoff: '2026-10-02'`, not a per-model fact. the review gate fails at 75% of it — ~96k.

openrouter publishes the true value per model as `context_length` on `GET /api/v1/models`.

## .the shape of the fix

1. at atom build, look up the routed model id (the package already derives it, via `asAtomTarget`)
2. read its `context_length` from `/api/v1/models` (cache it); fall back to the estimate only when
   the lookup fails, and say "estimate"
3. a test that asserts a model with a known window (e.g. one > 128k) reports that window

## .why it is not done in this round

it belongs to another repo. a tree adopts only what is scoped to itself.
