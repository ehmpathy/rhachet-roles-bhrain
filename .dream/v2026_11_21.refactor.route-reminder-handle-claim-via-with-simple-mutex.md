# 🌙 dream: the route reminder handle claim moves to `withSimpleMutex`

kind: refactor · owner: rhachet-roles-bhrain · caught 2026-11-21

## .the cue that fired

`fix-route-reminder-one-per-clone`, 5.3 peer rounds i001 and i002, repo-rules blocker.1: the pid handle claim is a hand-rolled lock (`rule.forbid.hand-rolled-locks`, `rule.require.locks-via-with-simple-mutex`). fulcrum F6.

## .the gap, precisely

- `genRouteReminder` reads the clone handle, skips a spawn while a live pid holds it, else spawns and claims the handle through `claimExclusiveWrite` (temp write + hard link, EEXIST = lost)
- a lost claim reconciles by hand: read the holder, probe it with `kill -0`, reap the extra daemon or clear a stale handle, retry (bounded)
- `setRouteReminderCrashLog` claims a crash-log slot through the same primitive
- the claim shipped on main in #540; the one-per-clone fix rekeyed it and made the publish torn-proof, but kept its shape

## .the shape of the fix

- wrap the findsert's read-check-spawn-write in one `withSimpleMutex` hold keyed on the clone, on a `simple-on-disk-cache` under the clone home; lease ~30s, acquire ~10s at 25ms, as `withReviewWatermarkHold` does
- inside the hold: read the handle; a live pid → return it; else spawn, then write the handle as plain state (a temp + rename publish, so a crash never tears it)
- retire `claimExclusiveWrite`'s EEXIST reconcile and `reconcileExtantHandle` / `retryClaim`; the orphan reap stays for a write fault inside the hold
- move the crash-log slot to an index read and write inside its own short hold, then delete `claimExclusiveWrite`
- the `kill -0` read stays: it reads whether the daemon the state names still runs, a fact about the registry, not a lease
- clamps: two concurrent findserts on one clone spawn one daemon (red with the hold removed); a crashed holder frees the key within the lease

## .why it is not done in this round

the claim predates the wish, and its move changes neither the one-daemon-per-clone guarantee nor the nudge. it rewrites the findsert, the crash-log slot, and the clamps of both, a dirty rework (F6) that belongs in its own wish.
