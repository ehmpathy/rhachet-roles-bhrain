# 🌙 dream: attribute an inherited brain to the stone that set it

**kind** = feat · **owner** = `ehmpathy/rhachet-roles-bhrain` · **caught** 2026-09-14

## .the cue that fired

self-review `behavior-declaration-coverage` on `5.1.execution.from_vision`. the guide asks *"is every
requirement from the vision addressed?"* — and `case=7` `[t2]` is not.

## .the gap, precisely

`1.vision.experience.case=7.the-next-stone-declares-none.md` `[t2]`:

```
when [t2] the driver reports the stone it entered
  then the line names the live brain AND that it was inherited
  and  it names the stone that last set it — 3.3.1.blueprint
```

the rendered demo:

```
🗿 3.4.roadmap
   └─ brain claude-opus-5[1m]   (inherited; last set by 3.3.1.blueprint)
```

**the build prints no line at all.** `stepRouteDrive.ts` renders on `outcome === 'requested'` and on
`outcome === 'unreachable'`; an `outcome === 'none'` stone emits the drive output unchanged.

### 🔴 why the absence is not merely an unwritten line

`case=7`'s own argument is that the attribution is what **earns** the sticky choice:

> *"sticky without attribution is a cost that appears from nowhere; sticky **with** attribution is a
> cost a human can trace to the stone that caused it and fix in one edit."*

⇒ so the build took `F6`'s sticky verdict and did not build the half that pays for it. **the cost
leak `F6` accepted is currently untraceable**, which is the exact state `case=7` was written to
prevent.

## 🔴 .the shape of the fix — and why it is a NEW artifact, not a field

the obvious move is a field on `DriveBlockerState`, which already carries `{ count, stone }` and is
already read at the entry edge. **measured, and it does not work:**

```
stepRouteStoneSet.ts:112   await delDriveBlockerState({ route: input.route });
```

⇒ the drive state is **deleted on passage** — at precisely the boundary the attribution must cross.
a `brainLastSetBy` field on it would be wiped the instant the driver left the stone that set it.

so the fix owes:

1. a **new persisted artifact**, whose lifecycle is the ROUTE rather than the stone
2. a **del** at route completion, and a decision for `--as rewound`
3. the render itself — one line, and it must stay silent on `absent-from-launch` (`case=10`)

⚠️ **step 3 is why a cheap variant does not exist.** `case=10` demands byte-identical output on a
stone that declared no brain **and no switch has ever happened**; `case=7` demands a line on a stone
that declared no brain **after** one has. the two cells differ only in history, so **without the
persisted state there is no way to part them** — and a line printed on both breaks every extant
stone-entry snapshot in every repo.

## .why it is not done in this round

**SAFE — no.** it introduces a persisted artifact with a lifecycle that must survive halt, block,
and rewind paths. a state that does not clear correctly reports a brain that is not live — which is
`case=3`'s own defect class, arrived at from a new direction.

**CLEAN — no.** it ripples into `stepRouteStoneSet` (the del), a new domain object, its get/set/del
trio, and the drive render — on a round whose subject is a switch dispatch.

⇒ both answers are no, so `rule.always.fix-forward-under-scouts-honor` sends it here. **and the
deferral is a judgment about ripple cost, so it owes a fulcrum too** — `F16`.

🟡 `case=7` is an **alterpath**, so its absence is a nitpick rather than a blocker by
`rule.require.experience-coverage`'s own grade. it is caught anyway because the vision demoed it,
and a demoed path that ships unbuilt is a claim the artifact set no longer supports.
