# 🌙 dream: two god-files carry the route cli, and sixteen review rounds never saw either whole

- kind  = fix
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught 2026-09-20

## .the cue that fired

`enroll-impl-arch-defects` at i016, on a round whose explicit ask was *decompose for recompose*:

> *"`setStoneAsPassed.ts` (1359 lines) is an unexamined god-file, and this round's entire
> self-review gate is a ~100-line slice inside it. **No review round in 16 iterations named this —
> because review scope tracked the diff, not the file.**"*

🔴 **that last clause is what makes it worth a record.** a diff-scoped review grades the lines a
round **changed**; it never grades the file those lines **live in**. so a file can absorb a hundred
lines a round, across sixteen rounds, and no lane ever reads it end to end.

## .the gap, precisely

| file | lines | what it owns |
|---|---|---|
| `src/domain.operations/route/stones/setStoneAsPassed.ts` | **1359** | the self-review gate · peer-review dispatch · judge execution · passage record · bouncer-cache updates |
| `src/contract/cli/route.ts` | **2490** | every route subcommand, plus `parseArgs(process.argv)` re-invoked at **16** independent call sites |

```sh
rhx grepsafe --pattern 'parseArgs\(process.argv\)' --path src/contract/cli/route.ts
```

🔴 **and the second one explains a deferral the round already made.** `F20` defers a unified
`FLAG_SCHEMA` because the repair touches three uncoordinated arity tables. **the reason there are
three is that there is no single dispatch point to hang one on** — 16 parse sites cannot share a
schema they each re-derive. ⇒ *the decomposition is what would make `F20`'s fix cheap instead of
another multi-file sweep.*

## 🟡 .the counter-example is in the same tree, and it is the argument

`src/domain.operations/route/guard/review/self/` — **22 files, ~4000 lines**, every one
single-purpose, most under 80. `getSelfReviewTriggeredPaths.ts` genuinely is the one place the
`(stone, slug)` key and the marker filenames are derived.

⇒ **the subsystem this round BUILT is well decomposed; the two files it touched tangentially are
not.** that contrast is the argument — the practice is already known here, and the two god-files
predate its application.

## .the shape of the fix

1. **`setStoneAsPassed.ts`** — lift each gate into its own operation, then let the caller read as
   narrative: the self-review gate (~lines 208–305) is already a clean slice with one entry point
   (`getSelfReviewChallengeDecision`), so it is the cheapest first cut
2. 🔴 **`route.ts`** — parse **once** at the top, thread the parsed options down to the 16 call
   sites. that single change is what lets `F20`'s `FLAG_SCHEMA` exist at all
3. **then** retire the three arity tables against the one schema (`F20`'s own fix, now cheap)

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE — no.** `setStoneAsPassed` is the gate every route in every repo passes through, and
  `route.ts` is the entry point for every route command. a decomposition there preserves behavior
  only if the tests cover every branch, and the round has not measured that
- **CLEAN — no.** ~3800 lines across two files, plus the acceptance snapshots that pin the cli's
  every refusal string, added to a diff already ~250 files wide

⚠️ **and it is not this round's defect.** both files predate the wish; the round added ~100 lines to
one of them. ⇒ recorded so the next traveler finds the measurement rather than re-derives it.

## 🔴 .the one property that makes it worth the trip

**it names a blind spot in the review harness rather than in the code.** sixteen rounds of
architectural review ran against this tree and none could see a 1359-line file, because **every one
of them was bound to the diff.** ⇒ a rubric that grades structure needs a target set that is not
diff-shaped, and no lane in this guard has one.

that is the transferable half: **a diff-scoped review can never catch a defect that predates the
diff** — and structure is exactly that kind of defect.
