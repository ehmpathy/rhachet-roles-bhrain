# 🌙 dream: the push-path stderr reason bypasses the brain halt, so an unswitched stone still reads as ready

- kind  = fix
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught 2026-09-18

## .the cue that fired

a byte snapshot, added to close i007 r002 nitpick.2, made the divergence visible for the first time.
`case21` asserts both halves and they disagree:

```ts
// stdout — the brain halt REPLACES the drive body
expect(result.emit?.stdout).not.toContain('--as passed');

// stderr — the SAME pass, and the invitation survives
expect(asStableDriveStdout(result.emit?.stderr?.reason)).toMatchSnapshot(
  'case21.t0.onstop.stderr',
);
```

the snapshot it wrote carries, verbatim:

```
   └─ are you here?
      ├─ when ready for review, run:
      │  └─ rhx route.stone.set --stone 1 --as arrived
      └─ when ready to continue, run:
         └─ rhx route.stone.set --stone 1 --as passed
```

## .the gap, precisely

`stepRouteDrive.ts:566` returns the **un-composed** drive body as the stderr reason:

```ts
return { emit: { stdout, stderr: { reason: stdoutDrive, code: 2 } } };
```

`stdout` went through `composeHaltStdout`, so an undispatched brain REPLACES the drive body on it —
the invariant `case=8` `[t2]` exists to hold: **an unswitched stone must not read as ready-to-pass.**
`stdoutDrive` did not, so the invitation survives on the other surface.

⇒ and the driver sees both. `src/contract/cli/route.ts:591-595`:

```ts
if (result.emit.stderr.reason) {
  console.error(result.emit.stderr.reason);
}
process.exit(result.emit.stderr.code);
```

⚠️ **the stop-hook path is the one that matters**, because on a non-zero exit a harness may render
stderr where it hides stdout (`rule.forbid.stdout-on-exit-errors` names that exact asymmetry). so the
one surface most likely to be read is the one that never got the halt.

## .the shape of the fix

the reason string is built once and used twice. compose it the same way the stdout is:

```ts
// stepRouteDrive.ts, the push return — today
stderr: { reason: stdoutDrive, code: 2 }

// what it wants
stderr: { reason: stdout, code: 2 }   // the ALREADY-composed body
```

`stdout` at that point is `composeHaltStdout(stone, stdoutDrive)`, so the fix is a one-identifier
change and no new call. **the design question the change decides** is whether the stderr reason is a
*duplicate of what the driver already read* or a *second, independent surface* — today it is the
second by accident rather than by intent.

⇒ before the swap, check the other code-2 return (`:532`, the stuck path) for the same shape, and
re-snap. every `case21`-family snapshot moves, which is what makes it visible rather than quiet.

## .why it is not done in this round

**safe?** no. it changes what a driver reads on every exit-2 stop of every route in every repo, and
it is not a defect the stone under review introduced — the push return predates `brain:`.

**clean?** no. it ripples into every drive snapshot that carries a code-2 stderr, and the call it
makes (duplicate-vs-independent surface) is a contract decision the wisher owns rather than a repair.

⇒ so the round pins it instead. the byte snapshot means the divergence can no longer change in
silence, and whoever takes this dream starts from a clamp rather than from a read.
