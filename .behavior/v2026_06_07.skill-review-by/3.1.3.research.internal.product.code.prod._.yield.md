## pattern.6 = YAML parse without external dependency

**[REUSE]** — parseSimpleYaml for rubric config

### source

`src/domain.operations/route/guard/parseStoneGuard.ts`

### citations

[11] simple YAML parser:
```ts
const parseSimpleYaml = (content: string): Record<string, unknown> => {
  const lines = content.split('\n');
  const result: Record<string, unknown> = {};
  let currentKey: string | null = null;
  let currentArray: string[] | null = null;

  for (const line of lines) {
    // handle key: value
    const keyMatch = line.match(/^(\w+):\s*(.*)$/);
    if (keyMatch) {
      if (currentArray && currentKey) {
        result[currentKey] = currentArray;
        currentArray = null;
      }
      const [, key, value] = keyMatch;
      if (value) {
        result[key] = value;
      } else {
        currentKey = key;
        currentArray = [];
      }
      continue;
    }

    // handle array item
    const arrayMatch = line.match(/^\s+-\s+(.+)$/);
    if (arrayMatch && currentArray) {
      currentArray.push(arrayMatch[1]);
    }
  }

  if (currentArray && currentKey) {
    result[currentKey] = currentArray;
  }

  return result;
};
```

### relation to wish

review.by will extend this to parse the rubrics.yml format:
```yaml
vibe:
  mascot: 🐢
  artifact: 🐚

rubrics:
  - slug: mech-failhides
    purpose: detect hidden errors and failhide patterns
    rules:
      - .agent/repo=ehmpathy/role=mechanic/briefs/practices/**/rule.*.md
```

note: the nested vibe + rubrics shape needs a nested parse; parseSimpleYaml is flat-only, so a nested variant is needed.

## pattern.7 = parallel execution with Promise.all

**[REUSE]** — parallel file reads pattern

### source

`src/domain.operations/review/stepReview.ts`

### citations

[12] parallel file reads:
```ts
const fileContents = await Promise.all(
  files.map(async (file) => ({
    path: file,
    content: await fs.readFile(file, 'utf-8'),
  })),
);
```

### relation to wish

review.by does NOT use this parallel pattern for rubric execution — rubrics run serially (one at a time), the same shape as the guard's `runStoneGuardReviews`. this `Promise.all` pattern stays internal to `stepReview` (parallel file reads within one review), which is invoked as a subprocess (`rhx review …`) via the shared `runOneReview` runner, once per rubric — NOT imported in-process:
```ts
const results: ReviewRubricResult[] = [];
for (const rubric of rubrics) {
  const cmd = genRubricReviewCmd({ rubric, paths, diffs, mode, brain, output });
  const run = await runOneReview({ cmd, timeout }, context); // shared runner, subprocess
  results.push({ slug: rubric.slug, verdict: run.verdict, outputPath });
}
```

## summary

| pattern | classification | rationale |
|---------|---------------|-----------|
| treestruct format | [REUSE] | identical box-draw pattern |
| count parse regex | [REUSE] | guard compatibility required |
| shell skill entry | [REUSE] | standard skill pattern |
| CLI arg parse | [EXTEND] | add --role, --for args |
| withSpinner | [REUSE] | same progress feedback pattern |
| YAML parse | [EXTEND] | nested vibe + rubrics variant |
| serial for...of await | [REUSE] | rubric loop mirrors the guard's serial runner (no Promise.all) |
| result structure | [EXTEND] | wrap per rubric |
| brain selection | [EXTEND] | default fireworks/deepseek/v4-flash, --brain override |
| output name | [EXTEND] | role-qualified paths (by=$role/rubric=$slug.md) |
| exit codes | [REUSE] | same 0/2 semantics |
| mascot/vibe | [EXTEND] | configurable via rubrics.yml vibe block |

no patterns marked [REPLACE] — all extant patterns are well-designed and align with wish requirements.
