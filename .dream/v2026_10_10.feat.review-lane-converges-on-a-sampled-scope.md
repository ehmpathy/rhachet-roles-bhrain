# 🌙 dream: a lane that samples a wide scope converges, rather than raises fresh points each round

kind: feat · owner: bhrain/driver + bhrain/reviewer · caught 2026-10-10

## .the cue that fired

stone 5.1, round i037: the four l3 enroll lanes (opus, no path bind) each state outright that they
read only part of a 400–650 file scope. every round they repaired, a fresh sample surfaced fresh
`[nitpick][better]` points — i036 raised 9, i037 raised 13 after all 9 were repaired or disputed.
the judge allows 7, so the stone stalls on points that are each real and each cheap, and the queue
never drains.

## .the gap, precisely

a review lane is a sampler whenever its scope exceeds what it can read in one pass, and a sampler
draws a new sample each round. so a repair round cannot drive its count to zero: the count measures
the sample, never the residue. no part of the guard tells a re-run lane what it already read, or
what changed since it last spoke.

checkable: `.reviews/peer/5.1.execution.from_vision._.review.i03{6,7}.*.r03{0,1}._.given.by_peer.*.md`
— the i037 points touch files the i036 givens never named, and each given says it sampled.

## .the shape of the fix

two levers, either alone helps, both compose:

1. **a delta scope on re-arrival** — a lane whose prior given exists reads, as its primary target
   set, only the files changed since that given's artifact hash (the guard already keys a clean
   reviewer by hash; the same key names the base). the full scope stays reachable as refs, so the
   lane can still cite context. converges by construction: an untouched file is not re-sampled
2. **a declared vertical partition per enroll lane** — `rhx route.guard.partition --for review
   --peer @all` through the review subdomains (meter · warmer · partition · guard), so each
   partition's scope fits one read and the sample IS the census (`rule.require.vertical-partitions`)

then a measure: the meter's `--of tree` could report, per lane, how many raised points touched a
file the prior round of that lane never named — the sampler signature, made visible.

## .why it is not done in this round

SAFE — yes. CLEAN — no: lever 1 changes what every guard lane reads on every re-arrival, across
every route that uses `$targets`; it needs its own vision and its own acceptance journey. lever 2
is a guard edit, cheap on its own, but it is a lever the driver can pull per route, and the tool
change (lever 1) is what makes it unnecessary. the decision to defer is F212.
