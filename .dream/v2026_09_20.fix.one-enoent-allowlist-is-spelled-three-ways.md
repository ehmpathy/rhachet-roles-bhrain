## .the cue that fired

peer round i009, lane `enroll-impl-arch-defects`, nitpick #1: the `.catch` that allows an ENOENT and
rethrows each other fault is hand-written at many sites, and each hand-written copy is a place
`rule.forbid.failhide` can be broken by a dropped `throw`.

🔴 **the cue is right and its count was low.** the reviewer named the pattern; a measurement named
the scale — and found that the repo does not merely repeat the pattern, it holds **two rival
operations for it** beside the copies.

## .the gap, precisely

one concept — *"an absent file is the answer; every other fault is a fault"* — is written three ways:

| the form | where it lives | call sites |
|---|---|---|
| `isENOENT(error)` | `src/domain.operations/route/guard/isENOENT.ts` | **6** — `route/judges/`, `route/guard/artifact/`, `route/guard/upgrade/` ×3, `route/guard/review/`, plus one test |
| `getFsErrorCode(error) === 'ENOENT'` | `src/domain.operations/getFsErrorCode.ts` | **5** — `learn/` ×3, `telepath/`, plus its own test |
| a hand-written `error.code === 'ENOENT'` | inline, no operation | **~13** — `contract/cli/route.ts` ×2, `review.by/`, `review/`, `route/stones/` ×6, `route/gitignore/`, `route/guard/review/self/` ×3 |

⇒ **~24 touch points across 9 directories.** checkable: `rhx grepsafe --pattern "code === 'ENOENT'"`
plus `rhx grepsafe --pattern 'isENOENT|getFsErrorCode'`, both under `src`.

🔴 **the two operations are a `rule.forbid.domain-term-inconsistency` violation on their own**, and
it predates this round. one concept, two words, no canonical term declared — so a traveler who wants
the behavior finds whichever of the two their directory happens to import, and writes a third by hand
when neither is in reach. **the ~13 inline copies are the predicted consequence, not a separate
defect.**

⚠️ and the copies are not interchangeable. each carries its own allowlist result — `return false`,
`return null`, a bare `return`, or a rethrow — so a sweep cannot be mechanical. the **shape** is
shared; the **outcome** is per-caller.

## .the shape of the fix

1. **settle the term first.** `isENOENT` is a boolean predicate scoped to `route/guard/`;
   `getFsErrorCode` is a code reader at the `domain.operations` root and is the more general of the
   two. ⇒ the likely canonical form is a **combinator** rather than either predicate, since the
   per-caller outcome is what varies:

   ```ts
   // asAbsentOr<T> — allow ENOENT with a caller-chosen value; each other fault reaches the caller
   export const asAbsentOr = <T>(whenAbsent: T) =>
     (error: unknown): T => {
       if (getFsErrorCode(error) === 'ENOENT') return whenAbsent;
       throw error;
     };

   // at the call site
   const stat = await fs.stat(p).catch(asAbsentOr(null));
   const found = await fs.access(p).then(() => true).catch(asAbsentOr(false));
   ```

   that shape absorbs all three forms **and** the four outcomes, so the sweep becomes one
   substitution per site rather than a judgment per site.

2. **itemize the term** under `domain.terms/`, per `rule.require.domain-term-itemization`, and record
   the rejected words as forbidden synonyms. the boundary answer to *"$word, of WHAT?"* is
   `fs.error` — so the cluster is `term=fs.error.absent.*`.

3. **sweep forward, never in bulk** — `rule.forbid.domain-term-synonyms`' own no-mass-rewrite clause
   applies: a find-and-replace cannot part a citation of `isENOENT` from an instance of one, and the
   per-caller outcome would be flattened.

4. **clamp it agreement-grain.** the value-grain clamp (`getFsErrorCode.test.ts` asserts the code a
   shape yields) already exists and would stay green if a caller dropped its `throw`. what is owed is
   a clamp that a **non-ENOENT** fault reaches the caller from each seam — the property
   `rule.forbid.failhide` actually guards.

## .why it is not done in this round

🔴 **the CLEAN test fails, on a MEASURED ripple rather than an estimate.** the round has had two
deferrals falsified by exactly this move — an estimate stood in for a count, and both estimates were
high — so the count was taken first:

- **24 touch points, 9 directories.** two of them — `learn/` and `telepath/` — this round has never

  and to make it inside an execution stone would settle a repo-wide vocabulary question as a side
  effect of a self-review repair
- **the outcomes are per-caller**, so the sweep is 24 judgments, not 24 substitutions

⇒ SAFE: ✅ the combinator is mechanical. CLEAN: 🔴 it ripples into contracts this change never
intended to open. **per `rule.always.fix-forward-under-scouts-honor`, a dirt deferral owes a fulcrum
beside this dream, and it has one.**

🟡 **what WAS done in this round**, so the dream is not a way to bank a refusal: the three sites this

down the mint-a-new-ask branch.* the pattern is correct at every site the round opened; what is owed
