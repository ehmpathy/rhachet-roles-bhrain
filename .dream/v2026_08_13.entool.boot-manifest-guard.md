the unguarded half the day it is born. **enumerate the role dirs; do not list them.**

## .the entoolment test, applied

> **"is that leftover turn a JUDGMENT, or a STEP?"**

a **STEP**, unambiguously. the check is: read `boot.yml`, list `briefs/**`, diff the two sets. it
is identical every time, and `getDriverRole.test.ts` **already implements it** — for two roles.

⇒ this is not a new tool to design. it is an extant tool that covers 2 of 5 roles.

## .the shape of the fix

extract the invariant from `getDriverRole.test.ts` into one parameterized case over all five
roles. two properties to preserve, both already load-bearing in the driver version:

- it filters `f.endsWith('.md')`, so `.md.min` condense sidecars are excluded — **F8 depends on
  this**
- it uses a non-recursive `readdir`, so nested dirs escape. **the librarian's `briefs/knowledge/`
  is nested**, so a naive lift would silently cover no file at all for that role 🔴

⇒ the librarian case needs a recursive walk, which the driver case never needed. that difference
is the whole reason this is worth a real look rather than a copy-paste.

## .why it is not done in this round

the wish's bound is **briefs only — no skills, no roles**. a test file is code. so this is
correctly out of scope, and correctly recorded rather than silently skipped
(`rule.always.entool-the-skills-you-touch`: *a manual workaround left unrecorded = blocker*).
