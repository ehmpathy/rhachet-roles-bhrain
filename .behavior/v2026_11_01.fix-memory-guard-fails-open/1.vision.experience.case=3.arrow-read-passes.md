# case 3: reads pass, arrows and all

rows 2, 5, 10, 11, 12, 13.

## .narrative

a clone spends its day on ordinary calls full of `>` tokens that write no file: `npm test 2>&1`, `grep '=>' src/a.ts`. they pass in silence, as they always should. then it audits what its native memory holds: `cat ~/.claude/projects/p/memory/MEMORY.md`, `grep x ~/.claude/projects/p/memory/a.md 2>&1`, `grep -- '->' …/memory/a.md`. before, the `2>&1` and the arrow were each graded a write into memory. now the guard reads each redirect's target: `&1` is a file descriptor, an arrow inside quotes is text, so no write into memory exists. last, it copies a note out with `cat …/memory/a.md > /tmp/out.txt`: the redirect lands in `/tmp/out.txt`, not memory, so it passes too. (a relative `> out.txt` is placed by the cwd: `case=9`.)

## .bdd sketch

```
given a tree with the learner linked
  when [t0] Bash `npm test 2>&1`
    then exit 0, silent
  when [t1] Bash `grep '=>' src/a.ts`
    then exit 0, silent
  when [t2] Bash `cat ~/.claude/projects/p/memory/MEMORY.md`
    then exit 0, silent
  when [t3] Bash `grep x ~/.claude/projects/p/memory/a.md 2>&1`
    then exit 0, silent
  when [t4] Bash `grep -- '->' ~/.claude/projects/p/memory/a.md`
    then exit 0, silent
  when [t5] Bash `cat ~/.claude/projects/p/memory/a.md > /tmp/out.txt`
    then exit 0, silent
```
