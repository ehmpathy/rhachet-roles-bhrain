# 🌙 dream: the word `promises` names two quantities in one return shape

- **kind** = fix
- **owner** = this repo (`rhachet-roles-bhrain`)
- **caught** = 2026-09-20
- **status** = ✅ **RESOLVED 2026-09-20** — fixed in the round that caught it, after a later lane
  (`enroll-impl-behavior-intent`, i008) re-raised it. ⇒ **the deferral below was wrong, and its
  reason was CHECKABLE and unchecked.** see `.the deferral, falsified`.

## .the cue that fired

a peer reviewer (`enroll-impl-arch-defects`, i006 r011 hazard 4) read `delStoneGuardArtifacts`'s
return and found one word that serves two concepts, one level apart.

## .the gap, precisely

```ts
delStoneGuardArtifacts(...) → { reviews, judges, promises, triggers: { blockers, promises } }
```

| field | counts |
|---|---|
| the outer `promises` | real `.guard.promise.*.md` files — a **promise** |
| the inner `triggers.promises` | archived self-review **trigger markers** (`.since` + `.uptil`) |

the two are unrelated quantities. the inner one borrowed the word because a self-review trigger
*gates* a promise — which is a relation between the concepts, never an identity.

⇒ `rewindAffectedStones.ts:73` sums `cleared.triggers.blockers + cleared.triggers.promises`, so a
reader of that one line holds both senses of `promises` at once and has no cue that they differ.

🔴 this is `rule.forbid.domain-term-ambiguity` exactly — *one word, one sense* — and this round paid
for the same class of defect twice already: `artifact` (the deliverable vs the articulation) made
two headline clamps unfalsifiable, per the yield's `.what is awkward` item 16.

## .the shape of the fix

rename the inner field to name what it counts:

```ts
{ reviews, judges, promises, triggers: { blockers, markers } }
```

`markers` is the word already used in this subsystem for the `.since`/`.uptil` pair — see
`getSelfReviewTriggeredPaths`'s docblock and `delStoneGuardArtifacts`'s own glob comments — so the
rename adopts an extant term rather than coins one. `selfReviews` is the alternative and is worse:
it names what the markers *gate*, which is how the collision arose.

## ✅ .what shipped

```ts
{ reviews, judges, promises, triggers: { blocked, selfReviews } }
```

🔴 **both keys were renamed, not one.** the dream named `triggers.promises` and stopped there;
`triggers.blockers` is the same defect on the same object — `blocker` means *a review concern's
severity* everywhere else in this subsystem, so a field that meant *the `$stone.blocked.triggered`
marker* borrowed a word already spent. ⇒ one edit, same three files, zero extra ripple.

⚠️ **and the dream's proposed word was refused, with a reason.** it argued for `markers` and graded
`selfReviews` *"worse: it names what the markers gate"*. that holds in isolation and breaks once the
neighbour key is renamed too: `blocked` names a **kind**, `markers` names the **genus**, so
`{ blocked, markers }` asks a reader to hold two levels of abstraction as peers. both keys now name
the marker KIND, which is the axis the object is actually partitioned on.

🟡 the tell that the old name was wrong is the cleanest evidence the repair was right: a
disambiguation paragraph in `delStoneGuardArtifacts.test.ts` existed solely to say which sense
`triggers.promises` carried, **and it recorded that the overload had already cost a misread while
that very case was authored**. the rename retired the paragraph.

## 🔴 .the deferral, falsified

the argument below was:

> the field is carried through `rewindAffectedStones` into the rewind's emit, so the rename re-takes
> `setStoneAsRewound`'s snapshots plus the rewind acceptance snapshots

**that is false, and one read of `rewindAffectedStones.ts:73` would have shown it.** that line
renders the **sum**:

```ts
`… ${cleared.triggers.selfReviews + cleared.triggers.blocked} triggers`
```

⇒ the field NAMES never reach the emit — only their total does. **measured after the rename: unit
2208 passed / 0 failed, acceptance 3607 passed / 0 failed, and NOT ONE snapshot re-taken.** the
predicted churn was zero.

🔴 **so the deferral cost a round of review for a fix that was SAFE and CLEAN all along.** the ripple
estimate was a guess presented as a measurement, and what it guessed about was three tokens on one
line.

⇒ **the transferable lesson: a CLEAN verdict is a claim about what crosses a boundary, so check what
crosses it.** `rule.always.fix-forward-under-scouts-honor` grades ripple, and ripple is observable —
read the call site, or re-run the suite and count the snapshots. an unchecked ripple estimate turns
the SAFE/CLEAN test from a gate into a rationalization, and it fails in the expensive direction:
toward a deferral nobody re-examines.

## ⚠️ .the transferable part the dream got RIGHT

**a nested field inherits its parent's namespace and loses its parent's context.** `triggers.promises`
reads unambiguously at the declaration, where `triggers:` sits one line above. it reads as the outer
`promises` at every **call site**, where the nest has collapsed into a dotted path.
⇒ when a field name repeats a peer field's word at a different depth, **read it at the call site,
never at the declaration** — that is where the ambiguity actually lands.
