wish =

# make the review prompt's spend MEASURABLE, then ATTRIBUTABLE, then CHEAPER — in that order

`rhx review` spends real money on every lane the grove runs, and until this branch the
spend was **unattributed**: a census could say a prompt cost $0.02 and could not say which
input bought it. the grove figure that opened this work is the whole motivation —

> **3,663 runs across 19 trees, $151.92, 779.5M input tokens, 2.8% cache hit rate.**

a 2.8% hit rate against a prompt whose static head repeats every round is not a pricing
fact; it is a **defect**. this wish is to build the instruments that prove it, fix what
they find, and leave the rules that keep the instruments honest.

## .the three desires, in dependency order

### 1. MEASURE — a per-run meter, and a grove-wide roll-up

- every `rhx review` run records measured tokens and measured cost, never a projection
- `rhx review._.cost --of tree|grove` — one command over the `breadth` axis
- a run whose cost cannot be known is **`unknown` and renders ABSENT** — never `$0.00`.
  a nil that is a FACT (`refused`) renders `$0`; the two must never be conflated

🔴 **`rhx review.corpus` was a fourth surface here, and is struck** (`F3`, 2026-09-21). it
answered the pre-run question by **estimate from declared guard globs**, then drifted from the
renderer it estimated — and its name was already a forbidden synonym of `scope`.

### 2. ATTRIBUTE — every char of the prompt lands in exactly one named input

- `getOnePromptComposition` splits the prompt into eight named inputs and states, per
  input, its **chars**, its **count**, and **which side of the cache seam it sat on**
- 🔴 the invariant that is easy to get wrong: `markup` is the RESIDUAL, so the eight rows
  sum to `chars` **by algebra**. the sum proves arithmetic and proves NO coverage at all.
  a second detector is owed — and must be PROVEN red under an unattributed input
- 🔴 the census must measure what the renderer **SENT**, never what the caller **HELD**.
  a diff counted-but-not-rendered drives the residual negative while the sum stays green

### 3. CHEAPEN — name the shared prefix, and make the prompt reach it

- the static head (instructions + output format + rules + refs) is the shared prefix; it
  leads the prompt, stays byte-identical, and is **pinned as the system prompt**, because
  the affinity key is derived from the system prompt and a cache lives per-replica
- a new file's `<target.diff>` and its `<target.file>` carry the SAME bytes — the diff is
  the body with a `+` per line under a `new file mode` preamble. one of the two must go
- the target corpus sorts by cache stability, so a repaired file lands last
- the tail emits `target` then `conversation`, so the prefix can reach into the target

#### 🔴 4. the fifth lever — a WARMER, because the defect is the CLOCK (added 2026-09-24)

the four levers above are layout levers: they make a shared prefix **exist**. a live probe then
measured that layout was never the bound that bit —

| gap since the prior round | reach |
|---|---|
| 20m | ✅ 90.0% |
| 33m | 27.8% |
| 66m · 67m · 118m | 🔴 0 |

monotone in **elapsed time**, and noise in prefix size: a 195.5k prefix at 67m served zero while
one 6.4× smaller at 33m served. ⇒ **a prefix that exists and has aged out is worth exactly as
much as one that never existed**, and no edit to a prompt repairs a clock.

so `rhx review` spawns a **warmer**: a detached process that **pokes** each lane's prefix on a
cadence while the guard's budget says a round is still due.

- ✅ the eviction policy is **LRU** — settled by two-arm probe, control missed at t+71m while
  treated hit 99.8%. a read refreshes residency, so a poke works
- the cadence is **12 pokes, 15m apart**, and one poke cannot carry it: `arm→read` is the sum of
  two gaps that must each stay under the ttl

  🔴 **this read `3 pokes` until 2026-09-25, and the count had been set against the wrong clock.**
  the INTERVAL was measured — 15m, off the decay census. the COUNT was assumed, and it bought a
  **45m** coverage window. the round cadence on this very branch was then measured against
  `passage.jsonl` and runs **1h29m to 3h05m**, so a warmer retired hours before the round it
  existed to protect — on every round. i009 is the demonstration: nine lanes cached **0.0%** with
  five warmers healthy, spawned, and already asleep.

  ⇒ 12 × 15m is **2h45m**, which covers the measured band. the interval is untouched, because it
  is the half the census actually settled (`F37`).
- the unit is **one reviewer** — each lane's head is its own rubric, so its own affinity key and
  its own replica. there is no global warmer
- 🔴 the gate is **"is the driver expected to DRIVE ON?"** — never a fact read off one meter.
  a warmer is a bet on a re-read, so it fires only where the engine will still nudge the driver
  back to that road.

  | the route | the driver will | the warmer |
  |---|---|---|
  | mid-drive, rounds left | re-arrive | **warms** |
  | budget exhausted | not re-run that lane | halts |
  | 🔴 **completed** | **not be nudged** — no next stone is emitted | 🔴 **halts** |
  | 🔴 **blocked** | **not be nudged** — the road is held | 🔴 **halts** |

  ⚠️ **this clause read *"the gate is `route.guard.budget`"* until 2026-09-24, and the budget was
  never the predicate.** the last two rows leave the round allowance untouched, so a budget-gated
  warmer keeps a prefix warm that nobody will ever read — the exact defect that clause cited to
  reject a bare timer, reached through a different door.

  ⇒ so the read is `passage.jsonl` plus the stone set, and the budget is one input to it rather than
  the whole test (`.seeds/…case=S17`).

  🔴 **SHIPPED AT A COARSER GRAIN STILL, and the gap is named rather than papered over.** what ships is
  *"a warmer spawns only where the review was run BY A GUARD"* — recovered from the output path
  by `asReviewRunIdentity`, which answers null for a hand `rhx review`. that gate is sound in the
  direction that matters (a hand review has no next round, so it never spends) and **weaker in
  the other**: it says naught about whether the driver will drive on, so **all three halt rows
  above still spawn** — exhausted, completed, and blocked alike.

  ⇒ the bound on that weakness is the plan itself — `k` pokes, declared up front, then it exits
  (bar 11). at the default that is **12 pokes on one lane**, which the rate card puts near half a
  cent. so the residual is a bounded over-spend, never an unbounded one.

  ⚠️ **and the bound grew 4× when `F37` widened the window**, which is the honest cost of that
  repair rather than a footnote to it: a warmer that covers the real round cadence spends four
  times what one that expired early did. the trade was taken because a warmer that retires before
  the round buys **naught** — 4× of a real benefit beats 1× of none — and it makes the payback
  question sharper rather than softer (see the `[research]` row on it).

  ⇒ the reason it is not closed here: `rhx review` is invoked BY the guard and holds no reference
  back to it — both the budget and the passage ledger live in route state keyed by route + stone,
  and to read either the review CLI would have to re-derive a route it was never told about. that
  is a real seam, and a guess at it is worse than the coarse gate. caught as a dream.
- 🔴 it needs **no new brain surface**. a poke is an ordinary completion that HITS, and
  `brain.ask` already returns `metrics.size.tokens.cache.get` and `metrics.cost.cash.total`
  (`ehmpathy/rhachet#550` would be an ergonomic wrapper, never a blocker)

##### the control surface — `--warmer off | on | <k>x,<m>m`

```bash
rhx review ...                      # on by default — 12 pokes, 15m apart
rhx review ... --warmer off         # no warmer spawns
rhx review ... --warmer on          # opt in, at the default cadence
rhx review ... --warmer 5x,10m      # 5 pokes, 10m apart
```

🔴 **struck 2026-09-27 — the default is now `off`** (`.seeds/…case=S24-the-warmer-defaults-off-until-it-pays.md`).
the default governs the bill, and the warmer's measured net on real guard rounds was a loss:
its pokes cost more than the cache reads they saved. so a spend no caller chose must not be the
default until its payback is shown. the original argument, kept for the council: a warmer a
driver must remember to enable never runs on the eleven-lane round they fired and walked away
from — the case it exists for.

🟡 **and `<k>x,<m>m` is one value, never two flags.** the two numbers are not independent: `k × m`
is the coverage window and `m` must stay under the ttl. to split them into `--warmer-count` and
`--warmer-every` would let a driver set `1x,90m` — a single poke past the ttl, which refreshes
naught and bills in full. one token keeps the pair legible and the invalid combination visible
at the call site (`rule.prefer.prevent-over-correct`).

⇒ `off` must stay reachable: a warmer spends real money on a live provider, and any spender a
driver cannot refuse is a spender they will disable by uninstalling the tool.

##### the warmer's own state — one live warmer per reviewer

```
.agent/.cache/repo=bhrain/role=reviewer/skill=review/warmers/reviewer=$xyz/
  └─ output.$run.log  # one log per WARMER — all k of its pokes, in order
```

(the live pid — the idempotency key and the handle to stop it — rides the warmer's watermark
record, not a file here; see the 2026-10-08 amendment below.)

🔴 **AMENDED 2026-09-26 — this read `output.$attempt.log`, *"one log per attempt, so a later round
cannot erase an earlier record"*, and BOTH halves of that clause were wrong.**

- the **reason** was false. `attempt` counts 1..k within ONE warmer's life and resets to 1 on the
  next spawn, so two warmers a week apart both wrote `output.1.log`. what keeps an earlier record is
  the `appendFileSync` in `setOnePokeRow` — clamped 2026-09-25 by
  `runReviewWarmer.integration.test [case7]`, which goes red on a `writeFileSync`
- the **axis** was wrong for the only reader this file has. keyed by attempt with an append, bar
  9b's `cat` produced the worst of both arrangements: one warmer's chronology **scattered** across
  k files while k warmers' rows **mixed** inside each, so `cat output.*.log` yielded every attempt-1
  row across all history, then every attempt-2. ⇒ a driver who checked a **live** spender could read
  a week-old row as current

⇒ the key is the **run** the warmer was spawned for, which buys three properties an attempt index
and a spawn-time stamp both lack: it **joins the two sinks** (`output.<run>.log` names the exact run
dir whose `warmer.pokes.jsonl` mirrors it), it **sorts chronologically under the glob** (because
`genLogDirName` leads with an escaped iso stamp of fixed width), and it is **already held** by
`runReviewWarmer`, so no new identity threads through the loop.

🟡 **the bar's REQUIREMENT is unchanged** — a warmer still leaves a pid and a readable log under
`warmers/reviewer=$xyz/`. what moved is the filename and the rationale, and the amendment is
recorded here rather than made silently, because a wish bar is the wisher's artifact. it was caught
first as `.dream/v2026_09_25.fix.the-warmer-attempt-log-is-keyed-on-the-wrong-axis.md`, then raised
as a review blocker on i010 against shipped bar 9b.

🔴 **and every row lands in a SECOND place too — bar 9's sink, beside the review output.** the two
are not alternatives, and a first read of bars 9 and 17 together reads as a contradiction, so it
is stated here outright:

| the sink | keyed by | it answers |
|---|---|---|
| `$logDir/warmer.pokes.jsonl` | the **RUN** | *"what did this round cost?"* — so `review._.cost` reaches it with no second discovery rule |
| `.agent/.cache/…/reviewer=$xyz/output.$run.log` | the **REVIEWER**, then the run | *"is a warmer alive for this lane, and what has it done?"* — a driver `cat`s it mid-flight |

⇒ they are keyed on different axes — the ledger by run alone, the voice log by **lane first** — so
neither can serve the other's question: no run dir gathers a lane's history, and no lane dir can be
priced without a second discovery rule. a warmer writes **both**, from one `setOnePokeRow`, so the
two cannot drift.

🟡 the run segment in the second path is a **join**, never a change of axis. the lane is still what
that dir answers for; the run parts one warmer's block from the next inside it.

🔴 **the pid file is a LOCK, never a breadcrumb.** a guard re-drives a lane many times per route,
and each round would otherwise spawn another warmer for the same reviewer. they never conflict —
they simply all bill, so **spend grows with rounds while coverage does not**. so spawn is a
findsert keyed on a LIVE pid (`rule.require.idempotent-operations`).

🟡 and a pid FILE is not a live process: the file outlives any warmer that was killed, crashed,
or spent its budget. the liveness probe is what lets the lock repair itself rather than latch shut
and leave a lane cold forever.

🔴 **AMENDED 2026-10-08 — the pid file and its pid-liveness probe are replaced by a beat watermark;
the two requirements above are unchanged, and each now holds by state rather than by a lock.**

- **the one-warmer findsert (bar 14)** is keyed on a warmer **record** in the warmer watermark
  (`getOneReviewWarmerRecord`), never on a `process.pid` file. spawn reads the record and skips
  while `isReviewWarmerRecordAlive` holds. the record is written under `withSimpleMutex` for one
  short transition only — no lock spans a warmer's life (`rule.require.locks-via-with-simple-mutex`,
  `rule.forbid.hand-rolled-locks`)
- **the self-repair (bar 15)** comes from the beat: a live warmer writes a fresh `wakeBy` at every
  wake and stamps `endedAt` on exit, so a killed or crashed warmer stops to beat and its record
  lapses within one cadence plus a two-minute grace. no pid probe is made — a recycled pid fools one
- **the stop handle (bar 17)** is the `pid` field of that record, printed on the spawn tree and the
  `--warmer off` tree. the voice log `output.$run.log` stays where bar 17 puts it; no `process.pid`
  file is written beside it

⇒ the bars' requirements stand — one live warmer per reviewer, a lock that cannot latch shut, a
handle to stop the spender. what moved is the mechanism, recorded here rather than made silently.

##### 🔴 the schedule is relative to the LAST TOUCH, never to a fixed clock

the warmer counts its attempts from **the last time the nominal review ran for that reviewer**,
and on each wake it asks one question before it spends:

> **has a real review run for this reviewer since I last looked?**

| the answer | what the warmer does |
|---|---|
| no | poke, and count the attempt |
| **yes, within `$duration`** | 🔴 **skip the round and reschedule** to `lastRun + $duration` |

⇒ **because a real review already warmed the cache.** a poke sent moments after one buys exactly
naught and bills in full — the redundant-warm case this rule exists to minimize. the schedule is
a chain of touches, and **a real review is a touch**, so it resets the clock exactly as a poke
does.

🟡 this is the same invariant the eviction probe had to learn the hard way: its gaps are measured
`sinceTouch`, never `sinceStart`, because a touch of either kind refreshes residency.

## .the bound — what this wish does NOT cover

- 🔴 **it does not claim a live grove-wide hit rate.** the layout is clamped by BYTES.
  the one live probe run (input **1**, cache.get **58,155**, ~97% off input) proves the
  PIN works; it does not prove what an 11-lane grove will realize. a projection does not
  close a bar here — `rhx review._.cost --of grove` reports the realized figure or nothing
- 🔴 **it does not settle two behavior questions**, and both are caught as dreams rather
  than ridden along:
  - the **tail order** trades ~31pp of cache against target recency. the flip shipped with
    a static closer as mitigation; the A/B against a live brain is still owed, and one
    fixture (a target revised every round) **regressed 93.2% → 70.1%**
  - the **new-file representation** was chosen on 7.8% of bytes plus two unmeasured claims
    about what a reviewer does with a `+` prefix
- it does not change any rubric or any lane's bind. the cross-lane rubric reuse question was
  **dispatched**, not answered here (`ehmpathy/rhachet-roles-bhuild#398`)

🔴 **AMENDED 2026-09-24 — this wish DOES now touch the guard.** the clause above read *"it does
not change any rubric, any guard, or any lane's bind"*, and the warmer breaks the middle third of
it: `rhx review` spawns a process, and the guard's budget is what gates it.

⇒ the amendment is deliberate and the reason is measured: **the four layout levers were clamped
by bytes and the binding constraint turned out to be the clock.** a wish that measured the defect
and then declined the one lever that repairs it would ship an instrument and leave the problem.

🟡 what stays bounded: the warmer reads `route.guard.budget` and **writes no guard state**. it
changes no verdict, no level, no passage, and no lane's bind. it is a spender the guard gates,
never a participant in the guard's decisions.

## .why it matters

the review ladder is the quality mechanism this whole repo runs on, and its cost is what
bounds how many lanes a guard can afford. a cheaper prompt is not a tidiness win — it is
**more lanes per stone**, which is more defects caught before a human reads the PR.

and the instrument matters more than any one lever: a lever measured wrong is a lever that
ships a regression while the number goes up.
