# 🌙 dream: rhachet unlinks a role and runs naught of it, so the role's init writes outlive it

kind: reseed · owner: ehmpathy/rhachet · caught 2026-10-16

## .the cue that fired
a peer reviewer (bhrain route `fix-status-line-binds-own-actor`, 5.1 i004 r10) ran the real cli:
after `rhachet init --roles -driver`, the driver link was gone and `settings.of.repo.json` still held
the driver's route status line. `init --hooks` left it there too.

## .the gap, precisely
rhachet runs a role's `inits` only right after it links that role (`rhachet init --roles <role>`).
an unlink (`--roles -<role>`) removes the link and runs no role code at all. so every write a role
init made — a `statusLine`, a permissions heal — stays in the repo layer with no role behind it,
and every actor derived from that layer keeps it. clamped as the gap it is in bhrain:
`init.claude.status-line.survives-layout.integration.test.ts` `[case4]` `[t2]`.

## .the shape of the fix
- let a role declare `inits.onUnlink` (or a teardown peer per init); rhachet runs them before it
  removes the link, framed like the link-time inits
- or: derive role-owned settings keys per role (the frame-lines dream), so an unlink drops them
  with the role and no teardown is needed
- bhrain's status-line init already carries the removal (`remove_our_line`, gated on the driver
  link); a teardown hook would only need to call it once the link is gone

## .why it is not done in this round
it belongs to another repo; a tree adopts only what is scoped to itself. the bhrain half — the
removal branch and its gate — ships in this route.
