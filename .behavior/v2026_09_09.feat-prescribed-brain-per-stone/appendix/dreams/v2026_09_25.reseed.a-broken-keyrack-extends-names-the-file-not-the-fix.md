# 🌙 dream: a broken keyrack `extends` names the file, never the fix

- kind = reseed
- owner = `ehmpathy/rhachet`
- caught = 2026-09-25

## .the cue that fired

the acceptance suite would not finish in this worktree. three consecutive runs — 2026-09-19,
and twice on 2026-09-25 — each ended on the same error and produced **no jest summary at all**:

```
🔐 keyrack get
   └─ ✋ ConstraintError: extended keyrack not found
      ├─ path: .agent/repo=bhrain/role=reviewer/keyrack.yml
      ├─ absolutePath: /…/.agent/repo=bhrain/role=reviewer/keyrack.yml
      ├─ from: /…/.agent/keyrack.yml
      └─ ran: keyrack get --for repo --env test --owner ehmpath

  ●  process.exit called with "2"
        at Object.source (jest.acceptance.env.ts:63:11)
```

⇒ 🔴 **and it took three reads of three logs to learn what to DO about it.** the error names the
absent file, its absolute path, the manifest that points at it, and the command that ran. it does
not name the one act that repairs it.

## .the gap, precisely

`.agent/keyrack.yml` is **tracked**; the role trees it extends are **generated and gitignored**:

```yml
# .agent/keyrack.yml — tracked
extends:
  - .agent/repo=bhrain/role=reviewer/keyrack.yml
  - .agent/repo=bhuild/role=dispatcher/keyrack.yml
  - .agent/repo=ehmpathy/role=mechanic/keyrack.yml
```

```
$ git check-ignore -v '.agent/repo=bhrain/role=reviewer/keyrack.yml'
.agent/repo=bhrain/.gitignore:6:*  →  ignored
```

⇒ **so a fresh clone or a fresh git worktree satisfies none of the three by construction.** the
manifest is committed; its targets are not, and no step between `git worktree add` and
`rhx git.repo.test` puts them there.

the repair is one command per role:

```sh
rhachet roles link --repo bhrain   --role reviewer
rhachet roles link --repo bhuild   --role dispatcher
rhachet roles link --repo ehmpathy --role mechanic
```

⇒ **after which acceptance runs.** the act is cheap, idempotent, and unguessable from the message.

## 🔴 .why it is worse than an ordinary absent-file error

three properties compound, and each one alone would be minor:

| property | the cost |
|---|---|
| it fires in **jest env setup**, not in a test | the failure carries no test name, so it reads as infrastructure noise beside real assertions |
| it calls **`process.exit(2)`** | jest prints no `Tests:` summary, so the run looks **truncated** rather than **failed** |
| the absent file is **gitignored** | a reader who greps for it finds naught, and concludes the manifest is stale rather than the tree unbooted |

⇒ 🔴 **the third is the sharp one.** `rule.require.errors-name-the-fix` would be satisfied by a
weaker message where the file is discoverable. here the file is invisible to every instinct a
reader has — `ls`, `git log`, a grep of the repo — so the error must carry the remedy or the
remedy is not reachable.

⚠️ **and the message actively misleads toward the wrong repair.** four fields of path detail
invite an edit to `.agent/keyrack.yml` — drop the line it names, and the error goes away *and the
credentials that line declared go with it*. the correct act touches no tracked file at all.

## .the shape of the fix

🔴 **upstream, in `sourceAllKeysIntoEnv`'s `extended keyrack not found` branch** — three bars,
each with a test:

1. **the message names a runnable command.** the manifest path already encodes the coordinates
   (`.agent/repo=$repo/role=$role/keyrack.yml`), so the fix line is derivable with no lookup:
   ```
   fix: rhachet roles link --repo bhrain --role reviewer
   ```
   assert the rendered error contains that exact string for a `repo=`/`role=` shaped path.
2. **it says the target is GENERATED.** one line — *"this file is linked from a package, not
   committed"* — so a reader does not reach for the manifest. assert it is present.
3. **it reports EVERY broken extend, not the first.** three were absent here and the error named
   one, so the repair loop is three runs long. assert a manifest with two broken extends lists
   both.

🟡 **bar 1 degrades gracefully**: a path that does not match the `repo=`/`role=` shape keeps the
extant message. the fix line is an addition, never a replacement.

### the cheaper alternative, if the ask is refused

a **preflight** in the consumer: `jest.acceptance.env.ts` checks each `extends` target before it
calls `keyrack.source`, and throws a `ConstraintError` that names the link command. that repairs
one repo and leaves every other consumer of `keyrack.source` on the bare message.

⇒ **it is strictly worse and it is available today**, which is worth a note so a future traveler
can take it under deadline rather than re-derive it.

## .why it is not done in this round

- **not clean.** the message is rendered inside `rhachet`'s `sourceAllKeysIntoEnv`, another repo
  on another cadence. no edit here reaches it
- the local preflight **is** reachable, and it is out of this route's scope — this drive is a
  prescribed-brain feature, and a test-bootstrap guard rides along with none of its stones

## .what this re-prices

🔴 **an acceptance run that produces no `Tests:` summary must not be read as inflight.** this one
had already ended, three times, and its last line looked like a warn. ⇒ **the absence of a summary
is a signal, and the reflex should be to grep for it rather than to wait.**
