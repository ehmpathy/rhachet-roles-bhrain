# 🌙 dream: a booted brief names `rhx route.mutate.guard` a driver-owned lever, and it is the hook that BLOCKS guard reads

- kind = `fix`
- owner = `rhachet-roles-bhrain`
- caught = 2026-09-13

## .the cue that fired

nine l1 peer lanes returned `constraint ✋` on a context overflow. the sanctioned remedy, per three
separate booted briefs, is a **guard edit** — narrow that lane's `--paths-with`, trim its
`--conversation`, then let the guard run it. so i reached for the lever the owner table names:

> `rule.always.spend-own-levers-before-escalation`, the **driver** column, row 2:
> *"🔴 `rhx route.mutate.guard` — the stone's own `--paths-with`, `--conversation`, `level`,
> `budget`"*

`rhx route.mutate.guard` returns silently. `--help` returns silently. i read the source.

## .the gap, precisely

`.agent/repo=bhrain/role=driver/skills/route.mutate.guard.sh` is **not a mutator**. its own docblock:

```sh
# .what = pretooluse hook to protect route stones, guards, and metadata
#
# .why = prevents drivers from:
#        - reading guard files (enables gaming review criteria)
#
# usage:
#   configured as PreToolUse hook via getDriverRole.ts
#   reads tool input from stdin JSON
#
# exit codes:
#   0 = allowed · 2 = blocked
```

⇒ **it is the mechanism that forbids the act the table says a driver owns.** it reads stdin JSON, it
takes no `--paths-with`, and it exits 2 on a `.guard` read.

the real gate is one line further down that same docblock:

```sh
# privilege:
#   human can grant via: rhx route.mutate grant allow
#   creates flag at: $route/.route/.privilege.mutate.flag
```

measured this round:

```
$ rhx route.mutate grant get
status = blocked (no privilege flag)
```

⇒ so the lever is **human-gated**, and it sits in the table's **driver** column.

### 🟡 the harm is the one the row was written to prevent

that row was added after a measured incident — a driver filed an overflowed-lane repair as a
**fulcrum**, a call reserved for the wisher, and collected six rounds of evidence about it while the
remedy sat unused. the wisher closed it in seven words: *"you have the abiltiy to edit the guards."*

the row's own note states the mechanism:

> *"an absent row does not read as absent. it reads as 'not mine.'"*

🔴 **a row that names a hook fares worse than an absent one.** an absent row sends a driver to look;
this row sends them to run a command that returns silently, and a silent exit 0 reads as a no-op
rather than as a wrong tool. i only found the truth because i read the `.sh`.

## .the shape of the fix

two parts, and the second is the larger question:

1. **the doc half — a move and a name.** the row belongs in the **human** column, and its command is
   `rhx route.mutate grant allow` (which mints `$route/.route/.privilege.mutate.flag`), never
   `rhx route.mutate.guard`. the same edit is owed in `rule.forbid.hand-run-reviews` and
   `rule.always.diagnose-reviewer-malfunctions`, which both prescribe *"`rhx route.mutate.guard` —
   narrow its `--paths-with`"* as the sanctioned answer to an overflowed lane. **three booted briefs
   carry the same wrong command.**

2. 🔴 **the capability half — is a driver-owned guard edit wanted at all?** the guard's stated `.why`
   is *"prevents drivers from reading guard files (enables gaming review criteria)"*, and a driver who
   may narrow a reviewer's scope can narrow it away from the code it grades. so the honest options:

   | option | what it costs |
   |---|---|
   | **A** — doc-only. the lever is a human's; the driver halts with the exact grant command | a halt per overflowed lane, and the wisher's attention |
   | **B** — a scoped mutator: a driver may narrow `--paths-with` and `--conversation`, never `budget` or the rubric | a new skill, and an argument about which fields are safe |
   | **C** — leave it, and treat overflow as a route-artifact-size problem | what this round actually did. see below |

   ⇒ **B is what the owner table already promises**, which is the strongest argument that the table
   is a design intent that was never built rather than a typo.

## .why it is not done in this round

**safe — no. clean — no.**

- it edits three **booted, published** briefs in `.agent/repo=bhrain/role=driver/`, none of which
  this branch has opened. that is a scope leak out of a concurrency wish and into the driver's own
  rulebook
- option 2 is a **capability** decision with a stated security rationale against it. a driver is the
  wrong party to widen the privilege that constrains a driver
- and the diff is already the thing under review: this round closed its halt by a **rehome** of its
  own archaeology to gitignored `.agent/.notes/`, which needed no privilege at all. ⇒ option C
  worked, so the lever was not load-bearing today

🟡 **it is load-bearing the next time.** the rehome is a one-time refund; a route that keeps drafting
artifacts to answer reviewers will overflow again, and the only remaining driver-owned move is to cut
its own record further. **that is a floor, and the guard edit is the lever that does not have one.**
