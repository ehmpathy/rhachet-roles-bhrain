# case=2: director reads every pedigree

inventory rows: g1 (g2, g3 as subtrees). feel: happy. care: alterpath, chosen for demo — a hand read of each `pedigree._.md` is a workable fallback, but the wish names `get` as a deliverable, so its shape is worth a sketch.

## .narrative

before a sprint, the director wants to know which roles hold which courses. one bare call:

```
$ rhx education.pedigree get

🦉 roots run deep

📜 education.pedigree
   ├─ mechanic (ehmpathy, via .mods)
   │  ├─ v2026_11_23 idempotency
   │  │  ├─ greats: helland · kleppmann · stripe · aws builders' library
   │  │  ├─ kernels: 2 held, 1 refuted
   │  │  └─ yields: 2 briefs, 0 skills
   │  └─ v2026_11_30 observability
   │     ├─ greats: majors · beyer (sre book) · honeycomb docs
   │     ├─ kernels: 4 held, 0 refuted
   │     └─ yields: 3 briefs, 1 skill
   │
   └─ no courses (12 roles)
      └─ architect · ergonomist · behaver · dispatcher · driver · learner · librarian · reviewer · researcher · thinker · any · debunker

🥥 open a course
   └─ rhx education.pursuit init --for <role> --course <slug>
```

the director sees architect has no courses, and opens one.

## .bdd sketch

```
given a repo with three roles, one with two graduated courses
  when [t0] the director runs education.pedigree get
    then stdout lists every role, each with its courses in date order
    then each course shows its greats, kernels held vs refuted, and yields
    then roles with no courses collapse into one leaf that names each, never absent, never one branch apiece
    then the hint names the init command
  when [t1] the director runs education.pedigree get --for mechanic
    then stdout holds only the mechanic subtree
```
