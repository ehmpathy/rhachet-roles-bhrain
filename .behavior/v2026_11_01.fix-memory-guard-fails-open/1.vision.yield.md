# vision: memory.guard never halts a tool it cannot judge

## .the first act — the line that fires

one blocked call, captured verbatim. the hook command (`./node_modules/.bin/rhx memory.guard --mode hook`), in a tree where the learner role is not linked:

```
✋ ConstraintError: no skill "memory.guard" found in any linked role
...
tip: did you `npx rhachet roles link` the --role this skill comes from?
exit=2
```

(reproduced 2026-11-01 via `rhx <unlinked-skill> --mode hook`; the same lookup path the crews hit.)

⇒ **the stall is an exit-code collision.** rhx grades its own lookup fault a `ConstraintError` and exits 2. claude code reads exit 2 from a PreToolUse hook as *block*. so a hook that cannot find its skill halts every `Write|Edit|Bash` call.

the other suspects do NOT fail closed in claude code, verified by exit code:

| suspect | exit | claude code reads it as |
|---|---|---|
| absent `./node_modules/.bin/rhx` | 127 | non-block error, call proceeds |
| import rejects in `memory.guard.sh` | 1 | non-block error, call proceeds |
| hook timeout | killed | non-block, call proceeds |
| **rhx cannot find the skill** | **2** | **block** |

## .where each cause is cured

the stall's causes sit in the framework that runs the hook, not in the guard. a bridge in this repo's hook command was built, then dropped on the commander's call: each cause is cured at its owner, as a p0 row. the full list: `root-causes.md`.

## .the outcome world

in a linked tree, naught changes for the crew but the false halts: a write into `~/.claude/**/memory/` still halts with the owl nudge, exit 2. a `grep x ~/.claude/projects/p/memory/a.md 2>&1` now passes, where before it was graded a write. a 160KB heredoc is judged, where before the guard faulted on it.

the nudge names the act it halted: a write into memory, a copy beside memory, or a write the guard cannot place beside memory.

in an unlinked tree, the stall holds until R1–R3 land at rhachet; this pr does not change the hook command.

**the aha:** the guard has exactly one way to say *stop* — its own verdict on a memory write. a read is never that verdict.

## .the contract

| situation | exit | the call | stderr |
|---|---|---|---|
| a write into native memory (Write, Edit, or a Bash redirect, tee, teesafe, cp or mv into it) | 2 | halted | the owl nudge, act `write` |
| a cp or mv beside a memory path (either direction) | 2 | halted | the owl nudge, act `copy`, with a `cat` route for a read |
| a Bash write beside memory the guard cannot place (a `$var` set under `.claude/`, a relative target with no cwd) | 2 | halted | the owl nudge, act `unplaced` |
| any other call the guard judged | 0 | proceeds | silent |
| empty, malformed, or no-`tool_name` stdin | 0 | proceeds | silent |
| a payload past the ~128KB env cap | as its verdict | as its verdict | as its verdict |

a fault in the guard's own run (skill not linked, cli absent, a throw) behaves as on `main`; R1–R4 own it.

### the shape

- the verdict grades a Bash redirect by its **target**: `>`, `>>` or `>|` (with an optional `N` or `&` before it) whose target is a memory path. `2>&1`, `>&2`, `>&-`, `=>`, `->` are not redirects to a file. a relative target is placed by the harness `cwd` and any `cd` before it.
- tee and teesafe are graded by where each operand lands; cp and mv stay blunt, by the presence of a memory path (fulcrum F10).
- `memory.guard.sh` holds the payload in a shell var, never exported, and hands it to node on node's own stdin via a here-string.
- the hook command is `main`'s, unchanged.

## .mental model

a smoke detector that shrieks at steam from the kettle is one a crew unplugs. the guard's one job is to stop one act; every false halt on a read teaches the crew to strip it. so the verdict reads a read as a read.

## .evaluation

- solves: the false halts on reads (R5) and the fault on large payloads (R6), both clamped red before, green after.
- does not solve: the stall in an unlinked tree. that is R1–R3, at rhachet, prioritized as p0.
- cons: cp and mv still halt in either direction beside memory (F10); a read route is two calls.
