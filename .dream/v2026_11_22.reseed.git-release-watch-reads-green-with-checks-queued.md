# 🌙 dream: git.release --watch reads green while every check is queued

kind: reseed · owner: rhachet-roles-ehmpathy (mechanic) · caught 2026-11-22

## .the cue that fired

the ship of `fix-route-reminder-one-per-clone`, pr ehmpathy/rhachet-roles-bhrain#835. the pr was opened by `git.commit.push --auth as-human`.

## .the gap, precisely

- `rhx git.release --watch`, run twice right after the push, printed `🌊 release: ` with an empty title, `👌 all checks passed`, `🫧 no runs inflight`, `0s watched`. `gh pr checks 835` at the same moment listed 35 checks not yet run and 3 passed
- the empty title suggests the skill found no pr for the branch, then read "no checks" as "all checks passed". a green verdict over an absent read is a failhide: a driver who trusts it reports a green pr that has not run
- `git.commit.push` printed `pr: pr #835`, a newline, then `1 (created)`, and handed `835`, a newline, `1` to `git.pull.watch set --which`, which refused it. the pr number parse holds a stray line

## .the shape of the fix

- `git.release --watch`: when no pr is found, or the pr has zero check runs, fail loud (exit 2, `ConstraintError: no pr found for <branch>`), or wait for checks to register. never print `all checks passed`
- `git.commit.push`: take the first integer of the pr lookup output, and clamp it with a test where the lookup prints a second line

## .why it is not done in this round

both skills live in rhachet-roles-ehmpathy; this repo consumes them. the ship used `gh pr checks 835 --watch` in their place.
