# 🌙 dream: the guard cache reconstructs its state by a re-parse of its own rendered prose

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04

## .the cue that fired

a change to the artifact tree render — omit an empty stream bucket, and close the artifact with
`└─ label` instead of `├─ label` — broke **three** assertions in a suite two directories away,
none of which was a snapshot: a cached judge's `reason` came back `null`, a cached judge
re-executed when it should have been reused, and a stdout assertion found no text.

⇒ the render is not merely a display surface. **it is the cache's storage format.**

## .the gap, precisely

`formatTreeBucket` writes a bucket. Two separate operations read one back, each with its own
hand-rolled regex over the same glyphs:

| site | role |
|---|---|
| `guard/tree/formatTreeBucket.ts` | the WRITER |
| `route/judges/runStoneGuardJudges.ts` → `parseTreeBucketContent` | reader, judge cache |
| `guard/artifact/getAllStoneGuardArtifactsByHash.ts` → `parseTreeBuckets` | reader, review cache |

one grammar, three encodings, no test over the pair. both readers matched only the
**middle-child** form (`├─ label`, `│  ` column), so a last-child bucket read as `''`.

🔴 **and the failure is silent.** an unmatched regex yields `''`, which is indistinguishable from
a command that genuinely printed no text — so `passed` and `reason` go null with no error raised,
and a cached verdict is quietly wrong rather than loudly absent.

## .what was done in this round

the two readers were consolidated into one operation, `guard/tree/asArtifactStreamContent`, placed
beside the writer, with a **round-trip** test (`asArtifactStreamContent.test.ts`) that renders with
the real formatter and reads with the real reader. that test goes red on a change to either half.

⇒ so the drift is now caught. **the fragility is not.**

## .the shape of the fix

the durable repair is to stop the re-parse of rendered prose altogether. the artifact file exists
for a HUMAN to read; the cache needs a MACHINE record, and one artifact is asked to be both.

two candidate shapes:

1. **a structured sidecar** — write `$artifact.json` beside the `.md` with `{ stdout, stderr,
   exitCode, passed, reason, durationMs }`. the cache reads the sidecar; the `.md` is free to be
   re-rendered for legibility at any time with no cache consequence
2. **a fenced block inside the `.md`** — cheaper, one file, but it keeps the dependency that a
   reformat can still break

⇒ prefer (1). the whole defect is that one artifact serves two consumers with opposed needs, and
a sidecar is the split.

⚠️ the same dependency binds `getReviewCountsViaRegex`, `getReviewTacticFromContent`,
`asExitCodeFromArtifactContent`, and `getDurationMsFromContent` — every one of them re-parses the
render. a sidecar would retire all five.

## .why it is not done in this round

**clean? no.** it changes the artifact write contract, so every cached artifact on disk in every
live route becomes unreadable to the new reader unless a fallback is kept through a deprecation
window. it also touches five readers, their tests, and the snapshot corpus of both guard suites.

**safe? no.** a wrong move here silently mis-caches verdicts, which is the same silent-wrong class
the defect itself belongs to.

⇒ the round's blocker asked for an empty box to be removed. the consolidation was the smallest
change that made that safe. the sidecar is a behavior of its own.
