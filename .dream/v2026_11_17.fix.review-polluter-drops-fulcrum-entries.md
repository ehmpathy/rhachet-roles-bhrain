# 🌙 dream: the review polluter filter keeps fulcrum entries in scope

- kind: fix
- owner: bhrain/role=reviewer (review scope)
- caught 2026-11-17

## .the cue that fired

two rounds of `behavior-intent-coverage` on 5.1 read the fulcrum summary as rows with no entries
behind them. the entries existed on disk; the review's own `input.scope.debug.json` lists each
`inventory.of=fulcrums.case=*` file under `targetFilesDropped`.

## .the gap, precisely

the polluter filter drops a route's `.fulcrums/inventory.of=fulcrums.case=*` entries (beside vision
cases, dreams, and the wish) and keeps the summary `inventory.of=fulcrums._.md`. so a reviewer sees
an index with no members, and grades the absence it was shown. since fulcrum frontmatter became
the one home of a deferral, the entries are the record; the summary is derived from them.

## .the shape of the fix

- the polluter filter keeps `.fulcrums/inventory.of=fulcrums.case=*` in a review scope, or drops
  the summary with them, so a reviewer never sees one without the other
- a clamp: a route with a summary and two entries, run through the scope filter; both survive

## .why it is not done in this round

the filter is a review-scope concern, beside this route's dispute gates. a change to it moves the
scope of every review in every repo, and earns its own review.
