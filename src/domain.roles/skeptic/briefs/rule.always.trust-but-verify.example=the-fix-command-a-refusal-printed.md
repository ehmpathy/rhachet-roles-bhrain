# rule.always.trust-but-verify.example=the-fix-command-a-refusal-printed

> row: an error text names a fix. 2026-11-21, nheuron, the acceleration subdirector seat.

## .the shape, in any life

an old note on the office copier says "to clear a jam, open tray 3". a clerk tries it twice, but on this model tray 3 holds paper. have I read the label of the part, before I follow the note?

the case below: a verb printed its own fix, the fix failed on a flag it misread, and one look at the flag would have shown it.

## .what happened

`git.tree.behavior` refused a sprout into ehmpathy/rhachet-roles-ghlitch on a stale declapract pin, and printed its fix: the upgrade verb, then the same sprout with `--after-ship` and an inline `--wish '<text>'`.

## .the claim

a fix command that a tool prints is a claim about that tool, as much as any peer's word.

## .the read

- the first re-run, sent before the upgrade tree existed, hit the same stale-pin refusal
- the second re-run, sent once the upgrade tree was live, failed: `--wish file not found: <the text, read as a path>`. under `--after-ship` the verb reads `--wish` as a file
- a wish file under the route, passed by path, queued the tree

## .the miss

the seat ran the printed command as fact twice. a read of the flag (`--help`, or one try with the wish as a file) would have caught it in one call.

## .the cost

two failed runs before the tree queued.

## .the cure

treat a printed fix as a lead: read the flag it names before the run. a printed fix that fails is a tool defect, owed to the verb that printed it.
