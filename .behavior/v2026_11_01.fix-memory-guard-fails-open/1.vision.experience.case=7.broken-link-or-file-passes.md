# case 7: a dangled link or a broken skill file never costs a call

rows 34, 35, 36, 37 (rows 38, 45 itemized).

proof: `src/domain.roles/learner/getLearnerRoleHookCommand.integration.test.ts`, the given named at each block.

## .narrative

a crew's tree holds the learner link, but the package behind it is gone: an install was pruned, a dist not rebuilt. the link stays, pointed at naught. the hook finds the link and cannot read the skill. a hook that treated any failure as a halt would stall the crew. this one sees the dangle, lets the call through, and leaves one line for the human: the skill link dangles at a path, reinstall, then link again. the dangle may sit on the skills dir or on a dir above it; the line is the same.

in another tree the skill file itself is bad: a half-written `memory.guard.sh` with a syntax fault, a zero-byte file, a file cut short before its exit map. the exit map lives inside the file, so a file that cannot run as written never reaches it. a syntax fault would exit 2, a halt. an empty or cut file would exit 0, a silent pass that hides the fault. the hook seals the codes it accepts, so each of these reads as a fault: exit 1, one line that says the skill ended short of a sealed code, and reinstall.

on a host whose `readlink` lacks `-f`, the guard still finds its own package. no step changes for the clone: a memory write halts, `ls` passes in silence.

## .bdd sketch

```
given [caseA3] a learner link whose package is gone (the link dangles)
  when [t0] a Bash `ls` fires the hook
    then exit 1, never 2
    then stderr is one line:
      📜 memory.guard: could not run (skill link dangles at <tree>/.agent/repo=bhrain/role=learner/skills/memory.guard.sh); call allowed. fix: reinstall rhachet-roles-bhrain, then ./node_modules/.bin/rhachet roles link --repo bhrain --role learner
  when [t2] the dangle sits on an ancestor dir, not the skills dir
    then the same line, the same exit

given [caseD-file] a linked learner whose skill file cannot run as written (syntax fault · empty · cut short)
  when [t0] a memory write fires the hook over each broken file
    then each exits 1, never 2 and never a silent 0
    then the first stderr line of each matches:
      📜 memory.guard: could not run (skill ended with exit <n>, short of a sealed code, at ./.agent/repo=bhrain/role=learner/skills/memory.guard.sh); call allowed. fix: reinstall rhachet-roles-bhrain

given [caseG] a learner skill linked as a file, on a host whose readlink lacks -f
  when [t0] a memory write fires the hook
    then exit 2, the nudge
  when [t1] a Bash `ls` fires the hook
    then exit 0, silent
```
