# 🌙 dream: a hand-run skill reads `dist/`, so an unbuilt `src/` change is invisible

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-bhrain
- **caught** 2026-09-18

## 🔴 .this dream shipped a FALSE claim for one round — the correction is the first section

it first asserted that **`git.repo.test --what acceptance` does not build first**, and called that
*"verified 2026-09-18"*. **it is false.** `package.json:65`:

```json
"test:acceptance:locally": "set -eu && npm run build && LOCALLY=true jest -c ./jest.acceptance.config.ts …"
```

both acceptance commands open with `npm run build`. ⇒ the blackbox suite is **never** blind to an
unbuilt `src/` change, and the row that said it was has been struck.

**what the "verification" actually was:** a full acceptance run went green right after a `src/`
change, and that was read as *"it passed against a stale `dist/`"*. it was not — it built, then
passed honestly. **a green result was explained by the theory rather than tested against it**
(`rule.require.trust-but-verify`).

🟡 **and the correction was forced by evidence, not by a re-read.** the very next acceptance run
went **red on exactly the change under test** — an unbuilt-`dist/` suite could not have noticed it.
⇒ that is the check the original claim never ran: *if the suite were blind, what would it fail to
catch?*

⚠️ **the residual defect below is REAL and was measured.** only its blast radius was overstated.

## .the cue that fired

a source change was written, its unit tests went green, and **the real command still showed the old
behavior**. the roster of other self-review lanes rendered in `formatRouteStoneEmit.test.ts` and did
not render in `rhx route.stone.set --as passed`.

⇒ the tell was the gap between *"the unit test proves this renders"* and *"the driver does not see
it"*. the fix was `npm run build`, and naught else.

## .the gap, precisely

every skill entrypoint imports the **built package**, never `src/`:

```sh
# .agent/repo=bhrain/role=driver/skills/route.stone.set.sh:28
exec node -e "import('rhachet-roles-bhrain/cli/route').then(m => m.routeStoneSet())" -- "$@"
```

`rhachet-roles-bhrain/cli/route` resolves through `package.json` exports to `dist/`. so:

| how the code is reached | what it reads | an unbuilt `src/` change |
|---|---|---|
| unit | `src/` | ✅ seen |
| integration | `src/` | ✅ seen |
| acceptance (blackbox) | `dist/` — **but it builds first** | ✅ seen |
| 🔴 a **hand-run skill** (`rhx …`) | **`dist/`** | 🔴 **invisible** |

**one row is left, and it is the row a human and a driver actually stand in.** the suites all
protect themselves; the terminal does not.

## 🔴 .why it still matters, with the suites exonerated

the harm is no longer *"a green suite that means naught"*. it is narrower and still real:

- a **driver** tests a change by hand, sees the old behavior, and concludes the change did not work
- ⇒ so they debug a defect that was already fixed, or worse, "re-fix" it and land a second change
- a **human** reviews a branch by a run of the command and sees pre-change output
- the failure is **silent**: no error, no warn, no hint that `dist/` predates `src/`

⚠️ **it is at its worst for exactly the change that is hardest to unit-test** — an emit, a message,
a rendered tree. those are the ones a person naturally verifies by eye, at the terminal, which is
the one path with no build in front of it.

**measured:** the roster change had 11 green unit assertions and a bite check, and still rendered
naught at the terminal. two of the three proofs read as sufficient and were not.

## .the shape of the fix

🟡 **option 1 from the first draft is struck** — *"build as a precondition of the acceptance lane"*
was written for a defect that does not exist; the lane already does it.

1. **fail loud on a stale `dist/`** — compare the newest mtime under `src/` against the newest under
   `dist/`; if `src/` is newer, warn (or throw a `ConstraintError`) that names `npm run build` as
   the fix. it costs milliseconds, and it names the fix rather than hides it
2. **build on demand in the skill entrypoint** — cheapest to reason about, and it puts a multi-second
   build in front of every `rhx` call. ⇒ **not recommended** at that price
3. **make the skills import `src/` under a flag** — removes the blackbox property the entrypoint has,
   which is that a driver runs the artifact a human gets. ⇒ **not recommended**

⇒ **option 1 is the recommendation**, and the warn form is likely better than the throw: a stale
`dist/` is normal and harmless when nobody edited `src/`, and a hard throw would fire on a dirty
worktree that is merely mid-edit.

## .why it is not done in this round

**SAFE?** yes — it touches a skill entrypoint, no production path.
**CLEAN?** 🔴 **no.** the check belongs either in `rhachet`'s skill runner or in each role's skill
entrypoint, and both live in **different trees** from this repo. so the fix is a re-seed rather than
an edit here (`rule.always.catch-dreams-for-followups`: *a fix that belongs to another repo is
caught as a dream*).

⇒ so it is caught, with the corrected diagnosis and the recommended option, rather than
half-applied here.

## 🟡 .the transferable lesson, which is not the defect

the defect is a build step. **the lesson is that a claim was called *verified* on evidence that
could not have falsified it.** a green suite is consistent with *"the suite is blind"* and with
*"the suite is fine"* alike, so it distinguishes them not at all.

⇒ the check that settles it is one line of `package.json`, and it was never opened — because the
theory already explained what was seen. **an explanation is not a test.**
