# 🌱 seed: a peer-review round can start while a prior blocker sits unanswered

- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **severity** = blocker — the root cause of a 9-day, 32-iteration non-convergent stone
- **caught** 2026-09-03 by a reflector on a read-only enrollment, at the request of a human

## .what

the invariant, stated plainly:

> **it must be impossible to run another round of peer review while any prior blocker-bearing
> `.given` is unanswered.**

today it is possible, and a live stone ran **28 iterations with zero `.taken` files written**.

done when: a driver cannot enter a peer-review round while it owes an articulation — and a
`.taken` debt survives an edit to the code under review, so the debt is discharged by an answer
rather than by a hash change.

## .why

`rule.always.converge-with-reviewers` already asks for this in words: *"in every branch you write
a `.taken` and re-submit. you do not stop at the block."* the engine does not enforce it, and it
quietly un-asks it — so the rule is obeyed only by drivers who choose to, and the cost of that
choice falls on whoever waits for the stone.

the incentive is what makes it structural rather than incidental. a driver blocked by a review
has two exits — write the articulation, or edit code and hope the finding does not return.
**the edit is strictly cheaper and feels equally legitimate.** so the driver edits, the whole-tree
hash moves, every cached clean verdict dies, all N reviewers re-roll, and the loop repeats without
a conversation ever occurring.

## .the evidence — read from source, in `rhachet-roles-bhrain`

two defects compose. **each alone is survivable; together they open a door a driver can leave the
conversation through, indefinitely.**

| # | defect | file |
|---|---|---|
| **D1** | the contemplation gate is on the **exit**, never the **entrance** | `runStoneGuardReviews.js` |
| **D2** | contemplation debt is keyed `(slug, hash)`, so any code edit discharges it | `getRouteGuardReviewPeerContemplationStatus.js:64` |

**D1** — `getStoneGuardReviewPeerUncontemplatedUnforgiven` is the single source of truth for *"who
still owes a `.taken`"*. its consumers:

- ✅ `setStoneAsPassed.js`
- ✅ `setStoneAsOverruled.js` / `setStoneAsForced.js`
- ✅ `getRouteDriveBlockerMessage.js` (display)
- ❌ **`runStoneGuardReviews.js` — never calls it**

so the gate does not bite until the driver attempts **passage**, and a re-run is not passage.

**D2** — `getRouteGuardReviewPeerContemplationStatus.js:64-68` reads givens at `hashCurrent`
**only**, and `computeStoneReviewInputHash.js:53-64` hashes the **entire** `artifacts:` set. so one
line changed anywhere retires every outstanding debt. three ways an unanswered blocker dies
silently, and only the third is legitimate:

1. the reviewer re-runs at H2 and stochastically does not re-raise → debt gone, never answered
2. the reviewer is **exhausted** (`runStoneGuardReviews.js:369`) → no given at H2 → no debt.
   ⚠️ this makes the "manufactured exhaustion" that `rule.always.converge-to-terminal` calls a
   defect **structurally free**
3. the reviewer re-runs clean → a real discharge

⇒ the obligation to answer is contingent on **the critic's re-detection**, never on the driver's
engagement. that is backwards.

## .scope — do NOT let these expand it

surfaced in the same investigation, all lower priority, none required here:

1. **per-reviewer cache keys** — `computeStoneReviewInputHash` hashes the whole artifact set, so a
   reviewer's clean verdict dies on a hash change its own rule does not govern. `input.scope.json`
   already records each reviewer's exact `targetFiles`

   blockers, escalate rather than re-roll. a backstop; the fix above removes most of what it catches

4. **route artifacts as review targets** — `0.wish.md` and `1.vision.yield.md` are `targetFiles`
   for peer reviewers at stone 5.1, so 5.1 grades frozen outputs of a stone that already passed
