# 🌙 dream: a timeout message names its bound, and not the contention that caused it

- **kind** = fix
- **owner** = `rhachet-roles-bhrain`
- **caught** = 2026-09-09

## .the cue that fired

a `behavior-declaration-coverage` self review walked the vision's own commitments against the code.
one line of fulcrum **F7** is an obligation on THIS round rather than a deferral:

> *"the timeout message — which already names the bound — should also name the **in-flight count**,
> so contention is a visible candidate rather than one the driver must infer."*

⇒ the message was checked. it names the bound and says naught about the count.

## .the gap, precisely

`runOneReview.ts:90` builds the malfunction stderr:

```ts
stderr: `💥 malfunction: review timed out after ${formatTimeoutForHuman({ ms: input.timeoutMs })}`,
```

**it is already good** — its `.why` cites `rule.forbid.failhide` by name, and
`driver.route.peer-review-timeout.acceptance.test.ts:64` clamps that it contains `'timed out'`. so a
driver reads *"timed out after 21 minutes"*, never a bare `malfunction`.

🔴 **what it cannot answer is the question concurrency just made askable:** *was this lane slow, or
were seven co-members?*

`PT21M` is a **wall-clock** bound, and every value of it — the default and any `timeout:` an author
tuned by hand — was calibrated while a lane ran **alone**. eight `rhx enroll claude` lanes share one
machine and one provider quota, so **the level gets faster and each lane gets slower.** the timeout
measures the quantity that degrades.

⚠️ and a tripped timeout is not a retry — it escalates:

| step | what happens |
|---|---|
| 1 | contention pushes a lane past its bound |
| 2 | no parseable verdict → **`malfunction`** |
| 3 | malfunction is **terminal for unlock** |
| 4 | 🔴 the next level opens and spends its budget |
| 5 | the stone still cannot pass — a malfunction blocks passage |
| 6 | the driver diagnoses a reviewer that was never broken |

⇒ the message is what stands between step 6 and a correct diagnosis, and it currently omits the one
fact that would point at the cause.

## .the shape of the fix

```
💥 malfunction: review timed out after 21 minutes (7 co-members in flight at its level)
```

the count is **not** available where the message is built. `asReviewSubprocessCapture` is a pure fold
over `{ stdout, stderr, code, killed, timeoutMs }` and knows no level. so the count must be threaded:

| where | what it holds today | what it would carry |
|---|---|---|
| `runStoneGuardReviews.ts` — `runOneBounded` | the level roster, and the bottleneck | a **live reader** of the in-flight count |
| `runOneReview` | `timeoutMs` | plus `inflight: (() => number) \| null` |
| `asReviewSubprocessCapture` | the fold | appends the clause when a reader is supplied |

🔴 **it must be a READER, never a number — corrected 2026-09-11, and this is what makes it dirty.**
an earlier draft of this dream said *"the in-flight count at spawn"*. that count is **wrong** in the
one case the clause exists to explain: a lane that spawns alone and dies 21 minutes later, with seven
co-members aloft by then, would report `0 co-members` — and a confidently wrong diagnostic is worse
than an absent one (the argument `rule.forbid.failhide` makes about a swallowed error, applied to a
number).

⇒ so the pour must hand down a closure over the bottleneck's `.active`, read at the moment of the
kill. that is a **contract change on a shared operation**, not a suffix.

⚠️ **and `runOneReview` has a SECOND caller.** `review.by`'s `stepReviewBy` composes it directly, and
runs no pour — so it must pass `null`, and `rule.forbid.undefined-inputs` forbids the optional form
on an internal contract, which is why the shape above is `| null` rather than `?`. (an earlier draft
cited `GuardProgressEvent.slot` as precedent for `?` — that field is **sdk-exported**, which is the
declared exception, and `runOneReview`'s input is not.)

🟡 **and the snapshot moves.** `driver.route.peer-review-timeout.acceptance.test.ts` pins the
message, so the clamp must be re-cut with the clause and a sanitizer for the count.

### 🔴 the tree shows no duration for a malfunctioned lane — found 2026-09-11

the driver's fallback for *"was this lane slow, or were seven co-members?"* looks like it should be
the guard tree itself: settled lanes render `rejected [TIME]`, so a reader could compare.

**they cannot.** `driver.route.peer-review-timeout.acceptance.test.ts.snap:7` is the whole line:

```
   ├─ malfunction 💥
   ├─ terminal — does not block higher levels
```

⇒ **the timed-out lane carries no duration**, so the tree offers no comparison basis at all. the
`timed out after 21 minutes` text lives in the `.given` artifact's stderr, one file away.

⚠️ **and that repair is bigger than this one.** a `[TIME]` on the malfunction line is a render change
that re-cuts every malfunction snapshot among the 36 the vision froze — which acceptance 2 exists to
hold still. it is a second dream, not a clause on this one.

## .why it is not done in this round

the SAFE/CLEAN test, answered honestly:

| question | answer |
|---|---|
| **safe?** | ✅ yes — a message suffix on a failure path |
| **clean?** | 🔴 **no** — a live-reader argument on a **shared** operation with a second, pour-less caller, plus a re-cut acceptance snapshot |

⇒ this round's diff holds eight `src/` files and `runOneReview.ts` is not among them. and the
corrected shape above is what settles it: a **number** would have been a suffix; a **closure over the
pour's semaphore, threaded into a shared operation and defaulted to `null` by its other caller**, is a
ripple.

⚠️ **and the half that would make the message TRUE is unmeasured.** F7's own overturn condition is a
contention multiplier, and that measurement was impossible until concurrency shipped. it now has —
so the honest order is **measure first, then word the message against what the measurement shows.**
to ship the clause now would state a count with no evidence that the count is the cause.

⇒ per `rule.always.fix-forward-under-scouts-honor`, a defer for **dirt** owes a dream **and** a
fulcrum — the dream records the work, the fulcrum records that a judgment was made. the fulcrum is
**F7**, already on the board at 78%, and this dream is now cited from it.
