# case 4: a broken guard never costs the clone a call

rows 21, 22, 23, 24, 39, 40, 41, 43 (rows 42, 44 itemized).

proof: `src/domain.roles/learner/getLearnerRoleHookCommand.integration.test.ts`, the given named at each block.

## .narrative

a clone works in a tree where the learner is linked, but the installed package is broken. it runs `ls`; the file list comes back as if no guard existed. it writes a file; the write lands. it never learns the guard is broken, and it never needs to. its human sees a `memory.guard hook error` notice under each call that names the fault and the fix.

the notice differs by who must act:

- a dependency at the wrong version leaves a module the cli cannot load. a reinstall cures it, so the notice is one line that says reinstall.
- a cli that throws as it loads, or a guard that throws as it runs, is a defect a reinstall reloads unchanged. the notice asks for a report, and the stack follows the first line so the report carries what a debug needs.
- a guard that exits a code it has no verdict for, or a stray 2 of node's own, is no verdict. only the guard's private block code reads as a halt, so the stray 2 proceeds like any fault.
- a setup step in the skill that exits 2 before node runs would read as a halt under `set -e`. it maps to a fault.

and if the clone, in any such tree, tries a write into native memory, it lands. a guard that could not judge does not halt (row 24, forbidden by design); the notice is what tells the human the guard is off.
