# 1.vision.yield

> **a driver cannot enter a peer-review round while it owes an articulation to a prior blocker.**
> **and an unanswered blocker survives an edit to the code under review.**

## .the outcome

| | before | after |
|---|---|---|
| exits from a blocker | answer it, **or edit and re-roll** | answer it. plus a human overrule |
| the cheaper exit | the edit — one keystroke | the answer |
| a blocker survives an edit? | no — dies with the hash | yes — keyed to the reviewer |
| when the driver learns it owes | after a full round + judges | at the door, before a subprocess spawns |
| exhaustion + a blocker unanswered | discharges it free | persists it |

the mechanism: `runStoneGuardReviews` never calls
`getStoneGuardReviewPeerUncontemplatedUnforgiven`, so the check runs at **passage** — and a re-run is
not passage. the edit clears the debt as a side effect, and today that is permitted.

⚠️ **limit: the gate cannot check that an answer is real.** `setStoneAsContemplated.ts:77` tests
that a `.taken` exists, never what it says. an empty one passes the engine, costs a round, and is
re-raised by the reviewer that reads it.

## .the contract

### 🔴 P1 and P2 are order-coupled

**both ship, or neither does.** the table below is a hypothetical: what would still be broken if only
one half landed.

| if only this shipped | what would still be broken |
|---|---|
| **P1** | it consults a hash-keyed debt that the driver's edit already retired, so the gate finds no debt and never fires. **inert** |
| **P2** | the debt now survives the edit — but the round still runs, writes a new given, and a clean re-roll discharges it. **the wish's defect #1 would remain open** |

⇒ **neither half is the fix. the pair is.** a clean re-roll *must* discharge a debt — that is case=4,
and it is correct. what makes it safe is **when** it happens: under P1, only after an answer already
did. **the key must survive the edit; the gate must precede the re-run.**

### P1 — gate the entrance

`setStoneAsPassed`, **after `:289`** (zero-reviewer auto-pass), **before `stampGuardReport` at
`:299`**. that seam is structural:

- **no guard stamp** — the helper is not yet in scope, so the halt cannot stamp a report for reviews
  that never ran (the `review.self` gate at `:195-255` returns a raw emit for the same reason)
- **no wasted compute** — `computeStoneReviewInputHash` (`:326`), `getMaxStoneGuardIteration` (`:340`)
- **no hash needed** — `getStoneGuardReviewPeerUncontemplatedUnforgiven` takes `{ stone, route }`

**pure reuse:** that operation · `formatRouteGuardReviewPeerContemplatePrompt` case `reply-prompt`
(identical to today's exit-gate tree; snapshot exists) · `genStoneGuardBlockedEmit` with
`refs: { reviews: [], judges: [] }`.

### P2 — key the debt by reviewer, never by (reviewer, hash)

`getRouteGuardReviewPeerContemplationStatus` reads the **latest given per slug** across hashes; a
`.taken` discharges when it matches **that given's** hash.

🔴 **two sites — to miss the second is a deadlock:**

| site | today | under P2 |
|---|---|---|
| given read — `…GivensAtHash:30-35` | every given at `hashCurrent` | latest per slug |
| taken match — `…Uncontemplated:24` | `taken.hash === hashCurrent` | 🔴 **the path the given DERIVES** |

the taken's path is derived, never chosen: `…ContemplationStatus:41` builds it from the **given** path,
and `…PathTaken:33-34` swaps one infix and keeps *"every other segment verbatim"*. so a carried given
at H1 prints a taken path at H1. a matcher keyed to H2 finds no match, and **no prompt in the engine
names an H2 path** — so the gate refuses a file the driver has no way to produce.

⚠️ **this vision proposed `taken.hash === given.hash` for that cell, and it was not enough.** a `.taken`
write does not move the artifact hash, so a reviewer that re-runs and refuses an answer writes its
fresh critique at the **same hash**, one iteration later — and `(slug, hash)` hands that fresh critique
the prior answer. `behavior-intent-coverage` caught it at 5.1 i002. the landed key is the derived path
itself, which carries the iteration. ⇒ the reason the path wins is already stated two lines above: it
is the one grammar source, so every re-derivation of the pair from a coordinate subset is a chance to
pick a subset that is not unique.

🔴 **P2 must SORT.** the zero-pad guarantees a correct comparator, never a sorted input —
`enumFilesFromGlob:13-20` returns raw `globby` output and no caller sorts. without it, "latest" is
**filesystem-dependent**: correct on one machine, wrong on another.

**F7 comes with the swap** — `:31-33` tags `stale` when a taken exists but none matched. once
"matched" means *the latest given's hash*, the tag fires when the reviewer has spoken again.

**four consumers, one change** — all reach it via `…ContemplationStatus`: entrance gate · exit gate
(`setStoneAsPassed:820-872`) · overrule short-circuit (`setStoneAsOverruled:77-83`) · stophook
(`getRouteDriveBlockerMessage:77-82`). so case=10's stophook repair is inherited, not authored.
⚠️ `:10` and `:25` say *"current-iteration"* — stale under P2.

### ⚠️ both gates stay

**entrance** catches debt carried *into* a round; **exit** catches debt created *by* it. remove the
exit gate and a driver passes on the critique it just received.

### exhaustion change kept — the wish asked whether to keep it

today an exhausted reviewer writes no given, so the debt clears with no source. that is the cheapest
of the exits, and it makes the "manufactured exhaustion" `rule.always.converge-to-terminal` calls a
defect cost zero rounds. after the change the driver keeps two — an answer, and a budget top-up; the
human overrule is the third (case=5; deadlock check, case=6).

### prior art — `.dream/2026_06_07.require-driver-response-before-retry.dream.md`

three months older, same goal, and its **#3 is P2**. 🔴 **its #1 is the anti-fix**: *"require artifact
hash change between attempts"* makes an edit the **ticket** to re-entry, and under D2 that same edit
erases the debt it was owed. **mark it delivered and record why #1 was dropped**, or the next reader
re-proposes it.

## .the mental model

**how a driver would say it:** *"you cannot start a new review round while you still owe an answer to
the last one."*

**an analogy, never the mechanism** — the mechanism is flat in `.the contract`. the artifact hash works
like an address:

| | today | under P2 |
|---|---|---|
| the debt is filed | against the **address** | against the **debtor** |
| so it survives | until you move | until you pay it |

⇒ **an edit is a change of address.**

### .their words vs ours

| a driver says | the contract says |
|---|---|
| *"reply to the review"* | `contemplate` (`--as contemplated`) |
| *"the review"* / *"the comment"* | the **given** |
| *"my response"* | the **taken** |
| *"I still owe them one"* | **uncontemplated** |

⛔ **`debt` is prose only** — never an operation, field, flag, or status (F5; resolved dispute in
`term=route.guard.review.contemplate._.choice.reason.md`).

### ⛔ the corrected row — an unreadable verdict GATES

**this vision argued that an undetected verdict scores `blockers: 0`, so a malfunctioned reviewer
could never mint a debt. the argument was wrong, and `mech-failhides` caught it at 5.1.**

a `0/0` scored from a verdict nobody could read is a **fake clean bill** — `contract.reviewer-output`
names it exactly: *"if it finds no numeric count it can NOT assume zero."* so the shipped engine gates
on an unreadable given (`asPeerGivenVerdict`), and the debt is answerable rather than unanswerable —
the driver gets a named `.taken` path like any other reviewer.

⇒ what the row got right is that a malfunctioned reviewer must not **deadlock** the stone. what it got
wrong is the mechanism: safety comes from an answerable halt, never from a silent pass.

### ⛔ the second corrected row — there are TWO discharge paths, never three

**this vision claimed a reviewer could supersede its own blocker with no `.taken`, and counted that
as a third way out. it cannot happen on its own.** caught by the wisher, 2026-09-07, in one question:
*"how could we ever reach this? didnt we block re-entry if the `.taken` is omitted?"*

verified at `setStoneAsPassed.ts:332-337` — the entrance gate is **stone-level and unscoped**, and it
returns before any reviewer runs. ⇒ **while a debt stands, no reviewer speaks.** a reviewer that
cannot run cannot withdraw its own blocker, so a clean re-run is a **consequence** of path 1 or 2,
never an alternative to them.

| | claimed | actual |
|---|---|---|
| discharge paths | 3 | **2** |
| require an actor | 2 of 3 | **both** |
| a path that clears itself | 1 | 🔴 **none** |
