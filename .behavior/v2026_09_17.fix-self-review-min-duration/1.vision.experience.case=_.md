### 🔴 .the D7 row claimed a property the CODE denies — and it is the first time this catalog contradicted the code

**caught by the peer review.** the row read *"a re-promise is **idempotent** and **burns no
attempt**"* — one sentence, two claims, and only the first is true.

| the claim | verdict | why |
|---|---|---|
| the **verdict** is idempotent | ✅ true | the gate reads `firstAdjudication` — an atomic `wx` create the OS grants to exactly one caller. the second promise gets the same answer |
| 🔴 the **count** burns naught | 🔴 **false** | `setSelfReviewTriggeredReport.ts:133` increments `.attempts` on **every** adjudicated promise. a re-promise takes it to 2 |

⇒ **and the correction does not change the cell's verdict, which is the part worth the read.** the

🔴 **the harm is that a doc which states a wrong mechanism is a trap for the next maintainer.** a
reader who took *"burns no attempt"* at face value would key a future gate on `.attempts` — which is
a read-modify-write, so two lanes that promise one slug in the same instant can both read N and both
write N+1. ⇒ **that is the exact hazard the round already repaired once** in
`getSelfReviewChallengeDecision`'s own docblock, and the catalog was still carrying it.

🟡 **the transferable form: a catalog row that states an OUTCOME and a MECHANISM in one sentence can
be half-right and read as wholly right.** the outcome is what a reviewer checks; the mechanism is
what the next author builds on.

### 🔴 .and only TWO of the four barred rows bar CELLS — which is why the count was murky

the four barred rows are not one kind, and to read them as one kind is what produced the row-count

⚠️ **the two grains of `itemized` differ in strength, and the difference is stated rather than
hidden:**

- the **4** carry a per-cell reason and a fulcrum row (`F04`, `F05`, `F08`). a reviewer checks each

- ⇒ so the 22 are itemized at a **coarser grain**, and their check is *"do the invariants hold?"*
