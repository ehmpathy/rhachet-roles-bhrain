# 🌙 dream: every cli error appends a raw json context dump under its human message

- **kind** = fix
- **owner** = `rhachet-roles-bhrain`
- **caught** = 2026-09-10

## .the cue that fired

an `ergo-friction-hazards` peer review read the new concurrency-refusal snapshots and graded the
render a nitpick:

> *"Each refusal snapshot shows the human message followed by an unlabelled, machine-oriented JSON
> dump of the error's `context` (e.g. `{ "undeclared": ["anthropic"], "declared": [] }`). To a driver
> editing a guard, that raw context block is screen noise after an otherwise clear, actionable
> message."*

🔴 **the cue is what the check for it exposed.** the render is not this feature's. it is the
surface **every** command in the repo already writes.

## .the gap, precisely

`BadRequestError` and its siblings carry structured metadata, and the cli boundary prints the error's
full string form — message, blank line, then the metadata pretty-printed as json. so a human who
typo'd one line of a `.guard` gets an actionable sentence and then a machine's copy of it.

**checkable today, on `main`, with no code from this branch involved:**

| snapshot | the dump under the message |
|---|---|
| `driver.route.set.acceptance.test.ts.snap` | `{ "stone": "1.vision" }` |
| `driver.route.set.acceptance.test.ts.snap` | `{ "pattern": ".", "matched": [...] }` |
| `driver.route.stone.add.acceptance.test.ts.snap` | carries the same shape |
| `driver.route.guard-upgrade.acceptance.test.ts.snap` | carries the same shape |
| `driver.route.guard-upgrade.journey.acceptance.test.ts.snap` | carries the same shape |

⇒ **five snapshot files carry the shape, and four of the five are untouched by this branch.** the
concurrency refusals are the fifth, and they inherited it rather than invented it.

⚠️ **and the metadata is not waste** — it is what makes a failure diagnosable from a log. the defect
is its PLACEMENT: a debug artifact rendered onto the surface a human acts on
(`rule.require.errors-name-the-fix` asks the error to name the fix; it does not ask it to also print
its own telemetry).

## .the shape of the fix

one boundary, one branch — the cli error printer, not the error class:

- **the human surface** — the message alone, plus the hint the message already carries
- **the log trail** — the message AND its context, unchanged

⇒ so the two readers are served apart rather than one render served to both. the metadata keeps every
property it has today; it stops to be what a human reads last.

🟡 **it re-baselines five snapshot files**, which is the whole reason it is not done here.

## .why it is not done in this round

the SAFE/CLEAN test, answered honestly:

| question | answer |
|---|---|
| **safe?** | 🔴 **no** — it changes the error render every human sees, on *every* command in the repo, not on the two this feature added |
| **clean?** | 🔴 **no** — it moves at least four snapshot files this diff does not touch, which is the shape `rule.require.review-test-changes` names outright |

⇒ and this feature already carries **one** unasked-for snapshot movement it must hand to the wisher
(the eight rounds-count snapshots, `blocker.1` of `behavior-intent-coverage`). to ride a *second*,
larger, entirely unrelated snapshot movement in beside it would make the first one harder to judge —
the wisher would be asked to accept two changes under one question.

⇒ per `rule.always.fix-forward-under-scouts-honor`, a defer for **dirt** owes a dream **and** a
fulcrum. the fulcrum is
`.behavior/v2026_09_03.feat-peer-review-parallelism/.fulcrums/inventory.of=fulcrums.case=F11-a-refusal-renders-its-own-telemetry.md`.

## 🔴 .an amendment, 2026-09-16 — the deferral was being papered over by a FALSE comment

still deferred, and the SAFE/CLEAN answer above is unchanged. what changed is that the defect had
grown a cover story, and a peer reviewer repeated it.

two test comments asserted that the cli **strips** the dump:

> *"the CLI catch block applies `asHumanMessage` and strips the JSON block"*
> — `setStoneAsContemplated.integration.test.ts`, on two separate cases

**there is no `asHumanMessage` in `route.ts`, on any branch.** every catch prints
`error: ${error.message}`, and `BadRequestError.message` carries the metadata — which is this
dream's own premise, two sections up.

⚠️ **the comment was load-bearing.** three lanes graded the SDK snapshot at i020 (r5, r6, r7), and
one wrote *"(the CLI strips it via asHumanMessage)"* into its own report, then graded the dump a
**nitpick** on the strength of it — *"documented SDK-path behavior rather than a silently-drifted
surface."* ⇒ the severity turned on a claim no test could check.

🔴 **what closed it was an ORACLE, not a re-read.** a cli-grain snapshot of the same refusal —
`routeStoneSetContemplation.acceptance.test.ts` `[case7][t4]` — renders the dump on stderr, and
disproved the comment the moment it was committed. the comments now state what the code does.

⇒ **the lesson this dream carries forward: a deferral is honest only while its record is.** the
defect was correctly deferred on 2026-09-10 and then quietly re-described as absent, and no rule
fired — a comment asserts a downstream behavior and no check grades it. **the repair for that class
is an oracle at the grain the comment speaks about**, which is now in place here.
