memory.guard blocks one act only: a true write into native claude memory. every other call proceeds, even when the guard itself cannot run. closes #653.

## what changed

- **the hook runs the linked skill directly**, anchored on `CLAUDE_PROJECT_DIR`, never via `rhx`: an unlinked `rhx` exits 2, which claude code reads as block
- **the hook seals the skill exits.** it asks for codes 20/21/22 and maps them back; any other end (a syntax fault, an empty or cut skill file) gets the fault line and exit 1
- **a guard that cannot run exits 1**, not 0 (fulcrum F1, ruled): claude code shows stderr only on a non-zero exit, so the one fault line reaches the human. the wish said exit 0; F1 settled exit 1
- **each simple command is graded by where it writes.** `2>&1`, `=>`, `->` stay reads; a cwd fold, a whole-command memory carry, and tee operands keep true memory writes blocked, exit 2
- the payload rides node stdin, never the env, so a payload past 128KB is still judged
- **the block nudge names its act**: a write into memory (header unchanged), a copy beside memory, or an unplaced write beside memory

## for consumer repos

a session runs the hooks it booted with. a repo picks up the new hook command after `npx rhachet init --hooks` and a fresh session; until then its old `rhx memory.guard` line stays.
