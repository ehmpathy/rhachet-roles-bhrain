# case 1 — orders tracked to proof

feel: happy · care: critipath · actor: commander, achiever · seams: talk hook, store, stop hook

## .narrative

the commander types three orders in one message: fix the flaky auth test, bump zod, and do not push.
the talk hook writes the message to the ask inventory before the achiever reads a word. the achiever
sets three goals, one per order. each carries a done check: a shell command whose exit 0 means done.
the constraint goal ("do not push") closes with the work it bounds.

it works auth first. it runs the close, the store runs the check, and the check exits 0, so the goal
closes. zod next: same. at stop, every ask is covered and every goal closed by its check. the stop
hooks say naught. the commander never had to ask "did you get all three?"

## .[tn] — a sketch, not committed flags

```
given  a commander message with three orders
when   [t0] the message is submitted
then     the talk hook appends it to $scope/asks.inventory.jsonl (extant setAsk; $scope = $route/.goals when bound)
when   [t1] rhx goal.memory.set --slug fix-auth-test --how.gate 'npx jest auth.test.ts' --covers $hash   (x3)
then     rhx goal.triage.infer shows uncovered = 0
when   [t2] rhx goal.memory.set --slug fix-auth-test --status.choice fulfilled
then     the store runs how.gate; exit 0 → the goal closes, the check's tail kept as proof
when   [t3] the achiever stops
then     goal.triage.infer --when hook.onStop and goal.triage.next --when hook.onStop exit 0, silent
```
