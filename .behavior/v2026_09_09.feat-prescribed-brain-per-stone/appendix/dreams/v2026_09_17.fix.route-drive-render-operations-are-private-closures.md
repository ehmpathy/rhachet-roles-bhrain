# 🌙 dream: extract the ten `formatRouteDrive*` render operations into leaf transformers

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-17

## .the cue that fired

i033 `r004` (`arch-opport-decomposition`) nitpick.1, verbatim:

> *"Extract `formatRouteDrive*` into one-operation-per-file transformers in `route/drive/` and have
> `stepRouteDrive` import them, so the narrative is purely composition and the render bytes are
> testable where a transformer belongs."*

## .the gap, precisely

`src/domain.operations/route/stepRouteDrive.ts` is 1,100+ lines, and **ten pure render operations are
declared as private `const` closures inside the orchestrator's own body**:

```
formatRouteDrive              formatRouteDriveBlocked
formatRouteDriveMalfunction   formatRouteDriveExhausted
formatRouteDriveMalfunctionEscalate
formatRouteDriveEscalate      formatRouteDriveBlockReason
formatRouteDriveNudge         formatRouteDriveComplete
formatRouteDriveUnbound
```

each is a **transformer** by `define.domain-operation-grains` — pure, deterministic, no I/O, its whole
job a string. so each owes its own file and its own unit test, and none has either.

⇒ **the evidence that this grain is right sits in the same directory.** `drive/formatRouteDriveMixedHalt.ts`
is already a named file with a named test, and it is one of eleven peers. ⇒ the convention exists, and
these ten sit outside it.

## .what it costs today

| cost | how it lands |
|---|---|
| **untestable at leaf grain** | a closure has no import path, so its bytes are provable only through a full `stepRouteDrive` integration run |
| **unrecomposable** | no other surface can render a drive body without a re-derive |
| **the orchestrator does not read as narrative** | `rule.require.orchestrators-as-narrative` — a reader who follows the halt branch lands in 40 lines of string assembly |

## .the shape of the fix

one file per operation, under `src/domain.operations/route/drive/`, each with a `.test.ts` beside it:

```
drive/formatRouteDrive.ts                        + .test.ts
drive/formatRouteDriveBlocked.ts                 + .test.ts
drive/formatRouteDriveMalfunction.ts             + .test.ts
drive/formatRouteDriveExhausted.ts               + .test.ts
drive/formatRouteDriveMalfunctionEscalate.ts     + .test.ts
drive/formatRouteDriveEscalate.ts                + .test.ts
drive/formatRouteDriveBlockReason.ts             + .test.ts
drive/formatRouteDriveNudge.ts                   + .test.ts
drive/formatRouteDriveComplete.ts                + .test.ts
drive/formatRouteDriveUnbound.ts                 + .test.ts
```

then `stepRouteDrive` imports the ten, and its body becomes composition alone.

🟡 **a closure that reads a variable from the orchestrator's scope needs that variable as an input.**
walk each one and lift the free variables into its `input:` object before the move — a mechanical
edit, and the one place the extraction can go subtly wrong.

⇒ **the mechanical check that the extraction was faithful: the drive snapshots.** every byte these ten
emit is pinned by `__snapshots__/stepRouteDrive.integration.test.ts.snap`, so a faithful move is a
**zero-diff** snapshot run. a diff is the defect, and it names itself.

## .why it is not done in this round

the two questions of `rule.always.fix-forward-under-scouts-honor`:

| | answer |
|---|---|
| **is it SAFE?** | ⚠️ **partly.** the ops are pure, and each lift of a free variable is a place to change behavior by accident. the snapshots catch it, so the risk is bounded rather than absent |
| **is it CLEAN?** | 🔴 **no.** 20 new files, a 1,100-line orchestrator restructured, and **not one line of it is this feature's diff** — every one of the ten predates `brain:` |

⇒ **it fails CLEAN outright, and that half decides it.** this round's subject is a per-stone brain;
a render-surface decomposition that touches every drive output in the repo is a different change that
would ride in under this one's name — the *smuggled refactor* `rule.always.fix-forward-under-scouts-honor`
names as a **blocker**.

🟡 **and the reviewer graded it a nitpick for this reason.** it wrote *"This PR goes most of the way"*
and named the three extractions this round DID make (`applyStoneBrain`, `composeStoneBrainRender`,
`asRouteDispositions`). ⇒ the ask is aimed at the **neighbours** of this diff, never at its content.
