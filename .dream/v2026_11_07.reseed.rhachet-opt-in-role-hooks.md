# 🌙 dream: rhachet owes a native opt-in hook, so a role need not thread an author past three read rules

- kind = reseed
- owner = ehmpathy/rhachet
- caught 2026-11-07, on `.behavior/v2026_11_07.feat-toggle-term-learner-hook`

## .the cue that fired

the vision for `learn.terms.hook` wrote the line *"a rhachet-native opt-in hook would be cleaner"*.

## .the gap, precisely

a role can declare a hook (always on, in every repo that links it) or not at all. it cannot
declare a hook that a repo opts into. to toggle one per repo, the learner writes a Stop entry by
hand under `toggle=learn.terms.hook/role=learner`. that author is picked to thread three rhachet
1.51 read rules, none declared as a contract:

- `syncOneRoleHooksIntoOneBrainRepl` deletes undeclared entries under exactly `repo=X/role=Y`
- `pruneOrphanedRoleHooksFromOneBrain` deletes `^repo=.+/role=.+$` authors no linked role holds
- `getSettingsForRoles` keeps a hook for a peer actor only if its `role=` segment is held

a change to any one rule silently breaks the toggle.

## .the shape of the fix

a role declares `hooks.onBrain.onStop: [{ command, timeout, optin: 'learn.terms.hook' }]`. rhachet
syncs it only where the repo has opted in (a key in `.agent/` or the repo settings), under the
role's normal author, and offers `rhx roles hooks optin get|set|del` (or the role's own skill
calls a rhachet sdk). the per-role sync, prune, and narrow then treat it as any declared hook.

## .why it is not done in this round

it is another repo's contract, and the wish's nano bound keeps this round to the toggle. the
learner's toggle can migrate to the native form once it ships.
