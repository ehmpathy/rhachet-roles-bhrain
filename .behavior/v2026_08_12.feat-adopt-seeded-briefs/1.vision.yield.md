# 1.vision — every brief a seed asked for is present in the role that needs it

## .what this vision settles

the wish asks for one outcome: **the arrears are paid.** every open seed that asks for a brief on
an extant role has that brief in the repo, claimed, and closed.

the wish also says the enumeration is mine, and it is the artifact the next round trusts. so this
vision leads with the enumeration and the criterion that produced it, then paints what the world
looks like once it lands.

---

## the criterion

> **a seed is in scope iff writing markdown alone fully satisfies its acceptance.**

markdown alone means: brief files under `src/domain.roles/<role>/briefs/` or
`.agent/repo=.this/role=any/briefs/`, plus the `boot.yml` lines that load them, plus the symlinks
that cross-list one brief into a second home.

the test, applied to the **body**, never the title:

| ask | verdict |
|---|---|
| write only markdown and the seed is done | **BRIEF** — in scope |
| markdown is a separable half; the rest needs a skill/hook/route/sdk | **MIXED** — brief half in scope, seed stays open |
| needs a skill, hook, cron, guard, sdk export, CLI flag, or bugfix | **CODE** — out |
| names a role with no `boot.yml` here | **ROLE** — out |

the two filters the wish records as failures are failures for the same reason: they read the
**form** of the seed (its title prefix, its keyword vocabulary) instead of its **deliverable**.
"what artifact closes this?" is the only question that separates *asks for a brief* from *mentions
a brief*, and it can only be answered against the body.

### the two boundary calls this criterion forces

**an eject is a brief ask.** seeds 370 and 369 ask to bring a driver rule here from
`ehmpathy/rhachet`. the deliverable in *this* repo is a markdown file in an extant role — in
scope. the follow-on removal from rhachet is another repo's work, and closing here must not retire
it.

**a mixed seed gets its brief and stays open.** a partial delivery that closes a seed retires the
unanswered half. the wish is explicit: *"a wrongly closed seed is worse than an unclosed one."* so
the brief lands, the seed keeps its question, and a comment names both what shipped and what
remains.

## the outcome world

### before

a clone boots the learner role. it carries 9 briefs, 6,232 tokens. it does not know that a lesson
must be timeless, so it writes `we decided not to...` into a brief that will read as an orphan in
a month. it does not know to check whether a rule already exists before it invents one, so it
writes a fourth near-synonym of a rule three roles already carry. nothing catches either. the
lesson that would have caught them is issue #321 and issue #373, sitting in a queue, unread.

meanwhile the queue is the only place those lessons live. **41 open, 0 claimed.** each seed is a
lesson someone paid for once, and every clone that boots since has paid for it again.

### after

that same clone boots the learner and carries the timeless rule and the reuse rule in context
before it writes its first line. it does not produce the session-bound brief, because the rule
that forbids it fires unprompted. it does not invent the fourth synonym, because the rule that
says *read the pavement first* fires unprompted.

the queue reads **26 open, 15 closed** — and each of the 15 closes names the file that satisfies
it, so a reader traces every one to an artifact.

### the aha

**the aha is not any single brief. it is the moment the queue stops being a graveyard.**

the value clicks when someone opens the queue after this lands and sees a close that reads
*"satisfied by `src/domain.roles/learner/briefs/rule.require.timeless-lessons.md`"* — and realizes
the lesson is now in the boot context of every learner that will ever run, instead of in an issue
body that nobody boots.

a code defect bites the next caller once, loudly. an absent brief bites every clone forever,
silently, and each victim re-derives it at full price. **this behavior converts 15 silent
forever-costs into 12 files.**

## user experience

### who the users are

| user | goal |
|---|---|
| **the clone that boots a role** | carry the lesson before it needs it, not after it pays for it |
| **the human reading the queue** | see what is delivered and what is still owed, without opening 41 bodies |
| **the next round's driver** | inherit a settled criterion instead of re-deriving one from two failed filters |

### the contract they leverage

the clone's contract is `boot.yml`. it is a two-tier declaration:

```yaml
always:
  briefs:
    ref:   # surfaced on demand — path only, body loaded when asked
      - briefs/im_a.bhrain_owl.md
    say:   # always in context — body inlined at every boot
      - briefs/rule.always.drive-autonomously.md
```

the tier is the whole contract. `say` costs tokens at every boot and fires unprompted. `ref` costs
one path and fires only when reached for. **a rule that must fire before the mistake belongs in
`say`; a philosophy that explains why belongs in `ref`.**

the human's contract is the radio:

```sh
# claim, at the moment of choice
rhx radio.task.push --via gh.issues --into @this --exid 321 --status CLAIMED

# close, naming the artifact
rhx radio.task.push --via gh.issues --into @this --exid 321 --status DELIVERED
```

### the timeline

```
enumerate ──► claim ──► verify ──► write ──► wire ──► build ──► prove ──► close
                          │                   │         │         │
                          │                boot.yml   npm run   boot output
                          │                  tier      build    shows the brief
                          │
                          └─ if already satisfied: close against the extant line, write nothing
```

three steps carry their weight for a specific reason:

- **`verify`** sits between claim and write. seed 300 is why — it is already satisfied, and a
  driver who skipped this step would write a file to fix nothing.
- **`build`** is not optional. boot reads `dist/`, and `dist/` is refreshed only by
  `npm run build`. skip it and a correct brief loads for nobody.
- **`prove`** is the acceptance test: the brief's own text appears in boot output under its role.
  **a close is earned by that, not by the file's existence.** for `driver` and `achiever`,
  `rhx git.repo.test --what unit` already proves the wiring half automatically; for `learner`,
  `librarian`, and `reviewer` there is no such test, so `prove` is the only guard those three have.

`build` and `prove` run **once for the batch**, not once per brief. an earlier draft of this vision
put them in the per-seed loop, which would have meant twelve builds and twelve boot inspections to
learn one fact each. one build after the last write, then one boot that shows all twelve, proves
exactly as much for a twelfth of the cost. **A3** keeps a single early end-to-end run so the
mechanism is exercised before the batch depends on it.

### what leverage looks like, concretely

a learner boots. `rule.require.timeless-lessons.md` is in its `say` tier. it starts to write
*"we deliberately do not declare a purpose enum here — the moment we would, it collapses back to
the muddle we discussed."* the rule's own test — *strip every temporal word; does it still stand?*
— fires. it rewrites to *"purpose is derived, never stamped: a stamped purpose enum re-couples a
flow-word to a perspective."* the lesson survives the session that produced it.

no hook ran. no reviewer blocked. the brief was simply present.

### ⚠️ and that last line is the vision's weakest claim — by this repo's own evidence

`.agent/repo=.this/role=any/briefs/research.selfreview-effectiveness.md` grades interventions:

| technique | effect size | evidence |
|---|---|---|
| implementation intentions (when-then cues) | **d = 0.65** | strong |
| forced articulation | **d = 0.55** | strong |
| identity / role adoption | moderate | supported |
| **a mindset message or a philosophical frame, alone** | **d = 0.05** | weak |

its own summary line ranks a behavioral scaffold above a philosophical frame, and notes the frame
has *"very small effects when not paired with"* that scaffold.

**a brief that is merely present is a message.** the scaffold — the hooks, the nudges, the guards —
is what the wish's scope explicitly excludes (seeds 341, 342, 358, 367, 287, 364). and seed 372
states the counterexample from the field directly: *"the rule was read and still lost, and
therefore the accompanying mechanism is not optional."*

two independent sources — one of them a seed in the very queue this behavior drains — say the same
thing: **a brief alone is a weak intervention.**

### what follows — it changes what to write, not whether to write

this does **not** argue against the wish. an unwritten brief has an effect size of exactly zero,
and these briefs are the prerequisite the enforcement seeds build on. but it reshapes two claims:

**1. the honest promise.** this behavior delivers artifacts that are **necessary and not
sufficient**. the arrears are paid; the effect lands when the scaffold seeds do. a vision that
claims behavior change from presence alone claims d = 0.05.

**2. the shape of every brief written here.** the research is prescriptive, and the delta is 13x:

- ✅ write rules as **when-then implementation intentions** — *"when you distill a lesson, strip
  every temporal word and re-read"* (d = 0.65)
- ✅ write them to **force articulation** — a test the reader must answer, not a principle they
  must admire (d = 0.55)
- ⚠️ write philosophy **sparingly, as support** — never as the primary artifact (d = 0.05)

seed 374 asks for a `philosophy.*` brief by name. that request stands — the *why* is what lets a
reader judge edge cases the rule does not enumerate — but it belongs **beside** the d=0.65 rule of
seed 373, never in place of it. the vision's cluster (374 + 373) already has that shape; the
research explains why it is the right one.

## mental model

### how a user describes it to a friend

> "we had a backlog of lessons nobody had written down. we wrote them down, into the exact role
> that needs them, so they load automatically."

### the metaphor that fits: **arrears, not features**

this is not a feature backlog. a feature deferred costs an opportunity. **a lesson deferred costs
the same tuition, over and over, to every student who follows.** the queue is not a wishlist — it
is an unpaid bill, and it compounds.

### the metaphor the seeds themselves supply: **pavement**

seeds 374/373/352 name it, and it is the right one for the whole behavior:

- someone walks a hard route and wears a path
- **pavement** is that path made permanent, so the next traveler spends no energy finding it
- an unwritten brief is a path someone wore and nobody paved — it grows over, and the next
  traveler bushwhacks the same line

this behavior is **paving 15 worn paths**. that the seeds asking for a pavement vocabulary are
themselves unpaved is the joke that makes the point.

### their terms vs ours

| they say | we say | why ours |
|---|---|---|
| "write it down" | **externalize** | `rule.always.externalize.lessons.into_briefs` |
| "add it to the prompt" | **boot at say-level** | the tier is the contract, not the prose |
| "issue", "ticket" | **seed** | the radio's own word |
| "backlog" | **arrears** | a backlog is optional; arrears accrue |
| "document it" | **pave** | pending — seed 352 settles it |

### the vocabulary hazard, named

`pave` and `learn` are adjacent, and the glossary already declares `learn`:

> `term=learn` — *"to durably retain a lesson so it is never re-derived"*, forbidding `study`,
> `train`, `memorize`
> (`.agent/repo=.this/role=any/briefs/domain.terms/term=learn._.choice._.md`)

`pave` is **not** listed among its forbidden synonyms, which is the correct starting posture but
not a settled one. the distinction that must hold in the `.reason` file, or `pave` is a synonym
wearing a new coat:

- **learn** = the *retention* — a lesson is held so it is not re-derived
- **pave** = the *provision* — a reusable path is laid so a **future traveler** need not derive it

if that line does not survive scrutiny, `pave` is a forbidden synonym of `learn` and seed 352
closes by recording the dispute, not by paving the term. either outcome is a legitimate close; the
`.reason` file is what makes it auditable.

## evaluation

### how well it serves the goals

| goal | served | how |
|---|---|---|
| the lesson reaches the clone that needs it | **fully** | boot.yml wiring is the delivery, not the file |
| the queue drops by what was delivered | **deferred** | the radio is read-only (Q6), so no seed closes this round. each brief still cites the seed it satisfies, so the close is a later sweep, not a later re-derivation |
| the next round inherits a criterion | **fully** | the criterion above, with its two boundary calls |
| the *whole* queue is retired | **no** | 23 seeds are code or absent roles, by design |

**on the deferred row — it is a deferral of *transmission*, not of work.** the artifact that
closes a seed is the brief, and the brief lands this round. what waits is the push that announces
it. the wish's own hierarchy blesses this order: *"a wrongly closed seed is worse than an unclosed
one"* — an unpushed close leaves every seed exactly where it stands, open and honest, while a
forced close would assert a delivery no one can yet verify against the queue.

### pros

- **highest leverage per token in the repo** — a `say`-level brief runs in every future boot of
  that role, forever, for one write
- **the criterion is reusable** — "does markdown alone close it?" survives this round and grades
  the next 41
- **the clusters make it cheaper than it looks** — 15 seeds collapse to ~12 artifacts, 3 of which
  are edits
- **verify-before-write pays immediately** — seed 300 closes for free

### cons

- **`say` is not free.** the learner boots 9 briefs for 6,232 tokens — ~690 tokens each. eight new
  learner briefs at `say` would add ~5,500 tokens to **every** learner boot. the arrears are real
  and so is the interest on paying them badly.
- **the learner `boot.yml` has no `ref:` tier at all.** every learner brief is `say` today. that
  was tenable at 9 briefs and is not at 17.
- **no close lands this round.** the radio is read-only, so all 41 seeds stay exactly as they were.
  the artifacts are real and the queue does not show it — the trail exists in-repo, and its
  transmission waits on a lifted blocker. honest, and less legible than a drained queue.
- **it fixes the arrears, not the accrual.** the seeds that would stop the next 41 from piling up
  are the hooks and nudges (341, 342, 358, 367) — all out of scope.
- **🔴 a brief alone is a weak intervention — d ≈ 0.05.** by this repo's own cited research, and by
  seed 372's field evidence, presence-in-context without a behavioral scaffold barely moves
  behavior. this is the honest ceiling on what this behavior can deliver, and the scope bound puts
  the strong half (the hooks) out of reach. it is mitigated, not removed, by writing each rule as a
  when-then cue (d = 0.65) rather than as a principle.

### edge cases, and the pit of success

| edge case | how the contract catches it |
|---|---|
| **a seed already satisfied** | verify precedes write. seed 300 closes against `boot.yml:14`, zero files |
| **a brief written into an unbooted role** | the wish's five-role table binds; `architect/` and `thinker/` carry 200+ briefs and **no `boot.yml`** — living proof of the failure mode |
| **a brief written and never wired** | boot.yml wiring is in scope by name; a file not in a tier is a file nobody loads |
| **a brief wired but never built** | boot reads `dist/`, refreshed only by `npm run build`. the `prove` step catches it: the brief must appear in boot output, not merely on disk |
| **a new synonym smuggled in** | `rule.forbid.domain-term-synonyms` — adhere or dispute in `.reason`, never drift |
| **a session-bound brief** | seed 321 is both an item in scope and the standard every file here must meet |
| **a partial delivery closing a seed** | mixed seeds stay open; the close names what shipped and what remains |
| **a duplicate brief** | seed 359's own lesson — extend the extant cluster, do not accrete a peer file |

the pit of success here is structural: **the failure modes are themselves items in scope.** 321
forbids the session-bound brief. 359 forbids the duplicate. 373 forbids the un-checked
reinvention. this behavior is graded by the rules it delivers.

## groundwork

### external research

**none — no external dependencies.** every referenced artifact is in this repo or in the github
issue queue of this repo. the two ejects (370, 369) name `ehmpathy/rhachet` as a *source*, and the
brief text they ask for is stated in the seed bodies; no rhachet API or contract is depended upon.

### internal research

verified against the working tree of `beav/feat-adopt-seeded-briefs` on 2026-08-12.

**roles that exist — the wish's table confirmed.** exactly five `boot.yml` files:
`src/domain.roles/{achiever,driver,learner,librarian,reviewer}/boot.yml`.

**roles that do not.** `src/domain.roles/architect/` and `src/domain.roles/thinker/` carry briefs
(1 and 353 tracked files respectively, per `git ls-files`) and **no `boot.yml`**. no `navigator/`,
`router/`, `reflector/`, or `researcher/` directory exists at all. this is the wish's exclusion,
verified as fact — and 353 unloadable files is the failure mode at scale.

**the boot.yml contract.** `src/domain.roles/driver/boot.yml` — `always.briefs.{ref,say}` and
`always.skills.say`. `ref` and `say` are the only tiers.

**the learner has no `ref` tier.** `src/domain.roles/learner/boot.yml:1-21` declares
`always.briefs.say` only — 9 entries, no `ref:` key. adding a `ref` tier is `boot.yml` wiring, in
scope.

**boot cost, measured this session.** driver 12 briefs → 6,910 tokens; learner 9 briefs → 6,232;
librarian 16 → 4,212; reviewer 13 → 3,755; `repo=.this/role=any` 58 → 3,898.

**seed 300 is stale.** `git show e30ef94 -- src/domain.roles/driver/boot.yml` shows
`briefs/howto.drive-routes.[guide].md` added under a newly created `say:` key in PR #203
(2026-03-20). it is at `boot.yml:14` today. issue #300 postdates PR #203.

**a brief reaches boot through `dist/`, not `src/`.** this is the single most load-bearing fact in
this groundwork, and it inverts the obvious assumption:

```
src/domain.roles/<role>/briefs/*.md          # what you edit; what git tracks
      │
      │  npm run build   →  build:complete:dist   (package.json:49)
      │  rsync -a --include='briefs/**' --include='**/boot.yml' src/ dist/
      ▼
dist/domain.roles/<role>/briefs/*.md         # gitignored (.gitignore:17)
      ▲
      │  symlink
.agent/repo=bhrain/role=<role>/briefs        # what boot reads
```

verified: `file '.agent/repo=bhrain/role=driver/briefs'` →
`symbolic link to ../../../dist/domain.roles/driver/briefs`; same shape for
`role=learner/briefs` and `role=driver/skills`. `git check-ignore -v dist` → `.gitignore:17`.
`git ls-files -s '.agent/repo=bhrain'` returns nothing, and `git check-ignore` on a path beneath it
errors *"beyond a symbolic link."*

**the consequence: a brief written to `src/` does not load until `npm run build` runs.** a
correctly authored, correctly wired brief is invisible to every clone until the build refreshes
`dist/`. `build:clean:tsc` (`package.json:45`) does `rm -rf dist/`, so the `.agent/` symlinks
dangle mid-build and are whole again after.

**there are TWO delivery paths, and only one needs the build.**

| home | tracked? | build needed? | who it serves |
|---|---|---|---|
| `src/domain.roles/<role>/briefs/` | yes, in `src/` | **yes** — via `dist/` | the five published roles; ships to consumers |
| `.agent/repo=.this/role=any/briefs/` | yes, mode `100644` **in `.agent/` itself** | **no** — boot reads it directly | this repo only; every role that boots here |

verified: `git ls-files -s '.agent/repo=.this/role=any/boot.yml'` and
`.../briefs/define.bhrain-repo-mascot.md` both return `100644` — real tracked files, not symlinks
into `dist/`. **a `role=any` brief lands and loads with no build at all.** the `build → prove`
step in the timeline binds the five roles; for `role=any` only `prove` applies.

**an extant test already enforces wired-ness — for two roles of five.**
`src/domain.roles/driver/getDriverRole.test.ts:8-56` asserts a bidirectional invariant:

- every `.md` in `briefs/` **must** be declared in `boot.yml` (say or ref)
- every brief declared in `boot.yml` **must** exist in `briefs/`

so **a driver brief written without a `boot.yml` line fails `rhx git.repo.test --what unit`.** the
same test exists for `achiever`. it does **not** exist for `learner`, `librarian`, or `reviewer` —
a `Grep` for `boot\.yml` across `**/*.test.ts` returns only those two role tests plus the
domain.terms integration test. **the guard against an unwired brief is uneven**, and the three
roles without it are where most of this behavior's briefs land.

two properties of that test matter here:

- it filters `f.endsWith('.md')`, so a `.md.min` sidecar is **excluded** — condense (F8) cannot
  break it
- it uses a non-recursive `readdir`, so a brief in a **nested** subdirectory escapes the check
  entirely (as `reviewer/briefs/lessons/` already does)

**`ref:` accepts globs — but only where they are declared.**
`.agent/repo=.this/role=any/boot.yml:39-41` declares:

```yaml
    ref:
      - briefs/domain.terms/term=*._.choice._.md
      - briefs/domain.terms/term=*._.choice.reason.md
      - briefs/domain.terms/term=*._.choice.example=*.md
```

**consequence for seed 352: paving `term=pave` requires zero `boot.yml` edits.** the files drop
into `domain.terms/` and the extant glob loads them. one less thing to wire, and one less thing to
forget.

**do not over-read this.** `domainTermsBootReachability.integration.test.ts:107-111` states these
are *"the only glob entries in any boot.yml in the repo."* the glob convenience is **specific to
`domain.terms/`** — every other new brief still needs its own explicit line. and
