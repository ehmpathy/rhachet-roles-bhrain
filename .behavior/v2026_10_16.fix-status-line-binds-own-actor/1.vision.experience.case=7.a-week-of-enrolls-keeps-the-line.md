# case=7 · a week of enrolls, upgrades, and a peer — the line holds throughout

coordinates: L=split · I=human → peer-actor · T=absent-key → ours-current · E=enroll, init --hooks, layout-findsert · feel=happy · care=critipath

🟡 **the densest walk in this catalog** — it crosses the layout seam, the derivation seam (twice,
for two actors), the findsert boundary, the no-op boundary, and the peer-config-dir note, in the
order a real repo meets them. it is the walk the wish's symptom came from, so it is the one most
likely to expose a defect.

## .narrative

monday: the human runs `rhx init --roles driver --hooks`. the init writes the repo actor's
`settings.of.repo.json`; the sweep carries it to each enrolled actor. they enroll a driver clone
(`hash=7dcf1989`); its foot reads `🗿 1.vision`.

wednesday: rhachet upgrades. `rhx init --hooks` re-lays the brain dirs and re-derives every actor.
the driver re-enrolls. the line is still there — where, before the fix, this is the day it vanished.

friday: the driver clone (`hash=7dcf1989`) re-runs the init by hand to be sure. it reports
`already configured`, names its own config dir, and writes no backup. a new reviewer actor is enrolled; on
an unbound branch its foot is blank, on this branch it shows the stone.

## .what is tested

`[t2]` and the derivation of `[t1]` and `[t4]` run through `rhachet init --hooks`, the sweep that
re-derives every actor. a real enroll spawns a claude session, so no test runs one; the enroll path
is read from rhachet's `dist`, and the sweep is the same derivation.
