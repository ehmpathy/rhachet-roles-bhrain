# 5.1.execution — RouteReminder

execute the vision at `.behavior/v2026_08_07.driver-cron/1.vision.yield.md`.

built the RouteReminder end to end: its **own deterministic behavior** (tick, inject, self-exit,
lifecycle), the shell surface (`route.reminder.{gen,get,del,daemon}`), the detached spawn host,
AND — per the wisher's reversal of Q9 — the **auto-wire**: `route.drive` findserts the reminder on
every drive while the route is live and reaps it when dead, so no human runs a manual command.
only the OS-level detached SPAWN stays an injected, substitutable boundary.

## flagged for the end-of-road council (fulcrums best-guessed, per rule.always.defer-fulcrums)

1. **build fork: self-contained daemon vs port-only** — chose self-contained. the daemon's own
   behavior is fully built + tested; the process **spawn** is an injected `spawnDaemon` seam
   (genRouteReminder's context). the real spawner — an actual detached process host — is the
   enroller tool's concern (vision Q9, out of scope). this is the ONE integration point rhachet
   must wire; a clean rework if the wisher wants it stubbed behind the `RouteReminderScheduler`
   port instead. no caller ripples.

2. **the active-drive predicate (vision Q4 edge)** — best-guessed: nudge THROUGH a machine-run
   review (arrived / promised / contemplated stay live), exit only on the four hard states
   (blocked / rewound / exhausted / malfunction). this keeps the nudge during a peer-review
   wait, per U1's day-in-the-life. the wisher's Q3 note ("in-review → absent") is the tighter
   reading; if that is the intent, move arrived/promised/contemplated into
   `REMINDER_ABSENT_STATUSES` — a one-line, one-array change.

3. **route completion is not a status rule** — a terminal `passed` stays live; the daemon's
   dead-session self-exit (clone say fails reach) catches a gone session when the route ends. so
   no "completed" detection is needed. flagged in case the wisher wants an explicit
   completed-exit before the session dies.

4. **Q10 pid-file scope** — RESOLVED this convergence round (r8.1). the handle is now per-session,
   keyed by route AND cloneAddr (`daemon.of=reminder-driveon.session=<addr>.pid`), so two sessions
   on one route never collide. delivers the wish's explicit "per session scope is desired".

5. **payload text is a must-validate lever (U1)** — the prose default lives in one constant. if
   the nudge fails to reliably re-drive an idle session, swap the payload for a deterministic
   `rhx route.drive` command. the constant makes this a one-file change.

instead of a silent re-spawn (rule.forbid.behavior-hazards). the settle costs latency ONCE per fresh
spawn (the findsert returns a live handle on later drives, no re-verify). `isProcessAlive` stays
IMPORTED, not injected (rule.forbid.inject-same-repo-domain-ops) — so the clamp drives a REAL
short-lived child, never a mocked probe.

boot (node + import) alone outlasts 250ms, so a daemon that boots then self-exits (session-dead on a
dead route) reads alive:true at the settle and exits later — only a child that dies BEFORE completing
its boot (a true crash-on-arrival) reads survived:false. the blackbox acceptance (33) confirms this
empirically — the real-daemon cases still report "spawned and live", not "crashed on arrival".
