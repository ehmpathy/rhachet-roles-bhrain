# 🌙 dream: `git.repo.test` reports a count and never the scope that produced it

- **kind** = `reseed` — the skill lives in `ehmpathy/rhachet-roles-ehmpathy`, never in this repo
- **owner** = whoever holds `role=mechanic/skills/git.repo.test`
- **caught** = 2026-09-12, on `.behavior/v2026_09_03.feat-peer-review-parallelism` stone
  `5.1.execution.from_vision`

## .the cue that fired

i re-ran the whole unit suite after the i003 repairs and measured **1681 passed, 187 files**.

my own yield, four sections above, recorded **599 passed, 47 files** and labelled that row
`unit — full`.

⇒ both numbers are correct. **the label is not.** `--what unit` bounds itself to the changed set,
and the whole suite is the sharded cicd gate rather than a local run
(`rule.forbid.thorough-test-runs`). so the earlier row claimed four times the coverage it had, and
i wrote it myself, in a section whose entire purpose is to state what was verified.

## .the gap, precisely

the skill's own stats block is what a driver copies into a yield:

```
   ├─ stats
   │  ├─ suites: 187 files
   │  ├─ tests: 1681 passed, 0 failed, 0 skipped
   │  └─ time: 32s
```

🔴 **three rows, and not one of them says WHICH files.** the block is byte-identical in shape
whether the run reached 47 files or 187, so the scope is recoverable only from the invocation — and
an invocation is not what survives into the record.

### it is checkable, and it was checked

| what was counted | files | the label i wrote |
|---|---|---|
| `--what unit --mode apply` | 47 | 🔴 `unit — full` |
| every unit suite on disk, by an un-filtered `--listTests` | **187** | `unit — whole suite` |
| `--what integration --mode apply` | 34 | 🔴 `integration — full` |
| `*.integration.test.ts` under `src/`, measured | **128** | — |

⇒ **two rows of a six-row verification table carried a false scope claim**, and both survived every
prior self-review, because the number beside each was true.

## 🔴 .why it is worse than a wrong number

a wrong count is loud — a reviewer re-runs and the two disagree.

**a right count under a wrong scope is silent.** it re-runs identically forever, so no re-measure
finds it. the only instrument that catches it is a count of the suites on **disk**, which nobody has
a reason to take until a round happens to compare the two numbers.

⚠️ **and it converts a bound into a promise.** *"47 files green"* bounds what was checked.
*"unit — full, green"* promises what was not.

## .the shape of the fix

one row in the stats block, derived from the flags the skill already parsed:

```
   ├─ stats
   │  ├─ scope: changed-set (47 of 187 suites) — the whole suite is the cicd gate
   │  ├─ suites: 47 files
   │  └─ tests: 599 passed, 0 failed, 0 skipped
```

three properties, and the third is the one that closes the class:

- it names the **scope kind** — `changed-set` against `whole-suite`
- it names the **denominator**, so `47 of 187` cannot be copied as `full`
- 🔴 **it names where the remainder IS checked** — a driver who reads that the gate is the push
  cannot believe a local run already stood in for it

⚠️ 🔴 **the row must NOT name `--thorough`, and an earlier draft of this dream did.**
`rule.forbid.thorough-test-runs` forbids the flag in any invocation **and** forbids any artifact
that keeps it legible as a normal option — *"the recommendation is the mechanism by which the flag
survives."* a row printed on **every** run is the widest such surface there is, so the remedy it
names must be the push.

⇒ the numerator is in hand today; the denominator is one un-filtered `--listTests`.

## .why it is not done in this round

**CLEAN = no.** the skill is published by `ehmpathy/rhachet-roles-ehmpathy` and consumed here as a
dependency, so the repair cannot land in this diff at all — a tree adopts only what is scoped to
itself.

**SAFE = also no**, for a second reason: the stats block is snapshotted by that repo's own
acceptance suite, so a new row re-baselines tests this repo cannot see.

🟡 **no fulcrum is owed.** a fulcrum records a judgment a council could overrule, and there is no
judgment here — the work is out of this tree's bounds by ownership, which is a fact rather than a
call (`rule.always.catch-dreams-for-followups`).

⇒ **what this round DID do is the in-scope half**: both mislabelled rows are corrected in the yield,
each with the measured denominator beside it, so the artifact no longer carries the false claim.
