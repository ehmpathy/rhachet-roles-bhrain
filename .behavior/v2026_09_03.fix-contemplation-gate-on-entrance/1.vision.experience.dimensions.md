# 1.vision.experience.dimensions

the experience space of the peer-review contemplation gate, factored into orthogonal axes and
walked as a product. the cells are verdicted in `1.vision.experience.case=_.md`.

## .the axes

### A — the move (7)

the act performed at the gate. **the actor is implied by the move**, because actor and move do not
vary independently here — a `--as contemplated` is a driver act, an `--as overruled` a human act.
two correlated axes are one axis (`howto.experience.decompose`), so they are merged.

| value | actor | what |
|---|---|---|
| `enter-review` | driver | `--as passed` / `--as arrived` — asks for a peer-review round |
| `answer` | driver | `--as contemplated --that <slug>` — records a response |
| `edit-code` | driver | edits an artifact under review, which moves the stone's review hash |
| `stop` | driver | ends the session; the stophook consults the stone |
| `overrule` | human | `--as overruled --level N` — waves a rung through |
| `observe` | human | reads the stone's state to judge whether it progresses |
| `reviewer-runs` | system | a peer-review subprocess executes and reads `$conversation` |

#### 🔴 the value set aside — `halt` (`--as blocked`), and why it is NOT an eighth

`rule.forbid.unanswered-exits-from-a-blocker` enumerates `--as blocked` as one of the exits a
driver can take from a blocker, so a reader who knows that rule will look for it here. **it is
deliberately absent, and the reason is measured rather than assumed.**

⇒ `setStoneAsBlocked` **never consults the contemplation machinery.** the only two operations that
do are `setStoneAsPassed` (`:333` entrance, `:899` exit) and `setStoneAsContemplated` (`:52`) —
verified by a grep of `src/domain.operations/route/stones` for
`Uncontemplated|ContemplationStatus`, which returns those two files and no third.

so a `halt` slab would be **16 cells, uniformly permitted, with no interaction at all** — a void
slab, of the same kind as the `reviewer-runs × exhausted` void column recorded below. it would grow
the product from 112 to 128 and add not one falsifiable claim.

⚠️ **that absence is a real property of the system, not an oversight, and it carries weight:** the
engine cannot tell a legitimate halt (a point answered and unclosable —
`rule.always.raise-a-blocker-a-taken-cannot-close`) from a forbidden one (a point never answered).
**only the driver knows which it is**, which is exactly why that row of the forbid rule is graded
`⛔ open` rather than `✅ refused`.

⇒ **a value that adds a void slab is recorded here, never walked.** if a future round makes
`--as blocked` consult the gate, this note is the trigger to add the eighth value and re-walk.

### B — the contemplation state (4)

the state of the peer conversation for the stone, before the move.

| value | what |
|---|---|
| `none` | no peer given carries blockers |
| `fresh-unanswered` | a given with blockers at the **current** review hash, no paired `.taken` |
| `carried-unanswered` | a given with blockers at an **earlier** hash, no paired `.taken`, artifacts since edited |
| `answered` | every given with blockers has its paired `.taken` |

🔴 **`carried-unanswered` is the cell this behavior exists for.** today it is indistinguishable from
`none`, because the engine reads the givens at the current hash alone.

### C — the reviewer state (4)

the state of the reviewer that holds the blocker, before the move.

| value | what |
|---|---|
| `live` | budget remains; it can run again |
| `exhausted` | `rounds >= budget`; `runStoneGuardReviews.ts` skips it |
| `retired` | **absent from the live guard config** while one of its givens still holds an unanswered blocker |
| `overruled` | a human overruled its level; `getStoneGuardOverruledLevels` forgives it |

🔴 **`retired` was added at 5.3, not found at the vision.** it surfaced from a peer read of the
execution's own snapshot — the render carries a `status = retired from the guard config` line and a
why-block, so a real experience existed that this contract did not hold
(`rule.require.experience-catalog-evolution`).

⚠️ **it is a C value, never a B value.** the test is the axis's own definition — *the state of the
reviewer*, and `retired` is a fact about the reviewer exactly as `exhausted` is. what parts them is
**reversibility**, and that is what earns `retired` its own value rather than a fold into
`exhausted`:

| | does it run? | can the driver restore it? |
|---|---|---|
| `exhausted` | no | ✅ **yes** — `rhx route.guard.budget --add N`, a driver lever |
| `retired` | no | ❌ **no** — no config entry to top up |

🔴 **and the human valve is shut too.** `getStoneGuardOverruledLevels` forgives a *level*, and a
slug absent from the config carries no level to forgive (F8). so `retired` is the one C value where
**neither** the driver's budget lever **nor** the human's overrule reaches — the debt is discharged
by an answer, or not at all. that is precisely why it cannot collapse into `exhausted`.

## .orthogonality

| pair | independent? | why |
|---|---|---|
| A × B | ✅ **with one exception** | no driver or human move is **impossible** at any contemplation state. the exception is `reviewer-runs × carried-unanswered` |
| A × C | ✅ **with one exception** | no driver or human move is **impossible** whatever the reviewer's budget or forgiveness. the exception is `reviewer-runs × exhausted` |
| B × C | ✅ **over the two unforgiven C-values** | a blocker can be unanswered from a `live` or an `exhausted` reviewer. at `overruled` the pair is **degenerate** |

🔴 **the test is IMPOSSIBLE, never FORBIDDEN — and the difference is the whole behavior.** `enter-review
× fresh-unanswered` is a driver move the gate **refuses**, and it is refused at four cells. that is
the invariant this vision creates, not a correlation between the axes: the move remains attemptable,
the engine answers *no*, and the walked product verdicts each cell. **a dimension is hidden only when
a cell cannot be reached at all.**

⇒ so a forbidden cell **confirms** orthogonality rather than breaks it. ⚠️ *"available"* was the wrong
word here and read as the wrong test.

🔴 **all three exceptions land on ONE axis-value each, and every one is verdicted in the
inventory.** the orthogonality table declares what a grader may assume, so an unstated exception is
a false clean bill — the walked product would contradict the table that generates it.

⚠️ **the three are of three different KINDS**, and one caveat would lose the distinction:

| pair | the exception | its kind |
|---|---|---|
| A × B | `reviewer-runs × carried-unanswered` | 🔴 **nurture** — P1 creates it. change P1's placement and the cell returns |
| A × C | `reviewer-runs × exhausted` | **extant mechanism** — `runStoneGuardReviews.ts`, true today |
| B × C | `unanswered × overruled` | **definitional** — the overrule forgives, so the B-value is unreachable at that C |

### the A × B exception — created by this behavior, not found by it

`reviewer-runs × carried-unanswered × live` is impossible under P1: to schedule a run a round must
be entered ✅ · P1 denies entry while a carried-unanswered debt stands unforgiven ✅ · no `edit-code`
occurs mid-round, so no fresh given turns carried inside one ✅.

⚠️ **the `fresh` twin is legitimately available**, and the contrast is the proof this is no blanket
claim about the row: in a multi-reviewer round, reviewer B executes while reviewer A's *fresh* given
stands.

### the A × C exception — within-axis, never a hidden dimension

`reviewer-runs × exhausted` is a **void column of 4 cells**. a void column demands a verdict: is a
latent dimension hidden, or is this within-axis?

**within-axis, and the test settles it.** `exhausted` is *defined* as `rounds >= budget` — a fact
about **whether the reviewer may execute**. `reviewer-runs` is the move *"the reviewer executes"*.

| the move's actor | does C constrain it? |
|---|---|
| the **driver** (`enter-review`, `answer`, `edit-code`, `stop`) | ❌ never |
| the **human** (`overrule`, `observe`) | ❌ never |
| the **reviewer** (`reviewer-runs`) | ✅ **by definition** — `exhausted` means *"does not run"* |

⇒ **6 of 7 moves are fully independent of C; the 7th is the one move C is about.** to name a third
axis would only restate `budget`.

⚠️ **do not confuse this void with `answer × fresh-unanswered × exhausted`**, which reads impossible
and is **real**: the skip is evaluated at a round's *start*, so a reviewer that spends its last
round to raise a blocker ends that round fresh-and-exhausted. the A₇ column is void because the
*move* cannot occur; the A₂ cell is live because the *driver's* move can.

### the B × C exception — degenerate rather than constrained

at `overruled` a human forgave the rung, so the blocker is no longer owed — the inventory's whole
`overruled` column reads *"forgiven, proceeds"*. the B-axis **collapses** there: `unanswered` and
`answered` become indistinguishable in outcome, since neither gates.

| the claim | accuracy |
|---|---|
| B × C is *independent* | ❌ false at `overruled` |
| B × C is *dependent* | ❌ overstates — B discriminates fully at `live` and `exhausted` |
| ✅ B × C is **degenerate** at `overruled` | the pair collapses at one C-value; 8 of 12 cells discriminate |

⚠️ **this does not merge the two axes.** a degeneracy at one C-value is a property of that value,
never evidence the axes were one all along — the same test that kept `exhausted` and `overruled`
together under C.

## .the product

**7 × 4 × 4 = 112 cells.** walked in `1.vision.experience.case=_.md`.

⚠️ **was 84 at the vision (C had 3 values).** the `retired` column added 28, and it did not merely
extend the grid — it moved the invariant: `enter-review ∧ unanswered ∧ ¬forgiven` now selects
**6** forbidden cells rather than 4, because `¬forgiven` holds at three C values rather than two.

## .what the walk surfaced

### 1. a latent axis — `slug-valid?`

the `answer` row forces it. `--as contemplated --that <slug>` takes a slug the driver types, so a
typo is a real input, and `setStoneAsContemplated.ts` already rejects a slug that names no
peer reviewer.

⇒ a rejection invariant on an axis this grid does not carry. recorded rather than folded silently
into a cell. **this behavior must not weaken it.**

### 1b. a second latent axis — `verdict-legible?` 🔴 found at 5.3

`asPeerGivenVerdict` scores a given whose stdout carried **no numeric count** as `blockers: 1`, and
the render says so outright: `verdict = unreadable — no numeric count found`. so a reviewer that
raised no blocker at all still gates.

⚠️ **this broadens the invariant the inventory states**, and that is why it is recorded rather than
passed over. the stated rule is *"no entry with an unanswered blocker"*; here there is no blocker —
there is no verdict at all.

⇒ the correction is to the wording, never the mechanism. the gate's real predicate was always
`blockers > 0`, and an unreadable verdict **is** scored `blockers = 1`. so the invariant holds as
written in code; the prose that paraphrased it as *"a blocker the reviewer raised"* was narrower
than the predicate. `contract.reviewer-output` settles which is right:

> if it finds no numeric count it can **NOT** assume zero. a silent `0/0` would look like a clean
> approval when in truth no verdict was seen.

**it is an axis, and it is deliberately not a grid coordinate** — for the same reason `slug-valid?`
is not. it modulates *how a cell's blocker count arises*, never *which cell* the move lands in: an
unreadable given sits at `fresh-unanswered` or `carried-unanswered` on B exactly as a read one does,
and every A × C verdict over it is unchanged. to fold it in would double the grid to 224 and
duplicate every verdict.

⇒ demoed at `formatRouteGuardReviewPeerContemplatePrompt.test.ts` `[case5]`, which pins that the
render says `unreadable` **instead of** a count — the failhide, re-hidden at the surface, is the
hazard it clamps.

### 2. the whole `edit-code` slab is permitted — all 12 cells

the sharpest claim the grid makes about the shape of the fix:

> **the invariant does not forbid the edit. it forbids the re-entry.**

a driver may always edit; what it may not do is walk back through the review door while it owes an
articulation. a design that blocked the edit would fight the driver's real work.

### 3. a void column — `reviewer-runs × exhausted`

impossible by nature. the same column for `overruled` is **not** void: an overruled reviewer with
budget left still runs — the overrule forgives its verdict, it does not skip its execution.

⇒ **that asymmetry is why `exhausted` and `overruled` are two values of one axis** rather than two
axes: they forgive at different moments.

## .axes considered and set aside

| candidate axis | why not |
|---|---|
| `gate-position` = {entrance, exit} | this is the **change**, not a coordinate — the before/after of the whole vision |
| `concurrency` = {first, concurrent, retried} | no concurrent-guard-run path exists; two `--as passed` on one stone serialize through one process |
| `reviewer-count` = {one, many} | not orthogonal to B — the contemplation state already aggregates over reviewers |
| `conversation-opt-in` = {blind, `$conversation`} | genuinely orthogonal, and it modulates `reviewer-runs` alone. folded into case=4 rather than a grid doubled to 168 |
