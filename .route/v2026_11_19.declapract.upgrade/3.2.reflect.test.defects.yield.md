## .practice bugs

### D3 — a stale patch key passes in silence
- **citation**: `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "ignorePatchFailures"` → `src/practices/pnpm/best-practice/package.json`, `package.json.declapract.ts`; the decision is upstream fulcrum `F55-allow-unused-patches-only` (overruled to both keys by its seed S10), with stale-patch retire in `src/practices/pnpm/stale-patched-dependency.declapract.integration.test.ts`
- **the bug**: the practice treats a patch whose key the lockfile moved past as stale, so harmless. here the dep moved 1.15.7 → 1.17.0 and the fix the patch carried was still owed. `allowUnusedPatches` + `ignorePatchFailures` let it drop with no signal; only a clamp test caught it. upstream's own F55 named this risk ("a fix the adopter relied on silently vanished — to ignore that is a failhide") at 60%
- **link**: https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/main/src/practices/pnpm/best-practice/package.json · https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/main/src/practices/pnpm/stale-patched-dependency.declapract.integration.test.ts
- **sharper still**: the stale-patch retire drops the key and deletes the patch file (its own test header says so). had it fired on a second apply, the fix would have left the repo, not merely gone unapplied
- **ask**: when a patch key goes stale because its dep was bumped (not removed), say so loud at upgrade, and name the rekey (`patches/<pkg>@<new>.patch`) rather than delete the file

### D4 + D7 — the jest files have no repo seam
- **citation**: `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "modulePathIgnorePatterns"` → `src/practices/tests-node/best-practice/jest.{unit,integration,acceptance}.config.ts`; each cuts only `['<rootDir>/.agent/']`. the prepares (`jest.integration.prepare.ts`, `jest.acceptance.prepare.ts`) and envs are exact copies too. `gh search code ... "retryTimes"` finds no practice file that sets retries; `gh search code ... "runInBand"` → `src/practices/tests-any/best-practice/package.json`, the source of the serial acceptance commands
- **link**: https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/main/src/practices/tests-node/best-practice/jest.integration.config.ts
- **the bug**: the practice owns the configs, envs, and prepares byte for byte, so every repo behavior (haste cuts, transforms, budgets, retries, a worker pool, a once-per-run setup) is dropped on upgrade, or held only as drift
- **the near seam upstream**: `src/practices/tests-node/best-practice/jest.integration.env.ts.declapract.ts` checks `contents === declared base + usecase inserts` via `defineExpectedContentsWithUsecaseInserts`. the insert mechanism exists, but only a practice (persist-with-dynamodb) may declare an insert; a repo may not
- **ask**: open that insert seam to the repo, or one declared seam, e.g. an optional `jest.repo.ts` the practice configs import if present (this repo's `asJestConfigOfRepo({ config, suite })` is a proven shape). queued as radio `293410814e2f028f`

### D11 — the slow-test report fails a fully skipped shard
- **citation**: `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "schema drift"` → `src/practices/cicd-common/best-practice/.github/workflows/report-slow-tests.sh`; `rhx git.repo.get lines ... --words 'skip'` on that file at `origin/main` → 0 matches, so the gap stands upstream today
- **link**: https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/main/src/practices/cicd-common/best-practice/.github/workflows/report-slow-tests.sh
- **the bug**: zero durations trips the schema alarm, and a shard whose every test skipped also has zero durations

## .adoption candidate

### D1 — clear dependency cycles at the source, never by exclude
- **citation**: `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "dpdmrc"` → `src/practices/lint/best-practice/.dpdmrc.yaml.declapract.ts`, with its policy clamp `src/practices/lint/dpdmrc-exclude-policy.declapract.integration.test.ts` (the check ships with `exclude: []`, node_modules included)
- **the pattern**: packages with a clean release: `pnpm.overrides` lift every transitive range past the cycle (`helpful-errors@<1.7` → 1.7.5, `domain-objects@<0.34` → 0.34.0). packages with no clean release: replace them (`wrapper-fns` → local `withRetry` / `withTimeout`; `@ehmpathy/as-command` → a plain command; `archiver` → `fflate`). `.dpdmrc.yaml` holds dev excludes only
- **why adopt**: an exclude hides a cycle forever; an override or a replacement removes it, and the comment in `.dpdmrc.yaml` tells the next reader which lever to pull. the two org packages are the ones most adopters carry, so the overrides apply as is
- **note**: `wrapper-fns` and `@ehmpathy/as-command` are org packages that carry `bottleneck`; the clean cure is upstream (radio `485257c39520be13`, `36db125e9fb634f6`)
