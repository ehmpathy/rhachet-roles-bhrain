# 🌙 dream: the self-review emit prints a path the guard does not check

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-bhrain
- **caught** = 2026-09-17

## .the cue that fired

a vision stone on `v2026_09_17.fix-self-review-min-duration` ran:

```
rhx route.stone.set --stone 1.vision --route .behavior/v2026_09_17.fix-self-review-min-duration --as passed
```

and the guard answered:

```
│  ├─ articulate into
│  │  ├─ /review/self/for.1.vision._.r1.has-grounded-in-reality.md
│  │  └─ the guard looks precisely here, write exactly to this path
```

**the route segment is absent.** the printed path is absolute, rooted at `/`. the driver noticed only
because the wish under drive is *about* this subsystem — an ordinary driver would have written the
file where they were told and been refused.

## .the gap, precisely

🔴 **it is ONE entry point, not the whole surface.** verified by a second run rather than assumed —
the two calls print different paths for the identical slug, stone, and index:

| the call | the printed path | verdict |
|---|---|---|
| `--as passed` | `/review/self/for.1.vision._.r1.has-grounded-in-reality.md` | 🔴 the route segment is absent |
| `--as promised --that <slug>` | `.behavior/v2026_09_17.…/review/self/for.1.vision._.r1.has-grounded-in-reality.md` | ✅ correct |

so the **formatters are innocent.** `formatWalkTheWay.ts:7-13` takes `route` and hands the whole
input to `getSelfReviewArticulationPath`; `formatPatienceFriend.ts:58` and `formatLetsReflect.ts:100`
each pass it through intact. the path is computed correctly wherever `route` arrives.

the defect is exactly two lines, on one call path:

| file | line | what it does |
|---|---|---|
| `src/domain.operations/route/stones/setStoneAsPassed.ts` | `248-259` | calls `formatRouteStoneEmit({ operation, stone, action, passage, note, selfReview })` — **with no `route` field** |
| `src/domain.operations/route/formatRouteStoneEmit.ts` | `265` | `route: input.route ?? ''` — the empty-string fallback that converts that omission into a rooted path |

checkable: `Grep` for `route: input\.route \?\? ''` returns exactly one hit, at
`formatRouteStoneEmit.ts:265`. `grepsafe --pattern 'selfReview: \{'` returns exactly one hit, at
`setStoneAsPassed.ts:254`.

🔴 **the failure is silent by construction, and the split makes it worse.** the `??` fallback
converts an absent input into a path that reads as plausible rather than a throw, so the defect
ships as output that reads as correct — and because the *second* entry point prints the path
correctly, a driver who compares the two sees the guard contradict itself with no explanation.

⇒ **the misdirection lands first.** `--as passed` is where a driver meets the ask; `--as promised`
is where they arrive after they have already written the file. so the wrong path is the one the
driver acts on, and the right one only appears once it is too late to have helped.

## .the shape of the fix

two repairs, and both are owed — the second is what stops a recurrence:

1. **pass the route.** `setStoneAsPassed.ts:248-259` holds `input.route`; add it to the emit it
   builds for the self-review block. one field.
2. 🔴 **delete the `?? ''` fallback.** make `route` required on that emit input, so an absent route
   is a type error at author time rather than a rooted path at runtime
   (`rule.forbid.unexpected-defaults`, `rule.require.failfast`). if some caller genuinely has no
   route, it should say so explicitly rather than inherit an empty string.

**the clamp** (`rule.require.clamp-edge-cases`): a test that asserts the emitted articulation path is
**byte-identical** to `getSelfReviewArticulationPath({ route, stone, index, slug })`. it must go red
under the un-fixed code — revert repair 1, confirm the assertion fails on the absent segment,
restore, confirm green. an assertion that merely checks the path is non-empty does not bite.

⇒ the route snapshots that carry this emit will move. **re-take them, never delete them** — the diff
is the proof the fix landed.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe?** yes. the fix is contained to one emit field plus one type.
- **clean?** 🔴 **no** — not because it ripples through code, but because of **scope**: the round is
  on stone `1.vision`, and a vision stone emits no code. a code change here would land production
  edits inside an artifact whose declared deliverable is a vision yield, and it would enlarge the
  review diff for every lane on this route.

⇒ so it is a deferral for **scope**, not for dirt — and the round it belongs to is plausibly this
same wish's own execution stone, since `S01` clause 4 (*"better guide where exactly to put the
file"*) already owns this surface. a later traveler should check whether the execution stone has
absorbed it before they open a separate branch.
