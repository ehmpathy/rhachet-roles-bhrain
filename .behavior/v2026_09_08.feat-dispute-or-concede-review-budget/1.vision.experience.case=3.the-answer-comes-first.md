# case=3 · the answer comes first

- **coordinates** = `dispute × unanswered × live`
- **feel** = sharp · **care** = critipath · **verdict** = forbidden → demoed

**the invariant that keeps a dispute from an evasion.** the wish's boundary says it in one line: *"a
`<dispute>` is a verdict on the disagreement; it does not discharge the duty to answer each point."*
this is the cell that enforces it.

## .the narrative

*driver, on `5.1.execution`, round 2, one round after the architect raised three blockers*

three blockers, and I disagree with all three. the fastest road is obvious: dispute them, drive on,
let the council sort it.

```
$ rhx route.stone.set --stone 5.1.execution --as disputed --with architect --about blocker.1 \
    --why .fulcrums/inventory.of=fulcrums.case=F007-file-placement.md
```

```
🦉 patience, friend

🗿 route.stone.set --as disputed
   ├─ stone = 5.1.execution
   ├─ with  = architect
   ├─ refused — architect is unanswered
   │
   ├─ 3 blockers stand with no .taken.by_self.architect
   │
   └─ answer first, then take your stance
      ├─ write .reviews/peer/5.1.execution._.review.i7.4b81e0a2c9f31d5e78.r2._.taken.by_self.architect.md
      │  └─ one [REPAIR] or [REFUTE] per point
      └─ rhx route.stone.set --stone 5.1.execution --as contemplated --that architect
```

🔴 **the hash in that path is the FULL 18 hex chars, never the 6-char display prefix.** the path
grammar is `$stone._.review.i$iter.$hash.r$idx._.taken.by_self.$slug.md`, and `$hash` is what
`computeStoneReviewInputHash.ts:54` returns — `asHashShake256(…, { bytes: 9 })`, and its own note
says *"9 bytes = 18 hex chars"*.

✅ **and the path does not have to be built — it comes derived.**
`getRouteGuardReviewPeerContemplationStatus`, scoped with `{ slug }`, returns a
`RouteGuardReviewPeerUncontemplated` that already carries `tag`, `blockers` (**the "3 blockers" count
above**), `pathGiven`, and `pathTaken` — the last one derived by
`getRouteGuardReviewPeerPathTaken({ pathGiven })` (`:43`), the same infix swap the gate itself uses.
⇒ **this refusal renders from one extant record**, and the path it prints is the path the gate will
compute.

⚠️ **a truncation is correct in a display line and a defect in a path.** `case=8`'s emit prints
`4b81e0` beside *"declared at hash"* — a prefix a reader compares by eye. **this line is a path the
driver writes to**, and the gate looks at the exact path it computed
(`getRouteGuardReviewPeerPathTaken` derives it from the `.given` by an infix swap, never a
re-derivation). ⇒ a shortened hash here produces the *"articulation is absent"* refusal against a
file that exists — the same pitfall `howto.run-self-reviews` records for the review **level**, one
field over.

so I write the three refutations. and **on the second one I find that the architect is right** — I
had missed a caller. so the three blockers do not take one stance; they take **three**:

```
rhx route.stone.set --stone 5.1.execution --as conceded --with architect --about blocker.2
rhx route.stone.set --stone 5.1.execution --as disputed --with architect --about blocker.1 --why <path>
rhx route.stone.set --stone 5.1.execution --as disputed --with architect --about blocker.3 --why <path>
```

🔴 **that is `S07`'s grain at work.** a per-lane stance forces one verdict over all three — it would
either dispute a blocker I agree with, or concede two I do not.

**the aha:** *the answer is not a tax on the dispute — it is what produces one. I could not have
known which of the three I actually disagreed with until I wrote all three down.*

## .the bdd timeline

```gherkin
given a stone `5.1.execution` with peer reviewer `architect`, budget 4, rounds 1
  and the architect's latest .given raises 3 blockers
  and no .taken.by_self.architect exists                          # B = unanswered

[t0] when the driver runs --as disputed --with architect --about blocker.1 --why <a fulcrum path>
     with the fulcrum entry ALREADY written                       # ⇒ so the F018 check would pass
     then it is REFUSED                                           # 🔴 R1
      and the refusal names the blocker count and the exact .taken path to write
      and it names --as contemplated as the next command
      and NO ledger row is appended                               # 🔴 the record follows the stance
      and the fulcrum entry is UNTOUCHED                          # ✅ F018 — the command never writes there

[t1] when the driver runs --as conceded --with architect --about blocker.1
     then it is REFUSED identically                               # R1 covers both stance moves
      and the refusal copy is the same                            # one class, one message

[t2] when the driver writes the .taken and runs --as contemplated --that architect
     then the response is acknowledged                            # B moves to `answered`
      and no stance is yet on record

[t2b] when the driver declares all THREE concerns                 # 🔴 S07 — one per concern
      --as conceded --with architect --about blocker.2
      --as disputed --with architect --about blocker.1 --why <path>
      --as disputed --with architect --about blocker.3 --why <path>
     then each is admitted separately                             # 3 ledger rows, one slug
      and the conceded blocker STAYS in the tally                 # so the lane still holds the road
      and a per-lane stance could not have expressed this         # 🔴 the grain earns its keep

[t3] given instead the architect's .given computes `approved`      # 🔴 the VERDICT, never a count
     when the driver runs --as disputed --with architect --about blocker.1
     then it is REFUSED: "architect's verdict does not hold the road"  # 🔴 R2 — a different class
      and the message differs from [t0]'s                         # the two refusals are not one

[t4] given the .taken exists on disk but --as contemplated has NOT run
     when the driver runs --as disputed --with architect --about blocker.1
     then it is REFUSED                                           # the gate reads the ledger, not the disk

[t5] given the architect raised 3 blockers and the driver answered only 2 points
     when the driver runs --as contemplated --that architect, then --as disputed
     then BOTH are admitted                                       # ⚠️ the known hole — see below
```

🔴 **`[t3]` proves R1 and R2 are two classes, not one.** both refuse a stance move; they refuse it
for opposite reasons — *"you owe an answer"* versus *"no verdict stands to answer"* — and a driver
that reads one message for both would take the wrong next step.

🔴 **`[t3]`'s `given` reads the VERDICT, never a BLOCKER COUNT.** an 8-nitpick, 0-blocker lane raises
no blocker and its verdict **does** hold the road, so a raw count is not what R2 keys on (`F012`).

⚠️ **a demo phrased on the count would be internally consistent and still walk a road the engine does
not have** — it names a count, refuses on it, and the refusal message names the same count. ⇒ **that
is what a coordinate audit catches and a read of the narrative cannot.**

⚠️ **`[t5]` is the honest hole, inherited whole.** `setStoneAsContemplated` tests that the `.taken`
**exists**, never that it answers every point — `rule.forbid.unanswered-exits-from-a-blocker` grades
that row `⛔ open — existence is asserted, never content`. this behavior **does not close it and does
not widen it**: the same one file discharges the same one slug, exactly as today.

✅ **and the self-correction is intact under the per-generation skip**: a thin `.taken` buys one
generation, and the reviewer re-raises what it left unanswered on the next.

🔴 **so the hole is inherited at its original size — no larger, no smaller.** ⇒ what remains the
strongest case against this design is the **repeated** dispute (`case=4` `[t4b]`), where a driver
re-declares every generation and the loop never gets its turn. **that is a different failure with a
different remedy**, and this case's hole is not it.

## .why it fails safe

**fast** — refused before any write, before any subprocess · **loud** — names the count, the path,
and the command · **teaches the fix** — the `.taken` path is printed **in full, hash and all**, and
the `[REPAIR]` / `[REFUTE]` shape is named.

🔴 **"in full" is a contract clause here, not a flourish.** the driver does not compute this path —
it copies it, exactly as `howto.run-self-reviews` instructs for the review level (*"copy the
`articulate into` path verbatim"*). ⇒ **any elision in this line becomes a refusal the driver cannot
diagnose**, because the file they wrote exists and the gate reports it absent.

⚠️ **and it fails safe in the direction that matters.** the refusal costs the driver a keystroke; a
permission would cost every future reader the reviewer's three unanswered points.
