# 🌙 dream: a term's "wake condition" names a stage, and no mechanism fires it

**kind** — feat · **owner** — bhrain (this repo) · **caught** 2026-09-08

## .the cue that fired

the `learn.domain.terms` progress files carry deferred terms with a **wake condition** — *"wake at
the execution stage, where a bounded pool is built."* it reads as a promise.

**it is a note.** no mechanism reads a wake condition, and no stage transition checks for one.

## .the gap, precisely

measured across this repo's own progress files:

| term | deferred since | days elapsed | woken? |
|---|---|---|---|
| `pool`, `roster` | 2026-09-03 | 5 | ❌ |
| `route.guard.progress`, `event`, `inflight` | 2026-09-04 | 4 | ❌ |
| `concurrency` | 2026-09-04 | 4 | ❌ |

⇒ **five terms, five days, not one woken** — and every deferral was individually correct, because
each names a stage that genuinely has not arrived. **the deferrals are sound and the mechanism is
absent**, which is what makes this a feature gap rather than a discipline failure.

🔴 **the sharper half: what is deferred is not merely a WORD.** three of these carry judgments the
round already **settled** — `left` = `inflight + queued` (a sense dispute, resolved), and
`roster` ≠ `pool` (a distinction litigated twice, at i008/r1 and i023/r1).

those judgments live in **exactly one place**: `.behavior/v2026_09_03…/1.vision.experience.case=8…md`
and `…case=9…md`. ⇒ `rule.always.scope-onetime-lessons-to-the-behavior` names this hazard by name —
**"the discarded kernel"**, a real generalization thrown out with its route dir.

⚠️ **and the hook cannot catch it.** `learn.domain.terms --when hook.onStop` fires on a timer and asks
*"what did this round touch?"* — a deferred term is, by construction, one the round did **not** touch.
**the one artifact that could surface an expired wake condition is the one artifact whose trigger
cannot see it.**

## .the shape of the fix

**the wake condition is data, so make it readable.** today it is prose inside a dated progress file.

1. **give it an address** — a deferral gets a coordinate file rather than a table row, per
   `rule.forbid.itemization-without-coordinates`. e.g.
   `domain.terms/deferral.of=term.case=<term>.md`, which carries: the term, the wake condition, **the
   settled judgment**, and **the path where that judgment lives today**.

2. **fire it at the stage boundary** — `route.stone.set --as passed` on a stone knows which stone it
   just closed. that is the natural place to check *"does a deferral name this stage?"* and print it.

3. 🔴 **surface the elapsed count** — the strongest signal is not the wake condition; it is **how long
   it has waited**. a deferral 5 days old with its stage still ahead is healthy; the same one 60 days
   old is an expired promise, and only the count parts them.

⇒ item 1 alone earns its keep even without 2 and 3: it moves a settled judgment out of a route dir
that will be archived, into the glossary tree that will not.

## .why it is not done in this round

**safe?** yes — a new coordinate file and a print statement mutate no extant behavior.

**clean?** 🔴 **no**, and for a specific reason: **the deferral file wants a home in `domain.terms/`,
and `rule.require.boundary-qualified-terms` blocks the very terms it would carry.** `left`'s boundary
is `route.guard.progress`, which is undeclared — the same root-down chain the glossary readme already
records for `say` / `ref` under an undeclared `boot`.

⇒ so the fix wants that chain settled first, or an explicit decision that a **deferral** file may sit
at a boundary its **term** cannot yet claim. that is a glossary-structure call with repo-wide reach,
well past the diff this wish owns.

⚠️ **and it is the second independent instance of the undeclared-boundary chain** (after `say`/`ref`
under `boot`), from a different subsystem — which is the evidence that the chain is a structural gap
in the glossary rather than one term's bad luck.
