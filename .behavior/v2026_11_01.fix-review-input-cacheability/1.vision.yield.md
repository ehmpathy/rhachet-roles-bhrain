# 1.vision — review inputs hit the prompt cache

## .the outcome world

a guard pours a level of nine reviewers over one corpus. today each pays the corpus in full: the
lane's own rubric opens its prompt, so two lanes part at the rubric, ahead of ~88% of the bytes.
after the cure each prompt opens with what the whole level shares — instructions, output format,
targets — and the lane's rubric, refs, and conversation trail. the first lane writes the corpus to
the cache; its peers can read it at ~1/31 of the price.

**the aha:** the reuse was always there — across lanes, inside one round, seconds apart. the layout
put each lane's own bytes in front of it.

a driver who asks "what did review cost, and on which brain?" reads it from `rhx review._.cost`, by
brain, and a zero cache read says whether the round came late or the layout broke.

## .the cures, in order

0. **a brain axis** on both reports — `by brain` beside `by provider`, in text and `--json`, and
   the prefix census split by brain, so each brain row carries its own `served` · `missed` ·
   `lapsed` counts. it changes no prompt byte, so it takes the per-brain before-figure ahead of
   cure 1. `case=2`
1. **the shared corpus leads; the lane's rubric trails** — head = instructions + output format +
   targets (for a partition, its shared band); tail = rules, refs, then a partition's own band,
   then the conversation. lanes over one corpus then compute one head, and the extant prime meet
   (keyed brain + head, `stepReviewOfCompiled.ts:120-139`) primes once per level with no new
   mechanism. the rubric leads the tail, so a lane's partitions still share it. `case=1` ·
   `case=4` · fulcrum `F1`
2. **a `lapsed` verdict** — a pair whose round began past the reach of its prior. `case=3`
3. **C6's comments** state the pin as absent, and cite the dispatch

each cure ships with an offline clamp, red on today's code. cure 1 carries two: two lanes with
different rubrics over one corpus compile byte-identical heads; and one input compiled both ways
delivers the same sections, each once, byte for byte (`case=4`).

🟡 cure 1 also moves the cuts the section census makes. today both readers cut the head at
`## rules`: the compiled lane throws where that marker trails the targets
(`getOneHeadMarkerOffsets.ts:88-100`), and the disk reader starts its block scan there
(`asPromptSectionChars.ts:368-373`), so it would skip the whole target block. the cure re-keys both
cuts to a marker that leads the first block in either layout. the disk reader must still parse the
old layout, since the before-runs on disk are the baseline deliverable 4 compares against. a third
clamp: one run of each layout, parsed by the census, sums every section to its prompt with no
target chars in `scaffold`.

C2 and C7 leave as radio tasks to their own repos, each with the line above. a pin keyed on the
shared head is what turns cure 1 from "likely served" into "served": without it, lanes of one round
meet one host by the floor's choice, and one replica by chance.

## .mental model

a driver would say: *"the reviewers all read the same diff — now only the first pays for it."*

the analogy is a reading room. nine critics review one manuscript. today each is handed a copy with
their own rubric clipped on top, so the librarian photocopies the manuscript nine times. after, the
manuscript sits on the table once and each critic brings their own rubric.

| a driver says | we say |
|---|---|
| "the diff", "the files" | the target corpus, in the shared head |
| "the reviewer's rules" | the lane's rubric, in the tail |
| "it was cached" | a cache read, `cache.get` |
| "it came back too late" | `lapsed`, past the reach |

## .evaluation

| goal of the wish | how well |
|---|---|
| 1. measure before | done from the meter; per brain owed by cure 0 |
| 2. a cause per uncached input, to its line | C1–C8 above |
| 3. a cure per in-scope cause, red-then-green | cures 0–3, each clamped offline |
| 4. measure after, delta in tokens and USD/day | `5.3.verification`, same meter, same kind of rounds |
| 5. verdicts unchanged | the reviewer receives the same sections; only their order moves (see awkward) |

**pros.** the largest lever in this repo — up to (N−1)/N of the corpus per level — needs no new
mechanism. the level-pour prime is already built and sits inert: *"every prime watermark read
`peers: []`, `warm: false`"* (`genReviewPrefixPrime.ts:37-38`), because no two lanes have ever
shared a head. cure 1 is what gives it peers. **cons.** cross-round reuse of the rubric (~7% of a
heavy prompt) is given up; a rubric placed after the targets is unmeasured for verdict effect;
without C2's pin the cross-lane read is likely, not certain.

**the poke's break-even.** with the corpus in the head, a poke prefills it once at the full rate.
for a group of N lanes on one head, with p the chance a lane meets the primed replica, the prime
saves `H × (N·p·30/31 − 1)`. break-even p = 31 / (30·N):

| group size N | break-even p |
|---|---|
| 8 (`5.1`'s shared corpus) | 13% |
| 5 (`5.3`'s widest corpus) | 21% |
| 3 (`5.3`'s test corpus) | 34% |
| 2 | 52% |
| 1 | never pokes — a solo lane pays only the 1.5s gather (`genReviewPrefixPrime.ts:18-22`) |

the one measured cross-lane figure with no pin is ~39% (six lanes, one corpus,
`research.review-cost-and-cache.md:371-385`), above break-even for N ≥ 3 and below it for N = 2.
`5.3.verification` reads p from the prime outcomes and the peers' cache reads, and states which
group sizes paid.

**edgecases.**
- a lane with its own corpus (`mech-decode-friction` drops `**/*.test.ts`) shares no head with its
  peers — correct, and no worse than today
- a level of one lane gains naught and loses ≤7%
- a round that edits targets: across rounds, the cache serves a lane up to its first changed
  target, as today. within the round, the group's leader prefills the whole new head once and its
  followers read it back, edits and all — so the edited bodies are paid once per group, not once
  per lane
- a target order set by mtime is identical across lanes of one round, since they read one worktree
  (`getAllTargetsByCacheStability.ts:62-92`)

## .what is awkward

- **the rubric leaves the system slot.** the slot was chosen as the rubric's home on purpose, and a
  clamp holds it there (`reviewPromptCacheAnatomy.test.ts:525-528`). that choice rested on a pin that
  does not exist; the rubric is the narrow bytes, the corpus the shared ones
- **verdicts unchanged is a claim about content, not behavior.** the same sections reach the
  reviewer; only a live A/B proves the verdicts hold, and the bounds forbid one in ci. a count of
  verdicts across rounds before and after is no substitute: those rounds review different code.
  should the director want the A/B, it is one input, both layouts, one brain, run by hand once
- **the largest loss in this repo's reach stays uncured.** C5 is the guard's cadence. this route
  names it in the meter so it stops to pose as a layout defect
- **`lapsed` already names two things.** the meter's `cold (lapsed Nm)` means past the reach, and
  cure 2's verdict takes that sense. but the prime meet's outcome `lapsed`
  (`ReviewPrefixPrimeOutcome.ts`) means the lane's deadline left the meet no time. one word, two
  concepts, both extant (`rule.forbid.domain-term-ambiguity`). `5.1` owes the split: the verdict
  keeps `lapsed`, and the meet outcome takes a word of its own, or the reverse — itemized as a
  term before the code lands
- **the cure that makes cure 1 certain lives in another repo.** C2 is dispatched in `5.1`, not fixed
  here
