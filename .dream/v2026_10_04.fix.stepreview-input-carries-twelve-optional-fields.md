# 🌙 dream: `stepReview`'s input carries twelve optional fields on an internal contract

- kind = fix
- owner = rhachet-roles-bhrain
- caught 2026-10-04, in `.behavior/v2026_09_20.review-cost-meter` (stone `5.1.execution.from_vision`,
  self-review `has-pruned-backcompat` r2)

## .the cue that fired

a self-review row claimed `partitionable?` on `stepReview` was exempt from
`rule.forbid.undefined-inputs` as a boundary contract. a grep refuted it: `stepReview` lives in
`src/domain.operations/review/`, and only `src/contract/cli/review.ts` imports it. it is internal.

## .the gap, precisely

`src/domain.operations/review/stepReview.ts`, the input type near line 160, declares these optional:
`partitionable?`, `partition?`, `diffs?`, `paths?`, `pathsWith?`, `pathsWout?`, `polluters?`, `join?`,
`refs?`, `optional?`, `conversation?`, `cwd?` — twelve, by a grep for `?:` in the file. `rule.forbid.undefined-inputs`
grades an optional field on an internal input as a blocker: a caller can forget one and the
compiler says naught.

🟡 one of them is worse than the rest: `partition?` is set only by `stepReviewByPartitions` when it
recurses, so an SDK caller can see a field it must never set.

## .the shape of the fix

1. make each field required and nullable (`diffs: string | null`, `refs: string[]`, …); the cli,
   the one production caller, already holds a value or an absence for every one
2. update ~30 test call sites — a fixture factory (`genStepReviewInput({ ...overrides })`) beside
   `__test_assets__` keeps each test to the fields it cares about
3. lift `partition` off the public input: `stepReviewByPartitions` calls an inner `_stepReview`
   that takes it, and the exported `stepReview` omits it

## .why it is not done in this round

- SAFE — yes: a type-only change, the compiler finds every site
- CLEAN — no: ~30 call sites in nine integration suites, none of them in this round's diff. it
  predates the partition work, which only followed the input's extant shape
