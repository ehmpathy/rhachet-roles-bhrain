# 🌙 dream: an exhausted review level is dark, and no emit says so

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain` (`src/domain.operations/route/guard/…` — the halt emit
  and the review-meter tree)
- **caught** = 2026-09-20

## .the cue that fired

a peer lane at i014 reported that four architectural rubrics *"stopped running at i003"*. the meter
confirmed it and named the mechanism: **all nine l1 lanes hit their budget of 3 at i003 and went
exhausted together.** one of the nine was topped up **by name** at i012 and has read every round
since; the other eight were never named.

⇒ **eleven iterations of code shipped with no decode-friction, decomposition, scope-leak, or
maintenance-hazard pass.** the driver was not careless — they were never told.

## .the gap, precisely

🔴 **an exhausted level is a state the engine holds and reports to no one.** every emit a driver
reads names the lanes that **spoke**:

| the driver sees | the driver does not see |
|---|---|
| each lane that returned a verdict this round, with its rounds/budget | 🔴 any lane that was **skipped** because it is budget-locked |
| a halt that names the concerns owed | a level that has produced no verdict since iteration N |
| `--peer <x>: 5 → 8` after a targeted top-up | that eight sibling lanes sit at `3 / 3` |

two extant behaviors turn that omission into an eleven-round blind spot, and **each is correct on
its own**:

1. 🔴 **an exhausted level reads terminal-for-unlock**, so the ladder advances and the drive reads
   *terminal* and proceeds — exactly as designed
   (`define.invariant.review.peer.level-unlock-on-budget-exhaustion`)
2. 🔴 **a `--peer`-scoped top-up carries no signal about its neighbours.** the skill's own note is
   deliberate — *"a lower level stays exhausted unless it is explicitly named … a deliberate,
   targeted act, never a blanket sweep."* right, and the emit it prints (`arch-hazards-behavior:
   5 → 8`) reads as **the ladder healed**, never as *one of nine healed*

⇒ so the driver's every instrument agrees the system is at work, and the system has gone half-blind.

⚠️ **`rule.always.converge-to-terminal` already warns that exhaustion is often not what it looks
like.** what no brief says, and what the engine could simply print, is that a level can stay
exhausted across **eleven** further iterations while a higher level speaks every round.

## .the shape of the fix

**the state is already on disk — `.route/reviewPeerMeters.jsonl` plus the guard's per-lane budget.
no new quantity has to be computed.** the whole repair is to render what is already known.

one line per dark lane in the halt's review-meter tree, and it is the cheapest possible form:

```
├─ 🌑 dark — no verdict since i003 (budget spent)
│  ├─ mech-decode-friction            3 / 3
│  ├─ arch-opport-decomposition       3 / 3
│  ├─ arch-smell-scopeleaks           3 / 3
│  ├─ arch-hazards-maintenance        3 / 3
│  └─ … 4 more
└─ 🗿 yours to spend
   └─ rhx route.guard.budget --for review --add 3 --level 1 --stone <stone>
```

three properties worth holding:

- **name the iteration**, never merely the ratio. `3 / 3` reads as *bounded on purpose*;
  *"no verdict since i003, and the stone is at i014"* reads as *a gap*
- **print the level-scoped command**, since `rule.always.spend-own-levers-before-escalation` files
  budget as a driver lever and its own table omitted the guard row for a full release with a
  measured price
- 🟡 **a second, smaller repair beside it**: after a `--peer` top-up, print the lane's **siblings'**
  rounds. the targeted act stays targeted; the driver simply learns what they did not touch

## .why it is not done in this round

**SAFE: yes** — additive output, no gate condition changes.

**CLEAN: no**, and this is the half that blocks. the halt emit is snapshot-covered across the
acceptance suite (130 files, 3614 assertions), so a new tree branch re-takes snapshots in a diff
that is already ~140 files and under active peer review. ⇒ a reviewer cannot part a snapshot
re-taken for **this** change from one re-taken for the round's subject, which is the exact
confusion `rule.require.review-test-changes` forbids.

🟡 and it is **out of the wish's scope** on its own terms: this round repairs the self-review gate,
and this is a peer-review-ladder ergonomics defect that merely surfaced here.
