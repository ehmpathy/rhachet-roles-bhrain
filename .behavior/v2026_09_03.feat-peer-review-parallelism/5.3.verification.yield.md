## 🔴 .the defect verification itself found — a stable level-unlock deadlock

⚠️ **this is the one finding that came from the verification stone rather than from execution**, and
it was found by a drive of this very route, not by a test.

### the symptom

l1 was spent (`2/2`), l3 sat at `awaits arrival`, and no arrival moved it. more budget did not help
— `--as arrived` re-ran no lane, because l1 had none left to spend and l3 was never permitted to
start.

### the mechanism

`computeVerdicts` decided `wasExhausted` from the artifact hash:

```
a reviewer is exhausted  ⟸  it has NO review at the current artifact hash, AND rounds >= budget
```

that reads correctly in the two ordinary cases and inverts in a third:

| the reviewer | artifact at current hash? | read as | truth |
|---|---|---|---|
| ran this pass | yes | ran ✅ | ran |
| skipped, artifact moved since | no | skipped ✅ | skipped |
| 🔴 **skipped, artifact NOT moved since** | **yes** — its own stale rejection | **ran** ❌ | skipped |

⇒ row 3 reads `rejected`, `rejected` is non-terminal, so **the level above never opens** — and the
driver cannot move the hash, because the only work left is at the level that will not open.

🔴 **it is reached by ordinary work.** spend a reviewer's last round, then re-arrive to answer a
*different* reviewer's blocker: the artifact never moved, and that is row 3 exactly.

### the fix

read the authoritative record first — the `exhaustedReviewerSlugs` set that `runStoneGuardReviews`
pushes to as each level settles:

```ts
const wasExhausted =
  exhaustedReviewerSlugs.includes(pr.slug) ||
  (!artifactThisPass && rounds >= pr.budget);
```

⇒ enbriefed as `define.invariant.review.peer.level-unlock-on-budget-exhaustion`, with its
nature/nurture label, its counter-argument, and what would overturn it.

### 🔴 the second finding — `reviews` is a render input, never a run log

the obvious in-process test for *"did it run this pass?"* is *"is it in the `reviews` array?"*, and
it fails for the same reviewer:

> a level's settle pushes the artifact each member should **DISPLAY**, and for a member skipped for
> want of budget that is its own stale cached review (`reviewForDisplay` → `artifactByIndex` →
> `reviews`).

⇒ so a **skipped** reviewer IS in `reviews`. the variable was named `freshReview`, and the name
lied. renamed `artifactThisPass`, with the conflation recorded at the read site.

### 🔴 the near-miss — the same repair, applied to the judge, is a DIFFERENT defect

`route.stone.judge` runs as its own process with no in-memory set, so it falls back to the hash
test. i first relaxed that fallback to a bare `rounds >= budget` — the same shape as the real fix —
and it inverted `define.invariant.review.peer.exhausted`: a reviewer that ran and spent its last
round read `exhausted` **on the pass it ran**, so the level above read unlocked-but-unrun a full
pass early.

⚠️ **every assertion in `[t1]` still passed. only the snapshot caught it** — the judge's blocked
reason moved from `blockers exceed threshold (1 > 0)` to `review level 3 not yet run (still
queued)`, and the guard tree and the judge then disagreed inside one stdout.

⇒ reverted; the judge keeps the hash test, and the invariant brief carries a 🔴 *do not relax this*
with the measurement. **the judge never needed it** — unlock is decided upstream, so by the time the
judge runs the higher level has already poured.

## 🔴 .the second invariant this stone produced — level unlock is a LATCH

⚠️ **a design change, asked for by the wisher mid-verification**, and the sharper half of
the two. the first fixed a level that never opened; this holds open one that did.

### the wisher's words

> *"lets make it a latch though. as soon as l3 begins to run, it never stops the runs"* ·
> *"so even if l1 is restored, l3 doesnt stop"* · *"that way we keep the train moving,
> cause we know if its terminal, l3 is up regardless of what happens to the l1 reviews"*

### why it was owed

`terminal` is recomputed from the current verdicts on EVERY pass, so a lower level that
reads terminal once can read non-terminal later:

| pass | l1 | l3 |
|---|---|---|
| n | **malfunction** — terminal | pours ✅, rejects with real blockers |
| n+1 | the driver repairs the reviewer; it now **rejects** | 🔴 non-terminal ⟹ l3 **withdrawn** |

⇒ at n+1 the driver holds l3's `.given` and owes it a `.taken`, and the lane disappears.
**the work to answer l1 is what removes l3.**

🔴 **and a malfunction spends NO round** (`reviewCompleted` excludes it), so it never
exhausts into the budget-locked skip. the exhaustion path cannot rescue this case at all.

### 🔴 it needed no new store — the pavement was already there

`passage.jsonl` already carried `overruled` as a level-scoped sticky marker cleared by
exactly one lever: a rewind, with cross-stone cascade. `poured` takes the identical shape.

⇒ **no new file, no new gitignore, and no reset logic written** — so the wisher's own
constraint (*"the only operation that resets this is --as rewound"*) holds by construction
rather than by a second implementation that could drift.

### ⚠️ two defects found by the clamps, not by inspection

| defect | how it was caught |
|---|---|
| the reducer **never handled `poured`** — a blocked edit, never retried, while the brief asserted otherwise | 3 of the `getAllPassageReports` clamps went red. `poured` fell to last-entry-wins, keyed by STONE, so the latch would vanish the instant the stone blocked — the exact pass it exists to survive |
| the **display** read no latch | the acceptance journey went red: the 🦉 tree rendered `l3-reviewer rejected` (it ran) while the 🗿 block beneath it rendered `awaits l1 terminal` — two renders disagreeing inside ONE stdout |

🔴 **the second is the same drift class as the judge defect above**, met a third time. the
repair is structural rather than another thread-through: `getAllReviewPeerMeterStatuses`
now loads the latch ITSELF, since it already holds `stone` and `route`. it has four
callers, and an input would have been four chances to forget it.
