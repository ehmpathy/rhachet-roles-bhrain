# 🌙 dream: the grove meter re-reads every prompt on every call

kind = fix · owner = rhachet-roles-bhrain (review meter) · caught 2026-10-16

## .the cue that fired

`rhx review._.cost --of grove` took about fifteen minutes over 39 trees and 3,054 runs on this
machine. `--of tree` over one tree of 2,225 runs took minutes too. a meter that slow is a meter a
driver stops to consult, so each cost lever it reports goes unread.

## .the gap, precisely

- `getAllReviewRunMeters` meters every run dir from scratch on every call, at a bound of 8
- each run reads its compiled prompt (megabytes) to count chars per input, and 786 of 2,882 read
  runs still parse the rendered prompt (`source: parsed — coarse`)
- `getOnePrefixCensusOfTrees` then pairs each round with its prior round, a second pass over
  the same prompts
- a completed run dir never changes, so all of that work recomputes facts already known

## .the measure (2026-10-16, this machine)

| read | runs | wall time |
|---|---|---|
| `--of tree`, warm, this tree | 2,225 (all `compiled`) | 20s |
| `--of grove`, cold | 3,054 | ~15 min |
| `--of grove`, warm | 3,054 | 248s |

⇒ the 2,225 compiled runs cost ~20s; the other ~830 runs cost ~228s. those are the 786 runs
that predate `metrics.compiled.json`, re-parsed from a megabyte prompt on every call, plus
their prefix pairs. the cold figure is the same reads off a cold disk.

## .the root cause, found after the catch

the ~228s was not the re-read; it was the re-PARSE. `asPromptSectionChars` re-hunted every
tag from the cursor on every block, so a tag that opens once (`<rules>`, `<refs>`,
`<conversation>`) was searched to the end of a megabyte prompt once per later block —
O(blocks × prompt). a per-walk memo of each tag's next opener makes it linear.

- clamp `[case17]`: 400 targets, 2,409 full-prompt scans before, ≤ 5 after (red → green)
- measured: `--of grove` warm, 248s → 36s

⇒ the sidecar below is now a far smaller win (36s, not 248s). it stays caught, unbuilt.

## .the shape of the fix (the sidecar, still owed)

1. memoize one run's meter in a sidecar `meter.json` in the run dir, written the first time a
   COMPLETE run is metered; key it on the meter's schema version so a meter change re-reads
2. read the sidecar first; fall back to the full read when absent, stale, or the run incomplete
3. the same for the prefix pair of a run (its prior is fixed once both runs exist)
4. clamp: a test that meters a run dir twice and asserts the second call reads no prompt
   (spy on the fs read), red before, green after; and one that bumps the schema version and
   asserts a re-read

## .why it is not done in this round

it adds a persisted artifact and an invalidation rule — a contract change across the run log
layout. safe, but not clean beside a merged release; it earns its own branch and its own measure
(time `--of grove` before and after).
