# 🌙 dream: git.commit.push misreads the pr number it just opened

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, `git.commit.push`) · caught 2026-11-24

## .the cue that fired

`rhx git.commit.push --mode apply --auth as-human` opened pr #843, then its watch step refused:

```
   ├─ pr: pr #843
1 (created)
   ├─ watch: ✋ ConstraintError: --which must be a pr number; got '843
1'; rerun: rhx git.pull.watch set --which 843
1 --mode apply
```

## .the gap, precisely

on the `as-human` fallback path, the captured pr number carries a second line (`1`), likely a stray exit code or count echoed into the same capture. the render prints it, and the watch refuses it. the pr itself opened fine.

## .the shape of the fix

capture only the pr number on the `as-human` path (parse the last integer of the url, or `--json number --jq .number`), and add a test for that path that asserts the watch receives a bare integer.

## .why it is not done in this round

the skill lives in another repo; it is re-seeded there, never patched here.
