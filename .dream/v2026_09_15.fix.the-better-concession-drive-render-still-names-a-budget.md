## .the gap, precisely

in the mainline these `better` branches are UNREACHABLE, so this is not a live defect — it is
dead-ish code that lies about the behavior:

- `genRouteGuardExhaustedReason.ts` — `REASON_MARK_CONCESSION` + `REASON_TEXT_CONCESSION` +
  `isRouteGuardConcessionExhaustion` + the `better` branch of `genRouteGuardExhaustedReason`.
  the gate now only calls `genRouteGuardExhaustedReason` with `none`/`urgent` (it early-returns
  a pass for `better`), so the `better` branch is never taken there.
- `asRouteStoneDisposition.ts` — the `isRouteGuardConcessionExhaustion → { of: 'push' }` branch.
  it fires only for a persisted `exhausted` STATUS, which a `better` concession never writes
  (it passes). so the branch is dead.
- `formatRouteDriveBudgetExhausted.ts` — the `isConcession` (better) render branch. reached only
  via `getRouteDriveExhaustedMessage`, which the docstring says fires only when the passage
  status is `exhausted` — never for `better`.

⚠️ **the one live edge**: `getRouteDriveExhaustedMessage` recomputes the concession kind LIVE
from meters. in a race — an `exhausted` status persisted (a `none`/`urgent` halt), THEN the
driver concedes the remaining lanes `better`, THEN `route.drive` — the live kind could read
`better`, and the render would show "increase budget / then re-arrive" with `blocksStop: true`.
the `blocksStop` (self-drive toward `--as passed`, which now passes) is CORRECT; only the
render TEXT ("increase budget") is wrong for `better`. low severity, transient window.

## .the shape of the fix

1. narrow `genRouteGuardExhaustedReason`'s `concession` param to `'none' | 'urgent'` (the gate
   already excludes `better` before the call, so TS narrows it there).
2. remove `REASON_MARK_CONCESSION` + `isRouteGuardConcessionExhaustion` (both only serve the
   dead `better`-halt). KEEP `REASON_TEXT_CONCESSION` — it is the reason line an `urgent` halt
   shows via `asConcessionReasonDisplay`.
3. drop the `isConcession` (better) branch from `formatRouteDriveBudgetExhausted` and the
   `better`-push branch from `asRouteStoneDisposition`.
4. for the live race in `getRouteDriveExhaustedMessage`: when the live kind is `better`, render
   "the maintenance floor is met — run `--as passed` to proceed" (no budget), `blocksStop: true`.
5. resnap `asConcessionReasonDisplay.test`, `formatRouteDriveHalts.test`, and any drive snapshots.

⚠️ **do it carefully** — every one of these surfaces also renders the LIVE `urgent` halt, which
must stay byte-identical. verify the `urgent` render before and after (the exhausted integration
test now pins it).

## .why it is not done in this round

it is inert in the mainline (a `better` concession passes and never halts), and it is entangled
with the drive-time live-recompute race, so a rushed multi-surface cut risks the LIVE `urgent`
path for zero behavior gain. the behavior is already correct and clamped (S16 unit + acceptance).
this is hygiene + one transient-window text fix, best done deliberately.
