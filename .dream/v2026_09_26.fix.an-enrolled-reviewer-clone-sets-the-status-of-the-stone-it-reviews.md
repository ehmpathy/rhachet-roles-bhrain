# 🌙 dream: an enrolled reviewer clone sets the status of the stone it reviews

- kind = fix
- owner = rhachet-roles-bhrain (driver — `route.drive` hook; reviewer — enroll lanes)
- caught 2026-09-26

## .the cue that fired

`5.1.execution.from_vision` (review-cost-meter), round i002 `f9989f17260b48b058`, lane r012
`enroll-impl-arch-defects` (an `--enroll` peer lane). the stone came back `blocked`, and the
driver never ran `--as blocked`. the lane's own stdout says why:

- the clone tried to APPLY a fix it proposed, and its writes were denied
- *"per the route-drive hook's forced choice"* it then ran
  `rhx route.stone.set --stone 5.1.execution.from_vision --as blocked`
- the halt auto-attached `blocker/5.1.execution.from_vision.md` — a stale, LIFTED blocker from
  2026-09-21 on an unrelated exec-bit gap
- the tally then fell back to a sub-brain and malfunctioned

## .the gap, precisely

two defects, one mechanism: **the reviewer clone boots as a DRIVER of the bound route.**

1. the route's stop hook (`route.drive`) fires inside the enrolled clone, so a reviewer is told
   to advance, pass, or block the very stone under its review. the party that grades a stone can
   now set its status — the same review-scope defect `rule.forbid.hand-run-reviews` names, from the
   reviewer's side
2. the clone also believed it should FIX what it found. a review lane's contract is a report with
   two counts (`contract.reviewer-output`); an attempt to edit is out of contract, and its failure
   ate the round (the tally fallback found no parseable counts)

## .the shape of the fix

- the enroll lane's spawn sets a marker (env var, or the actor's settings) that `route.drive`
  reads: a reviewer actor never receives the drive nudge, and `route.stone.set` refuses
  (`✋ ConstraintError: a reviewer may not set a stone's status`) when the marker is present
- the enroll lane's prompt states the lane is READ-ONLY and its deliverable is the report
- clamp: an acceptance test that enrolls a reviewer on a bound route and asserts `passage.jsonl`
  gained no row from it

## 🔴 .the prompt half was tried, and it does NOT hold (measured 2026-09-26, i003)

the enroll prompts were amended to say READ-ONLY and to never run `route.stone.set` or any
`route.*` command. at i003 `enroll-impl-arch-defects` returned 0/0 and still wrote `blocked` to
`passage.jsonl` — its report says it did so because to move the stone forward is driver-role work.
⇒ **a prompt is not a mechanism**; only the marker + refusal above binds.

and the clone's own stderr names a second hole in the extant guard:

```
Permission deny rule (…settings.enroll.9366365e.local.json): Write(*/**/.route/**) is not matched
by file permission checks — only Edit(path) rules are. Use Edit(*/**/.route/**) instead
```

⇒ the enroll settings' `.route/**`, `.branch/.bind/*`, and `.meter/*` DENY rules are written as
`Write(...)`, which Claude Code ignores. the file-level fence around the route was never up. the
cheapest partial fix is to rewrite those rules as `Edit(...)` in the settings generator (owner:
wherever `settings.enroll.*.local.json` is generated — likely `ehmpathy/rhachet`'s enroll), and it
still does not stop a `Bash(rhx route.stone.set …)` call, so the marker remains owed.

## 🔴 .a third defect, same mechanism: the hook eats the verdict (measured 2026-09-27, i011)

the guard captures the clone's FINAL message, and the drive hook fires after the review is
written, so the final message is the clone's reply to the hook — or naught at all:

- i010 `enroll-impl-arch-defects`: the captured text is the clone's refusal of the hook's nudge
  (*"my review deliverable was already posted in full … I am a read-only reviewer"*); the tally
  survived only because the refusal happened to restate it
- i006 · i007 · i008 · i010 · i011: the enroll lanes returned `💥 malfunction: reviewer output
  lacks a numeric blocker/nitpick count`, with stdout that holds only the claude-code permission
  warnings. at i011 both lanes did, one after a 35-minute run

⇒ the marker above cures this too: a reviewer actor that never receives the nudge ends on its
report. and `rhx clone get` cannot inspect the loss, since two clones spawned in one cwd share a
transcript home (*"history is empty because this clone shared a cwd with another at spawn"*) — so
the fix should also give each enrolled lane its own transcript home.

## .why it is not done in this round

it spans `route.drive`, `route.stone.set`, and the enroll lane spawn — three surfaces this wish
never opened, and a contract change to `route.stone.set`. unsafe to ride along.
