# case 4 — the-field-name-is-misspelled

**actor** = driver-clone (a human typo produces the identical outcome — slice 4 subsumes) ·
**feel** = sharp · **care** = critipath
**cell** = `driver-clone × prescribe × misspelled-key × any reach`

> 🔴 **measured:** `parseStoneGuard` drops unknown top-level keys in silence. no throw, no warn, no
> trace (`parseStoneGuard.ts:164-430`, construct at `:47-53`).

## .the narrative — **today**, and it is the unsafe path

i am the driver, and i am about to prescribe a cheap brain for a routine execution phase. i open the
guard and write the field.

the slash command is `/model`. the flag on `enroll` is `--model`. the flag on every L3 peer review in
every guard i have ever read is `--model`. so i write:

```yaml
model: claude-sonnet-5[1m]

artifacts:
  - "$route/5.2.execution.phase1.yield.md"
```

naught objects. the guard parses. the route runs. every judge passes.

and the field is gone. `parseStoneGuard` walks the file line by line; it matches four literal keys —
`artifacts:`, `reviews:`, `judges:`, `protect:` — and list items under them. my line matches neither,
so it falls through the loop with no branch to catch it. the guard is then constructed from four
fields, and mine is not among them.

**every surface agrees with me that this worked.** the file on disk still says `model:` — a reader
who opens it to check sees exactly what they expect. the parse succeeded. the stone ran. no warn
appeared, because no code ever knew a field was intended.

so the stone runs on the inherited brain, and it is **indistinguishable from a stone that never
declared one**. that indistinguishability is the whole harm: there is no observation, anywhere, that
separates "prescribed sonnet, and got it" from "prescribed sonnet, and the word was dropped".

⇒ **the "aha": a silent parser turns a typo into a permanent, invisible lie.** case 2 and case 3 are
sharp but they are *loud* — they halt and teach. this one never surfaces at all. it is the only
critipath here with no natural moment of discovery, which is exactly what makes it the most
expensive.

## 🔴 .the narrative — **with the fail-safe**, and this is the path the build delivers

⚠️ **rewritten 2026-09-10, after the council RULED `F4`.** this section demoed a **throw** on an
unknown key. the wisher refused a closed key set — *"lets not; we want future compat."* — so the
throw is unbuildable, and a demo of it would be the exact defect peer review r2 caught on `case=3`:
a demonstrated safe path that cannot be built.

⇒ **the surviving remedy is a WARN, and it turns out to be sharper than the throw.**

### 🔴 the distinction the throw could not make, and the warn can

a closed key set refuses **every** unknown key, which is why it costs forward compatibility. but the
two kinds of unknown key are not alike:

| the unknown key | what it is | the right response |
|---|---|---|
| `foo:`, `cadence:`, `budget:` — near nothing you know | a **future** key, from a newer producer | ✅ **drop it in silence.** this IS forward compatibility |
| `model:` — a declared alias · `brian:` — one edit from `brain:` | a **typo**, or the synonym a hand reaches for | 🔴 **warn, and name the word they wanted** |

⇒ 🔴 **a typo is not an unknown key. it is a key that is one edit from a known one** — and that is
mechanically detectable, with no key set closed and no forward compatibility spent.

### the walk

same driver, same reflex, same typo. i write `model: claude-sonnet-5[1m]` and save. **the mutation
succeeds** — the key set is open, so nothing is refused. and the surface does not stay quiet:

```
🗿 route.mutate.guard
   └─ ✅ guard written

🦉 heads up — a key in this guard looks like one i know

   ├─ i found    = model:
   ├─ where      = 5.2.execution.phase1.guard:1
   ├─ i ignored it, and the stone will run on the inherited brain
   │
   ├─ did you mean
   │  └─ brain:   — the canonical word. `model:` is a forbidden synonym
   │
   └─ if `model:` is deliberate, this warn is safe to ignore
```

i read three lines and i know: the word, the line, **and what the parser did with it**. i change
`model:` to `brain:` and save again. the stone runs on sonnet, and `case=8`'s line says so.

⇒ 🔴 **the harm was never the typo — it was the INDISTINGUISHABILITY.** the warn destroys it at the
one moment i still hold the context that produced it. the key is still dropped; what changed is that
the drop is now **reported**.

🟡 **and the alias makes it a teacher rather than a scold** (`F2`). the message does not merely note
`model:` — it names `brain:` as the word i wanted. **a driver who hits this once does not hit it
twice.**

⚠️ **the warn is weaker than the throw on exactly one axis, and it is honest about which:** a driver
who does not read the output proceeds. the throw made reading mandatory. that is the price of
forward compatibility, and the grade table below states it rather than smooths it.

## .the bdd `[tn]` timeline

`[t0]`–`[t3]` walk **today**. 🔴 **`[t4]`–`[t7]` walk the SAME typo with the fail-safe in place**, and
that second walk is the experience this vision commits the build to deliver.

```
given a guard that a driver is about to mutate to prescribe a brain
  and  a parser that matches four literal top-level keys and no others

  # ---- today: the unsafe path ----

  when [t0] the driver writes `model: claude-sonnet-5[1m]` — the slash command's own word
    then parseStoneGuard matches no key and no list item for that line
    and  the line falls through the loop, and no branch throws

  when [t1] the guard is constructed
    then it carries artifacts, reviews, judges, protect — and no brain
    and  the guard is reported VALID; the mutation succeeds

  when [t2] the driver enters the stone
    then no switch is attempted, because no brain field parsed
    and  the stone is indistinguishable from one that declared no brain at all

  when [t3] a reader opens the guard to confirm the prescription
    then the file still reads `model: claude-sonnet-5[1m]`
    and  every surface agrees the prescription is in place, and none of them is right

  # ---- 🔴 the same typo, with the fail-safe: the safe path, demonstrated ----

given the same guard, the same driver, and the same typo
  and  🔴 a parser whose key set stays OPEN — an unknown key is still dropped
  and  a near-miss detector: an unknown top-level key is compared against the known set
  and  `model:` declared as a forbidden-synonym alias of `brain:` (F2)

  when [t4] the driver writes `model: claude-sonnet-5[1m]` and saves
    then parseStoneGuard drops the line, exactly as it does today
    and  the mutation SUCCEEDS — no throw, and forward compatibility is untouched
    and  🔴 the dropped key is compared against the known set, and `model:` matches the alias

  when [t5] the warn is rendered to the driver
    then it names the key it found, the file and line, and THAT IT WAS IGNORED
    and  it names `brain:` as the canonical word the alias points at
    and  it says the warn is safe to ignore if the key was deliberate

  when [t6] the driver changes `model:` to `brain:` and saves
    then the guard parses, carries `brain: claude-sonnet-5[1m]`, and no warn is emitted
    and  the whole correction cost one read and one edit, in the same turn as the mistake

  when [t7] the driver enters the stone
    then the switch is attempted and the brain line reports what ran (case=8)
    and  "prescribed sonnet and got it" is now DISTINGUISHABLE from "prescribed sonnet and lost it"

  when [t8] a NEWER producer writes a future key `cadence: weekly` into a guard
    then it is dropped, exactly as today, and 🔴 NO warn is emitted
    and  it is near no known key, so the detector does not fire
    and  forward compatibility is preserved by construction, which is what F4 ruled for
```

## .the fail-safe grade

⚠️ **today, `[t0]`–`[t3]`, this case fails every obligation.** ✅ **`[t4]`–`[t7]` is where each is
met, and it is walked above rather than promised.**

| obligation | today `[t0]`–`[t3]` | 🔴 demonstrated at, under the ruled `F4` |
|---|---|---|
| **fast** | 🔴 never — it is never caught | ✅ `[t4]`–`[t5]` — the warn lands at the save that introduced it, in the same turn |
| **loud** | 🔴 silent at every surface | 🟡 **a warn, never a halt** — `[t5]`. it names the key, the file, the line, and that it was ignored. a driver who does not read output proceeds |
| **teaches the fix** | 🔴 no message exists | ✅ `[t5]`–`[t6]` — it names `brain:` as the word wanted, and `[t6]` shows the driver act on it |
| **holds the limit** | 🔴 no limit is held | ✅ `[t8]` — 🔴 **a near-miss detector, so a FUTURE key is silent and a TYPO is not.** the limit is held by the shape of the check rather than by a closed set |

⇒ **the safe path costs one read and one edit, in the turn that made the mistake.** the unsafe path
costs a whole route run at the wrong brain, and never reports that it did.

### 🔴 what the `F4` ruling cost this case, stated plainly

| | with a closed key set (refused) | with the near-miss warn (ruled) |
|---|---|---|
| `loud` | ✅ a halt. reading is mandatory | 🟡 a warn. reading is not |
| forward compat | 🔴 spent — a new key breaks an older parser | ✅ **whole** |
| a future key | 🔴 refused, and it should not be | ✅ silent, `[t8]` |

⇒ **one obligation degraded from ✅ to 🟡, and one property that was 🔴 became ✅.** that is the trade
the council made, and it is the right one: a missed warn costs one stone at the wrong brain; a broken
guard format costs every downstream consumer on an older pin.

⚠️ **so `case=4` is no longer fully fail-safe, and it is honest about the residue.** the
indistinguishability is destroyed — a reader who looks can now tell the two apart — but the build no
longer forces the look. `rule.require.experience-coverage` is satisfied by the demonstration; the 🟡
is a **stated** limit rather than a hidden one.

## 🟡 .the two calls this case forces

### 🔴 `F4` — RULED 2026-09-10: the parser stays permissive

the silent drop is not specific to `brain:`. it applies to every key any guard will ever gain, and
this feature is the first to be bitten by it.

⇒ the vision best-guessed **reject unknown keys**, and paid the forward-compat cost with a version
gate. **the wisher overturned it** — *"lets not; we want future compat."*

> **forward compatibility is a property of the FORMAT; a loud typo is a property of one author's
> afternoon.** a guard format that refuses an unknown key cannot be extended by a newer producer
> against an older consumer, and that cost falls on every repo that consumes the format.

⇒ 🔴 **the remedy moved from a THROW to a NEAR-MISS WARN**, walked at `[t4]`–`[t8]`. the key set
stays open, and the check fires on the one shape a future key never has: proximity to a key we
already know.

⚠️ **and the ruling raises `F2` from a courtesy to the load-carrier.** with no closed set behind it,
the alias warn is the **entire** defense this case has.

### `F2` — the field is named `brain:`, and `model:` is accepted as an alias

the issue leans `brain:` because that is rhachet's domain term, and it is right —
`rule.require.ubiqlang` settles it: one canonical word per concept, and the concept is a **brain**.

but this case is evidence that `model:` is the word a hand reaches for, because it is the word on
`/model`, on `--model`, and in every extant guard's L3 reviews. that pull does not go away because a
rule says it should.

⇒ best-guess: **`brain:` is canonical, and `model:` parses as a forbidden-synonym alias that warns
and names the canonical word.** `rule.forbid.domain-term-synonyms` allows exactly this: the contract
carries the canonical term, and the synonym is recorded rather than silently tolerated.

⚠️ **this interacted with `F4`, and the ruling changed the interaction's shape.** the note read:
*"an alias is a known key, so it must be allowlisted before the key set closes."* the set never
closes now — so the alias is no longer a **carve-out from** a refusal. it is the **trigger for** a
warn, and the two are different code.

⇒ 🔴 **and the dependency inverted with it.** `F2` was a courtesy that a closed set backed up; it is
now the sole mechanism that makes this case's most likely typo visible. **build `F2` or `case=4`
has no fail-safe at all.**
