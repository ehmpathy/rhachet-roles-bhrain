# S3 — `clone get` reads the reply

## .said

> we ourselves can verify it was accepted via clone get followup, no?

## .settled

**a surface that reads a peer's own transcript is a detection mechanism, and it is not the same
candidate as a surface that reports live state.** the two differ on what they observe:

| the surface reads | what it yields | what it costs |
|---|---|---|
| the peer's **live state** | a **fact** | whoever owns that peer must build it |
| the peer's **own reply** | a strong **inference** | naught — the reply is already on disk |

⇒ a design that rules out the second because it is *"brittle"* has graded an **ad-hoc scrape**. where
the reply stream is a **shipped, contracted, directioned** surface, that grade is wrong, and the
candidate list that carries it is short one option.

🔴 **and the second-order point is the durable one.** a ruling that changes the **vocabulary** a value
is declared in changes the price of **every** candidate that compares that value — in both
directions. a candidate whose compare stays *within* the new vocabulary gets cheaper by the same
edit that makes a cross-vocabulary candidate dearer.

⇒ so a ruling recorded only as a cost against one option is a ruling recorded **half**. the sweep it
owes is: **after any change to the vocabulary of a declared value, re-grade every candidate that
reads it — not merely the one the change was noticed on.**
