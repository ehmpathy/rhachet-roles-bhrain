# 🌙 dream: `condense` is pre-approved in permissions and does not exist

**kind**: entool · **owner**: `ehmpathy/rhachet-roles-ehmpathy` (the mechanic role that publishes the permission set) · **caught** 2026-08-31

## .the cue that fired

`rule.always.reuse-pavement-before-improvise` fired at authorship: seventeen briefs needed a
condensed sidecar, and the repo's own permission set names a skill that does exactly that. five
patterns are pre-approved:

```
npx rhachet run --skill condense
npx rhachet run --skill condense --from briefs/rule.md
npx rhachet run --skill condense --from briefs/rule.md --mode plan
npx rhachet run --skill condense --from briefs/rule.md --mode apply
npx rhachet run --skill condense --from briefs/rule.md --onVerify restore
```

so the pavement is not merely documented — it is **pre-authorized**, which reads as the strongest
possible signal that it exists.

## .the gap, precisely

it does not exist.

```
$ rhx condense --from <brief> --mode apply
BadRequestError: no skill "condense" found in any linked role
```

and a glob for `**/condense*` across the worktree and its linked roles returns **zero files**.

🟡 **this is the second instance of one class, which is what makes it worth a dream rather than a
note.** the first was `rhx catch.dream`, named by a brief as the way to catch a followup, and
likewise absent. n=2.

⇒ **the class: a documented or pre-approved instruction that names a skill which does not exist.**
it is the **phantom path** — `rule.always.reuse-pavement-before-improvise`'s own named failure mode
— committed by the tool layer rather than by a brief's prose.

and it is the **worst** shape of that failure, because a pre-approved permission is a stronger
promise than a citation. a reader who greps for the skill and finds none concludes their own setup
is broken, not that the promise was empty.

## .the shape of the fix

two candidate repairs, and they are not exclusive:

1. **publish the skill** — if `condense` was intended and never shipped, ship it. the measured
   ratio it would need to hit is on record: extant hand-written pairs run 17%–38% of source size,
   and a mechanical pass must beat a hand-written one to be worth the call
2. **prune the permission** — if it was withdrawn, the five pre-approved patterns are stale and
   must go with it. a permission for an absent skill is a promise with no artifact behind it

⇒ **and the durable half is a check, not either repair.** the permission set is a declared list of
command patterns; the skills are a declared set of files. **a lint that intersects the two would
catch this class mechanically**, and would have caught `catch.dream` as well.

that check is the entoolment the two instances argue for — per
`rule.always.entool-the-skills-you-touch`, the leftover work here was *"grep for the skill, fail,
then write seventeen files by hand"*, and that is exactly the glue a tool should have removed.

## .why it is not done in this round

**owner**: the permission set is published by `rhachet-roles-ehmpathy`'s mechanic role, and the
skill (if it is to exist) belongs to whichever role declares it. **a tree adopts only what is
scoped to its own repo** — this is scoped to neither this repo nor this behavior.

**scope**: this behavior is briefs-only by its wish's hard bound. a skill and a lint are both code.

⇒ caught rather than dispatched: the radio is one-way this round, so `.dream/` is the local queue.
