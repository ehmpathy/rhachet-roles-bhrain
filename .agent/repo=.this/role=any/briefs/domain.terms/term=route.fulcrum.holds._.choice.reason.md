# domain.term.choice.reason: holds

## .etymology

a fulcrum is the point a deferral **rests on**; the concerns it carries are what it **holds** up. the
halt reads the field aloud to a human (`holds: lane/i001/blocker.1`), so the verb reads as a sentence:
this fulcrum holds that concern.

| word | what it loses |
|---|---|
| `covers` | it reads as an insurance span, a range rather than named items |
| `backs` | it collides with the dispute itself, which is what a fulcrum backs |
| `concerns` | it is the noun for the item held (`term=route.guard.review.given.concern`), so a field of that name would hold itself |

## .evidence

invariant 4 requires the halt to show a human what each deferral holds. the dispute path refuses a
fulcrum whose `holds` omits the concern (`assertFulcrumFitsDispute`), and the approval halt prints
the field per entry. both read one value, so one word.

## .the invariant

a dispute of `<reviewer> <ordinal>` cites a fulcrum ⟹ that fulcrum's `holds` carries an entry that
starts with `<reviewer>/` and ends with `/<ordinal>`.
