# 8.dogfood.reminder — yield

a live, end-to-end proof of the RouteReminder daemon against rhachet **1.47.6**, whose
`clone say` gained a screen read channel over the input triple (upstream PR #548, which
cites and closes the defect this repo reported as `ehmpathy/rhachet#527`).

`7.dogfood` proved the daemon's crash-loud self-exit held up under that upstream defect.
this stone proves the path `7.dogfood` could not: a **clean tick delivery** into a live
session.

## the session under proof

- clone `@:a8cbca64` (serial `a8cbca64-083d-4097-85d2-3e4fe2a0fb5c`), state LIVE
- freshly enrolled on rhachet 1.47.6 — so it answers the new screen probe
- route `.behavior/v2026_08_07.driver-cron`, live on stone `8.dogfood.reminder`

## 1 — the upstream fix, verified directly

a self-say against the fresh clone, read as machine output:

```
$ rhx clone say @:a8cbca64 --what "..." --output json
{ "delivered": true, "verdict": "enqueued", "reason": null, "probe": "capable", ... }
```

exit **0**. on 1.47.5 this exact case threw `MalfunctionError` ("did NOT leave its input
buffer") — a **false failure** on a message the brain had safely queued. the verdict is now
`enqueued` on a `capable` probe, and `enqueued` is a success channel.

the root cause the upstream fix names matches the corrected diagnosis this repo filed:
`released` formerly won on a transcript rise **alone**, so `enqueued` was unreachable in
production. it now also requires an empty queue.

the new read channel answers directly too:

```
$ rhx clone get @:a8cbca64 --what queue
😶 @:a8cbca64 — the queue is empty
```

a prior local stopgap — a raised `CLONE_SUBMIT_DELAY_FLOOR_MS` in the 1.47.5 install — is
moot and gone: the upgrade pruned that install entirely. upstream kept the floor at 50ms and
replaced the blind sleep with an **observed** commit (`CLONE_SUBMIT_READY_BUDGET_MS`), whose
own docblock records that no safe blind value exists. so the delay-floor instinct found a
real symptom and the wrong cure; observation was the cure.

## 2 — the daemon lifecycle, live

| step | evidence |
|---|---|
| auto-register | `rhx route.drive` on the live route findserted the daemon itself — **pid 115488**, with no manual `gen`. this is vision-Q9's auto-wire, proven live. |
| liveness | `rhx route.reminder.get` (zero flags — both route and clone addr auto-derived) reported `reminder is live — daemon pid 115488` |
| **tick delivery** | the daemon's tick injected `🗿 you can do it! drive on, fulcrum, and converge` into THIS session, observed as a real queued input. the nudge landed. |
| clean tick | the session's daemon log is **0 bytes** — no fault, no crash entry. the prior session's log, from the 1.47.5 era, holds **7927 bytes** of the repeat false failure. |
| per-session handle | the handle is `daemon.of=reminder-driveon.session=~40~3aa8cbca64-…{pid,log}` — keyed on route AND clone, so two sessions on one route never collide (Q10) |

the 0-byte-vs-7927-byte log contrast is the whole before/after of the upstream fix, measured
on the same route by the same daemon code.

## 3 — a residual defect, recorded not silently patched

the upgrade **overloads exit code 2** on `rhx clone say`. two cases now share it:

- **no clone at that address** — `getOneCloneByRef` returns null. verified live against a
  bogus address: `ConstraintError`, exit 2, and `metadata` carries **no** `verdict`.
- **the `withheld` verdict** — the clone is ALIVE but its screen refuses the write (a dirty
  input region where a human mid-types, a modal that holds focus, an unrecognized screen).
  exit 2, and `metadata.verdict === 'withheld'`.

`sayToClone.ts` reads ANY exit 2 as `{ reached: false }` — the dead-session door — so the
daemon would **self-exit** against a merely-busy target instead of skip-and-retry next tick.
a human who types while a tick fires would tear the reminder down for the rest of the session.

the two cases ARE separable: the verdict-carried failure holds `metadata.verdict`, the
dead-session one does not. but the read needs `--output json`, and that is **not a free
change**:

- `peerDependencies.rhachet` is `>=1.41.21`, where `clone say --output json` and the verdict
  metadata do not exist
- `sayToClone.ts` documents, with reasons, that its argv is exactly the vision's command with
  no extra flags — because an unknown flag makes every live call exit non-zero, which this
  wrapper would misread as a dead session and self-exit on every live route

so the honest fix is a peer-range decision, not a one-line branch. recorded as a named
follow-up for the wisher rather than smuggled into this stone (`rule.always.defer-fulcrums-to-last`).

**the follow-up**: raise the `rhachet` peer floor to `>=1.47.6`, then branch exit 2 on
`metadata.verdict` so `withheld` becomes a skip-this-tick rather than a teardown. this also
answers the wisher's earlier ask — "halt the reminder if it sees the buffer has contents" —
since upstream now refuses a say over a dirty input region on its own; the work left is
only to read that refusal as a skip instead of a death.

## verdict

the RouteReminder daemon **works end to end on rhachet 1.47.6**: the drive auto-registers it,
it survives boot, its tick delivers the nudge into a live session with a clean log, and `del`
reaps it with no orphan. the upstream defect that `7.dogfood` had to work around is fixed and
verified at the source and on the wire.

one residual — the exit-2 overload — is named above with its blocker and its fix, and touches
no behavior proven in this stone.
