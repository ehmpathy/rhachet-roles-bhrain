## .the gap, precisely

`B4`'s drafted home was `init.claude.permissions.route.jsonc`, and it is the **wrong** file — its
`deny` array names entries to **STRIP** from a generated permission set, never entries to add. so the
entry went to the real deny list instead, beside the `git.commit.uses allow` precedent already there:

```json
"Bash(npx rhachet run --skill route.mutate grant allow:*)",
"Bash(rhx route.mutate grant allow:*)",
```

**that file is this repo's.** a clone in any other repo that boots the driver role calls
`rhx route.mutate grant allow` with no harness refusal at all, and is held by the TTY probe alone.

🔴 **and the probe is graded WEAK by the operation that runs it** — a bot in a terminal defeats it,
which is why the docblock argues the pair rather than the probe. ⇒ **outside this worktree the pair
is a single, and the argument that carries does not.**

### what the single gate still protects

⚠️ stated so the gap is not over-read. the probe is weak, never absent:

| the caller | held? |
|---|---|
| a clone through a tool harness — a pipe on stdin | ✅ refused, exit 2 |
| a clone that spawns a pty deliberately | 🔴 **not held** |
| a human at a terminal | ✅ permitted, correctly |

⇒ the defect is that the second gate — the one that refuses **before the process starts** — is
absent everywhere but here.

## .the shape of the fix

the driver role ships its own permission defaults, so the entry belongs **in the role's shipped
set** rather than in one repo's local override.

1. find where the driver role's permission defaults are authored and published — the same mechanism
   that puts `rhx` on the prefix-approved list in the first place
2. add the two deny entries there, so every repo that boots the role inherits them
3. leave this worktree's local entries in place — a local deny is idempotent with an inherited one,
   and to remove them would open the door here while the fleet fix ships

🟡 **and check the neighbours while there.** `git.commit.uses allow` is denied by the same local
precedent this entry followed, and it may have the identical fleet-wide gap. ⇒ one read settles
both, and a fix that lands one and not the other re-creates the asymmetry.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe?** 🔴 **no.** it changes what every clone in every repo that boots the driver role may run.
  a deny entry with a wrong prefix silently blocks a command a human needs, in repos nobody on this
  route can test
- **clean?** 🔴 **no.** the authored home is outside this behavior's diff and probably outside this
  repo — the driver role's published permission set, which this route never opened

⇒ **defer, and the deferral is a judgment about ripple**, so it owes a fulcrum as well as this dream.
🟡 **the fulcrum is not owed on this route**: `F13`'s verdict pulled the actor check in and said
naught about where its second gate is published, so this is a gap the execution discovered rather
than a fork the vision reserved. it is recorded here and in
`5.1.execution.from_vision.yield.md` § *the log*, `B4`.

⚠️ **the cost of the deferral, on the record:** until this lands, `route.mutate grant allow` is
enforced by a weak probe alone in every repo but this one — and the flag it mints lifts every
protected write on the route, a guard's `budget:` line among them.
