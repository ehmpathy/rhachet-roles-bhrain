# 🌙 dream: the `reviews` array conflates "this reviewer RAN" with "this is its render artifact"

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-16

## .the cue that fired

a drive of stone `5.3.verification` hit a stable level-unlock deadlock. the first repair
reached for the obvious in-process test for *"did this reviewer run this pass?"*:

```ts
const freshReview = reviews.find((r) => r.index === pr.index);
```

it is wrong, and it looked right for long enough to ship a fix that did not work.

## .the gap, precisely

`reviews` is not a log of reviews that RAN. a level's settle pushes the artifact each
member should **DISPLAY**, and for a member skipped for want of budget that is its own
stale cached review:

```
runStoneGuardReviews.ts
  ~:829   const reviewForDisplay = cached ?? (await getLatestReviewArtifactForSlug(...))
          if (reviewForDisplay) artifactByIndex.set(pr.index, reviewForDisplay)   ← SKIPPED lane
  ~:968   artifactByIndex.set(outcome.value.index, outcome.value.artifact)        ← RAN lane
  ~:1002  if (artifact) reviews.push(artifact)                                    ← both, merged
```

⇒ **a skipped reviewer IS in `reviews`**, indistinguishable from one that ran. so
`!reviews.find(...)` reads a skipped reviewer as a run, and any predicate built on it
inverts for exactly the case it was written for.

**checkable evidence:** in `computeVerdicts`, disable the
`exhaustedReviewerSlugs.includes(pr.slug)` clause and leave the
`!artifactThisPass && rounds >= pr.budget` floor. run
`blackbox/driver.route.peer-budget-exhaustion-unlocks-level.acceptance.test.ts` —
**8 assertions go red across `[t2]`, `[t3]`, `[t4]`**, the hash-CHANGED cases among them,
which that floor was written to cover and does not.

## .why it is not done in this round

- **SAFE:** no. the array feeds the guard tree, the judge tally, and the verdict
  computation. to split it changes what three consumers read.
- **CLEAN:** no. it ripples through `artifactByIndex`, the settle loop, `computeVerdicts`,
  and every consumer of the returned `reviews` — well past the diff this stone opened.
- **the live defect is already closed:** the authoritative `exhaustedReviewerSlugs` set is
  read first, so the deadlock cannot recur. what stays open is the **trap**, not a defect.

⇒ the round's own fix-forward was the affordable half: the variable is renamed
`artifactThisPass` (never `freshReview`), and the conflation is recorded at the read site
so the next reader is not misled the way this one was.

## .the shape of the fix

part the two facts at the source rather than at each reader:

```ts
const artifactByIndex = new Map<number, ReviewArtifact>();   // what to RENDER
const ranThisPass     = new Set<number>();                   // who actually RAN
```

populate `ranThisPass` only where a lane settles from an execution (the `outcome.status
=== 'fulfilled'` merge), never from the `reviewForDisplay` skip path. then
`computeVerdicts` can ask the question it means to ask — `!ranThisPass.has(pr.index)` —
and the `exhaustedReviewerSlugs` set becomes a corroboration rather than the sole load
bearer.

🟡 **and audit the other readers while there.** any consumer that treats a `reviews` entry
as proof of a run carries this same defect silently — the judge tally and the guard tree
should each be checked against which of the two facts they actually want.
