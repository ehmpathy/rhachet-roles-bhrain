# experience dimensions — the status line reads a cached route file

## .the actors

| actor | encounter |
|---|---|
| **seat** (a human in front of one claude code session) | reads the line at every repaint |
| **driver** (the brain on a bound route, and the guard process that acts for it) | moves the route via `route.stone.set`, `route.bind.set`, a guard review round, `route.drive` |
| **box** (the host that runs 44 seats) | pays the cpu of every repaint |

## .the dimensions

| # | dimension | positions |
|---|---|---|
| D1 | bind | bound-once · bound-many (two or more flags on the branch) · unbound · unknowable (a detached HEAD, no `.git`) |
| D2 | route file, as the reader finds it | fresh · stale (a `.route/` ledger newer than it) · absent · unreadable (torn or unparseable) |
| D3 | trigger | repaint · route moved (a passage, a review round, a promise, a bind or stone change) |
| D4 | seats that read one route | one · many |
| D5 | the status write | lands · faults (EACCES, ENOSPC, EROFS, …) |
| D6 | writers of one route at once | one · many (a guard round and a stone set race) |
| D7 | reader reachability, from the harness command | linked (the role link stands, cwd at the root) · unlinked (`rhx init` removed the role link) · cwd drifted (the seat's cwd sits below the root) · never linked (no status line command in the settings) · node-era (the settings still hold the `node -e` command bound before the bash reader, until the seat's next `rhx init`) |

D1 × … × D6 = 4 × 4 × 2 × 2 × 2 × 2 = 256 cells per D7 position; × D7 = 1280.

each cell is a tuple of single positions. a move *causes* a change of D2 (say, fresh to stale on a
fault); the cell records the state the seat's next repaint finds, and the inventory's experience
column names the move that led there.

a seat's first repaint is not a position of D3: a seat holds no memory of its own, so its first
repaint reads the file exactly as any repaint does.

## .the correlations — stated, not hidden

| dependency | the band | kind | why |
|---|---|---|---|
| D1 ∈ {unbound, unknowable} → D2 has no value | unbound/unknowable × any D2 | impossible — nature | no route, so no route file exists to hold a state; the reader prints blank |
| D1 ∈ {unbound, unknowable} → D5, D6 have no value | unbound/unknowable × any D5 or D6 | impossible — nature | no route on this branch, so no write this seat reads |
| D3 = repaint → D5, D6 have no value | repaint × any D5 or D6 | impossible — nature | a repaint writes no file; only a move writes |
| D5 = lands → D2 = fresh | lands × {stale, absent, unreadable} | impossible — nature | a landed write is the newest file, whole by temp + rename; under D6 many the re-check makes the last rename carry the newest state |
| D5 = faults → D2 ∈ {stale, absent} | faults × {fresh, unreadable} | impossible — nature | a faulted write leaves the prior file untouched: stale if one stood, absent if none |

bound-many × stale is a reachable cell, not a band: the reader runs no stale test on a fault
record, and the record's claim holds while both flags stand (inventory case 25). where a flag is
removed by hand, the record outlives the multi-bind; that is an accepted blind spot, named in the
inventory.

## .the collapse rules

- **D7 ≠ linked** hides D1–D6 from the seat: the reader never runs, so no route state reaches the
  line. unlinked and cwd drifted collapse onto one row each — the harness command's fallback
  prints `🗿 status line reader not found, rhx init --roles driver` and exits 0. never linked
  shows no line at all, as before this wish. node-era runs the prior node entry, which renders
  each D1–D6 cell with the same words the bash reader prints, but spawns node per repaint; it
  collapses onto one row, healed by the next `rhx init`, which migrates the command to the bash
  reader. so the 256 cells are walked at D7 = linked alone

- **D4 (one · many)** changes cost, never what a seat sees: the read is per seat and lock-free, so
  each seat's view equals the one-seat case. the many column carries the box's experience (cpu).
- **D5 faults** leaves the prior file in place, so the next repaint finds D2 = stale (or absent, if
  none was written before).
- **D6 many** is safe only if the last rename carries the newest state. the race: writer A renders,
  writer B appends and renders a newer state, B renames, then A renames last — the file holds the
  older line with the newest mtime, so the stale test cannot see it. the cure, owed by every
  writer: after its rename, re-check the ledgers it rendered from; if any grew since its render
  began, render again. each writer converges on the ledgers as they stand when it last looks, so
  the last writer to finish holds the newest state (fulcrum F7).
- **D6 many × D5 faults**: a racer whose write faults leaves the other racer's rename in place.
  if the faulted racer held the newer append, its ledger is newer than the file, so the stale test
  fires and the seat sees case 5. a race on a multi-bind renders the same fault record twice, so
  the bytes match whichever renames last (case 28).

## .render states — the render's axis, held constant by construction

the line's own state (yield · review.self · review.peer · judge · approved? · exhausted · blocked ·
malfunction · complete) is an axis the *render* owns, not this wish. the writer calls the extant
renderer, so each state's words are byte-equal to today. what this wish does own is that each
state *reaches* the file: every halt and every pass is a passage, written through
`setPassageReport`, the writer's hook. the inventory demos that (case 10) and cites the snapshots
that already pin each state's words.
