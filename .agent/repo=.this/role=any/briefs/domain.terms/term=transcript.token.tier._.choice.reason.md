# domain.term.choice.reason: tier (transcript.token)

## .etymology
the four values are ordered, and each one below the first adds an assumption: a tier of evidence.
each inventory row lists the tiers its blocks were counted at, so a reader sees how much of a row
is read off the meter and how much is inferred.

chosen over `confidence` (implies a probability; the tiers are discrete methods, not odds),
`precision` (implies a numeric tolerance), `level` — already declared as `route.guard.level`,
a step on the review ladder — and `rung`, already declared as `route.guard.rung`. a second
`level` or `rung` would overload a declared term.

## .the line against `route.guard.level` and `route.guard.rung`
both name a step on a review ladder; a token tier is a method of count. no shared boundary, no
shared sense — neither ever meets a tier in one contract.

## .evidence
- invariant: `measured` ≥ `exact` ≥ `apportioned` ≥ `unattributed` in firmness; a block holds one
- the acceptance snapshot shows a row's tiers as `[apportioned, exact]` beside its count
