# .dream/ 🌙

this folder catches **dreams** — followups you noticed mid-flow and did not do.

it is a flat, repo-wide queue. the rule that governs what lands here is
`rule.always.catch-dreams-for-followups` (learner); the shape a dream takes is
`term=artifact.dream._.choice._.md`.

## .catch a dream

**write the file directly.** the name is coordinates, never prose:

```
.dream/v$YYYY_MM_DD.$kind.$slug.md
```

| `$kind` | what it means |
|---|---|
| `fix` | a defect in this repo, deferred |
| `enbrief` · `enskill` · `entool` | pavement this repo owes itself |
| `reseed` | 🔴 an ask owned by **another repo** — it must be transmitted, or it never arrives |
| `amend` | a correction to a seed already pushed |

each dream states: **the cue that fired** · **the gap, precisely** (with checkable evidence) ·
**the shape of the fix** · **why it is not done in this round**.

🟡 **name the owner in the header.** it decides whether `.dream/` is the whole queue or merely a
holding pen — see the transmit rule below.

## .link it back to the route that found it

`.dream/` is flat, so a dream dropped here loses the round that found it. the symlink is what keeps
the provenance, and **its location IS the record** — no prose citation to drift:

```sh
rhx symlink --at "$route/dreams/v$date.$kind.$slug.md" \
            --to ".dream/v$date.$kind.$slug.md" \
            --mode relative --idem findsert
```

## 🔴 .transmit every `reseed`

a dream owned by **this** repo is done — `.dream/` is its queue.

a dream owned by a **peer** repo is not. it must reach the tree that can serve it:

```sh
cat .dream/<the-file>.md | rhx radio.task.push --via gh.issues --into <owner/repo> \
                    --title '<the ask, in one line>' \
                    --description @stdin --idem findsert
```

🔴 **use `cat file |`, never `< file`.** an input redirect is **auto-declined by SHAPE**, for every
caller — refused before the push is even considered, so the decline reports naught about whether your
seed was authorized. **the `cat` is deliberate here; *"useless use of cat"* does not apply.**

⚠️ **a decline is not a refusal of the ask.** read `rhx radio.uses get` before you conclude a human
must intervene — if the meter says allowed, the defect is in your shell form and the fix is yours.
⇒ measured 2026-09-04: this readme taught the redirect form, and that form cannot run.

then record the transmit in the dream's own header — `✅ DISPATCHED <date> — <repo> #<n>, QUEUED` —
so a later reader can tell a caught dream from a delivered one without a query.

🟡 **check `rhx radio.uses get` first.** a human may hold a global blocker; if it stands, the dream
waits here and the transmit is a later sweep. **do not route around it.**

## 🔴 .prune a delivered dream — the marker is a WAYPOINT, never a home

once the ask is live in the tracker of whichever repo owns it, **that tracker is the queue.** a copy
kept here is a second queue, and a second queue can only drift from the first.

```sh
rhx globsafe --pattern '.dream/v*.md'                    # 1. the queue
rhx grepsafe --pattern 'DISPATCHED' --path .dream        # 2. which are delivered
gh issue list --repo <owner/repo> --state all            # 3. 🔴 VERIFY each one is live
rhx rmsafe --path '.dream/<the-file>.md'                 # 4. then, and only then, prune
rhx rmsafe --path '<route>/dreams/<the-file>.md'         #    …and its route symlink, or it dangles
```

⚠️ **verify BEFORE you delete, never after.** a delete on an unverified dispatch destroys the only
copy. and a dream staged-but-never-committed leaves **no diff at all** when removed — so its delivery
record must land somewhere tracked (a stage yield) *first*.

🔴 **re-read the dream before you send it, never merely its marker.** a dream held for days can be
falsified by events, and the delivered ask is what the repo that receives it acts on. measured
2026-09-07: one reseed's ask gained a whole clause between catch and dispatch, because the sweep it
recommended had since crossed into a glyph register.

⚠️ **a broken symlink is invisible to `globsafe` and visible to `git`.** after a prune, check
`git status` on the route's `dreams/` dir — the glob will not show you what you left behind.

⇒ **why this step exists:** `git log --diff-filter=D -- .dream/` returned **empty** for the whole life
of this folder. with no prune, `.dream/` is an accumulator rather than a queue, and a reader cannot
part a delivered dream from an owed one without an open of every file.

## 🔴 .mark a DELIVERED dream — and keep it, where a dispatched one is pruned

the two sections above trace a **`reseed`**'s journey out of this repo. a **`fix` this repo serves
itself, in the round that caught it**, reaches neither of them: it is never dispatched, and the prune
rule fires only *"once the ask is live in the tracker of whichever repo owns it"* — **an in-round fix
has no tracker.**

```md
- **status** = ✅ **DELIVERED <date>**, on <behavior> at stone <stone>

## ✅ .delivered
| what | where |
|---|---|
| the clamp | <the regression test that goes red without the fix> |
| the fix   | <the operation, and its call site> |
```

⚠️ 🔴 **keep it. do NOT prune it.** that is the whole difference from a dispatched dream:

| | the queue afterward | so the local copy is |
|---|---|---|
| **dispatched** (a peer owns it) | the peer's tracker | 🔴 a **second** queue — prune it |
| **delivered** (this repo served it) | 🔴 **none — the code is the record** | ✅ the **only** record — keep it |

⇒ **measured 2026-09-08:** exactly one dream in this folder carries a status field, and it **coined**
that field because no contract offered one. the marker is now declared in
`term=artifact.dream._.choice._.md` as the third state, beside `caught` and `dispatched`.

⚠️ **the cost this closes is the one stated above, one clause further out.** *"a reader cannot part a
delivered dream from an owed one without an open of every file"* — the prune rule closes that for a
reseed. for an in-round fix it stayed open, so a later traveler picks up a served ask and re-derives
it before they learn otherwise.
