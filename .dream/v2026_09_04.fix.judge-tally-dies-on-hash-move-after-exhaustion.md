## .the gap, precisely

`judge.1` (`--mechanism reviewed?`) reads review files **at the current artifact hash**. an
exhausted reviewer is skipped by `runStoneGuardReviews.ts`'s
`if (isReviewPeerVerdictExhausted(verdict))` branch, so it writes no given at a new hash.

⚠️ **this cited `:441` until 2026-09-08, and `:441` is the `continue;` of the CLEAN-CACHE
fast-path** — a different skip, twenty lines above the one meant. ⇒ the number was plausible, in the
right file, and pointed at the wrong branch; the expression cannot.
one edit after every reviewer exhausts therefore yields an empty tally, and the stone blocks with a
message that reports absence where the true state is *"clean, cached, and terminal."*

**reproduced first-party:**

| step | state |
|---|---|
| i006 | both reviewers `6/6`, `0 blockers`, `1 + 0 nitpicks` · `judge.1` ✅ **passed** |
| — | one artifact edit; hash → `796b200c` |
| i007 | both `exhausted 🌙, cached`, same clean verdicts · `judge.1` ❌ **`no review files found`** |

⇒ **the wish listed this exact string as an unexplained `passage.jsonl` entry** (*"two `no review
files found for hash` entries were not investigated"*). this is its cause.

## 🔴 .why it is not covered by the behavior that caught it

it is **D2's defect class one layer up**:

| | the read | what an edit discards |
|---|---|---|
| **D2** | givens, keyed `(slug, hash)` | an unanswered blocker |
| **this** | the judge's tally, keyed by hash | a clean, cached, terminal verdict |

**P2 does not reach it.** P2 re-keys *contemplation* to the reviewer; the `reviewed?` judge is a
separate read that P2 never touches. to widen that behavior's scope to cover this would fold two
distinct fixes into one stone.

⚠️ **this dream was caught the day before that settlement, so its fix-shape below reads as a guess. it
is no longer one.** a judge grades the newest verdict each reviewer has **spoken** — *"latest"* is a
property of the **reviewer**, never of the hash. a verdict is superseded by that reviewer's next
word, and by no other event.

⇒ so the row this dream reports — *"clean, cached, and terminal"* read as *"there are none"* — is not
merely a hazard to weigh. **it is a violation of a settled invariant.** whoever picks this up
implements the property; the only open call is which shape carries it.

## .the shape of the fix

the guard already holds what the judge cannot find — the same emit renders `cached` verdicts for
both lanes. so the likely repair is to have the judge **read the guard's resolved lane state**
rather than re-derive a tally from files at the current hash. absent that, the same latest-per-slug
read P2 introduces would serve here too.

⚠️ **a third shape was surfaced after this dream was caught, and it may dominate both** — per-reviewer
cache keys, the wish's own `.scope` item #1. `input.scope.json` already records each reviewer's exact
`targetFiles`, so *"latest"* could mean **latest still valid** rather than *latest ever*. that repairs
the cause instead of the tally, and it is what keeps reviewers off exhaustion in the first place. the
full argument, with the two shapes it displaced, is in
`.behavior/v2026_09_03.fix-contemplation-gate-on-entrance/review/handoff.v1.to_wisher.the-judge-tallies-one-hash-not-the-latest-review.md`.

⚠️ **check whether `malfunction` shares this cause** before you scope it — the wish reports two
`malfunction` entries alongside the two `no review files found` entries, and a common origin is
plausible but unverified.
