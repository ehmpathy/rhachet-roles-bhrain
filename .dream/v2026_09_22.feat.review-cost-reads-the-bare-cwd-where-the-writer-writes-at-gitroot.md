## .the gap, precisely

`--at` defaults to `process.cwd()`, and both tree-scoped breadths read it bare:

```ts
// getAllReviewRunMeters.ts  /  getOneReviewRunMeterLatest.ts
const root = asReviewLogsDir({ cwd: input.cwd });   // = path.join(cwd, '.log/bhrain/review')
```

so from `my-tree/src/`, the command reads `my-tree/src/.log/bhrain/review`, finds naught,
and refuses — over a tree whose reviews all sit in `my-tree/.log/bhrain/review`.

🔴 **the argument the lane did not have is that the WRITER never writes anywhere else.**
`rule.forbid.cwd-outside-gitroot` is a declared rule of this repo:

> *"never change cwd outside the git repository root. all subprocess and file operations
> must use repoRoot as cwd."*

⇒ so a nested read is not merely inconvenient — it reads a path the writer is
**forbidden** to write to. the bare-cwd default can therefore only ever find logs when
cwd happens to equal the git root, which makes the nested case a guaranteed miss rather
than a plausible one.

### checkable evidence

- `getAllReviewRunMeters.ts` / `getOneReviewRunMeterLatest.ts` — both call
  `asReviewLogsDir({ cwd })` with no resolution step
- `review.ts` — the peer command, bare `process.cwd()`, same shape
- `getRepoRootWithFallback.ts` — the proven walk-up idiom this repo already carries,
  reached for under `route/guard/` and not here
- `reviewCost.acceptance.test.ts [case7]` — the clamp that pins the current behavior, so
  a change to it goes red rather than slips

## .the shape of the fix

resolve the DEFAULT only; never touch an explicit `--at`.

```ts
const at = readOfAt.state === 'set' ? readOfAt.value : getRepoRootWithFallback();
```

three properties the fix must keep:

1. **an explicit `--at` is honored verbatim.** a wisher who points at an arbitrary tree —
   or a non-git dir — must get exactly that path, with no walk
2. **the fallback must be a FALLBACK.** outside a git repo, `getRepoRootWithFallback`
   answers the cwd, so the command degrades to today's behavior rather than throws
3. **`--of grove` is untouched.** its `--at` is a grove ROOT (a dir of worktrees), not a
   tree, and a git-root walk would be wrong for it

and the refusal's `looked in:` line must still echo the **resolved** root, so a driver
can see where it read.

### 🟡 the cheaper third option — a HINT rather than a walk

named by the i008 peer lane (`enroll-impl-behavior-intent`), and it is a real option this dream

> *"a driver who just ran a guard from a subdirectory and immediately types `rhx review._.cost`

```
   ├─ 🔭 found reviews 2 dirs up — did you mean the tree root?
   │     rhx review._.cost --of tree --at /my-tree
   └─ why: review logs are git-ignored ephemera, local to the machine that ran them
```

## .why it is not done in this round

**SAFE — no.** it moves where two shipped breadths look, and the peer `review.ts`
command reads the cwd the same way. to change one and not the other trades an
inconsistency between cwd and gitroot for an inconsistency between two peer commands,
which is a worse shape and a decision no lane has ruled on.

**CLEAN — no.** the honest fix touches both commands, their shared default-resolution,
and the acceptance clamp — and it opens a question the branch never asked: does `review`
itself owe the same walk-up? that is a `review` contract question, and this branch's
declared bound is *"it does not change any rubric, any guard, or any lane's bind."*

⇒ so the clamp ships and the behavior does not. the convention is now checkable, the
argument to change it is on record, and the next traveler inherits both rather than
re-derives either.
