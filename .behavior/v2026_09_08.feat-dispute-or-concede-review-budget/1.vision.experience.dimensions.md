# 1.vision.experience.dimensions

the experience space of the peer-review **stance gate**, factored into orthogonal axes and walked as
a product. the cells are verdicted in `1.vision.experience.case=_.md`.

## .the axes

### A — the move (9)

the act performed at or around the gate. **the actor is implied by the move**, because actor and
move do not vary independently here — a `--as disputed` is a driver act, an `--as overruled` a human
act. two correlated axes are one axis (`howto.experience.decompose`), so they are merged.

| value | actor | what |
|---|---|---|
| `enter` | driver | `--as passed` / `--as arrived` — asks to proceed through the gate |
| `answer` | driver | `--as contemplated --that <slug>` — records the reply to each point |
| `dispute` | driver | 🔴 `--as disputed --with <reviewer> --about <concern> --why <fulcrum-path>` — *"this ONE concern is fine to continue"*. the path must point at a fulcrum entry the driver authored (`S05`) |
| `concede` | driver | 🔴 `--as conceded --with <reviewer> --about <concern>` — *"the reviewer is right on this ONE; I will fix it"* |
| `top-up` | driver | `rhx route.guard.budget --for review --add N [--peer <slug>] --stone <stone>` — 🟡 `--peer` scopes it to one lane; the bare form extends every lane on the stone |
| `reviewer-runs` | system | a peer-review subprocess executes and writes a `.given` |
| `forgive` | human | `--as overruled --level N` / `--as approved` — lifts a gate the driver cannot. 🔴 **the lane's state is untouched** |
| 🔴 `rewind` | human | `--as rewound` — **deletes** the stone's givens, resets the peer meters, and so **voids the stance** |
| `rule` | human | at the end-of-route council: reads `.fulcrums/` and rules on a disputed call |

#### 🔴 `rewind` is a value SPLIT OUT of `forgive`

the test is *"if a value spans two concepts, split it"* — and one `forgive` implied two experiences
that are **opposite**:

| the human lever | what it does to a **disputed** lane |
|---|---|
| `forgive` — `--as overruled` / `--as approved` | 🔴 **the lane stays quiet for this generation.** the skip survives it (`case=4` `[t3]`) |
| 🔴 `rewind` — `--as rewound` | 🔴 **the lane comes back live at once.** `delStoneGuardArtifacts` deletes the givens, and invariant 3 keys a stance to the slug's latest given — so with none, there is no stance (`case=8` `[t4]`) |

🟡 **`S03` narrows the gap and does not close it.** an artifact edit brings a `forgive`-d lane back
**next generation**; a `rewind` brings it back **now**, and resets the meters besides. ⇒ *"survives a
human lever"* and *"voided by a human lever"* stay opposite, which is the test the split turns on.

⇒ **one `forgive` value would model a semantic that matches neither half**, with both outcomes
carried in prose rather than as coordinates — exactly the failure the walked product exists to
prevent.

🟡 **the split costs 15 cells and no forbidden cell.** `rewind` is a human lever, so like `forgive`
and `top-up` its whole slab is permitted — the 28-cell refusal arithmetic is **untouched**, since
every refusal class is a product over the stance moves and `enter`.

#### the values folded or set aside

| candidate | why not |
|---|---|
| `approve` as its own value | **folded into `forgive`.** both are human gate-lifts, and they verdict identically at every B × C. their real difference — a level vs the stone — is off this grid (F10) |
| `edit-code` | set aside. its whole slab is permitted and **unchanged** by this behavior; the prior route already walked it and found *"the invariant does not forbid the edit, it forbids the re-entry"* |
| `stop` (the stophook) | set aside. it consults the stone's state; this behavior moves no stophook copy, so the slab is uniformly permitted |

⇒ **each set-aside value is recorded, never merely dropped.** if a later round makes `stop` render a
stance prompt, this note is the trigger to add the **tenth** value and re-walk. 🟡 **a count in prose
beside a count in a table is a stale-duplicate waiting to happen** — this route caught the class four
times.

### B — the debt state (5)

the state of one reviewer's critique, before the move. **keyed to the reviewer's latest `.given`**,
per `getLatestPeerGivensPerSlug`.

| value | what |
|---|---|
| `clean` | 🔴 the latest given's **verdict does not hold the road** |
| `unanswered` | the verdict holds the road, and a `.taken` is **owed and absent** |
| `answered` | 🔴 the verdict holds the road, **every owed answer is written**, and no stance is declared |
| 🔴 `disputed` | answered, and the driver declared `--as disputed` **against this given** |
| 🔴 `conceded` | answered, and the driver declared `--as conceded` **against this given** |

🔴 **both keys read the VERDICT, never the raw blocker count** (`F12`). a count-keyed `clean` would
be `F015` fork A's predicate — so the grid would be built on A and then cited as independent evidence
**for** A.

| the lane | under a count-keyed B | 🔴 under the verdict-keyed B |
|---|---|---|
| 8 nitpicks, 0 blockers, `--allow-nitpicks 7` | `clean` — no stance owed, **stone passes** | `answered` — a stance is owed, and the halt fires |

⚠️ **the count-keyed read ships a defect**: the judge refuses that stone
(`computeReviewThresholdVerdict.ts:23-27` counts nitpicks), so the grid would say *permitted* where
the engine says *held*. ⇒ **the verdict key adds no cell and moves no verdict** — it widens two
definitions, and the nitpick lane lands where it belongs.

🟡 **`answered` now means *every OWED answer is written*, which covers two roads to one state:** a
`.taken` per blocker, **or** no blocker and so no `.taken` at all. a nitpick-only lane takes the
second road — the debt predicate (`blockers > 0`) never enrolls it, so invariant 2 passes
**trivially** rather than fails.

🔴 **every value here is read against the lane's LATEST given, never against the stone.** that is
invariant 3's key, and it is what makes the axis survive the wisher's per-generation verdict
(`S03`): when the artifact moves, a new given is minted and the lane falls back to `unanswered`,
whatever stance stood before. ⇒ **a lapse is a MOVE ALONG THIS AXIS**, never a fourth stance value —
which is why `S03` cost the grid no cells.

🔴 **`answered` is the cell this behavior exists for.** today it is the terminal state of the
driver's own effort and it **still holds the stone** — there is no move left but a human's. after
this behavior it is the state that owes a stance.

⚠️ **`disputed` and `conceded` are two values, not one `stanced`.** the whole wish turns on their
difference: `enter × disputed` is permitted and `enter × conceded` is forbidden. a merged value
would hide the one invariant this behavior creates (F10).

### C — the reviewer's budget state (3)

| value | what |
|---|---|
| `live` | budget remains; the lane can run again |
| `exhausted` | `rounds >= budget`; `runStoneGuardReviews.ts` skips it |
| `forgiven` | a human overruled its level; `getStoneGuardOverruledLevels` forgives it |

⚠️ **`retired` is deliberately absent**, though the prior behavior's grid carries it. a reviewer
absent from the guard config raises no *new* given, so its debt state is frozen at whatever B held
when it left — and every A × B verdict over it is identical to `exhausted`. ⇒ it would add a
20-cell slab and not one falsifiable claim **this** behavior makes. recorded rather than walked; if
a stance ever needs to distinguish the two, this note is the trigger.

## .orthogonality

| pair | independent? | why |
|---|---|---|
| A × B | 🔴 **independent over 8 of 9 moves — a RESIDUAL non-orthogonality at the 9th** | no move is *impossible* at any debt state, save `rule`, which needs a fulcrum to exist. ⚠️ **that is a whole-row correlation and this table once labelled it "✅ with one exception"** — see below |
| A × C | ✅ **with one exception** | no driver or human move is *impossible* at any budget state. the exception is `reviewer-runs × exhausted` |
| B × C | ✅ **over the two unforgiven C-values** | a debt can sit at any B while the lane is `live` or `exhausted`. at `forgiven` the pair is **degenerate** |

🔴 **the test is IMPOSSIBLE, never FORBIDDEN — and the difference is the whole behavior.**
`enter × answered × live` is a driver move the gate **refuses**, and it is refused at six cells.
that is the invariant this vision creates, not a correlation between the axes: the move stays
attemptable, the engine answers *no*, and the walked product verdicts each cell.

⇒ so a forbidden cell **confirms** orthogonality rather than breaks it.

### the A × B exception — `rule` needs a fulcrum

`rule` is the council's read of a disputed call. **a fulcrum entry is CITED only where a dispute was
declared** (`F018`: `--why` names it, and the path must EXIST), so
`rule × {clean, unanswered, answered, conceded}` is a **12-cell impossible slab**: there is no cited
artifact for the council to read.

🟡 **the slab is an argument about CITATION over existence.** an entry may sit in `.fulcrums/` with
no dispute behind it (a driver may itemize a plain best-guess), so what the council reads *as a
dispute* is the set the ledger's `fulcrum?` field points at.

⚠️ **this is within-axis, never a hidden dimension.** the test: does B constrain the *other eight*
moves? no — `enter`, `answer`, `dispute`, `concede`, `top-up`, `reviewer-runs`, `forgive`, `rewind`
are each attemptable at every B value. **8 of 9 moves are fully independent of B; the 9th is the one
move B is about.** to name a third axis would only restate *"a fulcrum exists"*.

#### 🔴 and it IS a residual non-orthogonality — recorded rather than dismissed

`rule.require.dimensional-decomposition`'s hidden-dimension check reads *"a whole row or column that
cannot occur means two axes were not orthogonal"* — and this **is** a whole row that cannot occur
outside one B value.

⇒ **a ✅ would overstate it.** the honest label is the one in the table: **independent over 8 of 9
moves, with a residual non-orthogonality at the 9th.**

⚠️ **the residual changes no verdict.** no real experience is hidden by it — `rule × disputed` is
walked and demoed at `case=7`, and the 12 impossible cells carry the reason on the page. 🟡 **a
hidden dimension COSTS coverage; a recorded residual costs a claim of tidiness.** only the second
applies here.

### the A × C exception — extant, and it carries F04

`reviewer-runs × exhausted` is a **void column of 5 cells**, true today: `exhausted` is *defined* as
*"does not run"*.

🔴 **and this behavior adds two more impossible cells to that same row** — `reviewer-runs ×
disputed × {live, forgiven}`. under `F004` a disputed lane is skipped for the generation its stance
covers, so the subprocess does not execute even where budget remains. **that is acceptance #2's
coordinate** (*"the disagreement consumes no budget"*), and it is why the `reviewer-runs` row earns a
place at all.

🔴 **the B axis reads the stance against the CURRENT given, and that is what keeps the cell
impossible after the wisher's per-generation verdict** (`S03`). when the artifact moves the lane mints
a new given, and a stance declared against the old one no longer covers it — ⇒ **the coordinate is no
longer `disputed`**, so the lane's re-run is a move within `answered × live`, never a violation of
this void. **the arithmetic is unchanged; only how it is read needed the qualifier.**

⚠️ **that qualifier is not a convenience — it is invariant 3's key.** the stance keys to the slug's
latest given, so *"is this lane disputed?"* is a question about **one generation** at every site that
asks it: the skip predicate, this axis, and `case=8`'s R3 refusal alike.

⚠️ **the two impossibilities are of different kinds:**

| cell | kind |
|---|---|
| `reviewer-runs × * × exhausted` | **extant mechanism** — `runStoneGuardReviews.ts`, true today |
| `reviewer-runs × disputed × {live, forgiven}` | 🔴 **nurture** — created by `F004`. reverse `F004` and the cells return |

### the B × C exception — degenerate rather than constrained

at `forgiven` a human forgave the rung, so no debt is owed and no stance is owed. the B axis
**collapses** there: the stance moves are refused at every B value, and `enter` is permitted at
every B value.

| the claim | accuracy |
|---|---|
| B × C is *independent* | ❌ false at `forgiven` |
| B × C is *dependent* | ❌ overstates — B discriminates fully at `live` and `exhausted` |
| ✅ B × C is **degenerate** at `forgiven` | the pair collapses at one C value; 10 of 15 cells discriminate |

⚠️ **this does not merge the two axes.** a degeneracy at one C value is a property of that value,
never evidence the axes were one all along.

## .the product

**9 × 5 × 3 = 135 cells.** walked in `1.vision.experience.case=_.md`.

🔴 **the `rewind` split added 15 permitted cells and moved the 28-cell refusal arithmetic naught** —
every refusal class is a product over the two stance moves and `enter`, and `rewind` is none of the
three. ⇒ **that invariance is the check**: a split that moved the refusal count would mean the two
values differed in what the **gate** does, rather than in what the **human lever** does.

## .what the walk surfaced

### 1. the stance gate's predicate is the contemplation gate's predicate

**one clause, and it names no count:**

> 🔴 **a stance is owed iff the reviewer's latest given computes `rejected` AND its level is
> unforgiven.**

⇒ that is `computeReviewPeerVerdict`'s own output, plus the overrule check the entrance gate already
runs. **the gate reads what the JUDGE reads**, which is why `dispute × clean` and
`dispute × * × forgiven` are refused rather than merely pointless: there is no verdict to stand
against.

#### 🔴 the two predicates it is NOT, and why

| the candidate | its defect |
|---|---|
| `blockers > 0` — the extant `getAllRouteGuardReviewPeersUncontemplated.ts:31` | ❌ **takes no thresholds.** at `--allow-blockers 3` a 2-blocker lane is **approved** and still trips it, so a literal read owes a stance on a lane that approved you |
| the verdict, **minus a nitpick carve-out** (`F015` fork A) | ❌ **reversed by `S06`.** a dispute is a **TALLY EXCLUSION**, so the predicate is whatever the tally counts — and `computeReviewThresholdVerdict.ts:15-27` counts nitpicks too |

⇒ so an 8-nitpick, 0-blocker lane at `--allow-nitpicks 7` is `rejected` and **owes a stance**. it
sits at `answered` beside the blocker-driven lane; `R2` never fires on it, `R4` does, and R4's
message is already right — *"answered and undeclared — dispute or concede"* (`case=10`).

#### ⚠️ and the WALK could not have caught the second, which is the lesson

axis B was first defined in fork A's own terms — `clean` as *"0 blockers"* — so the nitpick-only lane
sat at `clean`, `dispute × clean` refused it, and the grid read as independent evidence **for** the
predicate it was built from.

⇒ **a walk can only check a call it was not derived from.** the grid's claim to completeness is that
it is **generated** rather than curated — and a generated grid inherits every assumption in its axes,
silently. ✅ **the repair moves the AXIS, never a cell.**

### 2. a latent axis — `stance-agrees?` 🔴

the `dispute` and `concede` rows force it. a second stance on the same given may **agree** with the
first (idempotent) or **contradict** it (a flip-flop). that is a real input with a real rejection.

⇒ **it is an axis, and it is deliberately not a grid coordinate** — it modulates *whether a stance
move succeeds within a cell*, never *which cell* the move lands in. to fold it in would double the
grid to 240 and duplicate every verdict outside two rows. recorded as a rejection invariant (F09),
demoed at `case=8`.

⚠️ this is the same shape the prior behavior's `slug-valid?` took, for the same reason.

### 3. a second latent axis — `why-is-substantive?` 🟡 and two wisher rulings shrank it

`--as disputed --why <path>` takes a **path to a fulcrum entry the driver authored** (`S05` →
`F018`). the path is checked; **no gate reads the entry's content.**

🔴 **the floor is a FILLED TEMPLATE, never one character.** the fulcrum contract demands the fork,
the counter, the `rework` grade, and what would settle it. what stays unmechanized is whether those
sections **argue** aught.

| the residual | its bound |
|---|---|
| an empty `--why` | 🔴 **unreachable.** the argument is a **path**, and the file must EXIST — a blank is refused at the boundary, before any state moves |
| a thin one | 🔴 **bounded by `S03`.** the lane returns next generation, so the loop **is** the correction mechanism here — exactly as for a `.taken` |
| no gate reads it | ✅ **ruled acceptable** (`S04`). the beneficiary is the **author**; a gate cannot improve a mechanism whose action completes before any reader arrives |

⚠️ **it is not a grid coordinate for the same reason as #2** — it modulates success within a cell.
but unlike #2, **it has no invariant to encode**. it stays recorded here as a known, unmechanized
residual — 🟡 **and it is no longer the strongest case against this design.** that title now belongs
to the **repeated** dispute: a lane disputed at every generation is per-stone blindness reached one
round at a time, and no mechanism bounds it.

### 4. the whole `top-up` slab is permitted — all 15 cells

the sharpest claim the grid makes about ownership:

> **the budget lever is never gated by the stance.**

a driver may top up at any debt state and any budget state, before or after a stance, exactly as it
may today. **acceptance #5 is a property of the grid rather than of a new mechanism** — and the walk
is what proves it, because a single forbidden cell in that slab would have falsified it.

### 🔴 5. the axis the walk never CONSIDERED — `concern-count`

the set-aside table below asks whether **`reviewer-count`** earns a coordinate and answers no. **it
never asks `concern-count`** — how many blockers or nitpicks one reviewer raised — and that omission
is what let `S06` land a per-FILE mechanism under a per-POINT ruling (`S05`, one day earlier).

⇒ **a domain with no WORD for a thing cannot have an axis on it.** the design's finest named grain
was the lane; `getReviewCountsViaRegex` returns `{ blockers: number; nitpicks: number }` and no
per-item structure exists anywhere in the engine. so *"the concerns within one lane"* was not a
dimension anybody declined — **it was a dimension nobody could name**, and the walk's completeness
claim is silent about it exactly as it would be about any unnamed thing.

🔴 **`S07` names it: a `concern` is one blocker or one nitpick.** with the word in hand the axis is
askable, and the answer is that it is **not a coordinate either** — but for a reason worth writing
down, over an omission:

| the claim | its fate |
|---|---|
| `concern-count` = {one, many} is an axis | ❌ **no.** it does not decide *which cell* a move lands in — every A × B × C cell is reachable at either count |
| ⇒ so the omission cost naught | 🔴 **false.** it is a **rejection invariant**, exactly like `stance-agrees?` (§2) — and an unnamed axis encodes no invariant, so the mechanism was free to violate it |
| the census moves | ❌ **no.** 135 cells, unchanged |

⇒ **the invariant it encodes:** *a declaration discharges the concerns it NAMES; concerns it did not
name survive it.* demoed at `case=11`.

⚠️ **this is the third latent axis, and the first one the walk MISSED rather than weighed.** §2 and
§3 were considered and set aside with reasons on the page; this one has no row in the table below,
because a walk enumerates the axes its vocabulary permits. ⇒ `F0010`'s completeness claim is *"every
cell of the declared product"*, never *"every dimension the domain has"* — a distinction the entry
does not draw, and now must.

## .axes considered and set aside

| candidate axis | why not |
|---|---|
| `stance-grain` = {per-stone, per-reviewer} | this is the **fork** (F01), not a coordinate |
| `reviewer-count` = {one, many} | not orthogonal to B — the debt state already aggregates per reviewer, and the grid is walked per reviewer |
| 🔴 `concern-count` = {one, many} | a **rejection invariant**, never a coordinate — see §5. ⚠️ **added 2026-09-10; it was absent, over set aside** |
| `level` = {l1, l2, terminal} | the ladder's unlock rules are untouched by this behavior; the slab would be uniform |
| `stance-agrees?` | a rejection invariant, never a coordinate — see §2 |
| `why-is-substantive?` | ungated, so it encodes no invariant — see §3 |
