# 🌙 dream: `rule.require.get-set-gen-verbs`'s cardinality clause is 20% adopted — settle it or scope it

**kind** = reseed · **owner** = `ehmpathy/role=mechanic` (the rule) + `ehmpathy/rhachet-roles-bhrain` (the 97)
**caught** = 2026-09-14, at `5.1.execution.from_vision`, self-review r6 `role-standards-adherance`

## .the cue that fired

this round added one `get` operation and had to decide whether to name it `getNearMissGuardKey` or
`getOneNearMissGuardKey`. the rule's answer is unambiguous:

> *"get without One/All cardinality = **BLOCKER**"*

⇒ so the decision took one second, and then the **neighbours** were checked — and the check inverted
which choice would look like the defect.

## .the gap, precisely

**walked 2026-09-14** — `^export const get[A-Z]` across `src/**/*.ts` in `rhachet-roles-bhrain`:

| | count |
|---|---|
| exported `get*` operations | **122** |
| carry `One` or `All` | **25** |
| carry neither | 🔴 **97** |

**a booted BLOCKER rule at 20% compliance in a repo its own org owns.**

🔴 **and the 97 are not random — they share a shape the rule does not name.** not one returns a
collection. they return a decision (`getExitCodeClass`, `getGuardUpgradeDecision`), a report
(`getReviewSkipReport`), a path (`getSelfReviewArticulationPath`), a state (`getDriveBlockerState`).
the conformant 25 all read over a **set** (`getAllStones`, `getOnePassageReport`).

⇒ **the repo has a de-facto convention: cardinality marks a read over a SET, and is omitted for a
read that computes one value.** it is coherent, it is 80% of the corpus, and the rule contradicts it.

## .why this is a RESEED and not a local fix

the two candidate answers live in two different repos:

| the answer | whose |
|---|---|
| *"the rule is right; the 97 are debt"* | `rhachet-roles-bhrain` owes a 97-operation sweep |
| *"the de-facto convention is right"* | 🔴 `ehmpathy/role=mechanic` owes the rule an **amendment** — its cardinality clause binds a read over a SET, and says so |

⇒ **neither is this route's to choose**, and a tree adopts only what is scoped to itself.

## .the shape of the fix

**if the rule holds** — a sweep of the 97, one PR, no behavior change. every one is an exported
const whose filename mirrors it (`rule.require.sync-filename-opname`), so the rename touches the file
too. `rhx sedreplace` handles it per-operation; a single find-and-replace does not, because a
citation of a name and an instance of one are indistinguishable to it.

**if the convention holds** — amend `rule.require.get-set-gen-verbs`'s `.get retrieve extant` section
to state the axis it actually binds:

> `getOne*` / `getAll*` for a read over a **set** — a collection, a record, a lookup by key.
> a bare `get$Noun` for a read that computes **one value** with no set behind it.

⚠️ **the amendment is the harder half to write and the more valuable one.** the rule's current text
already gestures at this with its `lookup` / `compute` / `enumerate` / `assemble` subtypes — but it
demands cardinality on all four, and `compute` has no cardinality to carry.

## .why it is not done in this round

**SAFE?** ⚠️ the sweep is safe (no behavior change) and the amendment touches a booted org rule that
every mechanic session inherits. that is not safe to change from a feature branch in a consumer repo.

**CLEAN?** 🔴 **no, in both directions.** the sweep ripples into 97 files across every subsystem in
this repo — none of which this feature opened. the amendment ripples into another repo entirely.

⇒ the deferral is a **DIRT** deferral, so it owes a fulcrum beside this dream
(`rule.always.catch-dreams-for-followups`): `F19`, which records the call to conform to the 97 rather
than to the rule, and states the counter-case for the reverse.
