# case 2 — the-driver-was-never-enrolled

**actor** = driver-clone (the human feels it too — slice 5 subsumes here) · **feel** = sharp ·
**care** = critipath
**cell** = `driver-clone × apply × other-known × unenrolled`

> 🔴 **this is today's common case, not an edge.** a human opens a terminal, types `claude`, and
> drives. that driver has no clone address at all.

## .the narrative

i am the driver, and i was never enrolled. a human opened a terminal and started me. i have driven
four stones fine — `route.drive` works, guards work, the route does not care how i was launched.

now `5.3.verification` is next, and its guard declares `brain: claude-opus-5[1m]`. the human wrote
that on purpose: verification is where a cheap brain quietly signs off on work it did not
understand, so they paid for opus deliberately.

the hook fires and asks who i am:

```
$ rhx clone whoami
ConstraintError: not run inside an enrolled clone
  hint: whoami works from within a clone spawned by `rhx enroll`
```

i have no address. there is no `@:driver` to say into, because no `rhx enroll` ever registered one.

**the easy move is to shrug and drive on.** the stone would run. the work would look finished. the
human would read a green verification and never learn it was done by the brain they explicitly paid
to avoid — and the one artifact that exists to catch a lie would itself be a lie.

so i stop, and i say exactly what is wrong and exactly what fixes it:

```
🗿 5.3.verification
   └─ ✋ brain switch could not land

   the stone prescribes  = claude-opus-5[1m]
   this driver runs      = claude-sonnet-5[1m]  (inherited from launch)

   why: this driver has no clone address — it was not spawned by `rhx enroll`,
        so `clone say` has naught to address and the switch cannot be delivered.

   fix: re-enroll the driver with a slug, then re-enter the stone —
     rhx enroll claude --as @:driver --roles driver

   or:  remove `brain:` from 5.3.verification.guard, and accept the inherited brain
        deliberately rather than by accident.
```

🟡 **the re-enroll cannot itself set the brain, and that is the feature's own premise restated.**
`rhx enroll` takes a brain-**cli** (`claude`) and no model lever at all — measured at `--help`,
1.47.5. so the fix above restores **addressability**, and the stone's own `brain:` is what then
supplies the model on the next entry. an error that offered to do both in one command would name a
flag that does not exist.

⇒ **the "aha" is inverted here: the value is the halt.** a feature whose whole point is *which
brain did this work* has failed completely the moment it lets you believe a switch happened when it
did not. an unenforceable prescription is worse than no prescription — it reads like a guarantee.

## .the bdd `[tn]` timeline

```
given a driver launched directly — `claude` in a terminal, never `rhx enroll`
  and  no RHACHET_CLONE_SERIAL in its environment, so no clone identity record exists
  and  a stone 5.3.verification whose guard declares `brain: claude-opus-5[1m]`

  when [t0] the driver enters 5.3.verification
    then the hook runs `clone whoami` FIRST, before it dispatches aught
    and  whoami rejects with ConstraintError "not run inside an enrolled clone", exit 2

  when [t1] the hook reads that rejection
    then it dispatches NO `/model` — with no confirmed address, no say is attempted at all
    and  therefore no other clone can receive this stone's switch by accident

  when [t2] the hook reports the failure
    then the stone halts — it does not proceed under a brain the guard refused
    and  the message states what was prescribed, what is live, and why they differ
    and  the fix is a runnable command, not a description of one

  when [t3] the human re-enrolls the driver with a slug and re-enters the stone
    then reach becomes LIVE, and the switch lands exactly as in case 1
```

## .the fail-safe grade

per `rule.require.experience-coverage`, a sharp critipath must be shown to fail **fast**, **loud**,
to **teach the fix**, and to **hold the limit**.

| obligation | how this case meets it |
|---|---|
| **fast** | `[t0]` — the check is `whoami`, at the boundary, before any dispatch. it costs one local env read |
| **loud** | `[t2]` — the stone halts. it is not a warn line in a hook dump that scrolls past |
| **teaches the fix** | `[t2]` — a copy-paste `rhx enroll` line, plus the legitimate second option: remove the field |
| **holds the limit** | `[t1]` — no say is dispatched with an unconfirmed address, so the wish's *"a switch applied to the wrong clone"* is structurally impossible, not merely avoided |

## 🟡 .the call this case best-guesses

**halt, rather than warn-and-continue.** recorded as fulcrum `F1`.

the counter-case is real and it is not weak: most drives today are unenrolled, so a halt turns a
convenience feature into a gate for the majority of users. a warn is a defensible design.

it is best-guessed as **halt** on two grounds:

1. **the harm of the warn is silent and the harm of the halt is loud.** a missed warn ships a
   verification stone done by the wrong brain and nobody ever learns. a halt costs a human one
   command and they learn at once
2. **the rework is clean.** halt → warn is a flag, with no caller hardened against it

⇒ if the wisher prefers warn-and-continue, that is a one-line change. the council decides.
