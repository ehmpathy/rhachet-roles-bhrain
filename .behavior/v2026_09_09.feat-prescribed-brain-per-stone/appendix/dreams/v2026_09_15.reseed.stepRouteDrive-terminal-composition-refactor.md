# 🌙 dream: collapse stepRouteDrive's 21 return sites into one terminal composition

**kind** = reseed · **owner** = `ehmpathy/rhachet-roles-bhrain` · **caught** 2026-09-15

## .the cue that fired

an L3 architecture review (`enroll-impl-arch-defects`, i014 r011 finding 2, restated i015 r011) of
`.behavior/v2026_09_09.feat-prescribed-brain-per-stone`. the reviewer explicitly framed it as "a
decomposition opportunity for a follow-on wish rather than blocking this one on it, since the current
form is correct, just structurally fragile to the next contributor."

## .the gap, precisely

`stepRouteDrive.ts` (~874 lines) has **21 `emit: { stdout }` construction sites**. most now compose
through the shared `asRendered`/`asBooted`/`asStopped`/`asDriven` factory (this feature's work), but
a few — the hard-stop gate's `composeHaltStdout` — compose independently because they fire BEFORE
`stone`/`stdoutGuardWarns` are resolved.

the structural gap: **no part of the types or control flow PREVENTS a 22nd return site from being
added later with a raw, uncomposed `stdout` string.** the invariant "every stdout this function emits
has passed through the brain+advisory composition" is enforced by convention and review discipline,
not by construction — which is exactly why two defect classes recurred 6× and 4× across the review
history (advisory/brain bypassed on an early return; render-closure triplication), each "fixed" by a
patch of one more return site rather than by removal of the possibility of a missed site.

### .the checkable evidence

- grep `emit: { stdout` in `stepRouteDrive.ts` → ~21 sites
- the review history (i005–i014) shows the bypass class fixed at ~6 distinct return sites over time,
  and the render-triplication class at ~3, each a separate patch of the same shape

## .the shape of the fix

collapse the branches into ONE terminal composition: each branch computes a small variant
`{ body: string; kind: 'halt' | 'work'; stderr?: { reason: string; code: number } }` and stores it,
and the function falls through to ONE final `composeStoneBrainRender` + `return` at the bottom —
rather than each branch calling `asRendered(...)`/`composeHaltStdout(...)` and returning directly.

this needs the gate's early-exit shape to change (it currently returns before `stone` is resolved),
achievable by a resolve of `stone`/`stdoutGuardWarns` BEFORE the gate rather than after. then a 22nd
branch physically CANNOT emit an uncomposed stdout — it can only set the variant, and the single
terminal return composes it. the invariant moves from convention to construction.

**the clamp it owes:** a type-level or test-level assertion that every code path sets the variant and
none returns a raw `emit` directly (e.g. the branches return the variant type, and only the terminal
site builds `emit`).

## .why it is not done in this round

**SAFE — no.** it restructures the control flow of an 874-line orchestrator that every route in every
repo runs on every hook tick. the gate's early-exit-before-`stone` shape is load-bearing (it must
escalate a malfunction at once), and a move of `stone` resolution above it changes ordering that
several snapshots and the exit-code semantics depend on.

**CLEAN — no.** it touches ~21 return sites and the gate, and would re-baseline a large share of the
drive integration snapshots — far beyond an execution stone's diff.

⇒ the reviewer's own verdict: "real rework, not a nitpick-sized fix — a decomposition opportunity for
a follow-on wish." caught here as a `reseed` (it is a refactor of a shipped, correct orchestrator,
worth its own scoped behavior), rather than forced into this stone's diff.
