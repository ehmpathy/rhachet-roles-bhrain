# 🌙 dream: the contemplation gate counts REVIEWERS where the domain counts CONCERNS

- **kind** = fix · **owner** = `rhachet-roles-bhrain` · **caught 2026-09-10**

## .the cue that fired

a boundary walk on route `v2026_09_08.feat-dispute-or-concede-review-budget` graded every
declaration `PassageReport.status` accepts against one law:

> **a declaration discharges the concerns it NAMES. concerns it did not name survive it.**
> — `rule.forbid.suppression-of-undeclared-concerns`

nine of twelve obey it. **three break it, and two of those three are the new stances the route was
designed to add** — so they were fixed in the design (`S07`, per-concern grain).

⇒ **the third ships today**, and it was found only because the walk had to enumerate every
declaration to grade the new ones.

## .the gap, precisely

`rhx route.stone.set --as contemplated --that <slug>` discharges a **reviewer**. that reviewer may
have raised six concerns; **one `.taken` file discharges all six**, and the entrance gate is
satisfied.

🔴 **the rule that states the duty already admits the gap, verbatim:**

> *"the entrance gate refuses a round while a reviewer owes a `.taken`. it cannot check that the one
> file you wrote answered all six points behind that slug — **one `.taken` discharges the slug
> regardless.** ⇒ the gate enforces the parent rule, never this one … the door is a floor; this rule
> is the work."*
> — `rule.always.converge-with-reviewers.via-a-taken-per-point`

⇒ so **the concern was already the real grain of the domain, admitted in a booted rule, with no term
and no mechanism.** the reviewer re-raises what the driver skipped, which is the loop's own
correction — and it costs a full round to deliver it.

**checkable:** `getLatestPeerGivensPerSlug.ts` keys the debt by **slug**. `setStoneAsPassed.ts` reads
that keyed set. no operation anywhere reads a per-concern structure, because
`getReviewCountsViaRegex.ts` returns two integers and no per-item identity at all.

## .the shape of the fix

the route above is the enabler, not the blocker:

1. **the term exists now** — `term=route.guard.review.given.concern`, one blocker or one nitpick
2. **the address exists now** — `--concern <severity>.<ordinal> --that <reviewer>`, an ordinal within
   that reviewer's own report. **no reviewer contract change** (`contract.reviewer-output` untouched)
3. ⇒ so the fix is to let `--as contemplated` take the same `--concern` flag, and to key the debt on
   `(slug, severity, ordinal)` rather than on `slug` alone

✅ **`F020` is RULED — 2026-09-10, fork A** (`S08`): *"stances do not survive rounds; only live in
latest round."* ⇒ **the block is lifted**, and the dream inherits the scheme rather than the fork:

> a concern's identity is `(reviewer, severity, ordinal)` **within ONE given**.

⚠️ **and the hazard that justified the block is answered rather than avoided.** it read: *"a `.taken`
debt that renumbers under the driver is a worse defect than the one it repairs."* under A the debt is
keyed to the **given**, and a given is superseded whole by the next round
(`getLatestPeerGivensPerSlug`) — so **the debt renumbers WITH the given, never under the driver.**
the ordinal never moves while the debt it keys is live.

🔴 **what the verdict does NOT settle, and the fix must handle:** a reviewer that re-raises the same
concern at a **different ordinal** next round mints a *new* debt, and the driver's prior `.taken`
does not discharge it. that is correct under A — a fresh given is a fresh conversation — and it is
the cost `F020`'s hazard 1 names. ⇒ **the fix owes a render, never an identity change**: print the
concern's text beside its ordinal, so a driver sees *which* concern the debt refers to.

🟡 **the cheaper half is available now and is not this fix:** the halt could print the reviewer's
concern COUNT beside the `.taken` path, so a driver who wrote one paragraph for six concerns sees the
mismatch. that is a render change and it discharges no debt.

## .why it is not done in this round

**safe? no. clean? no.**

- the stance work is at `1.vision`, un-approved. this would widen an un-approved scope
- it changes a **shipped** gate every route in every repo passes through — `setStoneAsPassed` is the
  entrance, and a regression there halts every driver
- it depends on `F020`, an open fulcrum with **dirty** rework, since a stance and a `.taken` debt
  would both key on the same unsettled identity scheme

⇒ deferred for **dirt**, so a fulcrum is owed beside the dream and `F020` is it — the identity call
this fix would inherit.
