# 1.vision — the learner term hook returns as an opt-in toggle

## .the contract

```
rhx learn.terms.hook get       # report whether this repo's stops run the term hook
rhx learn.terms.hook enable    # add the onStop term hook to this repo's claude settings
rhx learn.terms.hook disable   # remove it
rhx learn.terms.hook --help
```

- default **disabled**: the learner role declares no onStop, so a repo that never runs `enable` has no Stop entry and pays naught (case=8)
- `enable` writes one Stop entry into the repo's committed settings file; the hook it adds runs the extant `learn.domain.terms --when hook.onStop` face, unchanged (the wish's nano bound), behind a guard on the learner's role link:

  ```
  [ ! -e .agent/repo=bhrain/role=learner ] || ./node_modules/.bin/rhx learn.domain.terms --when hook.onStop
  ```

  so a repo that later unlinks the learner pays one shell test per stop, never an error or a held stop (case=9)
- each write holds a mutex keyed on the target file and lands via temp + rename (concurrency cells in the inventory)
- each verb is idempotent; `get` never writes
- exit 0 on success and on a no-op · exit 2 on a refusal (bad verb, a link or malformed target), with `✋ ConstraintError:` on stderr and the fix

## .the outcome world

**before.** the term nudge was all or none. while it shipped, every session of every repo that
linked the learner ran a clock-driven gate on each stop, wanted or not; so it was withdrawn
(#466), and now no repo can have it.

**after.** kai's repo, whose vocabulary drifts, runs one `enable` and commits one file. from the
next session on, a clone that worked an hour without a distill is held at its stop with the guide.
every other repo is exactly as it was. a month later, glossary mature, kai runs `disable`.

**the aha.** the cost now sits only where the benefit is asked for, and the switch is a diff of
one hook block, which anyone can see in review.

## .the one design call that decides whether it works

rhachet reads a hook's `author` at three gates (rhachet 1.51):

- the per-role sync deletes any entry under exactly `repo=bhrain/role=learner` that the role does not declare
- the orphan prune deletes any `^repo=.+/role=.+$` author no linked role holds
- the peer-actor derive keeps an entry only if its `role=` segment names a role the actor holds

an entry under the learner's own author dies at the first gate, in silence, on the next
`rhx init --hooks`. a bare toggle author survives the first two and dies at the third, so no
enrolled clone would ever be nudged.

so the entry rides under **`toggle=learn.terms.hook/role=learner`**: outside `repo=`, so neither
the sync nor the prune claims it, and with a `role=learner` segment, so the derive keeps it for every
actor that holds the learner, as the withdrawn hook was scoped (fulcrum F1). case=3's clamps pin
all three gates.

## .mental model

> "it's a light switch for the glossary nag. on in this repo, off everywhere else."

| a human says | we say |
|---|---|
| the glossary nag, the term reminder | the onStop term hook (`learn.domain.terms --when hook.onStop`) |
| turn it on / off | `enable` / `disable` |
| is it on? | `get` |

analogy: a repo-level feature flag whose only effect is one hook entry in a committed config.

## .evaluation

| goal (wish) | how |
|---|---|
| a repo that wants the nudge can turn it on | `enable` (case=1), durable across re-sync (case=3) |
| every other repo pays no cost | no declaration in the role, no entry unless asked (case=8) |
| `get` / `enable` / `disable`, each idempotent | case=2, case=4, case=5 |
| toggle off ⇒ no session runs the hook | `disable` removes every entry that runs the command, whatever its author (case=5, F3) |
| default disabled | the role ships no onStop; the extant registration clamp stays green |

**pros.** zero cost by default · one visible, reviewable diff · reuses the extant hook face whole ·
survives rhachet's re-sync.

**cons.** the entry lives outside rhachet's management, so rhachet will not clean it up if the
learner is later unlinked; the guard makes the leftover free, not absent (case=9) · a change
reaches only sessions that start after it · on the split layout it reaches enrolled sessions
alone, never a bare `claude` · the hold has no bound: the face holds every stop until a fresh
distill is on file, so a session that never distills is held at each stop · the lock share with
rhachet is unsettled (Q8).

**pit of success.**
- a link or unparseable target is refused before any write, with the fix (case=6)
- a bad or absent verb never defaults to a write (case=7)
- `get` on an unparseable file refuses rather than claim `disabled`
- the output of each write names when it takes effect, and names the git-tracked path to commit — on the split layout `.claude` is a link into `.agent/.actors/actor.via.repo=ambient/brain/.claude/`, and `git add` refuses a path beyond a symlink

## .what is awkward

- **the skill name splits the vocabulary.** the extant skill is `learn.domain.terms`; the toggle is `learn.terms.hook`, which drops `domain`. the wish dictated the name, so it holds; a reader may look for `learn.domain.terms.hook`
- **an author that threads three gates.** `toggle=learn.terms.hook/role=learner` works because of how three rhachet read rules happen to parse an author. each is observed source, not a declared contract; case=3's clamps catch a change, but the fix would be upstream. a rhachet-native opt-in hook would be cleaner: caught as `dreams/v2026_11_07.reseed.rhachet-opt-in-role-hooks.md`
- **no live effect.** a human who runs `enable` mid-session sees no nudge until a new session starts; the output says so, but it can still surprise
