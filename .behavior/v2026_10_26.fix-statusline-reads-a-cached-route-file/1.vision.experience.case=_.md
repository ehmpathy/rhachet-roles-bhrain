## .the barred bands

| band | kind | why |
|---|---|---|
| unbound / unknowable × any D2 position | impossible — nature | no route, so no route file exists to hold a state |
| unbound / unknowable × any D5 or D6 position | impossible — nature | no route on this branch, so no write this seat reads |
| repaint × any D5 or D6 position | impossible — nature | a repaint writes no file; only a move writes |
| lands × stale, absent, or unreadable | impossible — nature | a landed write is the newest file, whole by temp + rename (D6 many converges by the re-check) |
| faults × fresh or unreadable | impossible — nature | a faulted write leaves the prior file untouched: stale if one stood, absent if none |

## .the invariants — barred by nurture, over every cell

these are not cells of the product; each is a rule every cell must keep, chosen by this wish.

| invariant | kind | why |
|---|---|---|
| zero node processes per repaint, over every cell at D7 ≠ node-era | nurture — the wish's own goal | 9 of 44 seats held 491% cpu on 2026-10-23; the empty-PATH clamp proves it per repaint. a node-era seat (case 37) runs the command its settings held before this release; the invariant reaches it at its next `rhx init` |
| a status write fault never refuses the move it follows | nurture — chosen | the file is a display cache; a cache that vetoes the state it shows would halt a route over a display defect (case 5) |
| a write leaves no orphan temp file, whether its rename lands or faults | nurture — chosen | each write makes its dir if absent, plants the dir's own `.gitignore` (intended, so a cache dir never shows in `git status`), then goes temp + rename; a faulted rename drops its temp, so a fault leaves the `.gitignore` and the prior file whole (case 5), and no temp beside them (`setRouteStatusLineCache` case1, case2 clamp) |
| a status write fault is caught by the move that triggered it | nurture — chosen | the write itself throws its fs fault to its caller (`setRouteStatusLineCache` case2); each move-grain writer catches it and prints one stderr row, so the move lands — the half that makes "never refuses the move" true, proven per writer by case 5's tests (writer case4, `setRouteBind` case5, `delRouteBind`) |
| an older line is never left marked fresh | nurture — chosen | a stale test that a writer race can blind would show a confident lie (case 16, fulcrum F7) |

## .the accepted blind spots

| blind spot | why accepted |
|---|---|
| a multi-bind fault record is trusted until the next writer runs | a bind flag removed by hand (under a `route.mutate` grant) leaves the other route's file with `two routes bound`; the reader runs no stale test on a fault record, so the line holds that claim until the next write or drive. the same class as a hand-edited `.stone`: rare, outside every paved writer, healed by one `rhx route.drive` |
| a git rewrite reads as stale (case 31) | git gives a rewritten tracked ledger a fresh mtime with no change of content; the reader's only test is `-nt`, and a content test costs a parse per repaint. the line names its heal, and the onStop drive runs it at the end of the turn |
| a route outside `.behavior/` with no pointer yet reads blank | the no-pointer fallback globs the conventional route home alone, so the reader never walks the repo. such a branch shows its line from its first drive or bind on |
| a node-era seat boots node per repaint until its next `rhx init` (case 37) | a release cannot rewrite a seat's settings by itself; only the init touches them. the init migrates the node command to the bash reader with a backup, so the cost ends at the seat's next `rhx init`, and the line's words stay the same throughout |
| a move made before the writer lands reads stale for one repaint at most | a repaint between a ledger write and its status write sees the ledger newer than the file, and marks the line stale; the writer's rename follows within the same move, so the next repaint reads fresh. the stale mark is true for that instant |
