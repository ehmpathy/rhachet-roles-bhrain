# case=12 · the grant that is reported and not made

- **the experience** = *two permitted grants overlap, one is silently discarded, and the command
  prints success for both*
- **actor** = driver · **feel** = sharp · **care** = **alterpath** · **verdict** = demoed
- **coordinates** = 🔴 **an ORDER OF ARRIVAL, not a cell** — the A × B × C grid enumerates states of
  the world at the attempt, and this experience is about **two attempts that overlap**
- **requirements** = none directly. 🔴 **that is the point** — it is the first demoed experience the
  wish's eight requirements do not reach, and it is reachable anyway

🔴 **this is the FIRST demoed alterpath in the catalog**, and it arrived from outside: `r1` peer
review, on `rule.require.dimensional-decomposition`'s own list of usual omissions — *"concurrency,
actor = system, resource-absent states."*

```ts

```

| the property | verified |
|---|---|
| a lock, a lease, or a lockfile | 🔴 **absent** |
| an atomic rename (`write tmp` → `rename`) | 🔴 **absent** — a direct `fs.writeFile` |
| a compare-and-swap on the prior content | 🔴 **absent** |

⇒ the last row is what makes this reachable: **two grants that touch different PEERS still write the
same FILE**, so they collide even though they never name the same field.

## .the narrative

*driver, stone `5.1.execution`. one live urgent concession stands, so the gate permits. two lanes are
dry — `mech-rules` and `ergonomist` — and I top up both.*

I run them together, because they are independent asks and the engine has never told me they are not:

```
$ rhx route.guard.budget --for review --add 4 --peer mech-rules   --stone 5.1.execution   &
$ rhx route.guard.budget --for review --add 4 --peer ergonomist   --stone 5.1.execution   &
```

both are permitted — one warrant, two dry lanes, which is `F10`'s reach at work exactly as recorded.
both print success:

```
🗿 route.guard.budget                     🗿 route.guard.budget
   ├─ peer = mech-rules                      ├─ peer = ergonomist
   └─ updates                                └─ updates
      └─ mech-rules  18 → 22                    └─ ergonomist  12 → 16
```

I re-arrive. `ergonomist` runs. 🔴 **`mech-rules` is skipped, still exhausted.**

I read its guard:

```yaml
    - slug: mech-rules
      budget: 18      # 🔴 the 22 I was told I bought is not here
    - slug: ergonomist
      budget: 16
```

**the aha, and it is the quiet kind:** *the command told me it wrote 22. it read 18, computed 22, and
its write was overwritten by a peer that had read 18 too. no error, no caution, no exit code — the
only evidence is a lane that stays silent.*

## 🔴 .why the BOUND is not what broke — and this is the whole grade

the `r1` concern named the opposite direction: *"two top-ups in parallel can both observe B = urgent
and both write — one granted quota that funds two grants."* **the source refuses that read:**

| the direction | can an overlap produce it? |
|---|---|
| **more** budget than the grants asked for | 🔴 **no.** each writer recomputes `budget + N` from **its own read**, so the later write carries a total that never saw the earlier one. two `--add 4` yield **+4** |
| a grant with **no warrant** | 🔴 **no.** the gate ran independently for each caller, and each had to pass |
| 🔴 **less** budget than the grants reported | ✅ **yes** — the lost update above |

⇒ **no order of arrival loosens the bound.** that is a real safety property of this design and it
earns a plain statement, because a first read of the axis expects the reverse.

⚠️ **and it is why the care grade is `alter`.** *if this path broke, would a core usecase fail, or is
there a workable fallback?* — the bound holds, the fallback is to re-run the grant, and the driver
meets the truth at the next arrival. the wish's outcome survives intact.

🔴 **what is sharp is the SILENCE, never the loss.** the command reports `18 → 22` for a write that
was discarded, which is a `rule.forbid.failhide` shape on a surface this design newly makes
load-carrying: under the gate, a grant is a **warrant spent**, so a grant that does not land spends a
warrant for naught.

## .the bdd timeline

```gherkin
given a stone `5.1.execution` with one live urgent concession
  and `mech-rules` at 18/18 and `ergonomist` at 12/12, both in one guard file

[t0] when the driver runs two `--peer`-scoped grants that OVERLAP
     then both pass the gate                              # ✅ correct — one warrant, two dry lanes
      and both read the guard file at `budget: 18 / 12`

[t1] when both writes land
     then 🔴 the later write OVERWRITES the earlier
      and one lane's bump is discarded

[t2] then 🔴 both invocations print `updates` with a budgetAfter that is not on disk
      and neither exits non-zero                          # the failhide

[t3] when the driver re-arrives
     then the discarded lane is STILL skipped for budget
      and the only signal is a lane that does not speak

[t4] when the same two grants are run SERIALLY
     then both land, and both reports are true            # ✅ the serial slab, unchanged

[t5] when any two grants overlap
     then 🔴 the total budget is NEVER more than a serial run would give   # the safety property
      and no grant is ever made without a warrant

[t6] when the write is made atomic                        # 🔴 the fix, and it is ONE move
     then a read-modify-write MUST NOT lose a concurrent peer's update
      and the shape (a lock, a rename, or a re-read-and-retry) is `F16`'s to rule
```

🔴 **`[t5]` is the assertion this case exists to pin.** it is the reassurance, and it is checkable:
the bound is safe under every order of arrival, so the concurrent slab **cannot** falsify req 1.

🟡 **`[t6]` is a MUST rather than a render**, for the same reason `case=11` `[t4]` is — the mechanism
is `F16`'s call, and a demo that picked one silently would settle a reserved question by side effect.

## .why it fails safe

**fast** — it does not; the loss is discovered at the next arrival, and that is the honest grade ·
🔴 **loud** — **it does not**, and that is the defect: success is printed for a write that was
discarded · **teaches the fix** — no, today it teaches the opposite · **holds the limit** — ✅
**yes, and this is the one criterion it meets outright**: `[t5]` shows the bound the wish asks for is
never loosened by an overlap.

⚠️ **so three of four fail-safe criteria are unmet, and the case is still `alter`.** the criteria grade
the **edge**; the care axis grades **what depends on the edge**. here what depends on it is a grant a
driver can simply re-run, and what must not break — the bound — is proven safe at `[t5]`.

🟡 **the residual:** until `[t6]` ships, a permitted grant is reported as made whether or not it
landed. the design does not create that defect (it is the extant write path) and it does **raise its
price**, since a warrant spent on a lost grant is not refunded. ⇒ `F16`, and a caught dream for the
atomic write.

## .the cells this case covers

**no grid cell — it is an ORDER OF ARRIVAL.** it re-walks `driver × urgent × exhausted` (`case=2`'s
cell) twice over, and the experience lives entirely in the overlap between the two walks.

🟡 **⇒ a sixth axis `F concurrency` (`serial` | `concurrent`) exists in the source and was never
walked.** `F = serial` reproduces the whole 32-cell slab unchanged, so only the second slice is new,
and this case is that slice — the same shape `D` and `E` take at `case=10` and `case=11`.

🔴 **three axes were missed, by three different instruments, and that is the transferable result.**

⇒ the walk detected none of the three from inside itself, which is `rule.require.dimensional-
decomposition`'s completeness-by-construction stated as a warning rather than a guarantee.
