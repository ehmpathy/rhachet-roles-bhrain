# 🌙 dream: the guard's review cache is keyed by INDEX, so a swapped reviewer inherits a verdict

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-05, on `.behavior/v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

a new acceptance case (`routeStoneSetContemplation.acceptance [case7] [t3]`) drove a reviewer
`departed` to raise a blocker, retired it from the guard config, enrolled `successor` in its place,
answered the retired debt, and re-ran. the round it snapped reads:

```
├─ r1: successor (l1, 0/5)
│   ├─ rejected, cached
│   ├─ 1 blocker 🔴
│   ├─ given: .reviews/peer/1.test._.review.i001.<hash>.r001._.given.by_peer.departed.md
│   └─ taken: .reviews/peer/1.test._.review.i001.<hash>.r001._.taken.by_self.departed.md
```

⇒ **`successor` has never run.** it is rendered `rejected` on a critique it never made, at `0/5`
rounds, under another reviewer's given and taken paths.

## .the gap, precisely

two lookups inside one loop body disagree on their key:

| the expression, in `runStoneGuardReviews.ts` | lookup | key |
|---|---|---|
| `cachedReviews.find((r) => r.index === pr.index)` | the **cached review** | **position** |
| `meterBySlug.get(pr.slug)` | the **meter** (round count) | **slug** |

⚠️ **this table carried `:402` and `:405` until 2026-09-08, and both were wrong** — the true lines
are `~:407` and `~:410`. the correction was **appended below**, at the two sections further down,
and this table was never touched. ⇒ **both downstream copies inherited the wrong numbers**, since a
copier reads top-down and stops at the first table. the expressions above need no re-check.

so a reviewer swapped into an occupied position inherits its predecessor's verdict while its own
round count starts at zero. the two halves of one reviewer's state come from two different
reviewers.

🔴 **the direction that ships silently is the one the case above does NOT reach.** the reuse branch
takes a fast-path:

```ts
if (cachedReview && cachedReview.blockers === 0) {
  reviews.push(cachedReview);
  continue;
}
```

⇒ enroll a **stricter** reviewer at a position whose predecessor returned `0 blockers`, and it is
**skipped outright and reported approved**. the reviewer never speaks; the stone passes on a verdict
it never gave. that is `rule.forbid.failhide` at the guard's own cache — the shape this repo already
names as *"a `0/0` from a reviewer that never rendered one."*

| the swap | what a driver sees | what is true |
|---|---|---|
| predecessor **rejected** | a false red on the newcomer | measured, above |
| predecessor **clean** | 🔴 a false green, and the round never runs | read from the fast-path above |

⚠️ **it is not a stale-cache bug.** the cache does exactly what it was told; the key is simply the
wrong one. an artifact-hash change does not help — both reviewers sit at the same hash.

## .the shape of the fix

key the review cache on the **slug**, as the meter already does.

the obstacle is that `RouteStoneGuardReviewArtifact` carries no slug — the rendered slug comes from
`pr.slug` (the live config), never from the artifact. so the repair is three coupled edits:

1. **add a `slug` to the artifact** and write it in `formatTreeBucket.ts` (the writer)
2. **teach `parseTreeBuckets` to read it** — `getAllStoneGuardArtifactsByHash.ts` (the reader), and
   keep a fallback to `index` for stamps written before the field existed
3. **key the lookup on slug**, at all **three** `cachedReviews.find((r) => r.index === …)` sites
   — two in `runStoneGuardReviews`, one in `getAllReviewPeerMeterStatuses`

⚠️ a slug key with **no** back-compat fallback silently invalidates every extant stamp, so every
cached lane re-runs once. that is loud and cheap, but it should be a chosen cost rather than a
surprise.

## .why it is not done in this round

**in scope? no.** this behavior gates the contemplation loop. the index key **predates** it — neither
P1 nor P2 touches `:402`, and the defect reproduces on `main`.

**safe? no.** the change lands inside the guard's review cache, which is the exact machinery this
behavior already rekeys (P2 moves the contemplation debt off `(slug, hash)`). two rekeys of adjacent
caches in one round is how a silent skip gets shipped — and a silent skip here is a stone that passes
with a reviewer unheard.

**clean? no.** the render *is* the cache's storage format (`formatTreeBucket` writes what
`parseTreeBuckets` reads), so a new field is a format migration rather than a local edit.

⇒ what was done instead: the defect was **snapped as-is, and labelled as a defect in the test body**,
so it could not be read as the contract. the day the key was corrected, that snapshot would go red and
hand the fixer the exact before-and-after.

⚠️ **that day came — 2026-09-08, and the clamp bit exactly as written.** the paragraph above is the
record of a state this dream no longer sits in: an interim guard shipped, the snapshot went red, and
it now pins the contract rather than the defect. **the full rekey is still owed** — see the 2026-09-08
amendment below, which states which half shipped and which half did not.

## ⚠️ amended 2026-09-06, i025 — a THIRD site existed, is now fixed, and the rest is narrowed

a scoped re-run of `ergo-snapshot-visual-blemishes` (dark for five rounds) raised this render as a
**blocker** rather than an accepted clamp. that pressure produced a real repair and a correction to
the record — stated in that order because the correction is the more useful half.

### ✅ what was fixed — the cross-hash fallback, a site neither this dream nor F10 named

`getLatestReviewArtifactForIndex` is the **exhausted-reviewer fallback**: when a reviewer has rounds
but no artifact at the current hash, it reaches back across hashes. it enumerated by `index`, so it
straddled a config change the same way — and it is now
**`getLatestReviewArtifactForSlug`**, keyed on the slug, via the one parser that owns the filename
grammar (`getRouteGuardReviewPeerPathMeta`) and the one sanitizer that owns the on-disk slug form.

⇒ this needed **no** artifact-schema change, because it reads the slug straight from the filename.
that is precisely why it was severable from the rest, and why it could land inside this round.

**clamped and proven to bite** (`rule.require.clamp-edge-cases`): `[case3]` provisions `departed` at
`r001`, enrolls `successor` at the same rung, and asserts `null`.

| the code | the clamp |
|---|---|
| index key (the defect, restored on purpose) | 🔴 **red** — `[case3][t0]` alone, 6 others green |
| slug key (the fix) | ✅ **green** — 7 passed |

### 🔴 what is NOT fixed — and this dream's own diagnosis was the correct one

after that rekey, the `[case7][t3]` acceptance render is **byte-unchanged**: `r1: successor` still
carries `by_peer.departed.md`. measured, not assumed.

⇒ so the render defect is driven by `cachedReviews.find((r) => r.index === …)` — **`:402` and
`:445`, exactly the two sites this dream named from the start.** the three coupled edits above stand
as written.

⚠️ **and the deferral now has a harder reason than "adjacent machinery".** the artifact's declared

```ts
public static unique = ['stone', 'hash', 'index'] as const;
```

**the index is the artifact's identity BY CONTRACT**, not merely the key a lookup happens to use. so
step 3 is not a lookup change — it is a **domain-entity identity change**, which is architect-scale
and ripples through every construction and comparison of the object.

### 🔴 the correction to the record

**F10 attributed this render to `getLatestReviewArtifactForIndex`** — *"the row is chosen by
`getLatestReviewArtifactForIndex` — by INDEX, never by slug, which is F9 verbatim."* that
attribution is **refuted**: the operation is now slug-keyed and the row is unchanged.

⇒ the useful lesson is not that F10 was wrong. it is **how** it was wrong: F10 reached its
attribution from a read of two operations that shared a defect shape, and it was right about the
shape and wrong about which site rendered the row. **a shared shape is a hypothesis; only a run tells
you which site produced the bytes.** F10's own entry records that it raised its confidence 74% → 91%
on a check it ran — this is the check it did not run.

## 🔴 amended 2026-09-07 — an INSERT cascades, and the sanctioned remedy is what arms it

**this dream's title says *"a swapped reviewer"*, and a swap is the mild case.** the general operation
is an **insert**, which shifts every later lane by one — and you remove no one, so it is far easier to
do without notice.

### the four reads that make it concrete

| # | the fact | where |
|---|---|---|
| 1 | the `rNNN` filename segment **is** the guard-list position — `index: i + 1` over `getGuardPeerReviews(guard)`, taken **before** the level sort | `runStoneGuardReviews.ts`, the `index: i + 1` map |
| 2 | the reuse branch is `if (cachedReview && cachedReview.blockers === 0)` | `runStoneGuardReviews.ts` |
| 3 | 🔴 a stone's `.guard` file is **not** in its own hashed artifact set (the default is `$route/$stone.yield*` + `$route/$stone*.md`; a custom `artifacts:` list rarely names the guard either) | `getAllStoneArtifacts.ts`, the default-glob list |
| 4 | ⇒ **a guard edit does not move the artifact hash**, so a cache minted before the edit is still live after it | `computeStoneReviewInputHash.ts`, the artifact-set hash |

⚠️ **row 2 read *"the reuse branch is at `:416`, not `:411`"* until 2026-09-08** — a correction of the
primary table above, **appended here rather than applied there**. the table kept the wrong number for
three days and two copies of it shipped. the table now carries expressions, so the correction has no
number left to correct.

### 🔴 the reachable sequence — and it is the PRESCRIBED one

```
1. run a round at hash H          → mints cached reviews keyed 1..n
2. edit the guard's peer list     → narrow an overflowed lane's --paths-with, or add a lane
3. re-run without a touch to the hashed artifacts
   ⇒ H is unchanged · the cache at H is live · every lane after the edit reads its predecessor's verdict
```

⚠️ **step 2 is exactly what `rule.always.diagnose-reviewer-malfunctions` prescribes for an overflowed
lane**, and step 3 is the natural next move. ⇒ **the sanctioned remedy for a dark lane is the operation
that arms this defect**, and the brief that prescribes it says naught about that.

### the worked instance, measured on this route

a lane was inserted at index 9. the shift, against the i029 cache:

| index | held it at i029 | holds it after the insert | that lane's i029 verdict |
|---|---|---|---|
| **11** | `enroll-verif-snapshot-blemishes` | 🔴 `enroll-verif-snapshot-coverage` | 🔴 **0 blockers, 0 nitpicks** |

`enroll-verif-snapshot-coverage` rendered **2 blockers** at i029. at index 11 it meets a `0 blockers`
cache, and `:416` reuses it with no slug check. ⇒ **a lane that REJECTED is skipped and reported

⇒ **this closes the doubt the F9 entry called its main drag.** the false-green direction was *"argued
from a read, never reproduced"*; it is now a configuration with a named victim. ⚠️ **not armed at the
live hash** — the artifacts moved after i029 — but armed by any ordinary run-edit-rerun above.

### 🔴 what this adds to the fix — an interim guard that needs NO migration

the full shape is unchanged (key the cache by **slug**, a `unique` change on the artifact). what this
adds is an **interim guard at the read**, and it is far cheaper than the full fix:

| what it needs | available? |
|---|---|
| a slug on the cached artifact | ✅ **already there, via `path`** — `path` is the entity's `primary` key and the filename carries the slug (`RouteStoneGuardReviewPeerArtifact:92`) |
| a parser | ✅ **extant and tested** — `getRouteGuardReviewPeerPathMeta({ path }) → { slug, iteration }` |
| a schema change or stamp migration | ❌ **none** |

```ts
const cached = cachedReviews.find((r) => r.index === pr.index);
const cachedSlug = cached && getRouteGuardReviewPeerPathMeta({ path: cached.path }).slug;
const cacheSafe = cached && cachedSlug === pr.slug ? cached : null;   // discard on mismatch
```

⇒ **it fails safe.** a discarded cache costs one re-run — the correct price for a lane whose rung
changed. a *reused* wrong cache ships a false green.

🔴 **this matters because the deferral's stated ground does not cover it.** the argument for deferral is
*"the render IS the cache's storage format, so a new field is a migration"* — **true of the full rekey,
false of this guard.** the same asymmetry that let `:468` be repaired cheaply applies here: that fix
worked because **it read the slug from a filename**, and so does this one.

⚠️ **one real caveat.** `getRouteGuardReviewPeerPathMeta` **throws** on an unparseable name, and
`.dream/v2026_09_04.fix.unparseable-peer-filename-halts-the-gate.md` records that an unparseable name
already halts a gate elsewhere. ⇒ **the guard must parse leniently** — parse-or-null, and treat null as
a mismatch, which fails safe in the same direction. a strict parse here would trade a silent false
green for a loud halt, which is better but still a regression.

## ✅ amended 2026-09-08 — the INTERIM GUARD shipped. the REKEY did not

the wisher ruled on the deferral and reversed half of it:

> *"lets do D and then leave a 'todo: fix structurally with A' which points to the dream of A"*

⇒ **the HARM ships closed today; the DEFECT stays open under a `todo` that names its record.** the
deferral above argued the fix as one indivisible migration, and the verdict split it — which is why
the deferral's ground (*"the render IS the storage format"*) is true and was never the whole picture.

### what landed

| artifact | what it does |
|---|---|
| `getCacheSafePeerReviewArtifact.ts` | the read-side guard: find by index, then **confirm the slug**, else return `null` |
| `asPeerReviewSlugFromPath.ts` | the **lenient** twin of `getRouteGuardReviewPeerPathMeta` — parse-or-null, per the caveat this dream raised |
| `runStoneGuardReviews.ts` | **both** its `cachedReviews.find(…)` sites now route through the guard |
| `getAllReviewPeerMeterStatuses.ts` | 🔴 **the third site** — the meter's own read, guarded too |
| `getCacheSafePeerReviewArtifact.test.ts` | 5 cases / 7 tests — swap · insert · separator slug · unreadable name · same-tenant |

🔴 **the sketch named ONE site. there were three, and the two it did not name are the dangerous
ones.** both feed **level clearance** rather than a render:

| # | where | what a retired tenant's cache would do there |
|---|---|---|
| 1 | the round loop, `runStoneGuardReviews` | the measured case — a false green or a false red on the newcomer |
| 2 | `computeVerdicts`, same file | 🔴 **unlock a level** on a verdict its current reviewer never gave |
| 3 | `getAllReviewPeerMeterStatuses` | 🔴 feeds `getStoneGuardLevelClearance` — the same unlock, by a second road |

⚠️ **site 3 sits directly beneath a comment that already argued the slug key** — the exhausted-reviewer
fallback three lines below it reads *"keyed by SLUG, never by index — this reach crosses hashes, so it
can straddle a config change."* ⇒ **the argument was written, in place, above an unguarded index
lookup**, and stayed there through two prior passes over this defect.

⇒ **a sketch names the site its author reached from. a grep for the EXPRESSION names them all** — which
is the same case this dream's own `.see also` already makes for why it cites by expression rather than
by line.

### the two departures from the sketch, and why each was forced

| the sketch said | what shipped | why |
|---|---|---|
| `getRouteGuardReviewPeerPathMeta({ path }).slug` | `asPeerReviewSlugFromPath` | the extant parser **throws**, and this runs on the hot path over engine-written files. a throw here is a new halt site — the exact regression this dream's own caveat warned of |
| `cachedSlug === pr.slug` | `asSanitizedPeerReviewSlug` on **both** sides | the filename carries the **sanitized** slug, so a raw comparison mismatches every slug with a separator (`.test/mock-review.sh` on disk is `.test-mock-review.sh`). `getLatestReviewArtifactForSlug` already paved this |

⇒ **both were found by implementation, never by a read.** the sketch was correct in shape and
under-specified in exactly the two places a run reveals.

### the clamp bit — measured, not asserted

`[case7][t3]` went red on the fix, as its own comment promised. the before/after it handed over:

| | before | after |
|---|---|---|
| `successor`'s budget | `0/5` — never ran | **`1/5`** — ran |
| its verdict line | `rejected, cached` | **`rejected <elapsed>`** |
| its given/taken | `…i001.…by_peer.**departed**.md` | **`…i002.…by_peer.successor.md`** |

the test is converted from a **defect** snapshot to a **contract** snapshot, and carries the same
`todo` pointer as the code.

### 🔴 what is still owed — and the `todo` is the only guard on it

**A is not done.** the key is still `index`; the guard merely refuses to trust it when the tenant
changed. so:

- a mismatch costs a **needless re-run** — correct, and not free
- `RouteStoneGuardReviewArtifact.unique = ['stone', 'hash', 'index']` is **unchanged**, so the
  artifact's declared identity still says the position is the identity
- ⚠️ **every new reader of that cache must recall to route through the guard.** a direct
  `cachedReviews.find((r) => r.index === …)` compiles, reads plainly, and reintroduces the defect

⇒ that last row is why this dream stays **open** rather than delivered. a guard at three call sites
is a discipline; the rekey would make the defect unexpressible. **the `todo` in
`getCacheSafePeerReviewArtifact.ts` points here, and this section is what it points at.**

⚠️ **and the count is the argument.** the sketch said one site, a grep found three, and the third had
been read past twice. **a fourth is exactly as easy to add as the third was to miss** — which is what
a discipline costs and a rekey does not.
