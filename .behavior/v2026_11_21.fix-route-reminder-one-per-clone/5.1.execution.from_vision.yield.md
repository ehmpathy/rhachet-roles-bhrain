## .deviations from the vision, each a clean rework

`1.vision.yield.md` stays as approved. the pr body is written from this yield, which states the shipped behavior; each place the shipped behavior parts from the vision is listed here (the sweep's callers and reach, the orphan bound, gen on a dead route among them).

- the daemon learns its anchor from an explicit `--repo-root` flag, not from its cwd. the spawn pins cwd to the git root of the caller's cwd, which in a hermetic test is this repo, not the temp route's anchor; an explicit flag keeps both sides on one dir in every case
- the drive sync anchors on the git root of the ROUTE it drives, not of the caller's cwd. a route always sits inside its repo, so both name one dir in practice; the route is the input the sync already holds, so no cwd read is owed
- the cli verbs take an injected `cwd` (default `process.cwd()`), the same seam as `say`, so a test anchors `get` / `del` on a temp dir with no chdir
- the legacy sweep reaches `.route/*/.route/` as well as `.behavior/*/.route/`, since a bound route may live under either root
- the sweep runs before a spawn and on `del`, never on every caller: the dead arm of a blocked route fires each turn, and a legacy daemon on a dead route exits through its own doors
- gen on a route that is not a live drive spawns no daemon. with a live daemon, it keeps the focus where it is; the vision had gen write the focus unconditionally, which would end the nudges of the route the clone does drive. with none live, the vision had gen spawn one that exits on arrival; that spawn held the clone's slot unowned until its first tick
- the daemon exits once its handle no longer names its pid; the vision bounded an orphan by its own exit doors, which never fire while the clone drives a live route

## .contract changes a release note owes

- `route.reminder.get` and `route.reminder.del` refuse `--route` and `--repo-root` (exit 2, with the fix); before, `--route` was required. a caller that passes `--route` to either must drop it
- the spawned daemon takes `--repo-root` in place of `--route`; it is spawned by this package alone, so no caller outside it passes either
- `route.reminder.gen` on a route that is not a live drive spawns no daemon and prints `reminder not spawned — …`; before, it spawned one and printed `reminder daemon spawned (pid N) but …`
- `route.reminder.gen` refuses a `--route` that is not a dir (exit 2, names the path)
- `route.reminder.del` clears a torn clone handle (a body that is not a pid) and prints `reminder handle was torn …`; before, it exited 1 on it
