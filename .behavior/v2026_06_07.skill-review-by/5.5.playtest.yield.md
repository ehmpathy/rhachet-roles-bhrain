# playtest: review.by skill

verify `review.by` by hand — the skill reads a role's `rubrics.yml`, runs each rubric serially,
emits owl-vibe treestruct stdout with guard-parseable counts, and exits 0 / 1 / 2.

review.by is a **base engine** in `repo=bhrain role=reviewer`, dispatched **by role**:

- run the base directly: `rhx review.by --repo bhrain --role reviewer -- --role <target> ...`
- or a role ships its OWN thin `review.by` wrapper that bakes in its role and delegates to the base

`rhx` forwards `--repo` / `--role` / `--skill` into the skill's argv on every call, so the base
tolerates those forwarded dispatch flags (a real typo still errors loud), and parses `--role`
last-wins so a wrapper's explicit `--role` overrides the forwarded one. see
`src/domain.roles/reviewer/briefs/howto.review-by.[guide].md`.

every step below cites the acceptance case that proves it automatically, so you can trust the
byhand walk maps 1:1 to committed coverage.

## prerequisites

- the repo builds: `npm run build` exits 0
- keyrack unlocked for the review brain (review.by dispatches real `rhx review`, which calls an
  llm): `rhx keyrack unlock --owner ehmpath --env prep`
- a demo fixture ships in-repo at
  `blackbox/.test/assets/codebase-review-by/` — a self-contained `role=demo` with one rubric
  (`demo-arrow-only`), a clean source file, and a dirty one that violates it

## sandbox

- all file creates/writes in these steps target `@gitroot/.temp/` — never the repo root
- the automated tier (part A) writes only to jest temp dirs; the manual tier (part B) copies the
  fixture into `.temp/`

## part A — automated proof (fastest confidence)

the acceptance suite runs the REAL skill against the demo fixture, blackbox. four files cover it:
the shell-entry contract + journey (`review.by.acceptance`, `review.by.journey.acceptance`), the
REAL `rhx` dispatch (`review.by.dispatch.acceptance`), and the wrapper-extends-base usecase
(`review.by.wrapper.acceptance`).

1. run the acceptance suite →
   ```
   rhx git.repo.test --what acceptance
   ```
   - ✓ pass if: exit 0, and the summary reports every `review.by.acceptance`,
     `review.by.journey.acceptance`, `review.by.dispatch.acceptance`, and
     `review.by.wrapper.acceptance` case green
   - ✗ fail if: any case red, or a snapshot mismatch is reported

2. spot-read the committed contract snapshots →
   ```
   git show :blackbox/__snapshots__/review.by.acceptance.test.ts.snap
   ```
   - ✓ pass if: the all-pass snapshot reads `🦉 not even a vole` and the findings snapshot reads
     `🦉 needs your talons` with a `summary` block that holds `1 blocker 🔴` / `0 nitpicks`
   - ✗ fail if: any turtle mascot 🐢 appears where the default owl 🦉 is expected (turtle is only
     legitimate in case13, the explicit vibe-override)

3. spot-read the dispatch + wrapper snapshots (the real-invocation path) →
   ```
   git show :blackbox/__snapshots__/review.by.dispatch.acceptance.test.ts.snap
   git show :blackbox/__snapshots__/review.by.wrapper.acceptance.test.ts.snap
   ```
   - ✓ pass if: both read the same owl treestruct (`🪨 run solid skill repo=bhrain/role=reviewer`
     header + `🦉 not even a vole` + `r1 demo-arrow-only ✓`) — proof the dispatch/wrapper layers add
     no drift over the direct-shell path
   - ✗ fail if: either snapshot carries an unknown-flag error or a mangled header

## part B — manual invocation (hands-on)

set up the fixture once in the sandbox, then walk the paths.

### setup

```
mkdir -p .temp/playtest-review-by
cp -r blackbox/.test/assets/codebase-review-by/. .temp/playtest-review-by/
cd .temp/playtest-review-by
npx rhachet roles link --role reviewer
```

- ✓ pass if: `.agent/repo=bhrain/role=reviewer/skills/review.by.sh` now exists under the temp dir
- (all commands below run from inside `.temp/playtest-review-by`)

### happy paths

1. **all rubrics, clean code passes** (acceptance case1) →
   ```
   bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --paths 'src/clean.ts'
   echo "exit:$?"
   ```
   - ✓ pass if: stdout header is `🦉 not even a vole`, the tree shows `r1 demo-arrow-only ✓`, and
     `exit:0`
   - ✗ fail if: any ✗, any blocker count, or a nonzero exit

2. **all rubrics, dirty code yields blockers** (acceptance case2) →
   ```
   bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --paths 'src/dirty.ts'
   echo "exit:$?"
   ```
   - ✓ pass if: header is `🦉 needs your talons`, the tree shows `r1 demo-arrow-only ✗` with
     `1 blocker 🔴`, a `summary` block reports `1 blocker 🔴` / `0 nitpicks`, and `exit:2`
   - ✗ fail if: `exit:0`, or the summary count lines are absent (a guard reads those lines)

3. **single rubric via --for, clean** (acceptance case3) →
   ```
   bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --for demo-arrow-only --paths 'src/clean.ts'
   echo "exit:$?"
   ```
   - ✓ pass if: the header line echoes `🔍 review.by --role demo --for demo-arrow-only`, tree shows
     `r1 demo-arrow-only ✓`, and `exit:0`

4. **output files land per rubric** (acceptance case1/case4) →
   ```
   cat .reviews/by=demo/rubric=demo-arrow-only.md | head -5
   ```
   - ✓ pass if: a review markdown file exists for the rubric that ran
   - ✗ fail if: the output dir is absent after a run

5. **help on demand** (acceptance case19) →
   ```
   bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --help
   ```
   - ✓ pass if: usage prints with the `--role` (required) / `--for` / `--paths` / `--diffs` /
     `--mode` / `--brain` / `--output` / `--help` lines and a worked example
   - ✗ fail if: help is absent or omits the required-arg marker

### edgey paths

- **role with no dir** (acceptance case6) →
  ```
  bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role ghost ; echo "exit:$?"
  ```
  - ✓ pass if: stderr reads `✋ BadRequestError: role not found at .agent/repo=*/role=ghost` and
    `exit:1`

- **absent --role** (acceptance case11) →
  ```
  bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh ; echo "exit:$?"
  ```
  - ✓ pass if: stderr reads a bare `error: --role is required` (no ✋ on inline arg-validation —
    the codebase reserves ✋ for caught BadRequestError only) and `exit:1`

- **--for a slug not in rubrics.yml** (acceptance case7) →
  ```
  bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --for ghost ; echo "exit:$?"
  ```
  - ✓ pass if: stderr names the absent rubric AND lists the available ones
    (`rubric not found: ghost. available rubrics: demo-arrow-only`) and `exit:1`

- **unknown flag typo** (acceptance case18) →
  ```
  bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --rool demo ; echo "exit:$?"
  ```
  - ✓ pass if: stderr reads a bare `error: unknown flag(s): --rool`, points to `--help`, and
    `exit:1`

- **value-flag with no value** (acceptance case20) →
  ```
  bash .agent/repo=bhrain/role=reviewer/skills/review.by.sh --role demo --brain ; echo "exit:$?"
  ```
  - ✓ pass if: stderr reads a bare `error: flag(s) expect a value: --brain` and `exit:1`

### the real dispatch path (the dogfood)

the steps above invoke `review.by.sh` directly. a real user calls it through `rhx`, which forwards
`--repo`/`--role`/`--skill` into the skill's argv. walk that real path too.

- **base via real rhx dispatch, clean code** (acceptance dispatch case-rhx3) →
  ```
  rhx review.by --repo bhrain --role reviewer -- --role demo --paths 'src/clean.ts' ; echo "exit:$?"
  ```
  - ✓ pass if: stdout header is `🦉 not even a vole`, tree shows `r1 demo-arrow-only ✓`, `exit:0` —
    the forwarded `--repo`/`--skill` did not trip the parser, and `-- --role demo` reached it
  - ✗ fail if: stderr reads `unknown flag(s): --skill` (the pre-fix dogfood failure)

- **dispatch tolerance is surgical** (acceptance dispatch case-rhx2) →
  ```
  rhx review.by --repo bhrain --role reviewer -- --role demo --rool oops ; echo "exit:$?"
  ```
  - ✓ pass if: stderr reads `error: unknown flag(s): --rool` and `exit:1` — a real typo still errors
    loud even through the dispatch layer

- **a role's own wrapper delegates to the base** (acceptance wrapper case-wrap2) →
  ```
  bash .agent/repo=demo/role=demo/skills/review.by.sh --paths 'src/clean.ts' ; echo "exit:$?"
  ```
  - ✓ pass if: stdout header is `🦉 not even a vole`, tree shows `r1 demo-arrow-only ✓`, `exit:0` —
    the demo wrapper baked in `--role demo` and delegated to the base, the full wrapper → base →
    rubric chain
  - the wrapper is one line: `exec rhx review.by --repo bhrain --role reviewer -- --role demo "$@"`
