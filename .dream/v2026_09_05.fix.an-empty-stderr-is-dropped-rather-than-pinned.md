# 🌙 dream: an empty stderr section is DROPPED from a snapshot rather than pinned

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-05, at `5.3.verification` i015, by `ergo-contract-snapshots` (bounded re-run,
  nitpick.1)
- 🔴 **WITHDRAWN 2026-09-05** — at i016, one round later. **the defect is repaired; the premise
  under `.why it is not done in this round` did not hold.**

## 🔴 .the withdrawal

**the claim, as stated:** the carve-out could not be repaired this round, because the repair needed
a resnap, and the only resnap available was a `lenient` flip that would pin a `0/0` failhide.

**the authority that overturned it:** `ergo-contract-snapshots` re-raised the ask as a **blocker**
at i016 (`.review/i016.r2.scoped.contract-snapshot-exhaustiveness.md`), which is the correct
escalation for an ask I had conceded was right. **the re-raise forced a re-read, and the re-read
found the premise false in two independent ways:**

1. **no resnap was ever needed.** both `stderr` sections in the extant baseline carry REAL bodies
   (`…snap:24-32`, `…snap:81-90`), so `bodyWasBare` is false for every line in the corpus and the
   deflake loop was a **pass-through**. its removal cannot move a byte of the baseline — measured
   from the baseline itself, never inferred.
2. **the variance no longer reaches the test at all.** `formatArtifactStreamBuckets` landed in this
   same round and emits a `stderr` bucket only when `stderr.trim() !== ''`, so the "no byte" and
   "bare newline" variants collapse to ONE output at the source. pinned at unit grain by
   `formatArtifactStreamBuckets.test.ts` [case5] and [case6].

⇒ **so the repair is stronger than the `<empty>` marker this dream proposed: the carve-out is
DELETED outright.** a mask is the right answer to variance that reaches the snapshot; no mask is the
right answer to variance the engine already removed. `blackbox/review.by.guard-peer.acceptance.test.ts`
now returns `kept` directly.

⚠️ **the durable lesson, and the reason this file is withdrawn rather than deleted:** an engine
repair landed in the same round silently dissolved a test-level workaround, and nobody re-checked
the workaround against it. **a deferral's stated reason has a shelf life, and the round that
deferred is exactly the round most likely to invalidate it.**

## .the cue that fired

a reviewer read the deflake sanitizer in `blackbox/review.by.guard-peer.acceptance.test.ts` and
named the trade it makes:

> *"an entirely-empty stderr block has no volatile bytes to mask … so dropping it leaves the stderr
> surface unpinned: a future regression that started to write bytes to stderr would sail through the
> snapshot. the value of snapping an empty block is precisely to prove the stream stayed empty."*

that is right, and it is the `never carved out` clause of
`rule.require.contract-snapshot-exhaustiveness` read exactly as written.

## .the gap, precisely

`blackbox/review.by.guard-peer.acceptance.test.ts:116-148` — a clean child process writes either no
byte at all to stderr (no section renders) or a bare newline (the section renders with an empty
body). the sanitizer settles that flake by **deletion**:

```ts
const bodyWasBare = next > index + 1;
const closesOnSibling = next >= kept.length || /^[├└]─ /.test(kept[next]!);
if (bodyWasBare && closesOnSibling) {
  index = next - 1;   // ⇐ the whole section is skipped
  continue;
}
```

⇒ the flake is gone and so is the claim. after the drop, a stderr that renders **real bytes** and a
stderr that renders **none** differ only by lines the sanitizer keeps — but the section header
itself is absent from the baseline either way, so the corpus no longer asserts the stream's shape.

⚠️ **the four peer files the same reviewer named are NOT this defect** —
`driver.route.{set,failsafe,conversation-visibility,judge-failure}` and
`driver.route.peer-measurement.journey`. there the empty `├─ stderr` branch left the snapshots
because **the render stopped emit it**: the judge tree now promotes `stdout` to the last-child glyph
`└─` when stderr is empty. that is a deliberate prod change and the snapshot tracks it faithfully —
real bytes would render a populated `├─ stderr` branch and go red. **one file carries this defect,
not six.**

## .the shape of the fix

one line, plus a resnap:

```ts
if (bodyWasBare && closesOnSibling) {
  deflaked.push('├─ stderr: <empty>');   // ⇐ collapse to a stable marker, never delete
  index = next - 1;
  continue;
}
```

both run-to-run shapes then converge on the **same** marker, so the flake stays settled **and** the
stream stays pinned: real bytes render a body, which no longer matches the marker.

⚠️ **then sweep for the same shape elsewhere before you call it done.** this sanitizer was authored
once and copied; `rule.require.enumerate-before-you-name` applies — grep every acceptance helper for
a branch that skips a section rather than marks it.

## .why it is not done in this round

**safe, but not verifiable here** — which is a different bar than clean, and the sharper one.

`review.by.guard-peer.acceptance.test.ts` drives a **real brain** through `rhx review.by`. its five
`ehmpathy.test.*` keys are absent on this host, so the only way to mint the new baseline is a
`lenient` resnap — and under `lenient` the peer malfunctions, `when.repeatably` writes an
`attempt 2`/`attempt 3` key from that malfunction, and the corpus records a `💥 malfunctioned`
reviewer as an approved `0 blockers / 0 nitpicks`.

⇒ **that is the exact `0/0` failhide `contract.reviewer-output` forbids, written as the approved
contract.** a marker minted that way is worse than the drop it replaces: it would look like a repair
and pin a lie.

🔴 **and to ship the edit WITHOUT a resnap is worse still** — the extant baseline would go red on the
next real-credential run, so the repair would break a green suite to fix a nitpick.

⇒ the edit was written, measured against both, and reverted. it lands the round a human runs it with
real keys, or the round CI mints the baseline.
