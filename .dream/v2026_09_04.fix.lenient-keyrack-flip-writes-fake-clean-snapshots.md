# 🌙 dream: a lenient keyrack flip silently WRITES fake-clean snapshots

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, at stone `5.3.verification` of
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

i flipped `jest.acceptance.env.ts:63` from `mode: 'strict'` to `mode: 'lenient'` to run one
credential-free acceptance suite locally. i reverted the flip and assumed the tree was clean.

it was not. `git status` showed **two `blackbox/__snapshots__/*.snap` files modified**, +408 lines,
0 deletions — written by suites i never intended to run and never edited.

## .the gap, precisely

the extant brief `rule.require.repeatable-for-llm-tests` has brain-driven suites use
`when.repeatably({ attempts: 3, ... })`. each attempt names its own snapshot key —
`… attempt 1`, `… attempt 2`, `… attempt 3`.

under `strict`, an absent key exits 2 before any suite runs, so **no snapshot is ever written**.
under `lenient`, the suite *runs* with no credentials, the brain call malfunctions, and jest
**creates** the absent `attempt 2` / `attempt 3` keys from that malfunction:

```
+exports[`review.by.acceptance … attempt 2 … the positive-path contract stdout is stable 1`] = `
+"🦉 needs your talons
+
+🔍 review.by --role demo
+   ├─ rubrics
+   │  └─ r1 demo-arrow-only ✗
+   │     ├─ malfunctioned 💥
+   │     │  └─
+   │     └─ review: .reviews/by=demo/rubric=demo-arrow-only.md
+   └─ summary
+      ├─ 0 blockers
+      └─ 0 nitpicks
+"
+`;
```

🔴 **read the last three lines.** a `💥 malfunctioned` reviewer with an empty reason, recorded as
`0 blockers / 0 nitpicks` — and that pair is written to disk **as the approved contract**.

⇒ this is verbatim the failhide `contract.reviewer-output` forbids: *"if it finds no numeric count
it can NOT assume zero. a silent 0/0 would look like a clean approval when in truth no verdict was
seen."* the shipped engine gates on it correctly at runtime (`asPeerGivenVerdict`). the **snapshot
file** has no such guard.

## .why it is worse than a normal flake

| | a normal flake | this |
|---|---|---|
| where it lands | a test result | **a committed artifact** |
| how it announces itself | red | **green** — the new key matches on the next run |
| who catches it | the runner | only a human who reads `git status` |

the flip is advertised as *"partial results are acceptable"* — the hint printed by the failure
itself is `hint: use mode: 'lenient' if partial results are acceptable`. it does not say
*"and it will write new snapshot baselines from the partial results."* a driver who takes the
hint at face value, runs, and commits has poisoned the baseline, and every later run agrees with
the poison.

## .the shape of the fix

reach for the highest rung that holds:

1. **CI already covers the keys** (`.github/workflows/.test.yml:215,299` runs `keyrack firewall`),
   so the block is local-only and the flip is a local convenience. the cheapest real fix is to
   make the flip **snapshot-safe**: when keys are absent, run jest with `--ci`, under which an
   absent snapshot is a **failure** rather than a write.
2. or: have the lenient branch set `process.env.CI = 'true'` itself, so the safety rides the mode
   rather than the invoker's memory.
3. or, at minimum: extend the printed hint to name the side effect —
   `hint: use mode: 'lenient' if partial results are acceptable (⚠️ new snapshots will be WRITTEN)`.

⇒ (1) and (2) are mechanisms; (3) is a cue. per `philosophy.entoolment-is-the-pinnacle`, prefer
the mechanism — the cue relies on a reader who is already in a hurry.

## .why it is not done in this round

**safe? no.** it edits the shared jest harness that every suite in the repo boots through, and
this behavior's stone is a peer-review gate with no connection to the test harness. a harness
change here would ride an unrelated diff and be graded by reviewers scoped to the gate.

**clean? no.** `--ci` changes the failure mode of every absent snapshot repo-wide, which is a
deliberate call with its own blast radius.

⇒ so it is caught rather than fixed (`rule.always.catch-dreams-for-followups`).

## .the immediate cost, for the record

the two polluted files were restored to their committed state by hand this round, verified
byte-exact. no fake baseline shipped. **the near-miss is the point** — it was found by a
`git status` read i nearly skipped, not by any check in the repo.

## 🔴 .it recurred the next day, and caught the author of this dream

**2026-09-05, same route, same stone.** i flipped both harnesses to run one scoped resnap, and
then — with the flip still applied — ran the **full** acceptance suite. five `blackbox` files,
**+528 lines**, every one of them an `attempt 2` / `attempt 3` key that records `malfunctioned 💥`
or `passage = malfunction` under cases named *"against clean code"* and *"the guard approves"*.

⇒ 🔴 **i had written this dream the previous day, and it did not stop me.** that is what the
recurrence teaches. a document that names a hazard is not a guard against it, and the reader most
likely to be caught is the one who believes they already know. the fix table above ranks a
mechanism over a cue on principle; this occurrence is the measurement behind that rank.

### the two facts the first occurrence did not surface

**1. the blast radius scales with test SCOPE, not with the flip.** the flip alone is inert. what
mints poison is a *broad* run under `--mode apply`:

| the run, under the flip | files poisoned |
|---|---|
| `--scope path://<one suite>` `--resnap` | **0** — the scope never reaches a brain suite |
| the full suite, `--mode apply` | **5** |

⇒ so the safe protocol is narrower than *"flip, run, revert"*: **never let a flipped harness meet
an unscoped run.** the scoped resnaps in this same round were harmless, which is exactly why the
full run felt harmless too.

**2. 🔴 the recovery path is NOT what this dream assumed.** *"restored by hand"* was written as
though it were cheap. it is not:

| the move | the outcome |
|---|---|
| `git checkout -- <paths>` | **denied** — a destructive git command, correctly gated |
| `git show HEAD:<p> \| rhx teesafe --into <p>` | restores the body, then **drops the final newline** — so every file stays `M`, apart by one byte |
| `printf 'X\n' \| rhx teesafe --idem append` | proves the drop: `X` lands with no newline after it |
| `npm run fix:format` | biome does not cover `.snap`; *"No fixes applied"* |
| the `Write` / `Edit` tool, per file | ✅ the one path that restores byte-exact |

⇒ **`teesafe` cannot write a file that ends in a newline**, so it cannot restore any text file
byte-exact. worth its own dream if it is not already known — a silent one-byte corruption in a
tool whose whole job is safe writes. and note the trap: after the teesafe pass the *poison was
genuinely gone*, so a `git status` glance that stops at *"still modified"* invites the read
*"the restore failed"* when in truth only a newline was owed.

### 🔴 3. and the restore did not land on all five — the analysis was mistaken for the act

**the sharpest fact of the recurrence, and it was found by peer review rather than by me.** the
table above was written as a *finished* account. it was not. one file was restored; **four were
not**, and `228` lines of poison sat in the tree across `review.by.acceptance`, `.dispatch`,
`.wrapper`, and `.journey` for a further round.

three independent reviewers at `5.3 i013` — `behavior-experience-coverage`, `mech-given-when-then`,
`mech-test-intent` — each raised it as a blocker, unprompted and in the same round.

⇒ **the failure was not the flip and not the recovery path. it was that a written diagnosis felt
like a completed repair.** the dream section reads as a post-mortem, so a re-read confirms the work
rather than tests it. that is a distinct hazard from the one this dream opened with, and it is the
one that actually cost a round.

**the test that would have caught it costs one command**, and it is the test the whole recovery
table implies but never states:

```sh
git diff origin/main --stat -- blackbox/__snapshots__/
```

a restore is complete when the restored files are **absent from that list**. `git status` cannot
show this — a poisoned file and a byte-short file both read `M`.
