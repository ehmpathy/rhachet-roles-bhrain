# case=5 — a fulcrum without frontmatter holds the stop

cells: R16 (sharp, critipath) · R45 (sharp, critipath) · R17 (sharp, alterpath) — invariant 5

the canonical field list, used by every surface below — one list, one formatter:

```
required: case · rework · ground · confidence · status · owed · holds · lean · verdict
optional: reflect   (required when owed: reflect)
```

## .narrative

mid-drive the driver itemizes fulcrum F9 the old way: a prose body and a summary row, no
frontmatter at all. it tries to end its turn. the onStop linter walks every
`$route/.fulcrums/inventory.of=fulcrums.case=*.md`, finds F9 holds none of the required fields, and
holds the stop with exit 2. the message names the file, lists every required field as absent, and
pastes the block to add. the driver adds it; the next stop goes through.

had the driver instead tried to dispute against F9, `--as disputed` would have refused at once,
with the same field list and fix — the cheapest moment to catch it.

later, F44 — already disputed, valid at the time — is hand-edited and its yaml breaks. the stone
reaches the human gate. the halt cannot read F44. it does not skip it: a skipped dispute is the
incident rebuilt. it lists F44 as `unreadable, owes repair`, and approval is refused until the
driver repairs the file.

the driver also edits the summary table by hand, and types F9's confidence as `0.85` while the
frontmatter says `0.65`. there is no second place to type it: the summary row is derived, so the
next derive overwrites the hand edit, and the halt never reads the summary at all.

```
  then stderr names the file
  then stderr names each absent field: all nine required fields
  then stderr shows the frontmatter block to paste

  then refused, exit 2, with the same field list and block (one formatter)
when [t1] the driver adds valid frontmatter and the turn ends
  then the stop goes through
when [t2] the summary row's confidence is hand-typed to disagree with F9's frontmatter
  then the summary is re-derived from frontmatter; the frontmatter wins
given F44 was disputed while valid, then its yaml broke
when [t3] the stone reaches its approved? halt                                         # R45
  then the halt lists F44 as "unreadable, owes repair" — never omits it
  then --as approved is refused until F44 reads again
```
