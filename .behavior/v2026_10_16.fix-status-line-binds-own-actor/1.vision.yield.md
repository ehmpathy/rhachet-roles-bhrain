# 1.vision — the status line binds where rhachet derives every actor from

## .the outcome world

a human links the driver role, enrolls a driver clone, and the foot of the clone's session reads
`🗿 3.blueprint`. a week later they upgrade rhachet, re-enroll, add a second actor — the line is
still there. nobody thinks about it again.

| | before | after |
|---|---|---|
| where the init writes | `<repo>/.claude/settings.json` | `<repo>/.claude/settings.of.repo.json` |
| what that name is, under rhachet ≥1.49 | an arrow to the grove — rhachet replaces any real file there | the one real file, and the **source** every actor derives from |
| next `rhx enroll` / `rhx init` | arrow restored, `statusLine` dropped in silence | `statusLine` rides through to every actor's own `settings.of.repo.json` |
| a clone of another actor | gets no status line | gets it at its next enroll, or the next `rhx init --hooks` |
| the init's stdout | `status = configured` — a lie, one enroll later | `status = configured`, true, plus a note when the caller's config dir is a peer actor's |

**the aha:** the init never had to know *which actor runs it*. rhachet already owns the fan-out —
it derives each actor's settings from the repo actor's file on every enroll. the init only has to
write the file rhachet reads, not the one it discards.

## 🟡 .the vision diverges from the wish's spec — on evidence, flagged for the gate

the wish asks the init to write into **the brain dir of `rhx clone whoami`**, and to refuse with
exit 2 when no clone runs it. measured against rhachet 1.49.2, both halves would re-open the bug:

| the spec | what rhachet does | the consequence |
|---|---|---|
| write into the whoami actor's own `settings.of.repo.json` | `genBrainCliConfigArtifact` rewrites a non-repo actor's `settings.of.repo.json` **whole**, from the repo actor's, on each enroll and each `rhx init --hooks` sweep (`setActorSettingsDerived`) | the bind survives the layout findsert, then dies at that actor's next enroll — the same silent vanish, one step later |
| no clone → exit 2 | `rhx init --roles` runs role inits from the caller's shell (`getRolesLinkedFromFound` → `execRoleInits`), and throws on any nonzero exit | every human `rhx init --roles driver` fails |
| `.claude` names "whichever actor" | `setRepoBrainDirSymlink` always links `<repo>/.claude` to the **repo actor**'s brain dir; rhachet's own doc names it as the write door for role inits (`setRepoActorBrainDirLayout`: a role init writes through `<repo>/.claude`, e.g. a permission hook that adds its allows to `settings.of.repo.json`) | the second fault in the wish is not a fault under 1.49 — `.claude` is the right door; only the filename was wrong |

⇒ the wisher's **local patch** (`$GITROOT/.claude/settings.of.repo.json`) is the fix, and it is
correct for every actor, not only by luck. the whoami route is kept on record as fulcrum F1, for
the wisher to overrule at this gate.

🟡 **this is pavement, not invention.** ehmpathy's `init.claude.permissions.sh` (1.39.5) — the
mechanism this init says it mirrors — already made this exact move: split layout →
`settings.of.repo.json`, old layout → `settings.json`, refuse a linked target, and a note when
`CLAUDE_CONFIG_DIR` names a peer actor. the vision adopts that shape.

## .the contract

```
init.claude.status-line.sh

target file, by layout:
  split  (settings.json is a link, OR settings.of.repo.json exists)  -> .claude/settings.of.repo.json
  old    (neither)                                                   -> .claude/settings.json

warn:     target is a link            -> 🦉 patience · status = not configured, on stderr, the fix named, exit 0, no write
warn:     target is not valid json    -> 🦉 patience · status = not configured, names the file, exit 0, no write
warn:     the .jsonc config is absent -> 🦉 patience · status = not configured, exit 0
          (a state a human must fix never fails `rhx init` / `rhx upgrade`; a jq fault still exits 1)
skip:     split layout, and driver is not linked (`.agent/repo=bhrain/role=driver`)
                                       -> 🦉 as leaves fall · status = skipped, names the fix, exit 0
remove:   split layout, driver not linked, and the target holds OUR statusLine
                                       -> 🦉 as leaves fall · status = removed, backup, exit 0
          (the link is the source rhachet derives the repo actor's roles from; its `actor.json` is
           a cache that lags until a clone enroll, so it is never read. rhachet runs this init only
           right after it links driver, so skip and remove fire on an explicit init alone — an
           unlink runs no init and the line stays, pinned and caught as a dream; F15)
skip:     a foreign statusLine in the target OR the grove ($HOME/.claude/settings.json)
                                       -> 🦉 as leaves fall · status = skipped, exit 0,
                                          names the layer, the command found, and how to opt in
no-op:    ours, current               -> status = already configured, exit 0
write:    absent, or ours in an older form -> status = configured, backup of a prior file,
                                          and a leaf: it takes effect at each rhx enroll session's next start
note:     $CLAUDE_CONFIG_DIR names a dir other than <repo>/.claude
                                       -> a leaf: this session's config dir, and when it picks up the bind
                                          ("session", not "clone": a human with their own
                                           CLAUDE_CONFIG_DIR trips the same test)
```

```
🦉 the path is clear

🗿 init.claude.status-line
   ├─ status = configured
   ├─ settings = .claude/settings.of.repo.json
   ├─ backup = .claude/settings.of.repo.2026-10-16T16-02-11Z.4112.bak.json
   └─ reach
      ├─ this session = .agent/.actors/actor.via.hash=7dcf1989/brain/.claude
      └─ picks it up at its next rhx enroll, or the next rhx init --hooks
```

## .mental model

> *"the driver's status line goes in the repo's settings file, and every clone inherits it."*

| a human says | we say |
|---|---|
| the repo's settings | the repo actor's `settings.of.repo.json` |
| every clone inherits it | each actor's `settings.of.repo.json` is derived from the repo actor's |
| my own claude settings | the grove — `~/.claude/settings.json`, behind `settings.of.grove.json` |

analogy: a team wiki page vs a printed copy on each desk. the old init scribbled on one desk's
copy, and the janitor (enroll) reprinted it. the fix edits the wiki page; every desk's next print
carries it.

## .evaluation

| goal | met? |
|---|---|
| the bind survives enroll and layout findsert | ✅ the target is the one file both leave alone, and the source both derive from |
| only actors enrolled with driver get it | 🟡 partial, by the wisher's call: bound only when driver is linked, so the repo actor carries it; an unlink leaves the line until rhachet runs a role teardown (F15); rhachet's derivation then copies it to every peer, driver or not — an accepted leak until rhachet renders a role-declared status line per actor (F3, a reseed dream) |
| `rhx init` / `rhx upgrade` never fail on this init | ✅ every human-fixable state warns and exits 0; the published init exited 1 when `~/.claude/settings.json` was absent (the dangled arrows) |
| no silent fallback | ✅ the target is chosen by layout, a link refuses, and the note names a peer config dir |
| a human's own status line is never clobbered | ✅ skip-and-warn, now over the grove too (F4) |
| `rhx init` from a human shell still works | ✅ no clone is required |

**cons**
- a non-driver actor derived from a driver repo actor also renders the line; a driver actor derived
  from a non-driver repo actor does not. both wait on the rhachet feature (F3)
- a live session does not pick up the bind until its next start; a peer actor, until its next
  enroll or `rhx init --hooks` — the output says both
- `init.claude.permissions.route.sh` carried the same defect (it wrote the arrow, so every run
  re-healed) and the same exit-1 path; it gets the same target choice and warn-and-pass
- a plain `claude` session started in the repo, outside `rhx enroll`, no longer renders the line.
  it reads `settings.json` — the grove arrow — and never `settings.of.repo.json`, which only rides
  a clone's spawn args (`enroll/asBrainCliSpawnArgs.js`: the user source, then `--settings` with
  the actor's `settings.of.repo.json`). the old init reached it only until the next enroll; under
  1.49 the role's hooks do not reach it either. so the line now lives exactly where every other
  rhachet-owned config lives

**edge cases, and the pit of success**
- target is a symlink → refused before any write (mirrors rhachet's own `must be a real file` refusal)
- a human statusLine in the grove → skip, since `--settings` would outrank and hide theirs. this
  keeps extant behavior: the old init's read of `settings.json` (`init.claude.status-line.sh:75`)
  went through the arrow to the grove, so it already skipped there
- a malformed target → a warn that names the file, exit 0. the published init dies on the ERR
  trap at line 75 with jq's own exit 5, and fails the whole `rhx init` run
- the grove absent → the arrows dangle; the published init writes `{}` through them into a dir
  that does not exist and exits 1. the fix never writes the arrow, so it binds and exits 0
- older form of our own command → recognized by the two ownership literals and updated
- two inits in parallel → `mktemp` temp + per-pid backup, as today

## .what is awkward

- the init cannot make a live clone see the bind now — the derivation is rhachet's, and runs on
  enroll or `init --hooks`. the note is the honest answer, not a fix
- the ownership check still keys on two string literals (`routeStatusLine`, `route.status.line`) —
  an accepted v1 tradeoff the init already records, left as is
- the vision reverses an explicit wisher spec. the evidence is strong (F1 at 90%), but the call is
  theirs, which is why it rides the vision gate rather than a later stone
