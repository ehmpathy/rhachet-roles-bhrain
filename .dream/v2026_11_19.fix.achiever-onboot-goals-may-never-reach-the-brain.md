## .the cue that fired

the absorbed law `rule.always.keep-the-top-goals-in-view` leans on the onBoot hook to put the open
goals back in view after a compaction. a read of `goalTriageNext` (`src/contract/cli/goal.ts`)
shows that on `--when hook.onBoot` it writes the goal tree to stderr and exits 2.

## .the gap, precisely

rhachet maps `onBoot` to claude code's `SessionStart`. per the claude code hooks doc, a
`SessionStart` hook's stdout is added to the brain's context, and exit 2 has no block effect: its
stderr is shown to the human only. so the open goals may print where the human sees them and the
brain does not, which is the exact miss the law names (priorities lost at each compaction).

unverified on a live session: the claim rests on the doc and the source, not on a transcript.

## .the shape of the fix

- verify first: a session with one enqueued goal, `/compact`, then read whether the brain's
  context holds the `💎 goal.triage.next --when hook.onBoot` tree
- if it does not: on `hook.onBoot`, write the tree to stdout and exit 0; keep stderr + exit 2 for
  `hook.onStop`, where exit 2 is the block that forces continuation
- clamp: an acceptance case on `--when hook.onBoot` that asserts stdout holds the tree and the exit
  is 0; revert the fix → red
