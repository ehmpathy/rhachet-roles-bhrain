# 🌙 dream: the unit suite crosses the filesystem boundary, repo-wide

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04

## .the cue that fired

a peer reviewer (`mech-test-scope-purity`) graded two of my new test cases a blocker under
`rule.forbid.unit.remote-boundaries` — a `.test.ts` file must not touch the filesystem.

it is **correct about the rule and wrong about the culprit**. i checked whether my diff introduced
the boundary, and it did not:

```
$ git show origin/main:…/enumRouteGuardReviewPeerFiles.test.ts | head -3
import * as fs from 'fs/promises';
import * as os from 'os';
import * as path from 'path';
```

`[case1]` on `origin/main` already calls `fs.mkdtemp`. same for `setStoneAsContemplated.test.ts`,
whose `genScene` helper is **context** in my diff, never an addition.

## .the gap, precisely

at least **8** unit-classified files import `fs` and do real disk i/o:

| file |
|---|
| `route/passage/getAllPassageReports.test.ts` |
| `route/passage/getOnePassageReport.test.ts` |
| `route/passage/setPassageReport.test.ts` |
| `route/stepRouteStoneGet.test.ts` |
| `route/stepRouteStoneDel.test.ts` |

plus the two the reviewer named. this is settled repo practice, never a defect this behavior
introduced.

## 🔴 .why it is NOT safe to repair today — and the two defects are ORDERED, not independent

the obvious repair is to rename each to `.integration.test.ts`. **that would take tests that pass
today and make them unrunnable**, because `jest.integration.env.ts:96` demands five brain keys of
*every* integration suite:

```
$ rhx git.repo.test --what integration --scope 'path://setStoneAsPassed.contemplation' --mode apply
  ✋ some keys were not granted, yet are strictly required
  at Object.source (jest.integration.env.ts:96:11)
```

⇒ **the harness defect is what holds the misclassification in place.** to reclassify first is to
trade a correct label for a dead test — a regression in verification dressed as a repair.

so the order is forced:

1. **first** fix the harness — see
   `.dream/v2026_09_04.fix.integration-harness-demands-five-brain-keys-from-every-suite.md`
   (a suite that makes no brain call must not be gated on brain keys)
2. **then** reclassify, in one sweep, with the tests still able to run

## .the shape of the fix

the harness half is the small one, and it unblocks the rest: gate `keyrack.source` on whether the
suite actually needs a key rather than on the file's extension. the cleanest form is a per-suite
opt-in — a suite declares the keys it needs, and the preflight demands only those. today it is
one blanket `strict` call at the setup level, so a suite of pure shell fixtures pays the same toll
as one that calls a frontier model.

⚠️ **the reclassification must be a single sweep, never piecemeal.** to move only the two cases the
reviewer named would split one test subject across two files while the same pattern stayed in
both — a fifth path beside four, which is the braided trail rather than a repair.

## .why it is not done in this round

- **not safe** — see above; the repair makes the tests unrunnable until the harness is fixed
- **not clean** — 8+ files, most of them untouched by this behavior and unrelated to the
  contemplation gate
- **out of scope** — `git diff origin/main --stat` shows this behavior touches none of the 8

## 🔴 .the sweep set grew after this dream was filed — amended 2026-09-06

peer lane `mech-test-scope-purity` (r009, i021) raised this as an explicit heads-up rather than a
re-raise, and the half it was right to ask for is that **the sweep set keep pace with the diff**.
two cases authored after this dream was filed cross the same boundary:

| where | what crosses |
|---|---|
| `enumRouteGuardReviewPeerFiles.test.ts` `[case8]` | `fs.mkdtemp` + `fs.mkdir` + `fs.writeFile` against a real temp route |
| `setStoneAsContemplated.test.ts` `genScene` | `execSync('git init', …)`, plus a retired-reviewer `.given` written to disk |

⚠️ **the `git init` seed is the one most likely to be missed**, because it sits in a shared scene
helper rather than in a case, so a sweep that reads case bodies alone will walk past it.

⇒ **these are added to the sweep set, not treated as new defects.** they are the same pattern in
the same suites, and the order above still holds: the harness first, the reclassification second,
in one pass.

🔴 **the general point this amendment records:** a dream that names its scope by enumeration goes
stale the moment the branch adds an instance. so a deferral of a *class* must be re-measured when
the class is touched, or the sweep it schedules will be partial — which is the defect class this
round was blocked for twice (i020 footers, i021 emphasis markers).
