# 🌙 dream: no acceptance test drives a real TTY, so the human-approval path is unproven at that grain

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-07, on `.behavior/v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

a zero-skips sweep of `blackbox/**` — mandated by the 5.3 stone — returned exactly one hit, and it
was the sharpest shape `rule.forbid.failhide` names:

```ts
given('[case2] human session (TTY)', () => {
  when('[t0] human runs --as approved', () => {
    then('acceptance skipped - unit tests cover this path', () => {
      expect(true).toBe(true);          // ← always passes
    });
  });
});
```

⚠️ **it passed the `.skip(` grep**, because it is not a skip — it is a **skip in prose**, declared in
the `then` title and implemented as a tautology. so the two checks the stone asks for (no `.skip()`,
no fake tests) each catch it only if the other is also run.

## .the gap, precisely

`invokeRouteStoneSet` shells out through `execAsync`, and a `child_process` subprocess has **no
terminal attached** — `process.stdout.isTTY` is `undefined` there. so the acceptance harness can
drive the `isTTY: false` branch and **cannot** drive `isTTY: true`.

| grain | `isTTY: true` | `isTTY: false` |
|---|---|---|
| operation — `setStoneAsApproved.test.ts` | ✅ `[case1]` `:35, :44, :52` · `[case4]` `:194–:224` | ✅ `[case3]` `:141–:174` · `[case4]` `:235–:260` |
| acceptance — `driver.route.approval-tty.acceptance.test.ts` | 🔴 **absent** | ✅ `[case1] [t0]` `:71–:91` |

⇒ **one real cell is empty**, and the vacuous case existed to make it look occupied.

🔴 **that is the harm, and it is not the absent test.** an absent case is a visible gap. a case that
renders green while it asserts naught is a gap that **reports itself as covered** — so no later sweep
finds it, and a reviewer who reads the case list concludes the human path is proven end to end.

## .what was done now, and why it is not the fix

the vacuous case is **deleted**, and a block comment in its place states: that it was removed, why,
where the coverage actually lives (with line cites), and that the acceptance-grain cell is still
empty and tracked here.

⇒ **no coverage was lost** — the operation grain always carried it. what was lost is a **false claim
of acceptance-grain coverage**, and that is the whole point of the removal.

✅ **safe to do with no run:** `expect(true).toBe(true)` cannot fail, so its removal cannot change
any suite's pass/fail outcome; the case takes no snapshot, so no baseline is minted or invalidated;
and `types` · `lint` · `format` · `unit` all pass after the edit.

## .the shape of the real fix

drive the CLI through a **pty** rather than a bare `child_process`, so the child sees a real
terminal and `isTTY` is `true`:

1. add a pty dependency (`node-pty` or equivalent) as a dev dependency
2. add an `invokeRouteStoneSetViaTty` helper beside the extant `invokeRouteStoneSet`, which spawns
   through the pty and collects the same `{ stdout, stderr, code }` shape
3. restore a `[case2] human session (TTY)` that asserts the real behavior — approval succeeds,
   `passage.jsonl` gains the row, and the stdout is snapshotted

⚠️ **the helper must stay a peer, never a replacement.** `[case1]`'s whole subject is the **non**-tty
agent path, and it needs the plain `execAsync` to keep that branch under test.

⚠️ **and a pty is a native module.** `ehmpathy/rhachet` has a live branch named
`beav/fix-node-pty-install` — so its install path is known to be thorny in this ecosystem, and the
dependency decision is a wisher call rather than a driver one.

## .why it is not done in this round

**in scope? no.** this behavior gates the contemplation loop (P1/P2). the TTY approval path shares no
file with it, and the gap predates the branch — `git diff origin/main` on that test file is empty.

**safe? no.** it adds a **native** dependency to the test harness, on a repo whose CI runs the
acceptance suite. a native build failure there turns a green pipeline red for every future branch.

**clean? no.** a new dependency plus a new harness helper plus a restored case with a fresh snapshot
is a dependency decision, not a local edit.

⇒ so the vacuous assertion is removed **now** (safe and clean, per
`rule.always.fix-forward-under-scouts-honor`) and the coverage gap is caught **here** — the two are
different acts, and only the first was mine to take.
