# 🌙 dream: teach `kind=` coordinates where new briefs are named

kind: fix · owner: bhrain (researcher, reviewer) · caught 2026-10-26

## .the cue that fired

the #692 rename put every brief file in this repo in coordinate form (`kind=$archetype`), and a
residual grep still found two published surfaces that tell an author to NAME a new file with a
bracket.

## .the gap, precisely

- `src/domain.operations/research/init/templates/5.1.briefs.curate.blueprint.stone` — its example
  tree and its `[doctype]` table name each curated brief `$topic.[article].md`, so every research
  route a consumer runs lays new bracketed files
- `src/domain.roles/reviewer/briefs/on.rules/rules101.collocated.kind=article.md` and
  `rules101.structure.kind=article.md` — the collocated-rule convention shows
  `rule.$directive.$topic.[demo].$qualifier.md`

each contradicts `rule.forbid.brackets-in-filenames` (librarian) for every file it seeds.

## .the shape of the fix

- rewrite each example name to `kind=$archetype` (`em101.fundamentals._.kind=catalog.md`)
- rewrite the `[doctype]` row to `kind=$doctype`, with `*.kind=article.md` as the glob it buys
- resnap the research init snapshots that print the stone

## .why it is not done in this round

it changes a published template contract and its snapshots, outside the rename the #692 thread
asked for (the files themselves); it rides its own pr.
