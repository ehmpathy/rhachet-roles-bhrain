# 🌙 dream: the tsconfig lib holds the es2022 Error `cause` option

- kind: fix
- owner: rhachet-roles-bhrain (mechanic)
- caught 2026-10-26

## .the cue that fired

a peer reviewer (5.1 execution, i002, arch-hazards-maintenance nitpick.5) flagged
`Object.assign(new Error(msg), { cause: error })` in
`src/domain.operations/route/statusLine/cache/getOneBranchFromGit.ts` as a workaround for the
native `new Error(msg, { cause })`.

## .the gap, precisely

`tsconfig.json` sets `"target": "es2020"` and `"lib": ["DOM"]`, which overrides the node20 base's
lib. so `ErrorOptions` is absent from the types, and `new Error(msg, { cause })` fails with TS2554,
though node 20 supports it at runtime.

## .the shape of the fix

add `"ES2022"` (or `"ES2022.Error"`) to `lib`, run types across the repo, then replace each
`Object.assign(new Error(…), { cause })` with the native option.

## .why it is not done in this round

a lib change is repo-wide: it can shift types in every module and is no part of the status line
fix. it fails CLEAN.
