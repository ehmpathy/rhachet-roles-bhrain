# wish: swap brains per stone, via `clone whoami` -> `clone say /model`

## .the outcome

deliver ehmpathy/rhachet-roles-bhrain#377: a `.guard` file may declare a prescribed brain for its
stone, and the driver-role hook applies it automatically on entry — no manual `/model` entry.

## 🔴 .the seed — read it before you design

```sh
gh issue view 377 --repo ehmpathy/rhachet-roles-bhrain
```

that issue carries the full shape: the `brain:` field, the precedent (L3 peer-review's per-model
`enroll`), and the open design questions the issue itself flags (field name, who applies it,
reliability + fallback, default + stickiness). answer those from the issue, not from this file.

## .the application sequence

apply the switch via:

```sh
rhx clone whoami                     # confirm which clone this hook targets
rhx clone say @:driver --what '/model <brainslug>'
```

`whoami` first — confirm the addressed clone is the live driver before the `/model` switch lands,
so a hook active in the wrong context fails loud rather than a silent switch of the wrong clone's
brain.

## .the bounds

| bound | why |
|---|---|
| fail loud, never a silent no-op, if the driver clone is unreachable or the brain rejects `/model` | per the issue's own reliability question, and `rule.require.errors-name-the-fix` |
| a stone with no `brain:` field keeps the inherited brain | no `.guard` should be forced to declare one |
| the field name and stickiness question are OPEN in the issue — best-guess and record the choice, do not block on them | `rule.always.defer-fulcrums-to-last` |

## .what would make this wrong

- a `/model` switch sent with no prior `whoami` confirmation
- a silent failure when the driver clone cannot be reached
- a switch applied to the wrong clone
