# 🌙 dream: the real-bucket backup case skips in silence when its uri is unset

- kind: fix
- owner: rhachet-roles-bhrain (reflect snapshot backup)
- caught 2026-11-05

## .the cue that fired

the `fix-review-input-cacheability` 5.3 scan for `.skip` / `.only` / `runIf` over `src/**/*.test.ts`
found four hits, none in a file the route touched:

- two `.only` under `.scratch/`, which every jest config excludes (`'!**/.scratch/**'`) — never run
- `stepDiverge.integration.test.ts` `when.skip` — already caught, with its fulcrum, as
  `.dream/v2026_10_23.fix.thinker-guards-ask-the-brain-to-refuse.md`
- this one, which no record holds

## .the gap, precisely

`src/domain.operations/reflect/snapshot/backupSnapshots.integration.test.ts:222` —
`given.runIf(process.env.BHRAIN_TEST_S3_BACKUP_URI)`: the only case that proves a real
`aws s3 sync` lands is opt-in, and with the env unset it skips with no line that says so. ci shows
a green suite that never touched a bucket. `rule.forbid.failhide` (tests) names a skip on an absent
resource as no alternative to a loud failure.

## .the shape of the fix

- add a test bucket prefix to the repo's keyrack (`.agent/keyrack.yml`), env `test`
- read it in the case; where it is absent, throw a `ConstraintError` with the hint
  `rhx keyrack unlock --owner ehmpath --env test`, and drop the `runIf`
- the human fills the key once (`rhx keyrack fill --owner ehmpath`)

## .why it is not done in this round

the repair needs a bucket and a credential this route does not hold, and the case sits in the
reflect role, outside this route's scope; a repair that cannot be run is not one.
