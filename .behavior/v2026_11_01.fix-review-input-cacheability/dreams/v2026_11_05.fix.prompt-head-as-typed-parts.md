# 🌙 dream: the head composer returns typed parts, so the census reads lengths, never markers

- kind: fix
- owner: rhachet-roles-bhrain (review compile)
- caught 2026-11-05

## .the cue that fired

a peer lane of `fix-review-input-cacheability` 5.1 i006: `getOneHeadMarkerOffsets` finds the
head's markers by `indexOf` in text `asPromptHead` just built, and carries hints for a
template edit that dropped one.

## .the gap, precisely

the compiled census re-parses output it composed. a marker drift is a class of defect that
exists only because the parts are not returned as parts.

## .the shape of the fix

- `asPromptHead` returns `{ text, parts: { preamble, outputFormat, targets } }`
- the compiled census sums part lengths; only the disk reader for old runs keeps the marker
  search
- stamp the layout in `metrics.compiled.json`, so the disk reader can retire its sniff once no
  unstamped run remains

## .why it is not done in this round

it reshapes the compile result every caller and snapshot reads; the census reads correctly
today, pinned by `compileReviewPrompt.layout.integration.test.ts` `[case4]`.
