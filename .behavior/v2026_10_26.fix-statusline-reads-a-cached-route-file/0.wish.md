# wish: the status line reads a cached route file, never a fresh node process per repaint

repo: ehmpathy/rhachet-roles-bhrain · tasks: ehmpathy/rhachet-roles-bhrain#673, #660

## the defect
the status line spawns a fresh node process on every repaint, per seat. on local, 44 seats: 9 of them held 491% cpu at 21:40 CT on 2026-10-23, on a box at 450%+ all day, where saturation turns integration suites red across the ship bar. the commander graded it p0 and put it on the shiptree.

## the outcome
- route.drive (or the stone set that moves the route) writes a small json beside the route: the current stone, its status, and when it was written.
- the status line reads that json, at most once a minute per seat, with no node process spawned per repaint.
- a stale or absent json reads as such on the line (never a silent blank), and the next route.drive refreshes it.

## done means
- a clamp: a test that counts process spawns per repaint goes red on the old status line and green on the new (zero node spawns per repaint).
- the line shows the same stone and status the old one showed, in a snapshot.
- unit + integration green; pr open; git.release --watch green. release waits on the commander's review.

a blueprint is the commander review: its open questions go to him, never best-guessed.
