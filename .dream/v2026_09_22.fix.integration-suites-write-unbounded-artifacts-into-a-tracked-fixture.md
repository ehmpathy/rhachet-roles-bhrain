# 🌙 dream: integration suites write unbounded artifacts into a tracked test fixture

**kind**: fix · **owner**: this repo (`rhachet-roles-bhrain`) · **caught** 2026-09-22

## .the cue that fired

a suite that passed at **1605 / 0 / 79** earlier in this same session failed at **1594 / 11 / 79**
an hour later, with no edit to it or to the code it exercises. every one of the eleven died at the
same line:

```
spawnSync /bin/sh ENOBUFS
>37 |   execSync('git commit -m "initial"', { cwd: repoPath, env: GIT_ENV });
   at setupTestRepo (src/domain.operations/review/getAllFileDiffsFromRange.integration.test.ts:37:11)
```

reproduced in isolation at one worker, so it is **not** a concurrency flake. ⇒ a test that gets
slower and then dies as the day goes on measures a quantity that grows.

## .the gap, precisely

`src/domain.operations/review/.test/assets/example.repo` is a **tracked fixture** — 15 files,
proven:

```
git ls-files 'src/…/assets/example.repo' | wc -l   →  15
```

and it is also a **write target**. `stepReview.integration.test.ts` and the four
`stepReview.caseBrain.*` suites run real reviews with `example.repo/prose-author` (and
`/typescript-quality`) as their cwd, so `writeInputArtifacts` lands a full run directory —
`input.prompt.md`, `output.response.json`, `metrics.realized.json`, seven more — **inside the
fixture**, on every run, forever.

```
tree -a -L 1 …/example.repo/prose-author/.log/bhrain/review | tail -3
  └── 2026-09-23T01-36-35-922Z.pid2379887.3a04b8ec-…
  654 directories, 0 files
```

🔴 **654 run dirs in one of the two, and the newest is timestamped DURING the run that caught
this.** at ~10 files each that is ~6,500 files of debris against a 15-file fixture — a **433×**
ratio.

it is invisible in `git status` because the repo-root `.gitignore` carries `*.log`:

```
git check-ignore -v …/example.repo/prose-author/.log/bhrain/review
  .gitignore:3:*.log	…/example.repo/prose-author/.log/bhrain/review
```

⇒ **that is what makes it durable.** the debris is ignored where it is written, so nobody sees it;
it is *not* ignored once copied into a fresh temp repo, because `.gitignore` does not travel with
a directory copy. so `git add .` stages all ~6,500, `git commit` prints one `create mode` line per
file, and the commit's stdout overruns node's 1 MB `spawnSync` pipe.

### 🟡 the proximate half is FIXED; this dream is the other half

| the defect | disposition |
|---|---|
| the fixture copy took whatever sat on disk, not what git tracks | ✅ **repaired** — `copyAssetFixture` copies the `git ls-files` set, at both copy sites. 11 failed → **11 passed**, 14s → 7s |
| 🔴 the suites still write unbounded debris into a tracked fixture | **this dream** |

⇒ the repair makes the *reader* hermetic and leaves the *writer* aimed at the fixture. so the
directory still grows, and the next consumer of that asset inherits the same trap — which is
exactly what happened here, since the copy predated the debris by a long way.

## .the shape of the fix

aim the run artifacts at a temp root rather than the fixture:

1. the five suites (`stepReview.integration.test.ts` + four `caseBrain.*`) copy the fixture into a
   `genTempDir` and run there, so the debris dies with the test. **this is the repair** — the
   writer's cwd contract is untouched, only the test's cwd moves
2. 🟡 do **not** reach for a per-suite cleanup that deletes `.log/` in `afterAll`. it re-creates
   the trap the moment a suite fails early, and it asserts over somebody else's directory
3. add `.log/` to a fixture-local `.gitignore`? ⛔ **no** — it hides the growth rather than halts
   it, and the fixture has no business with an ignore file at all
4. clean the extant ~6,500 files once, after (1) lands — before it, the next run re-creates them

🟡 **the clamp to write before the fix** (`rule.require.clamp-edge-cases`): assert the fixture dir
holds exactly the tracked file count after a suite runs. it must be seen **red** against today's
tree, which it will be — 654 dirs are there right now.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| leg | verdict |
|---|---|
| SAFE? | 🟡 **uncertain.** four of the five suites are `describe.skip`'d cost-gated llm suites, so a cwd change to them is unexercised by any run this repo ships — a change nobody can verify green |
| CLEAN? | 🔴 **no.** it touches five suites in a subtree this branch's diff does not otherwise open, and the cwd question overlaps `.dream/v2026_09_22.feat.review-cost-reads-the-bare-cwd-where-the-writer-writes-at-gitroot.md`, which reserves the writer's cwd contract for its own settlement |

⇒ a five-suite cwd change, landed inside a review-cost branch, is the **smuggled refactor** the
CLEAN question exists to refuse. and the leg that settles it is the overlap: to move the cwd here
would pre-empt a call that dream already holds open.

## .the fulcrum

> **a directory cannot be a FIXTURE and a WRITE TARGET at once.** a fixture is what is committed;
> a write target is what grows. this one is both, and `*.log` hid the contradiction for 654 runs —
> because the ignore rule that silences the debris at its source does **not** travel to the copy
> that chokes on it.
> rework: **the reader is hermetic now. the writer is still aimed at the fixture**, so the
> directory grows until the next consumer trips over it the same way.
