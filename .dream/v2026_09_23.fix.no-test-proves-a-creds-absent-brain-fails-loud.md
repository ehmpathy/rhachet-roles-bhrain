## .the gap, precisely

the brain-boundary corpus covers **one** failure mode and not the other:

| failure mode | covered? | where |
|---|---|---|
| brain **not found** | ✅ yes | `blackbox/review.by.guard-peer.acceptance.test.ts:433` and `blackbox/review.by.acceptance.test.ts:821` — both assert `brain not found: nonexistent/broken/brain` surfaces as `💥 rubric malfunctioned` rather than a fake `0/0` |
| **credentials absent or locked** | 🔴 **no** | none. `rhx grepsafe --pattern 'FIREWORKS_API_KEY\|ANTHROPIC_API_KEY\|credential\|keyrack\|apiKey' --path blackbox --glob 'review.*.acceptance.test.ts' -i` → **0 matches** |

⇒ the two are not the same defect. *brain not found* is resolved **before any call**, in a local
lookup over `loadAllAtoms()`. *creds absent* is resolved **at the call**, by keyrack, and it is the
mode a real deployment actually meets — an expired unlock, a rotated key, a wrong `--owner`.

🔴 **and the harm is specific to this gate.** `getReviewCountsViaBrain` exists to rescue a review
whose deterministic parse failed. if a creds failure returned an empty or zeroed tally rather than a
loud malfunction, the guard would read `0 blockers` and **approve a stone nobody reviewed** — the
exact failure `rule.forbid.failhide` and `contract.reviewer-output` are both written against
(*"where it finds no numeric count it can NOT assume zero"*).

## .the shape of the fix

the credential path is `src/.test/genTestBrainContext.ts:57-61`:

```ts
return genContextBrain({
  brains: { atoms, repls },
  choice: input.brain,
  creds: { keyrack: { owner: 'ehmpath', env: 'test' } },
});
```

⇒ so the seam is the `creds` argument, and the case does **not** need a keyrack lock. two candidate
directions, cheapest first:

1. **a bad-owner context.** add a `genTestBrainContextWithNoCreds()` beside it that passes
   `creds: { keyrack: { owner: 'no-such-owner', env: 'test' } }`, and assert
   `getReviewCountsViaBrain` surfaces a loud failure rather than a `0/0` tally. an integration test
   beside `getReviewCountsViaBrain.caseBrain.deepseek-v4-flash.integration.test.ts`. **no real
   keyrack state is touched** — the lookup fails on the owner
2. **the acceptance twin.** the same case at the `review.by` boundary, so the loud failure is proven
   to reach a driver's stdout as a `💥 malfunction` rather than an approval. more expensive, and it
   is the one a guard actually reads

⇒ **direction 1 is the one this dream recommends.** it satisfies the rule's clause, needs no
concurrency or keyrack manipulation, and sits in the file whose docblock already declares the
boundary it guards.

## .why it is not done in this round

- **safe?** 🔴 not entirely. the nearest zero-cost form — unset an env var — does **not** reach this
  seam, because creds come from keyrack rather than the environment. the form that does reach it
  needs a new test-context variant in `src/.test/`, a directory this round never opened
- **clean?** 🔴 no. it lands in the brain-boundary corpus (`src/.test/genTestBrainContext.ts` plus a
  new integration case), which is a subsystem this wish does not change. the diff already spans four
  independent repairs to one gate, and `5.3.verification`'s own yield flags that scope spread as a
  question the council may want to split

⇒ deferred, with both artifacts the rules require: this dream, and the fulcrum
`.behavior/v2026_09_17.fix-self-review-min-duration/.fulcrums/inventory.of=fulcrums.case=F26-the-route-driver-suites-stub-the-review-contract.md`,

are two separate calls.
