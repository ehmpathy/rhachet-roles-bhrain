# 🌙 dream: a unit test that imports `fs` is mechanically detectable, and only a reviewer catches it

- **kind** = feat
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-16

## .the cue that fired

`mech-test-scope-purity` raised the SAME point twice in one round:

| round | file | verdict |
|---|---|---|
| i016 | `setStoneAsContemplated.test.ts` | unit-tier, writes `os.tmpdir()` → moved to `.integration.test.ts` |
| i019 | `getAllPassageReports.test.ts` | unit-tier, writes `os.tmpdir()` → moved to `.integration.test.ts` |

two files, one rule, one round — and both were caught by a reviewer rather than by the
boundary itself.

## .the gap, precisely

`rule.forbid.unit.remote-boundaries` puts the filesystem, the network, and the database
out of the unit tier. the rule is clear, the repair is mechanical (rename the file), and
**the detection is entirely manual**.

⇒ a `.test.ts` that imports `fs`, `fs/promises`, `os` (for `tmpdir`), `child_process`, or
a dao is a **statically decidable** violation. no one has to read the assertions to know.

**checkable evidence:** both files above were detectable by one grep, and both survived
every prior round of a suite that runs on every commit.

⚠️ **and the cost is not the rename.** a unit suite that touches disk is slow, order-
dependent, and can leave litter between runs — so the tier boundary exists for real
reasons, and a boundary enforced only by review is one that drifts on every round nobody
happens to look.

## .why it is not done in this round

- **SAFE:** the check itself is safe. what is NOT safe is its first run: it will find more
  files than the two above, and each needs a judgment — move to integration, or refactor
  the fs out. that is a sweep, and a sweep at the close of a verification stone is the
  wrong moment.
- **CLEAN:** no. it lands in the test harness / lint config, never in this stone's
  deliverable, and it wants an allowlist for the cases that are genuinely exempt.
- **the immediate defects ARE closed** — both files are moved. what stays open is the
  recurrence, which is what a mechanism buys and a rule does not.

## .the shape of the fix

a lint rule, or a check in `git.repo.test --what lint`:

```
for every *.test.ts  (NOT *.integration.test.ts, NOT *.acceptance.test.ts):
  refuse if it imports:  fs | fs/promises | child_process | os.tmpdir | **/daos/**
```

⇒ the message names the fix, because the fix is always the same one:

```
🐢 this is a unit test that reaches a remote boundary

  why: it imports `fs/promises`, and the filesystem is a remote boundary
       (rule.forbid.unit.remote-boundaries)

  fix: rename it to the integration tier —
    rhx mvsafe --from src/…/foo.test.ts --into src/…/foo.integration.test.ts
```

🟡 **run it in plan mode first.** its first pass is a census, not a gate — the count it
reports is the real scope of the sweep, and that number is what decides whether the sweep
is one round or several.
