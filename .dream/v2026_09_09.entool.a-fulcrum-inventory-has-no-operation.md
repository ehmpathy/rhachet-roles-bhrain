## .the gap, precisely

🔴 **no code reads or writes `.fulcrums/`.** verified on this route: 64 matches under `src/`, every
one in a `briefs/*.md` or a `boot.yml` — **not one in a `.ts`.** the discipline is brief-level
convention only, so every property it claims is unenforced:

| what the convention claims | what enforces it today |
|---|---|
| an entry exists per best-guessed call | a driver's memory |
| the summary row and the entry both exist | a driver's memory |
| the filename is `case=F$n-$slug` | a driver's memory |
| a verdict lands back in the entry once ruled | a driver's memory |
| the board is readable as a set — sorted on `rework` | a human opens a directory |

⇒ **and the failure is silent by construction.** a fulcrum never itemized leaves no trace at all —
`rule.always.itemize-the-fulcrums-you-best-guess` grades that a blocker, and no mechanism can detect
it.

🟡 **measured on this very route, in one session:** the ordinals were unpadded and re-padded by hand
across 17 files, the count went stale in four separate artifacts, and a `.see also` line held a
superseded number through four review rounds. **every one of those is an operation's job.**

## .the shape of the fix

a `get`/`set`/`del` triad on the route's fulcrum inventory, per
`rule.require.get-set-gen-verbs`:

```sh
rhx fulcrum.set --route <route> --title <title> --rework clean|dirty --confidence <pct> --why @stdin
rhx fulcrum.set --route <route> --case F007 --status ruled --verdict @stdin
rhx fulcrum.get --route <route>                      # the board, sorted on rework
rhx fulcrum.get --route <route> --status open        # 🔴 the query the onStop hook needs
rhx fulcrum.del --route <route> --case F007
```

what the operation buys that the convention cannot:

- **the ordinal is computed, never typed** — 3-char padded at the source, so the sort holds and no
  hand sweep is ever owed (`asStoneGuardCounter.ts`'s `COUNTER_WIDTH = 3` is the extant precedent)
- **the summary row and the entry are one write** — the *"both are owed, always"* clause becomes
  structural rather than a rule a driver recalls
- **the count is derived** — every stale-copy defect this route hit is deleted at the root
- 🔴 **`--status open` becomes queryable**, which is what makes the hook below possible at all

⇒ it also closes the peer dream `v2026_08_31.entool.a-fulcrum-entry-has-no-template.md`, which asks
for `route.fulcrum.set` **by name** with its three sub-steps enumerated. **that dream is the prior
art; this one adds the `get`/`del` half and the `--status open` query.**

## .why it is not done in this round

**SAFE** — no. it is a new writer for a directory no code has touched, and it would ride into a route
whose wish is about a review gate.

**CLEAN** — no. the peer dream gates itself on a `boot.yml` scope call (*"the fulcrum discipline is
booted by ONE role"*), and that call ripples across every role. `:70-72` there says the operation and
the policy call *"travel together"*.

⇒ **and the wisher said so directly** — *"maybe that fulcrum inventory skill should just be a dream
for now."*
