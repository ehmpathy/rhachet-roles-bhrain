# 🌙 dream: rhachet's layout findsert drops a role init's write to settings.json in silence

kind: reseed · owner: ehmpathy/rhachet · caught 2026-10-16

## .the cue that fired
bhrain's driver status-line init wrote `statusLine` into `<repo>/.claude/settings.json`; the next
`rhx enroll` restored the grove arrow and the key was gone. neither tool said a word, so a human
asked "how come the status line is not bound?" days later (`ehmpathy/rhachet-roles-bhrain#620`).

## .the gap, precisely
`dist/domain.operations/actor/enrolled/setBrainDirSettingsLayout.js` `setArrow` swaps a real file
at an arrow name for the arrow and returns `{ kind: 'LINKED' }` — the same effect as a fresh link.
the replaced file's content is neither merged nor kept nor reported (rhachet 1.49.2).

## .the shape of the fix
- in `setArrow`, when `stat?.isFile()`, return a distinct effect (`REPLACED_REAL_FILE`), and have
  the enroll/init report render one leaf: *"replaced a real settings.json with the grove arrow; a
  role init wrote here — role settings belong in settings.of.repo.json"*, with the backup name
- sweep role inits across ehmpathy repos that still target `.claude/settings.json`
- the stronger fix: wrap role-init execution (`invokeRolesInit`, `run --init`) in rhachet's
  `withBrainDirSettingsShield`, which `syncHooksForLinkedRoles` already uses. it folds a write to
  `settings.json` by name into `settings.of.repo.json` under rhachet's mutex, so every init that
  predates the layout, here and in any consumer, just works. a notice alone reports the loss and
  keeps it
- once the shield wraps role inits, the layout probes in `init.claude.status-line.sh`,
  `init.claude.permissions.route.sh` and `src/.test/getRepoClaudeSettingsPath.ts` are delete-ready

## .why it is not done in this round
it belongs to another repo; a tree adopts only what is scoped to itself. the bhrain half is this route.
