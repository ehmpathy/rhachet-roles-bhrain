# 🌙 dream: the route guard's live emitter crashes on a closed pipe

kind: fix · owner: bhrain/driver (route guard) · caught 2026-10-22

## .the cue that fired

`rhx route.stone.set --stone 5.3.verification --as passed | head -80` on
`beav/feat-transcript-token-inventory` — the reader closed early, and the guard died with an
unhandled `'error'` event rather than a quiet end:

```
Error: write EPIPE
    at seal (dist/domain.operations/route/guard/genContextCliEmit.js:54:26)
    at emitLines (…/genContextCliEmit.js:61:13)
    at settle (…/genContextCliEmit.js:237:17)
```

## .the gap, precisely

- `src/domain.operations/route/guard/genContextCliEmit.ts` writes its live progress via
  `input.stderr.write(...)` (lines 51–66) with no handler for a closed stream
- `reflect.on.token.spend` already solved the same defect for its own cli —
  `withQuietClosedPipe` (`src/contract/cli/reflect.on.token.spend.ts:88`, EPIPE only, clamped by
  acceptance case28) — but it is file-local, so no other cli inherits it

## .the shape of the fix

lift `withQuietClosedPipe` to `src/infra/cli/` (it now has a second consumer —
`rule.prefer.most-common-denominator`), and call it at the route cli entry (`route.stone.set`, and
every cli that streams a tree). EPIPE ends the process quietly with the exit it would have had;
every other stream error still throws. clamp: an acceptance case that pipes
`route.stone.set --as passed` into `head -c 0` under pipefail, asserts no `EPIPE` on stderr.

## .why it is not done in this round

SAFE yes, CLEAN no: the route guard emitter and the route cli entry sit outside this route's diff
(a token inventory), and the lift moves a function other files would import — a ripple into the
driver's cli that this stone never opened.
