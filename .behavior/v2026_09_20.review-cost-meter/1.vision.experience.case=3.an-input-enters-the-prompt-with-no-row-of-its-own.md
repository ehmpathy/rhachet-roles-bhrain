# case=3 — an input enters the prompt with no row of its own

- cell = `run` × `chars` × `defend`
- path = **critipath** · feel = sharp · care = criti
- **the highest-cost cell on the board**

## .the narrative

an author adds a ninth input to the review prompt — a `<glossary>` block, say, fed by an
array `getOnePromptComposition` was never told about.

everything looks fine:

- the prompt compiles
- every test passes
- the meter renders a well-formed eight-row table
- the eight rows still sum to `chars`

that last line is the trap:

```
markup = chars − (the other seven)
```

`markup` is the **residual**. so `sum(all eight) === chars` holds **by algebra**, whatever
enters the prompt. the sum assertion proves the arithmetic and proves **no coverage at
all** — and it is the assertion an author naturally reaches for.

the unattributed chars land whole in `markup`, the table looks complete, and every
percentage in the corpus study is now wrong by the size of a block nobody named.

## .the second detector

`markup` is render overhead — section headers, xml tags, `---` separators. measured on a
realistic prompt it runs ~1%. so its **share** is a real detector where its sum is not:

```
markup.chars / chars   <   0.1
```

an input that enters with no row swells that share and trips the bound. a genuine prompt
never can.

per `rule.require.clamp-edge-cases`, the bound was proven red before it was trusted:
`[case5]` of the composition test renders 5,000 unattributed chars and asserts both that
the sum stays green (the tautology, demonstrated) and that the share bound trips.

## .the fourth obligation — measure what was sent

the same cell holds a second failure, in the opposite direction: a diff that the census
counted but the renderer did not send. `targetDiffs` inflates by bytes that never entered
the prompt, so the residual goes negative — and the sum assertion stays green through that
too.

the repair is structural, not vigilant: **one decision, read by both sides.**
`isTargetDiffSent` is called by `renderPushTarget` and by `getOnePromptComposition` alike,
so the two cannot disagree. with the census half reverted, `targetDiffs` read `401`
(expected `0`), `markup` read `−189`, and the sum assertion stayed green — the tautology,
demonstrated end to end.

## .the bdd sketch

```
given [case3] a prompt whose inputs are all declared
  when [t0] the composition is measured
    then every declared input carries chars, count, and a cache-seam flag
    then the eight rows sum to `chars`
    then markup's share is below the bound
given [case3b] a prompt with a block fed by no declared array
  when [t1] the composition is measured
    then the sum assertion stays green — and so proves no coverage
    then the markup share exceeds the bound
    then the unattributed chars are visible in markup, never hidden
given [case3c] a target whose diff is held but not rendered
  when [t2] the composition is measured
    then targetDiffs counts only what `isTargetDiffSent` admits
    then markup is >= 0 — a negative residual names a counted-but-unsent input
```

## .the mental model, in the reader's words

> *"the receipt has to add up — but a receipt that adds up is not a receipt that is
> complete. the line that says `other` is where everything unaccounted-for hides, so the
> question is never 'does it total?' — it is 'how big is `other`?'"*

## .why it is a critipath

low frequency, maximum cost, silent failure. every other cell fails loudly or visibly.
this one fails by producing a number that looks right, and the corpus study built on it
looks right too — which is how a lever gets chosen against a lie and ships a regression
while the figure improves.

it is also what makes `rule.require.distinguish-every-review-input` enforceable rather
than advisory: the rule is only as real as the detector that bites.
