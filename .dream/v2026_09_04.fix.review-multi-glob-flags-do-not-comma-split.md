## .the cue that fired

i reached for a second opinion per `rule.always.get-a-second-opinion-before-foreman`, passed three
rule files to `--rules`, and got told my globs matched no files. they matched three.

⚠️ **the cue is not the failure — it is that i believed the error.** i spent two probes on a
*"dot-directories are skipped by globby"* hypothesis that was wrong, because the message told me to
go look at my patterns and my patterns were fine.

## .the gap, precisely

`--rules` accepts **one** glob. hand it a comma-joined list and it matches zero — then reports that
as a pattern problem.

measured, with each half verified extant by `globsafe` first:

| `--rules` argument | result |
|---|---|
| `src/…/rule.always.spend-own-levers-before-escalation.md` | ✅ `rules: 1`, review ran |
| `.agent/repo=.this/role=any/briefs/rule.prefer.scoped-tests-locally.md` | ✅ passed the rules check |
| `src/…/rule.always.converge-to-terminal.md,src/…/rule.always.drive-autonomously.md` | ⛔ **`--rules glob found nada`** |

both halves of row 3 exist — `globsafe` returns 1 file for each. so the list form is the defect, not
the paths.

🔴 **two things are wrong, and the second is the expensive one:**

1. `--rules` does not split on `,` — while `--help` calls it *"glob pattern(s)"* (plural), and the
   peer flag `--paths` is documented *"comma-separated"*. so the contract reads as though it splits
2. the error hint is **misdirected**: *"verify the glob pattern matches files in your repo."* the
   patterns did match. it sends the reader to audit correct input, which is why i lost two probes

⇒ it fails **loud**, which is right, and then **names the wrong fix** — the shape
`rule.require.errors-name-the-fix` exists to prevent.

## 🔴 .the second amendment — BOTH prescribed workarounds are broken, and this cost five review lanes

**measured 2026-09-05, i016, same stone.** the amendment above closed with *"✅ a brace pattern
works and is the extant workaround for every one of them"*, and the fix shape below still says
*"pass a brace pattern like `{a,b}/**` **or repeat the flag**."* **neither holds.** the same
`rule.require.enumerate-before-you-name` failure this dream already confesses to, committed a
second time, on the workaround rather than on the defect.

### workaround 1 — a brace works in the DIRECTORY position and is silently dropped in the EXTENSION position

| `--paths-with` argument | scope block | targets |
|---|---|---|
| `{blackbox,src/contract}/**` — brace in the **dir** slot | ✅ `paths: {blackbox,src/contract}/**` | 71 |
| `**/*.ts` — no brace | ✅ `paths: **/*.ts` | 88 |
| `**/*.{ts,sh,md,snap}` — brace in the **ext** slot | ⛔ **`paths: (none)`** | **278** (unbounded) |

⇒ the earlier row that proved *"a brace works"* tested **one** brace position. the class is
narrower than the claim, and the position that fails is the one a reviewer reaches for most.

### workaround 2 — a repeated flag keeps only the LAST

| `--paths-with` arguments | scope block | targets |
|---|---|---|
| `'**'` then `'package.json'` | ⛔ **`paths: package.json`** | **1** |

`'**'` alone matches 278. it is discarded without a word.

**and this one is read from source, not only measured.** `parseReviewArgs`
(`src/contract/cli/review.ts:121-151`) is a hand-rolled loop, separate from the repo's own
`getCliArgs` — whose `accumulateNamedArg` *does* accumulate repeats into an array
(`src/infra/cli/getCliArgs.ts:20-33`, docblock: *"enables repeated flags like --refs x --refs y"*).
`parseReviewArgs` special-cases exactly two keys, `refs` (`:130`) and `optional` (`:136`); every
other flag falls to `:147`:

```ts
} else if (value && !value.startsWith('--')) {
  options[key] = value;   // 🔴 assignment, never accumulation
  i++;
}
```

⇒ **two parsers, one repo, opposite behaviour on repeats** — and `review.ts:157` then casts the
result `as string | undefined`, so a type error could never have surfaced it.

## .the shape of the fix

two edits, and the second matters more than the first:

- **split every multi-glob flag on `,`** — `--rules`, `--paths-with`, `--paths-wout`, `--refs`,
  `--conversation` — so the plural in `--help` is true. 🔴 **one shared arg-parse transformer, reached
  for by all five.** there is no correct peer to copy: the measurement above shows `--paths-with`
  carries the same defect, so a per-flag fix would leave the family split again
- 🔴 **accumulate repeated flags in `parseReviewArgs`.** it special-cases `refs` and `optional`
  and assigns every other key, so a repeat overwrites. the repo already owns the correct
  transformer — `accumulateNamedArg` in `src/infra/cli/getCliArgs.ts` — so this is a **reuse**,
  never a new mechanism. ⚠️ **do this one first**: it is the smallest edit and it makes "repeat
  the flag" a true workaround for the rest
- **make the error discriminate.** when the raw argument holds a `,` and the unsplit string matched
  zero, say so: *"`--paths-with` takes one glob; it does not split on `,` — repeat the flag."*
  that is the difference between a hint that settles it and one that costs two probes. ⚠️ **do not
  hint a brace pattern** until the extension-slot case above is fixed — the hint would send a
  reader to a form that fails silently
- 🔴 **and part `(none)` from `(unmatched)` in the scope block.** today an unsupplied flag and a
  refused list print the identical `paths: (none)`, so the one artifact a reader consults to diagnose
  the scope cannot name which of the two happened

⚠️ **check `--conversation` before any edit ships** — it is documented *"comma-separated"* and the
guard expands `$conversation` into it, so a silent zero-match there would drop prior-round dialogue
from a peer review **with no error at all**. that is the same class and a worse blast radius, because
the review still runs and returns a plausible verdict. **enumerate the flags; do not fix the one you
tripped over** (the i005 lesson from this very behavior: *to extract a transformer does not tell you
where it must be reached for*).
