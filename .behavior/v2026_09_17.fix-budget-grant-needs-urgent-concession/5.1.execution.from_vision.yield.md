### 🔴 `F15` DISSOLVED by a source read — no fork was needed

the vision opened `F15` as a live fork: `formatBlockRemedyGroups` is **synchronous**, takes
`{ stone, passage, reason }`, and the gate's predicate wants a `route` and an `await`. it best-
guessed **option B** — compute a boolean upstream and pass it in — and priced options A and C.

**the premise was wrong.** the severity already travels in `input.reason`: `genRouteGuardExhaustedReason`
writes one of two disjoint prefix marks ahead of the `budget exhausted:` colon, and
`asConcessionReasonDisplay` already parses them.

⇒ **no thread, no async, no boolean.** the slot-1 branch reads what its own input already carries:

| halt kind | the driver's lever |
|---|---|
| urgent concession | `increase budget — yours to spend` — unchanged |
| better concession | `fix what you conceded — yours to run` → `--as passed` |
| no concession | `converge with the reviewer — yours to run` → `--as absorbed --that <slug>` |

🟡 **the marks sit AHEAD of the colon deliberately** — the slug parse is `/budget exhausted:\s*(.+)/`,
so a mark written after it would be swallowed into the slug list.

### 🔴 an unplanned fix: a failure-ORDER defect the gate introduced

**found by a test, not by a read.** two acceptance cases in `driver.route.peer-budget-bulk` `[case2]`
failed: a `--peer` that named no configured reviewer got the gate's refusal (*"no live urgent
concession stands"*) where it had gotten `error: peer reviewer not found`.

**the root cause:** the peer check was inferred from `updates.length === 0` **after** the write ran,
so the new gate sat between the caller's typo and its diagnosis.

⇒ **the principle, stated because it will recur:**

> **a caller-fault in the INVOCATION is diagnosed before a gate that judges the ROUTE'S STATE.**

the gate asks *"was a round earned?"*, and that question presumes the invocation named a real lane.
ask it first and a typo'd slug is answered with a fix the caller cannot run — `rule.require.errors-name-the-fix`
is violated by **order** rather than by copy.

**the fix:** a pure read-only probe above the gate that calls the SAME `updateGuardPeerBudgets` the
write does, with `addAmount: 0`. the probe and the writer cannot disagree about which peers a guard
configures, because they share one parser. the dead post-write check was removed rather than left as
an unreachable "guarantee".

✅ **the original snapshot was restored byte for byte — no resnap.** the repair returned the
behavior the corpus already pinned, which is the strongest evidence it was a defect and not a change.
