# case=3 · a clone of a peer actor runs the init

coordinates: L=split · I=peer-actor · T=absent-key · G=no-statusLine · feel=happy · care=critipath

## .narrative

a foreman clone (`hash=7dcf1989`) runs `npx rhachet run --repo bhrain --role driver --init
init.claude.status-line`. its `CLAUDE_CONFIG_DIR` is its own brain dir, not `<repo>/.claude`. the
init still writes the repo actor's `settings.of.repo.json` — the source — and adds a `reach` leaf:
this clone's config dir, and that it picks the bind up at its next enroll or `rhx init --hooks`.
the peer's file is never written directly, so no later derivation can erase the write.

## .bdd

```
given a repo with two actors, .claude linked to the repo actor
  when [t0] the init runs with CLAUDE_CONFIG_DIR = actor.via.hash=7dcf1989/brain/.claude
    then statusLine lands in <repo>/.claude/settings.of.repo.json
    then actor.via.hash=7dcf1989's settings.of.repo.json is not written by the init
    then stdout names this clone's config dir and when it picks up the bind
  when [t1] that actor's settings are derived
    then statusLine appears in its settings.of.repo.json
```
