# domain.term.choice.reason: spend (transcript.token)

## .etymology
the wisher settled the skill's name as `reflect.on.token.spend`. *spend* names tokens as a budget
paid out — which is the frame the report needs: a spend can be inventoried, priced, and ranked for
a cut.

chosen over `usage` — the api's own field (`message.usage`) and so a wire word: it holds counts and
no prices, and the report holds both. `cost` is rejected because the report states the cost
**inside** the spend (the `priced` sums); to name the whole by one of its fields overloads the
field. `consumption` / `burn` carry no sense `spend` lacks.

## .evidence
- the wish frames the outcome as where the tokens *went*, and which part of the *spend* is waste
- the cli name, the report object (`TokenSpendReport`), and the operation (`getOneTokenSpendReport`)
  all carry the one word
