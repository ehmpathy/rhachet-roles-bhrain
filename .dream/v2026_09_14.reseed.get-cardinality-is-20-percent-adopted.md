## .the cue that fired

a new `get` operation needed a name: `getNearMissGuardKey` or `getOneNearMissGuardKey`. the rule
answers in one line — *"get without One/All cardinality = **BLOCKER**"* — and the neighbours answer
the other way.

## .the gap, precisely

walked 2026-09-14, `^export const get[A-Z]` across `src/**/*.ts`:

| | count |
|---|---|
| exported `get*` operations | 122 |
| carry `One` or `All` | 25 |
| carry neither | 🔴 97 |

the 97 share a shape the rule does not name: each computes **one value** — a decision
(`getExitCodeClass`), a report (`getReviewSkipReport`), a path, a state. the 25 each read over a
**set** (`getAllStones`, `getOnePassageReport`).

⇒ the de-facto convention: cardinality marks a read over a set, and is omitted where no set exists.

## .the shape of the fix

| the verdict | the work |
|---|---|
| the rule holds | this repo sweeps the 97 — one PR, no behavior change, file renames per `rule.require.sync-filename-opname`, one `sedreplace` per operation |
| the convention holds | amend the rule's `.get` section: `getOne*`/`getAll*` for a read over a set; bare `get$Noun` for a read that computes one value |

🟡 the amendment is the harder half and the more valuable one. the rule's `compute` subtype already
names the case, and has no cardinality to carry.

## .why it is not done in this round

- **safe?** the sweep is; the amendment changes a booted org rule from a consumer repo
- **clean?** 🔴 no — 97 files across every subsystem, or another repo
