# case 2 — the route moves, the file follows

happy · critipath · cell bound-once · fresh · route moved · one · lands · one (the move makes the
file stale for an instant; its write makes it fresh before the next repaint)

## .narrative

the driver finishes the vision and runs `rhx route.stone.set --stone 1.vision --as passed`. by the
time the human looks down, the line already reads `🗿 5.1.execution.from_vision, yield 🌾`. the
human typed no refresh, and never thought about one.

later, as the guard's peer review runs round after round, the human watches the count tick —
`l1@i002`, then `l1@i003` — just as it did before. when they rebind the seat to another route, the
line shows that route's stone on the next message; when they unbind, the line goes blank.

## .timeline

```
given a route bound to branch feat/x, current stone 1.vision
when the driver runs `rhx route.stone.set --stone 1.vision --as passed`      [t0]
  then the route's file is rewritten atomically                              [t0]
  and it holds stone = 5.1.execution.from_vision, phase = yield, line        [t0]
when the harness next repaints                                               [t1]
  then stdout is `🗿 5.1.execution.from_vision, yield 🌾`                    [t1]
  and no node process is spawned                                             [t1]
when the guard's peer review appends round i003 to reviewPeerMeters.jsonl   [t2]
  then the guard's own node process rewrites the file                        [t2]
  and the next repaint shows `…, review.peer, l1@i003 🔍` — the tick stays live [t2]
when the driver runs `rhx route.bind.set` onto another route                 [t3]
  then that route's file is written, and the next repaint shows its stone    [t3]
when the driver runs `rhx route.bind.del`                                    [t4]
  then the next repaint is blank, as unbound — the old route's file is not read [t4]
```

## .the writers

the render now runs once per move rather than once per repaint. every write of a render input
already happens inside a node process; each ends with one status write: `setPassageReport` (every
passage), `setRouteStoneGuardReviewPeerMeter` (each review round), the promise write in
`setStoneAsPromised`, `setRouteBind` / `delRouteBind`, `route.stone.add` / `route.stone.del`, and
`route.drive` as the explicit refresh.
