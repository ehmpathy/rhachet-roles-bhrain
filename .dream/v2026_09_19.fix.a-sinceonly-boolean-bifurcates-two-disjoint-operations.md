# 🌙 dream: a `sinceOnly` boolean bifurcates two structurally disjoint operations

- **kind** = fix
- **owner** = this repo (`rhachet-roles-bhrain`)
- **caught** = 2026-09-19

## .the cue that fired

a peer reviewer (`enroll-impl-arch-defects`, i004 r011 point 4) named it, and the read is exact.
I attempted the split, wrote both halves, then measured the ripple and reverted — the measurement
is the part worth a record, because the reviewer's estimate of it was off by an order of magnitude.

## .the gap, precisely

`setSelfReviewTriggeredReport(input, options?: { sinceOnly?: boolean })` performs two operations
that share no state and never overlap:

| `sinceOnly: true` | the default |
|---|---|
| mint the ASK — one atomic `wx` create of `.since` | claim first-ness — one atomic `wx` create of `.uptil` |
| touches no `.uptil` | increments `attempts` via a read-modify-write |
| returns `firstAdjudication: false`, always | preserves the ask's mtime across its own rewrite |
| one call site: `setStoneAsPassed.ts` | one call site: `getSelfReviewChallengeDecision.ts` |

the flag bifurcates the body **end to end** — the `sinceOnly` branch returns before any line the
other branch runs. `rule.require.get-set-gen-verbs` and `rule.prefer.wet-over-dry` both name this
shape, and the repo's own guidance is to split it.

🔴 **and the file carries a real dead read because of the flag**: `sinceFound` is probed at the top
for both branches and is used by neither line of the `sinceOnly` path. one `fs.access` per ask,
discarded.

## .the shape of the fix

two operations, each with one responsibility:

```
setSelfReviewAsked({ stone, slug, route })
  → { sincePath, uptilPath }
  mkdir · getSelfReviewTriggeredPaths · the `wx` mint, EEXIST allowlisted
  ⇒ the `sinceFound` probe goes away — no line on this path reads it

setSelfReviewAdjudicated({ stone, slug, route })
  → { sincePath, uptilPath, attempts, firstAdjudication }
  the body as it stands, minus the `sinceOnly` branch
```

🔴 **the one invariant that couples them must be stated at BOTH ends, or the split loses it.**
today one docblock holds it: the adjudication captures `.since`'s mtime and restores it after its
own rewrite, **precisely because the mint is what set that mtime**, and that mtime is a gate
operand (the haste cue's `askedAt`, and the freshness bar's datum). a split that says this in one
file only leaves the other looking arbitrary.

🟡 **and `getSelfReviewTriggeredPaths` stays one operation.** the two halves genuinely share the
filename derivation, and that is the correct shared owner — the flag was never about paths.

## .why it is not done in this round

**SAFE?** borderline-yes. the operation is the one two peer rounds just repaired for atomicity
(i002 → i003, the `.since` race), and the suite would catch a regression. but it is the least
settled code in the round.

**CLEAN?** 🔴 **no, and this is the deciding answer.** the reviewer wrote *"the two call sites never
overlap"*, which is true of **production** and is not the ripple. counted `2026-09-19`:

| file | call sites |
|---|---|
| `setSelfReviewTriggeredReport.test.ts` | 14 — plus the filename, the `describe`, and 3 `when` labels |
| `getSelfReviewChallengeDecision.test.ts` | 7 |
| `getSelfReviewTriggeredReport.test.ts` | 6 |
| `setStoneAsPassed.ts` | 1 |
| `getSelfReviewChallengeDecision.ts` | 1 |
| prose refs in 3 further files | 3 |

**~32 edits across 8 files**, and it is NOT one `sedreplace`: the two forms differ in arity
(`(input, { sinceOnly: true })` → `setSelfReviewAsked(input)`) so each site is read and chosen by
hand. `rule.prefer.scouts-honor` grades *"a large cleanup smuggled into an unrelated change"* a
**blocker**, and this round already carries four independent repairs to one gate — a scope question
its own yield flags for the council (`.what is awkward` item 6).

⇒ so it fails the CLEAN question of `rule.always.fix-forward-under-scouts-honor`, and the deferral
is the rule's own answer.

## 🟡 .what WAS done in this round instead

the cheap half of the same reviewer's point 5 — an explicit statement, in the extant docblock, that
`attempts` is a deliberate diagnostic, is known-racy under the fork, and **must not** have a gate
built on it. that was the harm the reviewer named (*"a future maintainer assumes it is load-bearing"*),
and it needed no rename to close.

## ⚠️ .the transferable part

**a reviewer's "two call sites" counted PRODUCTION call sites.** the test suite held 27 more, and a
split's cost is dominated by the suite in exactly the subsystems that are well-tested. ⇒ when a
refactor is graded clean-or-dirty, **count the test call sites first** — they are the larger number
whenever the code is worth a refactor at all.
