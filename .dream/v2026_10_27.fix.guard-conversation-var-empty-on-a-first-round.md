# 🌙 dream: an empty `$conversation` never reads as a lost path

kind: fix · owner: bhrain driver (route guard) · caught 2026-10-27

## .the cue that fired
5.3 verification i004: both `enroll-verif-*` lanes that rejected said the conversation path "came through blank". r12 then emitted prose with no numeric counts, and a fallback brain inferred "5 blockers".

## .the gap, precisely
- `$conversation` is built per lane slug (`getAllRouteGuardReviewPeerConversationFiles`), so a lane's first round has no files and `asConversationVar` renders `''`
- `rhx review --conversation ''` tolerates that; a prose prompt (`read the prior peer-review conversation at $conversation`) reads as a broken instruction
- an `rhx enroll … -p` lane is never told to emit the two numeric lines, so its tally is a sub-brain guess (contract.reviewer-output)

## .the shape of the fix
- the guard template (`route.guard` enroll lanes) phrases the var so empty reads true: "prior rounds of this review, if any: $conversation"
- the enroll lane prompt ends with "end with two lines: `N blockers` and `N nitpicks`"
- or, at the tool: a prose-safe render of an empty conversation, with a clamp that a first-round enroll lane's prompt names no blank path

## .why it is not done in this round
the guard is sealed without a human grant (`rhx route.mutate grant allow`); this route's guard is edited once the grant stands, and the template fix belongs to the route-guard template, beyond this pr's scope.
