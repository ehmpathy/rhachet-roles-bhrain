# domain.term.choice.reason: target

## .etymology

a target is what an act is aimed at. each toggle verb aims at one file, and every refusal names
it the same way: *the settings target is a link*, *… is a dir*, *… resolves outside the repo*.

rejected:
- **destination** — implies a write; `get` reads the target and writes naught
- **config** — this repo's word for its own settings; the target is claude code's file

## .boundary

`target` holds a sense in `review.scope` too — one file a review judges
(`term=review.scope.target`). the two never meet: a review target is graded, a toggle target is
rewritten. the boundary `learn.terms.hook` keeps them apart, as `review.scope` does on its side.

## .evidence

- the declared type `TermsHookTarget` and its pick `getOneTermsHookTarget`, the same pick
  `init.claude.status-line.sh` makes (fulcrum F2)
- the refusal family, each keyed on what sits at the target path
- invariant: one verb, one target; the target is re-picked under the hold, so a layout that splits
  mid-wait is refused rather than written to the file rhachet no longer reads (case11)
