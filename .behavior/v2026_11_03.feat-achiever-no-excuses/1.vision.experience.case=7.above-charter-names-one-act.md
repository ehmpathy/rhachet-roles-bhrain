# case 7 — the act above charter, named as one command

feel: happy (an honest halt) · care: critipath · actor: achiever, commander · seams: store, stop hook, a human

## .narrative

the achiever must edit a guard, and the guard is sealed until a human grants the mutate. it cannot
grant itself; that is truly above its charter. it does all else first: it writes the guard edit it
will make, answers every point it can, and only then records the blocker as above charter, with the
one act and who may do it: `rhx route.mutate grant allow`, by the commander.

the stop is allowed. the commander reads one line, runs one command, and the achiever resumes. no
"i'm blocked, what should i do?" and no list of five options for the human to weigh.

## .[tn] — a sketch

```
given  an inflight goal whose next act needs a human grant
when   [t0] rhx goal.memory.set --slug x --status.choice blocked
           --cure.via charter --cure.act 'rhx route.mutate grant allow' --cure.who commander
then     the set accepts it: one act, runnable, with an owner
     and the stop passes, and its last line names the act:
           🗿 one act above charter: rhx route.mutate grant allow (commander)
when   [t1] the cure.act names more than one command, or prose with no command
then     the set exits 2: name the ONE act, as a command someone can paste
```
