# 🌙 dream: diagnose why a temp repo reports `unreadable-clone` where the repo root reports `unenrolled`

- kind  = fix
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught 2026-09-16

## .the cue that fired

a blackbox acceptance test asserted the `unenrolled` halt, on the measured fact **F-a**: at this
repo's root, `rhx clone whoami --output json` exits 2 (`not run inside an enrolled clone`). the same
probe, spawned from a `genTempDirForRhachet` fixture, produced `unreadable-clone`.

## .the gap, precisely

the temp-repo driver reads *"fix: run the probe by hand"* where the true remedy is `rhx enroll` — an
honest halt, and the weaker one, on the most common cause.

which environment is the outlier is **unknown**:

| hypothesis | what it would mean |
|---|---|
| the shim breaks after it resolves in the fixture | a fixture artifact; production is unaffected |
| `clone whoami` exits non-2 whenever the cwd is not a rhachet-introspected repo | a real defect: a fresh consumer repo gets the weaker halt |

**ruled out:** an absent binary. `invokeRouteSkill.ts` symlinks `node_modules/.bin`,
`node_modules/rhachet`, and `node_modules/.pnpm` into the fixture, so `rhx` resolves.

**not a clamp:** `RHACHET_CLONE_SERIAL: ''` would force exit 2 — but only if rhachet's whoami is the
layer that fails, which is the unknown.

## .the shape of the fix

1. **read the cause, do not guess it.** `getCloneAddress`'s `code !== 0` arm settles
   `unreadable-clone` with no `noteCause`, so the exit code and the child's stderr are discarded. add
   one `noteCause` that names the code and the stderr tail
2. re-run the acceptance suite; read `.log/bhrain/brain/apply.log` out of the temp dir
3. hypothesis 1 → record it in the suite's header; leave the code alone
4. hypothesis 2 → ask `ehmpathy/rhachet` for exit 2 from any cwd that is not an enrolled clone

## .why it is not done in this round

**SAFE ✅ · CLEAN 🔴.** step 1 is safe, but the diagnosis ends in step 4, an ask on another repo, on a
branch no vision case demoes. the acceptance suite asserts what every cause guarantees, so it is
correct either way.
