# 🌙 dream: promote `⟨requested — unconfirmed⟩` to confirmed, via the hook's own `transcript_path`

- kind = feat
- owner = `rhachet-roles-bhrain`
- caught = 2026-09-20

## .the cue that fired

a live dogfood of the `brain:` guard field
(`.behavior/v2026_09_09.feat-prescribed-brain-per-stone/5.4.dogfood.brain-switch.yield.md`)
dispatched `/model claude-opus-4-8[1m]` and the brain-cli accepted it. the yield could not
record that acceptance **programmatically**, and filed it under `F5` — a cross-repo ask on
`ehmpathy/rhachet` for a `whoami --brain` surface.

the wisher then asked the sharp question: *"shouldn't it find the exact session via
`rhx clone whoami` and target JUST that clone's transcript?"*

⇒ it did target the exact clone, and the gap is one level below that. the ask was mis-scoped.

## .the gap, precisely

### `clone get` cannot map a clone to its transcript, by construction

| id | owned by | where it lives |
|---|---|---|
| the clone **serial** | rhachet | `RHACHET_CLONE_SERIAL`, what `whoami` returns |
| the transcript **exid** | the brain-cli | the transcript's own filename |

no map exists between them, and rhachet says so —
`node_modules/rhachet/dist/domain.operations/clone/genCloneHistoryLink.js:19-21`:

> *"the exid lives in the transcript's filename (an interactive TUI never prints a parseable
> session id), so we DISCOVER the file rather than parse the stream"*

so the link is **inferred** from `(cwd, spawnedAt)`. with two clones in one cwd the heuristic
ties, and `:61-68` refuses to link and quarantines each candidate — correct conduct, and a
privacy guarantee. measured: `exidsAmbiguous` over 11 ids, empty history returned.

### 🔴 the discriminator already exists, on the hook side

a hook fires INSIDE the clone, and the platform hands it the transcript by name:

```ts
// src/contract/cli/telepath.ts:99-102
transcriptPath:
  typeof payload.transcript_path === 'string'
    ? payload.transcript_path
    : null,
```

**exact, platform-named, no discovery, immune to a shared cwd.** this repo already parses it for
the telepath stop-hook throttle, so the read is paved.

⇒ `clone get` is the right instrument to read **another** clone, and the wrong one for a
**self**-read. the brain-switch verify is a self-read.

## .the shape of the fix

1. capture the dispatch — when `dispatchBrainSwitch` requests a `/model`, record the prescribed
   value and the request time into the extant brain-apply state (beside the entry stone)
2. read the reply on a later hook turn — parse `transcript_path` off the payload, scan the
   tail for the brain-cli's own acknowledgment of that `/model`
3. promote the render — `⟨requested — unconfirmed⟩` becomes `⟨confirmed⟩` on a match, and a
   **refusal** becomes a loud halt that names the rejected value

🟡 **the vocabulary matches, so no bridge is owed.** the `F10` verdict declared the guard value
in the brain-cli's own `/model` vocabulary, and the reply is in that same vocabulary — the
cross-vocabulary map `F5` would have needed does not arise here.

🟡 **keep the dispatch-time label honest.** the reply has not landed when the dispatch line
prints, so `⟨requested — unconfirmed⟩` stays correct AT THAT MOMENT. this adds a later
promotion, never a change to the first render.

## .why it is not done in this round

- **not clean.** it adds a new state field, a new transcript read, a new render state, and a new
  halt cause — it ripples past the diff the dogfood opened
- **not in scope.** the route is complete and its stones are passed; this is a feature the wish
  did not ask for
- the dogfood's own job was to PROVE the switch fires, and it did

## 🔴 .BUILT 2026-09-20, then WITHDRAWN — and the withdrawal is the durable part

the fix above was built end to end and reverted the same day. what it cost, and why:

| built | verdict |
|---|---|
| `getBrainSwitchVerdict` + 8 cases / 18 tests, green in 90s | ✅ worked |
| a `confirmed` / `refused` / `superseded` arm on `StoneBrainOutcome`, each rendered | ✅ worked |
| a stdin capture in `route.drive.sh`, to get the payload past `node -e` | 🔴 **the tell** |

**the wisher's read, verbatim:** *"this looks gross. shouldnt we just be able to get it from
`rhx clone whoami`?"* — and *"for now, just do it without the double confirmation."*

⇒ **the mechanism was sound and its PLACE was wrong.** to read the value, a consumer repo had
to (a) add a shell-level stdin capture to every hook wrapper and (b) parse another tool's
stdout shapes. two of those are rhachet's contract, and a scrape of a third party's prose is
a dependency nobody declared — it goes stale on a release that reworded one string.

🟡 **the shapes are measured and worth a keep, since whoever builds this next needs them:**

```
accept:  {"type":"system","content":"<local-command-stdout>Set model to \u001b[1m<brain>\u001b[22m</local-command-stdout>"}
refuse:  {"type":"system","content":"<local-command-stdout>Model '<brain>' not found</local-command-stdout>"}
```

🔴 **two traps, each of which a careless reader walks into:**

1. **the ANSI anchor carries the load.** a brain value legitimately CONTAINS `[1m]` — the
   million-token context marker — and real ansi wraps it. a `/\[[0-9;]*m/g` strip mangles
   `claude-opus-4-8[1m]` into `claude-opus-4-8`, so the compare fails on a switch that LANDED
2. **bind on `type === 'system'` AND the `<local-command-stdout>` wrapper, both.** measured: of
   57 transcript records that mention one brain value, **55 were the conversation's own prose
   about it** — a tool input, a file write, a diff hunk. a text match self-confirms when it
   reads its own description of a switch
