# 1.vision.experience.dimensions

## .the axes — each closed, each justified as orthogonal

| axis | positions | why it is orthogonal |
|---|---|---|
| **actor** | driver clone · maintainer human · CI | who stands at the keyboard. each actor can hold any credential state and hit any moment; no actor implies a key or a host |
| **goal** | get a verdict · see which brains exist (`--help`) | why they came. either goal is open to any actor at any moment |
| **brain source** | default (no `--brain`) · explicit `--brain openrouter/...` · explicit stale `--brain fireworks/...` · the tally fallback (`FIXED_FALLBACK_BRAIN`) | where the slug comes from. the code holds it, or a caller types it. the source does not decide whether a key or a host exists |
| **credential** | `OPENROUTER_API_KEY` present · absent | a keyrack fact, set by a human, independent of who calls or how |
| **supply** | ≥1 openrouter host keeps the caller's filter set · none does | an openrouter-side fact, set by the market, independent of our key or caller. *which* filter set applies is a projection of brain source; see the latent axis below |
| **moment** | steady (one call, host answers) · transient (a host throttles or fails mid-ask) · concurrent (several lanes ask at once on one key) | when the call lands. a property of the network at call time, not of who called or what slug |
| **tier age** | current (the flash the tier picked last) · advanced (the 7-day tier pick moved to a newer flash) | a property of the clock over days, not of the call. it co-occurs with every moment, so it is its own axis, not a moment position |

**feel** (happy / sharp) and **care** (critipath / alterpath) are not multiplied in: they are the two
attributes each cell is **graded** on (`define.experience`), so they appear as columns in
`case=_`, never as factors of the product.

🟡 `outcome` was an axis in the first draft and is **removed**. it was `credential × supply` relabelled
(absent key ⇒ refused, no host ⇒ refused, else counts), so it was derived, not orthogonal.

## .the latent axis the CI column exposes — *who authors the slug*

CI meets `default` and `explicit openrouter` live, and the tally fallback only through an injected
builder. **CI has no human to type a slug, and it runs only what a test file names**. so beneath
`actor` sits a latent split, **slug author = code · test file · human at a prompt**. it is
surfaced here and not multiplied in, since it is a function of actor × brain source (a CI cell's
slug is always test-authored), so it adds no new cell.

it decides how CI meets a stale fireworks slug: only through a test file that names one. that is a
**nurture** fact, since a human wrote the file. two live fixture guards name it today. so the CI ×
stale cell is **forbidden** (F-1), not impossible: the attempt can happen, and the behavior must
refuse it.

## .the walk — how every cell of the product gets a verdict

the full product is 3 × 2 × 4 × 2 × 2 × 3 × 2 = 576 cells. it is walked in three steps, so each
cell receives a verdict **by construction**, not by recall:

1. **the base grid**: actor × goal × brain source, under the nominal modifiers (key present ·
   host qualifies · steady · tier current). 3 × 2 × 4 = 24 cells, each verdicted by name in
   `case=_` §base: 12 for `goal = get a verdict`, 12 for `goal = see which brains exist`
2. **the modifier combinations**: for the 12 `get a verdict` cells, each of the 24 combinations
   of credential(2) × supply(2) × moment(3) × tier age(2) gets a verdict, via one row per
   non-nominal position plus the refusal order below. each modifier acts at one layer, beneath the
   slug: the keyrack read, the openrouter endpoint pick, or the openrouter transport. a layer below
   the slug cannot tell which actor asked. where it can tell which *source* asked (the tally's
   filter set), the row names the exception
3. **the `--help` cells take no modifier**: 12 cells × 24 combinations, all verdicted
   *unaffected*. `--help` lists the atoms discovered from package.json. it never reads the keyrack
   and never calls openrouter, so no modifier can reach it

⇒ 12 × 24 + 12 × 24 = 288 + 288 = **576**, the full product.

the **refusal order** for a multi-modifier combination is the call path:
**credential** (keyrack read) → **supply** (endpoint pick) → **moment** (the ask in flight).
a combination takes the verdict of its **first** non-nominal position on that path. so key-absent ×
any moment = case 3/4, since no ask is sent. no-host × transient = case 7, since the pick refuses
before any ask.

**tier age never refuses**, so it is not on the refusal path. `advanced` overlays case 8 on
whatever verdict the other three axes give: no-host × advanced = case 7, key-absent × advanced =
case 3/4, steady × advanced = a normal verdict on the newer flash. the slug in every snapshot stays
`openrouter/deepseek/flash` across both positions.

## .the latent axis the supply row exposes — *which filter set the caller asks for*

`supply` reads as a market fact, but the §modifiers `no qualified host` row names an exception:
the tally asks for json, so its host set is narrower and empties first. so beneath `supply` sits a
latent split, **filter set = default (`floor&speed=min50tps&privacy=full`) · json-required (the
default plus `structured_outputs`)**. it is a function of brain source alone (tally fallback →
json-required; every other source → default), so it is surfaced here and not multiplied in. it is
why the no-host verdict is uniform in kind (case 7) but not in likelihood: the tally reaches it
first. that is open question 2 in the yield.

## .the latent axis the goal column exposes — *does the goal name a slug*

`goal = see which brains exist` collapses all of `brain source`. that is the same tell as the CI
column. the latent split beneath it: **slug required = yes (a verdict needs one brain) · no (the
`--help` list shows every brain)**. a goal that names no slug has no source for one. it is
surfaced here and not multiplied in, since it is a function of `goal` alone. it explains the 9
`n/a` cells in §base.

## .actors × feel — the grid that seeded the critipaths

| actor | happy | sharp |
|---|---|---|
| driver clone | guard review returns counts; prose is tallied → case 1 · tier advanced → case 8 | key absent mid-guard → case 3 · stale fireworks slug → forbidden F-1 · no qualified host → case 7 · concurrent lanes throttled → case 9 · transient host failure → case 10 |
| maintainer human | `rhx review` by hand → coverage-subsumed by case 1 · `--help` lists the openrouter tiers → case 6 · tier advanced → case 8 | key absent → case 3 · stale fireworks slug → forbidden F-1 · no qualified host → case 7 · concurrent → case 9 · transient → case 10 |
| CI | suites green → case 2 · tier advanced → case 8 | secret absent → case 4 · stale fixture slug → forbidden F-1 · no qualified host → case 7 · concurrent → case 9 · transient → case 10 |

rows are exactly the declared `actor` values. cases 7–10 recur in every row because §modifiers
scopes them to every `get a verdict` cell, so each actor meets them. the driver is where case 9
bites hardest (a guard pours lanes in parallel), but it is not where case 9 lives alone.
