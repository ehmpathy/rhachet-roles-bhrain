# 🌙 dream: `globsafe` and `grepsafe` must not report a pruned dot-dir as an empty result

- kind  = `reseed` — the skills belong to `ehmpathy/rhachet-roles-ehmpathy`, never to this tree
- owner = `ehmpathy/rhachet-roles-ehmpathy` (`role=mechanic`)
- caught 2026-09-17

## .the cue that fired

four `.taken` artifacts were written to a repo-root `.reviews/peer/` rather than to
`$route/.reviews/peer/`. the search for them ran through `globsafe` and `Glob` five times and
returned zero every time, so the diagnosis went to the review ladder instead of to the filesystem.
`tree -a` found all four in one call.

⇒ the round was lost to a **silent** zero, never to a wrong answer.

## .the gap, precisely

a **wildcard** segment does not descend into a dot-prefixed dir. a **literal** one does. measured
2026-09-17, on the same four files:

| the call | result |
|---|---|
| `globsafe --pattern '.behavior/**/*i033*taken*'` | 🔴 `files: 0`, exit 0 |
| `globsafe --pattern '.behavior/$route/.reviews/peer/*i033*taken*'` | ✅ 4 files |
| `grepsafe --path '.behavior/$route/.reviews/peer' --glob '*i033*'` | ✅ 4 files |

the behavior itself is correct — it is `fast-glob`'s `dot: false` default, and it is what keeps a
`**` off `.git/` and `node_modules/`. **the defect is the REPORT.**

```
🐢 crickets...
🐚 globsafe
   ├─ pattern: .behavior/**/*i033*taken*
   └─ files: 0
```

⇒ 🔴 **that output is byte-identical whether the tree holds zero matches or holds four behind a
pruned dot dir.** `rule.forbid.failhide`: one word for two outcomes, and the reader cannot part them.

⚠️ **and the two outcomes want opposite next moves** — a true zero means the artifact was never
written; a pruned zero means it was written and the probe was wrong. a driver who reads the first
into the second spends the round at the wrong layer.

🟡 `rule.always.reuse-pavement-before-improvise` already warns that `grepsafe` *"reports a LOWER
BOUND, never a census"* and names two causes. **this is a third cause, and it is the one that costs
most**, because the other two are defeated by a `--path` the author already knows to supply.

## .the shape of the fix

in `ehmpathy/rhachet-roles-ehmpathy`, `skills/claude.tools/globsafe.sh` + `grepsafe.sh`. any one of:

1. 🔴 **name the prune in the zero-result render** — when a run returns zero **and** the pattern
   holds a `**` or a `*` segment, append one line: `└─ note: dot dirs were not descended. spell
   the dot segment, or pass --dot`. the strongest of the three: it costs one branch, changes no
   default, and it repairs the **report** rather than the behavior
2. **a `--dot` flag** — opt in to `dot: true` for one call. useful beside 1, and weak alone: a
   reader who does not know the prune happened never reaches for it
3. **`dot: true` by default** — rejected. it would drag `.git/` and `node_modules/` into every
   recursive sweep, which is the hazard `rule.forbid.unbounded-recursive-globs` exists to close

⇒ prefer **1**, with **2** as its companion. the note is what converts an unreadable silence into a
next action, which is `rule.require.errors-name-the-fix` applied to a non-error.

🟡 **1 must fire on the zero case only.** a note on every run is emphasis noise, and a reader who
sees it beside a healthy result stops to read it within a day.

## .why it is not done in this round

- **SAFE?** ❌ — the skills live in another repo on another release cadence. this tree cannot change
  what `globsafe` prints
- **CLEAN?** ❌ — a local wrapper would be a **second path beside a serviceable one**, the braided
  trail `rule.always.reuse-pavement-before-improvise` names. and it would be invisible to every
  other repo that runs the same skill against the same hazard

⇒ a tree adopts only what is scoped to itself. caught as a `reseed`, not adopted.

⚠️ **caught is not dispatched.** the radio push to `ehmpathy/rhachet-roles-ehmpathy` is a separate
act, and it has not happened.

⇒ see also: `hazard.a-route-artifact-at-the-repo-root-reads-as-stale` (this repo — the symptom it
produced, and the literal-path workaround that serves until this lands).
