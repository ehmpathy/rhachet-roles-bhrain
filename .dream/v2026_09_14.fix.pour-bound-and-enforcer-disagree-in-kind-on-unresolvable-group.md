# 🌙 dream: the pour-bound and the enforcer disagree in KIND on an unresolvable group

- **kind**: fix
- **owner**: bhrain / any
- **caught**: 2026-09-14

## .the cue that fired

peer review i022/r011 (enroll-impl-arch-defects) sharpened the F19 duplication: the two
hand-synced models of one concurrency bound do not merely risk drift — they are **already
inconsistent** on one input, behind a parse guard that happens to make it unreachable.

## .the gap, precisely

for a group name that resolves to no declared group:

- `getOneReviewLevelPourBound` treats the unrecognized group as **unbounded** — it counts the
  member as uncapped.
- `runWithinConcurrencyBounds` **throws** `BadRequestError` for the identical input.

so the announce and the enforcer disagree in KIND, not just value. the path is unreachable today
because `assertConcurrencyGroupsResolve` refuses it at parse. but if that parse guard is ever
loosened — a dynamic/programmatic guard-build path a future SDK caller or `route.guard.upgrade`
might introduce — this silently becomes a live defect with no test to catch it, since neither file's
suite exercises the "invalid but not parse-refused" case together.

**evidence:** the two functions branch on `group: string | null` independently;
`assertConcurrencyGroupsResolve` is the sole gate between them and an inconsistent live result.
verified by the reviewer against current code.

## .the shape of the fix

route both consumers through one pure classifier so they can never disagree on WHICH lanes are
grouped vs level-only:

```ts
const selectBoundKind = (member: { group: string | null }): 'level' | { group: string } =>
  member.group ? { group: member.group } : 'level';
```

that collapses the drift surface from "two formulas can disagree on all of it" to "two formulas can
disagree only on arithmetic" — the smaller, already-tested surface. the unresolvable-group
divergence in kind then cannot exist, guard loosened or not.

## .why it is not done in this round

safe but not clean: F19 is an 8+-round deferred item whose repair extracts a shared classifier
across two files, and the round's task is the malfunction retry (the l3 tally fallback). the
extraction ripples past the diff the retry needs, and the divergence is unreachable behind the parse
guard today — so it rides a follow-up rather than the retry.
