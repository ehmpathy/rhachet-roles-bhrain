## .the cue that fired

a rename of five glossary clusters ran `sedreplace` across
`.agent/repo=.this/role=any/briefs/**/*.md`. one of the matched paths was a **symlink**:

```
.agent/.../domain.terms/catalog.of=externalization._.md
  → ../../../../../src/domain.roles/learner/briefs/catalog.of=externalization._.md
```

after the apply, `file` reported it as `Unicode text, UTF-8 text`. **the symlink was gone**, and in
its place sat a regular file holding the edited content — while the real source under `src/` still
held the old.

## .the gap, precisely

`sedreplace` writes the edited content **to the path it matched**, rather than through the link to
its target. so for a symlinked path it performs three acts where one was asked for:

| what was asked | what happened |
|---|---|
| edit the file | ✅ the content was edited |
| — | 🔴 the **symlink was destroyed** |
| — | 🔴 the **target was left stale**, so one artifact became two that disagree |

⚠️ **and every one of those is silent.** the plan preview renders a normal diff, the apply reports
`updated`, and the exit code is 0. there is no signal at any point that a link was consumed.

## 🔴 .why it is worse than an ordinary write defect

**the failure mode it creates is the one the symlink existed to prevent.**

a brief is symlinked into a second home precisely so **one claim lives in one file**. this repo's
own `rule.always.reuse-pavement-before-improvise` names the result of the opposite arrangement —
*the braided trail*: two homes for one fact, neither authoritative, and a reader who cannot tell
which is current.

⇒ so a tool reached for **to keep one artifact consistent across many files** quietly produces the
exact fork that discipline forbids. and it does so on the artifacts most apt to be symlinked —
the shared, cross-role ones, which are the highest-traffic briefs in the tree.

⚠️ **the detection window is narrow and closes fast.** it was caught here only because the very
next `Edit` failed with *"string to replace not found"* — the src copy still held the old text. had
the round ended one step earlier, two divergent copies would have been staged, and the diff would
have read as a normal edit plus an unexplained typechange.

## 🔴 .it can MANUFACTURE an open defect — seed #397, in this very directory

**seed #397 reports a crash whose precondition this tool creates.** `learn.domain.terms` aborts
outright when `domain.terms/.readme.md` is a **real file** rather than the symlink it manages:

```
genSymlink upsert: .agent/repo=.this/role=any/briefs/domain.terms/.readme.md
is present but is not a symlink — refuse to clobber
```

⇒ #397 files that as a **consumer-repo** condition — a downstream repo commits the file for real,
so the skill dies there and never here. **that read is incomplete.** the two records are ends of
one causal chain, and neither names the other:

| step | the record |
|---|---|
| 1. a `sedreplace` glob matches a symlinked path under `domain.terms/` | **this dream** |
| 2. the link is consumed; a real file sits in its place, silently | **this dream** |
| 3. `learn.domain.terms` now refuses to clobber it, and aborts | **#397** |
| 4. the staleness sentinel never clears, so the onStop nudge fires forever | **#396** |

⚠️ **so bhrain is not immune to #397 — it is one glob away from it.** the clobber measured here
landed on `catalog.of=externalization._.md`, a **folder-mate** of `.readme.md` in the same
directory, matched by the same `domain.terms/**/*.md` sweep. had the sweep touched the other file,
this repo would have reproduced #397 against itself, and the reported cause — *"a consumer repo
commits it for real"* — would have been false at the very site of the failure.

⇒ that is the sharpest argument for the write-through fix below: **the tool does not merely damage
an artifact, it manufactures a documented crash**, and it does so in the one directory whose whole
purpose is to be symlinked into two homes.

## .the shape of the fix

**dereference the path before the write.** for each matched path:

1. if it is a symlink, expand it to its target
2. bound-check the **target** against the repo root (the extant guard, applied to the real path)
3. write to the target, so the link survives and the one artifact stays one

⇒ the bound check is what makes step 3 safe, and `sedreplace` already performs it on the matched
path — so the change is *where* the check is applied, not whether.

**the alternative, if a write-through is judged wrong:** refuse. a symlinked match errors as a
`ConstraintError` naming the target, and the caller edits the target directly. that is worse
ergonomically and it is honest — **either is better than a silent fork.**

⚠️ **the same hazard is worth a check in `teesafe` and `cpsafe`**, which also write to a
caller-supplied path. this dream names `sedreplace` because that is where it was measured.

## .the repair applied here, for reference

the clobbered link was restored by hand — `cpsafe` the edited content onto the real source,
`rmsafe` the regular file, then `rhx symlink --mode relative --idem upsert`. that is three commands
to undo one silent write, and the next traveler will not know to run them.
