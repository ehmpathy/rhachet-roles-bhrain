## .the gap, precisely

there are **three** tables that each know part of what a flag is, and **each covers a different
subset**. the counts below are measured rather than estimated:

| the table | where | flags declared | what it knows | what it does NOT |
|---|---|---|---|---|
| `parseArgs`'s lookahead | `src/contract/cli/route.ts` | **0** | naught — it **guesses** arity from whether the next token starts with `--` | which flags carry a value |
| `asFlagOwnership` | `src/domain.operations/route/getStrayFlagRefusal.ts:38` | **6** | which **verb** owns each — 🔴 for `route.stone.set` **alone** | arity; the other 20 flags |
| 🔴 `FLAGS_THAT_REQUIRE_A_VALUE` | `src/contract/cli/route.ts` (added this round) | **1** | arity, for `--into` | ownership; every other flag |
| **distinct flags read across `route.ts`** | — | 🔴 **26** | — | — |

🔴 **the two extant tables do not cover one surface at two grains — they cover DIFFERENT SURFACES.**
`asFlagOwnership` knows 6 of 26, and only for one verb. so the unification is **not** a merge of two
tables at parity: it must widen ownership from **6 → 26**, which means declaring ownership for **20
flags whose ownership has never been declared anywhere**.

**checkable evidence**, all three live in the current tree:

```sh
rhx grepsafe --pattern 'asFlagOwnership' --path src
rhx grepsafe --pattern 'FLAGS_THAT_REQUIRE_A_VALUE' --path src
rhx grepsafe --pattern "options\[key\] = 'true'" --path src
```

the failure the split permits: a **future** value-carrying flag is added, its author threads it
through `parseArgs` and `asFlagOwnership` (both of which they must touch), and silently omits it
from the arity allowlist (which they have no reason to know exists). a bare `--newflag` then
coerces to the string `'true'` again — the identical defect, one flag over.

## .the shape of the fix

one schema, declared once, read by both consumers:

```ts
/**
 * .what = the one declaration of what each cli flag IS
 * .why  = arity and ownership are two properties of one flag, and they were split across
 *         two tables that each knew one — so no table could catch a bare value-taking flag
 */
export const FLAG_SCHEMA = {
  into: { valueRequired: true, allowedFor: ['promised'] },
  that: { valueRequired: true, allowedFor: ['promised', 'absorbed'] },
  say: { valueRequired: false, allowedFor: 'any' },
  // … 26 flags in total
} as const;
```

🟡 **`allowedFor: 'any'` is the cheap path, and it is what makes this affordable.** the 20 flags
whose ownership was never declared keep no ownership — they take `'any'`, and only their **arity**
is declared. ⇒ the fix is then a real merge rather than twenty new contract decisions, and the
ownership widening becomes a separate, later, optional move. **cost this variant first**
(`F20`, `.confidence`).

then:

- **`parseArgs`** reads `valueRequired` to decide whether to consume the next token — so it stops
  to guess from lookahead, and a bare value-carrying flag is a loud constraint rather than `'true'`
- **`getStrayFlagRefusal`** reads `allowedFor` — the property it already holds, now from the
  shared declaration
- 🔴 **`FLAGS_THAT_REQUIRE_A_VALUE` is DELETED** — it is the third table, and this fix is what
  retires it

⚠️ **the boolean flags are the trap, and three of them are measured.** these read `=== 'true'`, so
they depend on the very coercion a schema would remove:

```
src/contract/cli/route.ts:970                                   say:  options.say === 'true'
src/domain.operations/route/stones/asYieldModeForRewound.ts:14  hard: input.hard === 'true'
src/domain.operations/route/stones/asYieldModeForRewound.ts:15  soft: input.soft === 'true'
```

⇒ a schema that defaults `valueRequired` to `true` breaks all three at once. **enumerate both kinds
explicitly**; a default on either side re-creates the guess.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE — no.** `parseArgs` is the entry point for **every** cli flag on this surface. a change to
  how it decides arity changes how every command's arguments are read, and this round's diff is
  already ~240 files under review
- **CLEAN — no.** it ripples into `getStrayFlagRefusal`, into `parseArgs`, into the boolean-flag
  call sites that would each need an explicit schema row, and into the acceptance snapshots that
  pin the cli's refusal text

⇒ **defer, and the deferral is a DIRT call rather than a size call**, so it owes a fulcrum beside
this dream (`rule.always.fix-forward-under-scouts-honor`). that fulcrum is **`F20`**, at
`.behavior/v2026_09_17.fix-self-review-min-duration/.fulcrums/inventory.of=fulcrums.case=F20-three-flag-tables-and-none-knows-arity.md`
— it carries the option table, the refused inversion, and the one variant the drive did not cost.

the third table ships with a docblock that names this dream and marks itself for deletion, so the
next author who touches it finds the shape already worked out.

## .the one property that makes it worth the trip

the current split cannot fail loudly. an absent arity row produces a **fabricated value**, never an
error — so the defect surfaces as a bewildering `challenge:mismatch` three layers downstream, which
is exactly how i014's bug was found and why it took a reviewer two rounds to name.
