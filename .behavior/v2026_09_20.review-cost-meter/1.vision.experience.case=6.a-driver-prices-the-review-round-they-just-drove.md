# case=6 — a driver prices the review round they just drove

- cell = `tree` × `cost` × **`trace`**, **crossed with the guard, the brain, and the log**
- path = **critipath** · feel = sharp · care = criti
- the densest walk on the board — it crosses six boundaries in one pass

## .why this cell is `trace`, not `observe`

`case=1` is a driver who reads a number. this is a driver who **produces** the number and
then reads it. its `[t3]` does not price a round — it **differences two of them**, which no
`observe` surface can do: a marginal averages a lane's rounds, so the series
`0, 0, 8.4, 41.2, 7.3` reports as one 29.7% and the step is gone.

per `define.experience._.metric=boundary-density`, the experiences worth centering are the
ones that cross the most boundaries in one walk, because that is where both the value and
the risk concentrate. this walk crosses six:

```
guard → review lane → brain (network) → log artifact → meter → driver
```

`case=1` through `case=5` each exercise one of those seams with the others held as
fixtures. this is the only case where all six are live at once, and the only case that can
catch a defect that lives **between** two of them — and this route is that walk: it drove a
guarded stone through its own lanes, and the meter priced them.

## .the narrative

a driver marks a stone `--as arrived`. the guard runs its peer lanes. some approve, some
reject. the driver absorbs, re-arrives, and the ladder eventually clears.

then, with no context switch and no credential:

```sh
rhx review._.cost --of tree
```

```
├─ runs: 5 (5 metered)
├─ tokens
│  ├─ input:     74.4k
│  ├─ cache.get: 58.2k
├─ cache: 43.9% of prompt tokens served from cache
└─ cost: $0.032900425
```

the figure is about **the rounds they just lived through** — not a dashboard, not last
week's grove, not an estimate. that immediacy is what makes the number act on behavior: a
driver who sees one lane at 80% of the bill edits that lane's `--paths-with` in the same
session, while they still remember why it was wide.

## .the defects only this walk can catch

each lives *between* two seams, so every single-boundary case passes while it is present:

| defect | why `case=1`–`case=5` all miss it |
|---|---|
| the guard writes its log somewhere the meter does not read | each side is correct alone; only a live round proves they agree on a path |
| a lane crashes mid-round and writes no `metrics.realized.json` | `case=2` proves `unknown` renders right **given** such a run — only this walk produces one |
| `sharedPrefix.sentAs` records `prompt` rather than `brief` | the anatomy test measures bytes; only a real call records what was actually sent |
| the census is written but its `metrics.compiled.json` never lands beside the realized one | `writeInputArtifacts` is unit-tested; the pairing is not |
| the cache rate is real but near zero because heads differ per lane | the fixture measures one lane's rounds. eleven live lanes is a different question |

the last row is the open question of the whole wish, and this is the only walk that can
close it — which is why `1.vision.yield.md` refuses to claim a grove-wide rate: no run of
this walk at grove scale has happened yet.

## .the bdd sketch

```
given [case6] a guarded stone with several peer lanes
  when [t0] the stone is driven to a terminal verdict
    then every lane that ran wrote a log dir under `.log/bhrain/review/**`
    then each dir holds BOTH `metrics.compiled.json` and `metrics.realized.json`
    then each realized record names the reviewer, the stone, and the round
  when [t1] `rhx review._.cost --of tree` is run in the same tree, immediately after
    then the run count matches the lanes that actually ran
    then the `by reviewer` roll-up names the same slugs the guard reported
    then the cache share is a REAL rate, not a byte-count projection
  when [t2] a lane crashed before it recorded cost
    then it is graded `unknown`, excluded from the sums, and counted in the header
    then the total does not silently absorb it as $0.00
  when [t3] the same stone is re-driven after a repair
    then the second round's cache share EXCEEDS the first's
    then this is the claim the whole wish rests on, and only [t3] can test it
```

## `[t3]` is satisfied

closed in two steps: the instrument — `--trace` renders `byRoundAndReviewer` key-ordered, so
a two-round series is readable at all — and the measurement: `rhx review._.cost --of tree
--trace` over this stone's own i001 → i002, with a driver's repairs between them.

| round | runs | prompt | cached | cost |
|---|---|---|---|---|
| i001 | 18 | 9.1M | 0.0% | $2.099072360 |
| i002 | 17 | 9.0M | 28.5% | $1.497197412 |

the second round's cache share exceeded the first's — 0.0% → 28.5%, and per lane six of
nine stepped 0.0% → ~39.1% in lockstep. the near-identical prompt mass (9.1M vs 9.0M) is
the control that makes the $0.60 drop a cache effect rather than a smaller corpus.

three lanes stayed at 0.0% and are reported rather than dropped —
`arch-opport-decomposition`, `repo-rules`, `mech-decode-friction` — each marked
`⚠️ warm and cached NAUGHT` by the instrument. that is the clock defect `case=7`'s warmer
exists for.

the full record, with the LRU poke figure and what it does NOT establish (one stone, one
tree — never a grove-wide realized rate): `research.review-cost-and-cache`, *"the two-round
measurement"*.

no test file backs this: a hermetic fixture would assert the fixture, which
`philosophy.verification-strictness` forbids outright. the artifact that satisfies `[t3]` is
a dated live measurement, and the instrument that took it carries the tests.

## `[t3]` was not optional at verification

`rule.require.experience-catalog-evolution` states the terminus in both directions:

> at the vision, a critipath owes only a **sketch** … verification is where that sketch must
> become **proof**: by the time the verification stage passes, every critipath in the catalog
> owes a **real test** that exercises it.

`case=6` is graded `criti`, so `[t3]` was a blocker at 5.3, not a wish carried forward. every
other argument on this branch is a byte count; `[t3]` is the only walk that turns one into a
measurement, which is what wish bar 5 asks for — *"the gain is measured, never projected."*

## .why it is a critipath

it is the walk that turns every byte-count argument on this branch into a measurement or
refutes it. the wish's bar 5 — *"the gain is measured, never projected"* — has no other path
to closure.

and it is the walk a driver takes most often once the instrument exists, because it costs
them no extra step: they were already here.
