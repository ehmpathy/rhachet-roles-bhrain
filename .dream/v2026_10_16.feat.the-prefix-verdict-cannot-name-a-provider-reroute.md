# 🌙 dream: the prefix verdict cannot name a provider reroute

kind = feat · owner = rhachet-roles-bhrain (review meter) · caught 2026-10-16

## .the cue that fired

`rhx review._.cost --of tree` reports `prefix: 775 served · 🔴 622 missed`. one missed round,
read with `--of run`, shared 425.7k chars of prefix with its prior round, broke only in the
tail, and still read 0 cached tokens. the prompt was sound; the miss happened past the prompt.

the same report's `by provider` rows suggest where: Wafer 9.1% cached, Morph 7.0%, Decart 1.1%,
InferenceNet 1.2%, DigitalOcean 0.7%. a provider cache lives on that provider, so a lane whose
rounds land on two providers misses on every switch, however perfect its prefix.

## .the gap, precisely

- `getOnePrefixVerdict` grades a pair from `sharedChars`, `promptChars`, and tokens alone
- `getOnePrefixPairOfRuns` never reads either run's `provider`, though `ReviewRunMeter` carries it
- so a warm miss with a sound prefix reads `missed` whether the provider switched (a route
  defect, fixable by a provider pin) or held (an eviction, not fixable here)
- 1288 of 2225 runs in this tree predate `supply.provider`, so they stay unclassifiable; every
  run since carries it

## .the shape of the fix

1. pass both runs' `provider` into the pair; where both are known and differ and the prefix
   held, verdict `rerouted` (the cause named, beside `missed`)
2. render it on the `prefix:` lever line at every breadth (run, tree, grove), with the count
3. where `rerouted` dominates, the fix is upstream: a provider pin in the brain's route choice
   (`rhachet-brains-openrouter`), so the render names that lever
4. clamp: a pair with a shared prefix, zero cache read, and two providers grades `rerouted`;
   the same pair with one provider grades `missed` (red before, green after)

## .why it is not done in this round

a new verdict changes the render contract at three breadths and their snapshots. safe, but it
needs its own branch — and the branch for this loop's work is still undecided.
