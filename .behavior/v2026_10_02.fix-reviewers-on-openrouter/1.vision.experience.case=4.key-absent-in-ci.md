# case 4 — a maintainer pushes before anyone added the secret

sharp × criti · **the likely state on the first push** (see fulcrum F2)

## .narrative

the maintainer pushes the cutover the moment it is ready, before anyone has added an actions
secret. they open the failed run and brace for opaque `401`s. instead the credential step's report
names the key — `OPENROUTER_API_KEY` is absent — and every red suite fails with the same refusal:
exit 2, the key named, the command that sets it. no `401`, no stack trace. they know at a glance it
is a grant, not a code defect. they add the secret under the repo's actions settings, click re-run,
and case 2 follows.

the run does NOT stop at the credential step: today the firewall exits 0, so the red is spread
across each suite that reaches a brain rather than held to one step. that single early halt is owed
by rhachet, not this repo (fulcrum F3).

## .fail-safe owed
- **fast**: it fails at the credential step or the first brain call, not deep in each suite —
  delivered at the first brain call; at the credential step, owed upstream (F3)
- **loud**: one red step, not forty — owed upstream (F3); today each red suite is loud on its own
- **teaches**: the failure names `OPENROUTER_API_KEY` — delivered, at the step and in each suite

## .measured, and pinned

`blackbox/keyrack.firewall-key-absent.acceptance.test.ts` runs the CI credential step
(`keyrack firewall --env test`) with no secrets, in a bare env like a CI runner's:

| fail-safe | holds? | evidence |
|---|---|---|
| **teaches** | ✅ | the report row names `ehmpathy.test.OPENROUTER_API_KEY` as `absent`, with `rhx keyrack set --key OPENROUTER_API_KEY --env test` |
| **loud** | ✅ per suite | the firewall does not halt, so each suite that reaches a brain fails with the case 3 refusal: exit 2, the key named, no stack trace, no opaque `401` |
| **fast** — one red step | 🔴 not here | the firewall exits 0 on a declared-but-absent key (rhachet 1.48.1). pinned, so the test goes red the day rhachet changes it |

⇒ the single early failure is rhachet's to deliver: the firewall step is the shared declapract
workflow, and the halt belongs in `keyrack firewall` for every repo, not in a bespoke step here.
caught as a reseed dream: `dreams/v2026_10_03.reseed.rhachet-keyrack-firewall-halts-on-absent-key.md`.
