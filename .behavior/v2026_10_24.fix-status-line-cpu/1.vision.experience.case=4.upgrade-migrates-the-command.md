# case=4 — an upgrade migrates the command (happy · critipath)

## .narrative

an operator's repo still names the old command in `.claude/settings.of.repo.json`. they run
`rhx upgrade` as they do each day. the driver init sees a status-line command it owns (it
names `routeStatusLine`), compares it to the shipped config, finds it differs, backs the file up,
and writes the new subpath command. its tree reports `status = configured` (`init.claude.status-line.sh:324`). each seat picks it up at
its next session start. no seat had to be told; the old command kept a correct line until then.

## .bdd sketch

```
given('[case4] repo settings that hold the old cli/route status-line command')
  when('[t0] the driver status-line init runs')
    then('the settings now hold the cli/route.status.line command')
    then('a backup of the prior settings is written')
    then('every other settings key is untouched')
  when('[t1] the init runs again')
    then('it reports already configured, and writes no backup')
```
