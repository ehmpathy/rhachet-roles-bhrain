# 🌙 dream: the peer-review filename grammar is bypassed, in both directions

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, by `review.self` on `v2026_09_03.fix-contemplation-gate-on-entrance` —
  the **build** half at `r2 has-consistent-mechanisms`, the **parse** half at `r3`

## .the cue that fired

the guide asked *"do we duplicate extant utilities?"* about two new mechanisms. both times the
answer for mine was *"no"* — and both times the search turned up the mirror instead: **extant
callers that rebuild or re-read the peer-review filename by hand, where a production transformer
already does it.**

## .the grammar, and the two transformers that own it

```
$stone._.review.i$iter.$hash.r$index._.given.by_peer.$slug.md
$stone._.review.i$iter.$hash.r$index._.taken.by_self.$slug.md
```

| direction | the operation | what it guarantees |
|---|---|---|
| **build** a taken from its given | `getRouteGuardReviewPeerPathTaken` | swaps one infix, keeps *"every other segment verbatim"* — the pair cannot desync |
| **parse** a path into its parts | `getRouteGuardReviewPeerPathMeta` | one reader for `{slug, hash, iteration}`, and it **throws** on a name it cannot read |

⚠️ **this behavior made the grammar structural.** a taken now discharges its **own given's** hash
(P2b), so the derivation is the mechanism rather than a cosmetic detail — which raises the price of
every bypass below.

## 1. the build half — three tests rebuild the name from parts

```
src/domain.operations/route/drive/getRouteDriveBlockerMessage.integration.test.ts:45
  `1.vision._.review.i001.${hashCurrent}.r001._.taken.by_self.${t.slug}.md`

src/domain.operations/route/guard/review/peer/getRouteGuardReviewPeerContemplationStatus.integration.test.ts:49
  `1.vision._.review.i001.${hash}.r001._.taken.by_self.${t.slug}.md`

src/domain.operations/route/stones/setStoneAsContemplated.integration.test.ts:51
  `1.vision._.review.i001.${hashCurrent}.r001._.taken.by_self.architect.md`
```

**the hazard is a false green, not a false red.** change the filename grammar and these tests still
pass against the *old* shape while production writes the *new* one. a test that cannot observe the
grammar it depends on does not guard it.

## 2. the parse half — a second reader, with the OPPOSITE failure semantics

`getLatestReviewFilesPerIndex.ts` re-derives the stamp with its own regexes rather than the
production reader:

```ts
const iterMatch = path.basename(filePath).match(/\.i(\d+)\./);
const indexMatch = path.basename(filePath).match(/\.r(\d+)\./);
const iteration = iterMatch?.[1] ? parseInt(iterMatch[1], 10) : 0;
const index = indexMatch?.[1] ? parseInt(indexMatch[1], 10) : 0;
```

🔴 **this is worse than a duplicate, because the two readers of one grammar fail in opposite
directions:**

| the reader | a name it cannot read yields |
|---|---|
| `getRouteGuardReviewPeerPathMeta` | 🔴 **throws** `UnexpectedCodePathError` — failfast |
| `getLatestReviewFilesPerIndex`, at the two `parseInt(…) : 0` fallbacks above | **iteration 0, index 0** — failhide |

under the second, such a filename reads as *"the oldest"* and is silently outranked by every
well-formed peer. its two callers are `computeStoneJudgeInputHash` and `route.ts`'s guard-tree
render — so one silent misread lands in a **hash** and one in **display**, and neither announces
itself.

⚠️ **four line citations struck 2026-09-08** — `…PathMeta` and `route.ts` are both edited by this
branch, so their numbers were fused; the other two were redundant beside the code block and the
operation names above them. that is
`rule.forbid.failhide`, in a spot where a throw is already the house answer four files away.

⚠️ **`…PathMeta` cannot serve it as it stands** — it returns `{slug, hash, iteration}` and **not
`index`**, which is exactly the key `getLatestReviewFilesPerIndex` groups on. so this fix is a widen
of the parser, never a swap at the call site.

## .the shape of the fix

**for the build half** —
`src/domain.operations/route/__test_assets__/answerEveryPeerCritique.ts` already exists and does it
right. where a test needs *every* critique answered, call it; where it needs **one specific** taken
(the common case in those three), call `getRouteGuardReviewPeerPathTaken` rather than a template
literal. leave each test's assertions untouched.

**for the parse half** —
1. add `index` to `getRouteGuardReviewPeerPathMeta`'s return, and to its `stampMatch` capture
2. have `getLatestReviewFilesPerIndex` call it, and let the throw propagate
3. ⚠️ **check the two callers first.** if either legitimately feeds it a non-peer file, the fix is a
   filter at the call site, never a soften of the parser back to `?? 0`

⇒ each file is independent, so both halves can land one at a time.

## .why it is not done in this round

**safe, but not clean.** every file cited sits outside this behavior's diff.

- the three tests: `rule.require.review-test-changes` forbids a change to tests my work does not
  touch — a reviewer cannot tell a drive-by cleanup from a silent drop of an assertion
- the parser widen: it changes a **hash input** (`computeStoneJudgeInputHash`) for every stone in
  every repo that uses this engine. a behavior about the contemplation gate is the wrong diff to
  carry that in

⇒ both are genuine fixes, and each wants its own small diff where it can be reviewed as one.
