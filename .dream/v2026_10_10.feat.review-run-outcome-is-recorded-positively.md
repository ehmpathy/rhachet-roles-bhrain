# 🌙 dream: a review run records its outcome positively

kind: feat · owner: bhrain/reviewer · caught 2026-10-10

## .the cue that fired

i035 r031 nitpick.3: `refused` and `unknown` reach the meter only as the absence of
`metrics.realized.json` / `metrics.expected.json`. each new artifact a run writes must remember to
act as a witness, or a refused run reads as unknown.

## .the gap, precisely

`getOneReviewRunGrade` grades from which of three files exist. the prime and the partition split
each had to be checked against that rule by hand. `--of run` cannot say WHY a run is unknown.

## .the shape of the fix

1. `stepReviewOfCompiled` writes `outcome.json` on every exit: `{ grade: 'metered' | 'refused' | 'unknown', reason, unmeasured: N }`
2. `getOneReviewRunGrade` reads it first; the three-file grade stays as the legacy path for runs on disk
3. `--of run` renders `reason` under an unknown grade
4. clamp: a refused run with no metrics files grades `refused` from the record alone

## .why it is not done in this round

dirty: a new artifact contract, a legacy reader, and the snapshots of three breadths (F205).

## .deferred again — 2026-10-13

no `outcome.json` exists under `src`. to add it means a new artifact contract, a legacy reader in `getOneReviewRunGrade`, and snapshots at all three breadths. not clean for this branch.
