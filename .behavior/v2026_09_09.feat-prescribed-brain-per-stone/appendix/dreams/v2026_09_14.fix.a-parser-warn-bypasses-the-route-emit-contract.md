## .the gap, precisely

the repo already has a warn convention, and `getBudgetClobberWarnings` states it in its own `.note`:

```
src/domain.operations/route/guard/upgrade/getBudgetClobberWarnings.ts:15-16

  .note = pure — takes two already-parsed guards and yields structured warnings; the
          renderer owns the prose.
```

⇒ **a producer returns a structured warning; a renderer owns the words.** `GuardUpgradeWarning` is the
shipped type, `getAllGuardUpgradeWarnings` the collector, and `formatGuardUpgradeTree` the renderer.

the `model:` alias warn does neither. it writes prose to the process from inside a parser.

### 🔴 the sharper half — it is a BYPASS, not a style divergence

every other output in the route engine flows through the hook's own emit shape:

```ts
// stepRouteDrive.ts — the contract every branch returns
return { emit: { stdout, stderr: { reason, code } } };
```

a raw `console.warn` writes straight to process stderr, **outside that structure**. so the one signal
a near-miss key ever gets is delivered by a channel the engine does not own and its consumers do not
read as part of the emit.

⚠️ **whether it reaches a human is UNVERIFIED and is the thing to measure first.** hook stderr on a
zero exit may be suppressed by the consumer; the `F4` ruling made the parser permissive, so this warn
is the entire fail-safe `case=4` has. if it is invisible, the fail-safe is not degraded — it is
absent. **do not assume either way; run it.**

## .the shape of the fix

two candidates, and the first is the extant convention:

1. **mirror `GuardUpgradeWarning`** — `parseStoneGuard` returns its diagnostics beside the guard, and
   `stepRouteDrive` renders them into the `🗿` tree it already emits. ⇒ matches the repo, and changes
   `parseStoneGuard`'s return shape, which has many callers
2. **an optional field on the parsed object** — `warnings?: string[]` on `RouteStoneGuard`, rendered
   by the caller. ⇒ additive and non-breaking, and it puts a **parse side effect** onto a domain
   object whose whole subject is the guard's declared contents

⇒ **#1 is the convention and #2 is the cheap one.** the call between them is a real design question,
which is why this is a dream over an inline fix.

**the clamp it owes:** a guard with `model:` parsed through the full drive path, asserted to surface
in the emit a consumer actually reads — not merely in a captured `console.warn`. the extant test
(`parseStoneGuard.brain.integration.test.ts` `case5`) proves the warn is CALLED and proves naught
about whether it ARRIVES.

## .why it is not done in this round

**SAFE — no.** `parseStoneGuard`'s return shape is read across the guard, drive, judge, and upgrade
subsystems. to change it is to touch every one, on a round whose subject is a brain switch.

**CLEAN — no.** candidate #1 ripples into every caller; candidate #2 needs a domain-modeling call on
whether a parse diagnostic belongs on the parsed object.

⇒ both answers are no, so `rule.always.fix-forward-under-scouts-honor` sends it here. **and the
deferral is a judgment about ripple cost, so it owes a fulcrum too** — recorded as `F15` in the
route's inventory rather than left as a private call.
