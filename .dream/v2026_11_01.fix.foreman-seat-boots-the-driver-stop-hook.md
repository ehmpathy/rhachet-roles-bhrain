# 🌙 dream: a foreman seat must not boot the driver's onStop hook

- kind = fix
- owner = bhrain/role=driver (route.drive --when hook.onStop)
- caught 2026-11-01

## .the cue that fired

a foreman session, seated in a worktree whose route a separate driver session (`mechanic`) drives,
was held at every stop by `rhx route.drive --when hook.onStop` with "the reviewers await your reply".
the only way out was to write the driver's `.taken` and absorb, which is a second hand on one route.

## .the gap, precisely

the onStop hook keys on the worktree's bound route, never on which session drives it. any session
booted in that worktree inherits the driver's gate, so a foreman, a reviewer clone, or a director
probe is held to a duty it does not own. the hook offers no exit but the driver's own act, which
invites the collision: this foreman conceded, absorbed, and re-arrived on the driver's route while
the driver was mid-fix in the same files.

## .the shape of the fix

- the onStop gate applies only to the session that holds the route's drive (a watermark that names
  the driver session, written at drive start), never to every session in the worktree
- a non-driver session sees a one-line advisory, exit 0: "route X is driven by session Y; its gate is theirs"
- clamp: two sessions in one worktree; the non-driver's stop passes, the driver's stop still holds

## .why it is not done in this round

the fix is in the driver role's hook and drive watermark, a contract change outside the wish
(bhrain#653), and this seat is foreman, not driver.
