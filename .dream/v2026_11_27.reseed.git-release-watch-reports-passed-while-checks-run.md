# 🌙 dream: git.release --watch reports "all checks passed" while the head's checks still run

kind: reseed · owner: ehmpathy/role=mechanic (git.release) · caught 2026-11-27

## .the cue that fired

a push to pr #855 started a fresh ci run on its new head. `rhx git.release --watch`, run twice
right after, printed `👌 all checks passed` and `🫧 no runs inflight` both times, with
`0s watched`. `gh pr view 855 --json statusCheckRollup` at the same moment showed the lint,
types, unit, and every integration shard as QUEUED or IN_PROGRESS.

## .the gap, precisely

- the watch reads a check state that does not match the pr head's rollup; likely the prior head's
  runs, or only runs already registered when the watch starts
- a false green is the worst failure shape here: `rule.require.watch-release-after-push` sends
  every mechanic to this watch as the proof of green

## .the shape of the fix

- read checks by the pr's current `headRefOid`, and treat QUEUED / IN_PROGRESS as inflight
- if the head has no runs yet, wait for them to register before a verdict; never report passed on
  zero runs seen
- clamp: a test with a head whose rollup holds a queued check must not print passed

## .why it is not done in this round

the skill lives in rhachet-roles-ehmpathy, another repo; `gh pr checks --watch` serves as the
watch meanwhile.
