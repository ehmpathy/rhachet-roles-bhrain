# 🌙 dream: sedreplace answers `--help` and states its match mode

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill `sedreplace`)
- caught: 2026-11-24

## .the cue that fired

a rename of one word across rule files (`seat` → `session`) needed a word-boundary match, so that a
linked filename that holds `unseated` stays intact. `rhx sedreplace --help` exits 2 with
`unknown argument: --help`. a plan with `--old '\bseat\b'` reports `no files contain pattern`, which
shows the match is literal, never regex. both facts took a failed call to learn.

## .the gap, precisely

- no `--help` (`rule.require.help-on-demand`: a command with no `--help` = blocker)
- the usage line does not say whether `--old` is a literal or a regex, so a regex reads as "no
  match" and looks like a clean result
- no word-boundary option, so a rename of a short word cannot avoid its substrings in other words
- the same day, two peers of the same skill set: `rhx set.package.upgrade --help` exits 2 (`unknown argument: --help`), and `rhx set.package.install --for prod` on a package that sits in devDependencies refuses with "already installed. use set.package.upgrade instead", so a dev → prod move (the fix for a runtime import filed as dev) has no paved verb

## .the shape of the fix

- `--help` / `-h` print usage, inputs, and an example, exit 0
- the usage and plan header name the match mode (`match: literal`)
- an opt-in `--word` (whole-word match) or `--regex` flag, with a plan that shows each hit
- `set.package.*` answer `--help`; `set.package.install --for prod` on a dev entry moves it (or names the verb that does), and updates the lockfile with it

## .why it is not done in this round

the skill lives in another repo; a fix here would be a fork. the rename in this route used
per-line edits instead.
