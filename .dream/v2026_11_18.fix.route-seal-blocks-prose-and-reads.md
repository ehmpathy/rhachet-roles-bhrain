## .the gap, precisely

the seal keys on any `.route` path segment or the ledger name in a Bash command (r011 i007: a verb
list was a denylist a driver could route around). it fails closed, so it also blocks:

- a commit message passed inline that names the path
- `git add`, `git diff`, `cat`, `jq` of the tracked `.route/passage.jsonl`
- `rhx git.stage.add` of route files at commit time

the block text says "run `rhx route.drive`", which does not help any of these.

## .the shape of the fix

- parse the command into words with a shell lexer (bash's own `read -a` on a safe quote set, or a
  small ts lexer behind a solid skill), and seal only a word that is a path argument of a write
  form: a redirect target, a `tee` / `cp` / `mv` / `install` / `dd of=` destination, an editor
- keep the fail-closed default for any form the lexer cannot read
- a test per allowed read (`cat`, `jq`, `git diff`, `git add`) and per prose mention, beside the 8
  write forms in `COMMANDS_THAT_REACH_THE_LEDGER`
- a block text that names what IS allowed: reads, and `rhx git.commit.set -m @stdin`

## .why it is not done in this round

the lexer is a new parse surface on a security seal, and r011 graded the last narrow match as a
bypass. a fail-closed seal costs friction; a fail-open one costs the verdict's integrity. the
friction is the lesser harm until the lexer ships with its own review.
