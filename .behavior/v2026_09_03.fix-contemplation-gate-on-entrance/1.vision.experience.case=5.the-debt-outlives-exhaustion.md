# case=5 · the debt outlives exhaustion

- **coordinates** = `enter-review × carried-unanswered × exhausted`
- **feel** = sharp · **care** = critipath · **verdict** = forbidden → demoed

the deliberate behavior **change**. the wish asked that it be decided out loud. **it is kept.**

| | today | under this behavior |
|---|---|---|
| a reviewer exhausts with a blocker unanswered | the debt vanishes; the driver proceeds | the debt persists; the driver must answer, or a human overrules |

today exhaustion is the cheapest exit of all — a reviewer that burns its budget writes no given at
the next hash, so no debt exists to read. `rule.always.converge-to-terminal` calls a coasted budget
a defect, and **today the engine rewards it**. that inversion closes here.

## .the narrative

*driver, on a stone where the mechanic has run out of budget*

the mechanic raised one blocker on its last round and has no round left to re-check my fix.

**today** I would run `--as passed` and sail through — no given at the current hash, the gate reads
clean, the blocker is simply gone and nobody decided that.

**now it holds**, and I have two exits, both mine:

- **answer it** — `[REPAIR]` with the fixed lines quoted, or `[REFUTE]` with evidence. the mechanic
  will never read it, and that is fine: the `.taken` is on record for the human and for whoever
  reads this stone next
- **top the budget up** — `rhx route.guard.budget --for review --add 2 --stone 5.1.execution`, so
  the mechanic can confirm the fix itself

only if I can do neither honestly do I escalate — case=6.

**the aha:** an exhausted critic is not a withdrawn critic. it is a critic who ran out of breath
mid-sentence. the sentence still stands, and somebody still has to answer it.

## .the bdd timeline

```gherkin
given a stone `5.1.execution` with peer reviewer `mechanic`, budget 3, rounds=3
  and the mechanic raised 1 blocker at hash 7c04b9 (its last round)
  and artifacts have since moved the current hash to 4b81e0
  and no .taken.by_self.mechanic exists
  and no overrule covers the mechanic's level

[t0] when the driver runs --as passed
     then the guard halts at the entrance
      and the reply-prompt cites `mechanic`, with hash 7c04b9
      and the mechanic is NOT run                              # exhausted, correctly skipped

[t1] when the driver writes the .taken and runs --as contemplated --that mechanic
     then the response is acknowledged
      and a later --as passed is admitted
      and the mechanic remains exhausted and unrun             # a record, not a re-run

[t2] given instead the driver tops the budget up FIRST, with no .taken written
       rhx route.guard.budget --for review --add 2 --stone 5.1.execution
     then the mechanic has budget again
      and a later --as passed is STILL held                    # budget is not an answer
      and the mechanic does NOT re-run                         # 🔴 the entrance gate precedes it

[t2b] given the driver then writes the .taken and runs --as contemplated --that mechanic
      when the driver runs --as passed
      then the gate opens, and NOW the topped-up mechanic re-runs
       and it can CONFIRM the fix rather than leave a stale blocker on record

[t3] given instead the mechanic's last given carried 0 blockers
     when the driver runs --as passed
     then it is admitted                                       # only blockers gate
```

🔴 **`[t2]` is the sharp assertion, and `[t2b]` is what stops it from being read as the wrong
lesson.** more budget makes the reviewer able to speak again; it does not answer what it already
said. two separate levers — and **they are ordered, never optional-or-either**.

⚠️ **why the order is forced, and not merely advised.** the entrance gate sits *before* the review
run (P1), so while a debt is owed **no reviewer runs at all** — not even the one you just paid for.
a top-up spent before the answer buys a round that cannot be taken.

⇒ so the top-up is **not a discharge path**, and the yield's *"a reviewer drops its own blocker"* row
is reachable only **after** an answer opens the gate. what the top-up buys is the round in which an
exhausted critic **confirms** the repair — the difference between a stone that passes with a stale
blocker listed against it and one that passes clean.

🔴 **this paragraph was right, and the row it names survived two more stones.** the yield kept
*"clears with no `.taken`"* as a live edge-case answer, and the false clause reached the shipped code
comment; the wisher struck it 2026-09-07. ⇒ **a correction written beside a claim does not correct
the claim.** the row is now struck at the source — `1.vision.yield.md` § "the second corrected row".

🔴 **and it is still owed before any escalation.** `rule.always.spend-own-levers-before-escalation`
names the exact trap: the guard renders *increase budget* and *approve as-is* as peer branches, which
invites the read *"two human remedies."* only the second is one. **answer, then top up, and only then
consider case=6.**

## .why it fails safe

**fast** — halts at the entrance, no subprocess · **loud** — the same reply-prompt, verdict and
raise-hash both shown · **teaches the fix** — cites the file to write and the command to run.

⚠️ **the deadlock check — and it is narrower than it first reads.** the driver **does** hold a
unilateral exit here: `[t1]`, the answer. what has none is the **sub-case where no honest answer
exists** — an out-of-scope blocker the driver can neither repair nor refute. **that** sliver is why
case=6 must exist; absent or hard-to-reach, the human overrule would convert a stalled stone into a
stuck one. ⇒ **case=6 is not colour; it is the proof this case is survivable at its one exitless
corner.**
