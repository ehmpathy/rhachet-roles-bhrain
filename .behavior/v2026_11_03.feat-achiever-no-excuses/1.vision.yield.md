# 1.vision — role=achiever, no excuses

## .the outcome world

### before

- the commander types five orders over an afternoon. the clone hears all five and works three. the
  other two lived only in context and died at compaction. the commander finds out at review
- the clone hits a wall, writes "blocked: waits on the human for X", and stops. the extant onStop
  halt even suggests it: *"if blocked, run `--status.choice blocked`"* (`src/contract/cli/goal.ts:1629`),
  and a `blocked` goal releases the halt. the excuse is a paved exit
- a goal marked `fulfilled` carries any reason text. "looks done" closes it

### after

- every commander message lands in the scope's `asks.inventory.jsonl` before the clone reads it
  (the extant talk hook; the scope is `$route/.goals` when a route is bound, else `.goals/$branch`,
  `goal.ts:467-490`). each ask is covered by a goal; each goal closes only when its done check,
  a shell command, exits 0. the stop refuses while any ask is uncovered or any goal is open
- a blocker has three exits and no fourth:
  1. **run** the cure now (a locked key, a stale build, a defect in a tool it builds)
  2. **dispatch** the cure to its owner, with an hour: a follow-up deadline after which the stop
     refuses until the chase is logged
  3. **name the one act** truly above its charter, as a command, with who may run it
- "blocked on X" with no cure is refused at the set and at the stop

### the aha

the commander sends one batch of orders and walks away. on return, the record shows every order
closed by a check that passed, or blocked with one of three cures. there is no "what happened to the
rename?" and no "it said it was blocked, so it sat." the receipt and the proof are the same file.

## .the contract, sketched

the role stays `achiever` in this repo; it gains duties, not a twin. sketch commands, not committed
flags:

| surface | today | after |
|---|---|---|
| `rhx goal.memory.set --how.gate '<cmd>'` | prose | a shell check; prose refused unless `--how.gate.self-attested-why` |
| `--status.choice fulfilled` | any reason | the store runs the check; exit 0 or refused |
| `--status.choice blocked` | a reason | owes `--cure.via dispatch\|charter` (+ `--cure.ref --cure.await` or `--cure.act --cure.who`) |
| `GoalStatusChoice` | incomplete · blocked · enqueued · inflight · fulfilled | + `declined` (owes a why) · `deferred` (owes a when): the terminals the itemize rule already names |
| coverage (`Coverage.ts`) | links an ask hash to a goal slug only | + a no-work close with a why, so a remark or a one-line answer is covered without a fake goal (`case=11`) |
| onStop | not wired (`getAchieverRole.ts` has onBoot, onTool, onTalk only) | `goal.triage.infer --when hook.onStop` and `goal.triage.next --when hook.onStop` wired |
| onStop `goal.triage.next` | halts on inflight/enqueued; a blocked goal escapes | also halts on a blocked goal with no cure, and on a dispatch past its hour |
| a forbidden scope (main) | the talk hook throws, the order is lost; the stop passes | the order is held; the stop reds until the clone branches (`case=12`) |
| a hook malfunction | exit 1: a Stop gate fails open | exit 2 with `💥 MalfunctionError`: fail closed |
| inbound radio tasks | read by no hook | the stop reads the local channel's QUEUED inbound tasks as asks (`case=13`) |
| `inits/init.claude.sh` | calls an absent `init.claude.hooks.sh` | retired; every hook rides `Role.hooks` |
| briefs at say | goals-are-promises, triage howto, lucky-charms, itemize (2), scouts-honor | goals-are-promises; the three delegate briefs carried across (`rule.always.achieve-relentlessly`, `rule.forbid.tolerate-a-blocker`, `rule.always.track-every-ask`); the itemize cluster beneath track-every-ask; the rest to ref with `.min` peers |
| goal.tree (nheuron) | a second goal store, in another repo | promotes here onto `.goals`: done check, await, progress, close-green, subgoals, supersede, reopen, dupes. extant goals carry over unchanged |

**the clamps** (the wish's "prove each duty bites"):
- clamp 1 — an ask in the inventory with no goal → onStop exits 2 (`case=2`)
- clamp 2 — a blocked goal with no cure → set and onStop exit 2 (`case=6`)
- each is proven to bite: revert the wire, the test goes red

**the delivery**: the change ships as one pr in this repo, and it waits on the commander's review on
github; it is never auto-merged.

## .mental model

- to a friend: *"it writes down every order the second you give it, and it won't clock out while one
  is open, or while it's stuck without a plan to get unstuck."*
- analogies: a kitchen ticket rail (every order on a ticket; a ticket comes down only when the plate
  goes out); a foreman who never says "we wait on the electrician" without the call already made and
  a time to call back
- their words vs ours: "my asks" / "orders" → ask, goal; "it got stuck" → blocker; "fix it or chase
  it" → cure (run, dispatch); "you need me for that" → above charter

## .evaluation

| goal | how well | note |
|---|---|---|
| lossless track | strong | the inventory already writes at talk; the gap was the unwired stop and a done that proves naught |
| no excuses | strong | the cure shape removes the paved exit; the stop holds a dispatch to its hour |
| boot beside other roles | fair | cap is 7,500; the fit depends on F6 |
| one achiever | strong | same role, same store, same skills; one dead init retired |

pros: reuses the store, hooks, and skills that ship today; two clamps, each a single integration test;
the refusal names the three cures, so the fix is always on screen.

cons: a runnable done check costs a command per goal; some asks have no world check, and the
self-attested escape can grow into a new excuse. a stop that holds can loop; nheuron wraps its
goal.tree gate in `director.stop.gate.sh`, which caps it at two blocks per turn for this reason.

edge cases, and how the contract keeps the pit of success:
- a legacy goal on disk, blocked with no cure → the stop shows the three cures, not a crash
- a prose done check on a legacy goal → close via the self-attested why, named in the refusal
- a dispatch with no hour → refused at the set
- a slow done check (a full test suite) → it runs at close under a timeout, as goal.tree does
  (`del` at 15s); a timeout reads as not-yet-done and says so, never as a pass
- a done check that needs a key the clone lacks → that is a blocker, and it owes a cure (case 4)
- a cure.act with two commands or none → refused: one act, pasteable
- the commander cancels or re-orders → the itemize rule owes `declined` (with why) and
  `deferred` (with a when), but `GoalStatusChoice` holds neither (`Goal.ts`). the role adds both,
  so a cancel is a mark, never a drop or a fake `fulfilled`
- no route bound → the scope falls back to `.goals/$branch` (`goal.ts:458-461`); an absent dir is
  created at the first write (`setAsk.ts`). no loss
- on main/master → the store forbids the scope (`goal.ts:472-476`); today the order is lost and the
  stop passes. the order is held and the stop reds until the clone branches (`case=12`)
- a corrupt line or an unwritable store → today a hook crashes with exit 1, which a Stop hook reads
  as permission. the hooks fail closed: exit 2, a `💥 MalfunctionError` that names the file

## .what is awkward?

- `blocked` stays a status, but now means "blocked, with a cure in flight". a new word (e.g. `awaited`)
  may read truer; a rename ripples through every stored goal
- `how.gate` changes sense from prose to command. the old field name now holds a stricter contract;
  legacy goals hold prose there
- the self-attested escape is the soft spot. too cheap and it is "blocked on X" in new clothes; too
  dear and the clone writes fake checks (`echo ok`). the refusal of such checks is out of this round,
  caught as `dreams/v2026_11_03.feat.a-done-check-can-be-gamed-with-echo.md`
- a stop that holds is friction for a commander who truly wants the clone to pause. the commander's
  "stop" is itself an ask: it marks the open goals `deferred` with a when (a status the store must
  first gain), which the stop accepts
