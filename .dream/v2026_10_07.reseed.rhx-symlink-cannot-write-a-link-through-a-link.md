# 🌙 dream: `rhx symlink` cannot write a link whose target is itself a link

**kind** = reseed · **owner** = `ehmpathy/rhachet-roles-ehmpathy` (mechanic) · **caught** 2026-10-07

## .the cue that fired

the fixture `src/domain.operations/review/.test/assets/example.symlink/via-symlink` had to point at
`node_modules/test-fns/dist`. that path is a pnpm link into `.pnpm/<store-dir>`.
`rhx symlink --to node_modules/test-fns/dist --mode relative --idem upsert` wrote the realpath
instead: `.pnpm/test-fns@1.15.7_patch_hash=…/node_modules/test-fns/dist`. a raw `ln -sfn`, which the
permission hook forbids to a clone, was the only way to write the intended text.

## .the gap, precisely

the skill realpaths `--to` before it computes the relative link text. so a link through a stable
alias collapses onto the volatile target behind it. for pnpm, that target is the store dir. a
`patchedDependencies` entry, or a version bump, renames the dir, and every fixture link written by
the skill breaks. CI broke this way on PR #589 (run 37403587764, `enumFilesFromGlob` case5).

## .the shape of the fix

in `symlink.sh`, keep the repo bound check on the realpath, but compute the link text from the
lexical path of `--to` (collapse `..` and `.` segments, never follow links). an optional flag could
keep the old realpath behavior. a test case belongs beside it: a target that is itself a link, and
an assertion that `readlink` returns the lexical relative path.

## .why it is not done in this round

- **not clean** — the skill is published by another repo; a tree adopts only what is scoped to itself
- the one fixture that needed it is already repaired via a human-run `ln`
