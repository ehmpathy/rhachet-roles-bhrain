# 🌙 dream: a fulcrum entry's six fields are prose in a rule, with no template

**kind**: entool · **owner**: rhachet-roles-bhrain · **caught** 2026-08-31

## .the cue that fired

the wisher asked *"is it super clear howto declare fulcrums? has that been enbriefed?"* — and the
honest answer was **yes, at rung 1**, four times over:

| artifact | grain |
|---|---|
| `rule.always.defer-fulcrums-to-last` (driver) | the WHEN |
| `rule.always.itemize-the-fulcrums-you-best-guess` (driver) | the RECORD |
| `howto.navigate-fulcrum-choices.[guide]` (driver) | the clean/dirty ladder |
| `term=route.fulcrum._.choice.*` | the word |

⇒ the knowledge is complete. **the artifact is not.**

## .the gap, precisely

a fulcrum entry has **six required fields** — the fork, taken-and-why, rework-and-why,
confidence-and-why-it-is-low, where, the verdict — and they exist only as a markdown table inside a
rule's prose. so every entry is retyped from a re-read.

**and the summary row has five columns** that must agree with the entry, plus a census claim
(`rule.forbid.itemization-without-coordinates`: *"a summary row with no `case=$id.md` entry beside
it, or an entry absent from the summary = blocker"*).

⇒ this is `rule.always.entool-the-skills-you-touch`'s own test, answered against itself:
**"what did i still have to figure out myself?"** — the filename's ordinal, the slug, the field
order, and whether the summary row was appended.

🟡 **every one of those four is a STEP, not a judgment.** the judgment is the fulcrum's *content*;
the shape around it is the same every time.

## .the shape of the fix

**rung 1 → rung 2, at minimum:** a `template.route-fulcrum.md` beside `template.domain-term.md`,
which already exists and is the direct precedent — the glossary's cluster shape is a template, and
the fulcrum inventory's is not.

**rung 2 → rung 3, if it earns it:** a `route.fulcrum.set` operation that findserts both files —
computes the next ordinal from `Glob`, writes the entry from the six fields, and appends the
summary row in one call. that closes the census gap by construction rather than by discipline.

🟡 **the entoolment bar is real and low.** the *content* of a fulcrum is irreducibly a judgment, so
no rung retires it. what a tool retires is the **shape** — which is exactly the split
`philosophy.entoolment-is-the-pinnacle` says a route makes: a deterministic transport,
probabilistic cargo.

## .the open question this must answer first

🔴 **the fulcrum discipline is booted by ONE role.**

```
rhx grepsafe --pattern 'fulcrum' --glob 'boot.yml'
  → src/domain.roles/driver/boot.yml   (only — plus its dist mirror)
```

the **93% confidence floor** is a general discipline — *"a call you would not defend at 93% earns a
row"* — and it is reachable only from the driver. whether that is correct turns on one question:

> **does a role enrolled WITHOUT the driver ever best-guess a design fork?**

if no, the driver home is right and this is no gap. if yes, the floor belongs at `role=any` and the
route-specific half stays with the driver.

## .why it is not done in this round

**safe, and not clean.** a template is briefs-shaped and would fit; the operation is not, and the
boot-scope question is a policy call that ripples across every `boot.yml`. to ship the template
alone would entool the shape while the scope question stays open, so the two travel together.
