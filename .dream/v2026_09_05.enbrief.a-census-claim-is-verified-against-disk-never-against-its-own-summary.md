# 🌙 dream: a census claim is verified against DISK, never against its own summary

- **kind** = enbrief
- **owner** = `rhachet-roles-bhrain` — librarian (`rule.require.inventory-for-enumerable-concepts`)
- **caught** = 2026-09-05

## .the cue that fired

a condensation pass measured `.seeds/inventory.of=seeds._.md` at 0.73 marks per line and opened it
to cut. **the density was the cue; the census was the find.**

## .the gap, precisely

the summary table listed **22** rows. the directory held **27** entry files.

| the artifact | what it said |
|---|---|
| `inventory.of=seeds._.md` — the summary | 22 rows, and a gap line that read *"eighteen of the twenty-two are LIVE"* |
| `.seeds/*case=*.md` — on disk | **27** files. S23 · S24 · S25 · S26 · S27 had no row |

⇒ *"eighteen of the twenty-two"* is **correct arithmetic over an incomplete table.** the sentence is
internally consistent, so it survives every re-read — and it is false.

## .why the extant repair does not catch it

this route measured seventeen prior `declare-once` instances and produced a repair shape:
**enumerate by id, never restate a count** — because a struck row is then visibly absent.

**that repair does not reach this case, and the reason is exact:**

| the class | what catches it |
|---|---|
| a count that disagrees with its source | a careful re-read |
| an enumeration whose member was struck | the enumeration itself — the gap shows |
| 🟡 **a count that agrees with a summary which is itself incomplete** | **only a check against the artifact set** |

⇒ **an enumeration makes a STRUCK row visible. it does not make an ABSENT row visible.** the
seventeen prior instances were all of the first two classes, which is why the repair looked complete.

## .the shape of the fix

`rule.require.inventory-for-enumerable-concepts` already carries the principle — *"a silently
omitted cell (the omission voids the census claim)"* is listed as a blocker. what it lacks is the
**check**, and the check is mechanical:

```js
// the rows a summary claims vs the entries on disk. they MUST be equal.
const claimed = summaryLines.filter((l) => /^\|\s*\w+\d+\s/.test(l)).length;
const actual = fs.readdirSync(dir).filter((f) => f.includes('case=')).length;
```

so the rule wants one added clause and one added cue row:

- **the clause** — *a census claim is verified against the artifact set, never against the summary
  that states it. a `Glob` settles it; a re-read cannot.*
- **the cue** — *"you state a count of members in a cluster root"* → *glob the entries first*

🟡 **the rule already says the census is checkable by a `Glob`** — *"the gap check is a `Glob`, not
a read"*, in `rule.forbid.itemization-without-coordinates`. **the claim is present and no rule makes
anyone RUN it.** that is the whole gap: a stated affordance with no cue that fires.

## .why it is not done in this round

**safe: yes. clean: no.**

- the rule lives in the librarian's booted canon, and an edit to it is out of this behavior's
  declared scope — this route's diff is telepath 49 · learner 4 · reviewer 1
- the honest fix also owes an **audit**: every `._.md` cluster root in the repo should be checked
  against its entry set, and that sweep is dirty inside a behavior that still waits on `1.vision`
  approval
- ⇒ the local instance **is** repaired — the seeds summary now carries 27 rows for 27 entries, and
  the discrepancy is recorded in its own `.the gaps` table rather than quietly fixed
