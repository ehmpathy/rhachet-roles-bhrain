# wish: rhx review inputs hit the prompt cache, so a review re-run pays for its rubric and refs once

## .outcome

a review round (`rhx review`, as a guard runs it per peer lane) sends its stable inputs — the rubric, the briefs and refs it cites, the role boot — as a prefix the model provider caches, and the changed parts last. a second round over the same lane, or a peer lane that shares the rubric, reads that prefix from cache instead of paid fresh input.

the fleet's measured review spend was ~USD 50/day (2026-09-18), and a 0% cache hit rate was measured on one brain the same week. this row claims the waste inside that spend, not the total; the first deliverable measures how large the waste is.

## .done means

1. a measurement, before any change: for a sample of real review rounds, the share of input tokens that were cache reads vs fresh input vs cache writes, per brain the guards use. quoted with how it was read
2. a named cause for each uncached stable input (order of the prompt parts, a volatile token inside the stable prefix, a brain adapter that sets no cache marker, a ttl too short for the gap between rounds, or other), each traced to the line that causes it
3. the cure for each cause that the vision keeps in scope, each with a test that fails on the old prompt shape and passes on the new
4. the same measurement after the cure, on the same kind of rounds, with the delta stated in tokens and in USD per day
5. review verdicts unchanged: the cure moves bytes, never what a reviewer sees or decides

## .bounds

- no live brain call in a test that ci runs, and no credit ask: measure from transcripts and logs already on disk, and test the prompt shape offline
- a cause that lives in another repo (a brain adapter, rhachet core) is named with its line and dispatched as its own task; it is not patched from this tree
- size: start nano. if the measurement shows the cure needs a blueprint, say so at the vision and the director decides
