# roadmap: review.by skill

## how to read this

phases run in dependency order — each phase depends on the ones above it. every phase declares:

- **pre-reads** — briefs/yields to read before the phase
- **deliverable** — the files it produces
- **acceptance** — behavioral criteria it must satisfy
- **verify** — the exact command that proves acceptance

do not start a phase until its pre-reads are read and its upstream phases pass verification.

### pre-reads for every phase (the always-read set)

read once at the start, keep in context throughout:

- `.behavior/v2026_06_07.skill-review-by/0.wish.md` — the goal
- `.behavior/v2026_06_07.skill-review-by/1.vision.yield.md` — the outcome world + vocab
- `.behavior/v2026_06_07.skill-review-by/3.3.1.blueprint.product.yield.md` — the product blueprint (types, codepath, tests)
- `.agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/**` — prod-code rules (grains, narrative, failloud)
- `.agent/repo=.this/role=any/briefs/rule.forbid.*.md` — repo-wide blockers (cwd-outside-gitroot, unbounded globs, stdout-on-exit)

## phase 0 — eject the shared `runOneReview` runner

**the foundation.** both usecases (guard + review.by) dispatch this one runner. eject it from the guard's inline `runOneStoneGuardReview` first, so the rest builds on a single execution path.

### pre-reads

- `.behavior/v2026_06_07.skill-review-by/3.1.3.research.internal.product.code.prod._.yield.md` — extant runner internals
- `src/domain.operations/route/guard/review/runStoneGuardReviews.ts` — the source of the eject
- `src/domain.operations/route/guard/review/getReviewCountsViaRegex.ts` + `getReviewCounts` cascade — the tally called inside
- `.agent/repo=ehmpathy/role=architect/briefs/practices/repo.structure/rule.prefer.most-common-denominator.md` — why it lands at `src/domain.operations/review/`
- `.agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/pitofsuccess.errors/rule.forbid.failhide.md` — the malfunction-promotion must stay failhide-safe

### deliverable

- `[→] src/domain.operations/review/runOneReview.ts` — shared runner (subprocess exec + capture + timeout + tally + malfunction-promotion)
- `[~] src/domain.operations/route/guard/review/runStoneGuardReviews.ts` — `runOneStoneGuardReview` now dispatches `runOneReview`, then wraps the result into its artifact
- `[+] src/domain.operations/review/runOneReview.integration.test.ts`

### acceptance

- guard behavior is unchanged — the extraction is a clean lift, not a rewrite
- `runOneReview` execs the review cmd as a subprocess, captures `{ stdout, stderr, exitCode }` on both success + error branches
- exit-0 with no numeric verdict → `malfunctioned` (never a fake 0/0)
- nonzero exit / timeout → surfaced as malfunction
- detected verdict → passed/rejected

### verify

```
rhx git.repo.test --what unit --scope 'name://runOneReview'
rhx git.repo.test --what integration --scope 'name://runOneReview'
# REGRESSION GATE — every guard snapshot must stay byte-identical:
rhx git.repo.test --what integration --scope 'name://runStoneGuardReviews'
```

the 30 committed `runStoneGuardReviews.integration.test.ts.snap` cases are the regression harness. any snapshot diff = the eject changed behavior = defect. no `--resnap` here.
