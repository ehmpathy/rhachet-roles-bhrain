# 🌙 dream: redact a brain-authored blocker count before it reaches a snapshot

**kind** = fix · **owner** = `ehmpathy/rhachet-roles-bhrain` · **caught** 2026-09-16

## .the cue that fired

an acceptance sweep failed one case in `blackbox/review.by.guard-peer.acceptance.test.ts`:

```
-  │   ├─ 1 blocker 🔴
+  │   ├─ 2 blockers 🔴
-    ├─ reason = blockers exceed threshold (1 > 0)
+    ├─ reason = blockers exceed threshold (2 > 0)
```

## .the gap, precisely

the count is authored by a peer-review brain, so it is probabilistic. the snapshot pins it as though
it were deterministic. three full sweeps measured it:

| sweep | the case that failed | the count |
|---|---|---|
| 2026-09-16 | `case-seam-findings`, attempt 1 | expected `1`, got `2` |
| 2026-09-17 | `case-seam-pass-aggregation`, attempt 1 | expected `0`, got `1` |
| 2026-09-17 | none — 3278 passed, 0 failed | — |

⇒ a different case each time, then a clean pass with no change to test or snapshot. a stale snapshot
fails every run; this one does not, so variance is the cause. the second row is the sharper one: a
case the fixture keeps clean, where the brain invented a blocker.

🟡 every case already sits under `when.repeatably(REPEATABLE_CONFIG)` (`:277`, `:322`, `:373`), and
that cannot rescue a snapshot: each attempt owns a distinct snapshot key (it carries `attempt 1`), so
a failed attempt's `toMatchSnapshot` stays a failed jest test under `criteria: 'SOME'`.

⇒ a green sweep is a draw, never a fix.

## .the shape of the fix

one move, at two sites — the count renders in the guard tree **and** in the captured peer's summary:

- `sanitizeGuardTreeForSnapshot` (`:51`) and `sanitizeCapturedPeerForSnapshot` (`:71`)
- redact `1 blocker 🔴` / `2 blockers 🔴` → `[N] blocker(s) 🔴`, and `(1 > 0)` → `([N] > 0)`
- keep the threshold literal — the `0` is the guard's declared bar and deterministic

both sanitizers already redact `[TIME]`, `[N]`, `[HASH]`; the brain's count was never added.

## .why it is not done in this round

| | verdict |
|---|---|
| **safe?** | 🔴 no — every guard-peer acceptance case renders through these sanitizers, so each snapshot re-baselines |
| **clean?** | 🔴 no — `review.by`'s acceptance surface shares no file with the `brain:` feature |

no fulcrum: the ripple is measured, and no call is reserved.

## 🔴 .the durable lesson

the second sweep was priced at ~37 minutes and judged not worth it, since *"the diagnosis does not
turn on it."* it returned three corrections: the variance confirmed, a `bare when(...)` claim struck,
and the second sanitizer found.

⇒ **a bound that says "the diagnosis does not turn on it" prices the conclusion, never the premises
the observation would also grade.**
