# 🌙 dream: `route.foreground.guard`'s stderr snapshot pins one `jq` version

- kind  = `fix`
- owner = this repo
- caught 2026-09-16

## .the cue that fired

a full `path://route` integration run during the i022 convergence returned **998 passed, 1
failed** — and the one failure is in a suite this branch never opens:

```
● route.foreground.guard › given: [case6] infrastructure failure paths (fail loud, not silent)
  › when: [t1] stdin is malformed json › then: stderr matches snapshot

- Snapshot  - 1
+ Received  + 1

- jq: parse error: Invalid literal at line 1, column 5
+ parse error: Invalid literal at line 1, column 5
    🗿 route.foreground guard: failed to parse tool_name from tool input json
```

⇒ the whole delta is the string `jq: `.

## .the gap, precisely

the snapshot captures **stderr verbatim**, and that stream carries the `jq` binary's own error
text. `jq` changed that text: older builds prefix a parse error with `jq: `, newer ones do not.

⇒ **the snapshot therefore asserts a property of the HOST's jq, never a property of the hook.**
the hook's own line — `🗿 route.foreground guard: failed to parse tool_name from tool input json`
— matches exactly, on both sides. the assertion under test passes; the assertion nobody meant to
make fails.

**this is not this branch's defect.** checked 2026-09-16:

| check | result |
|---|---|
| `git diff --stat HEAD -- src/contract/cli/` | empty — this branch touches none of it |
| `git log --oneline -3 -- '*route.foreground.guard*'` | last touched by `#399` and `#305` |
| the changes this round made | `src/domain.operations/route/brain/*` and `route/guard/getRepoRootWithFallback.ts` — neither is on the shell hook's path |

## .the shape of the fix

🔴 **do NOT `--resnap`.** that pins *this* host's jq and moves the failure to whichever host runs
the other version — the same defect with a different victim, and harder to diagnose the second
time.

the fix is to stop the assertion from reaching a third party's message text. in preference order:

1. 🔴 **assert on the hook's OWN line, never the whole stream.** the test's subject is
   `🗿 route.foreground guard: failed to parse tool_name from tool input json`. a snapshot of the
   full stderr claims ownership of text the hook did not author
2. **strip the foreign prefix before the snapshot** — `asHookStderr`, which drops a leading `jq: `
   from each line, with its reason in the header. cheaper, and it leaves the snapshot shape intact
3. **have the hook swallow jq's stderr** and emit only its own line. the strongest, and the widest
   ripple: it changes what an operator sees at a real terminal, which is a behavior call rather
   than a test fix

⇒ prefer **1**. a snapshot is a contract about **our** output; a third-party binary's wording is
not ours to pin (the same claim as
`.dream/v2026_09_16.reseed.git-repo-root-absence-has-no-sentinel.md`, one layer out).

🟡 and check the neighbours while there — any other snapshot that captures a raw stderr stream
with a third-party binary on it carries this same latent pin.

## .why it is not done in this round

- **SAFE?** ❌ — it changes a **hook** test whose subject is a driver-blocking shell guard. the
  stone under drive is `5.1.execution.from_vision` for the prescribed-brain feature; a hook-guard
  test change rides along under a diff nobody bound it to
- **CLEAN?** ❌ — option 1 rewrites the assertion shape and its snapshot; option 3 changes hook
  behavior. neither lands inside the diff this round already has

⇒ deferred, with the shape of the fix above, per
`rule.always.fix-forward-under-scouts-honor`. **no fulcrum is owed** — this is not a judgment call
this round made, it is a defect this round *found* in work it does not own.
