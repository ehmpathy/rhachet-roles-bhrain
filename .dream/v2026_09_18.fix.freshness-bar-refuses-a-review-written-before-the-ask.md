# 🌙 dream: the freshness bar refuses a review written BEFORE the ask

- kind  = fix
- owner = rhachet-roles-bhrain
- caught 2026-09-18

## .the cue that fired

two integration cases went red with a `challenge:stale` verdict nobody expected, and the emit
rendered this:

```
🍂 that review predates the ask
   ├─ a file is at the owed path, and it is older than the question
   │  ├─ written  = <an iso stamp, to the second>
   │  └─ asked at = <the SAME stamp, character for character>
```

🟡 the literal values are elided — the repo's pre-commit hook forbids a wall-clock stamp in a
committed artifact. what matters is that the two rendered **identically**.

**two identical stamps, offered as proof that one is older than the other.** the fixtures wrote the
articulation before they ran the ask, so the file genuinely predated the trigger by milliseconds.

## .the gap, precisely

the freshness bar is `articulationStat.mtime < report.sinceMtime`, measured against the **trigger's**
`.since` mtime — ruled that way deliberately, because the question it asks is *"was this written for
the review we asked for?"*

🔴 **and a second verdict from the same round made that question answerable "no" for an honest
driver.** the articulation path now keys on `(stone, slug)` — the level ordinal was dropped precisely
so the driver could **compute the path by hand from operands they already hold**.

⇒ so a driver may now legitimately: read the artifact, write their findings to the computable path,
**then** run `--as passed` — and be told their review is stale. the two decisions are individually
correct and interact badly.

**checkable evidence:** `getSelfReviewChallengeDecision.ts` — the stale branch compares against
`report.sinceMtime`; `getSelfReviewArticulationPath.ts` — the path takes `(route, stone, slug)` and
no ordinal, so it is computable before any ask exists.

## .the shape of the fix

three candidate directions, none obviously right — which is why this is a dream and not a fix:

1. **compare against the ARTIFACT, not the ask.** the bar would then mean *"your review is older
   than what it reviewed"*, which is the harm a stale review actually carries. ⚠️ this reverses an
   explicit verdict, so it is a wisher call, never a driver's
2. **grant a grace window.** a file written within N seconds *before* the ask counts as fresh. cheap,
   and it buys off the common case with no reversal. 🟡 it re-admits an un-defended number, which
   this round spent effort to remove elsewhere
3. **leave the behavior and repair the message.** the emit now detects the identical-render case and
   says *"you wrote it just before the guard asked — re-save the file and promise again"*, which
   names a one-step fix. **this is what shipped**, as the safe half

⇒ direction 3 is in place. the open question is whether 1 or 2 is owed on top of it.

## .why it is not done in this round

**safe?** no — 1 reverses a wisher verdict on what the bar measures, and 2 adds a threshold the round
deliberately dropped elsewhere. either is a scope decision, not a repair.

**clean?** no — the bar, the path key, and the ask's lifecycle are three decisions that would have to
move together.

⇒ so the message repair rode along (safe + clean), and the behavior question is caught here.
