# 🌙 dream: `rhachet roles boot` drops a run of brief tags when its stdout is a pipe

- kind: reseed
- owner: ehmpathy/rhachet
- caught 2026-10-22

## .the cue that fired

`blackbox/roles.boot.consumer-seat.acceptance.test.ts` captured each linked boot through
`child_process.exec`. on separate runs the parsed `<brief.say path=…>` list for one role
(driver one run, learner the next) held only its first 3–5 briefs. the `budget = N / M tokens`
stats line at the tail stayed intact and its payload stayed identical (driver 19,956, learner
20,691).

## .the gap, precisely

- the same boot, written to a file (`> boot.stdout.txt`) and read back, holds every declared brief,
  two runs in a row (15/15 pass)
- so the loss is in the pipe capture, mid-stream, never at the tail. the payload is computed
  before render, so it hides the loss
- a consumer that pipes the boot into a hook or a session reader may see a partial boot with
  no error

## .the shape of the fix

in rhachet's boot render, await the drain of `process.stdout` before exit (or write the boot
as one `write` call whose callback ends the process). clamp it with a test that pipes a boot
of ≥20k tokens through `exec` and asserts every declared say tag arrives.

## .why it is not done in this round

the render lives in `ehmpathy/rhachet`, a different repo. this route worked around it in its
own test with a file redirect (commented at the call site).
