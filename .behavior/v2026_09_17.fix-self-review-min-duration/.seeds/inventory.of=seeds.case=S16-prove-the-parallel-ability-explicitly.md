ask, because the round had been driven as though the first implied the second:

## 🔴 .what the ask exposed — the demo asserts the OUTCOME and never the MECHANISM

the check that `S16` forced, and the reason the ask was worth the send:

> **read every clause of `case=8` and ask: is it satisfied by eight lanes run one after another?**

| the clause | serial run |
|---|---|
| `[t0]` a trigger is minted for all 8 | ✅ satisfied — a hand-out property, with no concurrency in it |
| `[t1]` three lanes repair, no report is reset | ✅ satisfied — repair 3, then run the rest |
| `[t2]` all 8 promise **in any order**, all allowed | ✅ satisfied — *order-independence is not concurrency* |
| `[t2']` **one** challenge round trip, never 8 | ✅ satisfied — each lane takes one call either way |
| `[t3]` two lanes, one slug — idempotent | ✅ satisfied — two sequential promises of one slug |

⇒ 🔴 **every clause passes under a serial run, so the demo proves the fork is HARMLESS and never that
it is POSSIBLE.** the property the wish actually buys — a repair that lands **inside another lane's
open window** — is stated in the narrative and asserted in no `[tn]`.

⚠️ **and that is exactly the property the hash key forbade.** so the round demoed the consequence and
left the mechanism unpinned, which is how a verification stage discharges a parallel deliverable with
a sequential test and violates no clause written down.
