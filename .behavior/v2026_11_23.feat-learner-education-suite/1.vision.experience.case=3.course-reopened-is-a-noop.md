# case=3: a reopen is a no-op at the pursuit, a refusal at the course

inventory row: i4. feel: happy (pursuit), sharp (course). care: critipath (retries are common: a director re-runs a command whose output scrolled away).

## .narrative

the director runs `pursuit init` twice, an hour apart. the student has already edited `0.wish.md` to state the aim. the second run overwrites naught, and says so:

```
$ rhx education.pursuit init --for mechanic --course idempotency

🦉 the pond is still

📜 education.pursuit init
   ├─ route = .route/v2026_11_23.education.pursuit.mechanic.idempotency
   ├─ role = mechanic (native)
   ├─ courses seeded
   │  └─ (kept as 0.wish.md holds them; a re-run never rewrites the wish, edit it to change the seed)
   ├─ files = 0 created, 8 kept
   ├─ bound = this branch (kept)
   └─ next: naught new was written; resume with rhx route.drive
```

a course has no reopen. the stack holds one course at a time, and a course ends only by exit:

- `course init` while the branch is inside a course refuses: exit it first
- `course init` for a course that has exited refuses: it is done; a retake is a new pursuit
- the open-course findsert (same ordinal, files kept) serves only a bind that has come back to the pursuit while that course's dir still stands open

## .bdd sketch

```
given an open pursuit whose 0.wish.md the student edited
  when [t0] the director re-runs education.pursuit init with the same role + course
    then no file is written, and every file is reported kept
    then the edit in 0.wish.md survives
  when [t1] the driver runs education.pursuit.course init while inside a course
    then it refuses, and names exit
  when [t2] the driver runs education.pursuit.course init for a course that has exited
    then it refuses, and names the exit already recorded
```
