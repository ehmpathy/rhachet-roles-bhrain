# 🌙 dream: the review-scope acceptance tests count files the host leaks into their temp dir

kind: fix · owner: rhachet-roles-bhrain · caught 2026-10-23

## .the cue that fired

a resnap of `review.rules-only-default` and `review.join-intersect` on one rhachet pin read
`targets: 10` / `11` on the dev box, while ci on the same commit and pin read `8` / `9`. the dev box
resnap was first misread as a pin change and pinned the host's counts into the snaps.

## .the gap, precisely

- both suites clone a fixture into a temp dir, run `npx rhachet roles link --role reviewer` there,
  then run a `--diffs since-main` review and snapshot `metrics.expected`
- on a host whose session runs under a rhachet actor dir (`.agent/.actors/actor.via.repo=…`), the
  since-main scope holds two more untracked files than on a clean runner
- the likely pair: the actor's `settings.of.grove.json` / `settings.of.repo.json`, which the same
  host also rewrites in this repo's own tree. not confirmed: the env read that would name the
  variable is not paved in this seat
- ⇒ the suites are not hermetic: their snapshot depends on the host's env

## .the shape of the fix

1. run the temp-dir `roles link` under an env scrubbed of actor and claude config vars (the
   harness in `blackbox/.test/invokeRouteSkill.ts` `execAsync` / `genTempDirForRhachet`)
2. or exclude the actor settings paths from the fixture's since-main scope
3. clamp: run the two suites with the actor env set; red before, green after

## .why it is not done in this round

not clean: the variable is unconfirmed from this seat, and a scrub in the shared harness touches
every acceptance suite that spawns `rhachet`. this round restored both snaps to main's bytes, which
ci confirms.
