# 🌙 dream: rhachet's hook dispatcher lands an `onTool` hook declared `when: 'after'` under PreToolUse

- kind: reseed
- owner: rhachet (ehmpathy/rhachet)
- caught 2026-11-24

## .the cue that fired

the skeptic role's hook map wants `skeptic.notice --when hook.afterTool` on PostToolUse. the declaration is
`onTool` with `filter.when: 'after'`, and a read of where that lands showed it never reaches PostToolUse.

## .the gap, precisely

- `rhachet@1.54.1` `dist/domain.operations/brains/dispatch/constants.js` maps `onTool: 'PreToolUse'` with the note
  "`filter.when: 'after'` still lands under PreToolUse, as the adapter places it today"
- the direct adapter `_topublish/rhachet-brains-anthropic/src/hooks/translateHook.js:54-58` does place `'after'` on
  PostToolUse, so the two paths disagree
- a repo synced through the dispatcher (`settings.of.repo.json` registers `hooks.dispatch.sh … PreToolUse`, no
  PostToolUse entry) runs an after-hook before the tool, where the payload holds no `tool_response`
- the hook costs a process per tool call and cannot see what it was declared to read; no error says so

## .the shape of the fix

- the dispatcher registers a PostToolUse entry when any manifest rule holds `when: 'after'`, and routes that rule
  there; `CLAUDE_EVENT_OF_BRAIN_HOOK_EVENT` gains the split, or the sync derives the event from `when`
- a sync that cannot place a declared `when` fails loud, never files it under the other event
- a clamp: a role with one `after` rule syncs to a settings file with a PostToolUse dispatcher entry, and a
  PostToolUse payload reaches the rule with its `tool_response`

## .why it is not done in this round

the fix is rhachet's dispatcher and its sync, in another repo. this role holds the hook back (F26) and ships
the skill and its suite, so the hook is one entry away once rhachet routes it.
