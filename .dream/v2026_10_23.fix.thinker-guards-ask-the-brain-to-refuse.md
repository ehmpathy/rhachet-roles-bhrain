# 🌙 dream: the thinker steps ask a brain to refuse input that code could reject

kind: fix · owner: rhachet-roles-bhrain · caught 2026-10-23

## .the cue that fired

`stepDiverge` (statement goal) and `stepTriage` (one element) each expect `BadRequestError` in
their output. on ci and on the dev box, the brain answered the input instead, about one call in
six: a list of jokes where the refusal was asked for.

## .the gap, precisely

- the refusal lives only in the prompt: `stepDiverge.template.md` says *"if the input was a
  statement, then simply output BadRequestError"*; triage, cluster, and demonstrate ask the same
  of one element or an empty input
- each precondition is deterministic: an empty input, one element, a goal with no `?`
- ⇒ a deterministic check is delegated to a probabilistic step, so the step refuses only most of
  the time

## .the shape of the fix

1. per step, check the precondition in code before the brain is called, and write
   `BadRequestError: <why>` to the output artifact (or throw `BadRequestError`)
2. drop the refusal clause from each template
3. the BadRequestError cases then need no brain and no `when.repeatably`; clamp each as a test
   that runs with no brain context

## .why it is not done in this round

not clean: it changes thinker product behavior in four steps and their templates, in a pr whose
scope is the boot budgets. this round wrapped the seven suites it un-skipped in
`when.repeatably(REPEATABLY_CONFIG)`, per `rule.require.repeatable-for-llm-tests`.
