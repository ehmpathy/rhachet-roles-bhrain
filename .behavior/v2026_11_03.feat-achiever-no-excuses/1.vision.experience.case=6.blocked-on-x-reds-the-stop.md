# case 6 — "blocked on X" reds the stop (clamp 2)

feel: sharp · care: critipath · actor: achiever · seams: store, stop hook

## .narrative

the achiever hits a wall and writes the old shape: status blocked, reason "waits on the human for the
api key". today that is a clean exit: the extant onStop halt even suggests it ("if blocked, run
--status.choice blocked"), and a blocked goal releases the halt.

with this role, the set itself refuses a blocked status with no cure, and the stop refuses a blocked
goal that carries none. the refusal names the three cures. the achiever tries the first: it reads the
key's error, finds `rhx keyrack unlock`, and the "wall" is gone. no turn ended on an excuse.

## .[tn] — a sketch

```
given  an inflight goal
when   [t0] rhx goal.memory.set --slug x --status.choice blocked --status.reason 'waits on the human'
then     the set exits 2:
           ✋ ConstraintError: a blocker owes a cure, not a reason
              ├─ run it:       cure it now, then close the goal by its done check
              ├─ dispatch it:  --cure.via dispatch --cure.ref <task> --cure.await <minutes>
              └─ above charter: --cure.via charter --cure.act '<the one command>' --cure.who <who may run it>
when   [t1] a legacy goal on disk is blocked with no cure (set before this role), and the achiever stops
then     goal.triage.next --when hook.onStop exits 2 and shows the same three cures
```

## .the clamp

an integration test writes a blocked goal with no cure, runs the onStop hook, and expects exit 2.
revert the cure check → green → the test must fail red under the revert.
