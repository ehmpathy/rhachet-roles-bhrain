# 🌙 dream: the seat boot clamp copies test files a seat never ships

kind: fix · owner: bhrain/role=any (roleBootClamps) · caught 2026-10-26

## .the cue that fired

a new colocated skill test, `driver/skills/route.status.line.integration.test.ts`, moved the
driver's pinned seat payload from 9936 to 9957 tokens (budget 10000), though the skill itself is
listed under `skills: not:` and a real boot no longer names it.

## .the gap, precisely

`getOneBootEmittedAsSeat` (`src/domain.roles/roleBootClamps.integration.test.ts`) copies the role's
src dir with a filter that drops git-ignored paths only. the dist build (`build:complete:dist`)
also drops `*.test.*` and keeps no `__snapshots__` outside `briefs/`, `skills/`, `inits/`. so the
clamp's `<also>` list holds `*.integration.test.ts` paths a seat never receives, and every role
that keeps a test beside its skills (driver: `route.foreground.guard`, `route.mutate.guard`,
`route.status.line`) pays tokens in the clamp it does not pay in a seat.

## .the shape of the fix

filter the seat copy by the same rules the dist rsync applies (exclude `*.test.*`, `.test/`,
`.route/`, `.scratch/`, `.behavior/`), ideally from one shared list both read. then resnap every
role's seat pin, and re-derive each `boot.yml` budget as the least multiple of 250 above its new
payload.

## .why it is not done in this round

it is safe but not clean: every role's pin moves, and any budget whose payload drops below a 250
step must be re-derived, a ripple across nine boot specs unrelated to the status line.
