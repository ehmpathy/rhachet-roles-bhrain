# 🌙 dream: repair the 142 guard globs that expand to no file

- kind = fix
- owner = rhachet-roles-bhrain
- caught 2026-09-19

## .the cue that fired

`rhx review.corpus` was built to measure what review prompts are MADE of. on its first walk of
every `.behavior/**/*.guard` in the tree it crashed outright on
`.agent/repo=ehmpathy/role=mechanic/briefs/practices/code.test/pitofsuccess.errors/rule.forbid.remote-boundaries.md`
— a path a guard cites and no file answers.

the crash was the cue. rather than let one bad citation void a 648-lane study, the study
recorded a glob that matches no file as **broken** and carried the count beside its totals
(`rule.forbid.failhide` — a zero and an absence are different facts).

the count came back **142**.

## 🔴 .re-homed 2026-09-21 — the detector that found this is DELETED

`rhx review.corpus` was struck (`F3`): it estimated the prompt from declared guard globs where
the renderer decides what is sent, so its cost figures drifted. **the cost study was the reason
it existed; `broken globs` was a passenger** — a guard-lint concern that rode along only because
that tool happened to resolve globs.

⇒ so this dream **inherits the whole concern, detector included**. what changes:

| was | now |
|---|---|
| detected as a side effect of a cost study | owed its own **guard lint** — the concern is rubric integrity, never chars |
| enumerable via `ReviewLaneCorpus.globsBroken` | 🔴 **no surface enumerates them.** the field went with the tool |
| reproducible via the corpus integration test | 🔴 **not reproducible.** the 142 is now a dated figure |

🟡 **the count is unverified since 2026-09-19 and cannot be re-taken until the lint exists.**
treat `142` as dated, never current — it is the evidence that the concern is real and worth a
lint, and it is not a work item you can check off against.

## .the gap, precisely

a lane declares its rubric as a glob:

```
--rules '.agent/repo=ehmpathy/.../pitofsuccess.errors/rule.forbid.remote-boundaries.md'
```

that file does not exist. it was renamed — the extant rule is
`code.test/scope.unit/rule.forbid.unit.remote-boundaries.md` — and the guards that cite the old
path were never updated.

🔴 **a rubric glob that matches no file means the lane grades against a rule it never loads.**
`rhx review` does not fail on it; the rubric is simply thinner than the guard claims, and the
lane returns a verdict that reads exactly like a real one. the defect is silent by construction.

### checkable evidence — 🔴 DATED, and no longer re-runnable

measured 2026-09-19 over 67 trees / 648 lanes, from the corpus report's own line:

```
├─ broken globs: 142  (a lane cites a path no file answers)
```

`ReviewLaneCorpus.globsBroken` carried the offending glob per lane, so the 142 were enumerable
by behavior, stone, and slug — not merely counted.

🔴 **both the field and the command are deleted**, so this evidence cannot be reproduced today.
the one claim that survives independent of the tool is the **mechanism**, and it is checkable by
hand against any single guard:

```sh
# the extant rule; the path 142 lanes cite does not exist
rhx globsafe --pattern '.agent/**/scope.unit/rule.forbid.unit.remote-boundaries.md'
rhx globsafe --pattern '.agent/**/pitofsuccess.errors/rule.forbid.remote-boundaries.md'
```

⇒ the first returns a file; the second returns none. **a lane that cites the second grades
against a rule it never loads**, and that is true whether or not any tool counts it.

## .the shape of the fix

0. 🔴 **rebuild the detector, as a guard lint.** this step did not exist before 2026-09-21 and is
   now the first one: a `rhx guard.lint` that walks `.behavior/**/*.guard`, resolves each lane's
   `--rules` glob, and prints the `behavior / stone / slug / glob` rows that match no file.
   ⇒ it is **cheaper than what it replaces** — it resolves rules globs only, where the corpus
   tool resolved every target and summed chars. and it cannot drift the way the corpus did: a
   glob either matches a file or it does not, so there is no renderer decision to re-derive.
1. **enumerate them by lane**, off that lint's output — rather than make a reader re-derive them
   from an aggregate, which is what the deleted tool forced.
2. **sort them into three kinds, because the repair differs per kind:**
   - a **rename** — the rule moved (the `remote-boundaries` case). repoint the glob
   - a **deletion** — the rule is gone. drop the glob, and check the lane still has a rubric
   - a **brace defect** — `'**/*.{ts,md}'` in an extension slot is silently dropped by
     `parseReviewArgs` (`.dream/v2026_09_04.fix.review-multi-glob-flags-do-not-comma-split.md`).
     a glob that reads correct and matches no file belongs to that dream, not this one
3. **repair only the LIVE trees.** most of the 67 behaviors are finished routes whose guards will
   never run again — a repair there is churn. the live ones are what matter.
4. 🔴 **then add the clamp**, which is the durable half: `--optional rules` already exists for a
   lane that legitimately has no rubric, so a lane WITHOUT that flag whose rules glob matches no
   file should be a **malfunction**, not a silent thin review. that is a one-line check in
   `runOneReview` and it is what stops the 143rd.

## .why it is not done in this round

**SAFE — no.** step 4 changes when a lane malfunctions. any lane in the repo whose rubric glob is
currently broken would begin to halt its stone rather than return a verdict. that is the correct
behavior and it is a behavior change with a blast radius I cannot see the edge of from here —
possibly many of the 142.

**CLEAN — no.** the repair touches guard files across up to 67 behavior dirs, none of which this
branch opened. this branch's diff is the review meter and the corpus study; a sweep of historical
guards would ripple far past it.

⇒ both questions answer no, so it is caught rather than ridden along
(`rule.always.fix-forward-under-scouts-honor`).

🟡 **and note the direction of the fix: it RAISES token cost.** these lanes are cheap today
precisely because they load rubrics they were never given. the repair buys correctness and spends
tokens — which is why it sits outside the cost-reduction levers in
`research.review-cost-and-cache` rather than among them.

🔴 **step 0 is now the blocker on every other step**, and that is a real regression in this
dream's readiness: before 2026-09-21 the enumeration existed and only the repair was owed; now
the detector is owed first. **that cost is charged to the `F3` deletion and named here so it is
not lost** — a concern re-homed without its detector is a concern quietly downgraded.
