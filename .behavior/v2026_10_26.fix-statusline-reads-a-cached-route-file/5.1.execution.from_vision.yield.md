| arm | cpu per repaint |
|---|---|

⇒ the reader costs ~18× less cpu than the node line it replaces, and spawns zero node processes.

## caveats

- `BASH_ENV=` in the command carries real weight: a host rc sourced per repaint cost ~57ms here
- the `.route/` dir is sealed to direct reads by the mutate guard; the reader reads it as a process, which the guard does not see
- the node entry stays (F5): seats whose settings predate this change run it until their next `rhx init`; its acceptance suite still covers it
- F7's settle loop is clamped by an injected interleave (writer cases 6 and 7): with the re-render cut, four cases go red
- the driver boot excludes the colocated skill tests and snapshots (`boot.yml` `skills.not`); the general seat-clamp gap for other roles stays a dream, `dreams/v2026_10_26.fix.role-boot-seat-clamp-counts-test-files.md`
- the heal the stale and unknown lines name is `rhx route.drive`, which also applies the stone's brain and syncs the reminder daemon; the onStop hook already runs it each turn, so no refresh-only command was added
- a git rewrite of a tracked ledger reads stale until that next drive (inventory case 31, an accepted blind spot)
- bash 3.2 rests on the builtin list in the reader header, never a run on bash 3.2: caught as a dream, `dreams/v2026_10_26.test.status-line-reader-on-bash-3-2.md`

## divergences from the wish, for the commander

- the wish names a `status` field; the file holds `phase`, the word the line already renders (arrived, blocked, yield, …). same fact, the render's own term
- the wish names "when it was written"; the file holds no timestamp (`rule.forbid.timestamps-in-route-artifacts`). the file's mtime stands in, and the stale test reads it
- the wish says "at most once a minute"; `refreshInterval: 60` adds an idle repaint each minute and caps naught. the reader still runs on each assistant message. what the change bounds is the cost of a repaint (one bash, zero spawns), not how often one fires
