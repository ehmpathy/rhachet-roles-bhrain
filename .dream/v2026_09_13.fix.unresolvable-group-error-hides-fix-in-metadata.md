# 🌙 dream: the unresolvable-group throw names its repair only in metadata, so the one hand-built surface that reaches it never reads the fix

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-13

## .the cue that fired

peer review i020/r009 (`ergo-friction-hazards`), nitpick.1, in the reviewer's own words:

> the `runWithinConcurrencyBounds` throw for an unresolvable concurrency group names its
> repair — *"declare it under reviews.groups.<name>.concurrency"* — only in the error's
> metadata bag, not in its human message. a driver who meets it reads a bare
> *"group not found"* sentence and must open the metadata to learn the fix.

the reviewer graded it a nitpick, and named why: *"the reach is normally parse-guarded
(`assertConcurrencyGroupsResolve` refuses the same shape first), so it fires only for a
guard built by hand around the parser."*

## .the gap, precisely

`runWithinConcurrencyBounds` throws when a reviewer names a `group:` that has no entry
under `groups:`. the throw carries the fix in its metadata object, never in the message
string a human reads first.

the reach is normally unreachable — `assertConcurrencyGroupsResolve` refuses the same
shape at parse, before a subprocess exists. so the throw is a fallback surface that fires
only for a guard hand-built around the parser (a test harness, or a caller that constructs
a `RouteStoneGuard` directly rather than through `parseStoneGuard`).

**checkable evidence:** the throw's message string does not contain the text
`reviews.groups`, while its metadata does. a driver who meets the fallback reads the
symptom and not the cure — a `rule.require.errors-name-the-fix` gap on the one path that
reaches it.

## .why it is not done in this round

- **SAFE:** yes — the edit folds a metadata string into the message string; it changes no
  control flow and no verdict.
- **CLEAN:** the edit lands in `src` → churns the artifact hash → re-runs every l1 lane
  fresh (non-deterministic), and this round already carries that churn from three real
  blocker repairs.
- **the harm is bounded to a hand-built surface:** a real driver drives through
  `parseStoneGuard`, which refuses the shape at parse with a message that already names
  the fix. so the fallback throw is met only by a caller that bypassed the parser — a
  tripwire, never a live driver path.

## .the shape of the fix

fold the `declare it under reviews.groups.<name>.concurrency` hint from the metadata bag
into the human message string of the `runWithinConcurrencyBounds` throw, so the one
hand-built surface that reaches it reads the fix in the sentence rather than in the
metadata. keep the metadata too — the message gains the hint, the bag does not lose it.
