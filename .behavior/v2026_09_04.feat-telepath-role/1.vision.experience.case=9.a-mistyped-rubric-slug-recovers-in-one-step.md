## .why an alterpath earns a demo here

this is the only alterpath demoed — 1 of the 29 alterpaths across the full 576-product, of which the other 28 are itemized. and it is not demoed for coverage. **it is demoed to isolate the care axis.**

🟡 the line read *"out of 27 itemized"* until `i011`, and that figure was two errors at once: `27` is the alter total of the *base walk* rather than of the product, and it counts this demo among the itemized rather than beside them. the reconciled arithmetic is in the inventory's `.the coverage claim` — 27 alter in the walk (26 📋 + this one) + 1 in `cached` + 1 in `taken` = 29 total, 28 itemized.

per `define.experience._.demo.surf-school`, the four quadrants are proven independent by held-constant pairs — hold one axis fixed, and the other must still vary. without a single alterpath demo, the care axis is asserted by the catalog and demonstrated nowhere.

| held constant | the pair | what varies |
|---|---|---|
| `feel = sharp` | 🎬 case=5 vs 🎬 case=9 | care: the canon is absent and the reviewer dead-ends (criti) vs the slug is mistyped and the engine names the valid set (alter) |

⇒ both actors hit a rejection edge on the same mechanism, one step apart in one session:

- the feel is identical
- only the fallback differs
- ⇒ and that difference is the whole care axis

## .the narrative

an adopter has enrolled telepath and wired the reviewer. they declare it on a stone, and they type the slug from memory:

```sh
rhx review.by --role telepath --for prose-densty
```

the reviewer does not run. the base engine answers:

```
✋ no rubric "prose-densty" for role telepath

   valid rubrics:
   └─ prose-density

   declared at:
   └─ .agent/repo=bhrain/role=telepath/briefs/reviews/rubrics.yml
```

the adopter reads the one valid slug, fixes the typo, and re-runs. **the reviewer runs on the second attempt, in the same minute.**

## .why this is an ALTERPATH, and case=5 is not

the one test: *if this path broke, would a core usecase fail, or is there a workable fallback?*

| | `case=5` — canon absent | `case=9` — slug mistyped |
|---|---|---|
| the edge | the rules glob matches zero files | the rubric slug matches no declared rubric |
| **if the good message broke** | the adopter sees a bare failure and **cannot know the canon must be enrolled** — the wire-in dead-ends, and `--optional rules` sits right there as a false cure | the adopter still knows they typed a slug; a bare *"no such rubric"* leaves **retype it** as an obvious recovery |
| the fallback | **none** — hence critipath | **retype** — hence alterpath |
| its absence in this vision | a **blocker** | a **nitpick** |

🟡 **the enumerate rule warns against exactly the assumption that would flip this**: *"do not assume the plainer default is critical."* a mistyped slug **feels** more like an everyday defect than an absent canon, and it is the less critical of the two — because a typo carries its own diagnosis and an absent dependency does not.

## .the fail-safe it does NOT owe, and meets anyway

🟡 the canon exempts this. `define.experience` is explicit: *"an alterpath needs no fail-safe proof — a surface demo that names it is enough."* so the grade below is volunteered, never obliged.

⇒ **it is graded because the experience rule and the ergonomist rule disagree on what this cell owes, and the stricter one is cheap to satisfy** — a rejection that omits the valid options is an ergonomic defect in its own right (`rule.require.errors-name-the-fix`, a blocker there) whatever its care.

| obligation | met | how |
|---|---|---|
| fast | yes | rejected at slug lookup, before any rubric is read or any file globbed |
| loud | yes | non-zero exit; no `0 blockers / 0 nitpicks` is ever printed |
| teaches the fix | yes | names the valid set and the file where it is declared |

🟡 the third row is the one that matters, and it is not free:

- an error that says *"invalid rubric"* and stops satisfies fast and loud
  - and it leaves the adopter to hunt for the rubrics file
- ⇒ per ergonomist `rule.require.errors-name-the-fix`, a rejection that omits the valid options is a blocker in its own right

⇒ so the alterpath's *demo* is a bonus; the quality of its message is not.

## .the bdd timeline

```
given [case9] a repo with telepath enrolled and its canon present
  and  a rubrics.yml that declares exactly one slug

when  [t0] the adopter invokes a rubric slug that is not declared
then       the reviewer exits non-zero and renders NO numeric verdict
 and       it does not print `0 blockers`
 and       it rejects before it reads any rule file

when  [t1] the rejection is printed
then       it names the invalid slug back to the adopter
 and       it lists every valid slug for that role
 and       it names the file where the valid set is declared

when  [t2] the adopter corrects the slug and re-runs
then       the reviewer runs and renders a numeric verdict
 and       no state from the failed attempt persists

when  [t3] the base engine gains a second telepath rubric
then       the valid set in the message grows with it
 and       no telepath-owned code changes
```

## .what this cell demands of the design

| demand | why |
|---|---|
| the valid-slug list comes from `rubrics.yml`, never a hardcoded list | `[t3]` — a second rubric must not need a code change to appear in the error |
| a bad slug **never** renders `0/0` | it is the same INV-1/2/6 hazard from a different entry point: an unrun reviewer must not read as clean |
| telepath owns **no** code for this | the base engine already parses the slug. this cell is a **check that extant behavior suffices**, not a build |

⇒ **that last row is why this demo is cheap.** `case=7`'s bill is two files and zero logic, and this cell tests that claim at a boundary: an adopter's typo must be handled by machinery telepath does not own.
