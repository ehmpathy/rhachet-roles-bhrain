# 🌙 dream: eight llm suites are skipped and no gate counts them

- kind: fix
- owner: `rhachet-roles-bhrain`
- caught: 2026-09-23

## .the cue that fired

the `5.3.verification` stone's letter is absolute: **zero skips**. a grep for
`\.skip|\.only|xit\(|xdescribe\(|todo\(` across `src/` and `blackbox/` returned **15 hits**, and
the classification of those 15 is what fired this dream:

| class | count | disposition |
|---|---|---|
| excluded by jest config (`.scratch/**`) | 2 | not live — `jest.integration.config.ts:29-34` never matches them |
| complementary-predicate pairs (`runIf`/`skipIf` over one condition) | 2 | not a skip — one of the pair always runs |
| grep false positives (the literal word in prose) | 2 | not a skip |
| 🔴 **genuine deferrals** | **8** | **the subject of this dream** |

⇒ **13 of 15 are innocent and the tooling cannot tell you that.** the only instrument this repo has
for the stone's mandate is a grep, and a grep over-reports by 62% here. so a driver who runs it
either investigates all 15 by hand, or trusts the number and reports a defect that is mostly noise.

## .the gap, precisely

the eight live skips share one shape: **an llm-backed suite, deferred because the brain call is slow,
costly, or non-deterministic.** they sit outside the role this round touched, and each was authored
by a different traveler for a reason that was true at the time.

🔴 **and the runner puts a number on it the grep cannot.** the integration run reports the toll
directly, and it is larger than the file count suggests:

```
rhx git.repo.test --what integration --mode apply
   └─ tests: 1185 passed, 0 failed, 63 skipped     # 2026-09-23
```

⇒ **63 skipped tests**, not eight. the eight are *suites*; each carries several cases. so the grep
under-states the toll by roughly 8× at the same moment it over-states the hit count by 62% — **the
one instrument available is wrong in both directions at once**, and a reader who trusts either number
gets a different wrong answer.

🟡 **the runner's `skipped` field is the honest count and no gate reads it.** it is printed on every
integration run, by a skill this repo owns, and discarded. ⇒ that is the cheapest possible source for
part 2 below — no grep, no classification, no false positives.

the checkable evidence:

```
rhx grepsafe --pattern '\.skip|\.only|xit\(|xdescribe\(' --path src --glob '*.test.ts'
rhx grepsafe --pattern '\.skip|\.only|xit\(|xdescribe\(' --path blackbox --glob '*.test.ts'
```

and the config that exonerates two of them:

```ts
// jest.integration.config.ts:29-34
testMatch: [
  '**/*.integration.test.ts',
  '!**/.yalc/**',
  '!**/.scratch/**',   // ← the two `.only` hits live here; they can never run
  '!**/.agent/**',
],
```

🔴 **and the sharper half: no gate counts any of this.** there is no lint rule, no ci step, and no
guard that tallies skipped suites. the count is knowable only by a hand grep whose output must then
be hand-classified. ⇒ **a skip added tomorrow is invisible to every instrument in the repo**, which
is how eight of them accumulated without a single round raising it.

## .the shape of the fix

two parts, and the second is the one that pays:

1. **resolve the eight** — each is an llm suite, so each wants one of: a `when.repeatably`
   conversion (`rule.require.repeatable-for-llm-tests` already names the pattern), a move to a
   `test:llm` scope run on a schedule rather than per-commit, or a deletion where the subject is gone.

2. 🔴 **give the count a gate — and take it from the RUNNER, not from a grep.** `git.repo.test`
   already computes `skipped` and prints it; the repair is to surface it as a readable field and let
   a guard assert `skipped == 0`. then a verification stone has a machine answer, and a new skip costs
   a conversation rather than a silence.

   ⇒ **this is strictly better than the `rhx test.skips.get` grep-plus-filter shape** the first draft
   of this dream proposed: the runner counts what actually ran, so it has no false positives to
   classify and no config exclusions to re-derive. **a skill that re-implements what the runner
   already knows is a second source for one fact**, which is the defect this round spent four repairs
   on elsewhere.

⇒ **part 2 is what makes part 1 stay fixed.** resolve the eight with no counter and the ninth lands
next quarter with nobody the wiser — which is exactly the history this dream records.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), answered honestly:

| question | answer |
|---|---|
| **is it SAFE?** | 🔴 **no.** the eight suites belong to roles this round never opened. a conversion to `when.repeatably` changes what those suites assert and how long they take; a deletion changes coverage for a subject this drive has not read |
| **is it CLEAN?** | 🔴 **no.** it ripples into files, roles, and a ci scope the diff never intended to touch — plus a new skill for part 2 |

both fail, so the deferral is legitimate. ⚠️ **and a deferral for DIRT owes a fulcrum beside this
dream** — the ripple estimate above is a judgment, and a judgment made alone is what a fulcrum list
exists to surface.

⇒ the one genuine tension worth the council's eye: **the verification stone's letter says "REMOVE
the skip, no exceptions"**, and `rule.always.fix-forward-under-scouts-honor` says a change that
ripples into an untouched role is a smuggled refactor. the drive takes the second and hands the call
up rather than deciding it quietly.

⚠️ the eight are not "blocked on a dated, external dependency" — they are each resolvable today by
someone who owns that role. what blocks them is scope, and scope is not one of the two questions.
**that is precisely why this is a dream rather than a fix**: the work is real, the owner is not this
drive, and the record is what carries it to them.
