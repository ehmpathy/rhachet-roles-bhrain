# case=10 · the route heal lands in the repo layer

coordinates: N=permissions-route · L=split · I=human · T=absent-key · feel=happy · care=critipath

## .narrative

`rhx init --roles driver` runs two inits. the second, `init.claude.permissions.route`, strips the
`.route/**` deny from the driver's permissions and allows the driver's own workspace, so a clone
can add a stone, emit a yield, or archive a seed. before this tree it wrote `.claude/settings.json`,
the same name rhachet reserves for a link: the heal was replaced by the arrow on the next layout
pass, and every run healed again. it also exited 1 on a dangled grove arrow, which red-marked
`rhx upgrade` for the human.

the heal now picks its target by layout, as the status-line init does. in the split layout it
heals `settings.of.repo.json`, leaves `settings.json` an arrow, and reports `status = healed`; a
rerun reports `already healed`. a link, a malformed or non-object target, or an absent owned
config each warn with the fix and exit 0 (`status = not healed`).

## .bdd

```
given a split layout whose settings.of.repo.json denies Write(**/.route/**)
  when [t0] the init runs
    then exit 0
    then settings.of.repo.json drops the owned deny and allows Edit(.route/**), Write(.route/**)
    then settings.json is still an arrow
    then stdout says status = healed, names the file, and names the guard that still protects passed stones
  when [t1] the init runs again
    then status = already healed, no backup written

given a target that is a link, malformed, or a json array
  when [t0] the init runs
    then exit 0, no write, status = not healed, and the fix is named

given the owned-permissions config is absent
  when [t0] the init runs
    then exit 0, no `.claude` created, status = not healed, fix: reinstall the package
```

tests: `init.claude.permissions.route.integration.test.ts` `[case1]` to `[case6]`, every tree snapped;
through the real cli, `survives-layout` `[case4]` `[case5]` (the framed block names the heal beside the bind).
