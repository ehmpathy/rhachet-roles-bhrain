# 🌙 dream: the captured-peer sanitizer carves out telemetry subtrees rather than masks them

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-05, at `5.3.verification` i017 — by the **scoped re-run** of the
  `ergo-contract-snapshots` lane, after the bound lane overflowed and rendered no verdict

## .the cue that fired

`rule.require.contract-snapshot-exhaustiveness` states: *"non-deterministic outputs are MASKED,
then snapped live — never carved out."*

`sanitizeCapturedPeerForSnapshot` in `blackbox/review.by.guard-peer.acceptance.test.ts` **carves**:
it skips from any telemetry header (`🔭 metrics.expected`, `🪵 logs`, `✨ metrics.realized`) to the
next verdict header, and drops the `├─ logs:` child line outright.

```ts
if (/(🔭 metrics|🪵 logs|✨ metrics)/.test(line)) {
  skipTelemetry = true;
  continue;
}
...
if (/├─ logs:/.test(line)) continue;
```

## .the gap, precisely

a **mask** keeps the deterministic structure and replaces only the volatile bytes:

```
🔭 metrics.expected          ← the header survives, so its absence would be a diff
   ├─ tokens: <masked>
   └─ cost: <masked>
```

a **carve-out** removes the whole family, so drift *inside* those regions is invisible to a PR
reviewer — and so is their **disappearance**. if the emitter stopped printing `🪵 logs` entirely,
the snapshot would not move.

⚠️ the reviewer's own qualifier is kept: it is **extant, not authored here**, and the newly-added
comment in this branch defends only the empty-`stderr` drop (which is engine normalization, and
sound). the carve-out predates the branch; the new comment merely sits beside it.

## .the shape of the fix

1. in `sanitizeCapturedPeerForSnapshot`, replace the skip-to-next-header behaviour with a
   per-line mask: keep the header and the child keys, substitute the volatile values
   (`<tokens>`, `<cost>`, `<ms>`, `<logpath>`)
2. resnap `blackbox/__snapshots__/review.by.guard-peer.acceptance.test.ts.snap`
3. eyeball the result — the point of the change is that the structure becomes legible, so the
   snapshot must read better afterward, never merely differently

## .why it is not done in this round

**safe? yes. clean? no — and it is credential-blocked besides.**

| the check | the answer |
|---|---|
| safe | yes — a sanitizer used by one suite |
| clean | 🔴 no — a resnap of a brain-driven acceptance suite |
| runnable here | 🔴 **no.** `jest.acceptance.env.ts:63` sources the keyrack in `strict` mode and demands five brain keys. `rhx keyrack status --owner ehmpath` holds only `@all.camp.GITHUB_TOKEN` |

⇒ **a resnap I cannot run is a snapshot I would have to write by hand**, which is the exact
failure `rule.forbid.failhide` names — an artifact that asserts an output nobody observed. so the
fix waits for the credentials, and the reason is on record rather than a silence.
