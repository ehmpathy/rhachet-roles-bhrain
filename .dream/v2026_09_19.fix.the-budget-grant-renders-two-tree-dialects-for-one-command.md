## .the gap, precisely

one command, two visual dialects, both snapshot-visible:

```text
// REFUSED — no spacer between the head rows and the refusal row
   ├─ peer = mock-reviewer
   ├─ refused — a grant needs a live urgent concession on the last round
   │  ├─ mock-reviewer = 0/2 rounds spent — 2 left

// GRANTED — blank `│` spacers part the logical groups
   ├─ peer = mock-reviewer
   │
   ├─ ✅ granted — earned by a live urgent concession
   │  └─ mock-reviewer · conceded urgent
   │
   ├─ 🟡 your human is warned this PR that an urgent concession earned this round
   │
   └─ updates
      └─ mock-reviewer: 2 → 4
```

🔴 **the sharp part: the shared head builder's docblock claims otherwise.**
`asGuardBudgetHeadLines` states the blank row is handled *"on both paths"* — and it is not. the
divergence lives in the two **tails**: `asBudgetGrantWarrantLines` opens with a `   │` spacer;
`formatBudgetGrantRefusalLines` appends `   ├─ refused — …` directly.

⇒ so a comment asserts a property the code does not have — the same shape
`rule.require.timeless-comments` forbids, and a reader who trusts the docblock will not look.

**who it costs:** a driver meets these back to back — refused, then converge, then granted. one tree
breathes at its logical groups and one does not, which is the *"consistent indentation / logical
groups"* blemish `rule.forbid.snapshot-visual-blemishes` names by title.

## .the shape of the fix

**one line, and the reviewer named it exactly:**

> *"align the refusal tail to open with the same `   │` spacer, or drop the spacer from the granted
> tail, so one command renders one tree style."*

**best guess = align the refusal up.** the granted tail's spacers are the correct shape — the
refusal carries three kinds whose children run straight down, and it reads denser than its mate.

| step | what it costs |
|---|---|
| 1 · open `formatBudgetGrantRefusalLines` with a `   │` row | one line, one file this diff authored |
| 2 · resnap the refusal path | `formatBudgetGrantRefusalLines.test.ts.snap`, plus 3 blackbox snaps — `driver.route.peer-budget-refusal`, `.peer-budget`, `.peer-budget-bulk` |
| 3 · repair the `asGuardBudgetHeadLines` docblock | it claims *"on both paths"*; make it true, or say which path it means |

🟡 **step 3 is owed whichever way step 1 is ruled** — a docblock that overstates its own reach is a
defect independent of the spacer.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe?** ✅ **yes** — a blank connector row, purely visual, no branch touched
- **clean?** ✅ **in code** — one line plus a mechanical resnap, in files this diff already owns
- 🔴 **clean in PROCESS? no** — and this is the whole reason it is deferred

⇒ **the stone had already PASSED when the concern was read.** the guard caches on artifact hash, so
an edit re-opens a sealed route and buys a fresh 12-reviewer walk (≈40 min of guard time) for a
`better`-grade cosmetic row. that ripple is exactly what the CLEAN question asks about — *"does it
ripple into files, contracts, and callers this change never intended to open?"*

🔴 **and the deeper reason is this behavior's own shipped thesis.** the route author set
`--allow-nitpicks 7`; 3 distinct `better` concerns landed. the floor exists so that a concern below
it earns **no further round**:

> **inside the budget, `better` is enough. past the budget, only `urgent` is.**

to spend another full walk on a spacer would be the `better`-churn loop this behavior was written to
stop, performed by the driver that shipped it. ⇒ the honest move is to catch it and let the next
change that opens these files carry it in.

⚠️ **had the concern arrived one round earlier it would have been SAFE ∧ CLEAN, and the rule would
have compelled the fix on the spot.** the deferral turns on its arrival after passage, never on its
size.
