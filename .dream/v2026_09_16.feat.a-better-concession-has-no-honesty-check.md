# 🌙 dream: require a `--why` on a `better` concession, if spurious grades prove real

kind: feat
owner: driver
caught: 2026-09-16

## .the cue that fired

the concession-exhaustion severity split (`better` sheds the tally and the stone passes
outright; `urgent` halts for a human) was live-dogfooded end to end through real production
code. the run itself surfaced an asymmetry the wisher then asked about directly: which path
is the more likely spot for a spurious call, dispute or concede?

## .the gap, precisely

`--as conceded --severity better` costs the driver **naught** beyond the flag itself — no
extra round, no human glance, no authored artifact. the harm test that decides the severity
("can you name the harm that ships if unfixed?") is entirely self-graded, with no mechanical
check anywhere downstream. contrast the dispute path: `--as disputed` **requires** `--why
<fulcrum-path>`, and the fulcrum must exist on disk before the command is accepted at all
(rung 1, `assertFulcrumPathExists.ts`) — a real cost that bounds how often a driver reaches
for it. the concede path has no equivalent, so once a lane's budget runs tight, `better` is
the cheapest exit available — cheaper even than a dispute.

the taught norm (`S11`, `rule.always.concede-with-a-severity`) already states the harm test in
prose. what is absent is any trace of the driver's OWN reason at the moment they applied it —
a council or a later reader has naught to check but the bare word `better`.

## .the shape of the fix

if usage shows this drifts toward a real problem: require `--why <short reason>` whenever
`--severity better` is declared — a plain string, not a fulcrum. lighter than dispute's
fulcrum requirement on purpose, so the two paths stay proportionate to what they cost: a
maintenance-floor concession earns a one-line reason; a genuine disagreement still earns the
heavier fulcrum. the reason rides in the ledger row beside `severity`, same shape as
`fulcrum?` does for a dispute, so a council can check WHY the driver believed no harm shipped,
not merely THAT they declared it so.

## .why it is not done in this round

not safe and clean to build now — it is a preventative feature gated on evidence of a problem
that does not yet exist. the wisher's own words are explicit and conditional: "if we see this
is a problem." to mandate a `--why` on every `better` concede up front would add friction to
the taught default path (concede-and-fix, `S11`) for a risk that is measured nowhere yet. the
honest move is to catch the gap, name the fix, and wait for the signal.
