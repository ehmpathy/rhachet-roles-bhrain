# 🌙 dream: iso-time's `asIsoTimeStamp` stamps local wall time with a UTC `Z`

kind: reseed · owner: ehmpathy/iso-time · caught 2026-10-08

## .the cue that fired

an r030 nitpick asked to move `RouteInflight.since` (epoch ms) onto iso-time. the check of what that
move would ship found the cast itself off by the host's utc offset.

## .the gap, precisely

`node_modules/.pnpm/iso-time@1.11.1/node_modules/iso-time/dist/domain.operations/checks/isIsoTimeStamp.js:13`:

```js
const asIsoTimeStamp = (input) => format(castInputToDate(input), "yyyy-MM-dd'T'HH:mm:ss'Z'");
```

date-fns `format` renders LOCAL time; the `'Z'` is a literal. so on any host whose zone is not utc the
stamp names the wrong instant: with `TZ=America/Chicago`, `new Date(0)` casts to
`1969-12-31` at hour 18, suffixed `Z` — six hours off, and it claims to be utc. it also drops
milliseconds.

## .the shape of the fix

render in utc: `date.toISOString()` (trim to seconds if the contract wants no ms), or date-fns-tz
`formatInTimeZone(date, 'UTC', …)`. clamp: a test under `TZ=America/Chicago` that
`asIsoTimeStamp(new Date(0))` names utc midnight of `1970-01-01` — red today, green after.

## .why it is not done in this round

the defect lives in another repo; a tree adopts only what is scoped to itself. here the consumer keeps
epoch ms (`RouteInflight.since`), so no shipped value carries the skew.
