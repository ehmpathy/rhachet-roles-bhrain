# 🌙 dream: concurrent builds in one worktree must never leave `dist/` absent

- kind = followup
- owner = rhachet-roles-bhrain (this repo's build commands)
- caught 2026-11-27

## .the cue that fired

three acceptance runs at once in one worktree (each `npm run test:acceptance` builds first) left
`dist/` absent. every role link into `dist/` broke, every hook failed closed, and the session lost
every tool until a human rebuilt and relinked.

## .the gap, precisely

`build:clean:tsc`, `build:compile:tsc`, `build:complete:dist`, and `build:complete:swap` all share
ONE stage dir, `dist.next/`. two builds at once:

- clean each other's half-written stage
- compile two `tsc` runs into one dir
- interleave their swaps: build A runs `mv dist dist.prev`, then its `mv dist.next dist` fails
  because build B already took the stage, so `dist/` stays absent

`hazard.a-build-wipes-role-links-and-fails-every-hook-closed` now states this case correctly. the
stage-and-swap cure covers one build at a time, never two.

## .the shape of the fix

1. one stage dir per build: `dist.next.<build id>/`, the id set once in `build` and read by each
   step. no clean ever touches a peer's stage
2. the swap alone runs under a short `withSimpleMutex` hold (an on-disk cache, a lease of seconds),
   so two swaps never interleave (rule.require.locks-via-with-simple-mutex: the hold spans the
   transition, never the build)
3. `tsconfig.json` exclude, `.gitignore`, and the build clean glob widen to `dist.next.*` /
   `dist.prev.*`
4. a clamp: two builds launched at once in a temp copy; assert `dist/` exists after both, and at
   every poll between. red before the fix, green after

## .why it is not done in this round

the route is at `5.3.verification` with an eta to the foreman. the fix ripples across
`package.json`, `tsconfig.json`, `.gitignore`, a new swap executable, and a clamp test: safe, not
clean. meanwhile the conduct rule in the hazard brief (run acceptance suites one at a time) holds
the hazard off.
