# case 4: a broken guard never costs the clone a call

rows 21, 22, 23, 24.

## .narrative

a clone works in a tree where the learner is linked, but the installed package is broken — a dependency at the wrong version, a half-written dist. it runs `ls`; the file list comes back as if no guard existed. it writes a file; the write lands. it never learns the guard is broken, and it never needs to. its human, though, sees a `memory.guard hook error` notice under each call that names the fault (the error message, or "cli absent") and the fix. on a loaded host where node cold-starts past the deadline, the clone's calls pass the same way, with a notice that the guard timed out.

and if the clone, in that broken tree, tries a write into native memory, it lands. a guard that could not judge does not halt (row 24, forbidden by design); the notice is what tells the human the guard is off.

## .bdd sketch

```
given a linked learner whose cli module throws at load
  when [t0] a Bash `ls` fires the hook
    then the call proceeds (exit 1, a non-block notice)
    then stderr is one line:
      📜 memory.guard: could not run (<error message>); call allowed. fix: reinstall rhachet-roles-bhrain
  when [t1] Bash `echo x > ~/.claude/projects/p/memory/x.md` fires the hook
    then the call proceeds; never exit 2

given a linked learner whose cli module is absent
  when [t0] a Bash `ls` fires the hook
    then the call proceeds; one line: cli absent, and the same fix

given a linked learner whose guard never settles
  when [t0] a Bash `ls` fires the hook
    then the call proceeds within the deadline; one line: timed out
```
