## .the cue that fired

on ehmpathy/rhachet-roles-bhrain#721 at head `287dc90e`, `rhx git.release --watch` exited 0 with
`✨ done!`. `gh pr checks 721` then held 4 checks (3 success, 1 skipped). the `test` workflow, 42
more checks, sat queued behind a run for a superseded head, so it had not yet posted a check.
once it ran, it failed one shard.

## .the gap, precisely

- the watch decides done when every check it can see has settled
- a workflow that has not started yet posts no check, so the watch cannot see it
- so a push that lands while an older run holds the concurrency group reads green with the test
  suite never run. a driver who quotes that green ships an unverified claim

## .the shape of the fix

1. before done, list the workflow runs for the head sha (`gh run list --commit <sha>`), and wait
   while any run is not yet `completed`
2. or require the repo's required checks (branch protection) to be present before done
3. clamp: a stub gh where one run is queued with no checks posted; assert the watch keeps on

## .why it is not done in this round

the skill lives in ehmpathy/rhachet-roles-ehmpathy; a tree adopts only what is scoped to itself.
