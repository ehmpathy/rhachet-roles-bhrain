# 🌙 dream: the push-path stderr skips the brain halt, so an unswitched stone still reads as ready

- kind  = fix
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught 2026-09-18

## .the cue that fired

`case21`'s byte snapshot pinned both halves of one pass, and they disagree:

```ts
expect(result.emit?.stdout).not.toContain('--as passed');          // the halt replaced the body
expect(asStableDriveStdout(result.emit?.stderr?.reason)).toMatchSnapshot('case21.t0.onstop.stderr');
```

the stderr snapshot carries:

```
      └─ when ready to continue, run:
         └─ rhx route.stone.set --stone 1 --as passed
```

## .the gap, precisely

the push return in `stepRouteDrive.ts` hands the un-composed body to stderr:

```ts
stderr: { reason: stdoutDrive, code: 2 },
```

`stdout` went through `composeHaltStdout`, so an undispatched brain replaces the body there —
`case=8` `[t2]`'s invariant: **an unswitched stone must not read as ready-to-pass.** `stdoutDrive`
did not, and `src/contract/cli/route.ts` prints it via `console.error` before `process.exit(2)`.

🟡 the stop-hook path matters most: on a non-zero exit a harness may show stderr and hide stdout
(`rule.forbid.stdout-on-exit-errors`).

## .the shape of the fix

```ts
stderr: { reason: stdout, code: 2 }   // the already-composed body
```

one identifier, no new call. check the stuck-path code-2 return for the same shape, then re-snap.

the change decides whether a stderr reason is a **duplicate** of what the driver read or an
**independent** surface — today it is independent by accident.

## .why it is not done in this round

- **SAFE — no.** it changes what a driver reads on every exit-2 stop, and the push return predates
  `brain:`
- **CLEAN — no.** every code-2 drive snapshot moves, and duplicate-vs-independent is a contract call
  — shared with `.dream/v2026_09_18.fix.the-malfunction-stderr-understates-the-remedy.md`

⇒ pinned instead: the byte snapshot means it cannot change in silence.
