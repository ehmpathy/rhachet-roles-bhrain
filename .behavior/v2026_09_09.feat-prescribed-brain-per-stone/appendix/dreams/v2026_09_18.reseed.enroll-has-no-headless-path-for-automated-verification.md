# 🌙 dream: `rhx enroll` has no headless path, so no automated test can verify a real `/model` dispatch lands in a live clone

- kind  = `reseed` — the fix belongs to `ehmpathy/rhachet`, never to this tree
- owner = `ehmpathy/rhachet`
- caught 2026-09-18

## .the cue that fired

a peer reviewer (i002, `ergo-acceptance-journey-coverage` blocker.1) asked for an acceptance-grain
test with "a live (or hermetically-enrolled) clone and a snapshot" proving a `/model` dispatch
actually lands. before answering, a feasibility probe was run rather than assumed away — and it
found a hard wall, not a soft one.

## .the gap, precisely

`invokeEnroll.js` decides whether the underlying brain cli opens interactively (a real pty, the
brain boots and stays live) or headlessly (`--print` mode, one-shot, exits) by reading the
ENROLLING PROCESS's own tty:

```js
// node_modules/rhachet/dist/contract/cli/invokeEnroll.js:231
interactive: !!process.stdout.isTTY,
```

a jest test process has no tty. so does a driver's own sandboxed shell tool — confirmed by a
direct probe, not inferred:

```
$ rhx enroll claude --as @:dogfood-r4-probe --roles driver --no-socket --output json
{"outcome":"baked","serial":"41c95973-...","slug":"dogfood-r4-probe","socketEligible":false}
Error: Input must be provided either through stdin or as a prompt argument when using --print
```

`rhx clone list --output json` immediately after: `"reachState": "DEAD"`. the clone registered,
then died within the same second — `--print` mode requires a prompt argument, and none was given
(there is none to give: this test asked for a live, addressable, waits-for-a-dispatch clone, not
a one-shot prompt/response), so the child exited before ever reaching a state `clone say` or
`clone get` could observe.

⇒ **this is not a credential gap.** perfect credentials change naught here — the branch fires on
`isTTY`, checked before any brain call is made.

## .what was ruled out before this was caught, so a later reader does not re-probe them

| tried | result |
|---|---|
| bypass the cli, call an enroll sdk function directly with `interactive: true` forced | ✗ — `rhachet`'s `package.json#exports` ships only `.`, `./brains`, `./actors`, `./keyrack`. no enroll entrypoint is public |
| wrap the child in a real pty (a terminal-wrapper utility) so its own `stdout.isTTY` reads true | untested — that utility is not on this environment's own command allowlist (`pretooluse.check-permissions`), so the one candidate workaround is itself walled off by this repo's own sandbox |
| `node-pty` (rhachet's own pty engine, `1.2.0-beta.15`) as a direct test dependency | not attempted — a native addon, pulled in solely to reimplement `enroll`'s own pty-allocation logic inside a test, is new infrastructure a fulcrum should rule on, not a unilateral driver call mid-gate |

## .the shape of the fix

in `ehmpathy/rhachet`, give `enroll` (or a new sdk export) a way to run interactively **without**
requiring the calling process's own tty — the two candidates, cheaper first:

1. **an explicit override** — `enroll --interactive` (or `RHACHET_ENROLL_INTERACTIVE=1`), so a
   caller that KNOWS it is allocating a real pty for the child (a test harness using `node-pty`
   itself) can say so, rather than have the decision re-derived from its own tty
2. **a public sdk export** — `./enroll` alongside `./brains`/`./actors`/`./keyrack`, that takes the
   pty-vs-print branch as an explicit parameter rather than an environment inference

⇒ either unlocks the exact acceptance test this feature's reviewer asked for, cleanly, with no
workaround downstream.

## .why it is not done in this round

- **SAFE?** ❌ — the fix is in another repo, on another release cadence. this tree cannot change
  how `invokeEnroll` decides `interactive`
- **CLEAN?** ❌ — the one workaround this tree COULD attempt (`node-pty` as a direct dependency,
  reimplementing enroll's own pty allocation inside a test) is new native-dependency
  infrastructure, not a scoped fix — `rule.always.reuse-pavement-before-improvise`'s braided-trail
  shape

⇒ a tree adopts only what is scoped to itself. caught as a `reseed`, not adopted.

⚠️ **caught is not dispatched.** the radio push to `ehmpathy/rhachet` is a separate act, and it
has not happened.
