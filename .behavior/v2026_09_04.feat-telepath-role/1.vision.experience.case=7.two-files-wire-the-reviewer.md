# case=7 · two files wire the reviewer

**cell** = `adopter · reviewer · happy · complete · file`
**feel** = happy · **care** = critipath (`freq` = once per role, but every role · `cost` = a costly wire-in means the reviewer spreads to no one)

**issues** = #394 · #386

## .why an adoption path is a critipath

the reviewer's value scales with the count of roles that run it. **if the wire-in is costly, it spreads to no one and the whole wish yields one unused rubric.**

so the adoption cost is a first-class outcome, never an implementation detail.

## .the narrative

a role owner wants telepath's prose reviewer on their role's yields.

the pavement already exists — `howto.add-review-by-to-a-role` settles it. they add two files:

**1 · `briefs/reviews/rubrics.yml`** — declare which rubrics to run

```yaml
rubrics:
  - slug: prose-density
    purpose: >-
      prose arrives in one pass — no narrative, no roundabout, one sentence
      per bullet, the argument refs out
    rules:
      - .agent/repo=bhrain/role=telepath/briefs/rule.forbid.narratives.md
      - .agent/repo=bhrain/role=telepath/briefs/rule.forbid.roundabouts.md
      - .agent/repo=bhrain/role=telepath/briefs/howto.densify-a-passage.md
      - .agent/repo=bhrain/role=telepath/briefs/rule.require.a-passage-refs-out.md
```

**2 · `skills/review.by.sh`** — the one-line wrapper, verbatim, same for every role

```sh
#!/usr/bin/env bash
set -euo pipefail
exec node -e "import('rhachet-roles-bhrain/cli/review.by').then(m => m.reviewBy())" -- "$@"
```

then `chmod +x`, rebuild, and:

```sh
rhx review.by --role telepath --for prose-density --paths '.behavior/**/*.yield.md'
```

it runs. the base engine owns rubric enumeration, the review subprocess, the treestruct, and the exit codes.

## .what the adopter does NOT write

the wrapper pattern is already enforced by `rule.require.review-by-wrapper-pattern`:

| anti-pattern | why forbidden |
|---|---|
| a **fat wrapper** that greps its own `rubrics.yml` and re-orchestrates | duplicates base logic that then drifts |
| a **second `rhx` dispatch** inside the wrapper | doubles the `🪨 run solid skill` banner |
| the **base-direct form** as the everyday command | `--repo bhrain --role reviewer --` is internal wiring; use it only in acceptance tests |

⇒ **telepath adds no new adoption mechanism.** it reuses the paved one, which is why this cell is `happy` rather than `sharp`.

```
 and       a guard can tally it without a sub-brain

then       it invokes `rhx review.by --role telepath --for <rubric>`
 and       it never reaches into telepath's internals
```

## .the adoption bill

| what | cost |
|---|---|
| files the adopter writes | 2 |
| lines of logic they own | 0 — the wrapper is verbatim, the rubric is declarative |
| new mechanisms telepath introduces | 0 |
| base engine changes required | 0 |

⇒ the wire-in is a **declaration**, never an implementation. that is what makes the reviewer spreadable.

### 🟡 .this bill is the ADOPTER's — telepath's own build is one line larger

the table above counts what a **role owner** writes. it is not telepath's bill, and the two must not be read as one.

| telepath's own build | cost |
|---|---|
| `briefs/reviews/rubrics.yml` | 1 new file |
| `skills/review.by.sh` | 1 new file |
| the rule briefs the rubric cites | the `.what` of this whole behavior |
| `getTelepathRole.ts` | **a one-line edit** — `skills: { dirs: [], refs: [] }` is **empty** today (`:14-17`), so a `skills/` dir alone would not register |

⇒ **the adopter's zero-logic claim survives intact; telepath's does not.** a bill of materials that omits a source edit is the kind of surprise that lands mid-execution, on a stone whose plan said *"declaration, never implementation."*

## 🟡 .the one decision left open

the rubric **decomposition** — one `prose-density` rubric, or several (`narratives`, `roundabouts`, `density`, `refs-out`)?

| shape | trade |
|---|---|
| **one rubric** | one reviewer, one verdict, cheapest. a blocker names its own rule, so granularity survives |
| **several rubrics** | per-concern verdicts a guard tallies separately. `n` review runs per arrival, `n×` the cost |

🟡 case=4 makes this a **cost** decision, never a taste one — each rubric is a separate brain call against the same subject.

⇒ settled in `1.vision.yield.md`, and flagged as a fulcrum.
