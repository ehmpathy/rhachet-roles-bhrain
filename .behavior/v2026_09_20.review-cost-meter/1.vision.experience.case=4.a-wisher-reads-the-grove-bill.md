# case=4 — a wisher reads the grove bill

- cell = `grove` × `cost` × `observe`
- path = **critipath** · feel = happy · care = criti

## .the narrative

a wisher suspects the review ladder costs too much but cannot say so with a number. every
tree keeps its own log; no surface joins them.

```sh
rhx review._.cost --of grove
```

the answer that opened this whole branch:

> **3,663 runs across 19 trees · $151.92 · 779.5M input tokens · 2.8% cache hit rate**

the point is not the dollar figure. it is **2.8%**.

a review prompt's static head — instructions, output format, rules, refs — is byte-identical
round over round by construction. a 2.8% hit rate against a prompt built that way is not a
pricing fact; it is a **defect**, and the number is what makes it arguable.

the roll-ups say where it lives: `by tree`, `by route`, `by stone`, `by reviewer`. the
follow-up finding — eleven lanes re-read one corpus for ~85% of the bill — is read
directly off the `by reviewer` block, not derived by hand.

## .the before/after

| | before | after |
|---|---|---|
| *"what does review cost?"* | a guess, per tree, by hand | one command, every tree |
| *"is the cache working?"* | unanswerable | a share, with its numerator and denominator named |
| *"where does the spend go?"* | unanswerable | four roll-ups |
| *"can we prove a lever fired?"* | no baseline existed | the realized figure, before and after |

## .the bdd sketch

```
given [case4] several trees, each with its own review log
  when [t0] `rhx review._.cost --of grove` is run
    then every discoverable tree is read, not just the cwd
    then the totals sum ONLY the metered runs
    then the cache share names its denominator (prompt tokens)
    then a roll-up is emitted by tree, by route, by stone, and by reviewer
  when [t1] one tree has no log at all
    then it is reported with zero runs, never omitted in silence
  when [t2] `--limit N` is passed
    then the roll-ups truncate, and say that they truncated
```

## .what it depends on

- `getAllReviewTrees` — tree discovery, with its own integration test
- `genReviewGroveReport` / `genReviewGroveStdout` — the roll-ups, snapshotted
- `asReviewRunIdentity` — parses tree / route / stone / reviewer out of a run's path

## .why it is a critipath

it is the **only** surface that can close bar 5 of the wish — *"the gain is measured, never
projected."* without it, every cache lever on this branch is a byte-count argument with no
way to be confirmed or refuted against a live grove.
