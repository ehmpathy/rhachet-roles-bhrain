# 🌙 dream: a role declares its status line top-level; rhachet renders it per actor, per brain cli

kind: reseed · owner: ehmpathy/rhachet · caught 2026-10-16

## .the cue that fired
bhrain's driver role wants `🗿 <stone>` at the foot of each driver session. today the only way is a
role init that merges `statusLine` into a claude settings file. rhachet 1.49 derives each actor's
`settings.of.repo.json` whole from the repo actor's file, on each enroll and each `rhx init
--hooks`. so the bind either leaks to every actor (write the repo file) or vanishes at the next
rebuild (write one actor's file). the wisher wants: only actors enrolled with driver get it.

## .the gap, precisely
- no role-level contract for a status line (or any frame line — header, footer) exists; a role
  must reach into a brain-specific settings file to get one
- actor settings derivation (`setBrainDirSettingsLayout`, rhachet 1.49.2) copies the repo file
  whole, with no per-actor, per-role filter, and keeps no per-actor overlay across a rebuild

## .the shape of the fix
- a top-level role declaration, e.g. in the role's manifest:
  `frames: { statusLine: { command: "<cmd>" } }` (name open — "frame lines" was the wisher's guess)
- at actor derivation, rhachet composes the frames of the roles THAT actor is enrolled with, and
  the brain cli adapter renders them in its own dialect (claude: the `statusLine` key in the
  actor's derived settings; other brains: their own equivalent, or a no-op)
- precedence: a human's own `statusLine` in the grove wins; a role frame never clobbers it
- one role per slot: two roles that both declare a status line fail loud, or compose by a declared
  rule — not last-write-wins in silence
- then bhrain deletes `init.claude.status-line.sh` and declares the frame on the driver role

## .why it is not done in this round
it belongs to another repo; a tree adopts only what is scoped to itself. the bhrain interim
(bind the repo actor's file, accept the leak to non-driver actors) ships on this route.
