## 🔴 .the problem this cell exposes — axis A is not observable at the call site

`route.guard.budget --for review --add 2 --stone 5.1.execution` is **one command with one syntax**.
a human and a bot issue it identically. so the gate cannot read the actor, and the three obvious
reaches all fail:

| candidate | why it fails |
|---|---|
| a `--as human` flag | 🔴 **forbidden outright.** a bot that passes its own human flag has laundered the gate, never met it — `rule.forbid.self-grant-human-gates`, and `0.wish.md` §what is NOT wanted names it |
| TTY / env detection | brittle, silent when wrong, and a bot in a terminal defeats it |
| a prompt for confirmation | a bot answers prompts |

⇒ **the actor cannot be detected RELIABLY. it must be REIFIED** — written to disk by a party the bot
cannot impersonate, and read by the gate as a fact.

🔴 **that word was *"cannot be detected"*, unqualified, until `r4` self-review — and the repo relies
on the very detection it dismisses.** `require_human()` probes `[[ ! -t 0 ]]` and refuses with exit 2,
in four files across two role trees:

| file | line |
|---|---|
| `radio.uses.operations.sh:34-44` | `# guard: mutation commands require TTY (human only)` |
| `git.commit.uses.local.sh:135` · `.global.sh:98` · `.org.sh:131` | `if [[ ! -t 0 && "${__I_AM_HUMAN:-}" != "true" ]]; then` |

⇒ row 2 of the table above is **correct that TTY is brittle** and wrong that it is unavailable. the
honest statement: **detectable, weakly** — which is exactly why a weak probe is not enough on its own,
and why the reification below is still the right move.

## ✅ .the resolution — the meter #458 already designed

the human does not run `--add N` in a way the engine trusts. **the human grants the LEVER**, once, and
the bot spends it:

```
$ rhx route.budget.uses allow --quant 1        # a human runs this; the bot's copy is denied by permissions
```

```
🦉 so it is

🗿 route.budget.uses
   ├─ scope = local (.meter/route.budget.uses.jsonc)
   ├─ quant = 1 grant
   └─ ✅ allowed — the bot may make ONE budget grant on this repo
```

🔴 **this is the extant `git.commit.uses` / `radio.uses` pattern, unchanged** — three levels
(global → local → org), **unset ⇒ blocked**. ⇒ the actor axis becomes a **quota on disk**, which is
exactly what `#458` proposed and exactly what `0.wish.md` req 3 demands of the concession predicate.

## 🔴 .what actually stops the bot from that write — TWO gates, and this cell named only one

it read *"the human's copy of the skill is the one the bot's **permission list** denies."* that is
true and it is **half**:

| gate | where | what it is |
|---|---|---|
| the **permission list** | the harness — a deny entry on the bot's copy | ✅ the one this cell named |
| 🔴 the **TTY probe** | inside the skill — `require_human()`, exit 2 | 🔴 unnamed here, **and it is the reach row 2 above calls brittle** |

🔴 **so the reification does not ESCAPE the brittle detector; it relocates it one hop back:**

```
the gate reads    →  a quota on disk                 (a fact — strong)
what writes it    →  a skill gated by [[ ! -t 0 ]]   (🔴 a detector — the brittle one)
```

✅ **the resolution still holds, and for a reason this cell did not state: two gates in SERIES beat
one.** a bot must defeat the harness deny entry **and** the TTY probe; either alone is weak, and the
pair is the argument that actually carries the meter — never *"detection was avoided."*

⚠️ **and the pattern ships the reach row 1 forbids OUTRIGHT.** every probe carries
`__I_AM_HUMAN=true` — *"allows integration tests to run mutations"* — which is **a bot that passes
its own human flag**, in an env var rather than a CLI flag. 🟡 whether a driver can reach it turns on
the harness matcher, which keys on a command prefix; **stated as an open cost, never a proven hole**,
and priced on `F02`.

## 🔴 .so the gate has TWO independent lifts, and that is the design

```
a grant is permitted  ⟺  a live urgent concession stands   (the bot's own path — case=2)
                      ∨  the human's `uses` quota has a grant left   (this cell)
```

⇒ **that disjunction is the synthesis the wisher's three prior positions never reconciled.** the
predecessor's `F011` recorded the reversals and left them open:

| date | the claim |
|---|---|
| 2026-08-04 | *"review budget is YOUR lever … never a human gate"* |
| 2026-09-07 (`#458`) | robot **blocked** by default, human-only |
| 2026-09-08 | *"a budget add is NOT a human-only operation"* |
| 🔴 **2026-09-17 (this wish)** | **refused by default, and the lift is EARNED rather than granted** |

⇒ the fourth position **is** the reconciliation: `#458`'s default-block is right, and *"human-only"*
was too narrow — the second lift is not a human, it is a **recorded harm claim**. ⇒ `#458` is not
superseded; **it is one half of this, and it should be implemented rather than closed** (`F02`).

## .the bdd timeline

```gherkin
given a stone `5.1.execution`, ergo-rules exhausted at 4/4
  and NO live urgent concession on the stone                          # B = none
  and .meter/route.budget.uses.jsonc is UNSET                          # the safe default

[t0] when the driver runs the top-up
     then it is REFUSED                                                # 🔴 unset ⇒ blocked (case=1)

[t1] when the human runs route.budget.uses allow --quant 1
     then the meter records quant 1, at local scope
      and the bot's own invocation of route.budget.uses is DENIED      # 🔴 by the permission list, not by the skill

[t2] when the driver runs the same top-up as [t0]
     then it is GRANTED
      and the quota decrements 1 → 0
      and stdout names the quota as its warrant, not a concession

[t3] when the driver runs the top-up a SECOND time
     then it is REFUSED                                                # the quota is spent
      and stderr names the human command to grant more

[t4] given the global meter is BLOCKED
     when the human sets the local meter to allow
     then the grant is still refused                                   # 🔴 global blocked ⇒ always blocked
      and stderr names the global lever and its owner

[t5] given a live urgent concession ALSO stands
     when the driver runs the top-up with the quota spent
     then it is GRANTED                                                # 🔴 the disjunction — either lift suffices
      and stdout names the CONCESSION as the warrant, and spends no quota
```

🔴 **`[t5]` pins the disjunction and the spend order together.** the urgent lift is checked first and
costs the human's quota naught — otherwise an earned round would silently consume a permission the
human granted for a different purpose.

🔴 **`[t1]`'s second clause is the whole integrity of axis A.** the `uses` skill is not defended by
cleverness inside the skill; it is defended by the **permission list**, exactly as `git.commit.uses`
is today. ⇒ a bot that tries it is blocked before the process starts.

## .why it fails safe

**safe by default** — unset ⇒ blocked, the `uses` pattern's own invariant, so a repo that never
configures it gets the bound rather than the loophole · **loud** — the grant names which of the two
lifts it spent, so a PR reader can count human grants apart from earned ones · **unforgeable** — the
human's act is a file the bot cannot write, never a flag the bot can pass.

⚠️ **the one hazard: a human who grants `--quant 99` once has re-opened the free lever.** the quota
is the bound, and a large quota is a large bound. that is the human's call to make, with the route in
view — which is precisely req 7. 🟡 recorded rather than mechanized.
