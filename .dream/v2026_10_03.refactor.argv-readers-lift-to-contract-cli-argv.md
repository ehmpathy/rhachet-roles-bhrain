# 🌙 dream: lift the argv readers into `contract/cli/argv/`, one policy for every cli

- kind = refactor
- owner = bhrain (this repo)
- caught 2026-10-03

## .the cue that fired

peer reviewer `enroll-impl-arch-defects` (stone 5.1, i056, nitpick.5) found generic flag readers
inside `src/contract/cli/review._.cost.ts`, and a second flag policy inside the warmer's argv reader.

## .the gap, precisely

- `review._.cost.ts` declares `FlagRead`, `getOneFlagRead`, `isArgValueOfFlag`, `getAllArgsStray`,
  `getAllFlagsRepeated`, `getAllFlagsUnknown` — none of them specific to the cost meter
- the warmer reads its own argv with another policy — `asWarmerArgsFromArgv` in
  `src/domain.operations/review/warmer/asWarmerArgv.ts`, the read half of the spawn's argv pair:
  the last value of a repeated flag wins, and a stray token is dropped silently
- ⇒ two clis, two policies; the next cli copies whichever it finds first

## .the shape of the fix

1. move each reader to `src/contract/cli/argv/$name.ts`, one operation per file, with a `.test.ts`
2. re-wire `review._.cost.ts` to import them; its help text and refusals stay where they are
3. move `asWarmerArgsFromArgv` onto the shared readers, so a repeated or stray flag refuses loud.
   keep `FLAG_OF_WARMER_ARG` as the one map both halves of the pair read
4. clamp: a warmer spawn with a stray token exits 2 and names the token

## .why it is not done in this round

safe, not clean. the lift opens the warmer's spawn contract and each cli test that drives it —
files stone 5.1 did not set out to touch. the deferral is recorded as fulcrum F85.
