# 🌙 dream: findsertGitignore's `action` conflates "created" with "overwrote stale content"

- kind  = fix
- owner = this repo (`rhachet-roles-bhrain`)
- caught = 2026-09-13, at stone `5.1.execution.from_vision`, from peer review i015/r11 (arch-defects, nitpick)

## .the cue that fired

`findsertGitignore.ts` reports `action: 'created'` on two distinct paths — the ENOENT path (the
file did not exist) and the stale-content-differs path (the file existed and was overwritten).

## .the gap, precisely

checkable evidence: `src/domain.operations/route/gitignore/findsertGitignore.ts:47-52` — both
branches resolve to `'created'`. harmless today because no caller branches on the value, so the
conflation is invisible.

## .the shape of the fix

split the reported action into `'created'` (ENOENT) vs `'rewrote'` (extant-but-stale), so a future
caller that branches on it reads the truth. add a unit case per branch.

## .why it is not done in this round

SAFE = yes. CLEAN = borderline — it changes a returned enum a snapshot or caller could read, so it
wants its own small pass rather than a ride-along on an overflowed diff. the reviewer graded it a
nitpick — *"harmless today ... but worth knowing before a caller starts relying on the distinction."*
