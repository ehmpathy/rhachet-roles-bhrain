# domain.term.choice.reason: locus

## .etymology

latin *locus*, a place. in mathematics a locus is the set of points that satisfy a condition — here,
the set of paths that carried target mass. the word names a PLACE and naught else, which is the
whole job: the composition already names the kind of mass, so the second axis must be the address.

rejected:
- **origin** — implies one point. a locus is a set of rows with shares
- **source** — already declared on the meter: a run's prompt `source` is `compiled` or `parsed`.
  to reuse it would overload one field name onto two concepts
- **breakdown** — names the act of division, never the axis it divides along. a composition is a
  breakdown too
- **hotspot** — names only the heaviest row, and carries a judgement. a locus reports every row,
  heavy or light, and a heavy row a lane needs is no defect

## .boundary

"locus, of WHAT?" → of a review's targets. the targets are the scope's members, so the boundary is
`review.scope` — the same head as `polluter` and `partition`, the two other words that say which
targets a review reads and where.

## .evidence

- the measured case that forced it: a run whose 113 targets were 100% one directory and 100%
  tests — correct for a tests lane, and the meter could not say so. the rollup that settled it was
  hand-written, which is the cue `rule.require.report-both-cost-levers-with-trend-and-locus` names
- it composes declared operations: `asTargetLocusLines`, `getOneTargetLocusRollup`,
  `asTargetLocusEntries`, `asCompiledLocus` — and a rendered surface, the overflow refusal's
  `locus:` block
- invariant: the rows of one locus sum to the target chars sent; a truncated render names its
  remainder, never drops it
