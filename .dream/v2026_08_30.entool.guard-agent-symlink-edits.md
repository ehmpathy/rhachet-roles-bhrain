# dream: a preToolUse hook that refuses an edit through an `.agent/` symlink

**kind**: entool · **owner**: this repo (`rhachet-roles-bhrain`) · **caught** 2026-08-30

## .the gap

`hazard.agent-brief-may-be-a-dist-symlink.md` names the hazard and gives its cue table. that is
rung 1 — a brief a reader must recall.

the failure it guards is **silent and delayed**: the edit reports success, the file reads back
correct, and the next `npm run build` reverts it via `rsync -a … src/ dist/`. so there is no
loud symptom at the moment of the mistake, which is exactly the case where a brief is weakest
(`research.selfreview-effectiveness` — a message alone scores d ≈ 0.05).

## .the ask

a `preToolUse` hook on `Edit` / `Write` that:

1. resolves the target path
2. refuses when it is a symlink whose target lands under `dist/`
3. names the fix — the `src/domain.roles/<role>/briefs/<name>` path it should have been

that is the same shape as the extant `pretooluse.forbid-terms.*` and
`pretooluse.forbid-suspicious-shell-syntax` hooks, so the mechanism is already paved.

## .why it is out of the behavior that caught it

`v2026_08_12.feat-adopt-seeded-briefs` is **briefs only** — no new skills, no hooks. so the
brief landed and the hook did not. this is the record of the half that remains.

## .the evidence

on 2026-08-30 an edit to `.agent/repo=.this/role=any/briefs/domain.terms/.readme.md` was applied,
reported success, and was reverted by the next build. it was caught only because a peer review
re-flagged the exact text that had already been "fixed" — which is a slow and lucky detection
path, not a reliable one.
