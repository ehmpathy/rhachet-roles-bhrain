# case=4 · the cure catches the disease

**cell** = `driver · reviewer · sharp · oversized · file`
**feel** = sharp · **care** = critipath (`freq` = every long route on a large tree · `cost` = the reviewer that grades bloat is silenced by bloat)
**issues** = #394 · #423 · #424

## .the recursion this demo exists to name

telepath's reviewer is added to *every stone that emits a yield*, because that is where prose bloat is born.

a stone that emits a yield is also a stone whose review subject *holds that yield*.

⇒ **so the reviewer's subject grows with the defect the reviewer detects, and the reviewer that is likeliest to overflow is the one declared to prevent overflow.**

this cell is why the reviewer's cost is a design constraint and never an afterthought.

## .the narrative

a driver on a long route arrives at `5.3.verification`. the guard fires four peer reviewers plus telepath's. the subject is the `--diffs since-main` set: 117 files, 915.3k tokens.

telepath's reviewer never reaches a verdict. it prints:

```
✋ prompt exceeds 75% of context window
   ├─ 94.3% of 1000000 tokens
   └─ reduce scope or use --focus pull

🔍 what is in scope
   ├─ rules: 4 files, 3.1k tokens
   └─ targets  →  files: 101, tokens: 707.4k
      ├─ .behavior/                          366.4k  51.7%   🟡 over 40%
      ├─ src/                                327.3k  46.2%
      ├─ largest files
      │  ├─ 5.3.verification.yield.md         73.9k  10.4%
      │  ├─ autoprune.acceptance.test.ts      64.5k   9.1%
      │  └─ 1.vision.yield.md                 45.1k   6.4%
      └─ pathsWith: **/*.{ts,sh,md,snap}
```

the driver reads the composition **in the message**, never behind a hint. it sees at once that `.behavior/` is half the subject and that `pathsWith` pulls every markdown in the diff.

it narrows telepath's reviewer to the yields alone and re-runs. the reviewer fits, and renders a verdict.

## .what the before-state cost

measured 2026-09-03 on `ehmpathy/test-fns @ 5.3.verification`, across 9 iterations:

| what happened | consequence |
|---|---|
| the overflow printed a **total** and a **file count**, and deferred composition to a hint | the driver formed a structural read before it reached the line that would overturn it |
| the driver read the overflow 8 times and never opened `tokens.expected.json` | *"a defect that costs one `cat` to find will be found only by someone who already suspects it"* |
| it escalated to a human with a **false causal claim** — *"every `.taken` lands in since-main"* | `.taken` files are gitignored. a grep of the breakdown for `taken\|given` returns no match |
| 25.7% of the subject was `review/self/` at an unignored duplicate path | one line in `.gitignore` cut 960.8k → 707.4k, **−25 points of context** |

⇒ the reviewer **already computes** the diagnosis into four log files. it printed the symptom and filed the diagnosis where the reader had to know to look.

## .the invariant this cell yields — INV-3

an overflowed reviewer rendered **no verdict**. it must never grade as a pass.

### the two paths disagree, and only one is paved

verified by source read, 2026-09-04:

| path | overflow throws | exit | `getExitCodeClass` | outcome |
|---|---|---|---|---|
| `rhx review.by` (the paved reviewer) | `BadRequestError` | **1** (`review.by.ts:336-338`) | `malfunction` | **blocks** ✅ |
| 🟡 `rhx review` (the direct bypass) | `BadRequestError` | **2** (`review.ts:300-304`) | `constraint` | terminal-for-unlock |

⇒ **INV-3 already holds on the shape this vision proposes.** `review.by.ts:309-330` is explicit about why:

> *"exit by worst outcome: 2 when any rubric found blockers (constraint), else 1 when any rubric malfunctioned (server-side failure surfaced, **never a fake 0/0 pass**)"*

🟡 **the residual risk is the bypass, never the reviewer.** `rule.always.diagnose-reviewer-malfunctions` instructs a driver to run `rhx review` **narrowed** for a scoped re-run — and that path grades an overflow `constraint`. so a driver who follows that brief on an overflowed telepath reviewer gets a terminal grade from a run that read no file.

⇒ that is a narrower defect than *"an overflow unlocks"*, and it belongs to the bypass path. it is caught rather than fixed here.

## .the bdd timeline

```
given [case4] a long route on a large tree
  and  a guard that declares a telepath reviewer on a yield stone

when  [t0] the reviewer's subject exceeds the context gate, on the PAVED `review.by` path
then       the reviewer renders NO verdict
 and       it does not grade as `approved`
 and       it exits 1 -> `malfunction`, so it does NOT grade terminal-for-unlock

when  [t0b] the same overflow is met through the `rhx review` BYPASS
then       the reviewer renders NO verdict
 and       it does not grade as `approved`
 and       🔴 it exits 2 -> `constraint`, which IS terminal-for-unlock
 and       so INV-3 holds on the paved path ONLY

when  [t1] the overflow message is printed
then       the top ~5 target entries by tokensScale appear IN the message
 and       the effective `pathsWith` glob appears IN the message
 and       no diagnosis is deferred to a hint alone

when  [t2] one directory exceeds 40% of the target tokens
then       the message names that directory and its share
 and       it names the flag that narrows it

when  [t3] the driver narrows the reviewer's scope and re-runs
then       the reviewer fits the gate
 and       it renders a numeric verdict the guard can parse

when  [t4] the telepath reviewer is declared on a stone
then       its subject is scoped to the artifacts telepath grades
 and       it does not inherit the full `--diffs since-main` code set
```

## 🟡 .the trap that makes the obvious fix wrong

the first move anyone reaches for is *"exclude the route dir from the review scope"*. do not take that as given.

`rule.always.converge-with-reviewers.via-a-taken-per-point` is explicit that a reviewer *re-reads with your articulation AND your diff in context*, and that a code fix with no `.taken` reads to it as no fix at all.

⇒ a blanket `--paths-wout '.behavior/**'` would repair the overflow and break the convergence loop in the same stroke.

🟡 **telepath's reviewer escapes that trap, and it is the only one that does:**

- its subject *is* the prose artifacts
- it holds no code diff and no `.taken` trail to preserve, because it grades the yield rather than the fix
- ⇒ so a narrow, prose-only scope is correct for this reviewer alone, and stays wrong as a blanket rule for the others

## .what this cell demands of the design

| demand | why |
|---|---|
| the reviewer's scope is prose-only, declared, never inherited | its subject is prose; a code diff is pure overflow risk |
| the rubric set is few and small | 4 rule files at ~3k tokens leaves the gate for targets |
| an overflow blocks, never unlocks | INV-3 |
| the overflow message carries the composition | so the driver diagnoses in one read, never in eight |
