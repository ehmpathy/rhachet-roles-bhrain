## .the gap, precisely

the `$stone.guard.promise.$slug.md` family has **four** independent hand-typed derivations in
production, and no canonical one:

| site | what it derives | how |
|---|---|---|
| `stones/setStoneAsPromised.ts:30` | the **path** | `` `${stone.name}.guard.promise.${slug}.md` `` |
| `guard/review/self/getStonePromises.ts:28` | the **glob** | `` `${stone.name}.guard.promise.*.md` `` |
| `guard/review/self/getStonePromises.ts:61` | the **parse** | `/\.guard\.promise\.([^.]+)\.md$/` |
| `stones/delStoneGuardArtifacts.ts:40` | the **glob**, again | `` `.route/${stone}.guard.promise.*.md` `` |

⇒ **four derivations of one convention, across three files, none of which imports another.** the
writer and the readers agree today by coincidence of authorship rather than by construction — which
is the precondition of the exact incident above.

## .the narrowness, measured — ✅ FIXED, and this record had it WRONG

this dream claimed the parse *"round-trips **wrong**"*, and read `i1.p1` as slug `i1`, and hedged it
as *"an observation, not a measured defect"*. **both halves were mistaken, in opposite directions.**

the round-trip clamp was written and run: `setStoneAsPromised({ slug: 'i1.p1' })` then
`getStonePromises` ⇒ **`Received length: 0`**, not a wrong slug.

🔴 **`([^.]+)` cannot span a dot AND is anchored by `\.md$`, so a dotted slug matched NAUGHT** — and
`getStonePromises.ts:40`'s `if (slug)` then dropped the file in silence. so the failure was never a
mis-parse; it was **a failhide** (`rule.forbid.failhide`), and the harm chain is worse than a wrong
label:

| step | what happened |
|---|---|
| the driver runs `--as promised --that i1.p1` | the file is written, and the cli reports success |
| the guard runs `getStonePromises` | `[]` — the promise is **invisible** |
| `findNextUnpromisedReview` | hands out `i1.p1` again |

⇒ **a hard-stuck driver, which `0.wish.md` requirement 3 forbids outright** (*"no driver is
hard-stuck"*). that is why it was promoted out of this dream rather than left here.

⚠️ **and the hedge was wrong too, in the other direction.** *"no production path was traced"* holds
of the **engine** — `parseStoneGuard.ts:183` mints dotted slugs only for **peer** reviewers, on
collision, and promise files are **self**-only. but a route author who writes `self: i1.p1` in a
`.guard` reaches it directly, and meets a silent perpetual loop with no message.

### the repair taken

one character, one file: `([^.]+)` → `(.+)` at `getStonePromises.ts:61`. greedy, anchored by
`\.md$`, so `all-done` and `i1.p1` both round trip. clamped at `getStonePromises.test.ts [case5]`,
bite-proven — **red before the fix (`length 0`), green after**.

🔴 **the clamp binds the WRITER to the READER, never a hand-typed filename to the reader** — the
agreement-grain lesson that `asSelfReviewTriggeredGlob` was extracted for, one dir away. a literal
filename in that test would grade the parse against the test's own guess rather than against
`setStoneAsPromised`, and would stay green if the writer's template moved.

### why this half was CLEAN when the extraction is not

the deferral below turns on **ripple**, never on scope (`rule.always.fix-forward-under-scouts-honor`

## .the shape of the fix

mirror what `getSelfReviewTriggeredPaths` now does, since it is the template that works and it sits
two directories away:

```ts
// guard/review/self/getStonePromisePaths.ts
const asBaseFilename = (input: { stone: string; slug: string }): string =>
  `${input.stone}.guard.promise.${input.slug}`;

export const getStonePromisePaths = (input: { stone; slug; route }) => ({ promisePath });
export const asStonePromiseGlob  = (input: { stone: string }): string => …;
export const asStonePromiseSlug  = (input: { filename: string }): string | null => …;
```

then route the four sites through it. 🔴 **and clamp the AGREEMENT, never the values** — the lesson
the trigger half paid for:

- a literal assertion pins what each derivation **says**, and stays green when the convention moves
  in one place and a reader is left behind. that is precisely the drift to catch
- the trigger half's clamp binds the glob's wildcard to a real slug and asserts it reproduces that
  slug's own filename, so the two are checked **against each other**
- **bite-proven there**: move the convention, leave the glob, and the literal assertion stays green
  while the agreement assertion goes red
- ⇒ the promise family owes a third leg the trigger family does not — the **round trip**:
  `asStonePromiseSlug({ filename: getStonePromisePaths({ slug }).promisePath })` must return the slug
  it went in with. ✅ **that leg already exists**, at `getStonePromises.test.ts [case5]`, bound to
  `setStoneAsPromised` rather than to a literal. the extraction must **keep** it pointed at the
  writer — re-aim it at `getStonePromisePaths` and it grades the new module against itself

🟡 **leave the test literals alone.** ~13 test files assert the filename as a string, and that is
correct: a test that derived the name from the same helper it grades would be **vacuous**. this round
paid for that lesson twice (yield item 16 — two headline clamps written against a file the mechanism
never read, both green under the defect).
