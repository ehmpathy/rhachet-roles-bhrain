## .the gap, precisely

there is ONE formatter (`formatGuardReviewerTree`) and ONE verdict operation
(`computeReviewPeerVerdict`), and both paths use both — so the rule's literal target is
met and the sharpest drift surface is already closed.

what remains is **two adapters** into that formatter, from two genuinely different
upstreams:

| adapter | its source | where it runs |
|---|---|---|
| `asReviewerTreeState` | a live `GuardProgressEvent` | the inflight stream, per emit |
| `asReviewerTreeStateFromMeter` | a persisted `GuardPeerMeterStatus` | the settled guard tree |

⇒ they agree today **by discipline**. each was independently hardened in this round — the
declared-index read landed in both, and the malfunction/constraint/exhausted/queued
branches exist in both — which is the reviewer's evidence that the next repair will need
two landings too.

**checkable evidence:** grep `ReviewerTreeState` and count the constructors. two produce
it; one consumes it.

## .why it is not done in this round

- **SAFE:** no. one adapter feeds the LIVE stream and the other the SETTLED tree. both are
  pinned by the 124-suite acceptance corpus, and the live one is the path whose
  header/detail split has already caused two rounds of snapshot churn.
- **CLEAN:** no. a unification needs a new seam — either a normalized intermediate both
  upstreams cast to, or a discriminated input the one adapter reads. that is a contract
  change across `genContextCliEmit`, `formatGuardTree`, and their fixtures.
- **the sharpest half WAS fixed in-round:** the identity block (`index`, `slug`, `level`,
  `rounds`, `budget`, `overruled`) was spelled out in five branches of the event adapter
  and is now one `asReviewerTreeIdentity`. that was safe and clean, so it was not deferred.

## .the shape of the fix

the two upstreams differ in exactly one way that matters: **an event describes a moment,
a meter describes an accumulation.** so the seam is a normalizer, never a merge:

```ts
// one shape both upstreams cast to, before either reaches the tree
type ReviewerTreeSource = {
  identity: Pick<ReviewerTreeState, 'index'|'slug'|'level'|'rounds'|'budget'|'overruled'>;
  outcome:
    | { kind: 'inflight' }
    | { kind: 'queued' }
    | { kind: 'malfunction' | 'constraint'; path: string }
    | { kind: 'settled'; verdict: ReviewPeerVerdict; blockers: number; nitpicks: number;
        path: string; cached: boolean; durationSec: string | null; tallier: string };
};
```

then `asReviewerTreeState(source: ReviewerTreeSource)` is the ONE adapter, and each
upstream owns only its own cast into `ReviewerTreeSource` — a cast with no verdict logic
in it at all.

🟡 **and the clamp writes itself:** feed one `ReviewerTreeSource` through both upstream
casts and assert the rendered block is byte-identical. that is the property discipline
currently holds by hand, and it is what a future repair would break silently.
