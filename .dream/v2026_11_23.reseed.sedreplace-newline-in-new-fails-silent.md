# 🌙 dream: sedreplace must apply a multi-line --new, or refuse loud

kind = reseed · owner = ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=sedreplace) · caught 2026-11-23

## .the cue that fired
a `--new @stdin` that held a newline (one import split into two lines) failed inside sed, yet the skill's tree ended on `updated`, with no file changed.

## .the gap, precisely
- the skill header says `--new @stdin` allows newlines in the pattern
- the apply path hands the text to `sed -e`, which ends the `s` command at the first newline: `sed: -e expression #1, char 120: unterminated 's' command`
- the skill swallows the sed exit code and reports `files: 10 · matches: 10 · updated`: a failhide

## .the shape of the fix
1. escape newlines in the replacement (`\` + newline for GNU sed), or do the replace in node, not sed
2. fail loud on any sed exit code other than 0, with the file named
3. a clamp test: a two-line `--new` applies, and a forced sed fault exits non-zero

## .why it is not done in this round
the skill ships from another repo; this route edited the ten files by hand instead.
