## .the shape of the fix

🔴 **ONE move, not two.** this section read *"two moves, and the first alone may suffice"* until the
2026-09-16 amendment. move 2 was already shipped before this dream was written, so there is one:

1. **redact the count in the sanitizer** — `1 blocker 🔴` / `2 blockers 🔴` → `[N] blocker(s) 🔴`, and
   `(1 > 0)` → `([N] > 0)`. the snapshot then pins what the case is actually about: **a guard that
   rejects off a raw base review**, which is true at any count above the threshold
2. ~~**wrap the block in `when.repeatably(REPEATABLE_CONFIG)`**~~ — 🔴 **ALREADY SHIPPED**, on every
   case in the file, and both sweeps failed anyway. see the struck row above

⚠️ **and the redaction is owed on BOTH sanitizers, never only the guard tree.** each sweep failed
in a **pair** — `sanitizeGuardTreeForSnapshot` and `sanitizeCapturedPeerForSnapshot` — because the
count appears in the guard's tree **and** in the captured peer's own `summary` block. a redaction
of one leaves the other red, and the sweep still reads `2 failed`.

⇒ so *"the first alone may suffice"* was right about move 1 and wrong about its scope: it is one
**kind** of move applied at **two** sites.

⚠️ the redaction must not swallow the **threshold**. `blockers exceed threshold (N > 0)` — the `0` is
the guard's declared bar and is deterministic, so it stays literal. only the left-hand count moves.
