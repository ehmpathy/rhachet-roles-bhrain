# case=5 — a transcript with compaction

cell: any · one · metered · compacted · finished · feel = happy · care = critipath (repaid
correctness) · boundaries = 6 + compaction

## .narrative

the foreman audits a long session they remember was compacted twice. they half expect the top
row to be the 300K review log a clone pulled in at call 120 — they nearly cut that reviewer's
output on a hunch last week.

they run `rhx reflect.on.token.spend --from <path>`. the header reads `rebases = 2`, each with cause
`compaction`, so they know the tool saw both. the review log sits mid-table: `repaid` charged it for 380 calls, up to the first
compaction at call 500, not for all 1,400. a separate row, `compaction.summary`, shows what the
compaction itself put back. at the top they find the boot — re-entered in every segment, which
no compaction removes.

the foreman drops the reviewer cut they nearly shipped and opens a dispatch on the boot instead.
the wrong cut was never made, because the instrument never ranked the dropped log as live.

## .timeline

```ts
given('[case5] a transcript with two compactions', () => {
  when('[t0] the foreman runs `rhx reflect.on.token.spend --from <path>`', () => {
    then('the header reports rebases = 2, each with cause compaction');
    then('repaid for a block ends at the first compaction after it entered');
    then('the compaction summary renders as its own inventory row');
    then('the inventory describes the context at the last call — the post-compaction context');
    then('efficiency totals still sum every call, before and after');
  });
});
```
