# 🌙 dream: repair the `rhx` skill banner — OFF stdout, and ONCE per run

🟡 **two defects, one banner.** the filename names the severe half (`--json` cannot pipe, at every
breadth, in every repo). the second half — the banner shown twice on a failure, ahead of the block
that names the fix — is the same banner in the same function, and is carried here rather than in a
second dream. both are measured below.

- kind  = `reseed` — the fix lives in `ehmpathy/rhachet`, not in this tree
- owner = `ehmpathy/rhachet`
- caught 2026-09-23

## .the cue that fired

stone `5.3.verification`, self review 6/8 (`has-critical-paths-frictionless`), whose guide demands
a **pasted** walk of each critical path. the consumer's path for `--of grove --json` is a pipe into
`jq`, so I walked it byhand rather than assert it:

```
$ rhx review._.cost --of grove --json | jq '{trees: .treesWalked, runs: .runsFound}'
parse error: Invalid numeric literal at line 2, column 5
```

⇒ it fails at **every** breadth, not only grove:

```
$ rhx review._.cost --of tree --json | jq '.tokens'
parse error: Invalid numeric literal at line 2, column 5
```

## .the gap, precisely

`rhx` prints its skill banner to **stdout**, unconditionally, ahead of every skill:

```js
// node_modules/rhachet/dist/contract/cli/invokeRun.js  (v1.47.5)
52  // log which skill will run
53  console.log(``);
54  console.log(`🪨 run solid skill repo=${skill.slugRepo}/role=${skill.slugRole}/skill=${skill.slug}`);
55  console.log(``);
```

so what reaches a pipe is three lines of chrome, then the document:

```
🪨 run solid skill repo=bhrain/role=reviewer/skill=review._.cost

{
  "root": "/home/camper/git/ehmpathy/_worktrees",
  ...
```

🔴 **rhachet already contradicts itself on this**, 100 lines down — the SAME banner, on stderr:

```js
160  console.error(``);
161  console.error(`🪨 run solid skill repo=${skill.slugRepo}/role=${skill.slugRole}/skill=${skill.slug}`);
```

⇒ the failure path knows the banner is chrome. the success path does not.

## 🔴 .and on a FAILURE both fire, so the banner appears TWICE

the two blocks are not alternatives. the head prints its banner ahead of the skill; the catch
prints its own when the skill exits non-zero. a human who mistypes one flag meets this:

```
$ rhx review._.cost --of fleet

🪨 run solid skill repo=bhrain/role=reviewer/skill=review._.cost


🪨 run solid skill repo=bhrain/role=reviewer/skill=review._.cost
   └─ ✋ blocked by constraints

🦉 --of "fleet" is not a breadth
   ├─ was:   renamed to `grove` — a fleet is ships; a grove is what holds trees
   ├─ valid: run | tree | grove
   └─ fix:   rhx review._.cost --of tree
```

⇒ **six lines of chrome, and a generic `✋ blocked by constraints` frame, ahead of the specific
block that names the fix.** `rule.require.errors-name-the-fix` wants the fix within reach;
nielsen 8 wants no noise that competes with the signal. this delivers neither, and it delivers
them in the worst order — the generic frame reads as the verdict, and the helpful block reads as
an afterthought.

🔴 **the stderr move does NOT repair this half.** send line 53 to stderr and a refusal still shows
the banner twice, both on stderr. the two defects share ONE cause — a single banner, owned by two
paths that do not know about each other — and need two different lines of repair:

| # | the defect | the repair |
|---|---|---|
| 1 | banner on **stdout**, so `--json` cannot pipe | `console.log` → `console.error` at 53-55 |
| 2 | banner shown **twice** on a failure | the catch re-states what the head already said. drop it, and let the head be the only banner |

🟡 they are filed as one dream on purpose: one banner, one function, one owner. whoever repairs #1
is already in the lines that carry #2, and a reader who meets only one will re-derive the other.

**there is no escape hatch.** `invokeRun.js` reads no `process.env` at all — no `--quiet`, no
`RHACHET_QUIET`, no json awareness. grep is empty.

## .the blast radius — this is NOT one command

it is **every `rhx` skill that emits machine-readable output, in every repo**. any
`rhx <skill> --json | jq`, any `| python -c`, any consumer that parses stdout. a `--json` flag is a
promise of a machine-readable document, and the runner breaks it before the skill ever starts.

🟡 it is also why the defect survived a 131-test acceptance suite — see *"what this taught"*.

## .the shape of the fix

one line, and the repo already shows which one:

```diff
- console.log(``);
- console.log(`🪨 run solid skill repo=…`);
- console.log(``);
+ console.error(``);
+ console.error(`🪨 run solid skill repo=…`);
+ console.error(``);
```

**the banner is status, and status belongs on stderr** (`rule.require.status-feedback`): a human at
a tty still sees it, and a pipe carries only the payload. that is the same split this very stone
made for the grove progress stream, for the same reason.

⚠️ **it is a behavior change with a real blast radius**, so it owes a clamp: a test that pipes a
`--json` skill's stdout into a parser and asserts it parses. and any consumer that greps *stdout*
for the banner — a hook, a log scraper, a test harness — moves to stderr with it.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), both legs fail:

| leg | verdict |
|---|---|
| **safe?** | 🔴 **no.** it changes stdout for every skill in every repo. any consumer that reads the banner off stdout breaks silently |
| **clean?** | 🔴 **no.** the file is `node_modules/rhachet` — another repo entirely. this branch touches not one file there |

⇒ a `reseed` dream is the sanctioned disposition for a fix whose home is another tree.

## 🔴 .what this taught, and it is the sharper half

**my acceptance suite could never have caught this, and it looked like it had.**
`reviewCost.acceptance.test.ts` spawns the *module*, by its package subpath, then `node -e`s an
import of it — where a human types `rhx review._.cost`. **the banner is emitted by the layer between
them**, so 131 tests — including a json-purity clamp written in this same stone, and called strong —
grade a path nobody walks.

⇒ the same shape as R9, one layer out: **a test grades the artifact it was pointed at; a runthrough
grades the artifact a human meets.** the entrypoint a test spawns IS part of what it clamps, and an
acceptance test that reaches past the published entrypoint has quietly narrowed its own scope.
