the `route/brain/` module by many releases:

| where | what it declares |
|---|---|

```
  → 78 clusters. not one is `halt`, and no boundary-qualified form of it exists either.
```

⇒ and `rule.require.domain-term-itemization`'s test is met outright: `asHaltParts` is a declared
domain operation of this repo, and `halt` is the noun its verb acts on.

## 🟡 .why it is a WIDER gap than the reviewer stated

the given reached `halt` through `StoneBrainHaltCause` — one new type on a feature branch. but the
word's real weight is in the **status line every driver reads on every stone**, and in a closed
verdict set no feature may extend. ⇒ **the cluster it is owed is the route's, not this feature's**,
and a cluster written from a brain-feature's perspective would be scoped wrong from birth.

## .the shape of the fix

```
term=route.stone.halt._.choice._.md         # the noun, boundary = route.stone
term=route.stone.halt._.choice.reason.md    # the etymology + the closed-set argument
```

the boundary answer to *"$word, of WHAT?"* is **a stone** — a halt is a stone's, never a route's:
the route continues; the stone stops.

what the `.reason` owes, and none of it is available from this branch alone:

- 🔴 **why the four-word set is CLOSED**, and what that costs a feature. this branch measured it:
  no fifth glyph is available, so every brain halt renders as `✋ blocked`. a reader who does not
  know the set is closed reads that as a choice
- the forbidden synonyms — `stop`, `abort`, `fail`, `error` — each of which names an outcome where
  `halt` names a **state a driver can act on**
- the seam with `blocked`: `blocked` is one halt WORD; `halt` is the genus. ⚠️ that is the
  ambiguity check `rule.forbid.domain-term-ambiguity` would run, and it needs the passage ledger's
  own history to settle
