🔴 **`[t2]` is the boundary of the lapse, and it was stated BACKWARDS until `r2` self-review.** this
section read *"the driver's own edit is what lapses its own stance"*, and derived an order trap from

**the source refutes it.** `getLiveReviewAbsorptions.ts:50-52` compares `stance.given` against the
slug's latest **`.given` FILE PATH**. a given is written when the guard runs that reviewer; a driver's
edit writes none. ⇒ **an edit lapses naught**, and the operation's own `.note` at `:25-26` says the
trigger in prose: *"the lane spoke again."*

| order | outcome |
|---|---|
| ✅ concede → **fix** → top-up → re-arrive | **granted.** the fix does not touch the key — `S11`'s own sequence, verbatim |
| 👎 concede → re-arrive → *the lane runs* → top-up | refused. the lane spoke, so the stance answers a question no longer asked |

next **run** of that lane — and at `C = exhausted`, where every refusal demo sits, the lane is

## .why it fails safe

**fast** — a ledger read, already implemented · **loud** — the two iteration numbers are printed, so
the lapse is checkable rather than asserted · **teaches the fix** — the current concern's concede is
offered as the lift, so the driver is never stranded · **cannot be hoarded** — a stance is spent on
the round it answers, so no driver accumulates permissions across a long stone.

🔴 **the property this cell protects is the one the wish cares about most.** without the lapse, one
urgent concession at round 2 is a licence to top up forever — *"a permission that never expires"*, in
the wish's own words, which is the free lever with an extra step.
