# case 1 — the-stone-switches-my-brain

**actor** = driver-clone · **feel** = happy · **care** = critipath
**cell** = `driver-clone × apply × other-known × live`

## .the narrative

i am the driver. i have just passed `3.3.1.blueprint` — a hard stone, and i was on opus for it
because a human typed `/model` before we started. now `5.2.execution.phase1` is next, and it is
routine: stamp files that the blueprint already decided.

i do not think about my brain. i run `route.stone.set --as passed` and read the next stone.

between those two moments, one line appears that i did not type:

```
🗿 5.2.execution.phase1
   └─ brain switched → claude-sonnet-5[1m]   (prescribed by 5.2.execution.phase1.guard)
```

my next turn is cheaper and faster, and nobody had to remember. the stone knew what it was worth.

the part that matters is what i did **not** have to do. i did not read the guard. i did not judge
whether this stone is worth opus — the human who wrote the guard already made that call once, for
every drive that will ever walk this route. i did not type `/model`, so i cannot forget to.

⇒ **the "aha": the brain is a property of the work, not of the session.** a stone is worth what it
is worth. before this, the brain was set by whoever launched the drive and then drifted for the
whole route — one decision, made at the worst possible moment, applied to work nobody had read yet.

## .the bdd `[tn]` timeline

```
given a driver enrolled as @:driver, reach=LIVE, live brain = claude-opus-5[1m]
  and  a stone 5.2.execution.phase1 whose guard declares `brain: claude-sonnet-5[1m]`

  when [t0] the driver passes 3.3.1.blueprint, and route.drive names 5.2.execution.phase1 next
    then the driver-role hook reads `brain:` from 5.2.execution.phase1.guard
    and  it resolves claude-sonnet-5[1m], and reads NO live brain — it runs no compare (F14)

  when [t1] the hook confirms the target BEFORE it dispatches aught
    then it runs `clone whoami` first, and reads its own serial and slug
    and  it dispatches only to that confirmed address — never to a slug it assumed

  when [t2] the hook dispatches `/model claude-sonnet-5[1m]` into the confirmed address
    then it hands the switch off and returns at once — it does not wait on its own brain (case 5)
    and  the driver's stdout names the stone, the brain, and that the guard prescribed it

  when [t3] the driver takes its first turn on 5.2.execution.phase1
    then it runs on claude-sonnet-5[1m]
    and  the driver typed no `/model` at any point
```

## .the boundaries this walk crosses

| boundary | where |
|---|---|
| guard parse — does a `brain:` key resolve | `[t0]` |
| 🔴 ~~difference — does the declared brain differ from the live one~~ | **deleted by `F14`** — the applier converges, so no branch sits here to cross |
| identity — is the addressed clone the live driver | `[t1]` |
| dispatch — does the say reach the pty input | `[t2]` |
| re-entrancy — does the hook return without a wait on itself | `[t2]` |
| turn — does the next turn run on the new brain | `[t3]` |

## .what makes it happy rather than sharp

`[t1]` is the guarantee. `clone whoami` runs **before** the say, so a hook active in the wrong
context refuses rather than switches the wrong clone's brain. the wish names that as the sequence,
and this case is where the sequence pays: the happy path is happy **because** the confirmation
already ran.
