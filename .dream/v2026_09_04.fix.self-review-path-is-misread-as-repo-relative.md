# 🌙 dream: the self-review prompt's path is read as repo-relative, and the miss destroys files

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, by `review.self r4 has-consistent-conventions` on
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

I wrote a self-review to the **repo root** rather than the route dir — **three times in one round**,
after each correction. a mistake that recurs after it has been noticed is not a lapse; it is a
surface that misleads.

## .the gap, precisely

the guard prints the target inside a treestruct:

```
   │  ├─ articulate into
   │  │  ├─ .behavior/v2026_09_03.…/review/self/for.5.1.execution.from_vision._.r4.$slug.md
   │  │  └─ the guard looks precisely here, write exactly to this path
```

the path **is** correct and complete. what misleads is the **frame**: at a glance the `├─` glyph
column reads as a path separator, so the eye takes `review/self/…` as the operative part and the
`.behavior/$route/` prefix as breadcrumb. the write then lands at `review/self/…` from the repo
root — which is a **real, tracked directory in this repo**.

🔴 **and that is what turns a typo into data loss.** the wrong path is not empty; `review/self/`
holds committed reviews from prior behaviors (`ac4fe20`, #333). so the sequence runs:

1. write the review to the root by mistake
2. notice, move the file to the route dir
3. remove the now-"stray" `review/self/` directory
4. ⛔ **the directory was never stray** — step 3 deletes the prior behavior's reviews

**measured this round: three tracked files destroyed**, two of them for stone `5.3.verification`,
which this behavior never touched. restored from the `rmsafe` trash.

⚠️ **every gate stayed green throughout.** types, lint, format and 1437 unit tests all pass with
those files gone, because they are markdown from a closed behavior. only a whole-tree `git status`
could see it — which is to say, **the loss is silent by default.**

## .the shape of the fix

three candidates, cheapest first — they compose, and the third is the one with teeth:

1. **mark the boundary in the render.** print the route prefix and the leaf as visibly one string,
   e.g. `$route ⟶ review/self/$file`, or repeat the full path on the `└─` confirm line rather than
   the prose *"write exactly to this path"*.
2. **name the hazard where the mistake lands.** the prompt already spends a line on *"the guard
   looks precisely here"*; that line could say *"this path is repo-root-relative — `review/self/`
   at the root is a DIFFERENT, tracked directory"*.
3. 🔴 **make `rmsafe` refuse a directory that holds tracked files the caller did not add.** the
   deeper defect is not the misread — it is that the **repair** for a misplaced *file* was the
   removal of a *directory*. a guard there would have caught all three occurrences regardless of
   what the driver misread.

⇒ (3) generalizes past this prompt: any cleanup that removes a container to undo a mistake that
created a member has the same failure mode.

## .why it is not done in this round

**the misread is mine and the surface is not.** (1) and (2) change the guard's rendered prompt,
which has snapshot coverage and is read by every driver on every stone in every repo on this engine
— a contemplation-gate diff is the wrong place to move it. (3) changes a shared `rmsafe` skill in
the ehmpathy tree, which this behavior does not touch at all.

⇒ each is small, each is independent, and each wants a diff where it can be reviewed as one.
