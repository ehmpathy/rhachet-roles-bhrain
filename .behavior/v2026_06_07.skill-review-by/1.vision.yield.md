# vision: review.by skill

## the outcome world

`review.by` lives in bhrain and orchestrates a role's standard review set. each role declares its rubrics in one config file; bhrain reads that file and runs every rubric against the target code.

roles in ehmpathy shipped an adhoc bash version of this as a stopgap. once bhrain's `review.by` is available, roles delete their adhoc bash and call bhrain's skill instead. roles keep only `rubrics.yml` — the what. bhrain owns the how.

### a day-in-the-life

**before:**
```bash
# mechanic wants their standard reviews — one review call per rule bundle
rhx review --rules '.agent/**/rule.require.failfast*.md' --paths 'src/**/*.ts'
rhx review --rules '.agent/**/rule.forbid.failhide*.md' --paths 'src/**/*.ts'
rhx review --rules '.agent/**/rule.forbid.*mocks*.md' --paths 'src/**/*.ts'
# ... remember which globs go together, copy-paste from prior sessions
```

**after:**
```bash
# run every rubric the mechanic role declares
rhx review.by --role mechanic --paths 'src/**/*.ts'

# run one rubric
rhx review.by --role mechanic --for mech-failhides --paths 'src/**/*.ts'

# eval: same inputs, compare brains
rhx review.by --role mechanic --for mech-failhides --brain fireworks/deepseek/v4-flash
```

### the "aha" moment

when a mechanic types `rhx review.by --role mechanic --paths 'src/**/*.ts'` and sees:

```
🦉 not even a vole

🔍 review.by --role mechanic
   └─ rubrics
      ├─ r1 mech-failhides ✓
      └─ r2 mech-decode-friction ✓
```

...they never have to remember which rules go together. the role's `rubrics.yml` already knows.

## user experience

### usecases

| who | goal | command |
|-----|------|---------|
| mechanic | run all rubrics | `rhx review.by --role mechanic --paths 'src/**/*.ts'` |
| mechanic | run one rubric | `rhx review.by --role mechanic --for mech-failhides --paths 'src/**/*.ts'` |
| architect | run all rubrics | `rhx review.by --role architect --diffs since-main` |
| ci/cd | quick check | `rhx review.by --role mechanic --diffs since-main --mode pull` |
| eval harness | compare brains | `rhx review.by --role mechanic --for mech-failhides --brain $brain` |

### contract inputs

| arg | required | forwarded to review | description |
|-----|----------|---------------------|-------------|
| `--role` | yes | no | role slug; bhrain locates that role's `rubrics.yml` |
| `--for` | no | no | single rubric slug; default: all rubrics |
| `--paths` | no | yes | target file patterns |
| `--diffs` | no | yes | diff scope (since-main, since-staged) |
| `--mode` | no | yes | pull or push |
| `--brain` | no | yes | brain override for evals; default: `fireworks/deepseek/v4-flash` |
| `--output` | no | partial | output dir; default: `.reviews/by=$role/` |

### contract outputs

**stdout has two shapes, keyed on scope:**

| invocation | scope | stdout |
|------------|-------|--------|
| `review.by --role X` (no `--for`) | the review set | the review.by summary tree |
| `review.by --role X --for <rubric>` | one review | the base `rhx review` stdout, verbatim |

#### aggregate run (no `--for`) → the review.by tree

a treestruct with guard-compatible summary counts.

pass (no findings):
```
🦉 not even a vole

🔍 review.by --role mechanic
   └─ rubrics
      ├─ r1 mech-failhides ✓
      └─ r2 mech-decode-friction ✓
```

findings:
```
🦉 needs your talons

🔍 review.by --role mechanic
   ├─ rubrics
   │  ├─ r1 mech-failhides ✗
   │  │  └─ 2 blockers 🔴
   │  └─ r2 mech-decode-friction ✗
   │     ├─ 1 blocker 🔴
   │     └─ 3 nitpicks 🟠
   └─ summary
      ├─ 3 blockers 🔴
      └─ 3 nitpicks 🟠
```

#### single-scope run (`--for`) → disintermediate to the raw review

when `--for` narrows to one rubric, review.by is a bare resolver around a single review, so it
emits that base review's stdout VERBATIM — no `🔍 review.by` anchor, no `rubrics` bucket, no
`r1 <slug>` row. the output is indistinguishable from a plain `rhx review`:

```
🦉 needs your talons
   ├─ review: .reviews/by=mechanic/rubric=mech-failhides.md
   └─ summary
      ├─ 2 blockers 🔴
      └─ 0 nitpicks
```

**why disintermediate:** the primary consumer of `--for` is a route guard peer review. the guard
captures the peer stdout, tallies off it, and wraps it in its OWN peer tree. if review.by --for
emitted its own tree, the guard would nest a review.by tree inside its tree — review info doubled.
disintermediation makes `review.by --role X --for <rubric>` a drop-in for a plain `rhx review` in
any guard peer slot. (see `rule.require.review-by-disintermediates`.)

**both shapes carry the guard-parseable summary** — the `N blockers` / `N nitpicks` lines a route
guard `reviewed?` mechanism reads:
- `/(\d+)\s*blockers?/i`
- `/(\d+)\s*nitpicks?/i`

**exit codes:**
- 0 = all rubrics passed (no blockers)
- 1 = malfunction (role or rubrics.yml absent, invalid yaml)
- 2 = constraint (any rubric has blockers)

**files:** each rubric writes its review to `.reviews/by=$role/rubric=$slug.md`.

### timeline

1. **invoke** — user runs `rhx review.by --role $role [--for $slug]`
2. **locate** — skill finds `.agent/repo=*/role=$role/briefs/reviews/rubrics.yml`
3. **read** — skill parses rubric slugs and their rules
4. **filter** — if `--for`, narrow to that one rubric
5. **execute** — skill runs `review` per rubric one at a time (serial), with the shared paths/diffs/brain — the same `for...of await` shape the route guard uses
6. **collect** — skill waits for all, parses blocker/nitpick counts from each
7. **emit** — if `--for` (one review), print that review's stdout verbatim (disintermediate);
   else print the review.by treestruct summary
8. **exit** — 0, 1, or 2

## mental model

### how users would describe it

> "review.by is the role's standard review set. the role already knows what to look for."

### terms

| user says | we say | what it is |
|-----------|--------|------------|
| "review set" | rubrics.yml | the config file that declares a role's rubrics |
| "check" | rubric | one named bundle of rules (e.g., `mech-failhides`) |
| "run all" | `--for` omitted | review against every rubric |
| "run one" | `--for $slug` | review against a single rubric |

note: `rubric` = the atomic bundle. this matches the terminology already shipped in ehmpathy roles. we drop the earlier "focus" term.

### rubrics.yml format

each role declares `briefs/reviews/rubrics.yml`:

```yaml
# optional vibe override (default: bhrain owl 🦉 / 🔍)
vibe:
  mascot: 🐢
  artifact: 🐚

rubrics:
  - slug: mech-failhides
    purpose: detect hidden errors and failhide patterns
    rules:
      - .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/pitofsuccess.errors/rule.*.md
      - .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.test/pitofsuccess.errors/rule.*.md

  - slug: mech-decode-friction
    purpose: detect inline decode-friction that hides intent
    rules:
      - .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/readable.narrative/rule.forbid.inline-decode-friction.md
      - .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/readable.narrative/rule.require.named-transformers.md
```

| field | required | description |
|-------|----------|-------------|
| `vibe` | no | mascot + artifact override; default owl 🦉 / 🔍 |
| `rubrics` | yes | the rubric definitions |
| `rubrics[].slug` | yes | unique rubric identifier |
| `rubrics[].purpose` | no | human description |
| `rubrics[].rules` | yes | rule file glob patterns |

## evaluation

### how well does it solve the goals?

| goal | solved? | notes |
|------|---------|-------|
| bundle reviews per role | ✓ | `rubrics.yml` declares a role's rubrics |
| single command | ✓ | `rhx review.by --role $role` |
| serial execution | ✓ | one rubric at a time, like the route guard (parallelism deferred) |
| guard integration | ✓ | summary has parseable count lines |
| eval comparisons | ✓ | `--brain` override, same inputs across brains |
| configurable mascot | ✓ | `vibe` block in rubrics.yml |
| replace ehmpathy adhoc | ✓ | roles delete adhoc bash, keep only rubrics.yml |

### pros

- **one home:** bhrain owns the orchestration; roles own only config
- **simple:** one command instead of many
- **composable:** forwards to extant `review`
- **eval-ready:** `--brain` override preserved from the adhoc skills
- **extensible:** add rubrics via yaml, no code

### cons

- **discoverability:** user must know which rubrics a role declares
- **maintenance:** roles maintain their rubrics.yml

### edge cases and pit of success

| edge case | handled how |
|-----------|-------------|
| role not found | fail fast: "role not found at .agent/repo=*/role=$role" (exit 1) |
| rubrics.yml absent | fail fast: "rubrics.yml not found for role $role" (exit 1) |
| `--for` slug not found | fail fast: "rubric not found: $slug" (exit 1) |
| duplicate slugs | fail fast: "duplicate rubric slug: $slug" (exit 1) |
| no rules match glob | forward to `review` — it degrades gracefully |
| one rubric malfunctions | capture, continue others, exit reflects worst outcome |

## open questions & assumptions

### assumptions

1. **bhrain owns `review.by`** — roles call it; roles do not reimplement it.
2. **rubrics.yml lives at `briefs/reviews/rubrics.yml`** per role — matches shipped ehmpathy layout.
3. **rules are inline in rubrics.yml** — bhrain reads them directly; no per-rubric standalone skill needed.
4. **`--brain` preserves the eval hook** — the adhoc atomic skills defaulted a brain and allowed override; bhrain carries this forward.
5. **mascot + artifact are per-role** — via the `vibe` block; default is bhrain owl.
6. **serial execution for now** — rubrics run one at a time (`for...of await`), mirrors the route guard; parallelism is deferred, not required for the mvp.

### migration

roles that shipped adhoc bash (`review.by.sh`, `review.rubric=$slug.sh`) replace all of it with a call to bhrain's `review.by`. they keep only `rubrics.yml`, with rules inline. the standalone rubric skills are no longer needed — bhrain reads the rules from the yml and drives `review` itself.
