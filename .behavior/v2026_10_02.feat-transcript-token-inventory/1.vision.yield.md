# 1.vision — reflect.on.token.spend: what a transcript cost, and what it bought

> the cache decides the price per token. the context decides how many.
> this instrument names what the context holds, and what each part cost to keep.

## .the outcome world

### before

a clone ends a 1,000-call session. 393M tokens were re-read. a human asks *"what do we cut?"*
the honest answer today is a guess: someone counts characters in a brief, divides by four, and
ships a compression nobody can prove saved aught.

the proposal ranks TARGETS, which the tool can measure. the hint beside each is a fixed line per
category, never a claim about this transcript — the tool cannot know which brief was never cited.

(figures illustrative; the token rows reproduce the #532 measurement. the `$` is priced at the
current opus 5.5 rates — input $4 · 5m cache write $5 · cache read $0.20 · output $20 per MTok,
where a cache read costs 0.05× input on opus 5.5 and sonnet 5.5 and 0.1× on prior models. source:
a webfetch summary of platform.claude.com/docs/en/about-claude/pricing on 2026-10-21, a pointer
only; the tool reads its rates from the brain atom specs, never from this line.)

### the aha

**the `repaid` column.** a 40K log dump at call 12 of a 1,000-call session costs 40K × 988 ≈ 39.5M
tokens, and it was read once. no extant instrument names that number. once it is on screen, the
compression is no longer a debate — it is a sort.

🟡 **and price, not tokens, says which sort.** at opus 5.5 rates a cache read costs 1/25 of a
5-minute cache write, so 393M re-read tokens cost $78.60 while 39.4M written tokens cost $196.91.
a token count ranks the re-read boot first; the price shows the cache churn (blocks written, or
re-written after an expiry) as the larger bill. this is why price leads (S4).

## .the contract

| aspect | proposal |
|---|---|
| verb | `rhx reflect.on.token.spend` — a peer of `reflect.snapshot` and `reflect.savepoint` |
| input | `--from <path \| session-uuid \| glob \| @current>`, repeatable; default `@current` |
| roots searched for a uuid or `@current` | `$CLAUDE_CONFIG_DIR/projects`, then `~/.claude/projects` |
| output | treestruct stdout (snapshotted). no `--output json`: the one future consumer (the gate) composes the reader operation directly |
| units | price leads `repaid` and the proposal rank (the only unit that knows read from write from input); tokens sit beside every price. the inventory leads with tokens — its question is how full the window is |
| exit | 0 report · 2 constraint (not found, no metered calls) · 1 malfunction |

### the three tiers of a figure, each labeled on screen

| tier | source | used for |
|---|---|---|
| **measured** | `message.usage`, deduped by `requestId` | the whole efficiency section; the total of every inventory; `assistant.own` (the prior call's `output_tokens`) |
| **exact** | a context growth between two calls in which ONE category arrived | an inventory row with that tag |
| **apportioned** | a context growth split across several categories by byte share of the MODEL-VISIBLE text | an inventory row with that tag |
| **priced** | tokens of any tier above × the rate for that call's `message.model`, per token kind (input · cache.read · cache.write · output), from the rhachet brain atom's `spec.cost.cash` (iso-price) | every `repaid` and proposal figure (primary), and the `$` beside each efficiency row. a model with no spec, or a rate its spec lacks (the 1h cache write), renders `unpriced` — never guessed |

🟡 **a block's span, per call.** the provider caches by prefix, so a call's prompt reads as three
spans in order — `cache.read` (the front), `cache.write` (the next stretch), raw `input` (the tail),
sized by that call's `usage`. a block's position in the prompt is known (system prompt + tool
schemas first, then records in transcript order), so per call its tokens fall in one span, or are
cut at a boundary, and take that span's rate. an expired cache shows as the block back in the write
span: a re-write is priced as a write, never assumed a read.

🟡 the byte share reads the text the model sees — a `tool_result.content`, a hook's `content`,
an `instructions` file's `content` — never the jsonl record's size. a `hook_success` record holds
its payload twice (`content` and `stdout`), so a record-size share would double-count every hook.

no figure is ever chars/4 on its own. every apportioned token sits inside a measured delta, so
rows always sum to the measured total — and `unattributed` absorbs whatever no record explains.

### the categories

| category | what it holds | how it is found |
|---|---|---|
| `boot.instructions` | CLAUDE.md and its imports — the role boot | `attachment.type = instructions` |
| `hook.output` | sessionstart / pretooluse / stop hook payloads | `attachment.type = hook_success` (+ peers) |
| `system.reminder` | per-call harness injections | `attachment.type` ∈ {total_tokens_reminder, date, skill_listing, …} |
| `tool.result` | per tool name, via the `tool_use.id` it answers; `Bash` further split by command head (`rhx <skill>`, else the first word) | `user` record with `tool_result` blocks; the command from the matched `tool_use.input.command` |

🟡 the `Bash` split is what makes #532's *"review output"* category visible: review spend arrives
as `Bash · review` and `Bash · route.stone.set` (guard halts print reviewer output). without the
split, every skill's output hides inside one `Bash` row.
| `assistant.own` | text, thought, and tool_use input | **measured**: call N's `output_tokens` is what the assistant adds to call N+1's context. never by bytes — the jsonl redacts thought text (measured: ≤282 chars stored against up to 5,555 output tokens) |

🟡 so each delta is first reduced by the prior call's `output_tokens`; only the remainder (tool
results, hooks, reminders, human words) is split by byte share. that shrinks what F3's
assumption ever touches.
| `human.words` | what the human typed | reuse `isHumanTurn` (`telepath/getLastHumanUtterance.ts:17`) |
| `unattributed` | the harness system prompt and tool schemas | the remainder of each delta — no record carries them |

### the seam with its two peers

| the meter | its subject | its corpus | its tense |
|---|---|---|---|
| `review-cost-meter` | the L1 peer reviewers a guard binds | `.log/bhrain/review/$ts/` | per review |
| `clone-token-meter` | a live clone's budget — a gate | a ledger not yet built | prospective |
| **`reflect.on.token.spend`** | any transcript — an audit | `*/projects/**/*.jsonl` | retrospective |

⇒ **this tool's reader is what `clone-token-meter` would consume.** the gate needs the same
per-call usage, deduped the same way, from the same file. so the reader (`getTranscriptCalls` —
parse + dedupe + order) is built here as a separate operation, and the gate later composes it.
that re-shapes the `clone-token-meter` row: its hard half ships here.

## .mental model

- *"it's a receipt for the session, itemized."* the efficiency half is the total at the bottom;
  the inventory is the line items; `repaid` is the line item × how many times you were charged.
- a human says *"what ate the context?"*; we say *"inventory by category."* a human says *"what
  did it cost to keep that around?"*; we say *"repaid."*
- **call, not turn.** the provider meters one `requestId`. a human "turn" may span many calls.
  the report counts calls and says so, because #532's "1,059 turns" are in fact 1,059 calls.

## .evaluation

| goal (wish) | met by |
|---|---|
| tokens in/out, cache read vs write | efficiency section, read and write never merged |
| context re-paid per call | `context.per-call` + `repaid` |
| inventory by category, as shares | inventory section, shares of the measured total |
| a ranked proposal | proposal section, ranked by share of `repaid` |
| any transcript on the machine | `--from` path / uuid / glob; two roots searched |

**pros:** every number traces to a provider field · `unattributed` keeps the shares honest ·
the reader is reusable by the future gate.

**cons:** within a multi-category delta the split is proportional to bytes, so a row tagged
`apportioned` is a measured total shared by an assumption · a 5.7 GB corpus (measured on this
machine) makes a whole-machine glob slow; it must stream.

### edgecases, and the pit of success

| edge | the contract keeps the human safe by |
|---|---|
| one call → several assistant records with the same `requestId` | dedupe by `requestId`; a naive sum double-counts (measured: 29 assistant records, 15 calls) |
| the live transcript's last line is half-written | skip a final unparseable line, and say `1 partial line skipped` |
| a malformed line mid-file | one transcript (or its subagent file) → exit 1 with file + line — mid-file corruption is not a live tail; corpus → that file skipped and named under `skipped (malformed)`, the rest reported (F6); every corpus file malformed → exit 1 |
| compaction shrinks the context | detect the drop; `repaid` for pre-compaction blocks stops at the compaction call |
| subagent transcripts (`<uuid>/subagents/*.jsonl`) | reported as their own rows under the parent; the parent sees only the `Task` result |
| a test-fixture transcript with zero `usage` | single path → exit 2 with the fix; corpus → skipped and counted |
| a uuid present under both roots | list both and exit 2; never pick one silently |
| a sidechain call, or a call to another model, interleaved in the main file | the delta sequence follows the main thread only (`isSidechain` false, the session's own model); other calls count in efficiency, never in a delta |
| a context SHRINK with no compaction marker | never attributed as negative tokens; the drop is reported as `context shrink (unexplained)` with its call number, and the inventory re-bases from the next call |
| prior thought blocks dropped from later context by the harness | `assistant.own` is measured by the delta it adds, and its `repaid` ends where the context stops to carry it — see open question 9 |

## .what is awkward

- **`apportioned` is a word a reader must learn.** the tag is honest, but a share tagged
  `apportioned` will still be quoted as fact. the tag must sit on the same line as the number.
- **the biggest row is only half actionable from here.** `boot.instructions` is 46%, and its
  record splits by FILE (`files[]`) — but nearly all of it sits in one file, `boot.md`, so the
  inventory still cannot say which BRIEF inside is waste. a per-brief split must parse
  `<brief.say path=…>` markers — possible, because the boot is tagged, but that parses rhachet's
  boot format, a second contract this tool would then depend on.
- **the `unattributed` row is a permanent floor.** no transcript field will ever shrink it.
- **two roots surprise a human** who knows only `~/.claude`. the not-found error must name both,
  or a correct uuid reads as absent.
