# 🌙 dream: a SOME-criteria `when.repeatably` passes once any attempt passes

- kind: reseed
- owner: ehmpathy/test-fns (`when.repeatably`), and this repo's `patches/test-fns@1.15.7.patch`
- caught 2026-11-05

## .the cue that fired

on PR #742, run 41955908646, shard `test-shards-integration (dynamic, 3, 3)`,
`stepReview.casePromptCache` `[case1]` ran under `criteria: 'SOME'`, attempts 3. attempts 1 and 2
passed every `then`. attempt 3 still ran, failed two `then` blocks, and the suite went red. the
rerun (job 127014364238) repeated the same shape.

## .the gap, precisely

`src/.test/infra/repeatably.ts` promises: under SOME, the test passes as soon as 1 of 3 attempts
passes, and later attempts are skipped. the observed harness does neither. it runs every attempt,
and a failed `then` in any attempt fails the suite. so SOME grades as EVERY, and every suite that
leans on `REPEATABLY_CONFIG` to absorb a transient host fault does not get that absorption.

## .the shape of the fix

- in test-fns: under SOME, once an attempt passes all its `then` blocks, mark later attempts
  skipped, and fail the `when` only when no attempt passed
- a clamp in test-fns: a `when.repeatably({ attempts: 3, criteria: 'SOME' })` whose third attempt
  fails a `then` must report green (red today)
- here: check whether `patches/test-fns@1.15.7.patch` causes or masks this; drop it once the fix ships
- here: a unit clamp on the same shape, so a test-fns bump that regresses it goes red in this repo

## .why it is not done in this round

the fix lives in test-fns, another repo; a tree changes only its own repo. this round gates
`casePromptCache` behind `RHACHET_LIVE_BRAIN`, which takes it off the default run but leaves the
harness defect in every other repeatable suite.
