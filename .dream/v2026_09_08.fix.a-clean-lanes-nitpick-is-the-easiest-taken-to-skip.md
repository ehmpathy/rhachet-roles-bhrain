# 🌙 dream: make the `.taken` debt legible when a lane returns `0 blockers`

**kind** — fix · **owner** — bhrain (this repo) · **caught** 2026-09-08

## .the cue that fired

iteration i020 of `1.vision` returned **`0 blockers` on both lanes**, with a single nitpick on one
of them. i re-arrived at i021 with **no `.taken.by_self` authored for either lane**.

i021's other lane then raised **the same nitpick, in near-identical words** — the exact mechanism
`rule.always.converge-with-reviewers.via-a-taken-per-point` names: *"the reviewer drops a point that
carries a response and re-raises one that does not."*

## .the gap, precisely

**a clean-header lane with a lone nitpick is the cheapest point in the ladder to skip**, and the
guard's own output is what makes it cheap:

| the driver sees | what it implies | what is actually owed |
|---|---|---|
| `approved 49.2s` | the lane is done | naught more, for the lane |
| `0 blockers ✓` | passage is not at risk | **correct** — and irrelevant to the debt |
| `1 nitpick 🟠` | below the `--allow-nitpicks 7` threshold | 🔴 **one `.taken`, before re-arrival** |

⇒ every visual cue on the line says *proceed*, and the one obligation on it is drawn as the smallest
element. the judge's threshold governs **passage**; it governs the `.taken` debt **not at all** — but
no part of the output draws that seam.

### the checkable evidence

- `.reviews/peer/1.vision._.review.i020.e2b4399509af1ff531.r001._.given.by_peer.dimensional-decomposition.report.md`
  — the nitpick, raised
- `.reviews/peer/1.vision._.review.i021.4c5afcc46b1f8e68f5.r002._.given.by_peer.experience-coverage.report.md`
  — the same nitpick, re-raised one round later by the **other** lane
- both i020 `.taken.by_self` files carry an `authored late` note and a `2026-09-08` date that
  postdates i021

⚠️ **the cost is measurable**: one full review iteration, both lanes, spent to be told what had
already been told.

## .the shape of the fix

two candidates, and the second is the one that bites:

1. **a brief** — sharpen `via-a-taken-per-point` with the clean-lane cue: *"a lane that returns
   `0 blockers` with one nitpick owes exactly as much prose as a rejected one."* cheap, and it is a
   better cue rather than a gate.

2. 🔴 **a mechanism, in the guard** — before a re-arrival runs the lanes, check every point in the
   prior iteration's `.given.by_peer` for a paired `.taken.by_self`, and refuse the arrival with the
   unanswered points named. **the guard already computes the paths it would look at**, so the check
   is a file-existence test against a list it holds, not a new traversal.

⇒ prefer 2. the rule was in my booted context, i agreed with it, and i skipped it anyway — which is
the situation `rule.require.specialize-a-rule-its-readers-look-past` says a brief alone does not
reach. the honest bound is that a specialization is the **first** move; this rule has now been
looked past on the record, so it has earned the mechanism.

⚠️ **and the guard tree is worth a second look regardless of which lands.** a lane's `.taken` debt is
invisible there today — it draws given-paths and taken-paths as two symmetric rows even when the
second file does not exist.

## .why it is not done in this round

**safe?** yes — a guard-side check is additive and refuses rather than mutates.
**clean?** 🔴 **no.** it changes the arrival contract for **every** route in this repo, and every
extant route with an unanswered historical point would begin to refuse. that ripples far past the
diff this wish owns, and it wants its own migration decision.

⇒ and the round it belongs to is close by: **this wish restructures the very code path that runs
these lanes**, so the check has a natural home once the concurrency restructure lands.
