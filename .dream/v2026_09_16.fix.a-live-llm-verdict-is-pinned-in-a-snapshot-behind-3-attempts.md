# 🌙 dream: a live-LLM verdict is pinned in a snapshot, and 3 attempts is not enough

- kind = `fix`
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught = 2026-09-16

## .the cue that fired

a full `--what acceptance --thorough` run came back `3430 passed, 2 failed`. both failures were one
case in `blackbox/review.by.guard-peer.acceptance.test.ts`:

```
● review.by.guard-peer.acceptance › [case-seam-pass-aggregation] … code is clean
  › [t0] the stone is passed → the guard approves off a raw base review, attempt 1
  › the guard-tree stdout is stable (full snapshot)

-    │   ├─ approved [TIME]        -    └─ ✓ judge.1 - allowed [TIME]
+    │   ├─ rejected [TIME]        +    └─ ✗ judge.1 - blocked [TIME]
-    │   ├─ 0 blockers ✓
+    │   ├─ 1 blocker 🔴
```

⇒ a **re-run of that one suite came back `54 passed, 0 failed`.** the code did not change between
the two runs.

## .the gap, precisely

the case drives a **real** `rhx review.by --role learner --for term-aggregation` against
`fireworks/deepseek/v4-flash`, over a fixture the case name calls *"code is clean"*, and then pins
the **whole guard tree** — the verdict word, the blocker count, the judge glyph, the passage line —
in a snapshot.

⚠️ **the mitigation the rule prescribes is already applied, correctly and with its reason stated:**

```ts
const REPEATABLE_CONFIG = { attempts: 3, criteria: 'SOME' } as const;
```

`criteria: 'SOME'` diverges from `rule.require.repeatable-for-llm-tests`'s
`process.env.CI ? 'SOME' : 'EVERY'`, and the file argues the divergence in its own `.why`: *"an LLM
verdict is inherently probabilistic, so one green attempt proves the shape."* that argument holds.

🔴 **so this is not a misconfiguration. it is the configured retry budget running out.** a failure
here means the brain returned a blocker on **all three** attempts, which means the per-attempt
adverse rate is high enough that `p³` clears a full-suite run's probability floor — and a full
acceptance suite is run on every CI push.

## .why it is worse than an ordinary flake

| | an ordinary flake | this |
|---|---|---|
| what goes red | a timing or ordering assertion | 🔴 **a VERDICT — `approved` → `rejected`** |
| what a reader concludes | *"re-run it"* | 🔴 *"the reviewer found a real defect"* |
| cost of the misread | a minute | a diagnosis of a defect that does not exist |

⇒ and it teaches the worst habit a red can teach: **a reviewer-verdict red that is routinely
re-run is a reviewer-verdict red nobody reads.** that is the mechanism
`rule.forbid.failhide` names, reached from the flake side rather than the catch side.

## .the shape of the fix

three candidates, cheapest first:

1. **raise `attempts`** — `3 → 5`. one number, and it buys `p⁵` over `p³`.
   ⚠️ each attempt re-drives a full guard + live review at ~60s, so 5 attempts is a ~5min
   worst case on one case. it lowers the rate and closes no hole.

2. 🔴 **stop pinning the VERDICT, keep pinning the SHAPE.** sanitize the verdict word, the counts,
   and the judge glyph out of `sanitizeGuardTreeForSnapshot` the way `[TIME]` and `[HASH]` are
   already sanitized, and assert the verdict separately with a `toMatch` that admits both.
   ⇒ **the snapshot then clamps what the test is for — the tree's shape, glyphs, and alignment —
   and stops clamping what the brain decides.** the seam the case exists to prove (guard → peer →
   `review.by` → captured artifact) does not depend on which verdict comes back.

3. **swap the fixture for one the brain cannot disagree about** — a file so plainly clean that the
   adverse rate falls to near zero. ⚠️ unfalsifiable: you cannot prove a brain will not object.

⇒ **candidate 2 is the one that fixes rather than defers.** the others move a probability.

## .why it is not done in this round

- **SAFE = no.** `sanitizeGuardTreeForSnapshot` is shared by every case in the file, so a change to
  it re-baselines all 54 assertions including the three `case-seam-*` cases this wish never touched
- **CLEAN = no.** it ripples past the diff this round holds: the sanitizer, the three
  `when.repeatably` blocks, and the committed `.snap`
- ⚠️ and it is **out of this wish's boundary** — `review.by.guard-peer` is a review.by seam test, and
  this wish is peer-review concurrency. the announce lines it gained are incidental

⇒ the test is correctly configured today, and it went green on the next run. what is owed is a
re-aim of what its snapshot clamps, and that is its own round.
