# 🌙 dream: carry a run's `defect` string into the tree and grove breadths

- **kind** = fix
- **owner** = `rhachet-roles-bhrain`
- **caught** = 2026-09-22

## .the cue that fired

a peer lane (`enroll-impl-behavior-intent`, i014) found that `run.defect` — the string that
names the file at fault and why it could not be read — was **computed, stored, asserted in
data, and read by no renderer at any breadth**.

the `run` half was repaired in the same round. the tree and grove half was not, and the reason
is a contract shape rather than a forgotten line.

## .the gap, precisely

`asReviewRunMeterOfDefect.ts:27` stamps a corrupt run with `defect: String(error)`, and
`getOneReviewRunMeterLatest.ts:69` promises in its own comment:

> an `unknown` row that names its defect, never a stack trace with no report at all

at `--of run` that promise now holds. at `--of tree` and `--of grove` it does not, and the
reason is that **the report contract drops the runs**:

```ts
export interface ReviewMeterReport {
  corpus: ReviewMeterBucket;
  byReviewer: ReviewMeterBucket[];
  byStone: ReviewMeterBucket[];
  byRound: ReviewMeterBucket[];
}
```

every field is a **bucket** — a fold. no per-run row survives into it.

🔴 **so `defect` is not merely unrendered at those breadths; it is unreachable.** it is absent
from stdout AND from `--json`, because `emitCostOfTree` serializes
`payload: { root, report }` and the report never carried it.

what a driver sees instead, from `asUnmeteredCaveat`:

```
⚠️ +2 unmetered (spend unrecorded, NOT zero)
```

a count, with no route to the cause.

### 🔴 why the cheap fix is WORSE than none

the obvious one-line repair is to point the caveat at the breadth that does carry it:

```
⚠️ +2 unmetered — see `rhx review._.cost --of run` for the cause
```

**that hint is a lie for every corrupt run that is not the latest.** `--of run` reads
`getOneReviewRunMeterLatest`, so a driver whose corrupt run sits three rounds back runs the
command, sees a healthy row, and concludes the defect is gone.

⇒ that is the exact defect `[case7] [t2]` clamps one branch over — *"a hint that hardcoded the
breadth would hand a driver a command that answers a different question, which reads as a fix
and is a redirect"* (`rule.require.errors-name-the-fix`).

## .the shape of the fix

three options, cheapest first. **option B is the one to reach for.**

### option A — name the defective dirs in the caveat

widen `ReviewMeterBucket` with `unknownDirs: string[]`, and render them under the caveat:

```
⚠️ +2 unmetered (spend unrecorded, NOT zero)
   ├─ 2026-09-20T00-00-01-000Z.pid2 — metrics.realized.json
   └─ 2026-09-19T11-04-22-000Z.pid7 — metrics.realized.json
```

- 👍 the driver gets a path they can `cat`, which is a real route
- 👎 a bucket is a fold, so the same dir repeats across `byReviewer`/`byStone`/`byRound`
- 👎 an N-defect corpus prints N lines four times over

### 👍 option B — carry the defective RUNS on the report root, once

add one field beside the four buckets, so the list is declared exactly once:

```ts
export interface ReviewMeterReport {
  corpus: ReviewMeterBucket;
  byReviewer: ReviewMeterBucket[];
  byStone: ReviewMeterBucket[];
  byRound: ReviewMeterBucket[];
  defects: { dir: string; defect: string }[];   // 🔴 the new field
}
```

then:
- `genReviewMeterStdout` renders one `defects` block **after** the rollups, bounded by
  `--limit` exactly as the axes are, with an overflow line that discloses what was cut
- `--json` carries the full list unbounded, since a consumer pays no scan cost
- the per-bucket caveat is untouched — it keeps the count, and the block below keeps the cause

⇒ this respects the grain: a **count** belongs in the fold, a **cause** belongs to a run, so
the cause is declared once at the root rather than smeared across four folds.

### option C — leave the roll-ups and widen `--of run`

give `--of run` an `--at <run-dir>` so any run is addressable by name, then the caveat's hint
becomes honest.

- 👍 it also closes `F10`'s neighbour — `--at` is already polysemous across `--of`
- 👎 it is a bigger cli surface change, and it still needs the dirs printed at tree breadth
  for a driver to know *which* dir to pass

## .why it is not done in this round

| question | answer |

| **SAFE?** | ✅ yes — additive, no extant behavior moves |
| **CLEAN?** | 🔴 **no** — it changes `ReviewMeterReport`, a contract three renderers and both `--json` payloads read, plus the acceptance snapshots for `tree` and `grove` |

⇒ the `run` half landed because it touched one renderer and its own test. this half re-cuts a
shared report contract, so it rides a diff this round did not open.

🟡 and the deferral is a **judgment about ripple cost**, so it owes a fulcrum beside this
dream: `F13`.
