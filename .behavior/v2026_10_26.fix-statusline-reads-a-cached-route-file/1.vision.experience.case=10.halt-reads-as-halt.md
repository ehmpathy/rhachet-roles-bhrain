# case 10 — a halt reads as a halt

sharp · critipath · cell bound-once · fresh · route moved · one · lands · one (the halt lands as
a passage; the next repaint finds the file fresh). the pass to `complete` in [t4] is happy, and
itemized apart as inventory case 15

## .narrative

the human glances down mid-task. a peer reviewer rejected the stone and the guard stopped for an
approval, so the line reads `🗿 1.vision, judge, approved? 👋`. the wave tells them they are wanted;
they stop and approve. had the line still said `yield 🌾`, they would have worked on past a halted
guard and lost the afternoon.

on another day a review malfunctions, and the line reads `malfunction 💥` on the next glance; on
another the driver hits a wall, and it reads `blocked ✋`. the day the last stone passes, it reads
`🗿 route complete 🌴🤙`. each looks exactly as it did before the change.

## .behind the glance

a halt *is* a move: the line's disposition comes from the stone's latest passage, and every halt —
a guard's blocker, a driver's wall, an approval wait, a malfunction — is a passage written through
`setPassageReport`, the one point every status write hooks. the same holds for the last pass that
makes the route complete. no halt can land unless the file is rewritten after it.

each halt's words and glyph are the extant render, pinned today by
`src/contract/cli/__snapshots__/routeStatusLine.acceptance.test.ts.snap`; the writer calls that
render, so the cached line is the line the snapshot already proves.
