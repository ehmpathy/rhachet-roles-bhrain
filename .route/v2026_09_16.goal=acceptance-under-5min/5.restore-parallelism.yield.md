# 5.restore-parallelism — yield

## .the guard, satisfied

**the full suite green at the raised worker count:**

```
🦉 bench.acceptance — after16
   ├─ jest                 9m51s
   ├─ suites    117/117 passed, 0 failed
   └─ cases     3252/3252 passed, 0 failed, 0 skipped
```

**compare reports zero lost cases:**

```
🦉 bench.acceptance compare --before before --after after16
   └─ delta   33m28s faster  (4.40x)
   ✅ no regression — all 3248 cases that passed before still pass
```

## .the curve, measured at three points

| workers | jest wall | speedup |
|---|---|---|
| 1 (serial, no cache) | 2575s | 1.00x |
| 8 | 710s | 3.63x |
| **16** | **591s** | **4.36x** |

⇒ **sublinear.** a doubled worker count bought 1.20x. 16 is this box's knee, and it is
now the config default — with the table written beside it, so the next traveler re-sweeps
on a different box rather than inherits 16 as a constant.

## .what was actually wrong

two settings, and **either one alone keeps the suite serial**:

- `maxWorkers: 1` in `jest.acceptance.config.ts`
- `--runInBand` in the `test:acceptance` npm command — which **overrides** the config

⇒ a config-only fix is silently inert. worth a note before a peer tries the one-line
version and measures no change at all.

## 🔴 .the recant, and the re-recant

the config carried its constraint with a stated reason: *"symlink race conditions in temp
dir setup"*. `git log -S maxWorkers` put it in the repo's **first import commit** —
inherited, never diagnosed here — and the current test-fns contradicts it outright: its
temp infra is documented as *"idempotent — safe to call from parallel workers"*.

so I raised it. **595 cases failed.** I recanted, and wrote down that the constraint had
been real all along.

**then the clean re-run came back 3252/3252 at 8 workers, and 3252/3252 at 16.**

the 595 failures were an external `npm run build` mid-run (`build:clean:tsc` does
`rm -rf dist/`, and every fixture resolves through a symlink into `dist/`). **the original
call was right. the constraint WAS lore.**

⇒ **the error was not the first conclusion — it was the recant.** I let a confounded
experiment overturn a conclusion the evidence supported, and I did it fast, because a red
run feels like proof in a way a green one never does.

**the rule:** a failed run is evidence about the RUN first, and about the hypothesis only
once the run is known clean. before any recant, ask *was this experiment valid?*

🟡 the useful half survives: provenance told me the note had never been checked, and that
was worth a move. the move it licensed was **a test**, never a conclusion — and never a
reversal of one either.

## .the second trap, recorded in full

I then diagnosed those 595 failures twice, confidently, and both were wrong:

1. a logic race in my own cache
2. an EMFILE effect — `fs.existsSync` returns **false on any error**, so 8 workers on 4
   cores exhausts fds and the `existsSync(dist)` check inside test-fns `createSymlinks`
   fails spuriously

story 2 was argued from library source, fit every symptom, and was **still wrong**.

⇒ **a story that accounts for every symptom is not evidence.** the cheap test — re-run
clean, see if it reproduces — sat available the whole time, and it is what finally
settled it.

## .what parallelism cannot do

`3.attribute.yield.md` carries the arithmetic. at the measured 4.36x, a 5m00s total needs
the aggregate work to roughly **halve** from 2575s. the worker curve is already bent;
the lever left is less work per case, never more workers.
