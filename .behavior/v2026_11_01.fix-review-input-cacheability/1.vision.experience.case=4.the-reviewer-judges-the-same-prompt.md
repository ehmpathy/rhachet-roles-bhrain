# case=4 — the reviewer judges the same prompt

feel = sharp · care = critipath · cells = S2 `new` × `whole` × `push` · `new` × `split` × `push`

## .narrative

the reviewer is a model with no memory of the old layout. it reads one prompt and renders one
verdict. the wish bounds the cure: bytes move, the verdict does not.

**before.** system: instructions, output format, rules, refs. user: targets, conversation.

**after.** system: instructions, output format, targets. user: rules, refs, conversation — and,
for a partition, the context-only list and the peer list behind the partition's own targets.

every instruction that names a section's place still reads true: *"apply the rules below to the
target files"* — the rules sit below the instructions; *"if a `<refs>` section appears below"* —
it does; *"ONLY review content in the `<target>` section"* and *"NEVER flag anything from the
`<rules>` section"* (verbatim, `asPromptHeadStatic.ts:61-62`) name a tag, not a place. no
instruction says "above", and no instruction says the rules come first.

the sharp edge is a section that drops or doubles in the move. that fails loud, offline, before
any brain sees it: a clamp compiles one input both ways and asserts the same set of sections, each
byte-identical, arrives once.

## .[tn] sketch

```
given one review input — rules, refs, targets, a conversation
  when it compiles under the new layout
    [t0] the head holds the instructions, the output format, and the targets
      then no `<rules>`, `<refs>`, or `<conversation>` tag sits in the head
    [t1] the tail holds the rules, then the refs, then the conversation
      then each section's body is byte-identical to the old layout's
      then no section is absent, and none is doubled
    [t2] every instruction that names a place is checked against the new order
      then "below" names a section that sits below the instruction
  when it compiles as a partition
    then the shared band sits in the head, the own band behind the rules in the tail
    then the context-only list and the peer list each arrive once
  when a section would drop or double
    then the clamp fails offline, and names the section
  when the section census parses a run of each layout
    then every section sums to its prompt
    then no target chars land in `scaffold`
```

## .what this case does not prove

that a model weighs a rubric read last the same as a rubric read first. the content is equal and
the instructions hold; the behavior is an empirical claim, and the bounds forbid a live call in ci.

🟡 a before/after count of verdicts from the logs is **not** that proof: the rounds before and after
review different code, so their counts differ for reasons the layout never touched. the honest
evidence on offer is the offline content equality above. a controlled A/B — one input, both
layouts, one brain — is the only test that settles it, and it needs a live call, so it is named
as an open question for the director rather than claimed.
