# 🌙 dream: sedreplace finds no match for a pattern that starts with `--`

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=sedreplace)
- caught 2026-11-26

## .the cue that fired

`rhx sedreplace --old '--for skepticize' --new '--for assumptions' --glob '…'` reported `no files contain pattern`, while `rhx grepsafe` found the text on three lines. the same patterns via `--old @stdin --new @stdin` gave the same false miss. the pattern with its dashes dropped (`for skepticize`) matched 4.

## .the gap, precisely

guess, from the symptom: the skill passes the pattern to its file search as a bare argument, so a pattern that opens with `-` is parsed as an option of the search tool, not as the pattern. the miss is silent: exit 0 and "no files contain pattern", so a caller trusts a rename that never ran.

## .the shape of the fix

pass the pattern after a `--` (or via `-e`) in every grep/rg call the skill makes, and add a case to its test: a pattern that starts with `--` matches.

## .why it is not done in this round

the skill is published by another repo; the fix belongs there, dispatched via the radio.
