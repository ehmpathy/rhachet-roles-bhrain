# domain.term.choice.reason: route.brain.halt

## .etymology

`halt` is this repo's own established word for a stop-and-fix state the driver must face — the
`route.guard.review.terminal` cluster and the `asHaltParts` closed vocabulary already name
`approved`/`exhausted`/`blocked`/`malfunction` this way. this feature reuses the SAME word for
the same sense — a state a human must read and act on — one level down, for the brain dispatch
specifically, rather than coin a second word for an identical concept
(`rule.forbid.domain-term-inconsistency`).

rejected alternatives:

- `failure` / `error` — read as exceptional or unexpected. the most common cause, `unenrolled`,
  is the ROUTINE state of a driver that was never enrolled, never an error in the code's sense

## .disputes

none raised.

## .evidence

`asHaltParts` (`:112-119`) admits exactly four glyphs. this feature's halt renders under that
SAME closed vocabulary, per the vision yield's own citation — no fifth glyph exists for a brain
halt, so it composes into the extant halt surface rather than grow one.

## .invariants

- a brain halt never blocks stone entry — the wish's "fail loud" clause binds a switch that was
  asked for and did not happen, never entry itself (case=10)
- a brain halt always carries exactly one `route.brain.halt.cause`
