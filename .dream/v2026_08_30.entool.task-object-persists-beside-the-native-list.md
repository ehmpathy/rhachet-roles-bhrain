# dream: a `Task` domain object that persists beside the native list

**kind**: entool · **owner**: this repo (`rhachet-roles-bhrain`) · **caught** 2026-08-30

## .the cue that fired

`rule.always.itemize-a-peers-asks-into-tasks._.md` closes with *".the mechanism is yours"* — a
task tool, a stated list, a structured section, whatever surfaces the state. and its new zoom-in,
`.via-systematic-execution`, adds a second demand: **every task reaches a terminal state.**

⇒ the only mechanism a clone actually reaches for is the **native task list**, and that list
cannot satisfy the second demand — because it does not outlive the session that made it.

## .the gap, precisely

the native list is session-bound. so:

| the rule demands | the native list delivers |
|---|---|
| a receipt the peer can read | ✅ within the session |
| every task driven to terminal | 🔴 the list is gone at session end; an open task is unrecoverable |
| a **deferred** task carries a *when* | 🔴 there is no later to defer into |
| a **declined** task keeps its reason | 🔴 the reason dies with the list |

⇒ **so a compaction or a session boundary silently converts `deferred` into `dropped`**, which is
the exact defect both rules forbid — and it converts it in the one way neither rule can catch,
because the evidence goes with the list.

⚠️ **and the repo already has the peer artifacts and no task among them.** a route has stones. a
drive has fulcrums. a round has seeds and dreams. **an ask has a row in a list that evaporates.**

## .the shape of the fix

a `Task` domain object that **links into** the native list rather than replaces it — the native
list stays the fast, in-session surface; the object is what survives.

**the object.** `[...noun][state]?` per `rule.require.treestruct`:

| field | holds |
|---|---|
| `exid` | the native task id, so the two surfaces stay joined |
| `ask` | the peer's words, **verbatim** — the same contract a seed keeps |
| `status` | `queued` · `inflight` · `completed` · `declined` · `deferred` |
| `reason` | required on `declined` — the argument the peer gets to contest |
| `when` | required on `deferred` — the rule grades its absence a blocker |
| `absorbedBy` | the task that satisfied it, when the parent rule's absorption applies |

⚠️ **`declined` and `deferred` are the whole point.** the native list has four statuses, and both
of the rule's non-completed terminals collapse onto `deleted` — which is indistinguishable from a
drop. **the object exists to make that distinction survivable.**

**the operations**, per `rule.require.get-set-gen-verbs`: `genTask` (findsert on `exid`),
`setTask`, `getOneTask`, `getAllTasksFor`, `delTask`.

**the persistence** — a `.agent/.cache/` jsonl or a dao, whichever the repo's extant cache shape
favors. it is a local store, not a radio queue: the radio carries work **between** repos, and this
carries asks **within** a round.

**the interface** — an `rhx task.*` skill family, so the object is reachable from a hook and from
a route guard, never only from a brain that remembers to write it.

## ⚠️ .the guard is where the value lands

the object alone is a record. what makes it enforce the rule is a **stophook that refuses a
session close over a non-terminal task** — the same shape as the learner's
`learn.domain.terms` sweephook, which already holds a stop on an unarticulated sentinel.

⇒ without it this is a nicer list. with it, `.via-systematic-execution`'s central enforcement line
— *a round reported done with a non-terminal task = blocker* — becomes a mechanism rather than a
message. by this repo's own cited research (`research.selfreview-effectiveness`), that is the
difference between d≈0.05 and a real intervention.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** the bound wish is **briefs only** — *no new skills, no new roles* — and
this is a domain object, a persistence layer, a skill family, and a hook. every one of the four is
outside the scope this round was given.

⇒ the two briefs that motivate it **did** land this round, so the rule exists and its floor does
not. that sequence is correct: a mechanism with no rule to enforce is a guess.

## .the fulcrum

> **the rule that demands every task reach a terminal state is enforced by a list that cannot
> outlive the session, so `deferred` decays to `dropped` with no trace.**
> rework: **clean** — the object is additive, and the native list keeps working untouched beside it.
