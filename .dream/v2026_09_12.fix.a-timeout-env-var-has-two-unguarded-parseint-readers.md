### 🔴 .what the delivery found that the catch did not — a THIRD reader

this dream's own table declared **two** unguarded readers, and i004/r011 and i005/r011 each
independently reported two. **there are three.**

🔴 **the third names a different env var — `RHACHET_FALLBACK_BRAIN_TIMEOUT_MS` — so a grep for the
one this dream is titled after does not reach it.** that is why three separate surveys all returned
two: each searched for the var, and the defect was a property of the **pattern**.

⚠️ **and its guard was the loosest of the three.** it used `if (override)` — a truthiness test — and
`'0'` is a truthy **string**, so a zero bound passed straight through to `parseInt` and armed a
timer that fires at once. it guards the fallback sub-brain tally, which exists to **rescue** a lane
whose stdout could not be parsed, and whose own `.why` warns that a tight bound *"would spuriously
malfunction the very reviews this fallback exists to rescue."*

⇒ **the lesson generalizes past this dream: a survey keyed on the SYMPTOM (one var's name) cannot
bound the CAUSE (an unguarded numeric env read).** caught separately as
`.dream/v2026_09_11.enbrief.a-scope-glob-picked-by-symptom-bounds-naught-about-cause.md`.

### .what the delivery did NOT take from the shape below

step 1 asked to **lift and rename** `asGuardPositiveInt` out of the guard-parse module, on the
grounds that a numeric env override is *"the same contract with a different source."*

🔴 **the contract claim is right and the move was declined.** the transformer's subject is a
declared positive integer, and its `at:` field already names an arbitrary site — so it reads an env
var with no change at all. a move would have touched every extant importer to buy a filename that
reads better, which fails CLEAN for a cosmetic gain inside a round that owes acceptance 2.

⇒ steps 2 and 3 were also declined, for a sharper reason: **a shared exported const would couple the
three readers' DEFAULTS**, and their defaults legitimately differ (`stepReview`'s literal
`21 * 60 * 1000`, `runOneReview`'s per-reviewer `IsoDuration`, the fallback's `PT21M`). the
transformer is the right unit to share; the **value** is not.

## .the gap, precisely

three readers of one env var, at two strictness levels:

| reader | how it takes the value | validated? |
|---|---|---|
| `src/domain.operations/review/stepReview.ts:162-165` | `parseInt(process.env.RHACHET_REVIEW_TIMEOUT_MS, 10)` | 🔴 no |
| `src/domain.operations/review/runOneReview.ts:46-49` | `parseInt(process.env.RHACHET_REVIEW_TIMEOUT_MS, 10)` | 🔴 no |
| `src/domain.operations/route/guard/review/runStoneGuardReviews.ts:121` | cites the var as precedent only; takes its own `RHACHET_LEVEL_CONCURRENCY` via `asGuardPositiveInt` | ✅ yes |

verified 2026-09-12 by a repo-wide grep: two `parseInt` sites, zero validation, no shared constant,
no test that couples them.

**what a malformed value does today:** `RHACHET_REVIEW_TIMEOUT_MS=abc` → `parseInt` yields `NaN` →
`NaN` is handed to `setTimeout` in one path and to `child_process`'s `timeout` option in the other.
node's docs declare neither behavior for `NaN`, so the bound is undefined rather than absent — the
reviewer's own verdict, and it matches the code.

⚠️ **and a zero or a negative passes too.** `RHACHET_REVIEW_TIMEOUT_MS=0` parses as a valid integer
and would bound every review at zero, which reads to a driver as every reviewer malfunctioned at
once. `asGuardPositiveInt` refuses exactly this class.

🟡 **`stepReview.ts:162` exports the result as `REVIEW_TIMEOUT_MS`**, so the value leaves its own
module and the blast radius of a change to it is wider than the two call sites.

## .the shape of the fix

one transformer, reused at both sites — the same move this round already made for
`RHACHET_LEVEL_CONCURRENCY`:

1. **generalize `asGuardPositiveInt`** past guard-file parse. it lives beside the guard parser
   today; a numeric env override is the same contract with a different source, so the lift is a
   move plus a rename that states the broader subject
2. **take the var once**, in one module, through that transformer, and export the millisecond value
3. **have both call sites consume that export** rather than re-read `process.env`
4. **one unit clamp per refusal**: `abc` → throws, `0` → throws, `-1` → throws, `1000` → `1000`,
   absent → the `PT21M` default. each goes red under a bare `parseInt`

⚠️ **the refusal must be LOUD.** a fallback to the default on a malformed value is the failhide
shape — an operator who typed the var believes their bound is live while the default runs.
`rule.require.failfast` and the extant `asGuardPositiveInt` both throw, so this inherits the answer
rather than re-argues it.

## .why it is not done in this round

**SAFE = yes. CLEAN = no.**

- **safe** — the change is a validation added ahead of two reads whose happy path is untouched. a
  well-formed value behaves identically
- 🔴 **not clean** — it ripples into two files this feature never opened (`stepReview.ts`,
  `runOneReview.ts`), plus a lift of `asGuardPositiveInt` out of the guard-parse module, plus an
  exported const whose consumers must be walked. the reviewer graded it out of this PR's diff
  surface and asked for no fix

⇒ per `rule.always.fix-forward-under-scouts-honor`, a deferral for **dirt** owes a fulcrum beside
the dream, so the judgment is reviewable rather than merely recorded. raised as **F14**.
