### 🔴 .the full-suite run found a LATENT FLAKE the scoped runs never could

the withdrawal was declared green on a scoped run of `driver.route.self-review` alone. the full
unscoped run of all 90 `driver.route.*` suites then reported **211 passed, 4 failed** — all four in
`[case1]`, all four `challenge:stale`.

⚠️ **the first diagnosis was wrong, and it is worth a plain statement.** mint-all was restored as a
bite check; `[case1]` went green, so the lazy mint read as the cause. **it was not.** the two runs
differed in **wall clock** — 507s versus 92s — never in mint strategy.
`setSelfReviewTriggeredReport` writes `.since` with `{ flag: 'wx' }` and returns on `EEXIST`, so a
re-ask is a genuine no-op and the backdate lands on the identical value under either strategy.

⇒ **the bite check's correlation was real and its conclusion was false**, because the revert and the
re-run changed two quantities at once. only a read of the mechanism parts them.

the fixture's real shape:

| step | what it did |
|---|---|
| `[t0]` scene | wrote **both** articulations at `T_scene` — the fork-era workflow |
| `[t2]` promise | back-dated the ask to `T_promise − 31s` |
| the bar | stale ⟺ `T_promise − 31s > T_scene` ⟺ `[t0]`+`[t1]` took over 31s |

⇒ **a precondition expressed as a duration.** it held all round because a scoped suite finishes in
seconds; under real parallel load `[t0]`+`[t1]` crossed 31s and the leftover articulation went stale.

🔴 **the repair is an order of operations, never a longer backdate.** `[case1]`'s scene now writes
the FIRST review's articulation only; the second is written in `[t2]`, **after** its own ask and
before the backdate. so `.since < articulation mtime` holds at any speed — and the fixture now
expresses the shipped serial contract rather than the withdrawn fork's.

⚠️ **the transferable form: a fixture whose precondition is a DURATION is a flake with a long fuse.**
recast it as an order of operations and the clock leaves the test. 🟡 and the fuse is long precisely
because `rule.prefer.scoped-tests-locally` is correct — a scoped suite is the right default and it
**cannot** produce the load that makes a margin bite.

### 🔴 .the flake was a CLASS, and the first repair caught one member of it

the `[case1]` repair above was aimed at the one case that went red, and it was **not the whole
defect**. a later full-corpus run — **130 files**, every acceptance suite, 3125s — went red on
`[case8][t2]` as well, and a re-read of the file found the class:

> **every case that asserts the haste cue FIRES carries the same unstated precondition: the scene
> plus every prior step must finish in under 30s.**

four sites, each one a duration in disguise:

| site | what it asserts | why it was fragile |
|---|---|---|
| `[case5][t0]` | the cue fires on a prompt promise | the ask is minted in the scene; the promise must beat 30s |
| `[case7][t0]` | the 1st of two back-to-back promises meets the cue | same ask, same race |
| `[case8][t2]` | the journey's rushed leg | 🔴 **the worst** — three prior legs spend real CLI time first |
| `[case9][t1]` | the cue is still owed after a stale verdict | a prior leg plus a re-save |

🔴 **the repair is one helper, `freshenAskAndArticulation`, called immediately before each promise.**
it re-stamps the ask at `now−1s` and the file at `now` — **both**, because the ask must stay OLDER
than the file (or the freshness bar refuses it) and YOUNGER than the window (or the cue never
fires). one write cannot hold both ends.

⚠️ **the bite check ran, and it is the one that proves a CONTROL rather than a fix.** the helper's
offset was pushed from `now−1s` to `now−31s` — the ask outside the window, no other change:

| | result |
|---|---|
| ask at `now−31s` | 🔴 **202 passed, 13 failed** |
| the 13 | exactly the four sites above, plus their snapshots — **zero collateral** |
| ask at `now−1s` restored | ✅ **215 passed, 0 failed** |

⇒ **zero collateral is the half of that table that carries the weight.** it proves the helper moves
the one operand the cue reads and no other, so the four cases still assert their own subject — the
fixture was made deterministic, never made lenient.

🟡 **and the lesson the first repair missed: when a flake is a duration, look for EVERY assertion
that reads the same clock.** `[case1]` failed first because it was slowest, not because it was
alone. a grep for the cue's own words (`what is the rush`, `patience`) enumerates the class in one
pass — and that grep is what the first repair should have run.
