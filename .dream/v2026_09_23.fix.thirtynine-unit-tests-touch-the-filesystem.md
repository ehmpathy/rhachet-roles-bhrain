# 🌙 dream: thirty-nine `.test.ts` files touch the filesystem

**kind** `fix` · **owner** `rhachet-roles-bhrain` · **caught** 2026-09-23

## .the cue that fired

a peer lane (`mech-test-scope-purity`) raised three blockers against
`rule.forbid.unit.remote-boundaries` — nine files in this round's diff are `.test.ts` and read or
write real files on disk.

🔴 **the cue is not the nine. it is what a count turned up when the nine were checked for company.**

## .the gap, precisely

counted with a `Grep` for `os.tmpdir()` across `**/*.test.ts`:

| | count |
|---|---|
| files that match | **115** |
| already `.integration.test.ts` | **75** |
| an `.acceptance.test.ts` | **1** |
| 🔴 plain `.test.ts` — the rule's violation | **39** |
| of those, in this round's diff | **8** |

they span eleven subsystems this wish never opened: `reflect/`, `goal/`, `git/`, `infra/git/`,
`route/passage/`, `route/gitignore/`, `route/judges/`, `route/stones/blocked/`, `route/guard/judge/`,
`route/guard/artifact/`, `route/guard/review/peer/`.

⇒ so `npm run test:unit` in this repo **touches disk today**, at thirty-nine sites, and the rule that
forbids it is enforced nowhere.

### 🔴 the second gap, and it is a DOCTRINE question rather than a cleanup

blocker.3 named `getAllStoneArtifacts.test.ts`, which uses **no** `os.tmpdir()` — it reads a
committed fixture under `path.join(__dirname, '../.test/assets')`, as all four of its cases do.

**the rule's own examples are about state the test cannot control** — a live db, a network call, a
config on the host. a committed fixture is deterministic, versioned, and travels with the test.
⇒ **whether `rule.forbid.unit.remote-boundaries` means to reach a repo-local fixture read is
genuinely unsettled**, and the answer moves the blast radius from 39 files to *every fixture-driven
unit test in the repo*.

## .the shape of the fix

**two independent pieces, and the second must be settled first:**

1. **settle the doctrine.** amend `rule.forbid.unit.remote-boundaries` to say explicitly whether a
   committed, repo-local fixture read crosses a boundary. one sentence, and it decides the size of
   piece 2
2. **the rename.** `mvsafe` each violation `X.test.ts → X.integration.test.ts`, then re-balance the
   CI gates — the fast `test:unit` gate loses 39 files and `test:integration` gains them, which
   changes both gates' wall-clock and the credential preconditions of the second

🟡 **the ordered list of the 39 is derivable in one command**, so it is not restated here:
`Grep` for `os.tmpdir\(\)` over `**/*.test.ts`, then drop every path with `.integration.` or
`.acceptance.` in it.

## .why it is not done in this round

the SAFE/CLEAN test, run on the **fix** rather than on the scope:

- 🔴 **SAFE — no.** a rename moves a file between two CI gates with different cadence and different
  credential preconditions
- 🔴 **CLEAN — no.** a rename of the 8 in the diff leaves the repo **inconsistent** rather than
  compliant: two files with byte-identical fixtures would carry different extensions, and the only
  fact that parts them is which PR last touched them. a rename of all 39 opens eleven subsystems this
  wish never touched

⇒ both answers are no, so the deferral is `rule.always.fix-forward-under-scouts-honor`'s own verdict.
the judgment behind it — that a partial rename is worse than a consistent violation — is a call the
council may overturn, so it is a **fulcrum** too:
