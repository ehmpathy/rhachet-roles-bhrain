# 🌙 dream: a name-scoped journey frame fails for setup reasons, and reads as a real failure

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-13

## .the cue that fired

a teeth proof. i cut an emit and ran the one clamp that should go red:

```sh
rhx git.repo.test --what acceptance --mode apply \
  --scope 'path://driver.route.peer-concurrency' \
  --scope 'name://an UNGROUPED reviewer is appended'
```

⇒ **`0 passed, 10 failed`.**

that number reads as catastrophe. i had cut three lines behind a flag and ten frames went red, so
the first read is *"the cut broke the suite."* **it did not.** the whole-file run gave the honest
number — **48 passed, 1 failed** — and the one red was exactly the clamp under test.

## .the gap, precisely

a **journey** test's frames are ordered and stateful. `driver.route.peer-concurrency`'s `[t5]` opens
with a guard mutation that assumes `[t4]` already ran:

```ts
// blackbox/driver.route.peer-concurrency.acceptance.test.ts — [t5]
const guard = await fs.readFile(guardPath, 'utf-8');
await fs.writeFile(guardPath, guard.replace('  groups:', ...));
```

⇒ `'  groups:'` is present only in the guard **as `[t4]` left it**. run `[t5]` alone and the replace
matches naught, the guard is unmutated, and every assertion in the frame fails — **for setup
reasons, with no signal about the property under test.**

🔴 **and `--scope 'name://…'` maps onto jest's `--testNamePattern`, which SKIPS the frames it does
not match rather than refuse the run.** so the filter silently deletes the setup and then reports
the consequence as a failure. the output is indistinguishable from a real break:

| the run | what it reports | what is true |
|---|---|---|
| `--scope 'name://…'` on a journey frame | `0 passed, 10 failed` | the setup was skipped |
| the whole file | `48 passed, 1 failed` | one clamp is red, as designed |

⚠️ **the harm lands at the worst moment.** a teeth proof exists to tell a driver whether a clamp
bites, and this turns that proof into a false catastrophe — the one class of wrong answer most
likely to be acted on, because a red suite demands action.

## .the shape of the fix

two candidates, and the second is the cheap one:

1. 🔴 **the mechanism** — `git.repo.test` knows the scope it was handed. when `--scope 'name://…'`
   resolves to a file whose describe-block declares a journey (this repo's own convention is
   `.journey.` in the filename, or `[t0]`…`[tN]` frame labels), **warn at the invocation**:

   > `🟡 'name://' filters frames out of a JOURNEY. its later frames depend on earlier ones, so a`
   > `   filtered run can fail for setup reasons. drop 'name://' to read this file honestly.`

   ⇒ the same shape as `rule.require.errors-name-the-fix`: it names the fix rather than the symptom.

2. **the doc** — a `when… / then…` row in `howto.run-tests` or `rule.prefer.scoped-tests-locally`.
   cheaper, and weaker: it is read at the moment a driver plans a run, and the failure lands at the
   moment they read a number.

⇒ 🟡 **prefer 1.** per `research.selfreview-effectiveness`, a cue at the moment of use scores far
above a principle read earlier — and this defect's whole character is that the output looks correct.

**a clamp for either:** a fixture journey whose `[t1]` depends on `[t0]`, run under
`--scope 'name://[t1]'`. assert the warn is emitted (for 1), and assert the naive run's failure count
exceeds the whole-file run's (which is the defect, stated as a number).

## .why it is not done in this round

**SAFE = yes. CLEAN = no.**

- the emit lands in `git.repo.test`, a **skill** under `ehmpathy/role=mechanic` — a different role's
  tree from the one this route's stone is bound to
- the detect step needs a rule for *"is this file a journey?"*, and this repo has no declared marker
  for one. **to invent that marker inside a concurrency round is to settle a test-suite convention
  as a side effect** — exactly the call `rule.always.itemize-the-fulcrums-you-best-guess` reserves
- ⇒ the round's stone is `5.1.execution.from_vision`, scoped to the concurrency feature. a
  cross-role skill change plus a new convention is not a ride-along

⚠️ **and the diagnosis is already recorded where it was paid for** — the i008 `.taken` and F13's
teeth section both state that only the whole-file run is an honest read, so the next traveler on
*this* route does not re-derive it. **this dream is what carries it to every other route.**
