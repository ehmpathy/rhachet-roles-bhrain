## .the cue that fired

the l3 arch-defects review of `fix-memory-guard-fails-open` read a fail-open envelope hand-rolled into `memory.guard.sh` and named it generic: none of it was about memory. the commander then ruled no hook bridge in the role; the envelope was dropped from #742, and the cure is owed here, as root cause R2.

## .the gap, precisely

- `rhx` maps a skill lookup fault to exit 2, which claude code reads as block
- `Role.hooks` has no way to say what a hook's fault should mean
- so an advisory guard fails closed unless it hand-rolls an envelope beside its own logic; the learner's memory.guard and the driver hooks (fulcrum F2, its own dream) share the hazard unrepaired

## .the shape of the fix

a fault mode on the hook entry:

```ts
{ command: 'rhx memory.guard --mode hook', timeout: 'PT5S', onFault: 'allow' }   // advisory
{ command: 'rhx forbid.secrets --mode hook', timeout: 'PT5S', onFault: 'block' }  // safety gate
```

`rhachet init --hooks` renders the envelope around `command`: on a lookup fault, a load fault, or a timeout, `allow` prints one line that names the fault and its fix and exits 1; `block` exits 2. the skill keeps only its verdict.
