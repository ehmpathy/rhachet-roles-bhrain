## .the cue that fired

a `role-standards-coverage` self review walked the mechanic rule set against `parseStoneGuard.ts`
and found `concurrency:` validated its bound on `parseInt`'s **answer** rather than on the raw text
— so `concurrency: 2.5` parsed clean and poured 2. that was repaired in-round.

🔴 **the cue is what the repair exposed.** the fix reads the raw text with `/^[0-9]+$/`, and its two
neighbours three hundred lines down do not:

```ts
currentPeerReview.budget = parseInt(trimmed.slice(7).trim(), 10);   // :483
currentPeerReview.level  = parseInt(trimmed.slice(6).trim(), 10);   // :485
```

⇒ **one of three numeric keys in one file is now strict and two are loose**, which reads as a
settled convention rather than as an unfinished sweep.

## .the gap, precisely

`parseInt` reads a **prefix**. it stops at the first character that cannot extend the integer and
answers what it has, with no signal that it stopped early:

| declared | `parseInt` answers | what the guard runs with |
|---|---|---|
| `budget: 2.5` | `2` | **2 rounds** — the author wrote 2.5 and no line of output says otherwise |
| `budget: 1e3` | `1` | 🔴 **1 round**, where the author meant a thousand |
| `level: 1.9` | `1` | level 1 — plausible, and not what was written |
| `budget: abc` | `NaN` | 🔴 **worse than either** — see below |

checkable today, with no code change:

```
budget: 2.5   ⇒  parseInt('2.5', 10) === 2
budget: 1e3   ⇒  parseInt('1e3', 10) === 1
budget: abc   ⇒  parseInt('abc', 10) === NaN
```

🔴 **the `NaN` row is the sharpest, and it is not a truncation at all.** `rounds >= pr.budget` is
`false` for every `rounds` when `budget` is `NaN`, so a typo'd budget makes a reviewer **never
exhaust** — an unbounded ladder, reported nowhere. the same value in `level` sorts by
`a.level - b.level`, which returns `NaN`, and a comparator that answers `NaN` leaves the sort order
implementation-defined.

⚠️ **it is present today and this feature does not create it.** what this feature does is put a
third numeric key beside the two, so the inconsistency became legible.

## .the shape of the fix

lift the raw-text check `concurrency:` now carries into one named transformer, and route all three
through it:

```ts
/**
 * .what = reads a guard's declared integer, or throws with the text the author wrote
 * .why = `parseInt` reads a PREFIX, so it answers 2 for "2.5" and NaN for "abc" —
 *        each of which the guard then runs with, silently
 */
const asGuardPositiveInt = (input: { raw: string; key: string; at: string }): number => {
  if (!/^[0-9]+$/.test(input.raw) || parseInt(input.raw, 10) < 1)
    throw new BadRequestError(
      `${input.key} must be a positive integer: "${input.at}" declares "${input.raw}"`,
      { key: input.key, at: input.at, declared: input.raw },
    );
  return parseInt(input.raw, 10);
};
```

⇒ `concurrency:` then calls it rather than inlines it, and `budget:` / `level:` gain the check they
lack. one transformer, three call sites, and the `.why` lands in one place.

🟡 **and each owes its own case.** the `concurrency:` suite already carries a negative, a fractional,
and an integer-prefix case (`parseStoneGuard.test.ts` `[case14]` `[t2]`–`[t4]`); `budget:` and
`level:` owe the same three each, plus the `NaN` case that only they can reach.

## .why it is not done in this round

the SAFE/CLEAN test, answered honestly:

| question | answer |
|---|---|
| **safe?** | 🔴 **no** — `budget:` and `level:` carry weight on **every extant guard**, where `concurrency:` is introduced by this change and can carry no legacy value at all |
| **clean?** | 🔴 **no** — it is a behavior change to two keys this diff does not touch (`rule.require.review-test-changes`) |

⇒ the asymmetry is the whole argument for the deferral. **strictness on `concurrency:` costs no
extant guard by construction.** strictness on `budget:` and `level:` would refuse any guard in this
repo — or in any repo that consumes it — that carries a value the loose parser has quietly taken.
that is a migration, and a migration wants its own round and its own census of what is out there.

⚠️ **the census is the piece this round cannot supply.** *"no extant guard declares a fractional
budget"* is a claim over a set nobody walked, and it spans consumer repos this worktree cannot see
(`rule.forbid.absolutes`). the fix should open with that walk, not assume its result.

⇒ per `rule.always.fix-forward-under-scouts-honor`, a defer for **dirt** owes a dream **and** a
fulcrum. the dirt here is the unwalked set above, so the fulcrum is the judgment that a
one-of-three strictness is the right place to stop until that walk happens.
