# 🌙 dream: domain operations read process state through context

kind: refactor · owner: bhrain · caught 2026-10-10

## .the cue that fired

i035 r030 nitpick.3: `stepRouteDrive` and `stepReflect` pass `process.env` / `process.cwd()` to
predicates that already take them as input, so their tests mutate the global.

## .the gap, precisely

dozens of prod reads of `process.env` and `process.cwd()` sit in `src/domain.operations/`; the test
suites of `stepReview`, `runStoneGuardReviews`, and the timeout reads mutate the same global, so the
suite cannot run those files in parallel.

## .the shape of the fix

1. census: `rhx grepsafe --pattern 'process\.(env|cwd)' --path src/domain.operations`
2. add `context.process: { env, cwd }` at each contract entry (cli), the one place the global is read
3. thread it down; predicates already take `env` as input
4. clamp: a test that scans `src/domain.operations` for `process.env` outside an allowlist
