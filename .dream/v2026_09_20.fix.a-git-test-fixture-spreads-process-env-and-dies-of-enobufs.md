# 🌙 dream: the one `execSync` that spreads `process.env` dies of `ENOBUFS`

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-20

## .the cue that fired

a `--thorough` run at i011 — **itself a violation of `rule.forbid.thorough-test-runs`** — returned
11 red in `src/domain.operations/review/getAllFileDiffsFromRange.integration.test.ts`, a file this
branch never touched.

⇒ 🔴 **the flag's own forbid predicts this exactly**: *"a red suite you did not touch is a fact
about `main`, not about you."* the finding is real; the instrument that found it was the wrong one,
and the detour to diagnose it is the cost that rule names.

## .the gap, precisely

every one of the 11 fails at the same line, and the 8 further *"test suite failed to run"* entries
are its cascade through `usePrep`:

```
spawnSync /bin/sh ENOBUFS

> 37 |   execSync('git commit -m "initial"', { cwd: repoPath, env: GIT_ENV });
```

🔴 **line 37 is the ONLY `execSync` in that fixture that passes an `env`.** its three neighbours —
`git init` (:35), `git add .` (:36), `git branch -M main` (:40) — pass none, and all three succeed
in the same run.

```ts
const GIT_ENV = {
  ...process.env,            // 🔴 the whole host environment, inherited
  GIT_AUTHOR_NAME: 'Test User',
  GIT_AUTHOR_EMAIL: 'test@test.com',
  GIT_COMMITTER_NAME: 'Test User',
  GIT_COMMITTER_EMAIL: 'test@test.com',
};
```

**reproduced in isolation**, so it is not a parallelism artifact:
`--scope 'path://getAllFileDiffsFromRange'` → 11 failed, 0 passed, 11s.

⚠️ **and it is invisible to the bounded runner.** the default `--changedSince` bound excludes this
file for any branch that does not touch it, so `--what integration --mode apply` reports
**1178 / 0** on the same tree, in the same session, with the same host env. ⇒ the defect reaches a
driver only by a forbidden flag, or by cicd.

## .the diagnosis, and what it does NOT yet establish

**one honest pass, and it stops short of a proof.**

| the operand | what the evidence says |
|---|---|
| the `env` spread | 🔴 the strongest candidate — it is the sole property that parts line 37 from its three green neighbours |
| `maxBuffer` on stdout | unlikely. the asset repo is ~15 small files, so `git commit` prints ~15 lines |
| host resource exhaustion | refuted — it reproduces in isolation, at 11s, with one suite in flight |

⇒ the root cause is **not measured**, and the dream is honest that the fix below rests on the first
row rather than on a demonstration of it.

## 🔴 .the rule it violates, and why that is the durable half

`rule.forbid.bare-host-deps` and `rule.require.hermetic-tests`: **a fixture that spreads
`process.env` inherits whatever the host carries.** the same suite is green on a machine with a
lean environment and red on one with a fat one, and the test cannot say which it is on.

⇒ **the `ENOBUFS` is the symptom. the inherited host environment is the defect**, and it is a defect
whether or not this particular symptom is its consequence.

## .the shape of the fix

pass a **minimal, declared** env rather than the host's:

```ts
const GIT_ENV = {
  PATH: process.env.PATH,     // /bin/sh needs it to find `git`
  HOME: process.env.HOME,     // git wants a home, even with identity set
  GIT_AUTHOR_NAME: 'Test User',
  GIT_AUTHOR_EMAIL: 'test@test.com',
  GIT_COMMITTER_NAME: 'Test User',
  GIT_COMMITTER_EMAIL: 'test@test.com',
  GIT_CONFIG_GLOBAL: '/dev/null',   // and while there: no host gitconfig leaks in
  GIT_CONFIG_SYSTEM: '/dev/null',
};
```

🔴 **and clamp it by the bite test, never by a green run** (`rule.require.clamp-edge-cases`): the
suite is green today under the bounded runner, so *"it passes"* proves naught. the clamp must go
**red** with the `...process.env` spread restored, on a host whose env is large enough to provoke
it — which means the reproduction condition has to be captured first, and that is the expensive
half of this dream.

🟡 **and check the neighbours.** the same spread may sit in other fixtures; a `grepsafe` for
`...process.env` inside `.test.ts` / `.integration.test.ts` is the sweep this fix owes.

## .why it is not done in this round

**SAFE: no.** the root cause is a hypothesis rather than a measurement, and a change to a test
fixture's environment can turn a red suite green for the wrong reason — the worst outcome available
here.

**CLEAN: no.** the file sits in `src/domain.operations/review/`, a subsystem
`v2026_09_17.fix-self-review-min-duration` never opened. the round already carries four independent
repairs to one gate plus a scope-growth concern its own yield flags at item 6.
`rule.always.fix-forward-under-scouts-honor` grades *"a large cleanup smuggled into an unrelated
change"* a blocker from the mirror side.

⇒ and the deferral is a **size** call rather than a **dirt** call — the ripple is one file — so it
owes this dream and no fulcrum. what makes it large is the **reproduction**, not the edit.
