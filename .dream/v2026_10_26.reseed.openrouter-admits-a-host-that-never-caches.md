# 🌙 dream: the live-cache test brain can land on a host that never caches the prefix

- kind: reseed
- owner: ehmpathy/rhachet-brains-openrouter (a supply promise), then this repo's test brain
- caught 2026-10-26

## .the cue that fired

ci run 40286586280 on pr #692, shard integration 3/3: `stepReview.casePromptCache` [case1] went
red. every attempt's log shows the same host, `Morph`, for round 1, round 2, and the control. round 2
read 1,024 tokens (the static review head) of ~58.8k, a share of 0.017 against a bar of 0.5, on all
three attempts. main's last test run on b64f14d4 passed: its balancer picked another host.

## .the gap, precisely

`DEFAULT_TEST_BRAIN_OF_LIVE_CACHE` (`openrouter/deepseek/flash/speed=min100tps&privacy=full`)
admits every endpoint that meets speed and privacy. no supply promise says "this host serves a
cached prefix", so the balancer may keep the whole run on a host that never caches the rubric.
`when.repeatably` SOME cannot rescue it: every attempt in one run meets the same host. the suite's
header already says so.

this is the third host in the same trap: Wafer 2026-10-10, Makora/fp8 2026-10-17, Morph 2026-10-26.

## .the shape of the fix

- upstream: a supply promise in the filtered slug, e.g. `cache=read`, that admits only endpoints
  whose openrouter price card lists an input cache read rate (or a host the package has seen serve
  a cache read for that model). clamp: an endpoint set with one host that never caches is filtered
  to the rest
- here: append that promise to `DEFAULT_TEST_BRAIN_OF_LIVE_CACHE`, once the package version ships

## .why it is not done in this round

the cure is a filter in rhachet-brains-openrouter, which this repo must not patch. the suite is
unchanged from main. a retry only rerolls the host.
