# 🌙 dream: strip every time of day from the tree, the review meter's log-dir names included

- kind: fix
- owner: ehmpathy/rhachet-roles-bhrain
- caught 2026-11-27

## .the cue that fired

a strip order arrived ahead of the education pr's push. the branch was clean, and the extant tree
was not: `rhx timestamps.get --scope tree` reads 637 lines in 153 files (F29).

## .the gap, precisely

- `.husky/check.timestamps.sh` reads only a colon clock and a T-dash clock. it misses a clock
  digit masked as x and a bare dash time id, and it skips `.ts`, `.js`, and `.sh`
- the extant tree holds times of day in all three shapes: ~85 prose files from prior routes and
  dreams, 12 archived code files, and 56 live code and snapshot files under `src/` and `blackbox/`
- the review meter names each run's log dir by its mint time to the millisecond (`genLogDirName`)
  and reads order and elapsed minutes back from the name (`asLogDirMintedAt`,
  `asRunDirChronologicalOrder`, `isReviewRunDirLater`, `getOneMinutesBetweenRunDirs`), so its
  tests hold a time because the time is their subject

## .the shape of the fix

1. widen the hook (upstream, in `declapract-typescript-ehmpathy`, which locks it) to the three
   shapes and to code files, with `rhx timestamps.get` as its local twin
2. prose and dreams: keep each date, drop each time (a mechanical pass)
3. the review meter: mint a log dir by date plus a monotonic sequence or content hash; read order
   from the sequence; read elapsed minutes from a file inside the dir, never from its name
4. each test that picks a log by a stamped name picks it by date plus content

## .why it is not done in this round

the education pr is bounded to the learner suite. step 3 is a contract change to the review meter,
another bounded context, and the foreman ruled the order binds this branch only (F29).
