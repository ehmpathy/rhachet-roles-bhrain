# 🌙 dream: the snapshot corpus speaks two dialects, split by directory, with no rule that says so

- **kind** = `fix`
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-05, at stone `5.3.verification` of
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

a peer reviewer (`ergo-snapshot-visual-blemishes`, i016 nitpick.1) asked for a fixture hash to be
masked to `<hash>`, on the stated premise that *"every other migration/contemplation snapshot in the
corpus masks this segment"*.

the premise is **half true**, and which half depends entirely on the directory — a fact no brief
records and no reviewer can read off the corpus.

## .the gap, precisely

**measured 2026-09-05**, by grep across both snapshot roots:

| directory | normalizer | occurrences of `<hash>` |
|---|---|---|
| `src/contract/cli/__snapshots__` | `asStableEmit` | **59** |
| `blackbox/__snapshots__` | `sanitizeTimeForSnapshot` | 🔴 **0** |

so a review artifact path renders two ways, per the directory its test happens to live in:

```
src/contract/cli/…snap:23    given: .reviews/peer/1.test._.review.i001.<hash>.r001._.given.by_peer.counter.md
blackbox/…malfunction.snap:59  given: .reviews/peer/1.feature._.review.i002.d6ef1aa3fad755e23c.r001._.given.by_peer.bash.md
```

**each dialect is internally coherent, which is why neither looks broken from inside itself:**

- **blackbox pins verbatim** because `genTempDirForRhachet` clones a fixed asset dir, so the
  artifact set — and therefore the hash — is deterministic. there is no volatility for a mask to
  absorb, and the real hash carries information a mask would destroy (it shows two rounds at one
  hash, which is how the F9/F10 defect is legible at all in that file)
- **the cli suites mask** because `asStableEmit` normalizes several volatile tokens in one pass and
  the hash rides along with them

⇒ **the defect is not either dialect. it is that no artifact states which governs where**, so:

1. a **reviewer** who reads one corpus infers a repo-wide convention and reports the other as a
   violation — which is exactly what happened, and it cost a round to answer
2. an **author** who moves a test between the two roots silently changes its snapshot dialect
3. a **reader** cannot tell an unmasked hash from an oversight

⚠️ **the sharp part: this misfire reproduces itself.** the reviewer was right that the corpus is
inconsistent and wrong about the repair, and no evidence available to it could have parted the two.
the next lane to read either root will make the same call.

## .the shape of the fix

1. **write the convention down** — a brief under `.agent/repo=.this/role=any/briefs/` that states
   the rule and, more importantly, **the reason each root has the dialect it has**. the reason is
   what stops the next reviewer from a re-report: *blackbox scenes are hermetic and their hashes are
   evidence; cli emits ride a multi-token normalizer.*
2. **name the two normalizers in it** — `asStableEmit` (masks) vs `sanitizeTimeForSnapshot` (time
   only) — so an author can pick by intent rather than by copy from the nearest neighbour
3. **decide the genuinely ambiguous cell**: a test under `src/**` that drives a hermetic temp repo.
   today it inherits `asStableEmit` by proximity, never by a decision
4. ⚠️ **do NOT sweep one root into the other.** the blackbox verbatim hashes carry the load —
   `driver.route.malfunction`'s two `[t1]` snapshots pin the F9/F10 contradiction, and the shared
   `i002…` path across both trees is the whole evidence. mask it and the labelled defect becomes
   unreadable

## .why it is not done in this round

**not safe, and not clean.**

- **not clean** — it is a convention decision plus a brief plus a possible normalizer rename,
  across two corpora that ~90 snapshot files depend on. the ripple is far past this branch's diff
- **not safe** — step 4 says a naive sweep would destroy evidence this branch deliberately pinned.
  a repair made under round pressure is exactly how that gets missed

⇒ and the local question it was raised against is already settled on evidence (the census above),
so the stone is not blocked on it.
