# 🌙 dream: a stale LLM key does not fail loud — it fails FAST, and the suite verifies no behavior

**kind**: reseed · **owner**: `ehmpathy/declapract-typescript-ehmpathy` (it owns the cicd workflow
templates this fleet stamps) · **caught** 2026-08-31

✅ **DISPATCHED 2026-08-31 — `ehmpathy/declapract-typescript-ehmpathy` #585, QUEUED**

## .the cue that fired

three `test-shards-integration` jobs failed on `rhachet-roles-bhrain` PR #399 with:

```
401 Unauthorized
  at BrainAtom.ask  (rhachet-brains-fireworksai@0.1.6/…/genBrainAtom.ts:189)
```

the secret **reached the runner** — the job env logs `FIREWORKS_API_KEY: ***`. fireworks rejected
the value. **the key was stale in CI and valid everywhere else.**

## .the gap, precisely

**the same suite passes locally: 15 tests, 2 suites, 0 failed, 175 seconds.**

| where | duration | what actually ran |
|---|---|---|
| local, on a key the provider accepts | **175s** | every brain call, for real |
| CI, on a stale key | **`elapsed: 0s`** | 🔴 **not one brain call** |

⇒ a 401 returns before any work begins. **so for as long as that secret has been stale, these tests
have verified no behavior at all in CI** — and the only signal was a red X that reads like any other
test failure.

🔴 **and this repo's last successful main run was 2026-08-06 — 25 days before the failure was
seen.** the window in which the gap could have opened is a month wide, and no artifact narrows it.

## 🔴 .why it belongs upstream — it is a FLEET pattern, measured twice in one week

a peer, `rhachet-brains-anthropic@feat-frontier-claude-models`, reports `ANTHROPIC_API_KEY` absent
from its `.agent/keyrack.yml` and names that absence as why **its** CI missed defects.

| repo | the key | the failure mode |
|---|---|---|
| `rhachet-brains-anthropic` | `ANTHROPIC_API_KEY` | **absent** from the manifest |
| `rhachet-roles-bhrain` | `FIREWORKS_API_KEY` | **present, injected, and rejected** |

⇒ **two repos, one week, two different mechanisms, one outcome: an LLM suite that tests no
behavior.** neither repo has a check that says *"the provider ACCEPTS this key"* before a suite
depends on it — and the manifest check catches only the first row.

🟡 **the second row is the harder one, and it is the one a manifest cannot see.** `keyrack.yml`
proves a key is **declared**; the job env proves it is **injected**. **neither proves it is
accepted**, and only the third fact is what the suite needs.

## .the shape of the fix

a **preflight** step in the shared test workflow, before the shards fan out:

- for each declared LLM provider, make the cheapest authenticated call the provider offers (a model
  list, a token count — never a generation)
- a **401/403 fails the job with a named fix**: *"`$KEY` is rejected by `$provider` — rotate the
  repo secret"*, exit 2 as a `constraint` (`rule.require.exit-code-semantics`)
- it runs **once**, not per shard, so the cost is one call per provider per run

⇒ **the win is not that it catches the failure — the shards already do that.** it is that it
**names** the failure. today a stale key surfaces as three red test shards that read like three
product defects, and a driver spends a full diagnosis pass to reach a credential.

🟡 **and preflight is the only place the check has teeth.** a per-shard check is a list — a new
shard rejoins the blind set the day it is added. the preflight is a **bound**: every shard is
downstream of it by construction (`rule.require.clamp-edge-cases`, and the recurrence named in
**#606**).

## .why it is not done in this round

it is **another repo's**, which is the whole reason it is a `reseed` and not a fix. bhrain stamps
the cicd templates it receives; the preflight belongs beside the template that fans out the shards,
or every repo in the fleet re-derives it — the exact braid `philosophy.pavement-saves-nature` names.

the local repair for bhrain is one command a human owns:

```sh
gh secret set FIREWORKS_API_KEY --repo ehmpathy/rhachet-roles-bhrain
```

## .the fulcrum

> **a credential that is DECLARED and INJECTED and REJECTED passes both checks we have and fails the
> only one that matters.** the suite still runs, still reports, and verifies no behavior — and it
> fails in the shape of a product defect, so the diagnosis starts in the wrong place every time.
> rework: **clean** — one preflight step in one shared workflow; no artifact hardens against it.
