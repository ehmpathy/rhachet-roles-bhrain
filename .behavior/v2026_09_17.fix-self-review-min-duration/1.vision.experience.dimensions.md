# 1.vision.experience.dimensions

the orthogonal dimensions of the experience space, and the walked product.

⇒ the verdict per cell is in `1.vision.experience.case=_.md`. this file holds **the axes and the
walk**, so a reviewer can check the space was factored rather than free-listed.

## .the surface under decomposition

one command, one gate: **`rhx route.stone.set --as promised --that <slug>`**, and the decision
`getSelfReviewChallengeDecision` renders for it.

## .the TWO discriminants, and the six dimensions under them

🔴 **`D1` and `D0` are DISCRIMINANTS, not dimensions.** each selects **which axes apply at all**, so
neither multiplies into the product — to do so would generate scores of cells, every one undefined.

| # | discriminant | positions | what it selects |
|---|---|---|---|
| **D1** | **actor** | `driver` · `route-author` | the driver's encounter is with a **verdict**, and `D2`–`D7` apply. the route-author's is with a **config key**, and none of them do |
| 🔴 **D0** | **the ask** | `on record` · `absent` | whether a trigger exists for this `(stone, slug)` at all. with an ask on record, `D2`–`D7` apply. with **no** ask, the guard refuses **before it opens a file**, so every one of them is undefined |

### 🔴 .why `D0` is a discriminant and not a seventh axis

it was added in arrears, at `5.3.verification`, after the suite exercised a verdict the catalog did
not hold (`rule.require.experience-catalog-evolution`'s backward terminus). the reason it is a
discriminant rather than an axis is mechanical, not a matter of taste:

**every one of `D2`–`D7` presupposes a question to answer.** `D3` measures the file's mtime *against
the trigger's `.since`* — with no trigger there is no operand. `D5` measures elapsed *since the ask* —
same. `D2` and `D4` are about a path the guard computes *to satisfy an ask*. ⇒ with `D0 = absent`,
the product is not sixty cells with an odd verdict; it is sixty cells with **no defined question**.

🔴 **and the state is REACHABLE, which is why it earns a discriminant rather than a footnote.** a
rewind clears a stone's triggers (`S10`), so a driver who promises after one has an articulation on
disk and no ask behind it. the guard's answer is `challenge:unasked`, and its whole job is to refuse
rather than to **launder** the ask — a defect measured first-party on this very round, where the
adjudication minted a `.since` dated *now*, so a pre-rewind articulation read as fresh against a
timestamp that postdated it.

⇒ so the space is **three disjoint spaces**, never one product:

| the actor | the ask | the axes that apply | live cells |
|---|---|---|---|
| `driver` | `on record` | `D2`–`D7` | **60** |
| 🔴 `driver` | `absent` | **none** — one encounter, the `challenge:unasked` refusal | **1** |
| `route-author` | — | none — one encounter, the `hashbar:` key | **1** |

### 🔴 .`D7` collapsed to ONE position — the fork is withdrawn

`S17`: the guard hands out **one** self review per ask, and the next is reachable only once this one
is promised. so `D7 = parallel` is not a position a driver can occupy.

**why it went**, in one line: a forked lane needs a slug, a path, and a **guide** — and the guide
renders only for the review in hand, the route is sealed against a `.guard` read, and no retrieval
command exists. ⇒ the lane's only move was to promise blind to provoke a refusal, which
`rule.always.bear-every-self-review` forbids. **an invitation no mechanism can serve is worse than
no invitation.** the full record: `case=8`, retired.

🟡 **the axis is kept rather than deleted.** an axis with one live position still earns its row: it
names a question the round asked and answered, and a later round that re-proposes the fork inherits
the argument rather than re-derives it. the inventory verdicts `D7 = parallel` **forbidden**, and
that verdict is the artifact.

🔴 **and `D7 = serial` gained two cells it did not have** — an **order** the ladder must enforce
(`challenge:unasked` on an out-of-order promise) and an **ask clock** that must start per review (one
trigger per ask, never M at the first `--as passed`). neither was a question while the fork was
assumed, and the second was a live defect that the fork's premise had concealed.

### 🔴 .`D6` and `D7` are correlated before the change, and independent after it

the walk below concludes *"`D6` and `D7` are one axis seen twice"*, and a reader who takes the
orthogonality column above at face value will read that as a contradiction. **it is not — the two
statements describe the space at two different times, and the column was silent about which.**

| | are `D6` and `D7` independent? |
|---|---|
| **today**, with a hash-keyed trigger | 🔴 **no.** a fork is the maximal generator of hash churn — M lanes repair concurrently, so every repair resets every other lane. `D7 = parallel` **implies** `D6 = changed` at high rate, and that implication is the mechanism that forbids the fork |
| **after** the hashless report | ✅ **yes.** `D6` collapses by construction, so a lane count no longer implies aught about any lane's verdict |

⇒ so the orthogonality justification for `D7` holds **in the target space**, which is the space the
inventory verdicts. the correlation is real, it is pre-change, and **it is the wish's own result
rather than a defect in the factorization** — the axis that is not orthogonal today is exactly where
the defect lives.

⚠️ **the honest cost, said plainly:** a factorization orthogonal only after the proposed change is a
factorization of the **intended** space, not the extant one. that is legitimate for a vision — the
inventory's job is to verdict the world the wish creates — but a reviewer should read every
`D6`/`D7` cell as a claim about the after, never the before.

⚠️ **the arithmetic below is stated once, here, and cited elsewhere rather than restated** — an
axis added mid-stone invalidates every count written before it, which is exactly how the earlier
`288` and `120` figures drifted apart across two artifacts.

🟡 **D7 arrived with `S06` and is the axis the extant design does not have.** today the guard hands
out one unpromised slug per run (`findNextUnpromisedReview` takes `.find()`), so `D7 = parallel` is
not merely unwalked — it is **unreachable**.

## 🔴 .the walk — two dimensions are DEGENERATE, and that is the wish's whole claim

a 144-row table would bury the result. the honest walk states **which axes stop to matter, and
why** — because the claim under test is precisely *"D6 must not change any verdict."*

### D6 collapses **by construction**, `144 → 72`

the trigger report becomes **hashless** — keyed `(stone, slug)`, which is how promises are already
keyed (`getStonePromises.ts:12` — *"all promises are hashless (firm checkpoints that don't
invalidate)"*).

⇒ with no hash in the key, a repair mints no new report, resets no clock, and clears no attempt
count. **every verdict is provably independent of D6.** that is the defect's repair, stated as an
invariant rather than as a patch.

🔴 **the asymmetry was the defect.** the gate was hash-keyed; the artifact it produces is hashless.
D6 is the axis that asymmetry lived on.

### D3 is undefined where D2 = `absent`, `72 → 60`

a file that does not exist has no mtime. the `D2=absent` slice is `72 / 3 = 24` cells; with `D3`
undefined there it collapses to `12`, so **12 cells are impossible, not merely unreached** — and
they are **subtracted**, never counted among the live ones.

⇒ **the live driver space is `60`** — that is the `D0 = on record` space. with the `D0 = absent`
cell and the route-author's one cell, the walked total is **`62`**.

### 🔴 D5 stays live and its OPERAND changed — `F01` was re-ruled

`F01` ran twice. the first verdict was **B** — keep the timer, hashless report. `S11` re-ruled it to
**E**: *keep the prompt, drop the clock.*

| | D5's positions | what the guard reads |
|---|---|---|
| **under B** | `elapsed < threshold` · `elapsed >= threshold` | a wall clock, against the trigger's `.since` |
| **under E**, as `S11` left it | `the challenge fires` · `it does not` | an **attempt count** per `(stone, slug)` |
| 🔴 **under `S13`** | `the challenge fires` · `it does not` | 🔴 **a CONJUNCTION** — `attempts == 0 ∧ elapsed-since-the-ask < 30s` |

⇒ **the axis survives at the same cardinality through all three, so no count in this file moves.**
what moved is the operand — twice.

🔴 **and the third operand is the one worth a second read: the clock came BACK, on a new job.** `S11`
removed the elapsed read; `S13` restored it and changed what it decides:

| | does it refuse a promise? | how often | who pays a wait |
|---|---|---|---|
| **B** | 🔴 yes | every fresh hash — unbounded | 🔴 every driver who arrives early |
| 🔴 **`S13`** | 🔴 **yes** — and a paragraph renders with it | **at most once per slug**, inside the window of the ask | ✅ **no one** |

⇒ *a clock that costs a command is not a clock that costs a wait.* that is the distinction
`0.wish.md`'s `.what is NOT wanted` did not have a word for — it forbids *"a cleverer clock"*, and a
reader must be pointed at the wait-vs-command split rather than left to find it (`F11`). ⚠️ **the
refusal is real** — `challenge:rushed` returns `challenged: true` and the cli exits 2 — so a reader
who takes *"it only speaks"* from this table has taken the wrong half.

🔴 **and that is why the axis could not simply be deleted.** the naive read of *"drop the clock"* is
`60 → 30`, a degenerate D5 — which would have been option **A**, and `A` was refused precisely
because it *"removes the delivery vehicle for the encouragement `S04` asks to keep."* the prompt
stays, so the axis that decides whether the prompt renders stays with it.

✅ **its exact positions are RULED** — `F11 = E1, bounded` (`S13`). the drive guessed `E1` at 70% and
the verdict took `E1` **conjoined with a target condition the fork did not hold**:

| option | D5 | ruled? |
|---|---|---|
| **E1** as tabled — blocks once per slug, everyone | **live**, and **universal** — every driver meets it | 🔴 refused |
| **E2** — the prompt rides the ask, blocks never | **degenerate** — `60 → 30`, the gate reduces to path + freshness | 🔴 refused |
| ✅ **E1 ∧ `elapsed < 30s`** (`S13`) | **live**, and **targeted** — only a promise inside 30s of the ask | ✅ **taken** |

⇒ **the axis is live, so the inventory's 30 `it does not` cells all stand.** what the verdict changed
is *which drivers reach the `fires` position*: under the tabled `E1` it was everyone, and under `S13`
it is the hasty alone.

🟡 **`E2` would have retired 30 cells and is refused**, so the risk this section flagged — *"`F11` is
worth half the driver space"* — is closed rather than carried.

### 🔴 and it is worse than an ORDER defect — the path check is SHORT-CIRCUITED

`getSelfReviewChallengeDecision.ts:61-67`:

```ts
// no report = first challenge, start timer now (introduces concept before file check)
if (!report) {
  await setSelfReviewTriggeredReport(input);
  return { decision: 'challenge:first', articulationPath };
}
```

**the file check is at `:70` — after that early return.** so on the first promise against any fresh
trigger, the guard returns `challenge:first` **without one look at the filesystem**, whatever the
driver's path or claim says.

⇒ so `D5 × c1–c4, c6–c9` is not violated by a wrong **order**; it is violated by an **absent check**.
a driver whose real defect is a path is handed a clock message and learns of the path only on
attempt 2. the code comment states the intent plainly — *"introduces concept before file check"* — so
this is a design choice rather than a slip, and it is the choice the invariant forbids.

🟡 **measured on this stone.** the drive promised `has-questioned-requirements` with the file at `r2`
and the guard owed `r3`. the first attempt returned `patience, friend` — the clock. the **second**
attempt named the absence and the path. the round trip that taught the real lesson was the one the
clock made the driver wait for.

⇒ **so every `[t0]` in `case=3`, `case=4`, and `case=5` carries an implied precondition the vision
never stated: the path verdict must be reachable on the FIRST attempt.** the `challenge:first`
early-return must move below the path check, or carry the path verdict with it.
