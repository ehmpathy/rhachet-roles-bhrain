# 🌙 dream: each route ledger name has one import-free owner

kind = refactor · owner = ehmpathy/rhachet-roles-bhrain · caught 2026-10-24

## .the cue that fired

a peer review of the status line cache found its fingerprint types `passage.jsonl` and
`reviewPeerMeters.jsonl` as literals. if a ledger were renamed, the fingerprint would stat a name
the render never reads, and every guard change would show only at the 30s max age.

## .the gap, precisely

the two names are typed by hand in at least eight production files:
`statusLine/cache/getOneRouteStatusLineFingerprint.ts`, `passage/setPassageReport.ts`,
`passage/getAllPassageReportsRaw.ts`, `getAllStoneDriveArtifacts.ts`,
`guard/getOneStoneGuardApproval.ts`, `guard/setStoneGuardOverrule.ts`,
`getAllRouteStoneGuardReviewPeerMeters.ts`, `setRouteStoneGuardReviewPeerMeter.ts`.
`getStoneYieldGlob.ts` records the same drift class, which once left 13 markers unarchived.

## .the shape of the fix

- one import-free owner per ledger, the shape `asRouteBindFlagName` holds: e.g.
  `route/ledger/asRouteLedgerName.ts` that returns `'passage.jsonl'` / `'reviewPeerMeters.jsonl'`
  by a closed `kind` (no runtime branch: two named exports, per the `getStonePromisePaths` note)
- each of the eight files imports it; a grep for the literal outside the owner returns zero
- a completeness clamp: render a full-state route under an `fs` spy and assert each `.route/*`
  file it opens is a fingerprint row or on a named not-fingerprinted list

## .why it is not done in this round

safe, but not clean: it ripples into eight files across the passage, guard, and meter domains,
none of which this fix opens. the fingerprint takes the bind flag and promise names from their
owners already; F1 records the ledger literals as the accepted bound.
