# 🌙 dream: the guard emit crashes with a raw EPIPE stack when stdout closes early

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, on the critical-path walk for `review.self r6` of
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

i piped a guard run into `head -14` to trim the output. `head` closed the pipe after 14
lines, and the guard did not exit — it crashed, and printed a raw node stack trace over
the output i was reading.

## .the gap, precisely

`genContextCliEmit.ts` writes to stdout through a `seal`/`emitLines` path that installs no
`error` handler on the socket. when the reader closes early, node raises an unhandled
`'error'` event and the process dies:

```
🪨 run solid skill repo=bhrain/role=driver/skill=route.stone.set
   └─ 💥 failed with an error

node:events:505
    throw er; // Unhandled 'error' event
    ^

Error: write EPIPE
    at afterWriteDispatched (node:internal/stream_base_commons:159:15)
    ...
    at seal (dist/domain.operations/route/guard/genContextCliEmit.js:53:26)
    at emitLines (dist/domain.operations/route/guard/genContextCliEmit.js:60:13)
    at handleReviewEvent (dist/domain.operations/route/guard/genContextCliEmit.js:202:13)
  errno: -32,
  code: 'EPIPE',
  syscall: 'write'
}
```

⚠️ **the exit code is the sharper half.** the crash replaces whatever verdict the guard
had reached, so a `blocked` (2) or an `allowed` (0) becomes a node fault. any wrapper that
reads the exit code — a hook, a CI step, a calling operation — is handed a fault where a
verdict was due.

⇒ this is `rule.require.errors-name-the-fix` and `def.frictionless`' *"no unexpected error,
stack trace, or stall"*, on the one surface a driver reads most.

## .the reach — it is not only `head`

`| head`, `| less` (quit before the end), and any consumer that exits early all close the
pipe the same way. `less` is the common one: a driver pages a long guard tree, presses `q`,
and gets a stack trace.

## .the shape of the fix

install an `error` listener on the stdout stream in `genContextCliEmit`, and treat `EPIPE`
(and `ERR_STREAM_DESTROYED`) as a normal end-of-consumer — stop emitting and exit with the
verdict already computed, rather than throw.

🔴 **do not blanket-swallow.** `rule.forbid.failhide` binds here: an `EACCES` or an `ENOSPC`
on stdout is a real fault and must still surface. narrow the catch to the early-close codes
by name, exactly as `isENOENT` is used elsewhere in this tree.

## .why it is not done in this round

- **not safe** — the seal is the shared write path behind *every* guard emit. a catch drawn
  one code too wide converts real write failures into silent truncation, which is the
  failure mode `rule.forbid.failhide` exists to stop. it wants its own clamp
- **not clean** — the handler belongs on the stream at construction, so it touches the emit
  context every guard call flows through; the ripple lands far outside this behavior's diff
- **out of scope** — `git diff --stat HEAD -- src/.../genContextCliEmit.ts` is empty. this
  behavior never touched the file; the defect predates it and is unrelated to the
  contemplation gate
