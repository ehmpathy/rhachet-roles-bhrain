# 🌙 dream: a snapshotted LLM verdict exhausts its three retries

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-20

## .the cue that fired

a full acceptance run went **3605 passed, 2 failed**, and both failures were one case:

```
review.by.guard-peer.acceptance
  › [case-seam-pass-aggregation] guard peer runs review.by --for term-aggregation, code is clean
    › [t0] the stone is passed → the guard approves off a raw base review, attempt 1
```

the diff is a **verdict**, never a format:

```
- │   ├─ approved [TIME]        - │   ├─ 0 blockers ✓
+ │   ├─ rejected [TIME]        + │   ├─ 1 blocker 🔴
```

⇒ the case seeds code it declares **clean** and asserts the peer lane returns `0 blockers`. the lane
returned `1`, so the judge blocked, so the whole guard tree rendered a different shape — and **both**
of that step's snapshots moved together (the stdout and the captured artifact).

## .the gap, precisely

the case is **already** declared probabilistic, and the declaration did not hold:

```ts
const REPEATABLE_CONFIG = { attempts: 3, criteria: 'SOME' } as const;
```

`criteria: 'SOME'` passes if **any** attempt passes. ⇒ **all three attempts returned `1 blocker`**,
which is what a failure of this shape means. the file's own docblock names the risk exactly —
*"the verdict itself is what varies, handled by SOME"* — so the design anticipated the variance and
the budget did not absorb it.

⚠️ **measured once, so the rate is unknown.** an isolated re-run of the same case went green
(`15 passed, 0 failed`) in 29s, which confirms **variance** rather than a regression, and says naught
about how often. the prior full run in this same round was `3607 passed, 0 failed` — same test count,
so no test was added or removed between them.

🔴 **and the retries may be less independent than `attempts: 3` assumes.** if the rubric plus the
fixture put the reviewer near a decision boundary, three draws from one prompt are three draws from
the **same** distribution, not three chances at an unlikely event. that is the question worth an
answer before a retry count is raised.

## .the shape of the fix

🔴 **do NOT simply raise `attempts`.** a count raised with no measured rate is a guess, and if the
draws are correlated the next value fails for the same reason.

three candidate directions, in the order they deserve a try:

1. **measure first.** drive the case N times, record the per-attempt verdict. that number decides
   between every option below, and no option is defensible without it
2. **split the assertion from the verdict.** the case's subject is the **guard-tree seam** — that a
   `review.by` peer lane's output reaches the judge and renders. the LLM's verdict is the one part of
   that it does not intend to test, and it is the only part that varies. a fixture reviewer (or a
   pinned recorded verdict) would prove the seam with no draw at all, and a separate, un-snapshotted
   case could keep the live-LLM coverage
3. **widen the fixture's margin.** if the seeded code sits near the rubric's boundary, move it
   further from it, so a stricter draw still returns `0`

⇒ 2 is the direction this dream favours: a **snapshot** asserts an exact string, and an exact string
over a probabilistic verdict is a contradiction the retry budget only ever papers over.

## .why it is not done in this round

**SAFE: no** — and that is the half that blocks, which is rare for a test-only change. every option
above either changes what the case proves (2, 3) or changes a number with no evidence (1's absence).
a round whose subject is the **self**-review gate has no business to re-scope a **peer**-review
acceptance case's contract.

**CLEAN: no.** `blackbox/review.by.guard-peer.acceptance.test.ts` was never opened by this round; it
is not in the diff, and neither is its snapshot file. options 2 and 3 additionally re-take snapshots
this round has no other reason to touch.

⚠️ **and the honest bound on the evidence: one observation.** `rule.require.clamp-edge-cases` asks
that a fix be proven by revert — here there is no fix to revert, because there is no diagnosis yet.
the measurement in step 1 is the whole first move.
