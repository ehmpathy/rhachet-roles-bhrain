## .what changed

### P2a — the debt is keyed to the reviewer

`getAllRouteGuardReviewPeerGivensAtHash` → **`getAllRouteGuardReviewPeerGivens`**. the rename is the
contract change: it no longer takes a hash. it enumerates every hash and keeps the latest given per
slug, by the **numeric** iteration.

- `getRouteGuardReviewPeerPathMeta` now parses `iteration` as a `number`, and returns it beside
  `slug` — those two alone. it still *matches and validates* the hash segment, so the grammar check
  keeps its teeth; it just refuses to hand one out (i004, r11 b2)
- the pick lives in its own file, `getLatestPeerGivensPerSlug` — pure, and unit-clamped
- ⚠️ **it takes a MAX, never a first-or-last.** `enumFilesFromGlob` returns raw `globby` output and
  no caller sorts it, so an order-dependent pick would be filesystem-dependent — right on one
  machine, wrong on another. `[case4]` hands the same givens over in three different orders and
  demands one winner

`getRouteGuardReviewPeerContemplationStatus` dropped its `computeStoneReviewInputHash` call
entirely. readiness no longer depends on the current generation at all.

### P2b — the pair is matched on the DERIVED PATH

```diff
- (taken) => taken.slug === given.slug && taken.hash === input.hashCurrent
- (taken) => taken.slug === given.slug && taken.hash === given.hash
+ !pathsTaken.has(getRouteGuardReviewPeerPathTaken({ pathGiven: given.pathGiven }))
```

`hashCurrent` left the input shape. to have changed P2a and missed this site would have deadlocked
the gate: a carried given at H1 prints a taken path at H1, no prompt in the engine names an H2 path,
so a matcher keyed to H2 would refuse a file the driver has no way to produce.

🔴 **the middle line shipped first and was wrong too** — `behavior-intent-coverage` refuted it at
i002. `(slug, hash)` is not a given's **identity**: a `.taken` write does not move the artifact hash
(`computeStoneReviewInputHash` covers the `artifacts:` set only), so a reviewer that re-runs after it
was answered writes its fresh critique at the **same hash**, one iteration later — and that key hands
the fresh critique the prior answer. **the wish's own defect #1, reached through the honest
convergence loop rather than through any attempt to escape.**

⇒ the landed key is the path itself, and the reason it is the right one was already written in the
codebase. `getRouteGuardReviewPeerPathTaken`'s docblock: *"a pure string transform of the given path,
NOT a re-derivation from {stone,iter,hash,idx,slug}, so the given↔taken pair can never silently
desync."* **both wrong keys were exactly such a re-derivation.** `RouteGuardReviewPeerTakenMeta` now
drops `hash` entirely, with a note on why, so it is not helpfully restored.

**the general form, recorded in `term=route.guard.review.contemplate._.choice.reason.md`:** *a
given's identity is its path, and every attempt to re-derive that identity from a subset of its
coordinates has so far picked a subset that is not unique.*

### P1 — the gate moved to the door

inserted in `setStoneAsPassed` after the zero-reviewer auto-pass and before `stampGuardReport`. that
seam is structural, not aesthetic:

| it sits before | so a halt |
|---|---|
| `stampGuardReport` | cannot stamp a report for reviews that never ran |
| `computeStoneReviewInputHash`, `getMaxStoneGuardIteration` | needs no hash — the gate takes `{ stone, route }` |
| the review subprocesses | costs no round at all |

⚠️ **the halt is not free** (`r7`). it reads and
regex-parses **every** historical `.given` across all hashes, so its latency scales with total
conversation history rather than with the live reviewer count — and both gates pay it, since they
legitimately see different sets (F4). the comparison that holds is against what it replaces: a full
corpus scan is cheap against a spawned round plus judges. the per-reviewer cache key that would
narrow it is wish scope item 1, fenced out of this behavior.

**pure reuse, as contracted** — every target was already imported before the diff, and **no new
operation survives in the gate.** one was authored mid-round and then deleted by `r3`: the extant
`computePeerUncontemplatedUnforgiven` was one type parameter short of the job, so it got the type
parameter rather than a neighbour.

⇒ the gate now takes **one** read: `getStoneGuardReviewPeerUncontemplatedUnforgiven` returns the full
record, and the reply-prompt renders straight from it.

**both gates stay.** the entrance catches debt carried *into* a round; the exit catches debt created
*by* one. a note at the exit gate says so, so a later reader does not "dedupe" them.

### F7 — the stale line stopped blaming the artifact

```diff
-   why: the stone artifact changed, so the reviewer re-ran at a new hash.
+   why: the reviewer has spoken again. your prior response still
+        stands for what it answered — this is a NEW critique.
```

under reviewer-keyed debt an edit does **not** stale an answer. the old copy taught the exact wrong
model — that an edit acts upon your answer — and a driver who believes it will edit again.
