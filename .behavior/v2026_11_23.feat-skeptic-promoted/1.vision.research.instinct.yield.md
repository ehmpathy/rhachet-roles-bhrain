# PART A (lead): how industry builds an instinct INTO an agent, beyond prompts

the human's constraints, kept as filters on each item:
- the doubt must be GENERAL (any claim, any domain), not tied to one command. "a predicted test result is worthless: nobody runs a test to see it fail."
- a counter-take is rejected if it is "just a reviewer" (a peer is never the first skeptic; the agent must doubt first).
- a role is briefs + skills + hooks around a FIXED model. so for each item: can a role adopt it, or only training?

## A0. the one result that sorts all the rest: where does the outside signal come from

- Huang et al. full text (read via bhrowser, https://arxiv.org/html/2310.01798, 2026-11-26): after self-correction "the accuracies of all models drop across all benchmarks"; GPT-3.5 on GSM8K keeps its first answer 74.7% of the time, and when it does change, it is more likely to flip a right answer to a wrong one than the reverse; the gains that Reflexion and RCI reported came from oracle labels, and "the improvements vanish when oracle labels are not available"; multi-agent debate is "no better than self-consistency" at equal response count.
- the same paper names what does work: "when valid external feedback is available, it is beneficial to leverage it" (code execution results, search tools, trained verifiers) (read via bhrowser, same URL).
- Kamoi et al. 2024 survey, https://arxiv.org/abs/2406.01297, 2026-11-26 (read via bhrowser, abstract): "(1) no prior work demonstrates successful self-correction with feedback from prompted LLMs, except for studies in tasks that are exceptionally suited for self-correction, (2) self-correction works well in tasks that can use reliable external feedback, and (3) large-scale fine-tuning enables self-correction."
- consequence for a role: a prompt-only role (fixed model) has two honest routes. (i) route a real outside signal into the doubt (tool output, a decorrelated context, a written spec). (ii) accept that an instinct in the weights can only come from training (Kamoi point 3). a brief that says "doubt yourself" with no signal is the intrinsic case that Huang measured as harmful.

## A1. training-time routes (a role cannot adopt these; it can only borrow the shape)

| route | what it generalizes | what feeds the doubt an outside signal | measured effect | role-adoptable? |
|---|---|---|---|---|
| Constitutional AI, Bai et al. 2022, https://arxiv.org/abs/2212.08073, 2026-11-26 (read via bhrowser, abstract) | a model critiques and revises its own outputs against a list of written principles; then it is fine-tuned on the revisions, then RL from AI feedback | the written principles; no human labels of harm | a "harmless but non-evasive" assistant "with far fewer human labels" (abstract; no effect size there). critique helps small models more than large ones, and the first revision removes most harm: `guess:` (search summary) | the shape only: a brief that holds principles plus a critique-then-revise step at answer time. the baked-in instinct needs fine-tune |
| Deliberative Alignment, OpenAI 2024, https://arxiv.org/abs/2412.16339, 2026-11-26 (read via bhrowser, abstract) | the model is trained "to explicitly recall and accurately reason over the specifications before answering" | the written spec, recalled at answer time | "pushes the Pareto frontier": more jailbreak robustness and less overrefusal at once; better out-of-distribution (abstract; no numbers there) | the shape is adoptable: boot a spec brief and require recall before the claim leaves. recall with no prompt came from training |
| calibration: Kadavath et al. 2022, https://arxiv.org/abs/2207.05221, 2026-11-26 (read via bhrowser, abstract) | any claim: the model proposes an answer then scores P(True); or is trained to predict P(IK), "I know" | none for P(True) (own calibration); labeled right/wrong for P(IK) | larger models are "well-calibrated" on multiple-choice and true/false in the right format; P(IK) "partially generalize[s] across tasks" but calibration is weak on new tasks | P(True) as a prompt step is cheap to try, but it is intrinsic (no outside signal), so Huang applies. no study read on a P(True) prompt in a code agent. `guess:` it would not help |
| process reward models, Lightman et al. 2023, https://arxiv.org/abs/2305.20050, 2026-11-26 (read via bhrowser, abstract) | a verifier trained on step-level human labels | 800,000 step labels (PRM800K) | "process supervision significantly outperforms outcome supervision"; 78% of a MATH test subset | no. needs a trained verifier; math domain. the role-level echo is a separate verifier agent |

verdict for A1: these show a doubt habit can be general and can be a default of the model, but each needs a trained model plus a source of ground truth (principles, spec, labels). a role cannot install that. it can copy the shape (a spec in the boot brief; critique against the spec) and must supply the outside signal itself.

## A2. harness patterns that shipped in real code agents (a role CAN adopt these)

### A2.1 Claude Code: "a way to verify" plus enforce by hook
- best-practices page, https://code.claude.com/docs/en/best-practices, 2026-11-26 (read via bhrowser): the table row "When it's done" lists "A request for evidence, /goal, /code-review" as prompts and "Tests, typecheck, a Stop hook, CI" as the enforced forms.
- the same page states the adoption gap this research asks about: a line like "Always typecheck before you finish" in the instruction file "works most of the time, not every time"; a Stop hook "is enforced by Claude Code (the harness), so the turn doesn't end until the typecheck passes or the block limit is reached" (read via bhrowser, same URL).
- fresh-context review: "/code-review reviews the diff in a fresh subagent that never saw your conversation. It isn't swayed by the reasoning that produced the code" (read via bhrowser, same URL). the cost note on the same page: subagents cost tokens and can be slower (read via bhrowser).
- the Anthropic team post, https://claude.dev/blog/solving-code-review-at-anthropic/, 2026-11-26 (read via bhrowser): "We give Claude something it can run ... and ask it to show the output instead of saying it's done. Then a subagent reviews the diff with fresh context." findings "get verified by other agents ... a separate group votes on each finding ... We A/B tested those filters on our own PRs before we kept them." no effect size read.
- hooks reference, https://code.claude.com/docs/en/hooks, 2026-11-26 (read via bhrowser): the Stop event has "no matcher support" and "always fires on every occurrence"; exit code 2 on Stop "sends Claude back to keep working"; a prompt-based hook can have a model judge "whether all tasks are complete before allowing Claude to finish"; `/goal` "is a built-in shortcut for a session-scoped prompt-based Stop hook"; loop guards: an "8-consecutive-continuation cap" and a `stop_hook_active` flag.
- what is generalized: the cue is "the turn is about to end" (any claim, any domain, no command). what feeds the signal: a second model judge or a fresh-context reviewer that reads the final message and the diff, plus what any check command prints. measured effect: none published in what was read. role-adoptable: yes, fully (a hook plus a skill). risk: a prompt-based Stop judge is the closest relative of the word-pattern hook that cried wolf; the docs carry a loop cap because a judge can block forever.

### A2.2 SWE-agent: a guardrail in the tool the agent already calls
- SWE-agent paper, https://arxiv.org/html/2405.15793, 2026-11-26 (read via bhrowser): "we integrate a code linter into the edit function"; "invalid edits are discarded, and the agent is asked to try the edit again"; the lint ablation shows a 3.0 point gain in solved-issue rate over edit with no lint; 51.7% of GPT-4 Turbo runs had at least one failed edit; "the odds of recovery decrease as the agent accumulates more failed edits."
- what is generalized: none. it is tied to one command (edit). the doubt is a hard gate in the tool, not an instinct. outside signal: a linter. role-adoptable: yes, as a hook on edit, but it is the command-specific shape the human rejected for self-doubt. keep it as proof that a check folded into a tool the agent already calls is adopted with no effort from the agent.

### A2.3 Aider: auto-run checks, the default is the adoption lever
- https://aider.chat/docs/usage/lint-test.html, 2026-11-26 (read via bhrowser): "By default, aider will lint any files which it edits"; tests run after each edit only with `--test-cmd` plus `--auto-test`; "Aider will try and fix any errors if the command returns a non-zero exit code." lint is on by default; the test hook is opt-in. no usage data.
- command-specific, same limit as A2.2. role-adoptable: yes.

### A2.4 reproduction tests as a check of the claim "this bug is fixed"
- SWT-Bench, https://arxiv.org/abs/2406.12952, 2026-11-26 (read via bhrowser, abstract): "generated tests are an effective filter for proposed code fixes, [2x] the precision of SWE-Agent."
- TestPrune, https://arxiv.org/abs/2510.18270, 2026-11-26 (read via bhrowser, abstract): reuse of regression tests gives "8.0%-12.9% relative increase in issue [fix] rate within Agentless, SWE-Agent, and Trae agent."
- on the human's point: the useful test is one that FAILS before the fix and passes after (a differential), not a test whose pass the agent predicted. that is a signal from the world, so it is not "a predicted result".
- a test the agent writes can share the patch's wrong reading of the issue, and repeated self-check changes few patches: `guess:` (search summary; not read).
- command-specific (a test run); role-adoptable.

### A2.5 memory of past mistakes (Reflexion shape)
- Reflexion, Shinn et al. 2023, https://arxiv.org/abs/2303.11366, 2026-11-26 (read via bhrowser, abstract): agents "verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer"; 91% pass@1 on HumanEval vs 80% for GPT-4.
- caveat from Huang (read via bhrowser, https://arxiv.org/html/2310.01798): Reflexion's reasoning gains used oracle labels. its code gains use unit-test results, an outside signal. so a lesson store works when each lesson was bought with a real failure signal.
- generalizes: a lesson is text, so it can cover any domain. outside signal: the failed test or the human correction that made the lesson. role-adoptable: yes. a role can persist lessons as briefs (this repo's learner role holds that shape; not re-read here).

### A2.6 expectation before action
- WMLLM, https://arxiv.org/abs/2609.01608, 2026-11-26 (read via bhrowser, abstract): "predict-then-act" for black-box optimization, trained with reinforcement learning; state-of-the-art on a molecular benchmark at a small budget. optimization domain, trained model. the scores 4.071 vs 4.329: `guess:` (search summary).
- EOCV, https://arxiv.org/abs/2611.02438, 2026-11-26 (read via bhrowser, abstract): the agent states the expected outcome of each action and compares it to the observation; a mismatch triggers a replan; "broadly comparable average task performance" with a "29-35% reduction in average weighted token usage." the gain is cost, not accuracy.
- Qian et al. 2026, https://arxiv.org/abs/2601.03905, 2026-11-26 (read via bhrowser, abstract): agents given a world model as a tool "rarely invoke simulation (fewer than 1%)", "frequently misuse predicted rollouts (approximately 15%)", and show "degraded performance (up to 5%) when simulation is available or enforced"; the bottleneck is "decide when to simulate".
- reading: this matches the human's rejection. expectations help as a mismatch trigger for cost or in a trained loop; an optional foresight tool is ignored (under 1% use) and a forced one can hurt. command-specific. not a base for a self-doubt instinct.

### A2.7 generality: the one tool-free method that attacks ANY claim in a draft
- Chain-of-Verification, Dhuliawala et al. 2023, full text https://ar5iv.labs.arxiv.org/html/2309.11495 and https://arxiv.org/abs/2309.11495, 2026-11-26 (read via bhrowser): draft; plan verification questions about the draft's claims; reply to each question in a context that does NOT hold the draft ("crucially the context ... only contains the questions"); then revise. on list tasks (Llama 65B): hallucinated answers per query 2.95 (few-shot) to 0.68 (two-step CoVe); precision 0.17 to 0.36; longform FactScore 63.7 (factored) to 71.4 (factor+revise). stated reason: "models that attend to existing hallucinations in the context from their own generations tend to repeat the hallucinations."
- what is generalized: any claim in prose, any domain. what feeds the "outside" signal: not the world; a decorrelated context (the claim is re-derived from a question alone). so it is not the no-signal case of Huang (the reply to the question is a second independent draw, not a re-read of the first). limit: it fixes facts the model can recall; it cannot catch a claim the model gets wrong both times; it was measured on fact tasks, not on code claims or "done" claims.
- role-adoptable: yes, with a skill that asks the verification questions in a clean context. the agent doubts its own claim first (it writes the questions), so it is not "just a reviewer".
- Self-Refine, Madaan et al., https://arxiv.org/abs/2303.17651, 2026-11-26 (read via bhrowser, abstract): same-model feedback loop, "~20% absolute on average" across 7 tasks. Huang (read via bhrowser) contests it: on one task the gain came from a weak first prompt and vanished when the first prompt held the requirement. use with care.
- CRITIC, Gou et al., https://arxiv.org/abs/2305.11738, 2026-11-26 (read via bhrowser, abstract): "our research highlights the crucial importance of external feedback." the "without tool" ablation numbers: `guess:` (search summary).
- OpenHands, https://arxiv.org/abs/2407.16741, 2026-11-26 (read via bhrowser, abstract page): no mention of a critic or self-check loop on that page. the full text was not read. Cursor and Devin: not read; no claim made.

## B2. implementation intentions
- Gollwitzer 1999, American Psychologist 54(7), 493-503, abstract: https://www.ovid.com/journals/ampsy/abstract/00000487-199907000-00004~implementation-intentions-strong-effects-of-simple-plans, 2026-11-26 (read via bhrowser): plans of the form "Whenever situation x arises, I will initiate the goal-directed response y!" - Gollwitzer and Sheeran 2006 meta-analysis, full text (djvu) at https://ia801505.us.archive.org/34/items/06GollwitzerSheeranImplementationIntentionsAndGoalAchievement/06GollwitzerSheeran_ImplementationIntentionsAndGoalAchievement_djvu.txt, 2026-11-26 (read via bhrowser): "d = .65 based on k = 94 tests that involved 8461 participants"; d = .65 is the gain over a goal intention alone; d = .61 on the failure to start goal pursuit.

# PART D: predict-then-observe and the pretest effect

- POE review, https://www.mdpi.com/2673-8392/6/11/242, 2026-11-26 (read via bhrowser): prediction "creates epistemic commitment and reveals prior reasoning"; but findings "remain heterogeneous"; the review did no meta-analytic estimate; "a prediction without reasons becomes guessing" [sic: the source says so]; a confirmed prediction can also teach; "contradiction alone is weak", learners may "reject the result, reinterpret it, attribute it to apparatus"; the authors flag a bias toward positive reports. so the evidence is moderate and the unit is a class lesson in which a teacher shows the real result.
- the pretest effect (Kornell, Hays and Bjork 2009; Richland et al.): the williams.edu pdf and the Journal of Cognition page both failed in the browser (empty pdf text; navigation timeout). from the search summary only: `guess:` a failed attempt before feedback aids later learning, but not when feedback is delayed. https://web.williams.edu/Psychology/Faculty/Kornell/Publications/Kornell.Hays.Bjork.2009.pdf, 2026-11-26.

# RANKING: mechanisms by evidence for turning self-doubt into an instinct in an agent, and how each wins adoption

rank by (a) strength and directness of evidence for an LLM agent, (b) fit to the constraints (general, agent-first, role-adoptable).

1. an outside signal at a fixed cue, enforced by the harness (a Stop-hook gate that makes the agent produce its own check, with real evidence: tests, a diff, a fresh read). evidence: Huang, Kamoi, CRITIC, SWE-agent +3.0, SWT-Bench 2x, Claude Code docs. weak point: the Stop-judge form has no measured effect and is kin to the cut word-pattern hook. adoption: the harness fires it each turn end (the hooks doc says Stop always fires); the agent need not remember. who makes it the path: the role's own hook, shipped in the role so the user installs the role once. guards: the loop cap (8 continuations), a way to say "claim is not checkable" and pass, a low false-alarm rate.
2. independent re-derivation of the agent's own claims (CoVe factored). evidence: the strongest tool-free, general, measured effect (2.95 to 0.68; FactScore 63.7 to 71.4). weak point: measured on facts, not on "done" or code claims. adoption: a skill the agent calls itself, so it is the first skeptic; make it the path of least effort by fit into the skill the agent already calls to finish or to report (fold into an extant tool, not a new one). who: the role author, via the hook that asks for it at the cue.
3. a cue-bound if-then plan as the brief (implementation intention). evidence: d = .65 over 94 tests in people; no LLM test read. as a brief alone it is "works most of the time, not every time" per Claude Code docs, so it needs rank 1 behind it. adoption: the boot brief states "when X, do Y"; the hook holds the cue. who: the role (boot) plus the hook; no user effort.
4. consider-the-opposite as a named act (state the strongest case that the claim is wrong, then check it against a source). evidence: Lord 1984, beats a vague "be unbiased" order; for LLMs it is the intrinsic case unless a source is checked (Huang). adoption: phrase it as an act with an output, inside the same gate; do not ask for an attitude.
5. lesson memory from real failures (Reflexion shape). evidence: 91 vs 80 on HumanEval with test signals, discounted by Huang. adoption: lessons become briefs that boot each session; the human correction is the signal. slow (failures must come first).
6. pre-mortem (prospective hindsight). evidence: human, mostly the safe-to-dissent mechanism (Klein, first paragraph read); the 30% is unverified; no LLM test read. adoption: cheap as a prompt inside rank 1 or 2; do not rank it on its own.
7. habit by repeat (cue, routine, reward; 66 days). for a person, the base story. for an agent, repeats can only come from a hook that fires each turn (rank 1) or from training; the "reward" has no clear analog. a role cannot install weights.
8. predict-then-observe. evidence: class benefit is heterogeneous; for agents it gives cost savings (EOCV), a trained gain in one optimizer (WMLLM), and optional foresight use of under 1% (Qian). command-specific and rejected by the human; hold it only as a mismatch trigger, never as the core.
9. training-time routes (CAI, deliberative alignment, calibration, PRM). the strongest route to a real baked-in instinct (Kamoi point 3), but out of reach of a role. adoption: a vendor change; track it, borrow the shape (a written spec recalled at the cue).

## adoption in one line each
- persons: a cue the person already meets, a response small enough to do each time, a safe place to dissent (Klein), and a repeat count (about two months, Lally).
- agents: the harness owns the cue (hooks fire each turn end), the check is fit into the tool the agent already calls, the default is on, the output is a checkable fact and not a hunch, and the false-alarm rate stays low so the gate is not ignored.

bhrowser defects hit:
1. `browser.action --play` rejects a path with no leading slash as "not a valid package name"; a `./` path is looked up under the skill's install dir, not the cwd. only an absolute path works.
2. the playbook doc (`howto.browser-action-playbooks.md`) says `export default async (page, ctx)`, but the runner needs `export const action = async ({ page, browser })` and fails with "playbook must export an action function".
3. no `--ctx` or args flag, so each URL list needs a file the playbook reads.
4. pdf tabs: Chrome's pdf viewer gives empty `innerText` (Wood and Neal, Klein pdf, Mellers pdf, Kornell, CoVe pdf all returned 0 chars). no text-layer path.
5. bot walls (Cloudflare, ResearchGate, Semantic Scholar, NEJM, Wiley) block the headful browser, and a batch has no pause step for a human to clear one.
6. slow: roughly one to two minutes per page in a batch; a stalled `goto` (Journal of Cognition) cost the full 45 seconds; no progress output until the whole batch ends, so an agent must poll the files.
7. `browser.snapshot --focused` takes only the current tab, so proof per page needed a custom screenshot inside the playbook.
