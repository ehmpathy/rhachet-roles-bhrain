# 🌙 dream: one shell tokenizer for the memory guard's leaves

- kind: lift
- owner: rhachet-roles-bhrain (src/domain.operations/memory)
- caught 2026-11-01

## .the cue that fired

the l3 arch lane of `fix-memory-guard-fails-open`, round i006, traced a mis-split (a lone `&`, an escaped quote, `$'…'`) to five leaves that each read shell text by their own rule.

## .the gap, precisely

- `getAllBashCommandSegments` splits on a masked copy of the command
- `getOneBashCopyVerb` and `asMemoryGuardActOfCopy` split words on whitespace
- `asBashCwdAfterSegment` and `isBashAssignmentSegment` read the first words
- `getAllBashRedirectTargets` and `getOneMemoryPathFromCommand` read words via `BASH_WORD_CHAR`

a quoted word with a space reads as two words in every leaf but the mask.

## .the shape of the fix

`getAllBashTokens({ command }) → Array<{ kind: 'word' | 'operator'; text; quoted }>`, which tracks quote, escape, and `$'…'`. segments are the runs between separator operators; the verb, destination, cwd, assignment, and redirect leaves each read tokens. each leaf's extant case table stays its clamp, and gains a quoted-space row.

## .why it is not done in this round

the round's wish is a fail-open fix. the reader exemption already fails safe, and `asBashQuotesMasked` already holds the quote grammar in one place. the lift waits for the next parse bug (fulcrum F8).
