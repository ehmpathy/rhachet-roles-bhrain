## .the narrative — the driver's pov

four reviewers are in flight at level 1. thirty seconds in, one of them dies — the api key for
that rubric expired, and it exits 2 with zero blockers. a genuine constraint.

what must **not** happen: the other three get cancelled, and i am handed one constraint and three
absences. that would be strictly worse than today, because today the serial loop would have run
all four and given me three real verdicts plus one constraint. concurrency that turns one failure
into four is a regression in a speedup's clothes.

what must happen: the three stay aloft. they land. the level reports four outcomes — three
verdicts and one constraint — and the constraint is terminal-for-unlock, so level 3 still opens.
i read `rhx route.drive`, see one lane marked constraint, and go unlock the keyrack. the other
three reviewers' findings are in my hands the whole time.

the sharp edge fails safe: **the failure is contained to its own lane, it is loud, and it names
the fix.**

## 🔴 .the trap this demo exists to catch

`Promise.all` **rejects on the first rejection** and leaves its co-members unawaited. that is the
obvious port and it is the wrong one here, because a reviewer failure is a normal outcome in this
domain, not an exception — `malfunction` and `constraint` are *verdicts*, and the extant code
already treats them as such — see the `reviewCompleted` branch in `runStoneGuardReviews.ts`, which
converts an outcome into a verdict rather than a throw.

⇒ the group must settle **every** member regardless of outcome — `Promise.allSettled` semantics,
or a per-task catch that converts a throw into the same verdict the serial path would have
produced. a group that aborts on first failure would silently shrink the review surface, which
is `rule.forbid.failhide` at the level grain.

## .the bdd sketch

```gherkin
given [case1] a level with four reviewers, cap 3, all fresh
  and reviewer r2 exits 2 with 0 blockers (a genuine constraint — absent api key)
  and reviewers r1, r3, r4 complete normally

when [t0] the driver runs `--as arrived`

then four outcomes are reported, not one
  and r1, r3, r4 carry their real blocker and nitpick counts
  and r2 carries a constraint whose message names the absent credential
  and r2's meter is NOT incremented — a genuine constraint consumes no round
  and r1, r3, r4's meters ARE incremented
  and the level is terminal-for-unlock, so level 3 opens

given [case2] reviewer r2 instead throws mid-flight (the process is killed)
when  [t1] the group settles
then  r1, r3, r4 still return their verdicts
  and r2 is reported as a malfunction, never as an absence
```

🔴 **`and r2's meter is NOT incremented`** — the extant rule (`:598-605`) is that a genuine
constraint consumes no round. under concurrency each task writes only its own slug's meter row, so
this stays true per-task; the demo asserts it because a shared-write port could easily lose it.

## .the clamp this owes (acceptance 7)

```gherkin
given [case1] the four-reviewer level with r2 set to fail
when  [t0] the level executes concurrently
then  the artifact array holds 4 entries
```

⇒ **prove it bites**: swap the collector to a bare `Promise.all` and re-run — r2's rejection
rejects the whole call, so the assertion never reaches its array and the test goes red. restore the
settle-all collector — 4 entries, green.

### 🔴 the bite has a precondition, and it decides whether this clamp has teeth at all

⚠️ **caught in peer review i016/r2, and the reviewer was right on both counts.**

**first, the stated red condition was impossible.** this section read *"the array holds 1"*.
`Promise.all` is **all-or-none** — it resolves with every result or rejects on the first rejection,
and it **never yields a partial array**. so the red arm as written could not occur, which is the tell
that the bite had been asserted rather than walked.

🔴 **second, and worse: whether the swap bites depends on WHERE the throw becomes a verdict** — and
the two homes give opposite answers:

| where the conversion lives | what `Promise.all` sees | the clamp |
|---|---|---|
| **inside each task** — the task catches and returns a `malfunction` verdict | four **fulfilled** promises | 🔴 **green. no teeth** — the naive port passes |
| **in the collector** — a task may reject; the collector absorbs it | one rejection among four | ✅ **red** — the whole call rejects |

⇒ **so this is a clamp only under the second design**, and the vision must commit to it rather than
leave it to the implementer:

> **the per-task boundary propagates; the COLLECTOR converts.** a failed task lets its rejection
> escape, and the settle-all collector maps it to the same verdict the serial path would have
> produced.

⚠️ **note this pulls against `[case2]`'s `and r2 is reported as a malfunction, never as an
absence`**, which reads as though the task owns the conversion. it does not — `[case2]` asserts the
**observable**, and the collector is what produces it. **the observable is identical either way,
which is exactly why the ambiguity survived eleven rounds: two designs with the same output, and
only one of them clampable.**

⇒ and the lesson generalizes past this case: **a clamp that cannot part the correct implementation
from the naive one is decoration.** the bite procedure exists to test precisely that — and it only
does so when actually walked. this one was written, cited, and never walked.
