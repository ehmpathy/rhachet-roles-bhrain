## .the gap, precisely

`rule.always.spend-own-levers-before-escalation` poses one test:

> *"is there a command i could run right now that would move this stone?"*

it does not say **how to answer it**, and the cheap way to answer is to recall the last error the
tool gave you. that is what I did:

```
✋ focus 'pull' requires a brain with tool use (BrainRepl).
   brain 'fireworks/deepseek/v4-flash' is a BrainAtom without tool use.
```

I read *"pull needs `ANTHROPIC_API_KEY`"*, filed it under the credential gate, and moved on. **the
message names one requirement — a brain CLASS — and says naught about a key.** `rhx review --help`
lists **19 brains, four of which are repl** (`↻`), and one of those drives the local claude-code
session with no key and no vendor account at all.

⇒ 🔴 **the failure is a CATEGORY error with a very specific shape: a capability refusal read as an
entitlement refusal.** the two look alike — both are a `✋` from the same surface, both name what you
lack — and only one of them is a wall. the tell is what the message actually predicates:

| the refusal predicates | it is | who can clear it |
|---|---|---|
| a **capability** — a class, a mode, a flag, a shape | a **configuration** | 🔴 **you, right now** |
| an **entitlement** — a key, a quota, an account, a grant | a **gate** | a human |

and a re-read cannot catch it. **I re-read that message twice** across two rounds and passed it
both times, because a re-read confirms what you already concluded. what caught it was a **different
lever** — `--help` on the tool itself.

⚠️ **and the cost compounds through the artifacts.** a misread lever does not merely delay a fix; it
gets written down as a gate, cited by later files, and every subsequent round inherits it as a
premise. mine reached five `.taken` files and two escalation documents before it was caught.

## .the shape of the fix

a zoom-in on `rule.always.spend-own-levers-before-escalation` — the parent asks the question; this
would say how to answer it honestly.

1. **before you record a lever as spent-or-unavailable, read the tool's own surface** — `--help`,
   the flag list, the enum of accepted values. never the last error alone.
2. **classify the refusal.** capability vs entitlement, per the table above. a capability refusal is
   yours; an entitlement refusal is a gate.
3. **an error that names ONE requirement does not imply a second.** if you are about to write
   *"and therefore it needs X"*, X must appear in the message or in the tool's docs — otherwise the
   gate is your inference rather than the tool's claim.
4. **the enforcement**: an escalation whose blocked lever was never checked against the tool's own
   `--help` = blocker. a gate claimed from an inference rather than from a message or a doc =
   blocker.

⇒ it likely also wants a line in `rule.always.diagnose-reviewer-malfunctions`, whose overflowed-lane
remedy is exactly the command this misread closed off.

## .why it is not done in this round

**safe? yes. clean? no.**

- the parent rule lives in `src/domain.roles/driver/briefs/`, and a rule edit here means the `.md`,
  its `.md.min`, and the booted context every reviewer reads — **the diff every lane on this stone
  already grades**. this branch holds zero commits, so `since-main` is already 174 files wide and
  every artifact written to answer a reviewer enlarges the corpus the next round must read.
- it is **out of this wish's scope**. the wish gates the contemplation entrance; the driver briefs
  this branch touches were touched because they teach that loop. a rule about how to read a tool
  refusal is a different subject, and `rule.forbid.scope-leaks` binds.
- 🔴 **and it is a rule about escalation, caught mid-escalation, by the driver whose escalation it
  would grade.** it should be written by someone who is not currently the worked example.
