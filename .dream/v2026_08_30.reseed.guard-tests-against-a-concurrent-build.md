# dream: a test run and a build must not overlap — the failures they produce are lies

**kind**: reseed · **owner**: `ehmpathy/rhachet-roles-ehmpathy` (the `git.repo.test` skill) ·
**caught** 2026-08-30 · **status**: transmitted → `ehmpathy/rhachet-roles-ehmpathy` **#602**, QUEUED

## .the gap

`npm run build` begins with `build:clean:tsc` → `rm -rf dist/`. every `.agent/repo=<org>/role=*/`
entry that a role link created is a **symlink into `dist/`**, so for the whole build window those
links point at a path that does not exist.

a `git.repo.test` run that overlaps that window fails, and **it fails in a shape that reads
exactly like a real regression**:

| symptom | what it looks like | what it was |
|---|---|---|
| `BadRequestError: extended keyrack not found` at `.agent/repo=*/role=*/keyrack.yml` | a missed file in a role declaration | a broken symlink |
| a snapshot diff where **received is empty** | a skill that emits no output | the skill's own path was broken |
| `process.exit called with "2"` from `jest.acceptance.env.ts` | a credential defect | the same broken keyrack |

⇒ measured this round: a full acceptance run failed at 1360s with 4 snapshot failures and a
keyrack error. the same suite, re-run scoped after the build settled, passed **78/78 in 71s**.

## .why it is worth a guard rather than a habit

the diagnosis is expensive and the failure is **plausible**. a driver who reads
*"extended keyrack not found"* reaches for the keyrack, not for the clock — and the repo's own
briefs point them that way (`rule.always.diagnose-reviewer-malfunctions` grades an absent
credential a driver-fixable cause).

so the cost is not the lost run. it is the **wrong repair**, attempted against a real error
message that had no defect behind it.

## .the shape of the fix

a lock, held by both skills, in the repo's `.meter/` or `.log/` dir:

- `npm run build` takes an exclusive lock for its duration
- `git.repo.test` takes a shared lock, and refuses with a **constraint** (exit 2) plus a named fix
  when the build holds it: *"a build is in flight — the `.agent/` symlinks are broken. wait, then
  re-run."*

🟡 **it must be a `ConstraintError`, never a malfunction** — a build in flight is a legitimate
hold with a named remedy, which is the exact distinction `rule.require.exit-code-semantics` draws.

## .why it is not fixed here

`git.repo.test` is published by `rhachet-roles-ehmpathy`. per the wisher's default, settled
2026-08-13 — *a tree adopts only the briefs scoped to its own repo; a brief that belongs to a peer
repo gets re-seeded to that repo, never adopted here.* the same holds for a skill.

## .the fulcrum

> **a test run that overlaps a build reports failures no defect caused, and the report is
> indistinguishable from a real one.**
> rework: **clean** — the guard is additive, and no artifact hardens against its absence.
