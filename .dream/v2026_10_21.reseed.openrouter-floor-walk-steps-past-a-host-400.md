# 🌙 dream: the openrouter floor walk steps past a host's own 400

kind: reseed · owner: ehmpathy/rhachet-brains-openrouter (rhachet-ktlo's lane) · caught 2026-10-21

## .the cue that fired

every peer lane of `1.vision` on `v2026_10_21.fix-clamp-role-boot-budgets` malfunctioned, twice in
a row, with `BadRequestError: 400 Provider returned error`. the raw body was
`Request could not be processed` and the host was `OpenInference`, on `openrouter/deepseek/flash`.

## .the gap, precisely

- `dist/domain.operations/supply/getOneFloorCompletion.js` `asStepOutcome` steps past only a `429`
  and a `404`. any other status rethrows, so the walk never reaches the next qualified host
- the cheapest `deepseek/flash` host answers small prompts. `getOneReviewCountsViaBrain.caseBrain.deepseek-flash`
  (78 tests) and `stepReview.caseBrain.deepseek-flash.case3` (27 tests) both pass on 2026-10-21. the same host
  refuses a ~20k-token review prompt with no odd bytes in it. a context cap below the prompt fits
- ⇒ one host's limit fails the whole ask, while pricier hosts on the same tier would serve it

## .the shape of the fix

in `asStepOutcome`, a `400` whose body carries `error.metadata.provider_name` came from the host,
not from openrouter's request check. return `'failed'` for it, the outcome a mid-reply host failure
already uses: no cache entry drops, and the walk steps on. a `400` with no provider metadata still
rethrows. a clamp: a fake endpoint queue whose first host throws such a 400 serves from the second.

a local stopgap rides in this tree: `patches/rhachet-brains-openrouter@0.1.3.patch` adds that exact
line to the dist `asStepOutcome`. the guards keep their declared brains. the patch retires when
`rhachet-brains-openrouter.beav.fix-429-hop-and-tier-fallback` releases.

## .why it is not done in this round

the fix belongs to another repo, and the openrouter 400 is rhachet-ktlo's lane.
