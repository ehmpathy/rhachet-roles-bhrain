# 🌙 dream: the triage tags cannot say that a question GATES the design

**kind** = `reseed` · **owner** = `ehmpathy/rhachet-roles-bhuild` · **caught** 2026-09-11

## .the cue that fired

a research question sat five review rounds, tagged `[research]`, graded *nice to know*. it decided
the architecture. it was answerable by one turn in a live session the whole time, and it closed one
round after a triage table gave it an owner.

⇒ measured: `.behavior/v2026_09_09.feat-prescribed-brain-per-stone/1.vision.yield.md`, open
question *"does a `/model` switch preserve the conversation?"* — raised r3, answered 2026-09-11,
and it settled **two** design calls at once (mutate-vs-spawn, and the fulcrum `F14`).

## .the gap, precisely

`1.vision.guard:122-125` — the `has-triaged-questions` self-review — declares exactly three tags:

```
- [answered] — resolved now
- [research] — to be answered in the research phase
- [wisher]   — requires wisher input
```

**every tag names WHO answers. not one names WHAT THE ANSWER DECIDES.**

so these two carried an identical tag in one table:

| the question | what its answer decides |
|---|---|
| does a `/model` switch preserve the conversation? | 🔴 **the architecture** — mutate-in-place vs spawn-per-stone |
| what is the `clone say` round-trip latency? | one timeout value |

⇒ **a reader who sorts by tag cannot tell them apart, and the queue order that results is arbitrary.**

🟡 **and a fourth tag is owed on a second axis.** the same route found a question no observation could
ever close — *"what fraction of drives run unenrolled?"*, where the population leaves no record. it
does not fit `[research]`, because `[research]` is a **promise** that an observation exists.

## .the shape of the fix

**two axes, and they are orthogonal:**

| axis | values | what it answers |
|---|---|---|
| **who** — the extant tags | `[answered]` · `[research]` · `[wisher]` · 🔴 `[unanswerable]` | who can close it |
| 🔴 **what it decides** — absent | `gates` · `tunes` · `informs` | what the answer buys |

- `gates` — the design branches on the answer. **run it before the design is drawn**
- `tunes` — a value moves; the design does not
- `informs` — the record is better and no choice changes

⇒ a `[research]·gates` item outranks every `[wisher]` item in the queue, and today no notation can
say so.

**the smallest version that would have worked:** one sentence added to the guard's rubric —
*"for each question, also state what its answer DECIDES; a question the design branches on is run
before the design is drawn."* no fourth tag, no new column, and the rank falls out of the prose.

## .why it is not done in this round

**SAFE** ✅ — it is one clause in a rubric; nothing downstream hardens against it.

**CLEAN** 🔴 — the guard file is stamped by `init.behavior.sh` in `ehmpathy/rhachet-roles-bhuild`,
so a fix here would patch one route's copy and leave the generator untouched. **every future route
would re-stamp the defect**, and the repair would then read as fixed while it was not.

⇒ a tree adopts only what is scoped to itself. this is bhuild's rubric, and it is bhuild's to mend.
