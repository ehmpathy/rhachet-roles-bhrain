## 🔴 .why the fork was withdrawn — a guide no lane could reach

a forked lane needs three things: a **slug**, a **path**, and its **guide**. the roster served the
first two and could not serve the third:

| where the guide could come from | why the lane could not get it |
|---|---|
| the ask emit | renders for the **next-unpromised** slug only |
| a challenge verdict | renders for the slug in hand, and **only on a refusal** |
| the `.guard` file on disk | the route is **sealed** — `route.mutate.guard` blocks the read, deliberately, so a driver cannot game the rubric |
| a read-only retrieval command | 🔴 **there is none** |

⇒ a forked lane's only move was to **promise blind to provoke `challenge:absent` and read its guide
off the refusal** — which `rule.always.bear-every-self-review` forbids outright, and which burns the
attempt the haste cue reads. **an invitation no mechanism can serve is worse than no invitation.**

🟡 and the withdrawal needed **no new refusal branch**. the roster was the only surface that could
name the other slugs, so its deletion makes the ladder serial by construction — plus a tooth it was
never designed for: an out-of-order promise now finds no ask and meets `challenge:unasked`.

# .the argument as it stood while the fork was live

⬇️ **all of it below is the case for a capability that is now withdrawn.** it is kept for one
reader: whoever proposes the fork again. read `.the sketch caveat` at the foot first — `F07` and
`F08`, the two fulcrums this demo leaned on, are both 🌙 moot.

## .the narrative

a stone owes eight self reviews. a driver forks eight subagents, one per review. each reads the
blueprint against its own rubric. three of them find defects and repair the blueprint. all eight
write their articulations, and all eight promise.

**every one clears.** eight lanes, one challenge round trip each, all of them concurrent — so the
cost is one round trip of wall clock, not eight.

### 🔴 .the before — a fork is not merely unsupported, it is punished

two mechanisms, and both fire hardest on the forked driver:

| | today |
|---|---|
| **the serial ladder** | the guard hands out **one** unpromised slug per run (`findNextUnpromisedReview` takes `.find()`), and mints a trigger for that one slug only. slug 8's clock does not start until slug 7 is promised ⇒ **8 × 30s, serially** |
| **the hash key** | subagent 3 repairs the blueprint. the hash moves. subagents 1, 2, 4–8 each get a fresh trigger report with the clock at zero — **refused for work they did not do** |

🔴 **and the second mechanism scales with the fork's width.** the more parallel the driver goes, the
more repairs land per unit time, the more often every other lane is reset. **a fork is the maximal
generator of the exact input that breaks it.**

### .the "aha"

> **the two asks were one change.**

`S06` reads as a settlement plus a feature request. it is not: the trigger report's hash key is
what makes parallel repair unsafe, and the serial hand-out is what makes parallel review
unreachable. **drop the hash and trigger all M at once, and both fall out together.**

⇒ and the subsystem already agrees. `getStonePromises.ts:12` — *"all promises are hashless (firm
checkpoints that don't invalidate)"* — and `setStoneAsPassed.ts:336` on the peer ladder — *"it
needs NO hash … readiness does not depend on the current generation at all."* **two of three
artifacts here are already hashless. the trigger report is the straggler.**

## 🔴 .`[t4]` is the PROOF BAR, and every clause above it passes under a serial run

**`S16` asked that the parallel ability be explicitly proven, and the check that ask forced found
this demo short.** the check is one question, asked of each clause:

> **is it satisfied by eight lanes run one after another?**

| the clause | a serial run | what it actually asserts |
|---|---|---|
| `[t0]` a trigger is minted for all 8 | ✅ passes | a **hand-out** property — how many slugs the guard offers |
| `[t1]` 3 repair, no report is reset | ✅ passes | repair 3 first, then run the rest — the order is free |
| `[t2]` all 8 promise **in any order**, all allowed | ✅ passes | 🔴 **order-independence, which is not concurrency** |
| `[t2']` **one** challenge round trip, never 8 | ✅ passes | a per-lane **cost** claim; each lane takes one call either way |
| `[t3]` two lanes, one slug — idempotent | ✅ passes | two sequential promises of one slug |
| 🔴 **`[t4]`** | 🔴 **cannot be expressed** | **a repair that lands INSIDE another lane's open window** |

⇒ 🔴 **so before `[t4]` this demo proved the fork HARMLESS and never proved it POSSIBLE.** every
assertion was about the fork's **outcome**; none was about the **interleave** that produces it.

### .why that gap was invisible, and why it matters downstream

the property the wish buys is not *"eight lanes finish"* — it is that **lane B's repair is invisible
to lane A's gate while A is mid-flight**. that is precisely what the hash key forbade:

| | lane A asked at T+0, B repairs at T+5, A promises at T+6 |
|---|---|
| **today** — hash-keyed | B's repair moves the hash. A's promise looks up a report that does not exist, mints a fresh one, and returns `challenge:first`. 🔴 **A is confronted for work B did** |
| **after** — `(stone, slug)` | A's lookup finds the report minted at T+0, untouched. **B is invisible to A** |

⇒ **`[t4]` is the only step in this file that goes red today**, and it is the step whose repair IS the
wish. ⚠️ `[t1]` looks like it covers this and does not: it says *no report is reset*, which a serial
run satisfies because it never holds two windows open at once.

🔴 **the downstream consequence is the reason this is a correctness concern rather than a tidy-up.**
`rule.require.experience-catalog-evolution` binds every critipath to a **real test** by verification.
with `[t0]`–`[t3]` alone, a verification stage could discharge the parallel deliverable with a
**sequential** test suite and violate no clause written down — the tests would pass, the cell would
read covered, and the one property that required the hash change would be unexercised.

### .the proof bar, stated so a later stage cannot discharge it serially

> **a test discharges `D7 = parallel` only if it holds two lanes' windows OPEN AT ONCE and lands a
> repair inside one of them.**

three operands, each checkable, and `[t4]` names all three:

1. lane A's trigger **exists and is unpromised** at the moment B repairs — the windows overlap
2. the repair **changes the subject artifact's hash** — the input that used to reset A
3. lane A's report after B's repair is **byte-identical** to the one minted at T+0 — the assertion
   that the key no longer carries the hash

🟡 **operand 3 is the sharpest and the cheapest**: it compares a file to itself across another lane's
write, so it neither measures wall clock nor races. ⇒ **the proof needs no concurrency harness** — it
needs an **interleaved sequence**, which any sequential test runner can stage deterministically.

⚠️ **and that is the one honest limit of `[t4]`.** it proves the **interleave is safe**; it does not
prove **simultaneity is safe**. the residual — a genuine race on a non-atomic read-modify-write of
`.since` — is `F08`'s, and no sequence-based test reaches it.

## 🔴 .`[t3]` contradicts the extant code, and it is the assertion `F08` leans on

eight concurrent writers share one `.route/` directory. the promise artifact is
`$stone.guard.promise.$slug.md` — **keyed per slug**, so two lanes never write one file. that is
the property that makes the fork safe, and it is worth an explicit test rather than an assumption.

⚠️ **but `[t3]`'s second clause is not a property the code has.**
`getSelfReviewChallengeDecision.ts:95` increments the count on **every** promise attempt that finds
the file, before any decision is reached:

```ts
const { attempts } = await setSelfReviewTriggeredReport(input);
if (attempts >= plowthroughThreshold) return { decision: 'allowed' };   // :98
```

⇒ so a redundant promise **does** burn an attempt — and the hatch at `:98` clears the gate outright
on the third. **under a fork that is a bypass, not a delay**: M lanes that each promise one shared
slug arrive at 3 attempts in seconds, and the gate opens with no path re-verdicted and no second
look.

🔴 **`F08` cites `[t3]` as its own safety net** — *"it is what makes a lost increment merely late
rather than silently wrong"* — so the fulcrum's 75% call rests on an assertion the code refutes.
`[t3]` is therefore not a test to add later; it is a **behavior change** the parallel deliverable
requires, and `F08`'s verdict should be re-read with that cost in view.

### 🔴 `S13` SPLIT this demo's headline step, and the split is the fork's real payoff

`[t2]` asserted *"all 8 decisions are `challenge:first`"* and now asserts **`allowed`** — because a
driver who forks eight lanes and reviews for 25 minutes is past 30s of the ask on every lane.

| | the fork's challenge cost |
|---|---|
| **B** — the clock gates | 🔴 `8 × 30s`, serially — the defect this deliverable exists to remove |
| `S11` — no clock | **one** round trip for all eight, concurrently |
| 🔴 **`S13`** | ✅ **naught.** no lane meets the prompt at all |

⇒ 🔴 **so the parallel deliverable and the clock's re-purpose compound rather than merely coexist.**
a fork is the case where a driver is **most** likely to be past 30s — eight lanes take longer than
one — so `S13`'s target condition is satisfied by the very shape `S06` asked for.

🟡 **`[t2']` is kept as the sub-30s variant**, because a driver who forks and promises fast is real
(a lane that finds naught to say), and it is where the *"one round trip, never eight"* claim still
has to hold.

### 🔴 `S11` raised the stakes on `[t3]`, and `S13` raised them again

under the clock, the hatch was a **third** door beside a clock and a path check. the attempt count is
now **half the gate condition**, so a leaked increment is a leaked review — and it takes **one** leak
rather than three:

| | a redundant promise that burns an attempt | leaks it takes |
|---|---|---|
| **B** | the driver drifts toward a hatch that was itself a liveness relief | 3 |
| 🔴 **`S11`** | 🔴 **the count is the whole gate.** M lanes on one slug clear it with no read | 2 |
| 🔴 **`S13`** | 🔴 **the count is half the gate condition**, and the half that opens on `attempts != 0`. one stray increment retires the challenge for that slug | **1** |

⇒ **so `[t3]` and `case=5`'s `and no trigger report is mutated` are one clause seen from two
cells**, and it is the round's single heaviest assertion: **only a promise the guard adjudicated may
increment the count.** neither cell alone states it in full, which is why it is stated here, in
`case=5`, and in `1.vision.yield.md`'s invariant list — and why `F08` should be re-weighed against a
cost that has grown twice.

🟡 **one honest mitigation, and it is `S13`'s.** a stray increment now retires only the **prompt**,
never a gate — the path check and the freshness check are untouched by the attempt count. ⇒ so the
harm fell from *"a review clears unread"* to *"a driver misses one paragraph they should have read"*,
which is real and is not the same magnitude. **`F08`'s 75% should be re-weighed in both directions.**

⇒ the residual concurrency risk `F08` names — a non-atomic read-modify-write on `.since` — stands
beside this rather than instead of it.
