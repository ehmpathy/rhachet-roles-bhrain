# 🌙 dream: openrouter's per-dimension cost is a rate card beside a billed total

- kind = reseed
- owner = `ehmpathy/rhachet-brains-openrouter`
- caught 2026-10-05, on `rhachet-roles-bhrain` @ `beav/feat-review-cost-meter` (its fulcrum `F101`)

## .the cue that fired

a review meter read `cacheGet: 1280` beside `cacheSaved: $0` on an openrouter run, and the run's
four cost parts summed to ~6× its billed total.

## .the gap, precisely

`asCashWithSupplyTotal` (0.1.3) keeps the spec-rate estimate for `input`, `cacheWrite`,
`cacheRead`, and `output`, and replaces only `total` with the charge openrouter sent. on
`deepseek/flash` the spec card prices a cache read at the full input rate:

| dimension | written | rate |
|---|---|---|
| input | `$0.000623100` / 2,077 tok | $0.30/M |
| cacheRead | `$0.000384000` / 1,280 tok | $0.30/M — no discount |
| output | `$0.000452000` / 226 tok | — |
| total | `$0.000236230` | billed |

so a consumer that derives any figure from the parts (a cache-saved amount, a per-dimension share)
reads a projection as a measurement. `rhachet-roles-bhrain` now refuses to price an unreconciled
breakdown, so its warmer sees these runs as unpriced rather than as `$0` saved.

## .the shape of the fix

- read the per-dimension charge openrouter's usage payload carries (where the host sends it) and
  write measured parts, OR
- scale the spec parts so they sum to the billed total, and mark them as scaled, OR
- at least price `cacheRead` at the model's declared cache-read rate, and state in the cash report
  that the parts are an estimate (a `parts: 'estimate' | 'measured'` field would let a consumer
  branch on a declared fact rather than on an arithmetic check)

## .why it is not done in this round

it lives in another repo. this repo's side — refuse to price an unreconciled breakdown — is done
and clamped (`getAllReviewRunMeters.integration.test.ts` `[case9]`).
