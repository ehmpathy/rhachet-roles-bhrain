# 3.3.1.blueprint.product — role=achiever, no excuses

## .summary

5.1 builds the two clamps the wish requires, and only what they lean on:

1. **clamp 1 — an untracked order reds the stop.** wire `onStop` on the achiever role to
   `goal.triage.infer --when hook.onStop` (the extant halt on uncovered asks), so an ask with no
   goal makes the Stop hook exit 2
2. **clamp 2 — a blocker with no cure reds the set and the stop.** `blocked` owes a cure:
   `--cure.via dispatch` (+ `--cure.ref`, `--cure.await <minutes>`) or `--cure.via charter`
   (+ `--cure.act`, `--cure.who`). `goal.memory.set` refuses a cureless `blocked` (exit 2), and
   `goal.triage.next --when hook.onStop` halts on a blocked goal with no cure, or a dispatch past
   its hour
3. **fail closed.** a hook malfunction exits 2 with `💥 MalfunctionError`, never exit 1 (a Stop
   gate that exits 1 fails open)
4. **one achiever.** `inits/init.claude.sh` is retired; every hook rides `Role.hooks`
5. **the briefs.** the three delegate briefs carry across at say; lucky-charms and scouts-honor move
   to ref with `.min` peers, so the boot stays under its 7,500 cap

every new field is optional on read: an extant goal parses and renders as it did (F2, ruled).

facts the execution adheres to (from the source):
- the onStop hook logic already exists in both commands (`goal.ts:1398-1437`, `:1642-1728`); 5.1
  wires it, it does not rewrite it. onStop timeout `PT60S`, as rhachet's own onStop does
- `--status.choice` is cast to `GoalStatusChoice` with no check (`parseArgsForSet`, `goal.ts:618-619`);
  5.1 validates it against `GOAL_STATUS_CHOICES`, so a typo cannot slip past the cure check
- `blocked` resets the escalation streak (`delGoalBlockerState`, `goal.ts:913-915`, `:975-977`);
  that reset stays, since a blocked goal now always carries a cure
- the boot payload changes, so `boot.yml` `budget.tokens` and the `roleBootClamps` seat snapshot
  move together (budget = least multiple of 250 above the payload, `assertBudgetFitsSeatPayload`)
- acceptance tests run the built `dist` (`blackbox/.test/invokeGoalSkill.ts:102`): build before run

the rest of the vision — the shell done check, `declined` / `deferred`, the no-work coverage close,
the main-scope hold, the inbound radio read, and the goal.tree parity set — lands in later stones,
named in `.later stones`.
