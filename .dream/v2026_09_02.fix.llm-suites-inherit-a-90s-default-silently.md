# 🌙 dream: name the LLM test budget once, so a brain-backed suite cannot inherit the 90s default

- **kind** = fix
- **owner** = this repo
- **caught** = 2026-09-02

## .the cue that fired

three acceptance/integration suites failed cicd on the clock in one round, each for the identical
reason, and each was repaired by hand with a per-file `jest.setTimeout`:

| suite | what it inherited | what it needed |
|---|---|---|
| `src/domain.operations/review/stepReview.integration.test.ts` | 90s | 180s |
| `blackbox/review.exhaustive-dirty.acceptance.test.ts` | 90s | 240s |
| `blackbox/review.gitignore-subjects.acceptance.test.ts` | 90s | 300s |

the third is what turned an instance into a class. two had already been repaired and pushed when
the third surfaced from a shard that had passed the round before — so the defect was never a
property of any one file, and a per-file repair cannot find the next one.

## .the gap, precisely

`jest.integration.env.ts:8` and `jest.acceptance.env.ts:8` each set `jest.setTimeout(90000)`. that
is the right default for a deterministic cli case and it is **below the cost of a single real brain
call**, which measures 10–30s at best and carries fixture setup (`genTempDirForRhachet` plus one
`rhachet roles link` per role) INSIDE the timed block.

so a suite that drives a real brain gets a budget under its own cost, and **the surface gives no
signal at all**:

- no type error, no lint rule, no naming convention marks a suite as brain-backed
- the failure appears only in cicd, only sometimes, and only on whichever shard drew that file
- it presents as `Exceeded timeout of 90000 ms` — which reads as a hang, not as a mis-sized budget

🟡 **and the two present identically.** this same round had two genuine hangs — 420s and 180s, where
a retry of the same call passed in ~27s and ~13s. a reader who meets `Exceeded timeout` cannot tell
a wedged upstream from a budget that was never large enough, and the two want opposite repairs.

## ✅ .what was already done — the acceptance default was raised in-round

instances 4 and 5 arrived **one push after** the first three were repaired, which is the argument
this dream was written to make, proven within the hour. so the per-file approach was abandoned and
`jest.acceptance.env.ts` now defaults to **240s** rather than 90s.

🟡 **an earlier draft of this dream argued AGAINST that, and the argument was wrong.** it read the
90s as a *floor that keeps the deterministic majority fast-failing*. it is not a floor — **a budget
is a ceiling, never a duration.** a deterministic case that exits in 2s is untouched by a raised
ceiling. the only real cost is that a genuinely wedged test reports later, which this repo already
accepts (the guard-peer suite waits 420s).

⇒ the discriminator worth keeping: **a ceiling costs the passing case naught. it costs only the
hung case, and only in latency-to-report.** an argument against raising one has to be about that
latency, not about speed of the suite.

## .the shape of what REMAINS

**1. name the timeout once.** the extant overrides are a scatter of magic numbers — `180000`,
`240000`, `300000`, `420000`, and one `180000 * REPEATABLY_CONFIG.attempts` — with no declared
meaning, and two are now redundant with the raised default. a shared const beside
`@src/.test/infra/repeatably` would carry the sense: named tiers for *one call*, *one call plus
fixture setup*, and *a route guard that drives several*.

🔴 **it must NOT be named `*_BUDGET`.** `budget` is already this repo's word for the count of review
ROUNDS a peer reviewer may spend, published as `rhx route.guard.budget --add N` and declared as a
`*.guard` key — a countable store whose exhaustion is a **verdict the unlock ladder reads**. a
per-test time allowance is a duration the clock spends by itself, whose exhaustion is a **defect
report**. one word for both is the absent distinction `rule.forbid.domain-term-ambiguity` forbids,
and it misroutes in the costly direction: it invites *"add more"* against a call that is **hung**,
where more time changes nothing — exactly the third row this round measured.

⇒ the word is **`timeout`**, which this repo already declares — a `*.guard` key typed `IsoDuration`,
with `DEFAULT_REVIEW_TIMEOUT = 'PT21M'`. so the const takes `*_TIMEOUT` and coins naught. settled
2026-09-02 in `term=route.guard.budget._.choice.reason.md`.

**2. make the inheritance loud rather than silent.** the strongest version does not rely on an
author to remember: a suite that constructs a real brain could assert its own budget at setup and
fail fast with a named fix when the budget sits under a brain's floor. that converts an
intermittent cicd-only clock failure into a deterministic local one, at the moment the file is
written.

**3. the integration side is untouched.** `jest.integration.env.ts` still defaults to 90s. it has
not produced the same flapping — its brain-backed files each carry a per-file override already —
so it was left alone rather than changed on a hunch. if it starts to flap, the same one-line repair
applies.

## .why the remainder is not done in this round

**safe, and NOT clean.** a shared const ripples across every extant override — six files, and a
rename of values other suites already depend on — and the setup-time guard needs a way to know a
suite is brain-backed, which no marker supplies today. that is a wider diff than the test repair it
would ride with, and it would land unreviewed inside a test-fix commit.

the raised default plus the per-file repairs stand on their own and are verified. this dream carries
the residual.
