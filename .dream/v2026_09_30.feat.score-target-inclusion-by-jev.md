# 🌙 dream: decide which target files to include by a `jev` score

- kind: feat
- owner: rhachet-roles-bhrain
- caught: 2026-09-30

## 🔴 .the unsettled term — read this first

the wisher named the mechanism **`jev`**. that word is preserved verbatim and **its sense is
not settled** — a glob of this repo returns no `jev`, and no declared term, glyph, or operation
matches it.

⇒ **do not implement against a guess.** two candidate senses were considered and neither is
confirmed:

| candidate sense | what it would mean |
|---|---|
| **EV** — expected value | score each candidate file by expected review value per char, include top-N until a budget is spent |
| a **named tool or package** in the wisher's ecosystem | a scorer that already exists and should be adopted rather than re-derived |

**the first move on this dream is to ask which.** a term this load-bearing is owed a
`domain.terms/` cluster before any code (`rule.require.domain-discovery-for-term-proposals`),
and the gap belongs in `domain.terms/inventory.of=gaps._.md` meanwhile.

## .the cue that fired

`targetFiles` is **87.6%** of a review prompt and is selected today by **guard globs** — a
declared pattern per lane, with no per-file judgment. so a file that matches the glob ships in
full, whether or not it bears on the rubric.

the measured consequence: 113 targets, 881.3k chars, on a lane whose report cited a small
fraction of them.

## .the gap, precisely

glob membership is **binary and content-blind**. it answers *"is this file in scope?"* and
never *"is this file worth its chars to THIS rubric, this round?"*

⇒ so candidates are unranked, hence there is no way to spend a char budget well. a 40k file the
rubric cannot possibly fire on costs the same as a 40k file at the heart of the change.

## .the shape of the fix

score every glob-matched candidate, then include by score until a declared char budget is
spent:

1. **score** each candidate on the `jev` metric, once its sense is settled
2. **rank** candidates by score per char — the same shape as the volatility/size rank that
   orders sections (`rule.require.order-prompt-sections-by-volatility-then-size`)
3. **include** down the rank until the lane's char budget is spent; render the remainder as
   `targetPaths` so the reviewer at least knows what it did not receive
4. **meter it** — record the score, the cutoff, and what was excluded, so a false exclusion is
   auditable rather than invisible

🔴 **the failure mode to guard is a silent false exclusion.** a file dropped by a bad score
produces a review that looks complete and is not — which is strictly worse than a large prompt.
so the excluded set is always named in the prompt and in the meter, never merely omitted.

## .why it is not done in this round

the term is unsettled, so the mechanism cannot be specified. and it is the compose-time peer of
a read-time alternative that may subsume it — a reviewer that expands its own files needs no
score at all, because it decides after it has seen the diffs.

⇒ **these two dreams are alternatives as much as peers.** whichever ships first should be
measured before the other is built.
