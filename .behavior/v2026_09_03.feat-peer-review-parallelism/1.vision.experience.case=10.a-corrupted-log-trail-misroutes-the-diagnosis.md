# case=10 — a corrupted log trail misroutes the diagnosis

**cell** — `driver × multi-unbounded × member-fails × sharp` — 🔴 **no NEW cell; c5 already owns it**
**feel · care** — sharp · **critipath**

⚠️ these `[tn]` sketches are illustrative, not proof. no code exists yet.

🔴 **added after peer review i002/r2**, which found the log-directory collision argued in the yield
and verdicted nowhere: *"it lives entirely outside the walked matrix … either promote it to a case
or declare it out of the experience space."* the yield's own words decide the branch — *"close to
certain — routine, not a rare edge"*, and the harm lands on the **driver**, who is an actor on axis
A. an internal-only path would have been declared a gap; this one is not internal.

## 🔴 .this is the second hazard the feature CREATES rather than exposes

| hazard | today | after fan-out |
|---|---|---|
| F7 — the wall-clock timeout | calibrated while a lane runs alone | contention inflates the measured quantity |
| 🔴 **this one** | two reviews **cannot** share a millisecond — the caller is serial | N lanes spawn in a tight loop |

⇒ every other risk in this vision predates the change. these two are manufactured by it, and this
one is the only genuinely unsafe **write**.

## .the mechanism, verified

`stepReview.ts:126-128` keys the review log directory on wall-clock time alone:

```ts
const genLogTimestamp = (): string => {
  return new Date().toISOString().replace(/[:.]/g, '-');
};
```

— millisecond resolution, no slug, no index, no pid. its `.why` claims uniqueness, and uniqueness
held only because the caller was serial.

```ts
const logDir = path.join(cwd, '.log', 'bhrain', 'review', genLogTimestamp());   // :294
await fs.mkdir(logDir, { recursive: true });                                    // :295
```

⚠️ **`recursive: true` is silent on an extant directory.** so two lanes that share a millisecond
share a directory, and each overwrites the other's `input.scope.json`, `metrics.*.json`, and
input/output artifacts. no error, no warn, no signal of any kind.

⇒ a sharp critipath owes a demonstration that the edge **fails safe**. this case satisfies that in
its `[tn]` and its clamp, and its narrative is the opposite — a walk through the unsafe state, to
establish that the hazard is real and to show what the driver actually experiences.

⚠️ **the narrative is deliberately the pre-fix world, because this hazard has no extant sharp edge to
demonstrate.** the other cases narrate a behavior that already fails safe or soon will; here the
whole point is that today the failure is **silent**, and a narrative of the safe state would show a
driver who opens the right file and notices no defect — which teaches neither the hazard nor the fix.

🔴 **the fail-safe this case commits to** is stated once, so it is legible without a read of the
whole file: **the log directory is keyed on the reviewer index, so every artifact is attributable,
and the clamp asserts N distinct directories for N lanes.** that is the safe state; every section
below the narrative asserts it.

## .the narrative — the driver's pov (🔴 the PRE-FIX world)

l1 has eight reviewers (this repo's own `5.3.verification` guard — counted, not supposed). i run
`--as arrived`. eight lanes spawn in a tight loop, so several land in the same millisecond.

one of them malfunctions. the guard hands me the hint:

```
💥 malfunction: alpha-checker
   └─ inspect .log/bhrain/review/2026-09-03T18-05-18-645Z/input.scope.debug.json
      to see what was matched
```

i open it. **it is beta-checker's scope.** it is well-formed, plausible, and about a different
reviewer than the one that failed.

🔴 **i do not find an absent file. i find a wrong one.** so i do not suspect the log; i suspect my
guard. i spend the next twenty minutes on alpha-checker's globs, which were never the problem.

## 🔴 .why this is worse than an absent artifact

| if the artifact were… | what the driver does |
|---|---|
| **absent** | notices at once, suspects the tools, asks |
| 🔴 **another reviewer's, well-formed** | trusts it, and the trust is what costs the twenty minutes |

⚠️ **and it lands only under failure**, which inverts the usual detection order: nobody opens these
artifacts on a clean run, so the corruption is invisible right up to the moment it is expensive.

## .the scope, stated honestly

🔴 **this corrupts the diagnostic trail, never a verdict.** the log directory is written for human
inspection; it does not feed `computeReviewPeerVerdict`, the meter, or the gate. so it is **not**
`rule.forbid.failhide` — no review is skipped, no verdict is falsified.

⇒ it is a **critipath** on `freq × cost` rather than on correctness: near-certain at 8-wide l1, and
the cost is a misrouted diagnosis at the moment the driver is already blocked.

⚠️ **and it does not repair itself on a retry.** a re-run produces a fresh collision at a fresh
timestamp, so *"try again"* yields a differently-wrong trail rather than a right one.

## .the fix — key on the reviewer index

the reviewer's `index` is already a durable identity key: assigned pre-sort from the declared array
position (`runStoneGuardReviews.ts:347`), already in the review artifact's filename, already the
cached-approved cache key. it is unique per pass **by construction**.

⇒ key the log dir on `index` as well as the clock. additive, and every directory stays attributable
to the reviewer that wrote it.

⚠️ **not more clock precision.** a finer timestamp shrinks the window and does not close it, which
converts a **certain** defect into an **intermittent** one — strictly worse to diagnose, and it
would present as flake.

## 🔴 .the axis this did NOT earn

⚠️ noted because this vision just lost an axis value to a peer (case 7 / `unrecognized`), and the
overcorrection would be to invent one here.

the driver who reads `.log/` post-hoc invites the name **fourth actor** — a diagnostician, distinct
from the `driver` who waits and the `onlooker` who watches. **it is not one.** the hint at
`stepReview.ts:475` is printed *to the driver*, and the driver is who it misleads. same actor, later
moment.

⇒ a moment is not an axis unless two actors want different things at the same instant — which is
exactly the test that earned `onlooker` its split, and this fails it.

## .the bdd sketch

```gherkin
given [case1] a level of N reviewers, unbounded, spawned concurrently
when  [t0] the level executes
then  N distinct log directories exist
  and each is attributable to exactly one reviewer
  and no reviewer's scope artifact appears in another reviewer's directory

given [case2] two reviewers whose spawns land in the same millisecond
when  [t1] both write their scope artifacts
then  both artifacts survive
  and neither overwrote the other

given [case3] a reviewer malfunctions among N concurrent lanes
when  [t2] the driver opens the path named in the failure hint
then  the artifacts there belong to the reviewer that failed
```

## .the clamp this owes (acceptance 6)

```gherkin
given [case1] a level of N reviewers run concurrently
when  [t0] the level settles
then  the count of distinct log directories equals N
```

⇒ **prove it bites**: under the current wall-clock key it goes red the moment two lanes share a
millisecond — which at 8-wide l1 is the common case, not the rare one.

⚠️ **assert the COUNT of directories, never the content of one.** a clamp that opens a single
directory and checks it is well-formed passes under the defect, because the writer that survives
leaves perfectly well-formed artifacts — they are merely the wrong reviewer's. **the collision is
only visible in the aggregate**, which is precisely why it went unnoticed until a census was taken.
