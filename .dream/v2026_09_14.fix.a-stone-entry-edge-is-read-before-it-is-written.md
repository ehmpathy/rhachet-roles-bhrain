## .the gap, precisely

`applyStoneBrainOnEntry` reads `DriveBlockerState`, computes `entered = stateBefore.stone !==
stone.name`, and writes the mark later via `setDriveEntryStone`. the read sits outside the write, so
two concurrent hooks can both compute `entered === true` for one stone.

| consequence | state |
|---|---|
| a duplicate `/model` dispatch | ✅ closed — `genBrainDispatchClaim` grants one winner per (route, stone) per window |
| a lost count or entry update | ✅ closed — `withDriveStateLock` serializes every `mutateDriveBlockerState` write |
| a non-idempotent act placed behind `entered` | 🔴 open — the claim bounds it to one window, never to once |

## .the shape of the fix

let `mutateDriveBlockerState`'s `project` return whether the stone changed, and thread that back —
the edge is then computed inside the lock, from the write that records it. no separate pre-read.

## .why it is not done in this round

- **SAFE — no.** `mutateDriveBlockerState` is the shared writer behind the 21-block cutoff and the
  stop hook; a return-shape change reaches both
- **CLEAN — no.** a contract change to the engine's state writer rides past this wish's diff
- the one act behind the flag is convergent (`F14`), so no harm ships today

🟡 **the trigger:** any non-idempotent work placed behind `entered`. pick this up then.
