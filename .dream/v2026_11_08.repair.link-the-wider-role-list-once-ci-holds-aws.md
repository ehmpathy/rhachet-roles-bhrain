# 🌙 dream: link the wider role list, once CI holds an AWS key

- kind: repair
- owner: rhachet-roles-bhrain
- caught 2026-11-08

## .the cue that fired

pr #777 failed CI at the keyrack step: `ehmpathy.test.AWS_PROFILE` absent, strictly required.

## .the gap, precisely

`prepare:rhachet` once listed achiever, telepath, operator, observer, deployer, playwright, and enroller beyond main's nine roles. the ghlitch observer and operator roles extend keyracks that require `AWS_PROFILE` (or `AWS_ACCESS_KEY_ID`) in every env. CI holds neither, so an `rhachet init` with the wider list writes a `.agent/keyrack.yml` that halts every brain suite in CI.

## .the shape of the fix

1. a human adds an `AWS_PROFILE` or `AWS_ACCESS_KEY_ID` secret to the test env CI unlocks, or the ghlitch keyracks mark the key optional for repos that do not use the role's aws skills
2. restore the wider list in `prepare:rhachet`
3. run `rhachet init --keys --hooks`, commit the keyrack and hooks it lays out, and watch CI

## .why it is not done in this round

the toggle needs none of those roles (nano scope), and step 1 needs a secret only a human can set. see fulcrum F26.
