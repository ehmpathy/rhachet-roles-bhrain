# reseed → the org's brief-publisher repos: `kind=$archetype`, never `[$archetype]`

**status:** transmitted → `ehmpathy/rhachet-roles-ehmpathy` **#595**, QUEUED.

**owner repos:** every repo that publishes briefs with a bracketed archetype marker —
`rhachet-roles-ehmpathy` (`rule.require.failfast.[seed].md`,
`howto.write-bdd.[lesson].md`, the `[demo]` family) and any peer that copied the shape.

**why it is here and not fixed there:** the wisher's default, settled 2026-08-13 — *a brief that
belongs to a peer repo gets re-seeded to that repo, never adopted here.* the convention change is
theirs to make; this repo has fixed **its own** and forbidden the shape locally.

---

## .the ask

change the document-kind marker from the bracket form to the coordinate form:

```
👎  $topic.[$archetype].md          # kno601.inventories._.[article].md
👍  $topic.kind=$archetype.md       # kno601.inventories._.kind=article.md
```

## .why — `[` and `]` are glob metacharacters, and the failure is SILENT

`[article]` does not read as the literal text *"[article]"*. it reads as *"any one character from
the set `a,r,t,i,c,l,e`"*. so **the name a reader sees and the name a tool matches are different
strings**, and every tool that walks a path pays:

| the tool | what brackets cost it |
|---|---|
| `Glob` / `fast-glob` / `globby` | a bracketed name is **unmatched** — the pattern silently returns fewer files than the disk holds |
| `boot.yml` glob entries | a `ref:` glob cannot address a bracketed brief |
| shell (`bash`, `zsh`) | needs `\[` escapes; unescaped it expands to garbage or to itself |
| `mv` / `cp` / `rm` wrappers | `mvsafe`, `cpsafe`, `rmsafe` each carry a `--literal` flag **that exists solely for this** |
| a markdown link | `[text](url)` is link syntax, so `[article]` inside a link renders wrong |

⇒ **the failure that decides it is the silent one.** an escape error is loud and gets fixed. a
glob that returns 9 files where 10 sit on disk looks like a correct answer, and the tenth file is
simply absent for everyone downstream.

**caught in the act, in this repo:** a `Glob` for `dist/**/kno601*` returned **no match** while
`kno601.inventories._.[article].md` sat on disk. the file was correct, wired, and built — and
invisible to the tool built to find it.

## .why `kind=` specifically

it is the coordinate form these repos already dereference by everywhere — `repo=`, `role=`,
`term=`, `from=`. so `kind=article` inherits all three properties the bracket form destroyed:

- **computable** — a reader who knows the archetype knows the exact text to search for
- **globbable** — `*.kind=article.md` returns the whole archetype; `*.[article].md` returns none
- **self-declared** — `kind=` names the axis, where a bare `.article.` segment reads as prose

a **bare** suffix (`kno601.inventories.article.md`) was weighed and rejected: brief filenames are
dot-segmented prose, so a bare `article` segment is indistinguishable from a topic word.

## ⚠️ .do NOT run a bulk find-and-replace

a `sedreplace` sweep over the rule that documents this **rewrote its own counter-examples** — the
👎 lines above. a find-and-replace cannot tell a **citation** of a bad name from an **instance** of
one. three lines had to be restored by hand.

⇒ rename **files**, then fix references. leave prose alone.

## .the boundary

this governs **filenames** only. brackets in prose are untouched and correct:

- ✅ a markdown link — `[the guide](./howto.curate-an-inventory.md)`
- ✅ a table cell, a code block, a citation of another repo's bracketed path
- ✅ an emphasis marker in a header
