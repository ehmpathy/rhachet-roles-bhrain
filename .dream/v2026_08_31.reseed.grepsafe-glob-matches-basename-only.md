## .the gap, precisely

**`--glob` is matched against the file's BASENAME, never its path.** so any glob that carries a
`/` matches no file at all:

| the invocation | result | measured |
|---|---|---|
| `--glob '*.md'` | ✅ every `.md`, at any depth | 405 lines |
| `--path src --glob '*.md'` | ✅ every `.md` under `src/` | correct |
| `--glob 'rule.always.*.md'` | ✅ basename match, any depth | correct |
| `--glob 'src/**/*.md'` | 🔴 **0** | 0 |
| `--glob '**/*.md'` | 🔴 **0** | 0 |
| `--glob '.dream/*.md'` | 🔴 **0** | 0 |

the same corpus, the same pattern: `--glob '*.md'` → **405** · `--glob '**/*.md'` → **0**.

🟡 **and every part of the failure reads as success.** exit code `0`. the vibes header prints
`🐢 crickets...`. the tree renders `matches: 0`. **there is no surface on which a false zero
differs from a true one.**

⇒ the help text is the near-miss: `--glob GLOB   file filter glob (e.g., '*.ts')`. the example is a
basename, so the contract is arguably as documented — **but a documented contract that fails
silently when misread is still a failhide.** the caller is not told they wrote an impossible glob;
they are told the corpus is empty.

## 🔴 .why it is worse than an ordinary tool defect

**`grepsafe` is the tool the reuse discipline prescribes, and a false zero is the exact input that
discipline is built to refuse.**

`rule.always.reuse-pavement-before-improvise` (bhrain/learner) names it as move 1 — *look for the
paved path before you improvise* — and its whole argument is that a skipped look produces **the
braided trail**: a second artifact laid beside a serviceable one, because the author did not see
the first.

⇒ so the tool that answers *"is there pavement here?"* answers **no** when it looked at no file.
the traveler follows the rule exactly, is told the ground is bare, and improvises. **the rule's
own prescribed command manufactures the rule's own named failure mode.**

🟡 **worse: the false zero is unfalsifiable from the output.** a broken glob and a genuinely
unpaved concept are the same three lines of stdout. the discipline asks for a look; the tool
returns a look-shaped object that holds no look.

## 🔴 .the sharpest case — a check whose PASS is a zero

most searches want hits, so a zero at least prompts a squint. one class does the opposite.

`rule.always.yield-the-output-not-the-archaeology` (bhrain/driver) prescribes a **repetition

it shipped as `--glob '$route/*.yield.md'`. so:

|---|---|

**zero is the shape of a pass for that check.** a driver who ran it got the verdict the check
exists to earn, from a check that never opened the yield — and no part of the output said so.

## .the shape of the fix

**the fix is not merely to document the basename contract — it is to refuse the impossible glob.**
a caller who writes a slash has stated an intent the flag cannot serve, and that is knowable at
parse:

1. if `--glob` holds a `/`, **error** as a `ConstraintError` (exit 2) that names the fix:
   *"--glob matches the basename; scope a directory with --path"*
2. or, better, **honor it** — pass a path-glob through to ripgrep's `--glob`, which already
   supports full-path patterns, so the obvious guess is the right one

⇒ **(2) is the ergonomic answer and (1) is the safe one; either beats a silent zero.** the current
behavior is the one option that is neither.

🟡 **and check the whole `claude.tools` family for the same asymmetry.** `globsafe` does *not*
share the defect — its `--pattern` takes a full path, so `.dream/*.md` works there. **two adjacent
tools, both prefixed `--`, one accepts paths and one silently discards them.** that inconsistency
is a second defect on its own: it guarantees the mistake will be re-made by anyone who learns one
tool first.

## .the repair applied here, for reference

every prescribed invocation in this repo was corrected to `--path <dir> --glob '<basename>'`, and
the three live briefs gained a warn block that states the basename contract and the false-zero
hazard. the two dreams were corrected, and the `enroute` one now records that its claim survived a
re-run while its evidence did not.

⇒ that repair is **local mitigation, never the fix.** the next repo to reach for `grepsafe` gets
the silent zero with no brief beside it.
