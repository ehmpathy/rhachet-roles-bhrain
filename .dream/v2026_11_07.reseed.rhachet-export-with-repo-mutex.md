# 🌙 dream: rhachet owes an export of its `withRepoMutex`, so a peer writer of a settings file shares its lock by contract

- kind = reseed
- owner = ehmpathy/rhachet
- caught 2026-11-07, on `.behavior/v2026_11_07.feat-toggle-term-learner-hook`

## .the cue that fired

`withTermsHookSettingsHold.ts` restates rhachet's lock dir, key rule, and package pins, with a
`.note` that a change on rhachet's side splits the two locks. the clamp loads rhachet's lock by its
dist file path, past the `exports` map.

## .the gap, precisely

rhachet rewrites `.claude/settings.of.repo.json` whole (hook sync, enroll derive) under
`withRepoMutex`: a `withSimpleMutex` over a `simple-on-disk-cache` at
`<repo real>/.agent/.actors/.locks/`, keyed on the file path relative to the real repo root. a role
skill that also writes the file must take the same key, or a concurrent `rhx init` writes from a
stale read and drops the role's entry in silence. `withRepoMutex` is not exported, so the role
restates it:

- the dir and its `*` ignore
- the key rule (dir realpathed, path relative to the real root)
- the pins `with-simple-mutex@0.1.1` and `simple-on-disk-cache@1.8.1`, which must match on both sides

## .the shape of the fix

export `withRepoMutex` (or a narrower `withRepoSettingsHold({ repoPath, path }, logic)`) from a
public subpath, e.g. `rhachet/sdk/lock`. the learner's `withTermsHookSettingsHold` then becomes one
call to it, and the clamp imports it by name.

## .why it is not done in this round

it is another repo's contract, and the wish's nano bound keeps this round to the toggle. the
restated lock is clamped from the outside, so a split shows red.
