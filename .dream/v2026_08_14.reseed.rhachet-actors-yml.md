## .the ask

support **`.agent/actors.yml`** — a declarative manifest of the 🎭 actors a repo makes available,
and which one is the default. it is where actors get composed adhoc, by role set.

it should be able to **replace** the `rhx init --roles ...` invocation that repos currently carry
in `pnpm prepare`.

## .the extant mechanism, and what is wrong with it

today a repo declares its roles imperatively, inside an npm command:

```json
"prepare:rhachet": "npm run build && rhachet init --keys --hooks --roles mechanic behaver driver reviewer librarian ergonomist architect dispatcher learner",
"prepare": "if [ -e .git ] && [ -z $CI ]; then npm run prepare:husky && npm run prepare:rhachet; fi"
```

four costs, and each is a consequence of the flat-flag shape rather than a defect of any one repo:

| cost | why the flag list causes it |
|---|---|
| **no composition** | one flat list, so every actor gets every role. a repo cannot say *"the builder carries mechanic + behaver; the scholar carries librarian + learner"* |
| **no default** | there is no place to name which actor a bare invocation should use |
| **not readable** | the composition lives in a shell string inside a json field. any tool that wants to answer *"what actors does this repo have?"* must parse an npm command |
| **drift is invisible** | `prepare` re-runs and overwrites; no step compares declared against installed, so a hand-edit under `.agent/` is silently reverted or silently kept |

⚠️ **the fourth is the one that bites hardest**, and it is the same class of defect a declarative
manifest exists to retire everywhere else: an imperative install step has no *declared* state to
diff against.

## .why `actors.yml` is the right noun

`actor` is already rhachet's own declared term — the readme states it in its opening line:

> use 🧢 roles & add 🧠 brains to produce 🎭 actors who clone thought routes.

```
🧢 roles (💪 skills + 📚 briefs)
  + 🧠 brains
  = 🎭 actors
```

so this is **not a new concept.** it is the extant `roles + brains = actors` composition, made
declarable at the repo level, where today only the roles half is expressible and only as a flag.

`rhachet/actors` is already a published subpath export (`genActor`, `Actor`, `Role`), so the
runtime half exists — what is absent is the **manifest** that says which actors a repo declares.

## .a shape sketch — advisory, not a spec

```yaml
default: builder

actors:
  builder:
    roles: [mechanic, behaver, driver, reviewer]
  scholar:
    roles: [librarian, learner, architect]
  dispatcher:
    roles: [dispatcher]
```

⇒ **the outcome that matters** is that a repo declares its actors and its default in one readable
file, and that `pnpm prepare` reads that file rather than a flag list. the schema, the key names,
and whether brains are declarable alongside roles are all rhachet's calls.

## .questions worth a decision, not a guess

1. **do actors declare brains too?** the composition is `roles + brains = actors`, and this ask
   names only roles. if a brain belongs in the manifest, the file shape changes
2. **what does `rhachet init` become?** an idempotent read of `actors.yml` — or does the manifest
   replace the init step outright?
3. **how does an absent `actors.yml` behave?** every repo that would adopt this has none today, so
   the fallback path decides whether this lands without a flag day
4. **does a declared-vs-installed diff surface?** the drift cost above is only retired if some
   step reports it
