## .the ask

`rule.require.clamp-edge-cases` already says **clamp the boundary, never the single value that
broke.** it does not say **how to tell a real boundary clamp from a list dressed as one** — and
that is the step where a careful author still lands wrong.

add the tell.

## 🔴 .the tell

> **if you must reason your way into the bound — grep for members, judge which files are "in the
> class" — it is a list, not a bound.**

a bound is a property of the **container**. a list is a set of **members**. they feel identical at
the moment of the fix, because both are broader than the one value that broke, and breadth is what
the rule asks for.

⇒ the discriminator is not breadth. it is **whether a future member joins automatically.**

| the repair | a new member is covered… |
|---|---|
| a list | only when a human remembers to add it |
| a bound | 🔴 **by construction** |

## .the measured case — the clamp climbed twice, and the second climb is the lesson

a unit test flaked on jest's 5s default. it spawns a real subprocess and waits for a verdict, so
its honest runtime sat at 78% of the limit and crossed under a loaded suite.

| attempt | the bound | why it was not enough |
|---|---|---|
| 1 | `, 30_000` **per case** | a list of ~40 annotations, maintained by hand |
| 2 | `jest.setTimeout` **per file**, in 3 files | 🔴 **still a hand-maintained list**, one level up |
| 3 | `testTimeout` in the **unit jest config** | cannot be forgotten |

🟡 **attempt 2 is the one worth the record, because it passes the rule as written.** it clamps a
class rather than the observed value, so it satisfies *"clamp the boundary, not the single value"*
on its face — and it is a list.

**the tell fired and was not read:** it took a `grep` to decide which three files were "in the
class", and the third was clamped on a guess — *"it drives stones through `setStoneAsPassed`, so it
probably spawns."* **a membership judgment is the signature of a list.**

⇒ the prediction the rule's own logic implies came true within the hour: a fourth file crossed,
in a second suite the sweep never named.

## .why the rule as written does not catch it

the enforcement clause grades the **narrow** failure:

> a fix for a boundary defect that clamps only the single value that broke, not the boundary class
> = **nitpick**

attempt 2 is not that. it clamped three values, in a named class, deliberately. the rule has no
clause for **a class assembled by hand**, so the author reads their own work as compliant and
stops one rung early.

## .the shape of the fix

a `.the tell` section plus one enforcement row:

- **the question**, asked of every clamp: *"does a future member of this class get covered without
  a human who remembers?"* — no → it is a list; climb one rung
- **the cue**: you ran a `grep` to decide membership · you judged one member *"probably"* in ·
  the clamp names N specific files
- **enforcement**: a clamp whose membership is hand-maintained, where a container-level bound was
  available = **blocker** — it reads as a boundary clamp and defers the same defect

🟡 **it is not a demand for the widest bound available.** some classes genuinely have no container.
the ask is that the author **answer the question on the page**, rather than infer compliance from
breadth alone — which is `rule.require.clamp-edge-cases`'s own *prove the clamp bites* discipline,
applied one level up: prove the clamp **encloses**, not merely that it fires.

## .the fulcrum

> **breadth is not the property that makes a clamp a bound. automatic membership is.**
> rework: **clean** — the addition is a section and one enforcement row; no extant clause changes.
