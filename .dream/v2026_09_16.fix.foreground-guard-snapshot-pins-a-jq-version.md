## .the cue that fired

a full `path://route` integration run returned 998 passed, 1 failed — in a suite this branch never
opens:

```
● route.foreground.guard › [case6] … › [t1] stdin is malformed json › stderr matches snapshot

- jq: parse error: Invalid literal at line 1, column 5
+ parse error: Invalid literal at line 1, column 5
```

⇒ the whole delta is the string `jq: `.

## .the gap, precisely

the snapshot captures stderr verbatim, and that stream carries `jq`'s own error text.
- older `jq` builds prefix a parse error with `jq: `; newer ones do not
- ⇒ **the snapshot asserts a property of the host's jq**, never of the hook — the hook's own line
  matches on both sides

the snapshot now pins the unprefixed form
(`src/domain.roles/driver/skills/__snapshots__/route.foreground.guard.integration.test.ts.snap`), so
the red has moved to any host with the older jq. not this branch's defect: the suite was last
touched by `#399` and `#305`.

## .the shape of the fix

🔴 **a `--resnap` is no fix** — it moves the failure to whichever host runs the other version.

1. assert on the hook's own line, never the whole stream — a snapshot of full stderr claims text
   the hook did not author
2. strip a `jq: ` prefix from each line before the snapshot, with the reason in a header
3. ~~have the hook swallow jq's stderr~~ — changes what an operator sees; a behavior call

⇒ prefer 1: a snapshot is a contract about our output. check neighbour snapshots that capture a
raw third-party stderr while there.

## .why it is not done in this round

- **SAFE — no.** it changes a driver-block hook test, outside this feature's bound diff
- **CLEAN — no.** option 1 rewrites the assertion and its snapshot

no fulcrum: a defect this round found in work it does not own, never a call it made.
