# 4.cut-fixture-cost — yield

## .what was cut

322 calls to `npx rhachet roles link`, at ~**2.2s** each ≈ **708s**, or **27.5%** of the
serial jest wall — for output that is **five relative symlinks**, byte-identical each time.

rhachet's `bin/run` sends `roles link` to `run.jit` (a full node boot of the CLI); only
`roles boot|cost` reach the compiled bun binary.

## .why a cache is SOUND here, not merely faster

the link writes **relative** symlinks — rhachet's `symlinkFile` stores
`relative(targetDir, sourceAbsolute)`. every fixture temp dir is created by `genTempDir`
at the same depth under `/tmp/test-fns/<repo>/.temp/`, and each carries the same
`node_modules` symlink set. so one real link is valid in all of them.

three properties keep it honest:

1. **the cache is populated by a REAL cli call.** the CLI is still exercised once per
   role per run — what is dropped is the 321 redundant re-proofs, never the proof
2. **only the DELTA is cached.** a role link ADDS to `.agent/`, so a fixture that links
   two roles must end with both. a cache of the whole `.agent/` would let the second
   role clobber the first
3. **the key is stamped on `rhachet.repo.yml`'s mtime**, which every build regenerates —
   so a brief added to `dist/` invalidates the cached symlink SET

## .the two design calls that carried the most weight

**one seam, not 322 call sites.** the harness exports a shared `execAsync`; the fast path
lives there. 322 call-site edits would be 322 chances to change what a test proves, and
this stone's whole bar is that no test proves less. **zero test files were touched.**

**the original path stays reachable** behind `ACCEPTANCE_LINK_CACHE=off`. that switch is
what made the before/after possible at all — the baseline was captured LAST, three
attempts in, long after the changes were built. had the original been stashed away
instead, the comparison would rest on a start point nobody measured.

⇒ this is the reusable lesson: **make the old path a switch, not a deleted branch.** a
reversible change is measurable at any time; an irreversible one is measurable only
before you make it, which is exactly when you do not yet know what to measure.

## .what it did NOT fix

the cut is 27.5% of the serial aggregate. the other 72.5% is real test work, and the
levers left are named in `3.attribute.yield.md`:

- cold `bash → rhx → bun` boot per case, thousands of times
- `genTempDir`: 457 calls × (`git init` + 2 commits) ≈ 1,400 git spawns

⇒ `.route/…/3.attribute.yield.md` carries the arithmetic: the aggregate must roughly
HALVE again, on top of 16 workers, for the 5m bar.
