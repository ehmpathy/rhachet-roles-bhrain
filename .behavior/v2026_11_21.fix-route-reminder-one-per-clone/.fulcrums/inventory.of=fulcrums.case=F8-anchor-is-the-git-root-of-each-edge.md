# F8 — each edge anchors the clone home on the git root of the path it holds

- **fork**: (a) the drive sync and `gen` anchor on the git root of the route; `get` and `del` on the git root of cwd; the daemon on its `--repo-root` flag · (b) one anchor function at every edge, with the guard's `process.cwd()` fallback out of git · (c) a `RouteReminderCloneKey` resolved once and threaded to every leaf · (d) a machine-scope home keyed on `cloneAddr` alone, with an env override for hermetic tests
- **taken**: (a). a route always sits inside its repo, so the route's git root and the cwd's git root name one dir whenever a clone drives from its own worktree. a clone in another worktree is a different clone home by design: each worktree is its own checkout, and its daemon lives there. the out-of-git fallback (the path itself) serves only hermetic temp dirs; a real route is never outside git. `get` now names the anchor it read and says where a clone in another worktree keeps its reminder
- **rework**: clean — the anchor is one transformer (`getRouteReminderRepoRoot`) at three call sites; a switch to (b) or (c) changes those sites, no contract
- **confidence**: 75% — an out-of-git route in production would get one home per route; no such route was found, and none is created by any route template
- **on (d)**: a machine-wide home removes the anchor rules, but every worktree's daemons then share one dir with no sunset for a dead session, and the hermetic tests need a new seam. that is a new home contract, the owner's call; the typo-anchor case it would also remove is closed here, since `gen` refuses a `--route` that is not a dir (cli case30)
