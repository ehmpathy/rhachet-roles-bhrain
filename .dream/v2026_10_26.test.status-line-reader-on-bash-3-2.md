## .the cue that fired

a peer reviewer (5.1 execution, i004, enroll-impl-behavior-intent item 8) noted that the

## .the gap, precisely

`src/domain.roles/driver/skills/route.status.line.sh` lists the builtins it uses and those it
avoids (`mapfile`, `${x,,}`, associative arrays, `$EPOCHSECONDS`). no test runs it on bash 3.2,
so a 4.x-only construct added later would pass every suite and blank every macOS seat.

the stale test's `-nt` resolution is also unproven there (i006 r010 item 7). the vision claims
apfs carries nanoseconds, but whether bash 3.2's `-nt` compares sub-second mtimes is unverified.
every reader case plants inputs 60s apart, so none touches same-second order. if it compares
whole seconds, an input written in the same second after the status file reads fresh until the
next drive.

the reader is also never run in a real `git worktree` (i006 r010 item 5): case10 hand-builds a
relative `gitdir:`, while each seat here is a worktree with an absolute `gitdir:` into
`.git/worktrees/<name>`. the TS twin has a real `git worktree add` case; the bash reader has none.

## .the shape of the fix

a ci job (or a docker `bash:3.2` image in an integration case) that runs the reader integration
corpus under bash 3.2, or a lint that rejects the 4.x-only constructs in that one file.

plus two reader cases: one that writes an input in the same second as the status file and
asserts stale, and one under a real `git worktree add` with an empty PATH.

## .why it is not done in this round

it needs a new ci image or job, a change to the repo's ci, beyond the status line fix. it fails
CLEAN.
