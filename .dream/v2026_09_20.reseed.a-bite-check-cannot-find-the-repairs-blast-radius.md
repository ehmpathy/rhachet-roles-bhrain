# 🌙 dream: a bite check cannot find the repair's blast radius

- **kind** = reseed
- **owner** = `ehmpathy/rhachet-roles-ehmpathy`
  (`src/domain.roles/mechanic/briefs/practices/work.flow/diagnose/rule.require.clamp-edge-cases.md`)
- **caught** = 2026-09-20

## .the cue that fired

a repair moved a diagnostic tally out of a file whose mtime a gate reads, into its own marker. it was
bite-proven exactly as `rule.require.clamp-edge-cases` prescribes — re-fuse the two markers, watch
**9 red**, restore, watch green — and the unit suite was **1510 / 0**. the round read as done.

the integration and acceptance suites then failed on that same repair. **three assertions at two
coarser grains still encoded the old fused shape:**

| grain | the assertion |
|---|---|
| integration | `expect(sinceContent).toContain('attempts: 0')` |
| acceptance | `expect(sinceContent).toContain('attempts: 2')` |
| acceptance | a snapshot field `askContent: "slug: all-done\nattempts: 0"` |

## .the gap, precisely

🔴 **the bite check and a stale assertion have INVERTED POLARITY, so the check is blind to one by
construction.** the disarm *restores the old shape*:

| | under the repair | under the disarm |
|---|---|---|
| a **new clamp** — what the check hunts | green | 🔴 **red** ← the signal |
| a **stale assertion** of the old shape | 🔴 **red** | green ← the check never sees it |

⇒ the disarm-and-watch loop is aimed at tests that **exercise the changed property**. a test that
**asserts the property's old value** flips the other way, so a driver who watches for red sees
naught — and sees it *especially* when the loop is scoped to the suite the new clamps live in, which
is the cheap and therefore the usual way to run it.

⚠️ **the rule's own worked example has this shape and does not name it.** its case adds one clamp and
proves it bites; it says the clamp must go red under the un-fixed defect, and is silent on the
assertions that were green before the repair and are red after. so a reader who follows the rule
exactly still ships the gap.

🟡 **and it is not a slow-suite problem.** two of the three stale assertions here were in suites that
run in under 10s once scoped. the reason they went unrun is that the bite check **reported success**,
which is a stronger stop signal than a slow suite is.

## .the shape of the fix

add a second step to the rule, beside the revert-and-watch:

> **after the clamp bites, GREP for the old shape.** the disarm proves the repair; a grep for the
> value or field the repair removed is what finds every caller that still asserts it.

concretely, for a repair that removes or moves a field:

```sh
rhx grepsafe --pattern '<the removed field or value>' --path <the subsystem and its callers>
```

one command named all three stale assertions in the incident above, and it would have run **before**
the 405s integration suite rather than after it.

🔴 **and it finds one class no suite can.** the same grep surfaced a fourth defect: the operation that
computes the three marker paths returned three and its **own unit test clamped two** — the repair
added the third and never extended the test that owns that shape. the property was enforced only
three layers out, by behavior. no suite fails for an absent clamp; only a grep finds it.

⇒ the transferable line, and the one worth the rule's prose: **a bite check proves the repair; it
cannot find the repair's BLAST RADIUS.**

🟡 two smaller notes for whoever takes this:

- the repairs should be **re-aims, never deletions** — each stale assertion has a claim that is still
  true and a file that moved. the line that proved the tally was IN the operand now proves it is OUT
  of it, which is strictly better coverage than before
- a **snapshot** in the blast radius is a legitimate re-take, and the check that it is legitimate is
  that the *other* fields in it are unmoved

## .why it is not done in this round

**SAFE: yes** — it is an additive step to a rule, and it forbids naught the rule permits today.

**CLEAN: no**, and this is the half that blocks. the rule lives in
`ehmpathy/rhachet-roles-ehmpathy`, a different repo — this round's diff cannot reach it, and a tree
adopts only what is scoped to itself (`rule.always.scope-onetime-lessons-to-the-behavior`). a local
copy would be a second home for one rule, which is the braid
`rule.always.reuse-pavement-before-improvise` names.

⇒ the worked instance is recorded in this round's execution yield, under
`.behavior/v2026_09_17.fix-self-review-min-duration/5.1.execution.from_vision.yield.md`, so the
re-seeded rule has a citable example to point at.
