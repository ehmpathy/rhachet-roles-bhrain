## 🔴 .the per-entry analysis is REHOMED — twice now, and the recurrence is the finding

an inventory root is an index (`rule.require.catalog-is-an-index`): *"one row per member, and no
narrative about any one of them."* this file has broken that rule **twice, in two different shapes**,
and both records are kept so the next traveler can see the pattern rather than the patch:

| round | the shape that grew here | where it went |
|---|---|---|
| **i010** | a **per-round ledger** — thirteen `what changed in peer review iNNN` sections, 566 lines | `.agent/.notes/fulcrums.per-round-record.i001-i010.md` |
| 🔴 **i012** | 🔴 a **per-entry analysis** — eight `##` sections, each about one row or a small set | `.agent/.notes/fulcrums.analysis.per-entry.md` |

⇒ **naught was cut either time. the record was MOVED, whole.**

🟡 **the second one is what makes this worth a section rather than a silent trim.** the i010 repair
was correct and it did not hold, because **the rule's pull and the author's pull point opposite
ways**: every rehomed section was true, useful, and the natural place to write it was beside the row
it concerned. ⇒ so the index does not decay by a careless edit — **it decays by a sequence of good
ones**, which is the exact mechanism `rule.require.catalog-is-an-index` names.

⚠️ **and the repair is an EJECTION, never a trim**, per that rule's own words: compressed prose about
one member is still prose about one member, and it re-grows. the i010 cut proved that on this very
file in two rounds.

🟡 **both moves also lifted a halt, and that is a side effect rather than the reason.**
`.agent/.notes` is gitignored (`.gitignore:4`), so a rehome leaves the reviewer's
`--diffs since-main` scope entirely. at i010 nine l1 lanes returned `constraint ✋` at **79.5% of a
750k gate**; at i012 they returned it again at **80.7%**. ⇒ the cut was owed on its own merits each
time and it also bought scope — the loop `rule.always.raise-a-blocker-a-taken-cannot-close` names,
met in the wild twice.
