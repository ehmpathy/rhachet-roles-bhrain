- **kind** = fix
- **owner** = this repo (`rhachet-roles-bhrain`)
- **caught** = 2026-09-19

## .the cue that fired

a peer reviewer (`mech-failhides`, i002 r002) raised one instance in
`blackbox/driver.route.self-review.acceptance.test.ts`. the round's own rule says **sweep rather
than patch**, so I grepped rather than patched — and the shape is everywhere.

## .the gap, precisely

```ts
const files = await fs.readdir(routeDir).catch(() => []);
```

`ENOENT` is the real absence. **every other error is a fault**, and this coerces all of them to an
empty list: `EACCES` (a permission fixture left behind), `EIO`, `EMFILE` (real under a fork of M
lanes), `ENOTDIR`. the assertion downstream then goes green **for the wrong reason**.

⇒ `rule.forbid.failhide` names exactly this, and the repo already knows it: `findsertGitignore.ts`
carries a docblock about the same defect (*"swallowed EVERY read error via `.catch(() => null)`"*),
and `setSelfReviewTriggeredReport.test.ts` introduced an ENOENT-only `isPathFound` for it.

### 🔴 the two harms are not the same size

| the shape | what a fault costs |
|---|---|
| a **read fed to an assertion** — `expect(files.filter(…)).toEqual([])` | one false green. the check never ran and reports "clean" |
| 🔴 a **read fed to a fixture mutation** — a back-date loop, a cleanup | the loop is a **no-op**, so every case downstream runs against the wrong precondition and fails as a *wrong verdict* rather than as a fault |

the second is the one worth the hunt. a wrong verdict sends the next traveler to debug the subject
rather than the fixture.

## .the shape of the fix

**one named reader per module, not an inline allowlist per call site.** the pattern landed in
`driver.route.self-review.acceptance.test.ts` this round:

```ts
const getRouteDirFiles = async (routeDir: string): Promise<string[]> =>
  fs.readdir(routeDir).catch((error: NodeJS.ErrnoException) => {
    if (error.code === 'ENOENT') return [];
    throw error;
  });
```

⇒ and the repo has the better home for it already: **`src/domain.operations/route/isExpectedFsReadFault.ts`**
is extant and does this sort. the sweep should route through that rather than mint a third
convention — check its shape first, and lift the test-side reader into `blackbox/.test/` so the
acceptance suites share one owner.

🟡 **the clamp is cheap and it must bite** (`rule.require.clamp-edge-cases`): `chmod 0o000` a route
dir, run one case, assert it **throws** rather than reports empty. a revert of the allowlist must
turn it red — the extant suite cannot, because every fixture dir is readable.

## .why it is not done in this round

**SAFE?** no. it touches ~20 test files across four subsystems this round's diff does not open, and
a coerced-to-throw read can surface a **latent** fixture fault that was previously swallowed — which
is the right outcome and is not a change this round can absorb.

**CLEAN?** no. not one of these lines is in `git diff origin/main` for this branch; every one is
extant. `rule.prefer.scouts-honor` grades *"a repo-wide cleanup smuggled into an unrelated change"*
a **blocker**, and this would be exactly that.

⇒ so it fails both questions of `rule.always.fix-forward-under-scouts-honor`, and the deferral is the
rule's own answer rather than a dodge. **the two instances inside this round's own file were repaired
rather than deferred.**

### 🔴 the IN-DIFF subset was repaired at i004, and the bound is what the rule actually draws

`enroll-impl-arch-defects` (i004 r011 point 1) re-raised the class and named four files. **three of
them were already modified by this round's diff**, so `rule.prefer.scouts-honor` binds — a cheap,
safe improvement left unmade *in a file you edited* is a nitpick. those three are repaired, plus the
five `fs.access`-to-`false` probes in `archiveStoneYield.integration.test.ts` (also in-diff):

- `blackbox/.test/getRouteDirFiles.ts` is the shared ENOENT-only reader the three now import.
  🟡 it is a SECOND allowlist deliberately — see below
- `archiveStoneYield.integration.test.ts` gained a local ENOENT-only `isPathFound`

🔴 **and this dream's own advice about the owner was WRONG, which is the correction worth a record.**
it said the sweep should route through `src/domain.operations/route/isExpectedFsReadFault.ts`. read
it: that allowlist admits **EACCES, EISDIR, ENOTDIR, ELOOP, ENAMETOOLONG** — because it exists for a
*display fallback*, where an unreadable file is legitimately "show the placeholder". every one of
those is a **broken fixture** when a test asks what a route dir holds. ⇒ to route a test read
through it would re-introduce the exact swallow this dream is about. **two callers, two tolerances,
two allowlists** — and the third convention this dream warned against was the right call after all.

⇒ **what remains deferred is the OUT-OF-DIFF remainder**: the rows above with no ✅, plus the ~60
`stat`-to-`false` and ~8 `readFile`-to-`''` shapes. those still fail CLEAN, and the argument above
stands for them unchanged.

⚠️ **and it is worth the catch precisely because each instance is individually defensible.** nobody
wrote `.catch(() => [])` carelessly — it reads as "the dir may not exist yet", which is true and is
the common case. the defect is only visible when you ask *what else does this catch?*, and that
question is the expensive half. it is answered above.
