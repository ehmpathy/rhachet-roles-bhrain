# 🌙 dream: the driver's PreToolUse hooks fail closed when rhx cannot find their skill

kind: fix · owner: ehmpathy/rhachet-roles-bhrain (role=driver) · caught 2026-11-01

## .the cue that fired

while route `v2026_11_01.fix-memory-guard-fails-open` fixed memory.guard, the root cause turned out to be generic: `rhx <skill>` exits 2 (`ConstraintError`) when no linked role holds the skill, and claude code reads exit 2 from a PreToolUse hook as *block*.

## .the gap, precisely

`src/domain.roles/driver/getDriverRole.ts` registers three PreToolUse hooks through `./node_modules/.bin/rhx`:
- `route.bounce --mode hook` (Write|Edit)
- `route.mutate.guard --mode hook` (Read|Write|Edit|Bash)
- `route.foreground.guard --mode hook` (Bash)

in a tree where the driver is not linked but the settings carry these hooks, every matched call halts with `no skill "route.mutate.guard" found in any linked role`.

## .the shape of the fix

reuse the memory.guard shape: the hook command runs the linked skill file directly, and prints one stderr line + exits 0 when the file is absent:

```
[ -f .agent/repo=bhrain/role=driver/skills/<skill>.sh ] && exec bash .agent/repo=bhrain/role=driver/skills/<skill>.sh --mode hook || echo '🗿 <skill>: could not run (skill not linked in this tree); call allowed' >&2
```

each skill then maps any exit other than its own verdict 2 to 0. clamp per hook: an unlinked temp tree → exit 0.

🟡 a wider cure belongs to rhachet: a hook-mode invocation of `rhx` should never exit 2 on its own lookup fault. a reseed to `ehmpathy/rhachet` may be the better home.

## .why it is not done in this round

the wish scopes memory.guard. three more hooks, each with its own verdict contract and its own suite, is a second change with its own review.
