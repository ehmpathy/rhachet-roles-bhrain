# 🌙 dream: cli constraint errors print an unqualified `error:` header

kind = fix · owner = rhachet-roles-bhrain (`src/contract/cli/`) · caught 2026-10-21

## .the cue that fired

a review of `reflect.on.token.spend` for consistent mechanisms compared its error render to its siblings. the new cli prints `✋ ConstraintError: …` (exit 2) and `💥 MalfunctionError: …` (exit 1); every extant cli prints a bare `error: …`.

## .the gap, precisely

`rule.require.qualified-error-headers` (ehmpathy/mechanic) grades an error header with no `ConstraintError:` / `MalfunctionError:` qualifier as a blocker. the extant clis use `console.error(\`error: ${error.message}\`); process.exit(2);` — e.g. `src/contract/cli/route.ts:718` and `:764`. check: `rhx grepsafe --pattern 'error: \$\{' --path src/contract/cli`.

so a reader cannot tell from the first line whether they must act, and two shapes now coexist for one concept.

## .the shape of the fix

1. lift the render in `reflect.on.token.spend.ts` (`asErrorFacts` + `formatTokenSpendErrorTree`, under `src/domain.operations/reflect/tokens/`) to one shared `src/infra/cli/` pair, e.g. `asCliErrorTree({ error, skill })`, that maps `BadRequestError` → `✋ ConstraintError:` and all else → `💥 MalfunctionError:`, strips the class prefix HelpfulError adds, and hangs each metadata fact as a leaf with the hint last as `fix:`
2. route each extant cli catch through it, one cli per commit
3. resnap the blackbox stderr snapshots each cli touches; the diff is the header line alone

## .why it is not done in this round

safe, but not clean: it ripples into every cli and many stderr snapshots this route never opened. a smuggled refactor of that size fails the CLEAN question (`rule.always.fix-forward-under-scouts-honor`).
