## .the cue that fired

the stop hook `rhachet roles cost --all --when hook.onStop` refused:
`.agent/repo=.this/role=any/boot.yml (29,773 / 5,000 tokens)`.

## .the gap, precisely

- `git diff` on the boot spec shows ONE change: a new `budget: tokens: 5_000` header. the say set
  itself is unchanged from `main` — it has been ~30k tokens all along
- the header was seeded by rhachet's own init: `findsertBudgetIntoBootYml.js:13`,
  `BUDGET_TOKENS_DEFAULT = '5_000'`, landed with the rhachet 1.49.2 upgrade in this worktree
- so every session now ends with a refusal, until the spec fits or the budget is raised on purpose
- a removal of the header is no fix: the findsert re-seeds it on the next `rhx init`

## .the shape of the fix

`rhx cost --what .agent/repo=.this/role=any/boot.yml` ranks each batch by cost. then, per the
hook's four strategies, cheapest first:
1. **catalogize** — the `domain.terms/` and `domain.glyphs/` sets already ride as refs; check no
   say entry restates one
2. **condense** — the largest say briefs (the prompt-cache rules: `order-prompt-sections-by-volatility-then-size`,
   `name-the-shared-prefix-as-the-cache-anchor`, `suppression-of-undeclared-concerns`,
   `report-both-cost-levers…`) each run past 1k tokens; each owes a `.md.min`
   (`rule.prefer.rules-that-refout`: the cue stays, the argument refs out)
3. **reference** — rules that fire only in the review subsystem can move to ref; their cues
   could boot with the reviewer role instead
4. **budget** — if the curated floor still exceeds 5k, raise `budget.tokens` deliberately, with
   the reason beside it

## .why it is not done in this round

not clean, and not this route's call: it decides what every future session of every role here
boots with — ~25k tokens of curation — while this route's wish is the status-line init. and the
budget change came from a tool upgrade, not this work.
