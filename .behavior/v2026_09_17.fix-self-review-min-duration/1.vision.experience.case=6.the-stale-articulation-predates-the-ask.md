# case=6 — the stale articulation predates the ask

**cell** `D3 strip × c5` · **feel** sharp · **care** alterpath (chosen)

> the gate `S01` clause 3 asks for: *"and have an mtime greater than X."* demoed rather than merely
> itemized, because **a mis-set `X` re-creates the defect this wish repairs.**

## .the narrative

a driver rewinds a stone and re-arrives. the guard asks for the self review again. an articulation
file from the prior round is still at the owed path — real work, written days ago, about an
artifact that has since changed.

they promise. the path check passes: a file is there. **and the review it holds answers a different
artifact.**

the freshness bar catches it:

```
🗿 that one is old, friend
   │
   ├─ found at
   │  └─ $route/review/self/for.3.3.blueprint._.has-questioned-assumptions.md
   │     └─ written 2026-09-12
   │
   ├─ this review was asked for 2026-09-17
   │  └─ so that file answers an older question
   │
   └─ re-read, append what you find now, then promise again
```

### .the "aha"

> **the path proves a file. the mtime proves it was written for THIS ask.**

a path check alone reduces to *"a file with the right name exists"*, and a file that survives a
rewind satisfies it without a single fresh thought. the freshness bar is what makes the path check
a claim about **this** review.

## ✅ 🔴 .the trap — `X` is the TRIGGER, and it is now RULED

the bar reads `mtime(articulation) > X`. two candidates for `X`, and they behave oppositely:

| `X` | the driver who repairs 9 times | verdict |
|---|---|---|
| **the trigger's `.since` mtime** | writes once, passes. the `.since` is pinned at the ask and never moves | ✅ **taken** (`F02`, `S14`) |
| **the artifact's own mtime** | 🔴 **every repair invalidates their articulation.** they must re-touch the file after each edit — the original defect, in a new coat | 🔴 refused |

⚠️ **the second candidate is the more intuitive one** — *"your review should be newer than what it
reviews"* sounds right and is a trap. `F02` existed because the utterance named `X` and never defined
it; `S14` defines it as the trigger, at 97%.

🔴 **the transferable rule the verdict yields, and it is sharper than this cell's own words:**

> **measure freshness against the ASK, never against the SUBJECT.**

an artifact under review moves **because** the review works. so any bar that measures a review
against the artifact it reviews penalizes the review for its own success. ⇒ **the ask is the one event
in the interaction the driver's own diligence cannot advance**, and a bar is fair only when the party
under it cannot move the goalpost by good work.

## .the bdd sketch

```
  then the file's mtime is newer than the trigger

when [t2] the driver then repairs the blueprint 9 times and promises again
  then the articulation is still fresh                 # X is the trigger, never the artifact
   and the decision is 'allowed'

  then the trigger markers for this stone are deleted  # 🔴 today the cleanup glob misses them
   and the next ask mints a .since at that moment      # else [t0] is unreachable
```

## 🔴 .the narrative above assumes the trigger was RE-ASKED. today it is not

every line of this demo rests on one sentence — *"this review was asked for 2026-09-17"* — and that
freshness of the **trigger** is what the whole bar measures against.

**the trigger does not refresh.** the hash was what minted a new report per generation; the round
removes it, and the declared replacement is the rewind's cleanup, which is broken:

| the cleanup globs | the markers are named |
|---|---|
| `.route/$stone.guard.selfreview.*.triggered.*.md` (`delStoneGuardArtifacts.ts:42-45`) | `…triggered.since` · `…triggered.uptil` (`getSelfReviewTriggeredReport.ts:19-21`) |

`enumRouteFiles` is a plain glob pass, so `triggered.*.md` matches **zero** markers. ⇒ a rewind
clears the promise and keeps the clock. **measured on this route: 13 trigger markers in `.route/`,
and a promise glob that ends in `.md` and would clear both promises.**

⇒ so `[t0]` is **unreachable as written**: the `.since` never advances past the stale file's mtime,
the bar reads the file as fresh, and it clears on the first attempt. **the demo describes the
behavior the round intends, never the behavior the round produces**, and that gap is `F10`.

✅ 🔴 **`F10` IS RULED** (`S10`): the rewind removes the trigger markers **entirely** and **archives**
them. ⚠️ **the gap is closed in the design and open in the code** — the glob still demands `.md`. so
this demo remains the assertion `F10`'s build must satisfy.

🔴 **and `S14` makes the pair inseparable rather than merely adjacent.** the bar reads
`trigger.since.mtime`, so **whatever invalidates the trigger sets what this bar measures against**:

| if the trigger… | what the bar does |
|---|---|
| is removed by the rewind (`F10`, ruled) | ✅ compares each articulation against **this round's** ask |
| is never invalidated | 🔴 **compares every future articulation against a frozen instant** — it passes always, and the gate loses a tooth in silence |

⇒ **so `F02` and `F10` are one deliverable, not two.** a build that ships the freshness check without
the rewind repair ships a check that **cannot fail** — and that is a worse outcome than no check,
because a gate that always passes reads as a gate.

🟡 **the demo stands.** a demo deleted because the code cannot yet reach it would hide the gap it
exists to expose.

## 🟡 .why this is an alterpath, not a critipath

it fires only after a rewind or a re-arrival onto a stone whose review was already written — rare.
its **cost** when it fires is real (a stale review passes as a fresh one), which is what earns it a
demo; its **frequency** is what keeps it off the critical path.

⇒ `[t2]` is the assertion that matters most here, and it is not about staleness at all. it was the
guard against a wrong settlement of `F02` — ✅ **and `S14` settled it the right way**, so `[t2]` is
now the assertion that the settlement **shipped** rather than the guard against it going wrong.

🟡 **the demo is kept at alterpath, and `S13` did not change that.** the clock's re-purpose touches
`D5`; this cell is `D3`, and the two strips are orthogonal by construction — a stale file is refused
whether or not a prompt was rendered.
