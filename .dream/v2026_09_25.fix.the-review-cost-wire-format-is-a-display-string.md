# 🌙 dream: the review-cost subsystem persists money as a display string

- kind  = `fix`
- owner = `ehmpathy/rhachet-roles-bhrain` (this repo)
- caught = 2026-09-25

## .the cue that fired

the seventeenth warmer audit pass read the **seams** — does every test double return exactly what the
real operation returns, and no shape it cannot? a hundred integration tests inject a `poke` stub, and
if the stub's shape diverged from `getOnePokeMeasured`'s, the whole audit's green would be worth less
than it reads.

⇒ **the seam is exact.** the stub hands back `{ promptTokens, cacheGetTokens, cost }` with fixtures
like `'$0.001383360'`; production hands back `asIsoPriceHuman(metrics.cost.cash.total)`, which is the
same form. no drift.

🔴 **and the form both sides agree on is one `rule.require.iso-price` forbids.**

## .the gap, precisely

### 1. the rule, verbatim

> *"IsoPriceWords is the one you store/pass. **IsoPriceHuman (`'$50.37'`) is display-only
> (locale-bound, lossy) — keep at the ui edge, never stored/passed**"*
> — `rule.require.iso-price`

and its negative twin's enforcement line:

> *"money/price/fee/total declared as number or **display string** in a domain object, contract, or
> **stored value** = blocker"*
> — `rule.forbid.any-price`

### 2. it is the subsystem's WIRE FORMAT, not one file's slip

| site | what it persists |
|---|---|
| `stepReview.ts` lines 1011-1015, 1084, 1134-1138 | **eleven** `asIsoPriceHuman(...)` writes into `metrics.realized.json` — the run cost record the whole meter reads |
| `compileReviewPrompt.ts:386` | `costEstimate`, into the input artifacts |
| `getOnePokeMeasured.ts:150` | the warmer's poke row |
| `getOneWarmerSpend.ts:154` | the spend it returns |
| `getOneReviewRunMeterAt.integration.test.ts:2` | imports and declares the type `IsoPriceHuman` by name |

⇒ so it is **consistent and deliberate**, which is what makes it a design defect rather than a typo —
and what made it invisible. every warmer file matches its neighbours exactly.

### 3. what is actually lost, and what is not

🟡 **precision SURVIVES**, and this is worth stated plainly because it is the harm a first read
reaches for. the round trip is `asIsoPriceHuman` on write → `asIsoPrice` on read → `priceSum` →
`asIsoPriceHuman` to render, and iso-price preserves granularity to the most granular input. clamped:
`getOneWarmerSpend.integration.test` sums `$0.001383360 + $0.000036648` and asserts `$0.001420008`.

🔴 **the CURRENCY is what is lost.** `$` is shared by USD, CAD, AUD, SGD, MXN and more, so
`asIsoPrice('$0.000428')` must **assume** one. `IsoPriceWords` carries the iso 4217 code and cannot be
misread.

| the failure | reachable? |
|---|---|
| a provider that bills non-USD | not today — every brain on the card bills USD |
| two providers in two currencies summed together | not today — one brain per run |
| a reader of a row who cannot tell which dollar | **today**, and it is the honest statement of the harm |

⇒ **so the harm is LATENT, and the rule violation is present.** stated that way rather than dressed
up: `rule.forbid.overzealous-blockers` asks who suffers and how, and today the answer is a future
reader of an ambiguous record, never a user of a wrong number.

## .the shape of the fix

one substitution at each write site, and the reads need no change at all:

```ts
// getOnePokeMeasured.ts
- cost: asIsoPriceHuman(metrics.cost.cash.total),
+ cost: asIsoPrice(metrics.cost.cash.total),      // 'USD 0.000428'
```

- every reader already goes through `asIsoPrice`, which accepts **both** forms — so rows and
  `metrics.realized.json` files already on disk keep their meaning with no migration
- `asIsoPriceHuman` stays exactly where the rule puts it: the **render**, in
  `genReviewRunStdout` / `genReviewMeterStdout` / `genReviewGroveStdout`
- the `'$0'` literals (`getOneWarmerSpend.ts:158`, `asAccountedCost.ts:51`) become `'USD 0'`
- 🔴 the **type annotations** go too — `getOneReviewRunMeterAt`'s `IsoPriceHuman` becomes
  `IsoPriceWords`, which is what makes the compiler enforce the seam thereafter rather than a comment

## .why it is not done in this round

**SAFE — yes**, and unusually so: `asIsoPrice` reads both forms, so there is no migration and no
window where an old artifact is unreadable.

🔴 **CLEAN — no.** it is a wire-format change across the subsystem this branch was built on:

- **~8 production files**, `stepReview.ts` (11 sites) and `compileReviewPrompt.ts` among them — both
  far outside the warmer, and both central to the branch's own deliverable
- **every fixture that spells a cost** — the sweep above found `'$…'` literals in ~20 test files
- **the snapshots**, which pin rendered stdout; those must NOT change (the render stays `Human`), so
  each is a place the change must be proven inert rather than updated
- the `IsoPriceHuman` type annotations, which is where the real value is and also the real reach

⇒ and the timing argues the same way: this is the cost subsystem's declared format, chosen before
the warmer existed. to re-format it inside a warmer audit is exactly the scope leak
`rule.prefer.wickup-touched-prose` bounds — *on contact, in scope*, and a subsystem-wide wire format
is neither.

🟡 the urgent half is closed: the choice is now **declared** where the warmer persists it, with the
rule cited, the latent harm named, and the precision question settled — so the next reader can tell a
deliberate format from an accidental one, which is what they could not do before.
