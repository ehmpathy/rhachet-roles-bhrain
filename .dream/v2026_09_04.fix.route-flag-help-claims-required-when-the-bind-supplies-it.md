# 🌙 dream: `--route` help claims "(required)" when the branch bind supplies it

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04, on the i/o capture for `review.self r7` of
  `v2026_09_03.fix-contemplation-gate-on-entrance`

## .the cue that fired

`rhx route.stone.set --help` prints:

```
  --route <path>     path to route directory (required)
```

i had already run that exact command **without** `--route` dozens of times on a bound route, and it
worked every time. the help and the product disagree.

## .the gap, precisely

`route.ts` looks the flag up through `getRouteOrThrow`, whose bind branch reads:

```ts
if (bind) return bind.route;
```

⇒ so for every subcommand that goes through that lookup, `--route` is **inferred from the branch
bind** and is optional. the help calls it required anyway.

⚠️ `route.bind.set` is the one honest `(required)` — you cannot infer the route you are about to
bind, and it enforces the flag with its own error. it must keep the word.

🔴 **this section cited `route.ts:947` and `:834` until 2026-09-08. both had drifted by two** — the
true lines are `:949` and `:836`. ⇒ **an off-by-two is the worst size**: it lands inside the same
function, so a reader sees plausible code and never suspects the citation.

## 🔴 .it is also a term inconsistency — FOUR phrasings for one fact

```
$ rhx grepsafe --pattern 'path to route directory' --path src
```

| phrasing | where | verdict |
|---|---|---|
| `(required)` | `route.ts` ×4 · `route.stone.set.sh` `route.stone.get.sh` `route.stone.judge.sh` `route.stone.del.sh` | 🔴 **false** — these go through `getRouteOrThrow` |
| `(required)` | `route.ts` ×1 · `route.bind.set.sh` | ✅ true — bind.set genuinely needs it |
| `(optional, uses bound route)` | `route.ts` ×1 | true |
| `(uses bound route if absent)` | `route.ts` ×2 · `route.drive.sh` `route.review.sh` | true |
| `(default: auto-detect from branch)` | `route.ts` ×2 · `route.guard.upgrade.sh` `route.guard.budget.sh` | true |

⚠️ **each `route.ts` cell carried its line numbers, and every one was redundant** — the left column
holds a literal string, and the grep above finds every site of it. ⇒ **the counts are what the reader
needs; the addresses the grep supplies.** ten numbers, all fused to a file this branch edits, all
struck.

⇒ `rule.forbid.domain-term-inconsistency` fires on the three true phrasings — one concept, three
words, no canonical term declared. and the fourth group is not a synonym problem at all; it is
simply wrong.

## .why it bites harder now

the contemplation gate's emits print the fix command **without** `--route`, because a bound route
supplies it:

```
   └─ when you've contemplated this reviewer, run
      └─ rhx route.stone.set --stone 1.test --as contemplated --that mechanic
```

that emit is correct. but a driver who reaches for `--help` reads that a flag the tool just omitted
is *required* — so the two surfaces of one contract contradict each other at the exact moment a
halted driver is looking for guidance. `rule.forbid.surprises` and `rule.require.help-on-demand`
both land here; a help text that misstates a contract is worse than absent help, because it is
trusted.

## .the shape of the fix

1. pick **one** canonical phrasing for "inferred from the branch bind" and use it everywhere. of the
   three true variants, `(uses bound route if absent)` states the mechanism and the fallback in the
   fewest words; `(default: auto-detect from branch)` names a behavior the reader cannot verify
2. correct the four false `(required)` sites in `route.ts` plus their four skill-doc twins
3. leave `route.bind.set` as `(required)` — and add a one-line note saying **why** it differs, so the
   next reader does not "correct" it into the wrong column

## .why it is not done in this round

- **not clean** — 8 sites across 4 subcommands, three of which (`route.stone.get`, `route.stone.del`,
  `route.stone.judge`) this behavior never touched. the fix rides its own diff, not this one
- **it needs a term decision first** — step 1 is a canonical-word call under
  `rule.forbid.domain-term-inconsistency`, and a call like that made mid-drive to unblock a review is
  exactly the kind that gets re-litigated later
- **a piecemeal fix would be worse** — to correct only `route.stone.set` leaves three subcommands
  wrong and adds a fifth variant to a set that already has four. that is the braided trail
