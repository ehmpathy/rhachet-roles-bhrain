# 🌙 dream: diagnose why a temp repo reports `unreadable-clone` where the repo root reports `unenrolled`

- kind  = fix
- owner = `ehmpathy/rhachet-roles-bhrain`
- caught 2026-09-16

## .the cue that fired

a blackbox acceptance test for a prescribed `brain:` asserted the `unenrolled` halt, on the
strength of a measured fact from the vision stone (**F-a**):

```
$ rhx clone whoami --output json        # at this repo's root
ConstraintError: not run inside an enrolled clone        → exit 2 → cause `unenrolled`
```

the same probe, spawned from a `genTempDirForRhachet` fixture, produced **`unreadable-clone`** —
which `getCloneAddress` returns for a spawn error, or for any non-zero exit that is not 2.

## .the gap, precisely

**measured 2026-09-16**, `blackbox/driver.route.brain.acceptance.test.ts`, first run:

```
this driver runs     = unknown — the clone probe could not be read
why: `clone whoami` did not answer, or failed for a reason this build does
     not read. …
fix: run the probe by hand and read what it reports —
  rhx clone whoami --output json
```

⇒ so a driver in that environment is handed **"run the probe by hand"** where the true remedy is
`rhx enroll`. the halt is honest — it claims no diagnosis it did not make — and it is the **less
useful of the two**, on the cause that is by far the most common (`F-a`: unenrolled is the default
state).

🟡 **what is NOT known is which environment is the outlier.** two hypotheses, and no observation
parts them yet:

| hypothesis | what it would mean |
|---|---|
| the temp fixture's symlinked `node_modules` breaks the `rhx` shim, so the probe never runs | a **fixture** artifact. production is unaffected, and the acceptance suite simply cannot reach `unenrolled` |
| `clone whoami` exits non-2 whenever the cwd is not a rhachet-introspected repo | a **real** ergonomics defect: a fresh consumer repo gets the weaker halt |

### 🔴 .narrowed 2026-09-18 on i038 — the SIMPLEST form of hypothesis 1 is dead

a repair for `r010` nitpick.2 was designed on hypothesis 1's simplest form — *"the binary is absent,
so the spawn ENOENTs"* — and it was **checked before it shipped**. the check refutes it:

```
invokeRouteSkill.ts:33   { at: 'node_modules/.bin',   to: 'node_modules/.bin' }
invokeRouteSkill.ts:35   { at: 'node_modules/rhachet', to: 'node_modules/rhachet' }
invokeRouteSkill.ts:38   { at: 'node_modules/.pnpm',   to: 'node_modules/.pnpm' }
```

⇒ the fixture symlinks the `.bin` dir, the package, **and** `.pnpm` — and line 37 states the third
is there for exactly this shim: *"rhx wrapper does `$basedir/../.pnpm/...` which needs .pnpm to
exist"*. so `node_modules/.bin/rhx` **resolves** from a temp dir, and an absent-binary ENOENT is not
the cause.

⚠️ **hypothesis 1 is narrowed, never closed.** the shim can still break *after* it resolves. what is
ruled out is the one form that would have made this a fixture triviality.

🔴 **and a second candidate repair died with it.** `RHACHET_CLONE_SERIAL: ''` would force
`unenrolled` deterministically — rhachet's own check is `if (!serial) throw new ConstraintError(…)`
(`invokeCloneWhoami.js:38-42`), and an empty string is falsy — **but only if rhachet's whoami is
what breaks.** while the layer at fault is unknown, an env var aimed at a layer that may never run
is a guess dressed as a clamp. ⇒ **step 1 below is still the first move, and it is now the ONLY
move**: read the exit code rather than theorize about it.

## .the shape of the fix

1. **read the cause, do not guess it.** `getCloneAddress` already logs the instance to
   `.log/bhrain/brain/apply.log` via `noteCause` — but only on the spawn-error and parse-failure
   arms. a non-zero exit that is not 2 logs **naught**, so the exit code and the child's stderr are
   both discarded. ⇒ add a `noteCause` on that arm, which names the code
2. re-run the acceptance suite and read the log out of the temp dir
3. if hypothesis 1 → record it in the suite's header and leave the code alone
4. if hypothesis 2 → the remedy is upstream: `clone whoami` should exit 2 for "not an enrolled
   clone" from any cwd, which is a `ehmpathy/rhachet` ask

## .why it is not done in this round

**SAFE ✅ · CLEAN 🔴.** step 1 is a one-line addition to a communicator this round already opened,
and it is safe — but the diagnosis it enables ends in step 4, an ask on another repo on another
cadence, and the branch it would change (`code !== 0`) is one no case in this feature's vision
demoes. ⇒ the acceptance suite is written to assert what all six causes guarantee, so it is correct
either way, and the round does not block on a diagnosis it cannot finish.
