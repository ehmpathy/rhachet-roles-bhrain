# domain.term.choice.reason: absolute

## .etymology

the word is the **wisher's**, and it arrived with its own argument attached:

> *"only the sith deal in absolutes"*

that line does two things a coinage rarely does at once. it names the word, and it supplies the
**test** — an absolute is a quantifier, so the question a reader owes it is *what does it range
over?*

⇒ so `absolute` was not chosen against candidates on style grounds. it was adopted, and the
alternatives below were weighed after the fact and rejected because each drops the ground the
coinage came with.

| candidate | why it lost |
|---|---|
| `universal` | scopes correctly, and severs the line that motivates the rule |
| `blanket` | reads as a volume complaint, where the measured defect is one word |
| `categorical` | logic's term of art for a different shape, so it imports an argument we do not make |
| `overclaim` | grades the author's intent; this term must grade the artifact |

## 🟡 .the overload it is qualified against — a coordinate system, not a quantifier

`absolute` is the more common word **outside** this boundary, and the two senses share only the
english:

| the sense | what it names | where it lives |
|---|---|---|
| a coordinate system | a path rooted at `/`, over one rooted at the cwd | `symlink --mode absolute` (`ehmpathy/role=mechanic`, foreign) · test names · code comments |
| **a quantifier** | a claim over a set | `rule.forbid.absolutes` (this repo, booted) |

🟡 **the foreign sense sits in a published CLI flag**, so it is a contract — just not one of ours.
`rule.forbid.domain-term-ambiguity` grades an overload *in a contract* a blocker, and the boundary
qualification is what discharges it: `prose.absolute` dereferences to one sense, and a bare
`absolute` to neither.

⇒ that is the same repair `clamp` is blocked on and `warm` is blocked on — with one difference. this
one's head was already declared, so the cluster could be written the round the word entered a grade.

🟡 **the 1626 is a CANDIDATE set, never a defect count.** a regex parts no walked set from an unwalked

### the discovery move

not a decomposition and not a citation — a **corpus walk**, run because the rule's own test demanded
one. the rule asks *"did you walk the set?"*, so an author who ships it with no walk has failed it in
the act that declares it.

⇒ that recursion is the strongest evidence the term is real: **the word's test is checkable enough to
fire on the brief that declares it.**

## .disputes

### dispute: whether the contrastive shape is carved out  —  raised 2026-09-07  —  status: OPEN

- raised.by = the round that authored the rule
- claim     = *"X, never Y"* names Y, so it states a bound rather than a quantifier. it already
              performs the repair the rule asks for, and to grade it would demand a repair the
              passage has made
- counter   = three, and each is real:
  - the carve-out is a judgment a reviewer makes per line, so two reviewers can disagree — and a
    rule whose test forks is weaker than one whose test does not
  - a contrastive can still overstate: *"a reviewer never reads code"* is contrastive in shape and a
    quantifier in substance, and the carve-out admits it
  - `rule.require.disputable-claims` would catch that anyway, so the strict option's loss may be
    recoverable
- resolution = _open._ itemized as fulcrum F14 at 70%, and routed to the wisher. the counter that
              would move it: **a contrastive `never` found to carry an unwalked quantifier makes the
              carve-out a hole, and the repair is a tighter predicate rather than a wider forbid**
