# execution: memory.guard never halts a tool it cannot judge

## .todos

- [x] hook command runs the linked skill file directly, never `rhx` (`LEARNER_MEMORY_GUARD_HOOK_COMMAND`, `getLearnerRoleHookCommand.ts`, wired in `getLearnerRole.ts`)
- [x] hook anchors on `${CLAUDE_PROJECT_DIR:-.}`; an absent skill prints one line and exits 1
- [x] skill locates its cli from its own package: it follows its own links one hop at a time with plain `readlink` (bsd lacks `-f`), then `cd -P`; never the cwd
- [x] every guard fault → one stderr line with cause + fix, exit 1 (F1)
- [x] faults named apart, with the error class: a module absent at load says reinstall, one line; any other load rejection (a load defect) and a run throw (a guard defect) say report it, with the full stack after the line
- [x] a stdin read fault is named, never graded as an empty payload (`RHACHET_STDIN="$(cat)" || emit_fault`; export on its own line)
- [x] only the verdict `blocked` exits 2 — a setup step that fails under `set -e` with its own status 2 too: an `ERR` trap maps it to the fault line, exit 1; each setup step is its own assignment, so no nested failure hides from `set -e`
- [x] deadline in node itself (3.5s, exit 4) on every host; `timeout 4.5` as a backstop where the host has it; both under the hook's PT5S
- [x] redirects graded by target (`getAllBashRedirectTargets`): `2>&1`, `>&2`, `=>`, `->` are no writes
- [x] a redirect target is read as one shell word: a quoted span whole (`> "/Users/me/My Project/.claude/…"`), quoted and bare runs joined (`> "$HOME"/.claude/…`); `>& file` is a write, `>&2` and `>&-` are not
- [x] a redirect to a relative or `$var` path beside a memory path blocks, graded as a copy (`D=…/memory; echo x > $D/a.md`, `cd …/memory && echo x > a.md`): `main` blocked these, and the guard cannot know where they land
- [x] a copy verb grades only the memory path in its own simple command, and only as that command's name (`getAllBashCommandSegments`, `getOneBashCopyVerb`): `/bin/cp` and `\cp` copy; `grep -c tee M`, `cat M | tee /tmp/x`, `mv a b && cat M`, and a slug like `-home-me-cp-tools` stay reads
- [x] `tee` and `teesafe` write every operand, so their nudge names a write; `cp` and `mv` stay graded blunt, either direction (stated in the brief and clamped)
- [x] the verdict reads as narrative: `isNativeMemoryPath`, `getAllBashRedirectTargets`, `isBashPathAnchored`, `getAllBashCommandSegments`, `getOneBashCopyVerb`, `getOneMemoryPathFromCommand`; the memory grammar lives once, in `isNativeMemoryPath`, and the lift filters through it (clamped: a copy blocks at each shape it accepts)
- [x] settings regenerated via `rhachet init --hooks` (learner: +1, -1); the box-local actor settings stay out of the pr — a consumer runs `rhachet init --hooks` after the bump
- [x] learner brief `rule.forbid.native-memory` (`.md` + booted `.min`) states the fail-open line, the read line, and the blunt copy verbs; learner boot stays inside its token budget (`roleBootClamps` 117/117)
- [x] real-layout proof: `blackbox/learner.memory-guard.hook.acceptance.test.ts` runs a real `rhachet roles link --role learner`, then the exact registered command: a memory write exits 2 with the nudge, `ls` exits 0 silent. a session reads its hook settings once, at start, so no in-session check can run a changed command; a live Write in this session ran the old `rhx` hook, which proves only that the old command still blocks a linked tree
- [x] the hook names the dir it looked in (`skill not linked under <dir>`), so a wrong `CLAUDE_PROJECT_DIR` shows itself; a link whose package is gone reads `skill link dangles at <path>`, fix reinstall
- [x] the fix line runs verbatim from a repo root: `./node_modules/.bin/rhachet roles link …` (rhachet's manifest check refuses `npx … rhachet` anywhere in a hook command, echoed text included)
- [x] a payload the guard cannot judge (malformed json, no string `tool_name`) proceeds with one notice line, exit 1; empty stdin stays silent
- [x] the node run lives in a quoted heredoc (bash expands no `$` in it); the fault line format is declared once, `MEMORY_GUARD_FAULT_FORMAT`, and bash and node both render it
- [x] the verdict carries `path` + `act` only (`reason` read by no caller, dropped); the act union is named once, `MemoryGuardAct`
