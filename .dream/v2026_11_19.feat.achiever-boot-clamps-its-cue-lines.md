# 🌙 dream: the achiever's boot clamp pins its cue lines, as the condensed roles' do

- kind: feat
- owner: ehmpathy/rhachet-roles-bhrain (`src/domain.roles/roleBootClamps.integration.test.ts`)
- caught: 2026-11-19

## .the cue that fired

the achiever now boots four `.md.min` laws at say. `roleBootClamps` holds achiever in
`ROLES_BUDGET_ONLY`, so only its budget and seat payload are pinned.

## .the gap, precisely

a cue line cut from a min costs fewer tokens, so a budget-only clamp passes the cut
(`rule.require.a-cue-is-not-a-claim`). the condensed roles (learner, driver, librarian) pin every
say line, every ref, each min's `.md` peer, and the readme's min-convention line. the achiever's
mins have none of those clamps.

## .the shape of the fix

- move `'achiever'` from `ROLES_BUDGET_ONLY` to `ROLES_CONDENSED`, and let `SAYS_REQUIRED.achiever`
  list the four law mins
- renumber the `[case…]` labels so the condensed set's labels do not collide with `[case4]`–`[case6]`
  (the label set is the snapshot key, so every budget-only snapshot name moves once)
- the readme already carries the min-convention line, so the readme assertion holds

## .why it is not done in this round

the renumber renames every budget-only role's snapshot keys: a ripple across roles this change does
not touch, which fails the clean test for a fix pulled in now.
