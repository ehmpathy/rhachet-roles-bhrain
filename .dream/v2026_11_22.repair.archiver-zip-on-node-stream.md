# 🌙 dream: replace archiver, so the `/readable-stream@` cycle exclude can retire

kind: repair · owner: this repo · caught 2026-11-22

## .the cue that fired
`test:lint:cycles` holds `/readable-stream@` excluded: 2.3.8 and 4.7.0 (latest) both hold `_stream_duplex <-> _stream_{readable,writable}`. this repo reaches it only through `archiver`, in `captureSnapshot` (one `archiver('zip', { zlib: { level: 9 } })` call).

## .the gap, precisely
a prod dependency cycle ships to consumers; the stone's rule forbids its exclude, and no clean readable-stream release exists.

## .the shape of the fix
write the snapshot zip with a writer built on `node:stream` + `node:zlib` (or a zip lib with no readable-stream dep, checked by dpdm first), keep `captureSnapshot`'s contract, prove it with its extant tests, then drop the `/readable-stream@` line from `.dpdmrc.yaml`.

## .why it is not done in this round
a dependency swap in a feature path is out of the upgrade's scope, and the green-pr deadline leaves no room to prove it.
