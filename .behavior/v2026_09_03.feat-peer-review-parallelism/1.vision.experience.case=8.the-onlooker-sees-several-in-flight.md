# case=8 — the onlooker sees several in flight

**cell** — `onlooker × multi-unbounded × all-fresh × happy`
**feel · care** — happy · **alterpath, chosen**

⚠️ these `[tn]` sketches are illustrative, not proof. no code exists yet.

## 🔴 .this is an alterpath, and that is deliberate

the wish is explicit:

> ⚠️ **the live-stream renderer is DESIRED, never required.** … if you must pick, deliver
> acceptance 1–7 with a plain sequential render of results as they settle, and say so. a correct
> concurrent run with a dull display is a success. a beautiful display over a serial run is not.

🔴 **this demo carried two targets — a floor and a peak — until the wisher settled it 2026-09-08
(seed S2).** the peak was per-lane spinners, and `\r` yields exactly one mutable line, so it was
never buildable at any budget.

⇒ **there is now ONE target.** append-only blocks, plus a single **aggregate tail status line** that
carries the group's elapsed, the inflight count, and the count left. it is built on the extant
`overwrite`/`seal` pair, so **live status is committed rather than aspired to** — see
`.the peak, and why it shrank`.

⚠️ what stays an alterpath is **cosmetic** polish only — colour, unicode, frame rate. that is why
this file's `feel · care` still reads `alterpath` while its substance is now floor.

## .the narrative — the onlooker's pov

i watch the terminal while my driver runs `--as arrived`.

**the floor** — four reviewers start. i see four lines appear at once, each marked in flight. then
they settle, in whatever order they finish, **each one's full block APPENDED below** — never written
back up into the line that announced it. no spinner animates, and no line is ever redrawn. it is
plain, and it is honest: i can tell what started, what has landed, and what i still wait on.

⚠️ **the announcement line and the settled block are two separate appends, not one line that
fills.** *"each line completes in place"* is cursor math, and it contradicts this case's own
`never overwrite`. **the floor's whole claim is that it needs no cursor at all**, so a reader must
not picture a line that mutates.

🔴 **and one line at the very bottom moves** — the group's status, redrawn in place:

```
   └─ ⠸ 3 inflight · 1 done · 3 left · 34.8s
```

**it is the only mutable line on the screen**, which is the wisher's hard constraint
(seed **S2**): *"only the last line is updatable."* so the display is not four spinners — it is
**one spinner that speaks for the level**, and it carries the group's elapsed and the count left
rather than any one lane's.

### 🔴 `left` means NOT-YET-SETTLED, and the field must say so

⚠️ **caught in peer review i023/r2, which parsed the line the other way** — as
`inflight + done + left = members`, and so computed `0 left` where the render says `3`.

| the sense | on a 4-member level, 3 up · 1 down | is it what we mean? |
|---|---|---|
| `left` = **not yet settled** (`inflight + queued`) | `3 left` ✅ | ✅ **yes** |
| `left` = **queued, not yet started** | `0 left` | ❌ no |

⇒ **the counts reconcile under the intended sense**, so this is not an arithmetic defect. it is a
`rule.forbid.ambiguous-labels` defect, and **the reviewer's misparse is the proof**: a careful reader
took the second sense off the same bytes.

**the invariant a reader may check, stated once:**

```
done + left = members          # 1 + 3 = 4 ✅
left = inflight + queued       # 3 = 3 + 0, on an unbounded level
```

🔴 **the two senses agree only where the queue is empty**, which is why the ambiguity survived: on an
**unbounded** level every member starts at once, so `queued` is always `0` and `left == inflight`.
⇒ **the divergence appears exactly at `concurrency: 1`** — the level this feature exists to make
possible. a 4-member capped level, one settled and one aloft, shows `3 left` beside `1 inflight`, and
a reader on the wrong sense would judge the level stalled.

⚠️ **so the field is not renamed.** `left` is the wisher's own word (*"we want to know how many are
left too"*), and `rule.always.archive-the-wishers-words-verbatim` makes their coinage the term's
etymology. what is owed is the **definition**, carried beside it — which is what this section is.

⚠️ **a per-reviewer spinner cannot be built on `\r` at all**, which rewrites only the line the
cursor sits on. that impossibility is precisely what made a live renderer look expensive for as
long as nobody checked it — see `.the peak, and why it shrank` below.

either way the fact i actually need is present: **four are up, and here is which have come down.**
today's render can only tell me about one at a time, which under concurrency would be a display
that actively misleads — it would show one lane and hide three.

## 🔴 .why the extant render cannot simply be reused — verified, and worse than a garbled spinner

`genContextCliEmit.ts` (read in full) writes progress to **stderr**, and animates via `overwrite`
at `:47-56` — `input.stderr.write(`\r${padded}`)`. that much is the obvious problem: a `\r`
rewrites only the line the cursor sits on, so four lanes in flight would animate one and freeze
three.

**but the spinner is the lesser defect.** the real one is a *stateful split across two events*:

| `:204-229` — inflight | `:234-253` — finished |
|---|---|
| `seal`s the reviewer's **header** line permanently — `├─ r1: slug (l1, 1/∞)` | emits `lines.slice(1)` — **skips the header**, because *"header already sealed at inflight start"* (`:233`) |

⇒ that optimization assumes a strict interleave: `inflight(r1) → finished(r1) → inflight(r2) →
finished(r2)`. concurrency produces `inflight(r1) → inflight(r2) → finished(r1) → finished(r2)`,
and then **r1's detail block is emitted after r2's header** — so r1's verdict, blockers, and path
render nested under r2's name.

🔴 **the output would not merely look bad. it would attribute the wrong verdict to the wrong
reviewer.**

⚠️ **an earlier draft added *"and every one of the 36 peer acceptance snapshots reads this stream"* —
that is FALSE, and the yield's own stream audit is what refuted it.** the 36 snapshots capture
`sanitizeTimeForSnapshot(result.stdout)`; this emitter writes to **stderr** (`:50`, `:62`). so the
two live on different streams:

| stream | carries | exposed to the misattribution above? |
|---|---|---|
| **stderr** | these live frames | ✅ **yes** — this is where it happens |
| **stdout** | the settled tree the 36 snapshots record | ❌ no |

⇒ **the correction cuts both ways, and neither half cancels the other:**

- **the blast radius is smaller than claimed** — a botched live render cannot silently churn the
  recorded verdict trail, so the two can be clamped independently
- 🔴 **and that makes it WORSE for the human, not better.** a defect the snapshot suite cannot see is
  a defect no test goes red for. the driver who reads r1's verdict under r2's name is the **only**
  detector, and the demo above shows the output stays perfectly well-formed while it misreports

⚠️ **the determinism requirement is untouched** — it belongs to the **stdout** tree, and a
settle-order merge there would churn all 36. that claim was never about this stream.

⚠️ **and `clearActive()` fires at the head of every branch** (`:205`, `:235`), so r2's inflight
event kills r1's spinner interval outright. under concurrency at most one lane can ever animate,
and which one is a race.

⇒ the floor sidesteps all of it: **emit the full reviewer block at settle time, header included,
and never overwrite.** append-only output is correct under any concurrency, needs no cursor math,
and — crucially — carries no cross-event state to misattribute.

## 🔴 .the peak, and why it shrank — the wisher's constraint dissolved fulcrum F4

the peak was drawn as *"four lines, each with its own live spinner, redrawn together each frame"* —
which **needs** multi-line cursor-up redraw (`\x1b[{n}A`), a frame buffer over the group, and care
where a malfunction's stderr lands mid-frame. that is the piece the wish warns *"is most likely to
eat the whole round"*, and it is why **F4** subordinated the render.

⚠️ **the wisher then stated the constraint that makes that design impossible anyway** (seed S2):

> *"only the last line is updatable"* · *"we require the spinner to say how long all has been
> inflight"* · *"we want to know how many are left too"*

⇒ **a per-lane spinner was never available** — `\r` rewrites one line. so the question was never
*"can we afford four spinners?"*; it was *"what does ONE spinner say for four lanes?"* — and the
answer is an **aggregate**: the group's elapsed, and the count left.

### the mechanism is the extant one, unchanged

`seal()` terminates each line with `\n`, so after any append the cursor sits on a fresh **last**
line — precisely where `overwrite()`'s `\r` operates (`:47-56`, `:59-67`):

```
overwrite(status)          # the tail spinner, on the last line
… a lane settles …
seal(block line 1..n)      # pads over the status, then appends the whole block
overwrite(status')         # redraw the status on the NEW last line
```

🔴 **no cursor-up, no frame buffer.** and the append discipline is untouched — a settled block is
still emitted **whole**, header included, above the status line, so the misattribution demoed above
cannot occur.

⚠️ **it also removes the `clearActive()` race.** the extant code kills the active interval at the
head of every branch (`:205`, `:235`), so a per-lane design could animate at most one lane and
**which one was a race**. one interval for the whole level has no second interval to kill.

⇒ **so F4's premise is gone: live feedback is now inside the floor, not above it.** what remains
optional is only cosmetic polish, and the fulcrum's rework stays clean.

### the AFTER — a naive concurrent port, derived from `:209-217` and `:253`

the emit sequence becomes `inflight(r1) → inflight(r2) → finished(r1) → finished(r2)`. each
`inflight` seals a separator and a header; each `finished` emits `lines.slice(1)` **wherever the
cursor now sits**:

```
🦉 the way speaks for itself
   │
   ├─ r1: alpha-checker (l1, 1/5)          ← 🔴 header with NO body
   │

   │   └─ taken: …r001._.taken.by_self.alpha-checker.md
   │   ├─ rejected [TIME]
   │   ├─ 1 blocker 🔴
   │   ├─ 0 nitpicks ✓
   │   ├─ given: …r002._.given.by_peer.beta-checker.md     ← r2's own, appended below
   │   └─ taken: …r002._.taken.by_self.beta-checker.md
```

🔴 **two defects, and the second is the dangerous one:**

| what a reader sees | what it is |
|---|---|
| `r1` renders a bare header, no verdict | loud — an onlooker notices at once |
| 🔴 `r2` owns **two** verdict blocks, the first of them alpha's | 🔴 **quiet** — each block is well-formed, and only the `r001` / `alpha-checker` inside the path betrays it |

⇒ **that is why the artifact path in the `given:` line is the tell.** strip it and the two blocks are
indistinguishable, so a driver reads two verdicts against beta and none against alpha — and acts on
the wrong one.

⚠️ **and note what the byte-level view adds that the prose could not: the failure is not a garbled
frame, it is a well-formed tree that misreports.** a render defect whose output stays **legible** is
the one nobody reports.

## .the bdd sketch

```gherkin
# --- the floor: the committed target ---
given [case1] a level with four reviewers, unbounded, all fresh
  and their settle order is forced to differ from their declared order
when  [t0] the level executes
then  each reviewer's block is emitted whole — header AND details together
  and no reviewer's detail lines appear under another reviewer's header
  and no line is overwritten
  and every reviewer appears exactly once in the final tree
  and the final tree is ordered by declared index, not by settle order

given [case2] output is piped (not a tty)
when  [t1] the level executes
then  the settled blocks are byte-identical to the tty case
  and no escape code and no \r appears anywhere in the stream
  and the status line is SUPPRESSED entirely, never appended per tick
  and the level announces its roster ONCE, on stderr, before any lane launches

# --- the tail status line: live feedback, INSIDE the floor ---
given [case3] a tty, and a level with four reviewers in flight
when  [t2] the frame ticks
then  exactly ONE line redraws — the last one
  and it reads the group's elapsed, the inflight count, and the count left
  and no line above it is ever rewritten
  and a settled block appends ABOVE it, whole, header included
  and a malfunction's stderr line does not corrupt it
```

⚠️ **`[case3]` described four per-lane spinners until peer review i019/r2** — the exact design this
file's own narrative proves cannot exist on `\r`. **the artifact stated the impossibility and then
asserted it in its own timeline**, one screen apart.

⇒ and note what the repair did to its **kind**: `[case3]` is no longer *"the peak, shipped only if
the round has room."* the aggregate tail line is buildable with the extant `overwrite`/`seal` pair,
so **it moved from the alterpath into the floor.** this case's `feel · care` stays
`happy · alterpath` only because a *cosmetic* peak (colour, unicode polish) remains optional —
**live status is now committed.**

🔴 **`and the final tree is ordered by declared index`** — this is the same determinism claim as
case 1, seen from the render. **the 36 peer blackbox snapshot tests read the settled STDOUT tree**,
which this deterministic merge is what keeps stable — a tree ordered by settle order would be
nondeterministic and would churn every snapshot on every run.

⚠️ **this read *"read this output"* until i019/r1**, where *"this output"* was `[case1]`'s **stderr**
frames — the claim the stream table nine lines above had just refuted. **one repair, one section, and
its neighbour left stale**: the same shape this drive has chased for six rounds, committed *by* the
repair that named it.

⚠️ **`[case2]` is the honest ergonomics floor.** CI is not a tty. a render that only works under a
tty is a render that does not work where the suite runs.

🔴 **and its `then` says *identical INFORMATION*, never identical bytes — caught in peer review
i022/r2.** it read *"the output is identical to the tty case"*, which this document's own mechanism
section refutes: under a non-tty the two streams cannot agree in whole.

⚠️ **i022/r2 then named the WRONG divergence, and execution measured the right one.** it read that a
piped log *"appends one status line per tick"*, inferred from `overwrite`'s newline fallback
(`:52-55`). the fallback is real and `drawStatus` never reaches it — every spinner path is `isTty`
gated and returns at `genContextCliEmit.ts:117`. ⇒ a piped log got **zero** status bytes, not one
line per tick.

⇒ and the arithmetic says why that gate holds: `SPIN_MS` is 80ms against a `PT21M` timeout, so a
per-tick append is ~15,750 lines on one level. the suppression is a declared, clamped deviation
(`genContextCliEmit [case10]`), never an oversight.

🔴 **but the suppression took the ANNOUNCEMENT with it, and that was a real defect — raised
i009/r10.** a slotted level wrote no byte from launch to settle, so a reader could not part *"this
level is slow"* from *"this level never began"*. the repair is ONE line per level — O(1) rather than
O(ticks) — composed by `asReviewLevelPourAnnounce` from the DECLARED roster and written to **genuine
stderr** at the pour, before any lane launches.

| | the settled blocks | the status line | the pour announce |
|---|---|---|---|
| tty | appended, once each | one line, redrawn via `\r` | one line, at t≈0 |
| piped | 🔴 **byte-identical** | 🔴 **suppressed entirely** | 🔴 **one line, at t≈0** |

⇒ **the two runs can never be byte-identical in whole**, and the claim that they are would make the
clamp either unwritable or wrong. what IS byte-identical is the part that matters — the settled
blocks — and the `then` now asserts exactly that, plus the absence of any escape code, plus the
one-time announce that keeps a piped log legible.

🟡 **the announce closes the SILENCE and not an inactivity KILL.** every lane announces at t≈0 and
the log is quiet thereafter, so a runner that reaps a job with no output for N minutes still reaps
it. that wants a heartbeat on a cadence decoupled from `SPIN_MS`, which is a judgment rather than a
ride-along: carried as fulcrum **F15**.

## .the clamp this owes

floor only (acceptance 7 covers cases 1–7; this alterpath owes a determinism clamp):

```gherkin
given [case1] four reviewers whose settle order is forced to differ from declared order
when  [t0] the level executes twice with different settle orders
then  the rendered tree is byte-identical across both runs
```

⇒ **prove it bites**: emit in settle order and re-run — the two trees differ, test goes red.
restore the declared-index sort — green.

### 🔴 and this clamp does NOT catch the defect this case is about — a second one is owed

⚠️ **caught in peer review i019/r2, and it is the same shape as i016/r2's `Promise.all` catch: a
clamp whose red arm the defect never trips.**

the clamp above runs the level **twice with different settle orders** and asserts the two stdout
trees match. **the naive port passes it.** force a settle order and the header/detail split produces
the *same wrong tree* both times — it is **deterministic and it misreports, at once** — so a
byte-comparison across two runs sees no difference at all.

⇒ **the determinism clamp guards stdout ORDER. the misattribution lives on stderr** (per the stream
table above), and those are different properties on different streams. so a second clamp is owed:

```gherkin
given [case4] two reviewers at one level, settle order forced to r2-then-r1
when  [t3] the level executes
then  each reviewer's stderr block contains its OWN artifact paths
  and no reviewer's detail lines appear beneath another reviewer's header
  and each reviewer's header appears exactly once
```

⇒ **prove it bites**: restore the extant header/detail split — seal the header at `inflight`
(`:217`), emit `lines.slice(1)` at `finished` (`:253`) — and force the interleave. **r1's `given:`
path renders under r2's header**, and the `r001` / `alpha-checker` inside it is what the assertion
catches. red. restore the whole-block append — green.

🔴 **the tell that the first clamp was insufficient sits in this case's own prose:** *"a defect the
snapshot suite cannot see is a defect no test goes red for."* i wrote that as a warn about the stream
split and never drew the consequence — **that the only clamp i had listed was on the stream that
cannot see it.**

### 🔴 the two clamps have DIFFERENT oracles, and only one of them already exists

⚠️ **caught in peer review i022/r2.** the paragraph below once sat here unqualified and read as
`[case4]`'s oracle. it is `[case1]`'s. **a stderr misattribution under a correct stdout tree leaves
the stdout snapshot untouched** — so the extant snapshot cannot be what goes red for it.

| clamp | stream | oracle | does it exist today? |
|---|---|---|---|
| `[case1]` — tree order | **stdout** | the BEFORE block, held at `blackbox/__snapshots__/driver.route.peer-budget-parallel-l1.acceptance.test.ts` | ✅ **yes** — the committed bytes |
| 🔴 `[case4]` — misattribution | **stderr** | 🔴 **a NEW committed expectation.** the tell it names: `r001` / `alpha-checker` paths inside a `beta-checker` block | ❌ **no** — no artifact captures this stream |

⇒ **`[case1]`'s oracle is not invented** — it is the committed snapshot, so that clamp needs no new
expectation and a correct concurrent implementation leaves it untouched.

⚠️ **that is the strongest form a clamp of this kind takes.** a render clamp written against a
hand-authored expectation only proves the render matches what its author imagined. one written
against the **committed** bytes proves the render did not change — which is the actual claim
acceptance 2 makes about this whole feature.

🔴 **and `[case4]` cannot have that strength, which is the honest cost to state rather than hide.**
no committed artifact records this stream, so its expectation **is** author-written, and it inherits
exactly the weakness named above. ⇒ the execution stage owes a decision this vision does not make:
either capture the reviewer stderr blocks into the acceptance suite so a future clamp gains a real
oracle, or accept a hand-authored one and say so.

⚠️ **this is the third instance of the stream conflation in this one file** (i018/r2's audit,
i019/r1's bdd sketch, and this). each was a *different sentence* that made the same false merge, and
each survived a repair aimed at its neighbour — which is why the table above states the split as
**data** rather than as one more paragraph that can be locally corrected and locally missed.
