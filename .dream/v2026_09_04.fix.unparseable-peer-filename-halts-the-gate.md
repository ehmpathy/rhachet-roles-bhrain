# 🌙 dream: an unparseable peer filename halts the gate rather than gates answerably

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** 2026-09-04

## .the cue that fired

`arch-hazards-behavior` r007 nitpick.1, at i002 of
`.behavior/v2026_09_03.fix-contemplation-gate-on-entrance`. it named the asymmetry directly: this
same behavior made an unreadable verdict **body** answerable (`asPeerGivenVerdict` gates rather than
scores a fake `0/0`), and left an unreadable verdict **filename** as an uncaught throw.

## .the gap, precisely

`getRouteGuardReviewPeerPathMeta` throws when a filename fails the stamp grammar. three shared
readers reach it — the entrance gate, the exit gate, and the stophook — all through
`getRouteGuardReviewPeerContemplationStatus` → `getAllRouteGuardReviewPeerGivens`.

**it is reachable by a human typo, not only by a legacy file.** the driver hand-writes `.taken`
filenames, and the enumerator's glob is `…i*.*.r*.…` — `*` matches any run of non-`/` characters,
dots included. so a stamp the glob admits (`iOLD`, `r2b`, a hash with a dot in it) is one the parser
then refuses.

**P2 widened the exposure.** the read was scoped to the current hash; it now spans every historical
`.given` and `.taken` on the stone. so a stray file that used to sit outside the window is now
inside it, permanently.

⇒ the consequence is a hard halt with no move: the driver cannot see the reply-prompt, so it cannot
learn which reviewer it owes or where to write.

**mitigated, not fixed, in that round:** the throw now names the fix — the grammar, the bad path,
and the instruction to copy the halt's `articulate into` path rather than retype it
(`rule.require.errors-name-the-fix`). that turns a stranded driver into an unstranded one. it does
not make the state answerable.

## .the shape of the fix

🔴 **the two sides need OPPOSITE polarity, and that is the whole design problem** — it is why this is
not a two-line change:

| an unparseable… | to skip it means | so the right move |
|---|---|---|
| **`.taken`** | the given it meant to answer stays gated | ✅ **skip is safe** — the driver is re-prompted with the right path, so it self-corrects |
| **`.given`** | a real critique vanishes and the stone passes | 🔴 **skip is the failhide** — it must gate |

so: parse leniently into a discriminated record rather than throw —

```ts
type PeerFileRead =
  | { parsed: true; slug: string; hash: string; iteration: number }
  | { parsed: false; path: string };
```

- **takens** — drop the unparsed ones; they answer no given, and the gate re-prompts correctly
- **givens** — carry each unparsed one into the uncontemplated set as its own tag
  (`'unreadable-name'`), beside `absent` and `stale`, so it renders in the reply-prompt with the
  file named and the fix stated. the driver gets a move rather than a stack trace

⇒ that is the same shape `asPeerGivenVerdict` took for the unreadable **body**, applied to the
**name** — which is exactly the symmetry the reviewer asked for.

⚠️ the given branch has one open question: a given whose **slug** is unparseable has no reviewer to
attribute the debt to, so the prompt's per-reviewer tree has no row to put it in. it likely wants a
separate block above the reviewer list.

## .why it is not done in this round

**safe?** no. it changes the record shape that three shared gate readers consume, plus the
prompt's tag union and its snapshots — mid-round, on the diff that is itself under review.

**clean?** no. the tag union, the prompt copy, the case=N inventory, and the clamps all move
together, and the slug-attribution question above is genuinely open.

⇒ so it is caught rather than done. the round shipped the mitigation that is both safe and clean —
an error that names the fix — and left the shape change to a round that can carry it.
