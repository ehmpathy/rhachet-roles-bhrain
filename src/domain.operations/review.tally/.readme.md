# review.tally — a declared shared exposure

`review.tally/` reads a reviewer's stdout and returns its counts: `N blockers`, `N nitpicks`.

two contexts read it, and both are sanctioned consumers:

| consumer | why it reads the tally |
|---|---|
| `review/` | a `rhx review` run tallies its own output before it reports a verdict |
| `route/guard/` | the guard tallies each peer given, so its verdict keys on the same counts |

## .the contract

| export | grain | what it guarantees |
|---|---|---|
| `getOneReviewCountsViaRegex` | transformer | the deterministic read of `contract.reviewer-output` — numeric counts for both severities, or `null` |
| `ReviewCounts` · `ReviewCountsResolved` | type | the shape every consumer reads |
| `getOneReviewCounts` | orchestrator | the cascade: regex first, a brain only where the regex cannot read |
| `ReviewTallyError` · `ReviewTallyTimeoutError` | error class | the two faults the cascade's brain fallback may throw, so a consumer can classify a tally fault. they live in `getOneReviewCountsViaBrain`, the one module of this context a consumer may read beyond the three above, and only for these two classes |

⇒ it sits at the `domain.operations/` root, beside `brain/` and `git/`, so no consumer reaches
into another context's internals to read it. a reshape here is a contract change for BOTH
consumers; read every call site before you make one.
