## .the gap, precisely

`rule.forbid.failhide` (code.test) is unambiguous:

> skips (`it.skip`, `given.runIf`, `then.skipIf`) are NOT alternatives — absent resource =
> unacceptable, always fail loud.

so **every one of these eleven is a rule violation on its face.** and two of them are worse than a
skip:

🔴 **the two `.only` sites are the sharper defect.** a `.skip` removes one suite from the run and
says so in the summary. an `.only` **silently removes every peer** in its file — the summary
reports a pass, and a reader cannot tell that seven neighbours never executed. that is failhide in
its purest form, and it has sat in `.scratch/` where nobody sweeps.

### 🔴 the `.scratch` question, CHECKED — and it inverts the verdict above

a first pass left this open as *"they may not be collected at all — a claim nobody has checked."*
it is checked now, and the answer changes the disposition:

```
jest.unit.config.ts:34:        '!**/.scratch/**',
jest.integration.config.ts:32:  '!**/.scratch/**',
jest.acceptance.config.ts:32:  '!**/.scratch/**',
```

**all three scopes exclude `.scratch/` explicitly.** so the two `.only` are **never collected by
any test command this repo ships** — they are **dormant**, not live.

⇒ **nine live · two dormant**, and the two are today the *least* harmful of the eleven rather than
the worst: they cannot hide a peer that never runs, because no peer there runs either.

⇒ and the deletion becomes **SAFE and CLEAN both** — it surfaces naught, since the files are
excluded from every run. the first pass's stated reason for the deferral (*"it surfaces unknown
never-run tests"*) feared a consequence the exclusion makes impossible.

🔴 **so the sharper repair is not the deletion.** an `.only` inside a directory every config
excludes is a **symptom**: `.scratch/` is a second, ungoverned tree inside `src/` — shipped,
typechecked, linted, and never run by any test scope. delete the two characters and the directory
stays ungoverned, so the next `.only` lands the same way.

## .why it is NOT fixed in this round

the buttonup mandate says to fix a gap rather than note it. I ran the SAFE/CLEAN test
(`rule.always.fix-forward-under-scouts-honor`) on each, and every one fails at least one leg:

| the fix | SAFE? | CLEAN? |
|---|---|---|
| remove `describe.skip` from the 9 llm suites | 🔴 **no** — every ci run would then call a paid llm api, on every push, forever | 🔴 no — it ripples into ci cost and needs a credential decision only a human can make |
| remove the 2 `.only` | ✅ yes | ✅ **yes** — and it surfaces naught, per the exclusion above |

🟡 **the second row passes both legs, so why is it not done?** because
`rule.always.fix-forward-under-scouts-honor`'s own bound is *"in scope — the fix rides the change
you came to make"*, and `beav/feat-review-cost-meter` touches not one file under
`src/domain.roles/thinker/`. a two-character edit in an untouched role's scratch directory, landed
inside a review-cost branch, is the **smuggled refactor** that rule's CLEAN question refuses. and
the edit repairs a symptom while the ungoverned directory — the actual defect — stays.

⇒ 🔴 **the cost leg is the one that settles it, and it is this branch's own subject.** a branch
whose entire wish is *"the review prompt spends real money, and the spend was unattributed"* must
not close a coverage gap by a silent switch-on of unbounded llm spend in ci. that would be the
exact defect this work exists to prevent, committed by the work itself.

and the `.only` leg is the second-order cost the stone cannot absorb: a buttonup gate that enables
an unknown number of never-run tests hands the *next* stone whatever they find.

## 🔴 .the size of the gap, measured 2026-09-25 — and this dream undercounted it

this dream counts **SITES**. a full `--thorough` integration run counts **TESTS**, and the two are
far apart:

| the census | count |
|---|---|
| skip/only SITES (this dream's figure, above) | 11 |
| 🔴 **TESTS withheld** — measured, `1799 passed / 0 failed / 79 skipped` across 140 suites | **79** |

⇒ **nine `describe.skip` withhold seventy-nine tests.** a site count reads like nine small holes;
the real gap is 79 tests of 1,878 collected — **4.2% of the integration scope does not run.**

🟡 **this changes the size of the ask, never the verdict.** the SAFE/CLEAN argument below is
unaffected — to un-skip still bills a paid llm api on every push, and still needs a human's
ci-cost decision. what changes is what the human decides: **whether to fund 79 tests**, not
whether to enable 9 suites. the second form makes the choice look smaller than it is, in both
directions — 79 tests is a larger coverage win AND a larger bill.

⇒ and it sharpens the third repair below: a `--what thorough` lane's value is now quantified. it
would move **79 tests** from never-run to run-on-demand.

🟡 the unit scope is clean at the same moment: **0 skipped of 2,539 across 250 suites.** so the
repo's skip debt sits entirely in integration, which is where the paid-llm suites live — the debt
and its cause are the same set.

## .the shape of the fix

two separable repairs, and the second is far cheaper than the first:

1. 🔴 **settle `.scratch/`, and the two `.only` fall out of it.** the directory is excluded by all
   three configs, so the question is not *"delete two characters?"* but *"why does `src/` hold a
   subtree no test scope runs?"* — collect it (and then delete the two `.only`, and read what the
   peers do), or delete it. either answer disarms them permanently; the two-character edit alone
   leaves the next `.only` free to land the same way
2. **the nine cost-gated suites** want a declared mechanism rather than a skip, and the repo
   already has the vocabulary for it:
   - a `ConstraintError` with a hint (`rule.require.failfast`) is the rule's prescribed shape —
     but it turns every local run red for a human with no key, which is why nobody reached for it
   - ⇒ so the honest repair is probably a **third test scope** — a `--what thorough` lane that
     runs paid-llm suites on demand and in a scheduled ci job, not on every push. the
     `THOROUGH=true` note in `stepReview.caseBrain.claude-sonnet` shows somebody already reached
     for exactly this and stopped at a comment
   - the invariant to hold: **a suite that does not run must be VISIBLE as not-run at the scope
     level, never hidden inside a green summary**

🟡 write the clamp before the fix (`rule.require.clamp-edge-cases`): a test that asserts the
collected suite count for a given `--what`, so a suite that silently leaves the run goes red.

## .the fulcrum

> **a `.skip` is a gap you can see in the summary. a `.only` is a gap you cannot — it reports a
> pass for the peers it deleted from the run. and a directory no test scope collects is a gap you
> cannot see EITHER, which is why both `.only` landed there and survived.**
> rework: **the nine `.skip` are DIRTY** — they need a ci-cost decision only a human can grant.
> **the two `.only` are CLEAN but OUT OF SCOPE**, and their real repair is a scope call on
> `.scratch/` itself, in the role that owns it.
