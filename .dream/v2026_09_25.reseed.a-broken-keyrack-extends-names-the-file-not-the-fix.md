# 🌙 dream: a broken keyrack `extends` names the file, never the fix

**kind** = reseed · **owner** = `ehmpathy/rhachet` · **caught** 2026-09-25

## .the cue that fired

three acceptance runs in this worktree (2026-09-19, twice on 2026-09-25) ended on one error with no
jest summary:

```
🔐 keyrack get
   └─ ✋ ConstraintError: extended keyrack not found
      ├─ path: .agent/repo=bhrain/role=reviewer/keyrack.yml
      ├─ from: /…/.agent/keyrack.yml
      └─ ran: keyrack get --for repo --env test --owner ehmpath

  ●  process.exit called with "2"
        at Object.source (jest.acceptance.env.ts:63:11)
```

it took three logs to learn what to do.

## .the gap, precisely

`.agent/keyrack.yml` is tracked; the role trees it `extends` are generated and gitignored
(`.agent/repo=bhrain/.gitignore:6:*`). so a fresh clone or worktree satisfies none by construction.

the repair, unguessable from the message:

```sh
rhachet roles link --repo bhrain   --role reviewer
rhachet roles link --repo bhuild   --role dispatcher
rhachet roles link --repo ehmpathy --role mechanic
```

three properties compound:

| property | the cost |
|---|---|
| it fires in jest env setup | no test name — it reads as infrastructure noise |
| it calls `process.exit(2)` | no `Tests:` summary — the run reads truncated, not failed |
| the absent file is gitignored | a grep finds naught, so a reader concludes the manifest is stale |

🟡 **the message misleads toward the wrong repair.** its four path fields invite an edit to
`.agent/keyrack.yml`; drop the line and the error goes, with the credentials it declared.

## .the shape of the fix

upstream, in `sourceAllKeysIntoEnv`'s `extended keyrack not found` branch, three bars with tests:

1. **name a runnable command** — the path encodes `repo=`/`role=`, so
   `fix: rhachet roles link --repo bhrain --role reviewer` is derivable. a path of another shape keeps
   the extant message
2. **say the target is generated** — *"this file is linked from a package, not committed"*
3. **report every broken extend** — three were absent and one was named

the cheaper local alternative: a preflight in `jest.acceptance.env.ts` that checks each `extends`
target and names the link command. strictly worse — one repo — and available under deadline.

## .why it is not done in this round

- **not clean** — the message renders inside `rhachet`
- the local preflight is out of this feature's scope

## 🔴 .the durable lesson

**an acceptance run with no `Tests:` summary has ended.** grep for the summary rather than wait.
