# 🌙 dream: the ehmpathy mechanic keyrack still declares `FIREWORKS_API_KEY`

**kind** = reseed · **owner** = `ehmpathy/rhachet-roles-ehmpathy` · **caught** 2026-10-03

## .the cue that fired

after this repo dropped fireworks from its own `.agent/keyrack.yml`, the CI firewall report still
listed `ehmpathy.test.FIREWORKS_API_KEY`. it comes in via `extends` from the mechanic role.

## .the gap, precisely

`rhachet-roles-ehmpathy@1.39.3` → `dist/domain.roles/mechanic/keyrack.yml` lines 12 and 15 declare
`FIREWORKS_API_KEY` under env.prep and env.test. every repo that extends the mechanic keyrack keeps a
fireworks declaration alive after the fleet moved to openrouter — and once rhachet's firewall halts on
an absent key (`v2026_10_03.reseed.rhachet-keyrack-firewall-halts-on-absent-key.md`), that stale
line would halt CI in every repo whose secrets dropped fireworks.

## .the shape of the fix

in `rhachet-roles-ehmpathy`, replace `FIREWORKS_API_KEY` with `OPENROUTER_API_KEY` in the mechanic
keyrack (or drop it, if no mechanic skill calls a brain), then release. this repo picks it up on the
next role-package bump.

## .why it is not done in this round

- **not clean** — the file is published by another repo; a tree adopts only what is scoped to itself
- the line is inert here: the firewall exits 0 on an absent key today, and no code in this repo reads it

## .dispatched upstream

not yet — the radio push is a human-gated act.
