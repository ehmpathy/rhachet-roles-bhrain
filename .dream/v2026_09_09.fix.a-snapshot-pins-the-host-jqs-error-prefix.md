`sanitizeJqPrefixForSnapshot` now strips a `jq: ` prefix from the borrowed line before the
snapshot, and the one affected snapshot was rewritten by hand rather than by `--resnap`, so no

⇒ so a scope deferral is answerable by a **later stone's mandate**, never only by a re-derivation

a whole-suite integration run came back **1 failed of 1500**, and the one failure sat in a file

⚠️ **that run was invoked with a flag `rule.forbid.thorough-test-runs` forbids, and the invocation

## .the gap, precisely

`src/domain.roles/driver/skills/__snapshots__/route.foreground.guard.integration.test.ts.snap`
records a passthrough of `jq`'s own stderr, verbatim.

checkable evidence:

- the snapshot was last written in `605ebcd`, and this round's diff touches **no file** on that
  code path — the hook is `route.foreground.guard.sh`, which pipes stdin to the host `jq`
- `which jq` → `/usr/bin/jq` — the **system** binary, never a pinned dependency
- the test asserts `result.stderr` whole (`route.foreground.guard.integration.test.ts:445`), so
  every byte the child writes is pinned, upstream text included

⇒ that is `rule.forbid.bare-host-deps` at work: the suite passes or fails by which jq the box
happens to carry, and the repo declares no version.

## 🔴 .why a resnap is the WRONG repair

the obvious move — `--resnap` — is worse than the failure:

| the move | what it does |
|---|---|
| resnap here | pins **my** host's jq. the suite then goes red for anyone on the other version, and for CI if its image differs |
| pin the jq version | infra. it repairs the class and reaches past this repo |
| sanitize the passthrough | repairs it here, and changes an unrelated test's contract |

⇒ **a resnap does not fix a host dependency; it merely moves which host is correct.**

## .the shape of the fix

sanitize the borrowed text before the snapshot, exactly as `sanitizeTimeForSnapshot` already
sanitizes the clock:

1. add a sanitizer that strips a leading `jq: ` from any line — one regex, in the test's own
   helper, beside the extant time sanitizer
2. keep the assertion that stderr **names the parse failure**, which is the behavior under test
   and is already clamped separately (`then: stderr reports the parse failure` — that one passed)
3. resnap only that one case, once the passthrough is sanitized

⇒ the discrimination survives: the hook's own line
(`🗿 route.foreground guard: failed to parse tool_name from tool input json`) is this repo's
text and stays pinned byte for byte. only the **borrowed** half is normalized.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.**

- the repair edits a test whose subject is a different feature — the foreground guard hook — and
  this round's diff is the peer-review concurrency pour
- it changes an extant assertion's contract, so it wants its own review rather than a ride-along
  in a diff that already restructures a ~280-line loop
- and the failure is **prior to this branch**: it reproduces on the base, because the cause is
  the host binary rather than any change here

⇒ a fulcrum is not owed. the deferral is on **scope**, never on a judgment about ripple cost.
