# 🌙 dream: a verification count is a claim, and no mechanism ever re-measures it

- **kind** = fix
- **owner** = `rhachet-roles-bhrain`
- **caught** = 2026-09-10, on `beav/feat-peer-review-parallelism`, stone `5.1.execution.from_vision`

## .the cue that fired

**two stale counts surfaced in ONE artifact, on one round, by two unrelated routes.**

| the row | it read | the truth | how it surfaced |
|---|---|---|---|
| `unit` — full suite | **1,640 passed** | **586**, across 45 suites | 🔴 I re-ran it for an unrelated reason and the number did not match |
| `unit` — `path://readReviewWindows` | **14 passed** | **18** | 🔴 chance. I doubted my own memory and measured |

⇒ neither was caught by a reviewer, a hook, or a test. **the first was caught because I happened to
re-run the command; the second because I happened to distrust a recollection.** so a sample of two
prices no other row — it prices the **detector**, and the detector is luck.

## .the gap, precisely

a yield carries a `### the verification` table. every row is a **claim about a measurement**, and it
is written once:

```md
| suite | result |
|---|---|
| unit — `path://guard` | ✅ 715 passed |
| integration — `runStoneGuardReviews` | ✅ 132 passed |
```

**the claim has an expiry and carries no date.** the moment a repair adds four cases, the row is
false — and it is false *silently*, because:

- no test asserts a count that lives in prose
- no lint reads a markdown table
- 🔴 **the number still looks like evidence.** a reader who wants proof finds a specific figure and
  stops. a specific wrong number is more convincing than an absent one

⚠️ **and the failure direction is always the same: the recorded count is LOW.** a round adds cases;
it rarely removes them. so a stale row **understates** the work, which is the direction nobody
audits — an inflated claim invites scrutiny, a deflated one reads as modest.

### 🔴 why it is worse than an ordinary stale doc

`rule.require.timeless-lessons` governs prose whose claim is durable. **a measurement is the exact
opposite: it is dated by nature and rendered as though it were not.** the table format strips the one
field that would let a reader price it.

⇒ so this is not carelessness — the artifact shape **invites** the defect. a row has a `suite`
column and a `result` column, and no column for *when*.

## .the shape of the fix

three rungs, cheapest first. the first alone would have caught both.

| rung | the move | cost |
|---|---|---|
| **1** | every verification row carries **the date and the exact command** that produced it | a convention. a rule + a template |
| **2** | `git.repo.test` emits a **pasteable row** on success, so the record is a copy rather than a recollection | one format function in the skill |
| 🔴 **3** | a checker that re-runs each recorded command and **diffs the count** | real work, and it is the only rung with teeth |

⇒ **rung 2 is the sweet spot.** the defect is not that authors lie; it is that they **retype a number
from memory** when the tool already held it. remove the retype and the drift has no source.

```
🐚 git.repo.test --what unit --scope path://readReviewWindows --mode apply
   ├─ stats
   │  ├─ tests: 18 passed, 0 failed, 0 skipped
   │  └─ 📋 row: | unit — `path://readReviewWindows` | ✅ 18 passed · 2026-09-10 |
```

## .why it is not done in this round

**SAFE = no. CLEAN = no.**

- **safe** — rung 2 changes `git.repo.test`'s stdout, and that skill is the verification instrument
  every route in the org runs. a render change there touches every acceptance snapshot that captures
  its output
- **clean** — the repair lands in `ehmpathy/role=mechanic`'s skill, which this branch never opens.
  this branch's diff is `bhrain`'s guard concurrency, and a skill-render change would ripple into a
  re-baseline no reviewer here asked for

⇒ and the stone is **halted** on two wisher calls. to widen the diff while a human is asked to rule
on a snapshot movement is precisely the move `rule.forbid.commits-the-route-did-not-ask-for` names —
a change to what the reviewers can see, made by the party under review.

## 🟡 .what was done instead

both stale rows were **corrected in place**, and each says so on its own line rather than in a
changelog — so a future reader sees the correction beside the claim it repairs.

⚠️ **that repairs two rows and not the mechanism.** the next round writes a fresh table, by hand,
from memory, with no date column. **the defect is structural and it survives this fix.**

⇒ see also: `rule.require.timeless-lessons` (a measurement is the counter-case it does not name) ·
`rule.forbid.thorough-test-runs` (the source of the 1,640 — a figure from a run this repo forbids) ·
`rule.require.disputable-claims` (a count IS the settler; a stale one settles it wrong).
